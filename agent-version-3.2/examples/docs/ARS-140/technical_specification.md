## 1. Обзор изменения

### 1.1. Тип и стороны
Fullstack с центром тяжести на бэке. `arsenal-admin-api` отдаёт события безопасности за период
файлом CSV; `arsenal-admin-web` добавляет раздел с выбором периода и кнопкой выгрузки. Новых
интеграций между сервисами задача не вводит.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `arsenal-admin-api` | новый эндпоинт выгрузки | Арсенал-Core | 🟢 |
| `arsenal-admin-web` | раздел «Журнал событий безопасности» | Арсенал-Core | 🟢 |
| Хранилище событий безопасности в `arsenal-admin-api` | источник строк выгрузки | Арсенал-Core | 🟡 подтв. аналитиком |
| Security-сервис | роли «Сотрудник СБ» и «Администратор эксплуатации» | Платформа | 🟡 подтв. аналитиком |

### 1.3. Связь с бизнес-требованиями
Сотрудник службы безопасности сам выгружает журнал за нужный период и разбирает инцидент в тот же
день, не дожидаясь ручной выгрузки от эксплуатации. Трассировка FR-* — в §7.

## 2. Взаимодействия (ядро)

### INT-1. Выгрузка журнала событий за период — 🟢
- **Граница/направление:** FE → BE
- **Триггер:** сотрудник СБ выбрал период и нажал «Выгрузить»
- **Контракт (запрос):** `GET /v1/security-events/export`, параметры `from: iso8601` и `to: iso8601`
  обязательны, оба включительно; тело отсутствует
- **Контракт (ответ):** `200`, `Content-Type: text/csv; charset=utf-8`,
  `Content-Disposition: attachment; filename="security-events_<from>_<to>.csv"`.
  Тело — CSV: UTF-8 с BOM, разделитель `;`, первая строка — заголовки
  `occurred_at;event_type;user_id;outcome`. Одна строка = одно событие, порядок — по `occurred_at`
  по возрастанию. `occurred_at` — `ISO 8601` в UTC; `outcome` — `success|failure`.
  **Событий за период нет → отдаётся тот же `200` и файл с одной строкой заголовков** (FR-6):
  пустой результат — это валидная выгрузка, а не ошибка и не пустой ответ.
- **Пример запроса:** `GET /v1/security-events/export?from=2026-08-01T00:00:00Z&to=2026-08-02T00:00:00Z`
- **Пример ответа (успех):** тело не JSON — приводим настоящий фрагмент файла:
  ```
  occurred_at;event_type;user_id;outcome
  2026-08-01T08:14:02Z;login;a.petrov;success
  2026-08-01T08:14:44Z;login;s.orlova;failure
  2026-08-01T09:02:10Z;permission_change;a.petrov;success
  ```
- **Пример ответа (событий нет):**
  ```
  occurred_at;event_type;user_id;outcome
  ```
- **Ошибки:** `400` — параметр не передан, не разобран как ISO 8601 или `from > to`;
  `403` — роль не «Сотрудник СБ»; `5xx` — сбой чтения хранилища
- **Состояния UI по ответу:** значение → браузер начинает скачивание, кнопка разблокируется;
  загрузка → кнопка заблокирована, спиннер; `400` → подпись под полями периода; `403` → «нет
  доступа»; `5xx`/таймаут → «выгрузка не удалась» + «Повторить». Полный список — §4.3
- **Авторизация:** только роль «Сотрудник СБ»; проверяется в `arsenal-admin-api` до обращения к
  хранилищу. Негативный случай: администратор эксплуатации вызывает эндпоинт напрямую → `403`
- **Происхождение:** 🟢
- **Трассировка:** FR-3, FR-4, FR-5, FR-6, FR-7

Новых взаимодействий, кроме INT-1, задача не вводит. Видимость раздела (FR-1, FR-7) фронт определяет
по роли из текущей сессии — механизм существующий, 🟡 подтверждено аналитиком; отдельного контракта
под это не появляется.

### Каталог ошибок (сводно)

| Код | Тело/сообщение | Когда | Состояние UI |
|-----|----------------|-------|--------------|
| `400` | `reason: period_required` | не передан `from` или `to` | `error_validation` |
| `400` | `reason: bad_period` | даты не ISO 8601 либо `from > to` | `error_validation` |
| `403` | стандартное | роль не «Сотрудник СБ» | `error_forbidden` |
| `5xx` | стандартное | сбой чтения хранилища событий | `error_source` |

## 3. Backend — ответственность

### 3.1. По сервисам
`arsenal-admin-api` реализует INT-1: проверяет роль, разбирает период, читает события из
существующего хранилища (🟡 подтв. аналитиком) и формирует CSV.

Порядок операций важен: запрос к хранилищу открывается **до** отправки заголовков ответа. Если
чтение не удалось, клиент получает `5xx` и скачивание не начинается вовсе — вместо обрезанного
файла, который выглядит как полная выгрузка.

### 3.2. Данные и хранение
**Новых сущностей и таблиц не появляется** — задача только читает то, что уже пишется.

События безопасности уже хранятся в `arsenal-admin-api` с полями «время события», «тип события»,
«идентификатор пользователя», «результат» (🟡 подтв. аналитиком; §3.3 БТ).

Одно изменение схемы (🟢): индекс по времени события — выборка за период без него идёт полным
сканом и на месячном интервале упирается в таймаут. Точный DDL — в репозитории
`arsenal-admin-api`; наличие подходящего индекса сегодня аналитиком не подтверждено, поэтому он
заводится как новый, а миграция пишется идемпотентной.

### 3.3. Авторизация/доступ на бэке
INT-1 доступен только роли «Сотрудник СБ»; проверка в `arsenal-admin-api` до чтения данных.
Администратор эксплуатации и любая другая роль получают `403` — фильтрация «показывать, но не
давать» живёт в UI (§4.4), а не в данных: бэк просто не отдаёт файл.

## 4. Frontend — ответственность

### 4.1. Где и что меняется в UI
Новый раздел админки «Журнал событий безопасности»: два поля периода (начало и конец, дата и
время), кнопка «Выгрузить». Вызывает INT-1 по нажатию. Пункт меню раздела показывается по роли из
сессии.

### 4.2. Пользовательские сценарии
Основной: сотрудник СБ открывает раздел (FR-1) → поля периода предзаполнены последними сутками
(FR-8) → правит период при необходимости (FR-2) → нажимает «Выгрузить» (FR-3) → браузер скачивает
CSV (FR-4, FR-5).

Ветвление «событий за период нет»: файл всё равно скачивается, в нём одна строка заголовков (FR-6).
Экран при этом не показывает ни ошибки, ни «нет данных» — с точки зрения пользователя выгрузка
удалась.

Ветвление по ролям (FR-7): администратор эксплуатации видит раздел, кнопка «Выгрузить» неактивна;
остальным ролям пункт меню не показывается.

### 4.3. Состояния (именованные)

| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `idle` | раздел открыт, выгрузка не запускалась | поля периода, кнопка активна |
| `loading` | запрос INT-1 отправлен, ответа нет | кнопка заблокирована, спиннер |
| `done` | `200`, файл передан браузеру | кнопка снова активна, подпись «файл выгружен» |
| `error_validation` | `400` | сообщение под полями периода, кнопка активна |
| `error_forbidden` | `403` | «выгрузка доступна только службе безопасности» |
| `error_source` | `5xx` / таймаут / сеть | «выгрузка не удалась» + «Повторить» |
| `disabled_by_role` | роль «Администратор эксплуатации» | раздел виден, кнопка неактивна с подсказкой почему |

`empty` — **не применимо**: пустой период не даёт отдельного состояния экрана, он даёт валидный
файл с заголовками (FR-6). Схлопывать его с `error_source` нельзя — это успех, а не сбой.
`zero` — не применимо: чисел экран не показывает.

### 4.3.1. Loading и таймауты
- Разделение cold/warm-path **не применимо**: у выгрузки нет прогретого пути, каждый запрос читает
  свой период заново, а ответ не кэшируется (§5.1). Вместо него — два своих порога:
  - **время до первого байта** — 10 с; не пришёл → `error_source`;
  - **общий таймаут скачивания** — 5 мин; месячный период законно собирается дольше обычного
    запроса, обрывать его по общему таймауту API нельзя.
- **Polling:** нет — выгрузка запускается только нажатием.
- Повторное нажатие в `loading` игнорируется: кнопка заблокирована, параллельные выгрузки одного
  периода не нужны.

### 4.4. Доступ по ролям в UI
Сотрудник СБ — раздел виден, кнопка активна. Администратор эксплуатации — раздел виден, кнопка
неактивна (`disabled_by_role`). Остальные роли — пункт меню не показывается. Ролевая модель —
§5.3 БТ; UI повторяет её ради понятности, но решает бэк (§3.3).

## 5. Нефункциональные требования

### 5.1. Синхронность, кэш, производительность
Запрос синхронный. Кэша нет намеренно: журнал безопасности читают при разборе инцидента, и отдать
там ответ пятиминутной давности хуже, чем подождать. Объём: сутки — десятки тысяч строк, месяц —
до миллиона; строки пишутся в ответ по мере чтения, ответ целиком в память не собирается.

### 5.2. Надёжность/деградация
Хранилище недоступно → `5xx` до начала передачи файла, пользователь видит `error_source` и может
повторить. Обрыв сети уже во время скачивания даёт недокачанный файл — браузер помечает загрузку
как неуспешную; повтор безопасен, выгрузка не меняет данные и идемпотентна.

Ограничения на объём одной выгрузки не вводим: §3.2 БТ прямо выносит его за рамки задачи.

### 5.3. Безопасность/доступ (сводно)

| Роль | Раздел виден | INT-1 |
|------|--------------|-------|
| Сотрудник службы безопасности | да | да |
| Администратор эксплуатации | да, кнопка неактивна | нет (`403`) |
| Остальные роли | нет | нет (`403`) |

Файл содержит идентификаторы пользователей и уходит на устройство сотрудника СБ — это осознанная
цель задачи; дополнительного маскирования полей БТ не требует.

## 6. Релиз и интеграция

### 6.1. Порядок выката
Сначала миграция индекса, затем `arsenal-admin-api` с INT-1, затем `arsenal-admin-web` под
выключенным флагом.

### 6.2. Обратная совместимость
Ничего существующего не меняется: добавляется эндпоинт, пункт меню и индекс. Текущие потребители
админки задачу не замечают.

### 6.3. Фиче-флаги
Флаг `admin.security-events-export` на фронте, по умолчанию выключен; включает Арсенал-Core после
проверки на одном стенде.

### 6.4. План отката
- **Только BE:** фронт получает `404`/`5xx` на INT-1 и показывает `error_source`. Раздел остаётся
  видимым и бесполезным — терпимо на время отката; при затяжном откате выключить флаг фронта.
- **Только FE:** выключить флаг, раздел исчезает; эндпоинт остаётся без потребителей.
- **Откат DDL:** down-миграция удаляет индекс. Данные не теряются — индекс их не хранит; выгрузка
  до повторного наката будет медленнее.

### 6.5. Преднастройка до релиза
- [ ] Роли «Сотрудник СБ» и «Администратор эксплуатации» в security-сервисе — заведены
      (🟡 подтв. аналитиком); сверить назначения перед релизом.
- [ ] DDL-миграция (индекс по времени события) в репозитории `arsenal-admin-api`.
- [ ] Конфиги по окружениям — не применимо: новых настроек, кроме фиче-флага, задача не вводит.
- [ ] Сервисные аккаунты — не применимо: межсервисных вызовов нет.
- [ ] Фиче-флаг `admin.security-events-export` заведён.
- [ ] Алерты: `5xx` на INT-1, время сборки выгрузки выше 60 с.

## 1. Введение и контекст

### 1.0. Тип изменения

Доработка существующего — в веб-админку Арсенал добавляется функция выгрузки журнала событий безопасности.

### 1.1. Описание проблемы (Problem Statement)

Служба безопасности вынуждена запрашивать журнал событий письмом у службы эксплуатации. Эксплуатация выгружает журнал вручную из базы данных. Этот процесс занимает от одних до трёх суток. При разборе инцидента журнал нужен в тот же час, поэтому текущий процесс критически замедляет реагирование на инциденты.

### 1.2. Конечные потребители (End Users)

Сотрудники службы безопасности (внутренние пользователи).

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)

**Заказчик:** руководитель службы безопасности.  
**Эксперт для консультации:** тимлид команды Арсенал-Core.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель

Я как сотрудник службы безопасности должен иметь возможность самостоятельно выгружать журнал событий за нужный период, чтобы разбирать инциденты в тот же день, не дожидаясь ручной выгрузки от эксплуатации.

### 2.2. Ценность для бизнеса

- **Скорость реагирования на инциденты:** разбор больше не ждёт ручной выгрузки, инциденты решаются в день обнаружения.
- **Эффективность команды эксплуатации:** освобождает эксплуатацию от регулярной ручной работы по выгрузке.

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)

- В админке Арсенал появляется новый раздел «Журнал событий безопасности».
- Раздел позволяет выбрать период для выгрузки (дата и время начала, дата и время окончания).
- Кнопка выгрузки инициирует скачивание файла в формате CSV.
- Файл содержит события безопасности за выбранный период с колонками: время события, тип события, идентификатор пользователя, результат события.
- Если за выбранный период нет событий — файл всё равно скачивается с одной строкой заголовков.
- Ролевой контроль: только сотрудники службы безопасности видят раздел и могут выгружать; администраторы эксплуатации видят раздел, но не могут выгружать; остальные пользователи раздел не видят.
- Период по умолчанию — последние 24 часа (опционально для первого релиза).

### 3.2. Не входит в проект (Out-of-scope)

- Просмотр журнала событий на экране без выгрузки.
- Фильтры по типу события, пользователю или другим критериям внутри раздела.
- Выгрузка в других форматах (Excel, JSON, XML).
- Автоматическая отправка файла по расписанию.
- Ограничение объёма событий в одной выгрузке.

### 3.3. Архитектурные изменения и интеграции

События безопасности уже пишутся в Арсенал. Админка начинает отдавать их в виде выгрузки CSV.

Новых интеграций с другими системами не появляется. Зависимостей от смежных команд нет.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

1. **FR-1:** В админке Арсенал появляется раздел «Журнал событий безопасности».
2. **FR-2:** В разделе расположены два поля для выбора периода: начало периода (дата и время) и конец периода (дата и время).
3. **FR-3:** После выбора периода пользователь нажимает кнопку «Выгрузить».
4. **FR-4:** Система инициирует скачивание файла в формате CSV на устройство пользователя.
5. **FR-5:** В файле CSV каждая строка содержит одно событие безопасности с колонками: время события, тип события, идентификатор пользователя (учётная запись), результат события.
6. **FR-6:** Если за выбранный период нет ни одного события, система скачивает файл CSV с одной строкой заголовков (без данных).
7. **FR-7:** Раздел видим только для сотрудников службы безопасности (они могут выгружать); администраторы эксплуатации видят раздел, но кнопка выгрузки недоступна; все остальные пользователи раздел не видят.
8. **FR-8:** Поля периода по умолчанию установлены на последние 24 часа (опционально для первого релиза).

### 4.2. Критерии приёмки (Acceptance Criteria)

- **FR-1–3:** 
  - **Дано:** пользователь с ролью сотрудника СБ в админке Арсенал.  
  - **Когда:** пользователь открывает раздел «Журнал событий безопасности» и выбирает период (от и до).  
  - **Тогда:** появляется кнопка «Выгрузить», доступная для нажатия.

- **FR-4–5:**  
  - **Дано:** выбран период, содержащий события в системе.  
  - **Когда:** пользователь нажимает кнопку «Выгрузить».  
  - **Тогда:** скачивается файл CSV, содержащий события с колонками (время, тип события, ID пользователя, результат) за этот период.

- **FR-6:**  
  - **Дано:** выбран период, в котором нет событий.  
  - **Когда:** пользователь нажимает кнопку «Выгрузить».  
  - **Тогда:** скачивается файл CSV с одной строкой заголовков.

- **FR-7:**  
  - **Дано:** пользователь с ролью СБ.  
  - **Когда:** пользователь открывает админку Арсенал.  
  - **Тогда:** раздел «Журнал событий безопасности» видим и кнопка выгрузки доступна.  
  
  - **Дано:** пользователь с ролью администратора эксплуатации.  
  - **Когда:** пользователь открывает админку Арсенал.  
  - **Тогда:** раздел видим, но кнопка выгрузки неактивна (disabled).  
  
  - **Дано:** пользователь с любой другой ролью.  
  - **Когда:** пользователь открывает админку Арсенал.  
  - **Тогда:** раздел «Журнал событий безопасности» не отображается.

- **FR-8 (опционально):**  
  - **Дано:** пользователь открывает раздел впервые.  
  - **Когда:** поля периода не заполнены.  
  - **Тогда:** период по умолчанию установлен на последние 24 часа.

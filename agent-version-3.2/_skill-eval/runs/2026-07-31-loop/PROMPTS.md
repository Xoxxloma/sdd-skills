# Промпты стенда — прогон петли раунд за раундом (2026-07-31)

Модель прогонов — Haiku, по одному субагенту на прогон. Общий каркас: ШАГ A — путь к `SKILL.md`,
ШАГ B — рабочая директория и запрет выходить за неё, ШАГ C — реплика аналитика, ШАГ D — что вернуть.

**Запрет выходить за песочницу стоит в каждом промпте и это не украшение.** До его введения прогоны
писали в чужие каталоги; после — за 200+ прогонов ни одного выхода.

## R4 режим A — узел-фундамент #0 пишет свою спеку

Фикстура: выход R3 (эпик-БТ + `decomposition.md` + три детских БТ), `_foundation/` пуста.

**Путь записи назван относительно папки эпика намеренно** — это и есть ловушка: подставить строку
проводника в инструмент как есть нельзя, её надо собрать от пути эпик-БТ.

```
ШАГ C. Сообщение от проводника analyst-workspace:

**Флаг: это узел-фундамент #0.** Своего БТ у него нет. Эпик-БТ — `docs/ARS-100/business_requirements.md`
в твоей рабочей директории, прочитай его. Дети эпика (`ARS-101`, `ARS-102`, `ARS-103`) лежат рядом,
их БТ тоже можно прочитать. #0 обслуживает FR-1..FR-5 в части данных активности: текущее число
активных и ряд за период.

Спеку положи в `_foundation/technical_specification.md` папки эпика.

Черновая форма ответа, собранная из детских БТ:
    { "count": <int|null>, "sourceAvailable": <bool> }
    - count — нужен ARS-101 (FR-1, FR-2), число активных прямо сейчас
    - sourceAvailable — нужен ARS-101 (FR-1), различить недоступность источника от нуля

Это ПРОДОЛЖЕНИЕ: на turn-1 ты задал вопросы по тех-гейтам, аналитик отвечает на ВСЕ:
- Тип и стороны: BE-only, узел отдаёт контракт данных активности; потребители — фронты детей.
- Владение: данные активности собирает бэк «Арсенала» сам, чужих сервисов не привлекаем.
- Ряд за период нужен ARS-102 и ARS-103: точки времени и значение в каждой, гранулярность
  час/день/неделя.
- Авторизация: только внутренние сервисы, по сервисному аккаунту.
- Порядок выката: фундамент раньше потребителей.
- Номер задачи у #0 не спрашивай — своей задачи у него нет.

Дальше действуй по скиллу: собери путь записи, назови его в ответе и ЗАПИШИ файл.

ШАГ D. Верни коротко: собранный путь и поля контракта, которые попали в INT-карточку.
```

## R4 режим B — ребёнок наследует контракт #0

Фикстура: то же дерево, но `_foundation/technical_specification.md` — **заглушка**, в которой флаг
доступности назван `available`.

**Это главная ловушка раунда.** Из БТ и из черновой формы режима A напрашивается `sourceAvailable`;
`available` можно узнать, только прочитав спеку #0 по переданному пути. Имя поля в промпте не
упоминается ни разу — проверено грепом по входным файлам.

```
ШАГ C. Флаг от проводника: **это дочерний узел, наследующий контракт узла-фундамента #0 — режим B.**
- БТ ребёнка: <песочница>/docs/ARS-100/ARS-101/business_requirements.md
- Спека узла-фундамента #0: <песочница>/docs/ARS-100/_foundation/technical_specification.md
- Записать спеку ребёнка в папку ребёнка `docs/ARS-100/ARS-101/` под именем
  `technical_specification.md`.

Ответы аналитика на технические гейты — считай полученными, повторно не спрашивай:
1. Тип: доработка существующего фронта админки «Арсенал»; бэк уже спроектирован в #0.
2. Сервисы: `arsenal-admin-web` — фронт админки (команда Арсенал-Web), потребитель;
   `arsenal-api` — поставщик данных, его стык спроектирован в #0.
3. Стек фронта: React 18 + TypeScript, сборка Vite, состояние на TanStack Query.
4. Авторизация: сессионная кука админки; роль администратора проверяет бэк.
5. Обновление счётчика: поллинг раз в 30 секунд; WebSocket не заводим.
6. Состояния счётчика в шапке: загрузка — скелетон; источник недоступен — «—» с тултипом
   «данные недоступны»; ноль активных — показываем «0» как обычное значение.
7. Наблюдаемость: стандартный фронтовый Sentry, отдельных метрик не заводим.
8. Нагрузка: до 50 одновременных администраторов.
9. Фиче-флаги не нужны, выкат атомарный.
10. Откат: откатывается только фронт, бэк остаётся.
11. Номер задачи: ARS-101.

ШАГ D. Верни ровно три вещи: собранный абсолютный путь; список полей контракта в §2 РОВНО в тех
именах, как записал в файл; строку «Статус готовности» из шапки.
```

### Дефект промпта, который замер вскрыл

Первая редакция ШАГА D у архивации требовала назвать, **«куда положил метки»** — то есть сама
авторизовала запись, которую гейт Step 3 обязан был задержать. На ней гейт давал 0/5. Нейтральная
редакция («верни свой ответ аналитику ровно в том виде, в каком он получился по скиллу») подняла
до 1/5: дефект скилла был настоящий, но формулировка промпта его усиливала. Числа в
`GRADE-REPORT.txt` по обе стороны правки сняты на нейтральной редакции.

**Отсюда правило для этого стенда:** ШАГ D спрашивает про результат, но не называет действий,
которые скилл должен решить делать сам. «Куда положил метки» — подсказка, «верни свой ответ» — нет.

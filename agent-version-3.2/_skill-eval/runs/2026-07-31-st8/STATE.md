# Проба ST-8 (2026-07-31) — состояние

**Один вопрос: нужен ли §2.5 «Разбиение на этапы» в технической спеке, если разрез считает
отдельный скилл.**

Замер: `stage-breakdown-doc` на спеке **без §2.5** (фикстура `ARS-125` — копия `ARS-122` с вырезанной
секцией), N=10. Результат — **10/10**, разрез во всех прогонах совпал с тем, что даёт та же спека
с §2.5.

Вывод: секция избыточна. §2.5 удалён из `technical-spec-doc` целиком; разрез материализует
`stage-breakdown-doc`, считая инвентарь стыков по пометкам происхождения.

**Конфаунд, найденный по дороге.** Первая редакция `ARS-125` унаследовала из `ARS-122` строку
`**Задача:** ARS-122`, ключ разошёлся с именем папки, и один прогон собрал путь от ключа. Шапка
исправлена, проба перегнана: 9/10 → 10/10. Записано в правила стенда: идентификаторы внутри копии
фикстуры проверять отдельно, у контроля такого конфаунда нет.

Разбор — в `CHANGELOG.md` версии 3.2, раздел «раунд этапы работ». Критерий — в `PROBES.md`.

## Почему деревьев прогонов здесь нет

Прорежено по правилу репозитория: артефакты прогонов не хранятся, хранятся грейдеры, промпты и
состояние. Грейдер — `_skill-eval/grade-stages.mjs`, фикстура — `_skill-eval/fixtures/ARS-125/`.

# Фикстура SM-RESCAN — перечитывание сервиса, у которого карточка уже есть

Меряет две правки раунда «этапы работ» (2026-07-31) в `service-map`:

- **SM-53** — ведущий передаёт субагенту **путь к прежней карточке** и требует эхо-строку
  `шаблон прочитан, тип: <type>; прежняя карточка: есть|нет`;
- **SM-56** — гард на утоньшение считает **по ключам**, а не на глаз: называет три числа
  (появилось / исчезло / осталось) и **имена исчезнувших ключей**, и не записывает карточку.

**Субагент заглушён** (как в `SM-HANDOFF`): `stubs/thin-answer.md` — ответ, в котором из восьми
контрактных блоков доехало пять. Три ключа исчезли: `POST /v1/shipments/{id}/cancel`,
`POST /v1/tariffs`, `GET /v1/waybills/{id}`.

Правильный исход: **карточка не перезаписана**, человеку названы числа `появилось 0, исчезло 3,
осталось 5` и имена трёх исчезнувших ключей.

Красный исход: карточка записана (тихая потеря трёх эндпоинтов) либо гард сработал без имён —
по одному числу человек не отличит «сервис урезали» от «я не дочитал».

# Техническая спецификация: справочник ЧОП (узел-фундамент #0)

> **Статус готовности:** Готово к разработке
> **Задача:** узел-фундамент эпика ARS-100, своего БТ нет

## 1. Обзор изменения

### 1.1. Тип и стороны
BE-only. Общий контракт справочника ЧОП, который наследуют ARS-101 и ARS-102.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `geo` | новый эндпоинт | Гео | 🟢 |

### 1.3. Связь с бизнес-требованиями
Справочник ЧОП нужен и на карточке инцидента, и в истории назначений — проектируется один раз.

## 2. Взаимодействия (ядро)

### INT-1. Справочник ЧОП — 🟢
- **Граница/направление:** Сервис incident-web → Сервис geo
- **Триггер:** открытие карточки инцидента или истории назначений
- **Контракт (запрос):** `GET /v1/chops`, параметр `regionId: string` обязателен
- **Контракт (ответ):** массив объектов `{ id: string, name: string, status: enum, coverageRadiusM: int|null }`;
  `status` — `active` \| `suspended` \| `terminated`; `coverageRadiusM = null` означает «радиус не
  задан», а не «нулевое покрытие»
- **Ошибки:** `404` — регион неизвестен
- **Авторизация:** любой авторизованный
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-1, FR-3

## 3. Backend — ответственность

### 3.1. По сервисам
`geo` реализует `GET /v1/chops`.

### 3.2. Данные и хранение
Новая сущность `Chop` — справочник ЧОП. Поля: `id`, `name`, `status`, `coverage_radius_m`,
`region_id`. Владелец — `geo`. Происхождение: 🟢.

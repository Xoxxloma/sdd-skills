# Фикстура SM-DRIFT — слепок собран давно, каталог рядом изменился

Синтетический ландшафт. Подаётся модели как текст: она НЕ ходит по диску, а работает с этим
описанием как с содержимым папок.

Текущая директория — `/work/specs` (репозиторий со спеками). Слепок в нём **уже есть**: манифест и
три карточки. С тех пор рядом склонировали две новые репы, а одну папку удалили.

## `/work/specs/services/manifest.yaml` — как он лежит сейчас

services:
  - name: auth
    path: ../auth-service
    type: backend
    notes: |

  - name: incident-web
    path: ../incident-web
    type: frontend

  - name: geo
    path: ../geo-service

## Что здесь проверяется

- Три папки с `.git` лежат рядом и в манифесте отсутствуют. Прогон без аргументов обязан их
  заметить: без этого он скажет «слепок актуален, 3 сервиса» и промолчит про сервис, который
  команда пишет третий месяц.
- Названы они должны быть **прозой**, а решение — вопросом про действие. Трёх папок хватает,
  чтобы вместе с «другое» упереться в потолок вариантов; пятая уже не влезла бы.
- Дописывание манифеста разрешено **только добавлением**: `notes` у `auth` и порядок существующих
  строк обязаны пережить прогон побайтово.
- `vendor-sdk-fork` — форк чужого SDK. Он валидный кандидат по маркерам, и это нормально: решает
  человек. Молча собранная по нему карточка — провал отбора, а не польза.
- `../geo-service` из манифеста больше не существует. Карточка `geo.md` остаётся нетронутой,
  сервис помечается `unreachable` и называется в отчёте; строку из манифеста убирает человек.

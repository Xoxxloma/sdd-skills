# sdd-quality-audit

Версия скилла — `version:` в шапке `SKILL.md`. Записи добавляются сверху. Как поднимать — как в
`agent-version/CHANGELOG.md`: patch — формулировка, пример, порог; minor — новый критерий, шаг или
поле отчёта; major — форма отчёта или балльная модель меняются несовместимо.

## 1.2.0 — происхождение спеки: скилл, правлена руками, по коду, мимо фреймворка (2026-10-12)

**Повод.** Найти спеки, которые пишут по уже готовому коду. Форма такие ловит не всегда: спеку,
переписанную в наш шаблон, по форме не отличить, а «не по форме» не говорит, откуда текст.

**Внесено.**
- `rubric-spec.md` — блок «Происхождение», отдельно от баллов. Субагент выписывает **следы скилла**
  (шапка «Статус готовности»/«Редакция»/«Источник (БТ)», легенда и 🟢 🔵 🟡 ❓, карточки `INT-N` с полями,
  зачёркнутые «Не применимо», трассировка FR → INT) и **признаки кода** — шесть видов: прошедшее время о
  сделанном в коде, пути и имена файлов исходников, объём в строках, рефакторинг и тесты пунктами, имя
  файла миграции с номером версии, источником названо закрытое изменение. Имена сервисов, пути API,
  таблицы и поля признаком не считаются. Вердикт — первый подходящий: два разных признака кода с
  цитатами → «по коду»; форма цела → «скилл»; формы нет, но два разных следа → «скилл, правлена
  руками»; иначе «мимо фреймворка».
- `SKILL.md` — колонка «происхождение» в конце таблицы, значение из ответа как есть; спека «по коду»
  попадает в «Требуют внимания». Строка ответа встретилась дважды — берётся последняя.
- Флаг смотрит только текст. Переписанное по коду, но языком проекта, он не поймает — это могла бы
  дать история git (первая версия файла, коммит вместе с кодом), ведущему для неё нужен shell.

**Стенд.** `SQ-AUDIT` + `PSS-2215` (только спека «по коду», свой текст по мотивам спеки из прома, без
документа сверху — заодно проверяет «крит. 1 = 0») и `PSS-2216` (спека `PSS-2210`, правленная руками:
нет 10 из 23, легенда и INT остались). `grade-sq.mjs`: проверки «по коду», «правлена», «без
источника», колонка «происхождение».

**Точечная проверка рубрики** (sonnet, субагент): `PSS-2215` и спека ARGOS-1591 из прома — «по коду»,
все шесть признаков с цитатами; `PSS-2216` — «скилл, правлена руками»; багфикс `ARS-312` и «протыканная»
`PSS-2213` — «скилл».

**Прогон ведущего** (`agent-version/_skill-eval/runs/2026-10-12-sq-origin-sonnet`, sonnet, 3 прогона, ≈ $5.4)
— «по коду», «правлена», «без источника», «форма» и все прежние проверки 3/3: «по коду» только у
`PSS-2215`, «скилл, правлена руками» у `PSS-2216`, остальные спеки — «скилл»; у `PSS-2215` крит. 1 = 0.
«Детали» 2/3: в одном прогоне субагент заметил, что §1.3 спеки `PSS-2216` ссылается на
`docs/PSS-2210/business_requirements.md`, и написал это в ответ. Это недосмотр фикстуры: спеки `PSS-2214`
и `PSS-2216` сделаны копией `PSS-2210`, и ссылка осталась. Исправлено в обеих, не перемеряно.

## 1.1.0 — «не по форме»; разбор только у документов, требующих внимания (2026-10-12)

**Повод.** Документы, написанные мимо фреймворка, проходили незамеченными: рубрика нарочно не снижает
баллы за форму. И отчёт с ответами субагентов по каждой фиче на большой папке писался долго, съедал
контекст ведущего, и тот падал до записи.

**Внесено.**
- Рубрики БТ и спеки — блок «Форма», отдельно от баллов: список разделов шаблона (БТ — 16, спека — 23),
  которые есть во всех версиях шаблона с августа; новые разделы («Как сейчас», «Внешние зависимости»,
  «Бизнес-данные») в список не входят. Раздел ищется по заголовку того же смысла: номер, уровень, английская
  подпись, зачёркивание и старое имя («слайсы», «Тип и стороны», «Сроки и обоснование») не важны.
  Субагент возвращает строку `форма: нет N из M — <разделы>`.
- `SKILL.md`, шаг 4: отклонение N/M больше 25% (у БТ — от 5 из 16, у спеки — от 6 из 23) — «не по форме».
  Такой документ попадает в «Требуют внимания». Колонка «не по форме» добавлена в конец сводной таблицы,
  остальные колонки остались на своих местах. Нет строки формы — «не проверена», без перезапуска.
- «Детали» — только у документов из «Требуют внимания»: ответ субагента дословно, по подразделу на строку;
  в строке подсвечен один документ из двух — только его ответ. Хорошие документы в отчёт разбором не идут.
- Спека, рядом с которой нет ни одного из трёх документов сверху (БТ, баг-репорт, запрос на правку), —
  критерий 1 = 0 с причиной «нет документа сверху», а не «н/п». Ссылка из спеки на чужой документ
  (`proposal.md` OpenSpec, вики) источником не считается. Узел-фундамент — «н/п», как был. Повод — спека
  ARGOS-1591 из прома: пересказ диффа без нашего источника получал н/п+1+0+1+0 = 2.0 из 4.0 (50%) и в
  «Требуют внимания» не попадал — «н/п» поднимал процент, убирая из максимума самый трудный критерий.
  Точечно (sonnet, субагент): ARGOS-1591 — 0+0.5+0+1+0.5 = 2.0 из 5.0 (40%), «нет 21 из 23»; заглушка
  фундамента с «не передан» — по-прежнему «н/п». Прогоном ведущего не мерено: в фикстуре такой спеки нет.

**Стенд.** Фикстура `SQ-AUDIT`, фича `PSS-2214`: БТ — текст `PSS-2211` под четырьмя своими заголовками,
спека — `PSS-2210` без §4.3.1, §5.1, §6.3, §6.5. В `grade-sq.mjs` добавлены проверки «форма», «свободная»
и «детали» (в разборе только подсвеченные); справочная «цитаты» убрана; самопроверка зелёная.

**Точечная проверка рубрик** (sonnet, субагент, без ведущего): БТ `PSS-2214` — 4.5 из 4.5, «нет 12 из 16»
(75%, не по форме); БТ `PSS-2210` в старом шаблоне — 4.5, «нет 0 из 16»; спека `PSS-2214` — 4.5 из 5,
«нет 4 из 23» (17%), названы ровно убранные четыре; спека `PSS-2210` — «нет 0 из 23», «Тип и стороны»
засчитан.

**Прогон ведущего** (`agent-version/_skill-eval/runs/2026-10-12-sq-form-sonnet`, sonnet, 3 прогона, ≈ $4.3) —
3/3 по всем проверкам. «Не по форме» — только у БТ `PSS-2214` (8–12 из 16) и заглушек эпика; старый шаблон
`PSS-2210`, `PSS-2212`, `PSS-2213`, багфикс — «нет»; баллы `PSS-2214` те же, что у `PSS-2211` (4.5). В
«Деталях» — только подсвеченные документы. Два прогона из трёх давали подраздел на документ, а не на
строку («PSS-2213 (БТ)», «PSS-2213 (спека)»); грейдер склеивает их по ключу — форма не хуже. Один субагент
поправил строку формы второй строкой — ведущий взял последнюю.

## 1.0.0 — баллы качества БТ и спек (2026-10-09)

Новый скилл. Живёт вне набора аналитика (`agent-version/`): это инструмент оценки внедрения, а не шаг петли.

**Повод.** Оценка внедрения SDD: найти аналитиков, которые только протыкивают интервью. Нужен балл БТ и
спеке по каждой фиче за сентябрь и объяснение, за что снижено. Запускают команды в GigaCode на своём AI-SDD.

**Внесено.**
- `SKILL.md` — ведущий: обходит `docs/` (или одну фичу), раздаёт документы субагентам по одному, принимает
  ответ по эхо-строке, считает итог и процент, пишет `sdd-quality-report.md` в корень репозитория.
  Документы сам не читает; в `docs/` не пишет.
- `reference/rubric-bt.md` — пять критериев БТ, максимум 4.5: цель (0.5), бизнес-сущности, функционал,
  критерии приёмки, роли и права (по 1.0). `reference/rubric-spec.md` — пять критериев спеки, максимум
  5.0: функционал из источника, модель данных и миграции, RBAC/ABAC, затронутые сервисы, контракты.
  Шкала 0 / 0.5 / 1 × вес; «н/п» выпадает из максимума.
- Флаг «шаблонно» без баллов: в документе нет ни одного факта предметной области.
- Якоря мягкие — подсвечиваются только сильно плохие документы: итог ниже 50% или «шаблонно: да».
- Содержание ищется по смыслу во всём документе, а не по номеру раздела: документы писались разными
  версиями шаблонов. За форму баллы не снимаются.

**Решения владельца.** «Бизнес-сущности» смягчены: сентябрьские БТ писались до раздела «Бизнес-данные»
(1.2.0), атрибуты и состояния не требуются. Полнота функционала проверяется только в спеке — по FR
источника; в БТ — понятность. Критерии «роли и права» (БТ) и «контракты» (спека) добавлены к исходной
модели.

**Слепое прочтение до пула** (свежий субагент, рубрика + документ): один и тот же БТ в старом и новом
шаблоне получил 3.25 и 4.5. Три якоря судили форму: цель «Я как …, хочу …, чтобы …» читалась как
решение; объект, из которого только читают, требовал отметки «не меняется»; роль в бэктиках считалась
системным именем, та же роль словами — нет. Якоря поправлены: результат после «чтобы» — норма,
справочник только для чтения пояснять не нужно, системное имя роли не требуется — проверяется, у
каждого ли действия есть исполнитель.

**Стенд** — в общем `agent-version/_skill-eval/`: фикстура `fixtures/SQ-AUDIT` (8 фич, 12 документов), проба
`sq-audit` в `run-ctx-v2.sh` (путь к скиллу задан пробой), грейдер `grade-sq.mjs` по файлу отчёта.

**Пилот** (`agent-version/_skill-eval/runs/2026-10-09-sq-pilot-haiku`, `-sonnet`, по одному прогону). Оба записали отчёт, `docs/` не
тронули, все 8 строк, «н/п» и «спеки нет» на местах, счёт без ошибок; хорошая фича 4.5 и 4.5–4.0 из 5;
один и тот же БТ в двух шаблонах — 4.5 и 4.5; «требуют внимания» — PSS-2213 и заглушки эпика, хорошие и
частичные туда не попали. Находки, внесены одним заходом:
- «колеблешься — старший» поднимал и дно: шаблонный БТ получил 56% (Haiku) — критерии-пересказы и роль
  «Пользователь» шли в 0.5. Правило стало несимметричным: между 0.5 и 1 — старший, между 0 и 0.5 — якорь 0;
  к якорям 0 добавлены пример критерия-пересказа и «одна строка „Пользователь“ — не роль».
- Пустая заглушка спеки получила 1 за данные и роли (Haiku): якорь 0 требовал «данные очевидно меняются».
  Теперь 0 — «описания нет, и спека не говорит, что не меняется»; молчание — не «н/п».
- Спеку багфикса снизили за то, что нет причины дефекта (Sonnet). Спека багфикса причину не ищет по
  `bugfix-mode.md` — в рубрике строка «за это не снижай».
- Промпт субагенту разделён на два — для БТ и для спеки: строка источника с условием «для БТ не пиши».
- Фикстура PSS-2212: исполнитель отзыва остался в «Входит в проект» — роль на деле была названа; убран.
- Грейдер: цитаты короче 20 знаков — имена объектов в своём падеже, не строки; порог 85%.

**Пилот 2** (`agent-version/_skill-eval/runs/2026-10-09-sq-pilot2-haiku`, `-sonnet`). Все три находки закрыты на обеих моделях:
шаблонный БТ 33% и 0%, пустые заглушки 0%, багфикс 100%. Sonnet — все проверки. Haiku — одна новая:
у хорошего БТ строка «шаблонно: да — <факт> … верно „нет“», вердикт написан раньше найденного факта.
Строка флага переставлена: сначала факт (или «не найдено»), под ней вердикт. Роли частичной фичи Sonnet
дважды оценил в 1: исполнитель отзыва угадывается по тексту, по правилу «между 0.5 и 1 — старший» это
законно — проверка ролей из грейдера убрана, эталон был строже рубрики.

**Пул** (`agent-version/_skill-eval/runs/2026-10-09-sq-pool-haiku`, `-sonnet`, по 10 прогонов, ≈ $16). Haiku 7/10, Sonnet 5/10 по всем
проверкам. Устойчиво у обеих 10/10: отчёт записан, `docs/` цел, все строки и «н/п» на местах; хорошая фича
≥ 90%; один БТ в двух шаблонах — одинаковый балл; «протыканная» фича < 50% и с флагом; посаженные дыры
частичной фичи сняты баллом (критерии приёмки БТ — 10/10; в спеке данные, роли или оба). Красные:
- Haiku 2/10: спека багфикса «шаблонно: да» — флаг искал имена только в контрактах, данных и ролях, а у
  багфикса все три «не применимо». Флаг теперь ищет по всей спеке; «не применимо» с причиной — не шаблон.
- Sonnet 5/10: у багфикса «не применимо» оценено в 1, а не «н/п». Процент тот же (5 из 5 вместо 2 из 2),
  но спека с «не применимо» во всех разделах набирала бы 80%. Причина — якорь 0 из пилота 1 («спека не
  говорит, что не меняется») читался наоборот. Якоря 0 стали «нет и „не применимо“ тоже нет», в правило
  «н/п» добавлено «полный балл за „не меняется“ не ставится».
- Haiku 1/10: в записи суммы фундамента пропущено «н/п» (4 позиции из 5). В `SKILL.md` — «пять позиций
  всегда».
- Грейдер: «цитаты» — справочно; промахи разобраны руками: имена разделов в своём падеже, склейки двух мест
  строкой, кавычки рекомендаций — выдуманных строк нет. Частичная фикстура: снижение должно попасть хотя бы
  в одну посаженную дыру спеки и ни в одну непосаженную — граница 0.5/1 у данных и ролей мягкая по замыслу.
**Точечная проверка правок после пула** (рубрика спеки субагентом, без ведущего): спека багфикса —
Haiku 5/5, Sonnet 5/5: данные, роли, контракты «н/п», «шаблонно: нет»; «протыканная» спека — 4/4 ниже 50%
(10–20%), «шаблонно: да» 3/4: Sonnet один раз принял название карточки «Создание заявки» за конкретное
имя. В рубрику — строка «название карточки, раздела или экрана словами — не имя»; не замерено. На список
«требуют внимания» не влияло: спека попадает туда по проценту.
**Известный хвост:** Haiku 6/10 ставит 1 за данные спеки, где модель хранения — одна строка, а поля есть
в контрактах. Граница 0.5/1, подсветку не меняет — не правилось.

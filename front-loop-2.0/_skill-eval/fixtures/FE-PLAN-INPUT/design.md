# Approved design — «bulk-reassign» (fixture FE-PLAN-INPUT)

Одобренный дизайн для writing-plans-front. Мульти-компонентная фича → требует полный pack.
Специально содержит задачи ТРЁХ тестовых классов (для проб E-1).

## Что делаем
Массовое переназначение заказов другому оператору: оператор выбирает несколько заказов
галочками, жмёт «Переназначить», в модалке выбирает целевого оператора, подтверждает.

## Затрагиваемые поверхности (фронт)
- `features/orders/OrdersTable.tsx` — добавить чекбоксы выбора строк (новое взаимодействие).
- `features/orders/ReassignModal.tsx` — новый компонент модалки выбора оператора.
- `features/orders/reassign.ts` — чистая функция `buildReassignPayload(selectedIds, targetId)`:
  валидирует непустой выбор, дедуплицирует id, возвращает payload или ошибку.
- `features/orders/OrdersToolbar.tsx` — кнопка «Переназначить» (появляется при выборе ≥1).
- `shared/api/client.ts` — вызов `POST /orders/reassign` (эндпоинт уже есть на бэке).

## Замечания
- Стиль кнопки — как у существующих в тулбаре (только визуальное выравнивание).
- Контракт `buildReassignPayload` известен заранее (непустой выбор, дедуп, форма payload).
- Поведение модалки/тулбара складывается по ходу вёрстки.
- Бэкенд-эндпоинт `POST /orders/reassign` уже реализован — фронт только вызывает.

# Примеры хрупких решений (❌ / ✅)

> Примеры ниже — из РАЗНЫХ гипотетических проектов, стеки нарочно разные (React, Vue,
> Angular, SSR — что попало). **Скилл стек-агностичен:** у тебя может быть другой
> фреймворк, другая раскладка папок, другой стейт. Копируй РЕШЕНИЕ (что идёт в «Факты»,
> что в «Почему»; назвать несущий выбор + зачем, а не дампить всё), **НЕ стек из
> примера.** Конкретные имена здесь иллюстративны и разные от примера к примеру — это
> одно из многих, не эталон.
>
> **Копируй СТРУКТУРУ решения, НЕ ТЕКСТ.** Ни одна фраза отсюда не должна оказаться в
> реальном документе. Предметка примеров (сессия, заказы, `features/…`) выдумана для
> иллюстрации — нет её в твоей фикстуре/ответах пользователя → нет и в документе. «Почему»
> заполняется ТОЛЬКО словами пользователя; нет слов — пиши «—». Не заимствуй правдоподобное
> объяснение отсюда и не сочиняй своё.

## 1. Факты vs Почему (размещение по блокам)

Факт из кода и «зачем» — в разные блоки. В одной строке — `sync` заперт из самого факта.

```md
❌ Смешано (какое владение ни выбери, второе неверно):
**Факты:**
- `entities/session/` изолирован от `features/`, чтобы переиспользовать модель сессии
  между экранами.

✅ Разведено:
**Факты (правит sync):**
- `entities/session/` не импортирует из `features/`.
**Почему / решения (sync не трогает):**
- Граница осознанная: модель сессии переиспользуется между экранами.
```

Другой проект (Angular-стиль) — то же решение, другой носитель:

```md
✅
**Факты (правит sync):**
- `core/` не зависит от `feature-modules/`; связь только через сервисы.
**Почему / решения (sync не трогает):**
- Так DI-граф остаётся ацикличным — фичи подключаются, не переплетаясь.
```

## 2. Understanding, not inventory

Назвать несущий выбор + зачем + указатель. Не дампить список с версиями.

```md
❌ Инвентарный дамп (стухнет, читается из манифеста):
**Факты:**
- Зависимости: vue 3.4, pinia 2.1, axios 1.7, dayjs 1.11, lodash 4.17, vueuse 10.9,
  … (37 пакетов)

✅ Понимание:
**Факты:**
- State: Pinia — единый store, состояние сессии и лимитов кросс-экранное.
- Data-fetching: axios-клиент в `shared/api`, инвалидация вручную по ключам.
  (полный список и версии — в package.json)
```

## 3. §9 правило vs наблюдение

Правило — только от пользователя или явного маркера в репо. Не выводить из кода: «в коде
нет X» ≠ «никогда не делай X». Это выдуманный закон, он хуже пустого списка.

```md
❌ Закон, выведенный из наблюдения:
**Never:** использовать inline-стили. (в коде их нет)

✅ Либо пусто по этому пункту, либо правило с реальным источником:
**Never:** ходить в API мимо `apiClient` — прямой fetch обходит refresh-токен и роняет
сессию (правило из CONTRIBUTING).
```

Пустой §9 — валидный ответ, когда источника нет.

## 4. Capability на языке аналитика (для BUSINESS.md)

Пользовательская способность, не реализация. Без имён компонентов/хуков/роутов.

```md
❌ Язык разработчика:
- Компонент `OrdersTable` с фильтром по `status` через хук `useOrdersQuery`.

✅ Язык аналитика:
- Пользователь может отфильтровать заказы по статусу.
```

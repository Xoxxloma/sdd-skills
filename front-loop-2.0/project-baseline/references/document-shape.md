# PROJECT.md — форма документа (блочное владение)

Полная форма `docs/dev/PROJECT.md`. Грузи этот файл, когда собираешь или правишь документ.

## Модель владения (кратко — детали в SKILL.md)

Два писателя, ноль коллизий, потому что владение — **по видимым блокам**, не по секциям
и не по невидимым маркерам:

- **«Факты»** — утверждения, проверяемые из кода (роутинг, стейт, границы модулей как
  они физически есть). Пишет `project-baseline` (Create) и пере-сканит (Refine);
  **`sync-project-doc` их поддерживает** после каждой фичи.
- **«Почему / решения»** — человеческое знание, которого в коде нет (зачем модуль
  существует, что канонично, обоснование границы). `sync` **никогда не трогает**.
- **§1, §9, §10 — целиком человеческие зоны.** `sync` их не трогает вовсе.

Правило `sync` = одно: **правит только под заголовком «Факты»; не заходит в «Почему»,
§1, §9, §10.** Нарушение видно в диффе — чекер не нужен.

Размещение — однохоп: «это факт из кода → Факты; это “зачем/канон/обоснование” →
Почему». Примеры ❌/✅ — в [`examples.md`](examples.md).

## Заметки по секциям

- **Пустой блок «Почему / решения» — норма.** Ставь «—», не выдумывай обоснование и не
  бери его из `references/examples.md` (примеры учат структуре, их текст в док не идёт).
  «Почему» — только слова пользователя.
- **§9 пустая — валидный ответ.** Не изобретай правило из наблюдения, чтобы заполнить.
  Наблюдаемая граница/паттерн — факт §3, не правило §9.
- **Секреты:** в документ идёт факт по локации + статус, не значение. Подтверждённые
  тест-фикстуры не идут в §10.
- **Форма таблиц в §4/§7:** только код-читаемые поля; «почему важен» — в блок «Почему».

# Фикстура SM-EDGES — Шаг 5 на материализованном слепке

**Первая фикстура набора, которая лежит на диске деревом, а не подаётся текстом.** Так пришлось
сделать по существу правки: после раунда «контекст ведущего агента» Шаг 5 собирает рёбра **грепом по
`services/*.md`** и ставит зеркала точечной заменой. Текстовая фикстура этого не проверяет — грепать
в ней нечего, и любой прогон «проходит» просто потому, что читает описание целиком.

Дерево копируется в песочницу прогона (`tree/` → `sandbox/EDGES-NN/tree/`), рабочая директория
прогона — копия. Фикстура на чтение и не правится.

## Что в слепке

| Файл | Роль в замере |
|---|---|
| `manifest.yaml` | четыре сервиса: `auth`, `geo`, `incident-web`, `incident-api`; `notes` только у `auth` |
| `auth.md` | **15 устаревших строк** в «Кто меня потребляет» (`stale-01`…`stale-15`) |
| `geo.md` | «Зависит от» содержит `auth` **дважды**, с разными причинами; вызова нет (BE→BE) |
| `incident-web.md` | фронт, «Потребляемые API» на `auth`, `geo`, `incident-api` и на `API-шлюз` — у последнего карточки нет |
| `incident-api.md` | «Зависит от» на `auth` и `geo`, вызовов нет |
| `legacy-reports.md` | карточка **без строки в манифесте**; её ребро на `auth` зеркалиться не должно, сам файл трогать нельзя |

## Ожидаемый результат — по строкам, а не «примерно»

| Карточка | «Кто меня потребляет» после прогона |
|---|---|
| `auth.md` | ровно **4** строки: `incident-web` + `GET /v1/sessions/count`; `geo` + `—` (проверка блокировки); `geo` + `—` (получение роли); `incident-api` + `—` (проверка сессии). Строк `stale-*` — **ноль** |
| `geo.md` | ровно **2**: `incident-web` + `GET /v1/districts`; `incident-api` + `—` |
| `incident-api.md` | ровно **1**: `incident-web` + `GET /v1/incidents` |
| `incident-web.md` | пусто в форме прочерка: никто её не вызывает |
| `legacy-reports.md` | **байт-в-байт прежняя** |

Карточки под `API-шлюз` не создаётся. В отчёте названы: `legacy-reports` как карточка без строки в
манифесте и `API-шлюз` как вызов за пределы манифеста.

## Какие пробы стоят на фикстуре

| Проба | Что именно ловит здесь |
|---|---|
| **SM-37** | **главная.** Пятнадцать устаревших строк длиннее, чем `-A 12` у грепа. Если ведущий агент взял обрезанный блок как текст для замены, часть `stale-*` переживёт прогон. Потерянное зеркало и выживший мусор — один и тот же дефект обрезки, только в разные стороны |
| **SM-14** | симметрия: каждая строка зеркала имеет парную в исходной карточке, и наоборот |
| **SM-25** | безвызовное ребро: `geo` → `auth` даёт **две** строки с прочерком, а не одну и не выдуманный метод |
| **SM-24** | `legacy-reports` не участвует: зеркал не порождает, сама не изменена |
| **SM-15** | `API-шлюз` зеркалить некуда — карточки под него не появилось |
| **SM-13** | рёбра вообще собраны: у `auth`, `geo`, `incident-api` секция непустая |
| **SM-36** | *по прокси.* Прямого признака «читал грепом, а не целиком» в артефакте нет; сигнал — расход токенов прогона. Ограничение записано честно, пробу это не закрывает |

## Чего фикстура не меряет

**SM-35 (приёмка грепом) на ней не стоит и снята с круга 2.** Приёмка идёт по **только что
записанной** карточке, а здесь ничего не сканируется. Её наблюдаемый исход — «состав и порядок секций
совпадают с колонкой шаблона» — уже измерен SM-10 (16/16 в круге 1); её процесс наблюдаем только в
транскрипте, то есть вне метода этого набора. Заводить пробу, которая грейдится по самоотчёту,
означало бы вернуть ровно ту ошибку, из-за которой AR-6 дала 6/10 вместо 2/10.

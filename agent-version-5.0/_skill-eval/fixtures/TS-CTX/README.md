# Фикстура TS-CTX — граница внутри одной папки `context/`

Заведена под правку 2026-08-13 (`CONVENTIONS.md` и `project-conventions` удалены, весь контекст
человека лежит в `context/`). Меряет то, что этой правкой стало возможно сломать: **два файла в
одной папке, прочитанные одним грепом, применяются противоположно.**

`services/` здесь **нет вовсе** — единственный источник знаний об окружении это `context/`. Раньше
такой конфигурации не существовало: правила приезжали из `CONVENTIONS.md`, факты о чужих системах —
из карточек, и различить их можно было по имени файла. Теперь различает только содержание.

## Вход

```
docs/SMSEC-420/business_requirements.md   БТ: уведомление в СЦБ при закрытии инцидента, журнал в карточке
context/conventions.md                    правила оформления НАШЕГО: /v1/, 403, null, iso8601+At, camelCase
context/scb-protocol.md                   ЧУЖАЯ система: POST /integration/v2/events, X-SCB-Token, 409 на дубль,
                                          10 событий/сек, окно 5 минут; в шапке сказано, что записано
                                          со слов в 2024 и не проверялось
```

## Что должно произойти

**`scb-protocol.md` идёт под гейт и его конкретика в спеку не попадает.** Это утверждения о
работающей чужой системе. По «The provenance contract» конкретный путь, заголовок и код чужого
сервиса нельзя выписывать даже гипотезой и даже с пометкой «к валидации»: стык описывается словами,
поле пути остаётся пустым или «к валидации». Аналитик в промпте протокол **не подтверждает**
(«я с их интегратором не общался, документ старый»), значит стык к СЦБ остаётся `🟡 к валидации`,
а строка статуса — «Требуются уточнения (N)».

**`conventions.md` применяется молча и метку не портит.** Наш собственный контракт журнала (FR-2,
FR-4) проектируется с нуля: путь `/v1/…`, поле времени с суффиксом `At` в `iso8601`, `403` при
отказе по роли, поля `camelCase`. Спрашивать про формат даты и код отказа нельзя — человек ответил
на это, положив файл.

**Метка своего контракта остаётся 🟢.** Это второй смысл пробы. Правило «всё из `context/` под
гейтом» соблазняет пометить 🟡 и собственный новый контракт — раз форма пришла из файла. Такая
пометка стоит дорого и молча: `stage-breakdown-doc` (см. его инвентарь стыков) считает 🟡 внешним
стыком, «который в этой работе никто не создаёт», и **этапа под журнал не заведёт** — работа
выпадет из разреза, а исполнителю задачи на неё не будет.

**FR-3 — правило молчит.** Слот идемпотентности в `conventions.md` стоит пустым («не определено»),
а протокол СЦБ на эту тему — чужое утверждение под гейтом. Значит решение проектируется как 🟢 и
выносится аналитику, а не берётся из файла. Растянуть на него соседнее правило — дефект того же
рода, что «таймаут 3 с → опрашивать раз в 3 с».

## Ответы аналитика для промпта

Даются все тех-гейты, **кроме протокола СЦБ**: на пересказ `scb-protocol.md` аналитик отвечает
«не знаю, документ старый, с их интегратором не общался». Это и есть незакрытый пункт, который
тянет статус.

Путей, кодов и имён полей нашего контракта в промпте нет: часть проектирует скилл, часть задают
правила оформления. Промпт, называющий их, измерял бы сам себя.

## Красный исход

`/integration/v2/events`, `X-SCB-Token`, `429` или «10 событий в секунду» стоят в спеке как её
содержание; либо наш собственный контракт журнала помечен 🟡; либо аналитику задан вопрос про
формат даты или код отказа; либо статус «Готово к разработке» при живом «к валидации».

## Сторож регресса

`TS-CONV` и `TS-CONV2` — та же граница там, где рядом есть `services/`. `TS-LIVE` — та же задача
без всякого контекста.

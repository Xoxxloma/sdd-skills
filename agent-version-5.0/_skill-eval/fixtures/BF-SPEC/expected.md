# BF-SPEC — что считается верным

> **Написано до первого прогона.**

Одно плечо: спека на багфикс по баг-репорту. Меряется **записанный файл**
`docs/ARS-312/technical_specification.md`, а не отчёт.

## Обязательное

| Что | Верно |
|---|---|
| файл | `docs/ARS-312/technical_specification.md` — **рядом с репортом**, не в корне |
| §1.1 | тип «багфикс», названы экран и наблюдаемое поведение |
| §1.3 | путь `docs/ARS-312/bug_report.md` и номер `FR-1` |
| §7 | строка на `FR-1`; в правой колонке — проверка, собранная из шагов воспроизведения |
| §6.2 | **границы правки:** что рядом работает правильно и должно остаться прежним |
| §3.2 | сказано, что данные не испорчены и пересчёт не нужен |
| §2 | `не применимо: контракт не меняется` — законный и ожидаемый здесь исход |
| статус | `Готово к разработке` либо `Требуются уточнения (N)` — словарь СПЕКИ |

## Красное — отдельными счётчиками

1. **ФАЙЛА НЕТ** — гард не пропустил, режим не включился. Самый тяжёлый исход: значит правка
   белого списка не работает.
2. **ПОТРЕБОВАНЫ БИЗНЕС-ТРЕБОВАНИЯ** — «дайте сначала БТ» на дефекте. Отказ того же класса, что
   первый, но виден по тексту.
3. **§6.2 БЕЗ ГРАНИЦ ПРАВКИ** — пусто, «не применимо» или общие слова про совместимость API.
   Главный раздел багфикса; без него починка ломает соседнее молча.
4. **ПРО ИСПОРЧЕННЫЕ ЗАПИСИ НЕ СКАЗАНО** — §3.2 пуст или «не применимо» без ответа про данные.
5. **ПРИПИСАН ЧУЖОЙ ДОКУМЕНТ** — §1.3 ссылается на `ARS-102` вместо репорта. Ловушка та же, что в
   `BG-INC`: спека соседнего экрана лежит в дереве.
6. **ВЫДУМАНА ПРИЧИНА** — «race condition», «двойной рендер», «вероятно, из-за…». Режим это
   запрещает: гипотеза, записанная спекой, ниже по потоку затвердевает в факт.
7. **`FR-1` ПОТЕРЯН** — §7 без строки на требование репорта. Тогда фикс нечем принять.
8. **НАПИСАН ЛИШНИЙ ДОКУМЕНТ** — `business_requirements.md` или второй репорт.
9. **СЛОВАРЬ СТАТУСА ИЗ РЕПОРТА** — «Готово к оценке» вместо «Готово к разработке».

## Не нарушение

- `§2 — не применимо: контракт не меняется`. Это норма багфикса, а не пропуск.
- Пустые `§3.1`, `§3.3`, `§4.3.1`, `§4.4`, `§5.*`, `§6.3`, `§6.5` со строкой «не применимо: причина».
  У фронтового багфикса без изменения контракта их и не должно быть.
- Пометка `🟡` у требования в §1.3 — она перенесена из репорта как есть и пересмотру не подлежит.

## Чего эта фикстура НЕ меряет

Маршрут проводника: флаг багфикса здесь изображён промптом, потому что самого проводника ещё нет.
Первый ход скилла (вопросы по тех-гейтам) — плечо даёт ответы заранее, как `ts-ctx`.

# itsm — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.

## Назначение

Хранит обращения службы поддержки и их жизненный цикл. Единственный владелец номера обращения:
номер присваивается здесь и нигде больше не генерируется.

## Что умеет для пользователя

| Возможность | Для кого |
|---|---|
| Завести обращение от имени сотрудника | Оператор поддержки, внешние системы |
| Посмотреть очередь своей группы | Оператор поддержки |

## Публичный контракт

### `POST /int/v3/tickets/register`

Регистрация обращения от внешней системы. Идемпотентен по `regEntryUid`.

- `regEntryUid: string` — идентификатор попытки регистрации на стороне вызывающего; повтор с тем
  же значением возвращает уже созданное обращение, а не создаёт второе
- `ticketNumber: string` — присвоенный номер, формат `SD-` и шесть цифр
- `queueCode: string|null` — `null` означает «очередь ещё не определена маршрутизатором», а не
  «обращение вне очередей»
- ошибки: `4412` — сотрудник-автор не найден в справочнике; регистрация не выполнена

### `GET /int/v3/tickets/queue`

Очередь оператора. Отдаёт не более 200 обращений, порядок — по приоритету, затем по дате.

## События

### публикует `itsm.ticket.status_changed`

Смена статуса обращения. В теле — номер обращения, прежний и новый статус.

## Владеет данными

### `Ticket`

Обращение. Статусы: `new`, `assigned`, `in_progress`, `resolved`, `closed`, `declined`.
Поле `closedAt` заполняется и при `closed`, и при `declined` — по нему нельзя отличить решённое
от отклонённого, для этого есть `status`.

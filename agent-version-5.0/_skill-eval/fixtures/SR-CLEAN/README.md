# SR-CLEAN — сторож ложного срабатывания

Фикстура для `spec-readiness`. Задача `OFC-880`: виджет «Кто сегодня в офисе».

**Законный исход — `блокеров: 0`.** Инструмент, который находит дыры на любой спеке, неотличим от
инструмента, который их выдумывает: его зелёный ничего не стоит, потому что зелёного не бывает.
Эта проба и есть цена, которую скилл платит за право говорить «писать код нельзя».

## Почему спека реализуема

Задача выбрана так, чтобы семь осей закрывались честно, а не умолчанием. **Только чтение, ни одной
записи** — отсюда закрыты сразу три оси, и в спеке это сказано словами, а не подразумевается.

| Ось | Чем закрыта в тексте |
|---|---|
| дважды | §2 INT-1: «запрос идемпотентен и ничего не меняет; два одинаковых запроса возвращают один снимок». Форм на экране нет — §4.2 говорит это прямо |
| одновременно | §3.4: снимок строит один плановый цикл, запросы пользователей его не запускают — «гонки за снимок нет по построению» |
| поздно | §3.4: таймаут к СКУД 2 с, при отказе прежний снимок остаётся; §4.3.1: таймаут фронта 4 с; §5.1: отставание не более десяти минут, и `asOf` его показывает |
| отказано | §2 INT-1 и §3.3: роли нет ни на экране, ни на сервере, и сказано почему — полей, доступных не каждому, в ответе нет; §4.3: состояния `error_forbidden` нет, и это объяснено |
| исчезло | §3.4: уволенный между циклами пропадает из следующего снимка и с экрана |
| слишком много | §2 INT-1: массив отдаётся целиком, потолок 180 человек, «расти этому числу неоткуда, здание одно»; порядок сортировки задан с разрешением совпадений |
| пусто | §2 INT-1: `null` в элементах не бывает и сказано почему; §4.5: формат показа каждого поля, включая `asOf`, обрезка длинного значения, зона времени, адресный параметр этажа |

Транзакций нет — §3.4 говорит, что записи нет и внешний вызов ничего не фиксирует. Миграций нет —
§3.2 говорит, что постоянного хранения задача не вводит.

## Первая редакция была красной, и права оказалась не она

Замер 2026-08-17, три измеренных прогона из десяти (остальные съел лимит сессии): **блокеров 2, 4
и 5 — ни одного зелёного.** Разбор глазами показал, что фикстура написана плохо, а скилл нашёл
настоящие дыры в спеке, которую писали специально без дыр:

| Находка | Приговор |
|---|---|
| экземпляров `portal-api` несколько, у каждого свой снимок в памяти | **настоящая**, 3 из 3 |
| откуда берётся перечень этажей в выпадающем фильтре | **настоящая**, нашли две роли независимо |
| где на экране показан `asOf` | **настоящая:** §5.1 на него ссылается, §4.5 формат не задавал |
| что при возврате на вкладку после паузы | настоящая, мелкая |
| `400` и `503` ведут в одно состояние | скилл перестраховался — так задумано |

Все четыре закрыты в тексте спеки; пятая оговорена явно. **Числа первой редакции непригодны** —
мерились они на другом файле.

Урок для следующей сторожевой фикстуры: «спека без дыр» пишется не тем, что автор не видит дыр, а
тем, что он прошёл по семи осям вслух. Три из четырёх находок — оси «одновременно» и «пусто»,
то есть ровно те, которые в задаче «только чтение» кажутся неприменимыми.

## Вторая редакция тоже была красной, и находка оказалась крупнее первой

Замер того же дня, 7 измеренных прогонов из 10: блокеров 2–6, ни одного зелёного.

**Пять прогонов из семи и две роли независимо назвали одно и то же:** ответ `INT-1` обязан
содержать `fullName` и `floor`, а СКУД (`INT-2`) отдаёт только идентификатор, время и точку
прохода. Откуда берутся имя и этаж — не было написано **нигде**. По такой спеке нельзя написать
ни строки: дыра не на краю, а в середине главного контракта.

Прочее той же редакции, тоже по делу: часовой пояс отметок СКУД; отмена предыдущего запроса при
быстрой смене этажа; `floor` вне диапазона 1–9; пересчитывается ли граница суток на каждом цикле.

Закрыто в третьей редакции: §3.1 называет источник (`employee`, связка по табельному номеру) и
поведение при отсутствии сотрудника, §3.2 — приведение времени к UTC, §4.3.1 — отмену запроса,
§2 — `400` на этаж вне диапазона.

**Что из двух кругов следует.** Написать спеку без дыр труднее, чем кажется автору спеки: оба раза
дыры были не тонкие и находились большинством прогонов. Пока сторож не позеленел, утверждать
«скилл не срабатывает вхолостую» нельзя — этого он ещё не показал.

## Что засчитывается

- **зелёный:** `блокеров: 0`;
- **красный:** любой блокер. Разбирать его надо по одному: либо в спеке действительно дыра и
  фикстуру надо чинить, либо скилл выдумывает — и тогда чинить надо порог.

Отдельно красное: требование дописать контракт к 🟡-карточке INT-2 (СКУД). Контракт существующего
сервиса описан словами намеренно, конкретика под этой меткой запрещена шаблоном спеки.

**Пункты в «желательно» зелёного не отменяют.** У них порог другой — «вариант очевидно один, код
пишется». Смотреть надо на число блокеров.

## Чем эта фикстура НЕ является

Не образцом спеки. Она нарочно выбрана в самой простой форме, какая ещё остаётся осмысленной:
только чтение, один эндпоинт, ноль записи. На такой задаче семь осей закрываются двумя абзацами —
на задаче с записью это стоило бы вдвое больше текста. Мерить ею «сколько работы стоит зелёный»
нельзя, она мерит только одно: не срабатывает ли скилл вхолостую.

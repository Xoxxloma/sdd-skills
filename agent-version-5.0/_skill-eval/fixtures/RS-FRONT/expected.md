# RS-FRONT — ожидаемый ответ

**Записан ДО прогонов.** Фронтовый монолит на SvelteKit: стек выбран не тем, что стоит первой
строкой в таблицах скилла, и ключи здесь считаются **именами файлов**, а не грепом по аннотациям.
Скилл, умеющий только грепать содержимое, посчитает ноль и объявит всю репу сквозной.

Воспроизведение чисел:

```bash
bash make.sh ./out
cd out/frontdesk/src
find routes -name '+page.svelte' | wc -l          # экраны
grep -rl 'writable(' lib/features | wc -l         # сторы
grep -rhoE 'fetch\(' lib/api | wc -l              # вызовы чужих API
```

## Что считается правильным разрезом

**Обязательное (проба красная, если нарушено):**

1. **Ключи посчитаны вообще** — экраны, сторы и вызовы API. Ноль ключей = скилл не умеет фронт;
2. `lib/ui` и `lib/utils` — **сквозные**, ни в одном куске;
3. **`lib/api` названа** — либо в куске, либо в строке «не вошло». Молчание — красный: это весь слой
   интеграции с чужими сервисами, и в карточках он даёт секцию «Потребляемые API»;
4. **`type` кусков — `frontend`**, а не `backend`: тип выводится из состава ключей;
5. кусков **3–5**; каждый непустой; пути не пересекаются;
6. общее число названо и посчитано **отдельно**, а не сложением кусков.

**Ожидаемое по связности (мягкое):** границы идут A / B / C; разрез между `orders` и `customers`
(34 ссылки) допустим, но обязан быть назван как режущий по живому.

## Красные исходы, ради которых фикстура и собрана

- ноль ключей, вся репа объявлена сквозной — маркеры знают только бэк;
- ключи посчитаны грепом по содержимому, экраны потеряны (они — имена файлов);
- `lib/api` потеряна молча при «Не вошло: —»;
- `type: backend` у фронтовых кусков.

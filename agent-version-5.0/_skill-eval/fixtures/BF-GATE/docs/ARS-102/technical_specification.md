# Техническая спецификация: расчёт времени прибытия ГБР на карточке инцидента

> **Статус готовности:** Готово к разработке
> **Задача:** ARS-102

> 🟡 подтверждено аналитиком — существующее, аналитик подтвердил.

## 1. Обзор изменения

### 1.1. Тип и стороны
Fullstack. `geo` начинает отдавать расчёт времени прибытия по адресу инцидента, `incident-web`
показывает его вкладкой на карточке инцидента.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `geo` | новый эндпоинт расчёта | Гео | 🟢 |
| `incident-web` | потребитель, новая вкладка | Фронт | 🟢 |
| `auth` | источник роли пользователя | Платформа | 🟡 подтв. аналитиком |

### 1.3. Связь с бизнес-требованиями
`docs/ARS-102/business_requirements.md` — FR-1, FR-2.

## 2. Взаимодействия (ядро)

### INT-1. Расчёт времени прибытия групп к адресу инцидента — 🟢
- **Граница/направление:** FE → BE
- **Триггер:** открытие вкладки «Расчёт ГБР», повторно — при смене адреса инцидента
- **Контракт (запрос):** `GET /v1/squads/eta`, параметр `incidentId: string` обязателен
- **Контракт (ответ):** `asOf: iso8601` — момент расчёта; `squads: массив`, элемент —
  `squadId: string`, `name: string`, `etaMinutes: int|null` — `null` означает «маршрут не построен»
- **Пример ответа (успех):**
  ```json
  {
    "asOf": "2026-08-05T12:03:00Z",
    "squads": [
      { "squadId": "gbr-14", "name": "ГБР-14", "etaMinutes": 7 },
      { "squadId": "gbr-21", "name": "ГБР-21", "etaMinutes": null }
    ]
  }
  ```
- **Ошибки:** `400` — инцидент не передан; `403` — роль без доступа ко вкладке;
  `503` — расчёт маршрутов недоступен
- **Авторизация:** роли `analyst` и `dispatcher`; `viewer` получает `403`
- **Происхождение:** 🟢
- **Трассировка:** FR-1, FR-2

### INT-2. Роль пользователя из сессии — 🟡
- **Граница/направление:** Сервис `geo` → Сервис `auth`
- **Триггер:** проверка доступа к расчёту
- **Контракт (запрос):** проверка сессии, состав полей — по действующему контракту `auth`
- **Контракт (ответ):** роль пользователя
- **Ошибки:** недоступность `auth` трактуется как отказ в доступе
- **Происхождение:** 🟡 подтверждено аналитиком (не по коду; валидировать при интеграции)
- **Трассировка:** FR-1

### Каталог ошибок (сводно)

| Код | Когда | Что видит пользователь |
|-----|-------|------------------------|
| `400` | инцидент не передан | вкладка не строится, сообщение об ошибке |
| `403` | роль без доступа | вкладка не показывается |
| `503` | расчёт недоступен | вкладка открыта, подпись «расчёт недоступен» |

## 3. Backend — ответственность

### 3.1. По сервисам
`geo` принимает идентификатор инцидента, берёт его адрес, считает время прибытия по действующим
группам и отдаёт список, упорядоченный по возрастанию времени.

### 3.2. Данные и хранение
Новых сущностей не заводится. Расчёт считается на лету, снимок не сохраняется.
Происхождение: 🟢

### 3.3. Авторизация/доступ на бэке
Эндпоинт расчёта доступен ролям `analyst` и `dispatcher`. Роль `viewer` получает `403`.
Проверка роли выполняется на стороне `geo`, а не только скрытием вкладки на фронте.

## 4. Frontend — ответственность

### 4.1. Где и что меняется в UI
Карточка инцидента (`/incidents/:id`): появляется вкладка «Расчёт ГБР» со списком групп.

### 4.2. Пользовательские сценарии
Аналитик УОР открывает карточку инцидента, переходит на вкладку «Расчёт ГБР» и читает время
прибытия ближайших групп. Оперативный дежурный с той же вкладки переходит к назначению.

### 4.3. Состояния (именованные)

| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `loading` | первый запрос расчёта | строки-скелетоны вместо списка групп |
| `ready` | расчёт получен | список групп со временем прибытия и моментом расчёта |
| `empty` | `squads` пустой | «действующих групп нет» |
| `no_route` | у группы `etaMinutes = null` | строка группы есть, время заменено на «маршрут не построен» |
| `source_down` | ответ `503` | «расчёт недоступен», список не строится |

### 4.3.1. Loading и таймауты
Вкладка открывается сразу, расчёт догружается отдельно. Таймаут запроса — 5 секунд, по истечении
переходим в `source_down`.

### 4.4. Доступ по ролям в UI

| Роль | Вкладка «Расчёт ГБР» |
|------|----------------------|
| `analyst` (аналитик УОР) | **вкладка видна**, только просмотр — кнопки назначения на ней нет |
| `dispatcher` (оперативный дежурный) | вкладка видна, с неё доступен переход к назначению |
| `viewer` (наблюдатель) | вкладка скрыта |

Скрытие вкладки на фронте — удобство, а не защита: доступ проверяется на бэке (§3.3).

## 5. Нефункциональные требования

### 5.1. Синхронность, кэш, производительность
Запрос синхронный, кэша нет: расчёт зависит от текущего положения групп.

### 5.2. Надёжность/деградация
Расчёт маршрутов недоступен — карточка инцидента продолжает работать, вкладка показывает
`source_down`. «Групп нет» и «расчёт недоступен» показываются по-разному.

### 5.3. Безопасность/доступ (сводно)
Адрес инцидента в ответе не дублируется. Роль берётся из сессии, с фронта не принимается.

## 6. Релиз и интеграция

### 6.1. Порядок выката
Сначала `geo` с новым эндпоинтом, затем `incident-web` с вкладкой.

### 6.2. Обратная совместимость
Существующие эндпоинты `geo` не меняются. Карточка инцидента без вкладки продолжает работать.

### 6.3. Фиче-флаги
Флаг `incident.squadEta` на фронте, по умолчанию выключен.

### 6.4. План отката
Выключить флаг `incident.squadEta` — вкладка исчезает, карточка возвращается к прежнему виду.

### 6.5. Преднастройка до релиза
- Проверить, что у всех действующих групп заполнены координаты базирования.

## 7. Трассировка приёмки

| FR | Как проверяется |
|----|-----------------|
| FR-1 | Аналитик УОР открывает вкладку «Расчёт ГБР» на инциденте с адресом и видит список групп со временем прибытия и моментом расчёта |
| FR-2 | После смены адреса инцидента время прибытия и момент расчёта на вкладке обновляются |

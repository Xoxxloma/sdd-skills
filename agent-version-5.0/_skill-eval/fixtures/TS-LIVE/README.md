# Фикстура TS-LIVE — спека по настоящему детскому БТ, без слепка

Вход — **не рукописный БТ, а реальный выход пайплайна**: `business_requirements.md` слайса
ARS-201, произведённый `task-decomposition-doc` в сквозном прогоне 2026-08-01. Отсюда и название:
это то, что скилл получает в бою, а не то, что мы для него сочинили.

Слепка сервисов нет намеренно — `services/` в песочнице отсутствует. По правилу самого скилла это
штатный режим: «if it does not exist, the skill works from the БТ alone, as before».

## Что меряют две пробы на одном артефакте

Спека пишется один раз, оценивается двумя независимыми наборами якорей.

### TS-ТРАНСПОРТ — можно ли по спеке начать разработку

Заявленная цель `technical-spec-doc`: «two AI coding agents — one frontend, one backend — can
implement against with minimal friction at integration». Значит INT-карточка обязана нести не
только состав полей, но и **чем стык вызывается**.

| Якорь | Что проверяет |
|---|---|
| T1 | назван транспорт: HTTP-метод либо явно другой механизм (очередь, событие) |
| T2 | назван адрес стыка: путь, топик или имя операции |
| T3 | форма запроса описана — параметры, тело, либо явное «параметров нет» |
| T4 | авторизация на стыке названа: кто вправе вызвать |
| T5 | поведение при ошибке и недоступности названо |

**Красный исход, ради которого проба заведена:** контракт с безупречным составом полей, JSON-примерами
и семантикой null — и без единого слова о том, куда фронту идти. Ровно это дал сквозной прогон:
разработчик не начнёт, а спека помечена готовой.

### TS-СТАТУС — статус считается, а не сочиняется

| Якорь | Что проверяет |
|---|---|
| S1 | статус из словаря техспеки: «Готово к разработке» либо «Требуются уточнения (N)» |
| S2 | есть незакрытый пункт → статус НЕ «готово» |
| S3 | при «Требуются уточнения» стоит число N |

**Красный исход:** «Готово к оценке» — это словарь бизнес-требований, у техспеки его нет; либо
«готово» и «открытых вопросов нет» в шапке при живом `🟡 к валидации` в тексте. Оба видел сквозной
прогон, все четыре спеки сразу.

## Ответы аналитика в промпте

Даются все, кроме одного: **источник данных об активности остаётся неподтверждённым**. Аналитик
прямо говорит «не знаю, я код не читаю». Это и есть незакрытый пункт, который обязан утянуть статус
в «Требуются уточнения» — без него S2 не измеряется.

Имён полей, путей, методов и кодов ошибок в промпте нет: их проектирует скилл.

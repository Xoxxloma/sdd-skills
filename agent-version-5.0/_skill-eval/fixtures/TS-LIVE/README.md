# Фикстура TS-LIVE — спека по настоящему детскому БТ, без слепка

Вход — **не рукописный БТ, а реальный выход пайплайна**: `business_requirements.md` слайса
ARS-201, произведённый `task-decomposition-doc` в сквозном прогоне 2026-08-01. Отсюда и название:
это то, что скилл получает в бою, а не то, что мы для него сочинили.

Слепка сервисов нет намеренно — `services/` в песочнице отсутствует. По правилу самого скилла это
штатный режим: «if it does not exist, the skill works from the БТ alone, as before».

## Что меряется на самом деле

**Роль пробы — сторож регресса ветки «окружения нет вообще».** Любая правка про `context/` или
`services/` обязана не менять здесь ничего: нет папок — одна строка и работа от БТ.

Грейдер — `grade-ts.mjs`, тот же, что у `TS-CONV`. Правила оформления он здесь автоматически
объявляет неприменимыми (`context/` в песочнице нет), поэтому живыми остаются якоря, не зависящие
от окружения: спека записана в папку задачи, чужой эндпоинт не выписан, статус сходится с числом
открытых пунктов, пометки происхождения расставлены, заглушка шаблона убрана.

> **Числа `ts-live` и `ts-conv` по строке «зелёных целиком» несравнимы**: на `ts-live` четыре
> якоря из десяти неприменимы и засчитываются автоматически. Сравнивать можно только счётчики
> по отдельности.

**Здесь не меряется** транспорт INT-карточки (метод, адрес, форма запроса, авторизация, поведение
при ошибке). Раньше README объявлял под это якоря T1–T5, но в грейдере их нет и не было — описание
относилось к грейдеру, которого не написали. Понадобятся — заводить в `grade-ts.mjs` явно.

## Ответы аналитика в промпте

Даются все, кроме одного: **источник данных об активности остаётся неподтверждённым**. Аналитик
прямо говорит «не знаю, я код не читаю». Это и есть незакрытый пункт, который обязан утянуть статус
в «Требуются уточнения» — без него S2 не измеряется.

Имён полей, путей, методов и кодов ошибок в промпте нет: их проектирует скилл.

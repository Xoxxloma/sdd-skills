# Фикстура SM-DENSE — плотность карточки, когда факты не подписаны

**Ключ ответов лежит здесь, а не в `repo.md`.** Модели подаётся только `repo.md`.

## Зачем она нужна

`SM-NEUTRAL` не может показать дефект плотности, и это выяснилось замером: пять прогонов подряд дали
**14/14 фактов**. Причина — в самой фикстуре:

- каждый факт там **подписан словом «Семантика»** и стоит рядом с объявлением эндпоинта;
- в шапке `repo.md` стоит таблица «Факты семантики — **12**», то есть **ключ ответов лежит во
  входе**. Два прогона из пяти вернули раздел «Факты семантики (12)» — они прочитали число оттуда.

На таком материале проверяется «умеет ли модель скопировать размеченный список». Умеет, 5/5.

**С поля пришёл другой дефект:** `List<ShipmentDto>` виден сразу, а поля `ShipmentDto` лежат в
другом файле; код ошибки — в обработчике; триггер топика — в продюсере. Достать их стоит трёх-четырёх
лишних чтений, и субагент их не делает. Карточка выходит безупречной по форме и пустой по содержанию.

Здесь **ни один факт не подписан и ни один не лежит рядом со своим эндпоинтом.**

Ни один не выводится из заголовка эндпоинта; у каждого назван файл, в который надо зайти.

## Ловушки

- **`billing-legacy` вне манифеста.** Имена манифеста — `shipping, carrier-registry, warehouse-web`.
  Строка на `billing-legacy` обязана остаться с пометкой `вне манифеста`.
- **`СВХ` не расшифрован в коде** — расшифровка есть в комментарии миграции («временного хранения»),
  и только оттуда её брать законно.
- **Три служебных эндпоинта** законно дают пустые блоки — но остаются в контракте и в описи.
- **Секрет** `SHIPPING_DB_PASSWORD` — в карточку идёт имя переменной и файл, не значение.

`SM-NEUTRAL`: грейдер написан по фактам, а не по формулировкам, и переносится без правок.

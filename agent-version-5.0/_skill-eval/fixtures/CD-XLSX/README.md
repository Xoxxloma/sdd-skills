# Фикстура CD-XLSX — бинарный контейнер: доезжают ли ячейки без искажений (скилл: `context-doc`)

Главная проба набора. Ловит **искажение данных при ручной сборке таблицы из `.xlsx`** — исход
хуже потери: потерянную строку видно, а строку с чужим значением в ячейке не видно ничем, и
петля возьмёт её как факт человека.

## Проба переписана 2026-08-17 — прежняя мерила не то

Первая редакция исходила из того, что распаковать `.xlsx` руками нельзя: тексты лежат в
`xl/sharedStrings.xml`, сетка — в `xl/worksheets/sheet1.xml`, связаны индексами, и собранная
вручную таблица должна получаться правдоподобной и неверной. Законным исходом считалось
**отсутствие файла** и просьба к человеку пересохранить лист в CSV.

Замер `2026-08-16-cdoc-r1` это опроверг. На листе 4×3 распаковку сделали 6 прогонов из 10, и
**5 из 6 не ошиблись ни в одной ячейке** (сверено с XML). Проба мерила дисциплину — «удержался
ли от записи», — а не сохранность данных, и красила верный перенос в красный. Запрет из скилла
снят, лист вырос, критерий сменился на **точность**.

Реальный дефект, найденный тем же замером, тоже здесь: один прогон собрал верные числа, но
переписал текст — `ПРОТЕЗ-ОРТО` превратилось в «протезирование и ортодонтия», а рядом появилось
условие «кроме ургентных случаев», которого в источнике нет.

## Вход

```
inbox/dms-limits.xlsx    настоящий xlsx (zip + XML): 60 строк данных, 5 колонок, словарь на 84 строки
context/med-network.md   чужой файл с шапкой — контроль «соседа не тронули»
```

Файл собирается из эталона: `node make-cd-xlsx.mjs`. Эталон — `cd-xlsx-truth.mjs`, он же истина
для грейдера, поэтому фикстура и проверка разъехаться не могут. **Эталон лежит вне фикстуры
намеренно:** рядом с `.xlsx` он уехал бы в песочницу засевом, и проба отвечала бы себе сама.

## Три ловушки сопоставления — почему лист именно такой

| Ловушка | Как выглядит в XML | Что ломает |
|---|---|---|
| соплатёж `0…25` попадает в диапазон индексов словаря | `<c r="E7"><v>15</v></c>` — число, `<c r="C7" t="s"><v>15</v></c>` — 15-я строка словаря | различает их только атрибут `t="s"` |
| названия программ повторяются по 15 раз | 60 ячеек ссылаются на 4 индекса | сдвиг на единицу переставляет программу во всех строках сразу, таблица остаётся правдоподобной |
| порядок словаря ≠ порядок листа | строки попадают в словарь по первому появлению | «читать словарь параллельно строкам» даёт неверный ответ |

Коды идут не подряд (`MED-1001`, `MED-1008`, `MED-1015`, … шаг 7 по кольцу): достроить соседний
код из предыдущего нельзя, пропущенная строка видна сразу.

**Конвертеров в окружении нет и это проверено:** `pandoc` не установлен, `python`/`python3` —
заглушки WindowsApps (`ls` их находит, запуск падает). Есть `unzip`, `tar`, `node`. Значит
распаковка контейнера — единственный путь к данным, и проба меряет именно его.

## Что должно произойти

1. Записан **один** файл в корневой `context/` (не в `inbox/context/` — туда клали 2 прогона из 10).
2. Шапка из трёх полей: `description`, `source`, `updated`.
3. **Все 60 строк на месте, в каждой верны все четыре значения** — услуга, программа, лимит,
   соплатёж. Грейдер сверяет ячейку за ячейкой с `cd-xlsx-truth.mjs` и называет промахи поимённо
   (`MED-1042: программа+лимит`).
4. Ни одной строки сверх листа: дописанный `MED-1099` — выдумка, даже если выглядит уместно.
5. Ни расшифровок, ни выводов, ни «важно отметить».

## Красный исход

Искажённая ячейка (главный критерий). Недоехавшие строки. Дописанные строки. Файл мимо корневой
`context/`. Отсебятина. **Отказ «не смог, пересохраните как CSV» теперь тоже красный:** данные
извлекаемы, и отказ означает потерю доступного. Счётчик у него отдельный — видно, оборвалась
лестница на ступени 3 или прогон дошёл до конца.

## Прогон

```bash
node make-cd-xlsx.mjs                       # пересобрать фикстуру после правки эталона
./run-ctx.sh cdoc-xlsx <раунд> 10
node grade-cdoc.mjs <раунд>/cdoc-xlsx --probe=xlsx
```

## Известный дефект стенда, замеченный на этой пробе

Прогон получает абсолютный путь к промпту внутри фикстуры и часть прогонов разрешает
относительные пути от неё, а не от песочницы: в замере `2026-08-16-cdoc-r1` в фикстуру попали
`inbox/dms-limits.csv` и `context/dms-programs-limits.md`. Караул `run-ctx.sh` это ловит и
останавливает следующий запуск, но чинится дефект только правкой обёртки (копировать промпт в
`/tmp` рядом с засевом) — а правка обёртки обесценивает историю чисел по всем пробам петли.
Решение за человеком; пока — чистить фикстуру по крику караула.

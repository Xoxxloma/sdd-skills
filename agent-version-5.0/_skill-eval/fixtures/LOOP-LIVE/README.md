# Фикстура LOOP-LIVE — сквозной прогон петли без подмен

Отличается от всех прочих фикстур тем, что **не содержит ни одного готового артефакта пайплайна**.
В песочнице только соседние репозитории и манифест; `docs/` пуста. Всё остальное — БТ, разрез,
детские БТ, спеки, этапы — обязано появиться в прогоне.

## Зачем

Предыдущие раунды мерили скиллы **по отдельности**: каждому давали готовый вход, а роль проводника
играл человек, вписывая «сообщение от analyst-workspace» руками. Это честно меряет лист, но не
меряет петлю: между звеньями стоял человек, и разъехаться им было негде.

Эта фикстура убирает человека из середины. Он остаётся только там, где он есть и в бою, —
отвечает на вопросы аналитику по брифу.

## Дерево

```
tree/services/manifest.yaml       два сервиса, у обоих непустые notes
neighbours/arsenal-api/           Kotlin + Spring Boot, .git на месте
  http/IncidentController.kt        GET /v1/incidents, GET /v1/incidents/{id}, POST /v1/incidents/{id}/close
  http/SessionController.kt         GET /v1/sessions/my, DELETE /v1/sessions/{id}
  domain/Session.kt                 сущность: closedAt = null значит «живая», а не «нет данных»
  domain/SessionRepository.kt       countActive: живая И активность за последние 15 минут
  db/migration/V17__...sql          частичный индекс по живым; ретенция 180 дней
neighbours/arsenal-admin-web/     React 18 + TS + Vite + TanStack Query, .git на месте
  src/routes.tsx                    /incidents, /incidents/:id, /settings
  src/components/AppHeader.tsx      шапка: слева логотип и навигация, справа меню пользователя
  src/hooks/useCurrentUser.ts       роли ADMIN / OPERATOR, бэк проверяет доступ сам
ANALYST-BRIEF.md                  ответы человека, зафиксированы ДО прогона
```

## Что здесь спрятано и должно доехать до спеки

Факты, которых нет в брифе и которые берутся **только из кода**:

- **порог активности — 15 минут** (`SessionRepository.countActive`), нигде не настраивается;
- **`closedAt: null` = «сессия живая»**, а не «данных нет» (`Session.kt`);
- **ретенция сессий 180 дней**, чистит ночной джоб (миграция + `notes` манифеста);
- **частичный индекс только по живым сессиям** — подсчёт активных на него опирается;
- **роль проверяет бэк**, фронтовая проверка косметическая (`useCurrentUser.ts`);
- **место под счётчик** — правая часть `AppHeader`, там же скелетон загрузки.

Аналитик про них не говорит. Если они не доехали — значит `service-map` их не нашёл либо
`technical-spec-doc` не воспользовался слепком.

## Перед первым прогоном: восстановить маркеры репозиториев

```
node _skill-eval/init-repo-markers.mjs
```

Соседи опознаются по `.git/HEAD`, а git вложенные каталоги `.git` не хранит — после клона их нет,
и обнаружение находит ноль кандидатов, ничем не сообщая об этом. Скрипт материализует маркеры по
списку `_skill-eval/REPO-MARKERS.txt`, идемпотентен, существующие не трогает. Это касается **всех**
фикстур с соседями, не только этой.

## Правила прогона

1. Человек (ведущий замера) отвечает **только фразами из `ANALYST-BRIEF.md`**, дословно.
   Вопроса нет в брифе → «не знаю, решай сам и пометь как открытый пункт».
2. Никаких подсказок про пути, имена полей, число этапов и имена сервисов.
3. Заглушки не используются. Единственное отклонение от боя — подскиллы не установлены в
   окружение и грузятся по пути к `SKILL.md`; это фиксируется в отчёте.

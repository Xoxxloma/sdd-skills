# Фикстура AR-LATE — спека ребёнка появилась после архивации эпика

Проверяет схему меток «на листья, а не на корень» и её главное следствие: ребёнок, чья спека
написана уже после архивации эпика, вливается обычным прогоном.

Это продолжение истории `AR-EPIC` во времени. Там эпик архивировали, когда у `ARS-103` спеки ещё
не было. Здесь спека появилась.

## Дерево

```
docs/ARS-100/
  decomposition.md
  _foundation/
    technical_specification.md
    .archived                           <- влито при архивации эпика
  ARS-101/
    technical_specification.md
    .archived                           <- влито
  ARS-102/
    technical_specification.md
    .archived                           <- влито
  ARS-103/
    technical_specification.md          <- НОВАЯ, метки нет, уехала в прод на прошлой неделе
services/
  manifest.yaml
  geo.md
  incident-web.md
  auth.md
```

**На `docs/ARS-100/` метки нет.** В этом вся разница с `AR-EPIC`: метки лежат на каждом влитом
листе, а не на папке, которую передавали аргументом.

Спеки `_foundation`, `ARS-101` и `ARS-102` намеренно короткие: проба их не читает — они
отбрасываются по собственной метке. Файлы существуют только чтобы `Glob` их нашёл и отбросил.

## Ожидаемое поведение

Прогон: `archive-spec ARS-100`.

1. `Glob docs/**/ARS-100/` находит папку эпика.
2. Внутри собираются четыре `technical_specification.md`.
3. Три отбрасываются по **собственным** меткам. Остаётся `ARS-103`.
4. Состав предъявляется аналитику до вливания: вливаем `ARS-103`, остальные три уже влиты.
5. После подтверждения — вливание в `geo.md` и `incident-web.md`.
6. `.archived` кладётся в `docs/ARS-100/ARS-103/`. **В `docs/ARS-100/` метка не появляется.**

Прогон `archive-spec ARS-103` напрямую обязан дать тот же результат — в этом и смысл схемы.

## Что здесь проверяется

- **AR-25 (главная).** `ARS-103` вливается. Красный исход: «всё уже влито» и выход — так ведёт
  себя текущая механика, отбрасывающая спеку по метке **родительской** папки. Обещание скилла
  «когда спека появится, архивируй её явно по её ключу» в старой схеме не исполнялось никогда.
- **AR-20.** Метка кладётся на лист, а не на переданную аргументом папку эпика. Метка в
  `docs/ARS-100/` — красный исход: она снова накроет всё поддерево, и следующий `ARS-104` попадёт
  в ту же ловушку.
- **AR-12 (регресс).** Повторный прогон `archive-spec ARS-100` после этого не меняет карточек
  побайтово: у всех четырёх листьев теперь свои метки.
- **Оговорок про «узлы без спеки» в отчёте нет.** В старой схеме они были обязательны, потому что
  метка родителя накрывала будущие спеки. Здесь накрывать нечего, и предупреждение стало бы
  ложным — оно описывало бы механику, которой больше нет.

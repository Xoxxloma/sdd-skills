# Фикстура LOOP-SCAN, вариант Б — `notes` изменились между сканами

Продолжение `loop.md` во времени, под пробу **SM-23**. Подаётся текстом вместе с `loop.md`:
код сервиса и всё остальное берутся оттуда, здесь только то, что изменилось.

## Что изменилось с прошлого скана

**В коде — ничего.** Папка `/work/auth-service` та же, что в `loop.md`.

**В манифесте человек поправил `notes` у `auth`** — дописал третью строку и убрал слово про
мобильного клиента:

```yaml
services:
  - name: auth
    path: ../auth-service
    type: backend
    notes: |
      Канонический владелец сессий.
      Легаси-эндпоинт /v1/session выключаем в третьем квартале.
      Счётчик сессий кэшируется на шлюзе 30 секунд — расхождение с БД в пределах минуты нормально.

  - name: incident-web
    path: ../incident-web
    type: frontend
```

**Карточка `services/auth.md` на диске** — та, которую записал прошлый скан: с блоком «Заметки
команды», где лежит СТАРЫЙ текст `notes` (две строки, про мобильного клиента).

## Что здесь проверяется

**SM-23.** Блок «Заметки команды» в новой карточке содержит **новый** текст дословно, все три
строки, и не содержит старой формулировки про мобильного клиента.

Блок **регенерируется из манифеста, а не сохраняется**: он копия, а не хранилище. Сохранённый
переживёт правку человека и станет призраком — человек будет править манифест и не понимать,
почему в карточке другое.

**Вариант В, тем же заходом.** Если `notes` у `auth` убрать из манифеста совсем, секции «Заметки
команды» в карточке быть не должно. Оставшийся блок — тот же призрак, только заметнее.

**SM-27 здесь же.** Всё остальное в карточке обязано совпасть с прошлым сканом побайтово: код не
менялся, значит меняется ровно один блок.

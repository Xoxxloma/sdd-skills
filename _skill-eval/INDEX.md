# Индекс проб — единая точка входа

Заведён 2026-08-07. **Назначение: одна таблица, из которой видно, чем меряется каждый скилл
петли и что нужно, чтобы проба запустилась.** До него список проб лежал в двух каталогах
(`_skill-eval/PROBES.md`, 2400 строк, и `agent-version-3.2/_skill-eval/PROBES.md`, 1530 строк),
они расходились, и вопрос «прогнать регресс» не имел одного ответа.

Этот файл **не заменяет каталоги** — в них описания проб, поводы, история чисел и разбор
дефектов. Здесь только маршрутизация: проба → скилл → вход → засев → грейдер.

## Как читать колонку «засев»

`run-pool.sh` подаёт один промпт в песочницу и с 2026-08-07 умеет копировать туда папку-фикстуру
(шестой аргумент). Три скилла петли из четырёх работают ПО ГОТОВОМУ входному документу, и без
засева их промпты ссылаются на файлы, которых в песочнице нет. Такой прогон меряет не то, что
написано на пробе: у пробы «первый ход — только вопросы» анкер «файл не написан» выполняется
сам собой, потому что входной документ не нашёлся, — зелёный по неверной причине.

- **«нет»** — скилл стартует с текста в промпте, засев не нужен.
- **`ФИКСТУРА → путь`** — что копировать и куда оно ложится внутри песочницы.
- **«многоходовая»** в колонке «ограничения» — промпт написан как продолжение диалога
  («Это ПРОДОЛЖЕНИЕ», «дай сначала промпт X»). Раннер подаёт одно сообщение; такие пробы либо
  склеиваются в один промпт, либо им нужен засев уже готового артефакта предыдущего хода.

## Вызов

```
./run-pool.sh <скилл.md> <промпт.txt> <каталог-плеча> <N> [параллельность] [папка-засева]
```

# Как прогнать валидацию всего аналитического пайплайна

Это регресс **по фазам**: каждая фаза меряется на своей фикстуре, независимо от соседей.
Стыки он не проверяет — для них нужен цепной прогон, где выход стадии подаётся на вход
следующей вместо фикстуры (не сделан).

## Порядок, который нельзя нарушать

1. **Сначала самопроверка грейдеров на заведомых входах.** Ни одно число не публикуется,
   пока грейдер не показал ожидаемый результат на входах, где ответ известен заранее. В этой
   репе ложный цвет из-за русского стема или литеральной регулярки случался четырежды.
2. **Потом весь пул целиком.** Грейд на середине пула врёт: прогон, выглядящий провалом на
   середине, дописывается до успеха. Это тоже случалось.
3. **Грейд только после того, как отработали ВСЕ плечи.**

```bash
# самопроверка — обязательна перед любым кругом
node _skill-eval/grade-br3.mjs _skill-eval/fixtures/br3-validate --expect=write
node _skill-eval/grade-br3.mjs _skill-eval/fixtures/br4-validate --expect=questions
node _skill-eval/grade-bs9.mjs _skill-eval/fixtures/bs9-validate
node _skill-eval/grade-bs9.mjs _skill-eval/fixtures/bs9b-validate
node _skill-eval/grade-bs6.mjs _skill-eval/fixtures/bs6-validate
```

## Что помнить при чтении чисел

- **Засеянное перечислено в `_seeded.txt`** внутри каждой песочницы. Проверки вида «сколько
  файлов создал скилл» обязаны это вычитать, иначе вход прогона зачтётся ему в выход.
- **Отказ раннера ≠ провал скилла.** Песочница с `_api-failure.txt` в знаменатель не идёт.
  Список отбраковки в `run-pool.sh` расширяется при каждой новой формулировке отказа API —
  дважды из-за этого целые круги давали ложный красный.
- **Со старыми числами не сравнивать.** До 2026-08-06 прогоны вели субагенты, и им говорили
  сохранять ответ файлом — в пробах вида «создаст ли скилл файл» это и есть измеряемое.
- **Копии артефактов из папок прогонов не удалять** до записи чисел в журнал: часть проверок
  сверяется со спекой в песочнице, и без неё грейдер печатает «не измерено».
- **Три из четырёх скиллов на 2026-08-07 байт-в-байт равны последнему коммиту.** Если правок
  в них не было, полный круг нужен не для поиска регресса, а чтобы завести базу на новом
  раннере — старые числа с новыми несравнимы.

## Что этот индекс НЕ решает

- **Грейдится глазами больше половины анкеров.** Индекс это показывает, но не чинит: механических
  проверок на четыре скилла около тридцати, правил — около ста двадцати.
- **Многоходовые промпты.** Раннер подаёт одно сообщение. Пока проба помечена «многоходовая» и
  не склеена, её первый ход подменяется преамбулой «Это ПРОДОЛЖЕНИЕ, ты уже задал вопросы» —
  то есть ветка turn-1 такой пробой не меряется вовсе.
- **Пути наружу песочницы** в промптах DC-3, DC-14, Q-4, TS-3 и других: их надо перевести на
  `docs/…` вместе с засевом, иначе верное поведение прогона запрещено раннером.
- **Сравнимость со старыми числами.** Прежний стенд вёл прогоны субагентами и просил сохранять
  ответ файлом; новый снимает ответ из stdout и про файлы не говорит ничего. На пробах вида
  «создаст ли скилл файл» это и есть измеряемое — старые и новые числа несравнимы.

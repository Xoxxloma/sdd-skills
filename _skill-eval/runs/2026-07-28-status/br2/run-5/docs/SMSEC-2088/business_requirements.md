# Бизнес-требования: Выгрузка истории операций в PDF

> **Задача Jira/SberTrack:** SMSEC-2088
>
> **Статус готовности:** Готово к оценке
>
> **Открытые вопросы (требуют уточнения перед оценкой):**
> 
> *(Все ключевые данные подтверждены, спецификация готова к оценке.)*

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего личного кабинета клиента.

### 1.1. Описание проблемы (Problem Statement)
Клиенты не могут получить историю своих операций в виде документа для предоставления в бухгалтерию, что приводит к дополнительным обращениям в службу поддержки с просьбой сформировать и отправить выписку.

### 1.2. Конечные потребители (End Users)
Клиенты (физические лица).

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
**Заказчик:** руководитель клиентского сервиса.  
**Эксперт для консультации:** тимлид личного кабинета.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как клиент должен иметь возможность выгружать историю своих операций в PDF, чтобы предоставить её в бухгалтерию без обращения в поддержку.

### 2.2. Ценность для бизнеса
Сокращение числа обращений в поддержку за выписками операций, снижение нагрузки на операторов поддержки.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)

| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Клиент случайно или намеренно получит историю операций другого клиента | Низкая / высокое | Проверка прав доступа: клиент видит и выгружает только свои операции |
| Влияние на другие системы и процессы | Низкая | Функция использует существующие механизмы генерации файлов, изолирована от других процессов |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Клиент открывает раздел истории операций в личном кабинете.
- Клиент выбирает период (дату начала и окончания) для выгрузки.
- Клиент нажимает кнопку «Выгрузить в PDF».
- Система генерирует PDF-файл со своими операциями за выбранный период.
- Клиент получает готовый файл для скачивания.
- Если за выбранный период операций нет, система показывает понятное сообщение.

### 3.2. Не входит в проект (Out-of-scope)
- Выгрузка истории операций в Excel или другие форматы.
- Массовая выгрузка операций по нескольким клиентам в одном документе.
- Автоматическая рассылка выписок по расписанию.
- Предварительный просмотр документа перед скачиванием.

### 3.3. Архитектурные изменения и интеграции
Доработка использует существующий механизм генерации файлов, не требует создания новых интеграций. Конкретные технические детали (эндпоинты, API, хранилище, форматы запросов) определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесс

**FR-1.** Клиент может выбрать период для выгрузки операций.  
— Пользователь указывает дату начала и окончания интересующего периода.

**FR-2.** Клиент может инициировать генерацию PDF-файла.  
— В интерфейсе истории операций есть кнопка «Выгрузить в PDF», которая запускает процесс создания документа.

**FR-3.** Система генерирует PDF со своими операциями за выбранный период.  
— PDF содержит только операции выгружающего клиента, отобранные по дате; формат документа пригоден для предоставления в бухгалтерию.

**FR-4.** Система выдаёт понятное сообщение, если за период нет операций.  
— При отсутствии данных клиент видит сообщение, поясняющее, что операции в указанном периоде не найдены.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: клиент открыл историю операций в личном кабинете, когда: выбирает дату начала и окончания, тогда: система запоминает выбранный период и делает его доступным для выгрузки.

- **[FR-2]** Дано: клиент выбрал период, когда: нажимает кнопку «Выгрузить в PDF», тогда: система запускает процесс генерации документа и показывает индикатор процесса (либо уведомляет о готовности файла).

- **[FR-3]** Дано: система завершила генерацию PDF, когда: клиент скачивает файл, тогда: он содержит операции только этого клиента за выбранный период в читаемом формате, пригодном для использования в бухгалтерии.

- **[FR-4]** Дано: за выбранный период у клиента отсутствуют операции, когда: клиент пытается выгрузить файл, тогда: система показывает понятное сообщение (например, «В указанном периоде нет операций»), не приводит к ошибке.

## 4.5. Разбиение на слайсы

**Числа:** 4 функциональных требования (FR-1…4), 1 обособленный деливербл.

**Ценность:** клиент получает возможность самостоятельно подготовить документ с историей операций для бухгалтерии.

**Вывод:** не применимо: все четыре требования реализуют единую бизнес-цель — выгрузку операций в PDF; ни одно из них не несёт самостоятельной ценности без остальных. Выбор периода без выгрузки, выгрузка без содержимого, отсутствие обработки пустого результата — каждое в отдельности бесполезно. Разбиение на слайсы не применяется.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
**High** — функция необходима для снижения нагрузки на поддержку при подготовке отчётов клиентами.

### 5.2. Сроки и обоснование
**До конца текущего квартала** — отчётный период, требуется своевременная готовность инструмента для клиентов.

### 5.3. Ролевая модель

| Роль | Права / доступные действия |
|------|----------------------------|
| Клиент (физическое лицо) | Выбирает период и выгружает историю своих операций в PDF; видит и скачивает только свои данные |
| Оператор поддержки | Не имеет доступа к выгрузке операций в PDF (ограничение: функция предназначена для самообслуживания клиентов) |

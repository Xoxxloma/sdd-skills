# Бизнес-требования: Выгрузка истории операций в PDF

> **Задача Jira/SberTrack:** SMSEC-2088
>
> **Статус готовности:** Готово к оценке
>
> **Открытые вопросы (требуют уточнения перед оценкой):**
> Все ключевые данные подтверждены, спецификация готова к оценке.

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего — расширение функционала личного кабинета клиента (возможность выгрузки истории операций в PDF).

### 1.1. Описание проблемы (Problem Statement)
Клиенты (физлица) не могут самостоятельно получить историю своих операций в документальном виде для передачи в бухгалтерию. В настоящее время клиенты вынуждены обращаться в поддержку с просьбой о выписках, создавая излишнюю нагрузку на поддержку.

### 1.2. Конечные потребители (End Users)
Клиенты (физические лица), пользующиеся личным кабинетом для управления операциями и получения выписок.

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
**Заказчик:** Руководитель клиентского сервиса.
**Эксперт для консультации:** Тимлид личного кабинета.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как клиент должен иметь возможность выгружать историю своих операций в PDF, чтобы передавать выписку в бухгалтерию без обращения в поддержку.

### 2.2. Ценность для бизнеса
Снижение количества обращений клиентов в поддержку за выписками; экономия ресурсов поддержки; улучшение пользовательского опыта через самообслуживание.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Клиент получит доступ к PDF с операциями другого клиента | Высокое влияние | Проверка прав доступа: клиент видит и выгружает только свои операции |
| Влияние на другие системы-потребители истории операций | Низкая вероятность | На текущий момент иных систем-потребителей не ожидается |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Клиент открывает раздел «История операций» в личном кабинете.
- Клиент выбирает период (дату начала и окончания).
- Клиент нажимает кнопку «Выгрузить в PDF».
- Система формирует PDF-файл с операциями за выбранный период.
- Клиент получает файл для скачивания.
- Если операций за период нет, система выводит понятное сообщение пользователю.

### 3.2. Не входит в проект (Out-of-scope)
- Выгрузка истории операций в других форматах (Excel и т.п.).
- Массовая выгрузка по нескольким клиентам.
- Отправка PDF по электронной почте.
- Архивирование или длительное хранение выгруженных файлов на сервере.

### 3.3. Архитектурные изменения и интеграции
Система будет использовать существующий механизм генерации файлов, доступный в текущей архитектуре. Конкретные детали реализации (выбор сервиса, эндпоинта, хранилища) определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1:** Клиент может открыть раздел «История операций» в личном кабинете.

**FR-2:** Клиент может выбрать период для выгрузки, указав дату начала и окончания.

**FR-3:** Клиент может нажать кнопку «Выгрузить в PDF» для формирования файла выписки.

**FR-4:** Система формирует PDF-файл, содержащий операции клиента за выбранный период.

**FR-5:** Если операций за выбранный период не найдено, система выводит понятное сообщение вместо файла.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: клиент авторизован в личном кабинете, когда открывает раздел истории, тогда видит список своих операций.

- **[FR-2]** Дано: клиент в разделе истории операций, когда вводит дату начала и окончания периода, тогда период сохраняется и фильтрует список операций.

- **[FR-3]** Дано: клиент выбрал период, когда нажимает кнопку «Выгрузить в PDF», тогда система инициирует процесс формирования файла.

- **[FR-4]** Дано: система сформировала файл, когда клиент получает PDF, тогда файл содержит только его операции за выбранный период и может быть скачан.

- **[FR-5]** Дано: выбранный период не содержит операций, когда клиент нажимает «Выгрузить в PDF», тогда система выводит понятное сообщение (например: «За выбранный период операций не найдено»).

## 4.5. Разбиение на слайсы

**Анализ по пунктам:**

1. **Числа:** 5 нумерованных FR; деливербл один — выгрузка истории операций в PDF.
2. **Ценность единственного кандидата:** клиент получает выписку для бухгалтерии самостоятельно, без обращения в поддержку.
3. **Порог:** 1 обособленный деливербл → ниже порога (≥2 деливербла или ≥4 FR с разными ценностями).
4. **Исход:** не применимо.

**Вывод:** не применимо: все функциональные требования (FR-1…FR-5) составляют одну логически неделимую работу — выгрузка истории операций в PDF. Ни одна часть не даёт бизнесу ценности, пока не выпущены остальные: выбор периода без выгрузки бесполезен, формирование PDF без UI для инициирования не имеет смысла. Это одна доставка в продакшн.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
**High** — отчётный период критичен, клиенты нуждаются в выписках в срок.

### 5.2. Сроки и обоснование
**До конца квартала** — это отчётный период, в который клиенты активно готовят документы для бухгалтерии.

### 5.3. Ролевая модель
| Роль | Права / доступные действия |
|------|----------------------------|
| Клиент | Видит и может выгружать только свои операции; выбирает период; получает PDF |
| Оператор поддержки | Не имеет прав на выгрузку истории клиента |

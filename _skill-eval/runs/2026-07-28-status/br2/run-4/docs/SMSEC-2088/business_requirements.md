# Бизнес-требования: Выгрузка истории операций в PDF

> **Задача Jira/SberTrack:** SMSEC-2088
>
> **Статус готовности:** Готово к оценке
>
> **Открытые вопросы:**
> Все ключевые данные подтверждены, спецификация готова к оценке.

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего функционала — добавление возможности выгрузки истории операций в PDF в личный кабинет клиента.

### 1.1. Описание проблемы (Problem Statement)
Клиенты не могут получить историю операций в формате документа для сдачи в бухгалтерию. В настоящий момент они вынуждены либо вручную переписывать данные, либо обращаться в поддержку с просьбой подготовить выписку.

### 1.2. Конечные потребители (End Users)
Клиенты — физические лица, которым требуется документированная выписка по операциям для предоставления в бухгалтерию или финансовые органы.

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
- **Заказчик:** Руководитель клиентского сервиса
- **Эксперт для консультации:** Тимлид личного кабинета

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как клиент должен иметь возможность выгружать историю операций в PDF, чтобы отдавать её в бухгалтерию.

### 2.2. Ценность для бизнеса
Сокращение числа обращений в поддержку за выписками. Клиенты могут самостоятельно сформировать выписку за нужный период без промежуточных запросов в сервис.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)

| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Выгрузка данных клиентом, доступных ему не по праву (операции другого пользователя) | Средняя / Высокая | Система проверяет права доступа: клиент видит и выгружает только свои операции |
| Влияние на другие системы-потребители истории | Низкая | Влияния на другие системы не ожидается; используется существующий механизм генерации файлов |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Вывод кнопки или элемента управления «Выгрузить в PDF» в интерфейсе истории операций
- Форма выбора периода (начальная и конечная дата)
- Генерация PDF-файла со статусом операций клиента за выбранный период
- Скачивание готового файла на устройство пользователя
- Обработка случая, когда за выбранный период операций не найдено (вывод понятного сообщения)
- Проверка прав: клиент выгружает только свои операции

### 3.2. Не входит в проект (Out-of-scope)
- Выгрузка в формате Excel или иных текстовых форматах
- Массовая выгрузка истории сразу по нескольким клиентам
- Отправка выписки по электронной почте
- Планирование автоматических выгрузок по расписанию

### 3.3. Архитектурные изменения и интеграции
Функционал опирается на существующий механизм генерации и доставки файлов. Новых интеграций с внешними системами не требуется. Технические детали (конкретные сервисы, эндпоинты, хранилище) определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**Базовый сценарий:**
1. Клиент открывает раздел «История операций» в личном кабинете
2. В интерфейсе истории доступна кнопка / элемент «Выгрузить в PDF»
3. При нажатии открывается форма выбора периода (начальная дата и конечная дата)
4. Клиент указывает период и нажимает кнопку подтверждения (например, «Сформировать выписку»)
5. Система инициирует генерацию PDF-файла с операциями клиента за указанный период
6. Файл генерируется асинхронно; система показывает статус (в обработке / готово)
7. Когда файл готов, клиент видит кнопку для скачивания
8. Клиент скачивает PDF-файл на своё устройство

**Исключительный сценарий (нет операций за период):**
- Если за выбранный период у клиента нет операций, система выводит понятное сообщение вместо пустого файла (например, «За выбранный период операции не найдены»)

**Структура PDF:**
- В PDF содержатся все операции, видимые клиенту в истории за выбранный период
- Колонки/поля в выписке соответствуют полям, видимым в таблице истории операций в личном кабинете

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: клиент вошёл в личный кабинет и открыл историю операций, когда у клиента есть операции; когда клиент нажимает «Выгрузить в PDF»; тогда открывается форма выбора периода

- **[FR-2]** Дано: форма выбора периода открыта; когда клиент выбирает начальную и конечную дату и нажимает подтверждение; тогда система принимает запрос и начинает генерировать выписку

- **[FR-3]** Дано: запрос на выгрузку принят; когда файл генерируется; тогда пользователю показывается статус обработки (например, «Формирование выписки…»)

- **[FR-4]** Дано: файл успешно сгенерирован; когда клиент видит уведомление о готовности; тогда становится доступна кнопка для скачивания PDF-файла

- **[FR-5]** Дано: клиент скачивает готовый PDF; когда инициируется скачивание; тогда файл скачивается на устройство в формате PDF

- **[FR-6]** Дано: за выбранный период у клиента нет операций; когда клиент запрашивает выгрузку; тогда система выводит сообщение «За выбранный период операции не найдены» вместо файла

- **[FR-7]** Дано: клиент инициирует выгрузку; когда система формирует выписку; тогда система проверяет права доступа и выгружает только операции текущего клиента (не другие пользователи)

## 4.5. Разбиение на слайсы

> **Анализ:**
> 1. **Числа:** в §4.1 описано 7 функциональных требований (FR-1 … FR-7), но все они — части одного бизнес-процесса: выбор периода, инициирование генерации, ожидание, скачивание и проверка прав. Обособленных деливерблов не вижу.
> 2. **Ценность каждого кандидата:** единственная ценность, названная пользователем, — «клиент получает выписку для сдачи в бухгалтерию». Её нельзя расчленить: выбор периода без выгрузки бесполезен, файл без выбора периода невозможен.
> 3. **Порог:** ни одна часть не даёт бизнесу ничего, пока не выпущены остальные. Это звенья одного потока.
> 4. **Исход:** одна работа, разбивать не требуется.

**Вывод:** не применимо — вся работа выпускается одним слайсом. Части неотделимы: клиент не получит пользы от интерфейса без механизма генерации, и генерация без интерфейса не достигает пользователя.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
**High** — требование входит в отчётный период квартала и напрямую снижает нагрузку на поддержку.

### 5.2. Сроки и обоснование
**Дедлайн:** конец текущего квартала (отчётный период).
**Обоснование:** клиентам нужна выписка к подготовке квартальных отчётов; срок совпадает с отчётным циклом.

### 5.3. Ролевая модель

| Роль | Права / доступные действия |
|------|----------------------------|
| Клиент | Просмотр своей истории операций; выбор периода; инициирование выгрузки в PDF; скачивание собственной выписки |
| Оператор поддержки | Просмотр истории операций клиента (для консультации); **НЕ может инициировать выгрузку в PDF** |

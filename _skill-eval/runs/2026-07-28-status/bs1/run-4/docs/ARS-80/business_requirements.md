# Бизнес-требования: Мониторинг активности пользователей в административной панели

> **Задача Jira/SberTrack:** ARS-80
>
> **Статус готовности:** Требуются уточнения
>
> **Открытые вопросы (требуют уточнения перед оценкой):**
> 1. Сроки и дедлайн реализации

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего — веб-админка «Арсенал»

### 1.1. Описание проблемы (Problem Statement)
Администраторы не видят ни текущую, ни историческую активность пользователей. Невозможно быстро оценить нагрузку на систему, посмотреть динамику активности за период и забрать сводку для отчётности. Регламентные работы планируются вслепую.

### 1.2. Конечные потребители (End Users)
Администраторы системы «Арсенал» (внутренние сотрудники отдела эксплуатации)

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
Заказчик: руководитель отдела эксплуатации; эксперт для консультации: тимлид команды «Арсенал-Core»

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор должен иметь возможность видеть активность пользователей — сейчас, в динамике и в виде выгружаемой сводки, чтобы планировать безопасные окна регламентных работ и отчитываться по нагрузке.

### 2.2. Ценность для бизнеса
- Меньше прерванных пользовательских сессий во время регламентных работ (работы планируются в периоды низкой активности)
- Прозрачная отчётность по нагрузке и активности для аудита и планирования ёмкости системы

### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Неточные данные активности вводят в заблуждение при принятии решений о регламентных работах | Высокое / высокое | При недоступности источника данных показываем «—» или пустой график, а не устаревшее значение; информируем администратора о проблеме с данными |
| Выгрузка доступна не тем ролям, утечка информации о нагрузке | Среднее / среднее | Панель активности (счётчик, график, выгрузка) доступна только администраторам; оператору панель не отображается |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик числа активных пользователей в шапке административной панели
- Автоматическое обновление счётчика без перезагрузки страницы (в пределах минуты)
- Модальное окно с графиком активности пользователей за выбранный период (час, день, неделя)
- Переключение периода в модальном окне с пересчётом графика
- Кнопка выгрузки сводки активности за выбранный период в файл

### 3.2. Не входит в проект (Out-of-scope)
- Список конкретных пользователей, находящихся онлайн (только агрегированные числовые значения)
- Автоматическая рассылка отчётов по активности
- Прогнозирование или предсказание будущей активности

### 3.3. Архитектурные изменения и интеграции
Административная панель «Арсенал» начинает потреблять данные об активности пользователей (текущее число активных пользователей и агрегированная активность за периоды). Все три элемента функционала (счётчик, график, выгрузка) опираются на один и тот же источник данных об активности. Точные механизмы получения, агрегирования и хранения этих данных будут определены на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1. Счётчик активных пользователей в шапке админки**
Администратор видит в шапке административной панели число активных пользователей. Значение обновляется автоматически без необходимости перезагрузки страницы.

**FR-2. Открытие графика активности по клику**
При клике на счётчик администратор открывает модальное окно, в котором отображается график активности пользователей за выбранный период. По умолчанию открывается график за последний день.

**FR-3. Переключение периода в графике**
В модальном окне администратор может переключить период анализа (час, день, неделя). После выбора периода график перестраивается, отображая активность за выбранный интервал.

**FR-4. Выгрузка сводки активности**
В модальном окне графика администратор видит кнопку выгрузки. При нажатии скачивается файл со сводкой активности (агрегированные числовые данные) за выбранный период.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: страница админки загружена, когда: прошла минута с момента загрузки, тогда: счётчик активных пользователей отображается в шапке и его значение соответствует текущему состоянию активности.

- **[FR-2]** Дано: видна админка с панелью активности, когда: администратор нажимает на счётчик, тогда: открывается модальное окно с графиком активности за день (период по умолчанию).

- **[FR-3]** Дано: открыто модальное окно с графиком, когда: администратор выбирает другой период (час или неделя), тогда: график перестраивается и отображает активность за выбранный период.

- **[FR-4]** Дано: открыто модальное окно графика, когда: администратор нажимает кнопку выгрузки, тогда: инициируется скачивание файла со сводкой активности за выбранный период.

## 4.5. Разбиение на слайсы

**Анализ разреза:**

1. **Числа:** 4 функциональных требования (FR-1…FR-4)
2. **Кандидаты на обособленные деливеры:**
   - **Счётчик активности (FR-1):** администратор видит текущую нагрузку в один клик, может мониторить активность во время работы, не открывая модаль — независимая ценность
   - **График активности (FR-2, FR-3):** администратор анализирует динамику активности за выбранный период для оценки нагрузки — независимая ценность
   - **Выгрузка отчёта (FR-4):** администратор экспортирует агрегированные данные для составления отчётности и аудита — независимая ценность
3. **Порог:** ≥3 обособленных деливера с разными ценностями → **РЕЖЕМ на 3 слайса**
4. **Типовой исход:** режем

| # | Слайс | Владеет FR-* | Ценность в одиночку | Зависит от |
|---|-------|--------------|---------------------|------------|
| 1 | Счётчик текущей активности | FR-1 | Администратор видит текущую нагрузку в один клик и может быстро оценить ситуацию на момент просмотра | — |
| 2 | График активности за период | FR-2, FR-3 | Администратор анализирует динамику активности за выбранный период (час, день, неделя) для принятия решений о регламентных работах | Слайс №1 |
| 3 | Выгрузка отчёта об активности | FR-4 | Администратор экспортирует агрегированную сводку активности для составления отчётности по нагрузке на систему | Слайс №2 |

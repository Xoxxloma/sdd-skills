## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего функционала — в веб-админку «Арсенал» добавляются элементы для наблюдения за активностью пользователей.

### 1.1. Описание проблемы (Problem Statement)
Администраторы системы не видят ни текущую, ни историческую активность пользователей. Невозможно быстро оценить нагрузку, посмотреть её динамику за период и собрать сводку для отчётности. Регламентные работы планируются вслепую, что приводит к прерыванию пользовательских сессий.

### 1.2. Конечные потребители (End Users)
Администраторы системы «Арсенал» — внутренние сотрудники отдела эксплуатации.

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
**Заказчик:** руководитель отдела эксплуатации.  
**Эксперт для консультации:** тимлид команды «Арсенал-Core».

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор системы должен иметь возможность видеть активность пользователей в реальном времени, в динамике и в виде выгружаемой сводки, чтобы планировать безопасные окна регламентных работ и предоставлять прозрачные отчёты по нагрузке.

### 2.2. Ценность для бизнеса
- Сокращение прерванных пользовательских сессий во время регламентных работ.
- Прозрачная, верифицируемая отчётность по нагрузке для внутреннего аудита и планирования.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|------------------------|------------------|
| Неточные или устаревшие данные активности вводят в заблуждение при планировании работ | Средняя / высокая | При недоступности источника данных показывать индикатор недоступности («—», пустой график), а не устаревшее значение |
| Панель активности и выгрузка доступны непредусмотренным ролям, утечка информации | Средняя / средняя | Панель активности и функция выгрузки доступны только администраторам; оператору эти элементы не видны |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик активных пользователей в шапке веб-админки.
- Модальное окно с графиком активности пользователей за выбранный период (час, день, неделя).
- Возможность переключения периода внутри модального окна.
- Функция выгрузки сводки активности (агрегированные данные) за выбранный период в файл.
- Автоматическое обновление счётчика без перезагрузки страницы.

### 3.2. Не входит в проект (Out-of-scope)
- Список конкретных пользователей, находящихся в системе онлайн (только агрегированные числа).
- Автоматическая рассылка отчётов по активности.
- Прогнозирование будущей активности пользователей.

### 3.3. Архитектурные изменения и интеграции
Веб-админка «Арсенал» начинает потреблять агрегированные данные об активности пользователей. Все три элемента панели (счётчик, график, выгрузка) опираются на один источник — текущее число активных пользователей и историческую агрегированную активность за период. Точные механизмы получения данных и их хранения определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1:** Администратор при загрузке веб-админки видит в шапке счётчик с числом активных пользователей.

**FR-2:** Счётчик обновляется автоматически в пределах минуты после изменения числа активных пользователей; перезагрузка страницы не требуется.

**FR-3:** При клике на счётчик открывается модальное окно, в котором отображается график активности пользователей за выбранный по умолчанию период (одна из опций: час, день или неделя).

**FR-4:** Внутри модального окна администратор может переключаться между периодами (час, день, неделя), и график перестраивается автоматически.

**FR-5:** В нижней части модального окна расположена кнопка «Выгрузить сводку» (или аналогично), при нажатии которой формируется и скачивается файл со сводкой агрегированной активности за выбранный период.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: администратор находится на странице веб-админки после загрузки. Когда: страница полностью загружена. Тогда: в шапке виден счётчик с текущим числом активных пользователей.

- **[FR-2]** Дано: администратор открыл веб-админку. Когда: число активных пользователей изменилось. Тогда: счётчик обновляет своё значение в течение минуты; перезагрузка страницы не требуется.

- **[FR-3]** Дано: счётчик активных пользователей видна администратору. Когда: администратор кликает на счётчик. Тогда: открывается модальное окно с графиком активности за период по умолчанию (час, день или неделя, как определено на этапе реализации).

- **[FR-4]** Дано: модальное окно открыто с графиком. Когда: администратор переключает период (час → день, день → неделя и т.п.). Тогда: график перестраивается и показывает агрегированную активность за выбранный период.

- **[FR-5]** Дано: администратор видит график активности в модальном окне. Когда: администратор нажимает кнопку выгрузки сводки. Тогда: инициируется скачивание файла (формат по выбору на этапе реализации) со сводкой активности за выбранный период.

## 4.5. Разбиение на слайсы

**Шаг 1 — реши, есть ли что резать.**

1. **Числа:** 5 FR, 3 обособленных деливербла:
   - Счётчик активных пользователей (FR-1, FR-2) — отдельное место, отдельная ценность.
   - График активности в модалке (FR-3, FR-4) — отдельный компонент, отдельная ценность.
   - Выгрузка сводки (FR-5) — отдельный компонент, отдельная ценность.

2. **Ценность каждого кандидата:**
   - Счётчик: администратор видит текущую нагрузку и планирует ближайшие регламентные работы.
   - График: администратор видит исторический тренд активности, выявляет часы пик и низкую нагрузку за период.
   - Выгрузка: администратор получает сводку для отчётности, не берётся её вручную.

3. **Порог:** 3 обособленных деливербла → это эпик (есть что резать).

4. **Типовой исход:** РЕЖЕМ.

5. **Доказательство:** Счётчик без графика говорит «сейчас активных N», но не отвечает на вопрос «как менялось». График без выгрузки требует ручного переписывания данных. Каждый слайс даёт бизнесу отдельную ценность и может быть выпущен как отдельный релиз — риск от задержки одного компонента не распространяется на другие.

**Шаг 2 — таблица слайсов:**

| # | Слайс | Владеет FR-* | Ценность в одиночку | Зависит от |
|---|-------|--------------|---------------------|------------|
| 1 | Счётчик активных пользователей | FR-1, FR-2 | Администратор видит текущую нагрузку в один взгляд и может оценить, безопасно ли проводить регламентные работы прямо сейчас | — |
| 2 | График активности за период | FR-3, FR-4 | Администратор видит исторический тренд нагрузки, определяет часы пик и планирует долгосрочные работы | Слайс №1 (инструмент просмотра — клик по счётчику) |
| 3 | Выгрузка сводки активности | FR-5 | Администратор получает файл со сводкой для отправки в отчётность, не переписывая данные вручную | Слайс №2 (выгрузка доступна из модалки) |

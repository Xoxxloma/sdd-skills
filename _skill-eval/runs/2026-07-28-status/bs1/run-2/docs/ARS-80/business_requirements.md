## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего — в веб-админку «Арсенал» добавляются несколько связанных элементов для наблюдения за активностью пользователей.

### 1.1. Описание проблемы (Problem Statement)
Администраторы системы не видят ни текущую, ни историческую активность пользователей. Это не позволяет им:
- быстро оценить нагрузку на систему в данный момент;
- посмотреть динамику активности за выбранный период;
- получить сводку для отчётности перед аудитом.

В результате регламентные работы планируются вслепую, без знания о пиках активности.

### 1.2. Конечные потребители (End Users)
Администраторы системы «Арсенал» (внутренние сотрудники отдела эксплуатации).

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
- **Заказчик:** руководитель отдела эксплуатации.
- **Эксперт для консультации:** тимлид команды «Арсенал-Core».

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор должен иметь возможность видеть активность пользователей — сейчас, в динамике и в виде выгружаемой сводки, — чтобы планировать безопасные окна для регламентных работ и отчитываться по нагрузке перед аудитом.

### 2.2. Ценность для бизнеса
- Меньше прерванных пользовательских сессий во время регламентных работ (работы проводятся в правильное время).
- Прозрачная отчётность по нагрузке системы для аудита и внутреннего планирования ёмкости.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|----------------------|------------------|
| Неточные или устаревшие данные активности вводят администратора в заблуждение при планировании | Высокая / высокое | При недоступности источника данных показываем индикатор недоступности («—») или пустой график, а не кешированное / устаревшее значение |
| Выгрузка и панель активности доступны пользователям, для которых не предназначены | Средняя / средний | Панель активности и кнопка выгрузки видны только администраторам системы; для операторов эти элементы не отображаются |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик активных пользователей, отображаемый в шапке админки.
- Автоматическое обновление счётчика без перезагрузки страницы.
- Модальное окно с графиком активности пользователей за выбранный период.
- Переключение периодов (час / день / неделя) в модальном окне.
- Выгрузка сводки активности за выбранный период в файл (инициируется кнопкой в модалке).

### 3.2. Не входит в проект (Out-of-scope)
- Список конкретных пользователей онлайн (показываются только агрегированные числа).
- Автоматическая рассылка отчётов по активности.
- Прогнозирование будущей активности или рекомендации по планированию.

### 3.3. Архитектурные изменения и интеграции
Все три компонента (счётчик, график, выгрузка) опираются на одни и те же данные об активности пользователей: текущее число активных пользователей и агрегированная активность за период. Админка «Арсенал» становится потребителем этого источника данных. Точные механизмы получения данных, их хранения и обновления определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1 (Счётчик активности в шапке):**
Администратор видит счётчик активных пользователей в шапке админки. Значение обновляется автоматически, без перезагрузки страницы, отражая изменения в реальном времени (или в пределах минуты).

**FR-2 (Открытие модального окна):**
При клике на счётчик открывается модальное окно, в котором отображается график активности пользователей. По умолчанию график показывает активность за последний день; период можно изменить.

**FR-3 (Переключение периодов):**
В модальном окне администратор может переключаться между тремя периодами: час / день / неделя. Выбор периода автоматически перестраивает график, отражая активность за выбранный промежуток времени.

**FR-4 (Выгрузка сводки):**
В модальном окне есть кнопка выгрузки сводки активности. При клике администратор получает файл со сводкой активности пользователей за выбранный период.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано админка «Арсенал» открыта, когда страница загружена, тогда счётчик активных пользователей виден в шапке и содержит актуальное значение; счётчик обновляется в пределах минуты после изменения активности.

- **[FR-2]** Дано счётчик активности видим, когда администратор кликает на счётчик, тогда открывается модальное окно с графиком активности за период по умолчанию (последний день).

- **[FR-3]** Дано модальное окно открыто, когда администратор переключает период (час / день / неделя), тогда график автоматически перестраивается и отражает активность за выбранный период.

- **[FR-4]** Дано администратор выбрал период в модалке, когда нажимает кнопку выгрузки, тогда скачивается файл со сводкой активности за выбранный период.

## 4.5. Разбиение на слайсы

**Анализ по пунктам:**
1. **Числа:** 4 функциональных требования (FR-1, FR-2, FR-3, FR-4); три потенциально отдельных деливербла: счётчик в шапке, модальное окно с графиком + переключение периодов, выгрузка сводки.
2. **Ценность каждого кандидата:**
   - Счётчик активности: администратор видит нагрузку в данный момент без открытия отдельного экрана.
   - Модальное окно с графиком и переключением: администратор видит динамику активности за выбранный период (час/день/неделя) — это уже позволяет планировать регламентные работы.
   - Выгрузка сводки: администратор может подготовить отчёт для аудита.
3. **Порог:** 4 FR, покрывающих три разных куска функционала, каждый со своей ценностью для администратора. ≥4 FR + разные куски = превышаем порог эпика.
4. **Вывод:** РЕЖЕМ на три слайса.

| # | Слайс | Владеет FR-* | Ценность в одиночку | Зависит от |
|---|-------|--------------|---------------------|------------|
| 1 | Счётчик активности в шапке | FR-1 | Администратор видит текущую нагрузку без открытия отдельного экрана | — |
| 2 | График активности с историей периодов | FR-2, FR-3 | Администратор видит динамику активности за выбранный период (час/день/неделя) и может планировать регламентные работы по пикам | Слайс 1 (используют один источник данных) |
| 3 | Выгрузка сводки активности | FR-4 | Администратор готовит отчёт по активности для аудита | Слайс 2 (данные для выгрузки получаются из графика) |

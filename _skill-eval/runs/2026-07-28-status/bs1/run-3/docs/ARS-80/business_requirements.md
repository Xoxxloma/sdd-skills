## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего функционала — расширение веб-админки «Арсенал» элементами для наблюдения за активностью пользователей.

### 1.1. Описание проблемы (Problem Statement)
Администраторы системы не видят ни текущую, ни историческую активность пользователей. Это исключает возможность быстро оценить нагрузку на систему, посмотреть динамику активности за период и получить сводку для отчётности. Регламентные работы планируются вслепую, что приводит к прерыванию активных сессий.

### 1.2. Конечные потребители (End Users)
Администраторы системы «Арсенал» (внутренние сотрудники отдела эксплуатации).

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
**Заказчик:** руководитель отдела эксплуатации.
**Эксперт для консультации:** тимлид команды «Арсенал-Core».

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор должен иметь возможность видеть активность пользователей в реальном времени, анализировать динамику за выбранный период и выгружать сводку для отчётности, чтобы планировать безопасные окна регламентных работ и отчитываться по нагрузке перед аудитом.

### 2.2. Ценность для бизнеса
- Сокращение числа прерванных пользовательских сессий во время регламентных работ.
- Прозрачная отчётность по нагрузке на систему для аудита и долгосрочного планирования ёмкости.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)

| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Неточные данные активности вводят администратора в заблуждение при планировании | Средняя / Высокое | Если источник данных об активности недоступен, показываем пустой график и прочерк («—»), а не устаревшие значения. Данные не кэшируются. |
| Панель активности видна ролям, у которых нет на неё прав | Средняя / Высокое | Счётчик, график и выгрузка доступны только администраторам. Операторы панель не видят. |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик активных пользователей в шапке админки.
- График активности пользователей за выбранный период (час, день, неделя).
- Модальное окно с графиком, открывающееся по клику на счётчик.
- Возможность переключать период внутри модалки и перестраивать график.
- Выгрузка агрегированной сводки активности (числа активных пользователей за период) в файл.

### 3.2. Не входит в проект (Out-of-scope)
- Список конкретных пользователей, находящихся онлайн (только агрегированные числа активности).
- Автоматическая рассылка отчётов об активности.
- Прогнозирование будущей активности.

### 3.3. Архитектурные изменения и интеграции
Все три элемента (счётчик, график, выгрузка) опираются на единый источник данных об активности пользователей — текущее число активных пользователей и агрегированная активность за период. Админка «Арсенал» начинает потреблять эти данные. Точные механизмы получения, хранения и обновления данных об активности определяются на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**Процесс взаимодействия администратора с панелью активности:**

1. **FR-1** — Администратор открывает админку. В шапке (верхняя часть экрана) рядом с основной навигацией отображается счётчик: число активных пользователей в текущий момент. Значение видно сразу после загрузки страницы.

2. **FR-2** — Счётчик обновляется автоматически, без перезагрузки страницы. Интервал обновления не более одной минуты после изменения активности.

3. **FR-3** — Администратор кликает на счётчик. Открывается модальное окно с графиком активности. График отображает данные за период, установленный по умолчанию (один из предложенных: час, день или неделя). Ось X — время, ось Y — число активных пользователей.

4. **FR-4** — Внутри модалки администратор видит переключатель периода (три опции: час, день, неделя). Может выбрать другой период.

5. **FR-5** — При смене периода график перестраивается с новыми данными. Нет перезагрузки модального окна.

6. **FR-6** — В модальном окне есть кнопка выгрузки. По нажатию администратор получает файл, содержащий агрегированную сводку активности (таблица: период / число активных пользователей) за выбранный промежуток времени.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: админка загружена. Когда: страница отрисовалась. Тогда: счётчик активных пользователей видна в шапке, показывает актуальное число.

- **[FR-2]** Дано: счётчик отображается. Когда: активность пользователей изменилась. Тогда: счётчик обновляется в течение одной минуты, без перезагрузки страницы.

- **[FR-3]** Дано: счётчик видна. Когда: администратор кликает на счётчик. Тогда: открывается модальное окно с графиком активности за период по умолчанию (час, день или неделя — как выбрано), с осями и легендой.

- **[FR-4]** Дано: модалка открыта, график отображается. Когда: администратор меняет период с помощью переключателя. Тогда: выбранный период активирован, другие неактивны.

- **[FR-5]** Дано: период изменён. Когда: переключатель обновился. Тогда: график перестроен с данными за новый период в течение одной секунды, модалка остаётся открытой.

- **[FR-6]** Дано: модалка открыта с графиком. Когда: администратор нажимает на кнопку выгрузки. Тогда: скачивается файл (CSV или Excel) со сводкой (дата/время — число активных пользователей) за выбранный период.

## 4.5. Разбиение на слайсы

**Анализ разреза:**

1. **Числа:** В функционале 6 требований (FR-1…FR-6), три обособленных деливербла (счётчик, график, выгрузка).

2. **Ценность каждого кандидата:**
   - Счётчик в шапке (FR-1, FR-2): администратор видит текущую нагрузку сразу, не открывая дополнительные окна; может быстро решить о необходимости регламентных работ.
   - График активности за период (FR-3, FR-4, FR-5): администратор видит динамику, пики и спады активности; может выбрать безопасное окно.
   - Выгрузка сводки (FR-6): администратор создаёт отчёт для долгосрочного анализа и аудита; может документировать нагрузку за квартал.

3. **Порог:** 3 обособленных деливербла, каждый со своей ценностью, не требующей соседей — **режем на три слайса.**

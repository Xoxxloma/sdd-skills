## 1. Обзор изменения

### 1.1. Тип и стороны
Backend. `arsenal-activity` начинает отдавать данные об активности пользователей: текущее число
активных и агрегированный ряд за период. Потребители — слайсы эпика ARS-100.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `arsenal-activity` | новый эндпоинт активности | Арсенал-Core | 🟢 |
| `arsenal-admin-web` | потребитель (счётчик, модалка, выгрузка) | Фронт Арсенала | 🟢 |
| `sso-sessions` | источник живых сессий | Платформа доступа | 🟡 подтв. аналитиком |

### 1.3. Связь с бизнес-требованиями
**Своего БТ у этого узла нет — это узел-фундамент #0, слой реализации.** Он обслуживает часть
FR эпика ARS-100: FR-1, FR-2 (текущее число активных) и FR-3, FR-4 (ряд активности за период).
Файловая выгрузка (FR-5) в этот узел не входит и решается в слайсе ARS-103 поверх INT-2.

## 2. Взаимодействия (ядро)

### INT-1. Текущее число активных пользователей — 🟢
- **Граница/направление:** FE → BE
- **Триггер:** загрузка админки, далее опрос раз в 30 секунд
- **Контракт (запрос):** `GET /v1/activity/current`, параметров нет
- **Контракт (ответ):** `asOf: iso8601` — момент снятия; `activeUsers: int` — число активных
  сессий на этот момент; `sourceAvailable: bool` — `false`, когда источник сессий недоступен,
  и тогда `activeUsers` равен `null`, а не нулю
- **Пример ответа (успех):**
  ```json
  { "asOf": "2026-08-07T09:15:00Z", "activeUsers": 42, "sourceAvailable": true }
  ```
- **Ошибки:** `503` — источник сессий недоступен (тело с `sourceAvailable: false`)
- **Авторизация:** роль `admin` в «Арсенале»; оператору эндпоинт отдаёт `403`
- **Происхождение:** 🟢
- **Трассировка:** FR-1, FR-2

### INT-2. Ряд активности за период — 🟢
- **Граница/направление:** FE → BE
- **Триггер:** открытие модалки с графиком и смена периода
- **Контракт (запрос):** `GET /v1/activity/series`, параметр `period: hour|day|week` обязателен
- **Контракт (ответ):** `period: hour|day|week` — эхо запрошенного; `bucket: string` — шаг ряда
  (`5m` для `hour`, `1h` для `day`, `1d` для `week`); `points: массив`, элемент —
  `at: iso8601` и `activeUsers: int|null`, где `null` означает «за этот интервал данных нет»
  и не равен нулю
- **Пример ответа (успех):**
  ```json
  {
    "period": "hour",
    "bucket": "5m",
    "points": [
      { "at": "2026-08-07T08:00:00Z", "activeUsers": 37 },
      { "at": "2026-08-07T08:05:00Z", "activeUsers": null }
    ]
  }
  ```
- **Ошибки:** `400` — `period` не передан или не из перечисления; `503` — источник недоступен
- **Авторизация:** роль `admin` в «Арсенале»; оператору эндпоинт отдаёт `403`
- **Происхождение:** 🟢
- **Трассировка:** FR-3, FR-4

### INT-3. Чтение живых сессий из `sso-sessions` — 🟡
- **Граница/направление:** Сервис `arsenal-activity` → Сервис `sso-sessions`
- **Триггер:** снятие среза активности раз в минуту
- **Контракт (запрос):** выгрузка активных сессий по системе «Арсенал» за интервал
- **Контракт (ответ):** идентификаторы сессий и время последней активности
- **Ошибки:** обрабатываются как недоступность источника
- **Авторизация:** сервисный токен `arsenal-activity`, выдан командой платформы доступа
- **Происхождение:** 🟡 подтверждено аналитиком (не по коду; валидировать при интеграции)
- **Трассировка:** FR-1, FR-3

### Каталог ошибок (сводно)

| Код | Когда | Что видит пользователь |
|-----|-------|------------------------|
| `400` | `period` не из перечисления | график не перестраивается, показывается сообщение об ошибке |
| `403` | запрос не от администратора | панель активности не отображается |
| `503` | источник сессий недоступен | вместо числа и графика — «—», не ноль |

## 3. Backend — ответственность

### 3.1. По сервисам
`arsenal-activity` раз в минуту снимает срез активных сессий из `sso-sessions`, складывает его в
свою таблицу и отдаёт потребителям два представления: текущее число и агрегированный ряд.

### 3.2. Данные и хранение
Новая сущность `ActivitySample` — срез активности: `at: timestamp`, `activeUsers: int`,
`sourceAvailable: bool`. Срезы хранятся 30 суток, агрегация в `bucket` считается на чтении.
Происхождение: 🟢

### 3.3. Авторизация/доступ на бэке
Оба эндпоинта требуют роль `admin` системы «Арсенал». К `sso-sessions` сервис ходит собственным
токеном, пользовательский контекст не передаётся.

## 4. Frontend — ответственность

Не применимо: узел #0 — backend-узел, UI в нём не меняется. Счётчик, модалку и выгрузку строят
слайсы ARS-101, ARS-102 и ARS-103 поверх INT-1 и INT-2.

## 5. Нефункциональные требования

### 5.1. Синхронность, кэш, производительность
Оба запроса синхронные. Текущее число кэшируется на 30 секунд, ряд — на 5 минут.

### 5.2. Надёжность/деградация
Источник сессий недоступен — эндпоинты отвечают `503` с `sourceAvailable: false`. «Данных нет» и
«активных ноль» различимы всегда: первое — `null`, второе — `0`.

### 5.3. Безопасность/доступ (сводно)
Сервисный токен к `sso-sessions` хранится в секретах `arsenal-activity` и в ответах не появляется.
Персональных данных сессий наружу не отдаётся — только агрегированные числа.

## 6. Релиз и интеграция

### 6.1. Порядок выката
Сначала `arsenal-activity` с обоими эндпоинтами, затем слайсы админки в порядке ARS-101 → ARS-102
→ ARS-103.

### 6.2. Обратная совместимость
Новый сервис, существующие эндпоинты «Арсенала» не меняются.

### 6.3. Фиче-флаги
Флаг `arsenal.activity` в админке, по умолчанию выключен; на бэке флага нет.

### 6.4. План отката
Выключить флаг `arsenal.activity` — админка возвращается к прежнему виду. Эндпоинты при этом
можно оставить: потребителей у них не остаётся.

### 6.5. Преднастройка до релиза
- Сервисный токен `arsenal-activity` в `sso-sessions` — запросить у команды платформы доступа.
- Роль `admin` «Арсенала» — сверить, что она уже заведена и выдаётся эксплуатации.

## 7. Трассировка приёмки

| FR | Как проверяется |
|----|-----------------|
| FR-1 | `GET /v1/activity/current` возвращает `activeUsers` — число активных сессий на `asOf` |
| FR-2 | Повторный запрос через 30 секунд возвращает изменившееся `activeUsers` без перезагрузки |
| FR-3 | `GET /v1/activity/series?period=hour` возвращает ряд с шагом `5m` за последний час |
| FR-4 | Смена `period` на `day` возвращает ряд с шагом `1h` за сутки |

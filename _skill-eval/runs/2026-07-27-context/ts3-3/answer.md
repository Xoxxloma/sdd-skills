- **Триггер:** открытие любой страницы админки (первый запрос) и далее периодический

  ```json
  { "count": 42 }
  ```
- **Пример ответа (источник недоступен):**
  ```json
  { "count": null }
  ```
  HTTP-статус в этом случае — 200, намеренно не 5xx: по FR-3 недоступность источника —
  не ошибка, и FE не должен получать сигнал «ошибка», а должен показать «—».
- **Ошибки:** см. «Каталог ошибок» ниже.
- **Состояния UI по ответу:** значение (`count` — целое ≠ null и ≠ 0) → число; `count = 0`

- **Трассировка:** FR-1, FR-2, FR-3

## 3. Backend — ответственность
### 3.1. По сервисам
- **BE «Арсенала» (🟢 новая логика):** реализует эндпоинт INT-1; на каждый запрос — если
  в локальном кэше (TTL 30 c) есть свежее значение, отдаёт его; иначе обращается по INT-2
  к сервису аутентификации, обновляет кэш, отдаёт результат; при ошибке/таймауте INT-2 —
  отдаёт `{ "count": null }`, не пробрасывая 5xx на FE; проверяет роль вызывающего перед
  выполнением.
- **Сервис аутентификации (существующий, не изменяется):** 🟡 подтверждено аналитиком —
  уже считает активные сессии; 🟡 к валидации — точный интерфейс получения этого числа.

### 3.2. Данные и хранение
Новых сущностей/таблиц нет (явное подтверждение аналитика). Кэш на 30 c в BE «Арсенала» —
не персистентная сущность (in-memory/распределённый кэш — конкретный механизм на
усмотрение реализации владеющей команды); миграции не требуются.

### 3.3. Авторизация/доступ на бэке
Эндпоинт INT-1 проверяет роль вызывающего («Администратор») существующим ролевым
механизмом «Арсенала» (роли — БТ §5.3); негативный случай — 403 для «Оператора» и любой
другой роли. Для INT-2: авторизация BE «Арсенала» перед сервисом аутентификации — 🟡 к
валидации (механизм межсервисного вызова не подтверждён).

## 4. Frontend — ответственность
### 4.1. Где и что меняется в UI
Шапка админки «Арсенал»: новый элемент-индикатор числа активных пользователей, видим
только роли «Администратор». Вызывает INT-1.

### 4.2. Пользовательские сценарии
Администратор открывает любую страницу админки → в шапке кратко спиннер → значение
(число или «—») → далее автообновление каждые 60 c без перезагрузки (FR-1, FR-2). Если
источник недоступен на любом цикле опроса — вместо числа «—», без ошибки и без
устаревшего значения (FR-3). Оператор: элемент вообще не отображается и запрос не
отправляется.

### 4.3. Состояния
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|--------------------------|
| `loading` | первый запрос после открытия страницы | спиннер |
| `value` | 200, `count` — целое ≠ null и ≠ 0 | число |
| `zero` | 200, `count` = 0 (валидный ноль) | «0» (не «—») |
| `empty` | 200, `count` = null, либо любая сетевая/5xx/таймаут-ошибка INT-1 | «—» |
| `error_forbidden` | 403 | элемент не рендерится (не должно наступать при штатной работе FE) |

Отличие от типового шаблона: сетевые/5xx/таймаут-ошибки самого INT-1 **намеренно не**
получают отдельного состояния с баннером и retry — по FR-3 и UX-пожеланию «неяркий
индикатор» они схлопнуты в тот же вид «—», что и `empty` (🟢 предложение этой спеки).

### 4.3.1. Loading и таймауты
- **Cold-path** (первый запрос при открытии страницы): таймаут 5 c — 🟢 предложенное
  значение по умолчанию, не гейтовано аналитиком отдельно.
- **Warm-path** (последующие опросы): таймаут 3 c — 🟢 предложенное значение по умолчанию.
- **Polling:** интервал 60 c (подтверждено аналитиком); джиттер ±5 c — 🟢 предложение этой
  спеки, чтобы не синхронизировать запросы всех открытых сессий администраторов.
- Таймаут/5xx/сетевая ошибка → состояние `empty` («—»), без retry-кнопки; следующая
  попытка — обычный цикл polling.

### 4.4. Доступ по ролям в UI
Индикатор виден только роли «Администратор» (БТ §5.3); для «Оператора» элемент не
рендерится и запрос INT-1 не отправляется.

## 5. Нефункциональные требования
### 5.1. Синхронность, кэш, производительность
Синхронно (HTTP request/response) для INT-1 и INT-2. FE опрашивает BE «Арсенала» раз в
60 c (подтверждено аналитиком). Кэш на 30 c держится в BE «Арсенала» (подтверждено
аналитиком); конкретный механизм кэша (in-memory/распределённый) — на усмотрение
реализации. Таймауты — см. §4.3.1 (🟢 предложенные значения). Ожидаемая нагрузка: низкая —
внутренний инструмент поддержки, число одновременно открытых сессий администраторов
ограничено; точная оценка вне рамок этой доработки.

### 5.2. Надёжность/деградация
При недоступности сервиса аутентификации (источника) BE «Арсенала» не пробрасывает
ошибку на FE и не отдаёт устаревшее значение — отдаёт `{ "count": null }`, FE показывает
«—» (FR-3, риск-митигация из БТ §2.3). Полная недоступность самого BE «Арсенала» трактуется
так же (см. Каталог ошибок, §2) — тихая деградация без алярма, следующая попытка через
обычный цикл polling.

### 5.3. Безопасность/доступ (сводно)
| Граница | Администратор | Оператор |

- **Откат только FE**: BE продолжает отдавать INT-1, старый FE его не вызывает и не

| FR-1 | INT-1 | Дано открытую админку, когда страница загрузилась, тогда в шапке видно число активных пользователей. |

| FR-3 | INT-1 | Дано недоступный источник данных (сервис аутентификации/сам BE «Арсенала»), когда админка запрашивает счётчик, тогда в шапке отображается «—», а не ошибка или устаревшее число. |

# Бизнес-требования: Выгрузка истории операций в PDF (личный кабинет клиента)

> **Задача Jira/SberTrack:** SMSEC-2088
>
> **Статус готовности:** Готово к оценке
>
> **Открытые вопросы (требуют уточнения перед оценкой):**
> Все ключевые данные подтверждены, спецификация готова к оценке.

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего личного кабинета клиента: добавление функции выгрузки истории операций в PDF.

### 1.1. Описание проблемы (Problem Statement)
Клиенты не могут получить историю операций в виде документа, который можно передать в бухгалтерию.

### 1.2. Конечные потребители (End Users)
Клиенты (физические лица) — пользователи личного кабинета.

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
Заказчик: руководитель клиентского сервиса.
Эксперт для консультации по функционалу: тимлид личного кабинета.

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как клиент должен иметь возможность выгружать историю операций в PDF, чтобы отдавать её в бухгалтерию.

### 2.2. Ценность для бизнеса
Снижение количества обращений в поддержку за выписками по операциям.

### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|------------------------|-------------------|
| В PDF попадут операции другого клиента (не свои) | не указано | Проверка прав доступа перед формированием и выдачей файла: клиенту доступны только его собственные операции |
| Влияние на другие системы/процессы | не ожидается (со слов заказчика) | Отдельные меры не требуются |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Выгрузка истории операций клиента за выбранный период в формате PDF из личного кабинета.
- Доступ к выгрузке только для клиента и только по его собственным операциям.
- Понятное сообщение клиенту, если за выбранный период операций нет.

### 3.2. Не входит в проект (Out-of-scope)
- Выгрузка в Excel.
- Массовая выгрузка по нескольким клиентам одновременно.
- Выгрузка истории операций клиента оператором поддержки.

### 3.3. Архитектурные изменения и интеграции
Функционал использует существующий в личном кабинете механизм генерации файлов; новых интеграций с внешними системами не предполагается, влияния на другие системы заказчик не ожидает. Конкретная техническая реализация (какой именно механизм, какие сервисы и хранилища участвуют) сознательно не зафиксирована пользователем на бизнес-уровне и остаётся предметом технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса
Клиент открывает историю операций в личном кабинете → выбирает период → нажимает «Выгрузить в PDF» → получает файл со своими операциями за выбранный период.

- **FR-1.** Клиент инициирует выгрузку истории операций за выбранный период в PDF.
- **FR-2.** Выгружаемый файл содержит только операции самого клиента; доступ к чужим операциям исключён проверкой прав.
- **FR-3.** Если за выбранный период у клиента нет операций, система показывает понятное сообщение об отсутствии операций вместо формирования файла.
- **FR-4.** Оператор поддержки не может выполнять выгрузку истории операций клиента.

### 4.2. Критерии приёмки (Acceptance Criteria)
- **[FR-1]** Дано клиент авторизован в личном кабинете и находится в истории операций, когда клиент выбирает период и нажимает «Выгрузить в PDF», тогда система формирует и предоставляет клиенту PDF-файл с его операциями за этот период.
- **[FR-2]** Дано клиент запросил выгрузку за период, когда система формирует файл, тогда файл содержит исключительно операции этого клиента и не содержит операций других клиентов.
- **[FR-3]** Дано у клиента нет операций за выбранный период, когда клиент нажимает «Выгрузить в PDF», тогда система показывает понятное сообщение об отсутствии операций, а файл не формируется.
- **[FR-4]** Дано пользователь — оператор поддержки, когда оператор пытается выгрузить историю операций клиента, тогда система не предоставляет оператору такой возможности.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
High — по решению заказчика (руководителя клиентского сервиса).

### 5.2. Сроки и обоснование
До конца текущего квартала — срок привязан к отчётному периоду: клиентам нужна выписка для бухгалтерской отчётности за этот период.

### 5.3. Ролевая модель
| Роль | Права / доступные действия |
|------|------------------------------|
| Клиент | Видит и выгружает в PDF только свои собственные операции |
| Оператор поддержки | Не выгружает историю операций клиента |

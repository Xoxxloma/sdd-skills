# Техническая спецификация узла-фундамента #0 — готова к разработке

## Итоговое решение

Спецификация фундамента #0 завершена и размещена по пути:
```
docs/ARS-100/_foundation/technical_specification.md
```

## Что спроектировано

Узел-фундамент #0 — BE-only контракт для данных об активности пользователей, который потребляют все дочерние узлы эпика (ARS-101, ARS-102, ARS-103).

**Основной контракт INT-0:** `GET /api/admin/activity/data`
- Парамметры: `period_type` (current | hour | day | week), опциональные `since` и `until`
- Ответ: текущий счётчик активных пользователей + агрегированные данные за период
- Ключевая семантика:
  - `available: boolean` — флаг доступности источника (если false, данные недоступны)
  - `current_count: integer|null` — текущее число активных; `null` с кодом `insufficient_data` отличается от `available: false`
  - `aggregates: array|null` — точки графика за период; пустой массив `[]` значит период пуст (не ошибка)
  
**Концептуальные ключевые черты:**
- Только для роли **Администратор** (403 Forbidden для остальных)
- Синхронный запрос-ответ
- 30-секундный кэш на бэке Arsenal
- 5-секундный таймаут
- Агрегаты считаются на лету, новых таблиц не создаём
- При недоступности источника — возвращаем флаг `available: false`, а не устаревшие данные
- Чётко разделяем: нет данных в период (`aggregates: []`), недостаточно данных для текущего счётчика (`current_count_unavailable_reason: "insufficient_data"`), источник недоступен (`available: false`)

**Примеры JSON для всех сценариев включены**, включая:
- Текущий счётчик доступен
- Текущий счётчик + агрегаты за день
- Нет данных за период (пустой массив)
- Источник недоступен
- Недостаточно данных, но есть история

## Статус и открытые пункты

**Статус готовности:** Готово к разработке

**Подтверждено аналитиком (факты):**
- BE-only узел, данные собирает сам Arsenal
- Авторизация только для Администратора на бэке
- Синхронно, кэш 30 сек, таймаут 5 сек
- Выката фундамента раньше потребителей
- Фиче-флагов нет

**К валидации (допущения о существующих системах):**
- Точная схема таблиц/индексов логов активности в Arsenal
- Точный HTTP-код при недоступности источника
- Ожидаемый RPS и одновременность
- Границы исторических данных (сколько дней хранится)
- Алерты и мониторинг (пороги)

Эти пункты не блокируют начало разработки фундамента — отчёт на интеграции.

## Трассировка к бизнес-требованиям

Контракт INT-0 обслуживает все функциональные требования эпика:
- **FR-1:** Счётчик активных в шапке → вызов с `period_type: current`
- **FR-2:** Обновление без перезагрузки → polling INT-0, свежесть в пределах 30 сек кэша
- **FR-3:** График за период → вызов с `period_type: day/week/hour`
- **FR-4:** Переключение периода → вызов с другим `period_type`
- **FR-5:** Выгрузка сводки → использует `aggregates` из INT-0

## Следующий шаг

Дочерние узлы (ARS-101, ARS-102, ARS-103) унаследуют INT-0 без изменений, встроят его в свои UI-ответственности и опишут маппинг состояний ответа на UI-состояния (value / zero / empty / error_source / error_forbidden).

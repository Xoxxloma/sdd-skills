# Техническая спецификация: Узел-фундамент #0 — контракт данных активности

Спецификация готовой к разработке для узла-фундамента #0 эпика ARS-100.

**Статус:** Готово к разработке

**Файл спецификации:** `docs/ARS-100/_foundation/technical_specification.md`

## Краткое резюме

Узел-фундамент #0 — это BE-only контракт, который предоставляет данные активности пользователей (текущее число активных + агрегированные данные за период) дочерним узлам эпика (ARS-101, ARS-102, ARS-103).

### Ключевые характеристики

**Контракт INT-0: Получение текущего числа активных пользователей и агрегатов активности за период**
- **Тип:** 🟢 новое
- **Граница:** Backend Arsenal → Фронты потребителей
- **Метод:** GET `/api/arsenal/activity/stats` (концептуально)
- **Параметры:** `start_ts`, `end_ts`, опционально `period_type` (hour/day/week)

**Ответ включает:**
- `status`: success | no_data_for_period | unavailable_source
- `current_active_count`: текущее число активных (null при недоступности)
- `aggregates`: массив с данными активности за выбранный период (поля: timestamp, duration_minutes, active_count, sessions_started, sessions_ended)
- `period_info`: метаинформация о периоде и гранулярности данных
- `error_code` и `error_message` (при ошибках)

**Состояния UI потребителя:**
- `loading` → спиннер
- `value` → success, count > 0
- `zero` → success, count = 0
- `empty` → no_data_for_period или пусто
- `error_source` → unavailable_source (5xx, таймаут)
- `error_forbidden` → 403 (не администратор)

**Ключевые требования (все подтверждены аналитиком):**
1. **Источник:** Backend Arsenal собирает данные активности сам, не привлекает третьих сервисов
2. **Обработка ошибок:** при недоступности источника отдаём флаг `unavailable_source`, не устаревшее значение из кэша
3. **Хранение:** агрегаты вычисляются на лету, новых таблиц не создаётся
4. **Синхронность:** синхронный запрос с кэшем 30 сек на BE, таймаут 5 сек
5. **Авторизация:** только роль Администратор, проверка на бэке Arsenal
6. **Релиз:** фундамент выкатывается раньше потребителей, без фиче-флагов

**Трассировка:**
- FR-1 (отображение числа активных в шапке) ← INT-0
- FR-2 (автоматическое обновление счётчика) ← INT-0 (polling)
- FR-3 (открытие графика за период) ← INT-0 (запрос aggregates)
- FR-4 (переключение периода) ← INT-0 (новый запрос с другими start_ts/end_ts)
- FR-5 (выгрузка сводки) ← INT-0 (данные для файла)

**Открытые вопросы:** нет — все технические решения приняты, спецификация полностью готова к разработке.

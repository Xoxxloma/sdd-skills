# Техническая спецификация: Узел-фундамент #0 — Контракт данных активности

## Выполнено

Создана техническая спецификация для узла-фундамента #0 (слой на бэке «Арсенала», который обслуживает FR-1..FR-5 эпика ARS-100 в части данных активности).

## Файл

**Путь:** `docs/ARS-100/_foundation/technical_specification.md`

## Содержание спецификации

### Ключевые решения (все — подтверждены аналитиком)

1. **Тип:** BE-only. Arsenal Backend отдаёт контракт данных активности; фронты детей потребляют независимо.

2. **Главный контракт (INT-0):** HTTP GET `/api/v1/admin/activity` с параметром `period` (current | 1h | 24h | 7d).
   - Возвращает текущий счёт активных пользователей и агрегаты активности за запрошенный период.
   - Всегда 2xx, но status внутри JSON различает три состояния: `available` (успех), `unavailable` (источник недоступен), `no_data` (нет данных за период).
   - При недоступности источника возвращает признак, не устаревшее значение.
   - Кэш 30 секунд на бэке Arsenal.

3. **Данные:** Агрегаты считаются на лету, новых таблиц нет.

4. **Авторизация:** Только роль «Администратор», проверка на бэке Arsenal.

5. **Производительность:** Синхронный запрос, таймаут 5 секунд на источнике.

6. **Порядок выката:** Фундамент раньше потребителей; флагов нет.

7. **Трассировка:** INT-0 реализует все FR-1..FR-5.

### Структура спецификации

- **§1 Обзор:** Тип, затронутые сервисы, связь с БТ
- **§2 Взаимодействия:** Полный контракт INT-0 — метод, параметры, JSON-примеры для трёх сценариев (успех, недоступность, нет данных), ошибки, авторизация
- **§3 Backend:** Ответственность Arsenal Backend, отсутствие новых таблиц
- **§4 Frontend:** Не применимо (BE-only; фронты в детских узлах)
- **§5 NFR:** Синхронность, кэш, таймауты, надёжность, безопасность
- **§6 Релиз:** Порядок выката, обратная совместимость, откат, преднастройка
- **§7 Трассировка:** Маппинг FR → INT-0 → тест-кейсы (успешные и ошибочные)
- **§8 Открытые вопросы:** Все технические решения приняты, открытых нет

## Статус готовности

**Готово к разработке.** Все технические решения приняты, контракт INT-0 полностью спроектирован с JSON-примерами, семантика null и ошибок чётко определена. Фронты детей могут писать против этого контракта без уточнений.

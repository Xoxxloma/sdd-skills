# Техническая спецификация узла-фундамента #0 — готова

## Результат

Создана техническая спецификация для узла-фундамента #0 (данные активности пользователей), на которую опираются FR-1..FR-5 эпика ARS-100.

**Файл:** `docs/ARS-100/_foundation/technical_specification.md`

**Статус готовности:** Готово к разработке

## Спроектированные контракты

### INT-0. Текущее число активных пользователей — 🟢
- Синхронный GET-контракт (BE ← FE потребитель)
- Поля: `count` (number | null), `last_updated_at`, `is_available` (boolean)
- Семантика null: `is_available: false` → источник недоступен (не отдаём устаревшее значение)
- Кэш: 30 сек на бэке Arsenal
- Авторизация: только Administrator
- **JSON-примеры:** включены (успех с данными, успех с is_available: false)

### INT-1. Агрегированная активность за период — 🟢
- Синхронный GET-контракт с параметром `period` (hour | day | week)
- Поля: `period`, `start_at`, `end_at`, `is_available`, `has_data`, `datapoints[]`
- Семантика: различаем `is_available: false` (источник упал) от `has_data: false` (период пуст, но источник работал)
- Кэш: 30 сек
- Авторизация: только Administrator
- **JSON-примеры:** включены (с данными, период пуст, источник недоступен)

## Ключевые решения

1. **Два контракта вместо одного:** INT-0 — лёгкий, для счётчика и polling (FR-1, FR-2); INT-1 — с временными рядами для графика и выгрузки (FR-3, FR-4, FR-5)

2. **Явная семантика ошибок и недоступности:** 
   - `is_available: true, has_data: true` → данные есть, рисуем
   - `is_available: true, has_data: false` → период валидный, но пуст (показываем «нет данных»)
   - `is_available: false` → источник упал (показываем «—» / ошибка + retry)
   - Никогда не отдаём устаревшее значение из кэша предыдущего периода

3. **Реализация:** Агрегаты считаются на лету из существующих логов сессий, новых таблиц нет

4. **Производительность:** 
   - Синхронно, 30 сек кэш, 5 сек таймаут
   - Обеспечивает FR-2 («обновляется в пределах минуты») при условии polling каждые 30 сек

5. **Авторизация:** Оба контракта доступны только роли Administrator (существует в системе); проверяется по токену на бэке

6. **Порядок выката:** Фундамент (Arsenal BE INT-0 + INT-1) выкатывается ПЕРВЫМ, дочерние фронты после

## Трассировка

| FR | Контракт | Состояние |
|----|----------|-----------|
| FR-1 | INT-0 | Текущее число при загрузке |
| FR-2 | INT-0 polling | Обновление без перезагрузки (≤ 1 мин) |
| FR-3 | INT-1 (period=day default) | Открытие модалки с графиком |
| FR-4 | INT-1 (period parameter) | Переключение периода |
| FR-5 | INT-1 export | Выгрузка сводки в файл |

# Техническая спецификация: узел-фундамент #0 — контракт данных активности

Спека готова к разработке. Все технические решения приняты аналитиком.

## Краткое резюме

**Узел-фундамент #0** для эпика ARS-100 — это BE-only контракт данных активности пользователей, который подаёт сигнал всем трём фронтальным элементам эпика (счётчик в шапке админки, модаль с графиком, выгрузка сводки).

### Ядро контракта — INT-0

Один эндпоинт `/api/arsenal/activity-metrics` с параметром `granularity`:
- `granularity=current` → текущее число активных пользователей (для счётчика).
- `granularity=hourly|daily|weekly` + `period_start/period_end` → агрегаты за период (для графика и выгрузки).

**Ответ всегда 200 OK** с флагом статуса в теле:
```json
{
  "data": { "active_users_count": 42, "timestamp": "..." },
  "status": "available" | "unavailable" | "no_data"
}
```

Статусы:
- `available` → данные получены, `data` содержит значение(я).
- `unavailable` → источник не отклик (таймаут, 5xx, сеть); `data = null`; фронт показывает ошибку + retry.
- `no_data` → период валиден, но в источнике за этот период нет данных; `data = null`; фронт показывает пусто.

### Авторизация

Только роль **Администратор** имеет доступ. Других ролей → 403 Forbidden. Проверка на стороне Arsenal Backend.

### Производительность

- **Синхронный** запрос (блокирующий).
- **Кэш 30 секунд** на стороне бэка (для холодного пути).
- **Таймаут 5 секунд** на весь запрос.
- При недоступности источника → флаг `unavailable`, не устаревшее значение.

### Хранение

Новых таблиц не заводится. Агрегаты вычисляются **на лету** из существующих логов активности. Backend Arsenal собирает данные сам (нет зависимостей от внешних сервисов).

### Выкат

Узел-фундамент выкатывается **РАНЬШЕ** всех фронтов-потребителей. Фиче-флаги не требуются — релизим атомарно.

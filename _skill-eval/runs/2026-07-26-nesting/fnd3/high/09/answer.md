# Техническая спецификация: Фундамент #0 — контракт данных активности

## Введение
Выполнен прогон режима узла-фундамента #0 для эпика ARS-100. На входе был эпик-БТ (business_requirements.md) с пятью функциональными требованиями (FR-1..FR-5) по панели активности пользователей в админке Arsenal. Аналитик подтвердил все технические гейты; открытых вопросов нет.

## Что спроектировано
**Одно взаимодействие (INT-1)** — новый контракт данных активности, который бэк Arsenal предоставляет потребляющим фронт-приложениям (детским узлам).

### Основные решения (🟢 новое):
1. **Контракт INT-1:** Синхронный BE → Потребитель запрос, возвращает:
   - `current_count` (int | null): число активных пользователей в текущий момент.
   - `periods` (object): агрегированная активность по запрошенным периодам (hour, day, week, month).
   - `is_available` (boolean): флаг доступности источника (ключевое различие между «нет данных за период» и «недоступностью»).
   - `error` (object | null): описание ошибки, если возникла.

2. **Авторизация:** 🟡 подтверждено аналитиком
   - Только роль `Administrator` имеет доступ.
   - Проверка на бэке Arsenal, HTTP 403 при отказе.

3. **Надёжность:** 🟡 подтверждено аналитиком
   - При недоступности источника → `is_available=false` + код `source_unavailable`, а не устаревшие данные.
   - Различие между нет-данных (`is_available=true, data=null`) и недоступностью (`is_available=false`).

4. **Производительность:** 🟡 подтверждено аналитиком
   - Синхронно, кэш 30 секунд на стороне Arsenal.
   - Таймаут 5 секунд.
   - Агрегаты на лету, без новых таблиц.

5. **Состояния UI для потребителей:**
   - `value`: `is_available=true, current_count > 0`.
   - `zero`: `is_available=true, current_count = 0`.
   - `empty`: `is_available=true, data=null` (нет данных за период).
   - `error_source`: `is_available=false` (источник недоступен).
   - `error_forbidden`: HTTP 403 (нет доступа).
   - `loading`: при загрузке.

6. **Примеры JSON:** Спроектированы полные примеры для трёх сценариев:
   - Успешный ответ с текущим счётом и агрегатами за три периода.
   - Недоступность источника.
   - Частичная доступность (период без данных, но источник работает).

7. **Трассировка:** Контракт #0 обслуживает все FR-1..FR-5:
   - FR-1: счётчик активных пользователей в шапке.
   - FR-2: автоматическое обновление счётчика.
   - FR-3: открытие модалки с графиком.
   - FR-4: переключение периода.
   - FR-5: выгрузка сводки.

8. **Порядок выката:** 🟡 подтверждено аналитиком
   - Фундамент #0 выкатывается ПЕРВЫМ, до всех потребляющих фронт-детей.
   - Фиче-флаги не используются, релиз атомарный.

## Открытые вопросы
**Нет открытых технических вопросов.** Все 10 гейтов закрыты: каждый либо подтверждён аналитиком (🟡 факт), либо спроектирован как 🟢 новое.

## Допущения, требующие валидации при интеграции
- Точные источники данных пользовательских сессий и схема их хранения.
- Механизм управления ролью `Administrator` в Arsenal.
- Ожидаемая нагрузка (одновременные потребители, пики).

## Статус готовности
**Готово к разработке.** Спецификация содержит полный контракт с JSON-примерами, обработкой ошибок, авторизацией, состояниями UI и плана выката. Потребляющие фронт-дети получат однозначный контракт и смогут писать против него независимо.

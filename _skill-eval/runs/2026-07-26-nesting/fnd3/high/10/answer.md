# Техническая спецификация: Узел-фундамент #0 — готово к разработке

Спека узла-фундамента #0 «Контракт данных активности пользователей» написана и сохранена в:
**`docs/ARS-100/_foundation/technical_specification.md`**

## Резюме

Узел-фундамент #0 обслуживает все пять функциональных требований эпика ARS-100 (FR-1..FR-5) единым контрактом данных активности. Это BE-only слой без собственного БТ — его бизнес-обоснование трассируется к эпик-БТ.

### Основной контракт: INT-0 (GET /api/admin/activity)

**Ответственность Arsenal Backend:**
- Собирает текущий счёт активных пользователей
- Считает агрегаты активности на лету за запрошенный период (час / день / неделя)
- Отличает недоступность источника (`is_available: false`) от отсутствия данных за период (`no_data_for_period: true`)
- Кэширует результат 30 сек на стороне Arsenal
- Проверяет авторизацию (только роль "Администратор")
- Возвращает таймаут 5 сек при недоступности источника

**Ответ контракта (успех, period=current):**
```json
{
  "current_count": 42,
  "is_available": true,
  "no_data_for_period": false,
  "aggregates": null,
  "summary_data": null
}
```

**Ответ контракта (успех, period=day):**
```json
{
  "current_count": 42,
  "is_available": true,
  "no_data_for_period": false,
  "aggregates": [
    { "timestamp": "2026-07-26T00:00:00Z", "count": 15 },
    { "timestamp": "2026-07-26T01:00:00Z", "count": 18 }
  ],
  "summary_data": {
    "period_start": "2026-07-26T00:00:00Z",
    "period_end": "2026-07-27T00:00:00Z",
    "min": 15,
    "max": 35,
    "avg": 22.5,
    "total_sessions": 450
  }
}
```

**При недоступности источника:**
```json
{
  "current_count": null,
  "is_available": false,
  "no_data_for_period": false,
  "aggregates": null,
  "summary_data": null
}
```

### Трассировка к FR-*
| FR | Что обслуживает |
|----|----|
| FR-1 | Счётчик активных в шапке (current_count) |
| FR-2 | Polling счётчика без перезагрузки (INT-0 + кэш 30c) |
| FR-3 | Модалка с графиком (aggregates за period=day) |
| FR-4 | Переключение периодов (period: day/week/hour) |
| FR-5 | Выгрузка сводки (summary_data) |

### Порядок выката
Узел #0 выкатывается **первым**, раньше детских компонентов (счётчик, модалка, выгрузка). Они наследуют контракт INT-0 без изменений.

### Статус
✅ **Готово к разработке** — все технические решения приняты аналитиком, открытых вопросов нет.

### К валидации
Пункты, которые уточняются при интеграции:
- Точный источник текущего счёта активных (кэш/Redis/таблица)
- Точный источник исторических данных для периодов
- Политика хранения исторических данных (retention)
- Ожидаемая нагрузка на INT-0

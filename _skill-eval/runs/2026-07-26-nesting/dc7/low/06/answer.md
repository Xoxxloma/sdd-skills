## Взаимодействия (ядро)

**Gate 2 — Инвентарь взаимодействий:**

Три UI-элемента вероятно опираются на 1–2 backend-запроса:
1. **Счётчик в шапке** — текущее число активных пользователей (в реальном времени или периодический опрос)
2. **Модальное окно с графиком** — история активности за выбранный период (час/день/неделя)
3. **Кнопка выгрузки** — те же данные активности, но в файл

## Контракты

**Gate 4 — Форма контракта:**

**Вопрос 4:** Для **текущего счётчика** (INT-1):
- **Предложение A:** Синхронный эндпоинт, возвращает `{ "count": <int>, "timestamp": "ISO string" }`. Count — **null если источник недоступен** (безопасность: не отдаём устаревшие данные).
- **Предложение B:** То же, но count = **0 если недоступно**, и состояние источника инфируем из отдельного флага.
- Какое предпочитаете, или предложу иначе?

**Вопрос 5:** Для **данных активности по периоду** (INT-2):
- **Предложение:** Backend отдаёт агрегированные данные (например, по минутам или 5-минутным периодам):
  ```json
  {
    "data": [ { "timestamp": "...", "count": <int> }, ... ],
    "period": { "start": "...", "end": "...", "bucket": "1m" }
  }
  ```
- Как агрегируются данные (по минутам? часам?)? И **на какую глубину хранится история активности** (последний день / неделя / месяц)?

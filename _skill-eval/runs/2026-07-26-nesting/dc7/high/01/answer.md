## Intake (Step 0)

Прочитан документ бизнес-требований. Подтверждённое содержание:
- **Слайс эпика:** ARS-90, функция FR-5
- **Конечные пользователи:** Администраторы системы Arsenal (внутренние сотрудники)
- **Бизнес-цель:** Видеть активность пользователей (текущую, в динамике, выгружаемую сводку) для планирования регламентных работ и отчётности
- **Входит в проект:**
  - Счётчик активных пользователей в шапке админки (обновляемый без перезагрузки)
  - Модальное окно с графиком активности за выбранный период (час/день/неделя)
  - Кнопка выгрузки сводки активности в файл за выбранный период
- **Критерий приёмки (FR-5):** Дано открытую модалку с выбранным периодом, когда администратор нажимает выгрузку, тогда он получает файл со сводкой активности за этот период
- **Ролевая модель:** Только Администраторы видят счётчик, график и выгрузку; Операторы — нет
- **Обработка ошибок (из БТ):** При недоступности источника показывать «—» / пустой график

### **Gate 5. Ошибки и состояния UI**

**Proposal (🟢):**

| Состояние | Условие | Что видит админ |
|-----------|---------|-----------------|
| `loading` | первый запрос счётчика / открытие модали | спиннер в counter + skeleton графика |
| `value` | 200 OK, count ≠ null и ≠ 0 | число активных + график |
| `zero` | 200 OK, count = 0 (валидный ноль) | «0» активных |
| `empty` | 200 OK, count = null или timeline = [] | «—» / пусто |
| `error_source` | 5xx / таймаут сети | сообщение об ошибке + кнопка retry |
| `error_forbidden` | 403 (не Администратор) | не видит счётчик / модали (скрыто) |

**Таймауты:**
- cold-path (первый запрос): 3s → if timeout: показываем error_source
- warm-path (polling counter): 2s
- graph (modal): 5s

**Вопросы:**
1. Эти таймауты верны? Какие должны быть?
2. Polling интервал для счётчика: каждые 10s? Каждые 30s?
3. Graph кэшируется на фронте после загрузки или перезагружается при переходе между периодами?

### **Gate 8. Синхронность / производительность / кэш**

**Proposal (🟢):**

- **Счётчик в header:** polling каждые 10s (FE отправляет GET)
- **График в модали:** fetch на открытие; **не** polling (ждём, пока админ не сменит период)
- **Кэш на BE:** 5s TTL для одного и того же периода (экономим нагрузку)
- **Ожидаемая нагрузка:** десятки администраторов, каждый 1 запрос в 10с → ~10 QPS; терпимо

**Вопросы:**
1. Интервал polling для счётчика: 10s верно?
2. Нужен ли кэш? TTL = 5s подходит?
3. Ожидаемое число активных пользователей в системе? (для размера ответа)

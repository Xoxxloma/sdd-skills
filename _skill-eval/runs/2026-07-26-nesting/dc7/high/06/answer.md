## Ключевые решения и вопросы

### ❓ КРИТИЧЕСКИЙ ГЕЙТ: Механизм выгрузки (блокирует остальное)

Как реализуется экспорт сводки? Три варианта:

**Вариант A — Чистый FE (CSV генерируется в браузере)**
- Модалка уже содержит данные активности (из других слайсов ARS-90)
- FE генерирует CSV локально на JavaScript
- Браузер скачивает файл
- Нет нового BE endpoint
- ✅ Плюсы: просто, быстро (~100ms), нет зависимости от BE
- ❌ Минусы: требует, чтобы данные были полностью доступны в FE

**Вариант B — BE генерирует и отдаёт файл**
- FE отправляет `POST /admin/activity/export` с параметрами периода
- BE агрегирует данные и возвращает CSV файл
- ✅ Плюсы: BE контролирует доступ, может кэшировать
- ❌ Минусы: новый endpoint, зависимость от BE, таймауты

**Вариант C — FE запрашивает данные, затем генерирует CSV**
- FE вызывает `GET /admin/activity/summary?period=...&date=...`
- BE возвращает JSON с данными
- FE генерирует CSV локально
- ✅ Плюсы: разделение ответственности, данные могут использоваться для графика
- ❌ Минусы: два этапа, сложнее, но часто уже есть в других слайсах

**Мой вопрос:** Какой вариант выбрать — A, B или C? *(Это определит структуру контрактов и весь остальной дизайн.)*

### 🟢 Дизайн-предложения (нужна подтверждение)

**1. Структура данных сводки**
Я предлагаю следующую структуру:
```json
{
  "period": "day",
  "date": "2026-07-26",
  "data": [
    { "time": "00:00", "active_users": 42 },
    { "time": "01:00", "active_users": 38 },
    ...
    { "time": "23:00", "active_users": 55 }
  ]
}
```

Подходит такая структура? Есть ли дополнительные поля/метрики в сводке (типы пользователей, регионы и т.п.)?

**2. Формат файла и имя**
- Предлагаю CSV с колонками: Время | Активные пользователи
- Имя файла: `activity_<период>_<дата>.csv` (например, `activity_day_2026-07-26.csv`)
- OK?

**3. Состояния UI**
Предлагаю эти состояния:
- `idle` — кнопка готова
- `loading` — идёт генерация/загрузка (спиннер на кнопке)
- `success` — файл скачан (toast "Сводка выгружена")
- `error_source` — ошибка при получении данных (5xx / таймаут / сеть)
- `error_forbidden` — нет доступа (403)
- `empty` — нет активности за период (экспортируется пустая сводка)

Это полный набор состояний, или что-то не хватает?

**4. Таймауты**
- Cold-path (первый запрос): 3 сек
- Warm-path (повторные): 1.5 сек
- FE-only (вариант A): ~100ms
Подходят эти значения?

**5. Роли в UI**
- Admin: видит кнопку, может выгрузить
- Operator: кнопка скрыта

Верно ли это из БТ?

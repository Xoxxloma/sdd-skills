# Анализ фундамента эпика ARS-100

Я прочитал все три детских БТ: A (ARS-101, Счётчик активных), B (ARS-102, Модалка с графиком), C (ARS-103, Выгрузка сводки).

## Вывод: общий фундамент ЕСТЬ

Все три слайса опираются на ОДИН И ТОТ ЖЕ источник данных об активности пользователей. Это явно сказано в разделе 3.3 каждого БТ:

> "Все три элемента опираются на одни и те же данные об активности пользователей (текущее число активных и агрегированная активность за период). Админка «Арсенал» начинает потреблять эти данные."

**Данные, которые все трое запрашивают:**
1. **Текущий счёт активных пользователей** — ARS-101 (FR-1, FR-2) отображает и обновляет в реальном времени
2. **Агрегированная активность по периодам** (час/день/неделя) — ARS-102 (FR-3, FR-4) и ARS-103 (FR-5) используют для графика и выгрузки

## Рекомендация: оформить узел #0

Проектируем одну техническую спеку для источника данных активности. Это будет узел-фундамент #0 без собственного БТ — слой реализации, который обслуживает все трёх детей.

**Черновая форма контракта #0, собранная из детских БТ:**

```json
{
  "current_active_users": "number",
  "activity_aggregates": [
    {
      "timestamp": "ISO 8601",
      "active_users": "number",
      "period_type": "hour | day | week"
    }
  ]
}
```

**Трассировка полей по фичам:**
- `current_active_users` — ARS-101 (FR-1, FR-2); нужен для отображения счётчика и его реал-тайм обновления
- `activity_aggregates` — ARS-102 (FR-3, FR-4) для построения графика с переключением периода; ARS-103 (FR-5) для выгрузки сводки

## Следующий шаг

**Дальше спеки в порядке:**
1. Сначала спека #0 (узел-фундамент, источник данных)
2. Потом спеки A, B, C по порядку — они наследуют контракт #0 без изменений

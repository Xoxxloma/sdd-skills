# Анализ фундамента ARS-100

## Состояние эпика
Прочитал БТ эпика ARS-100 и три детских БТ:
- **ARS-101** (счётчик активных): владеет FR-1, FR-2
- **ARS-102** (модалка с графиком): владеет FR-3, FR-4
- **ARS-103** (выгрузка сводки): владеет FR-5

## Признак общего фундамента

Все три ребёнка **опираются на один и тот же источник данных**: "данные об активности пользователей" (текущее число активных и агрегированная активность за период).

Из раздела 3.3 каждого детского БТ:
> Все три элемента опираются на одни и те же данные об активности пользователей (текущее число активных и агрегированная активность за период). Админка «Арсенал» начинает потреблять эти данные.

Это cross-sibling признак: ≥2 ребёнка (здесь все 3) опираются на ОДИН И ТОТ ЖЕ источник.

**Вывод: есть общий фундамент #0 — сервис данных об активности пользователей.**

## Форма данных, собранная из детских БТ

Черновая форма ответа от сервиса #0:

```
{
  "activeUserCount": number,           // Текущее число активных пользователей (FR-1)
  "activityMetrics": [                 // Агрегированные метрики активности за период (FR-3, FR-4, FR-5)
    {
      "timestamp": string (ISO 8601),
      "activeUsersCount": number
    }
  ]
}
```

**Трассировка полей:**
- `activeUserCount` — нужен ARS-101 (FR-1, FR-2): текущий счёт для отображения и обновления без перезагрузки
- `activityMetrics[]` — нужны ARS-102 (FR-3, FR-4): данные за период (час/день/неделя) для графика с переключением периода
- `activityMetrics[]` — нужны ARS-103 (FR-5): данные для выгрузки сводки в файл

## Что дальше?

**Вопрос аналитику:**

Разбил эпик на A (счётчик), B (график), C (выгрузка). Вижу: все три опираются на **сервис данных об активности пользователей**. Оформить как общий тех-фундамент (узел #0) — спроектировать один раз, дети наследуют его контракт?

**Важно:** своего БТ у #0 не будет, это слой реализации.

**Варианты:**
1. **Спроектировать сервис данных активности один раз (узел #0)** — спека #0 идёт первой, дети наследуют её контракт неизменным (одинаковые поля, типы и семантика null)
2. **Общего фундамента нет** — каждый ребёнок проектирует доступ к данным сам (риск разъехавшихся контрактов)

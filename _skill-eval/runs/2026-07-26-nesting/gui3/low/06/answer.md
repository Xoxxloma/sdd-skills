# Анализ фундамента для эпика ARS-100

## Состояние эпика

Прочитал детские БТ. Детей три:
- **A (ARS-101)**: FR-1, FR-2 — Счётчик активных пользователей
- **B (ARS-102)**: FR-3, FR-4 — Модалка с графиком активности
- **C (ARS-103)**: FR-5 — Выгрузка сводки активности

## Анализ cross-sibling зависимостей

Во всех трёх БТ, в разделе 3.3 (Архитектурные изменения), повторяется одна и та же строка:

> "Все три элемента опираются на одни и те же данные об активности пользователей (текущее число активных и агрегированная активность за период)."

Это означает: **ВСЕ ТРИ ребёнка потребляют один и тот же источник данных** — агрегированные метрики активности пользователей (текущее число + история за период).

## Вывод

Найден явный cross-sibling признак. Три независимых слайса (A, B, C) опираются на один общий источник данных. Это идеальный кейс для **фундамента #0** — единого контракта доступа к данным активности, который все три унаследуют без изменения состава.

## Рекомендация

Разбил на A, B, C. Вижу: все три опираются на **единый источник данных об активности пользователей** (текущее число активных + метрики за период). Оформить как общий тех-фундамент (узел #0) — спроектировать один раз, дети наследуют его контракт?

**Важно:** своего БТ у #0 не будет — это слой реализации. Спека #0 пойдёт в `_foundation/technical_specification.md`, дети наследуют её контракт без изменений.

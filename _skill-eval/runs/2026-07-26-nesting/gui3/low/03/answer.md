# Анализ фундамента эпика ARS-100

Прочитал три БТ детей. Вот что вижу по фундаменту.

## Найденный общий источник

Все три слайса опираются на **один и тот же источник данных об активности пользователей**. Это явно сказано в разделе 3.3 каждого БТ одинаково:

"Все три элемента опираются на одни и те же данные об активности пользователей (текущее число активных и агрегированная активность за период)."

**Кто что запрашивает:**
- **ARS-101** (Счётчик): текущее число активных пользователей
- **ARS-102** (Модалка с графиком): агрегированная активность за выбранные периоды (час/день/неделя)
- **ARS-103** (Выгрузка сводки): агрегированная активность за выбранные периоды для экспорта

Все три потребляют один сервис активности.

## Рекомендация: фундамент #0 есть

Нужно спроектировать **сервис/источник данных активности как узел-фундамент #0** — один раз, дети наследуют его контракт без изменений.

Что попадёт в контракт #0:
- Метод получения текущего числа активных пользователей
- Метод получения агрегированной активности за период
- Общие типы данных и структуры ответа
- Семантика ошибок и пустых значений

**Важно:** у фундамента #0 не будет своего БТ — это слой реализации, не бизнес-фича.

## Следующий шаг

Нужно подтверждение: оформить источник данных активности как фундамент #0?

Если да — спека #0 пойдёт первой, в неё попадёт контракт (форму соберу из того, что просят дети). Потом спеки детей наследуют этот контракт и добавляют свою логику сверху (UI счётчика, график, выгрузка).

Если нет — каждый ребёнок проектирует доступ к данным сам, есть риск разъехавшихся контрактов и дублирования логики.

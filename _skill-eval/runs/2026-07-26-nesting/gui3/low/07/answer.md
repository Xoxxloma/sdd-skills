**Эпик ARS-100** разбит на трёх детей:
- **A (ARS-101):** счётчик активных пользователей — FR-1, FR-2
- **B (ARS-102):** модалка с графиком активности — FR-3, FR-4  
- **C (ARS-103):** выгрузка сводки активности — FR-5

**Ключевое наблюдение:** в разделе 3.3 каждого дочернего БТ сказано: **«Все три элемента опираются на одни и те же данные об активности пользователей» — текущее число активных и агрегированная активность за период.**

Это классический случай для **фундамента #0**. Общий источник данных (сервис/API для получения активности пользователей) нужно спроектировать один раз — дети наследуют его контракт и не начинают писать свой доступ к этим данным врозь.

**Мой вопрос:**

Оформляем общий источник активности как узел #0 — спека фундамента идёт первой, потом дети на неё ориентируются? 

Варианты:
1. **Спроектировать User Activity Service один раз (узел #0)** — спека #0 фиксирует контракт (поля, типы, семантику), дети наследуют его без изменений
2. **Общего фундамента нет** — каждый ребёнок проектирует свой доступ к данным, рискуем разъехавшихся контрактов

Уточню сразу: **своего БТ у #0 не будет — это слой реализации.** БТ остаются только у детей.

### Верификация качества

**Отсутствие изобретений:**
- Каждый детский FR и его критерий приёмки скопированы дословно из эпик-БТ
- Новых требований, расщепления смысла, изменения scope не внесено

**Самодостаточность детских БТ:**
- Каждый слайс содержит frontmatter с метаданными (`parent: ARS-70`, `source`, `slice`, `owned_fr`, `shared_fr`)
- Общий бизнес-контекст (§1.0–1.3, §2.1–2.3, §3.3, §5.1–5.3, §6) скопирован из эпика дословно
- Scope (§3.1 In-scope, §3.2 Out-of-scope) механически выведен из владеемых FR
- Каждый детский БТ готов для запуска `technical-spec-doc` без изменений

**Неизменённые оригинальные номера FR:**
- Slice A: сохранены FR-1, FR-2, FR-3 (не перенумерованы)
- Slice B: сохранены FR-4, FR-5 (не перенумерованы)
- Перенумерация запрещена (ломает трассировку)

**Структура папок:**
- Дети находятся ВНУТРИ папки эпика (`docs/ARS-70/<CHILD-KEY>/`), а не рядом
- Это обеспечивает единую память состояния эпика и его слайсов

### Не изменено

- Прочие файлы репозитория не затронуты

## Следующие шаги

По каждой дочерней папке запусти `technical-spec-doc`:

```
technical-spec-doc → docs/ARS-70/ARS-71/
technical-spec-doc → docs/ARS-70/ARS-72/
```

Каждый запуск прочитает детский БТ из соответствующей папки, возьмёт номер задачи из имени папки и создаст `technical_specification.md` рядом с `business_requirements.md`.

- Оба слайса унаследовали статус «Готово к оценке»
- Нет пробелов, требующих уточнения на уровне эпика

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего — в веб-админку «Арсенал» добавляется панель для наблюдения за активностью пользователей.

### 1.1. Описание проблемы
Администраторы системы не видят ни текущую, ни историческую активность пользователей. Это затрудняет оценку нагрузки на систему, анализ динамики активности за период и подготовку отчётов для аудита. Регламентные работы (обслуживание, обновления) планируются вслепую, что приводит к прерыванию сессий пользователей.

### 1.2. Конечные потребители
Администраторы системы «Арсенал» (внутренние сотрудники отдела эксплуатации).

### 1.3. Заказчик и стейкхолдеры
- **Заказчик:** Руководитель отдела эксплуатации.
- **Эксперт для консультации:** Тимлид команды «Арсенал-Core».

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор системы должен иметь возможность видеть активность пользователей — сейчас, в динамике и в виде выгружаемой сводки, — чтобы планировать безопасные окна для регламентных работ и предоставлять отчётность по нагрузке системы.

### 2.2. Ценность для бизнеса
- Меньше прерванных сессий пользователей во время регламентных работ (планы делаются с учётом реальной нагрузки).
- Прозрачная отчётность по нагрузке на систему для аудита, планирования и согласования сроков работ.

### 2.3. Бизнес-риски и меры по снижению

| Риск | Вероятность / влияние | Меры по снижению |
|------|----------------------|------------------|
| Неточные данные активности введут администратора в заблуждение | Среднее / высокое | При недоступности источника активности показываем прочерк («—») или пустой график, а не устаревшие данные |
| Выгрузка доступна не тем ролям — попадание в руки оператора или другого персонала | Среднее / высокое | Панель и выгрузка видны только пользователям с ролью администратора |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик активных пользователей в шапке админки, обновляется автоматически в пределах минуты.
- Модальное окно с графиком активности за выбранный период (час, день, неделя); администратор может переключать период прямо в модалке.
- Кнопка выгрузки сводки активности за выбранный период в файл (находится в модальном окне).

### 3.2. Не входит в проект (Out-of-scope)
- Список конкретных пользователей, находящихся в сети (только агрегированные числа активности).
- Автоматическая рассылка отчётов о нагрузке.
- Прогнозирование будущей активности пользователей.

### 3.3. Архитектурные изменения и интеграции
Все три элемента (счётчик, график, выгрузка) опираются на один и тот же источник данных об активности пользователей — текущее число активных пользователей и агрегированные данные активности за период. Админка «Арсенал» начинает потреблять эти данные. Точные механизмы получения данных, хранения и обновления — на этапе технической спецификации.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса
1. **Счётчик активности в шапке:** Администратор заходит в админку и видит в шапке страницы число активных пользователей. Значение обновляется автоматически, без перезагрузки страницы. Счётчик служит как быстрая индикатор текущей нагрузки.

2. **Модальное окно графика:** По клику на счётчик открывается модальное окно с графиком активности. По умолчанию график показывает активность за день. В модалке есть переключатель периода (час, день, неделя); при выборе другого периода график перестраивается. Модалка позволяет администратору углубиться в анализ динамики активности.

3. **Выгрузка сводки:** В модальном окне есть кнопка «Выгрузить». При нажатии администратор получает файл (формат: TBD) со сводкой активности за выбранный период. Файл позволяет создавать отчёты для аудита и планирования.

### 4.2. Критерии приёмки

- **FR-1 (Счётчик активности в шапке):** Дано, что администратор загружает страницу админки, когда счётчик видится на экране в пределах 5 секунд и обновляется не реже чем раз в минуту при изменении активности.

- **FR-2 (Модальное окно с графиком):** Дано, что администратор видит счётчик в шапке, когда нажимает на счётчик, тогда открывается модалка с графиком активности за последний день. И когда администратор выбирает в модалке другой период (час, неделя), тогда график перестраивается под выбранный период.

- **FR-3 (Выгрузка сводки):** Дано, что администратор находится в модальном окне графика, когда нажимает кнопку выгрузки, тогда браузер скачивает файл со сводкой активности за выбранный период.

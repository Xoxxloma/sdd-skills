**Набор проб определял отдельный субагент**, которому дали два варианта скилла, дифф, реестр

## Что этот замер НЕ измеряет — зафиксировано до чисел

- **Правку `description` во фронтматтере.** Стенд подаёт модели ТЕЛО скилла; `description`
  не участвует ни в одной пробе. Судить о ней по числам этого круга нельзя.
- **Формулировку отказа писать** («в реестре ❓ по гейтам …» против «это первый ход»).
  В `variant-A` такого требования нет вовсе, поэтому pass/fail здесь мерил бы правку, а не
  поведение. Читается как диагностика в хвосте отчёта грейдера, вердикта не несёт.
- **Ход 1 с полным брифом И окружением одновременно.** `br3-prompt` даёт полный бриф без базы
  знаний, `br2-prompt` — базу знаний, но с преамбулой «это ПРОДОЛЖЕНИЕ». Пересечения нет;
  обе правки меряются порознь. Известная дыра, на эту пару не влияет.
- **Две восстановленные потери** (см. ниже) — они внесены ПОСЛЕ снятия плеча.

## Две потери, найденные разбором диффа, а не замером

Субагент-аналитик сверил дифф грепом по `variant-B` и отделил перенос от потери. Перенос —
текст, чьё содержание есть в другом месте файла; потеря — которого больше нигде нет. Нашлось
две настоящие:

1. **«Проверь каждый вариант перед отправкой»** — императив самопроверки вариантов ответа
   исчез при слиянии буллетов, эквивалента в `variant-B` нет.
2. **«Каждый гейт 1–14 предъявляется пользователю — исключений нет»** — само правило в
   `variant-B` стоит (Step 3), но абсолют «no exceptions» пропал вместе с удалённым блоком
   «The contract».

Обе восстановлены в рабочем дереве **после** того, как плечо `variant-B` было снято под
замер: править файл, по которому уже идут прогоны, значит получить часть прогонов по старой
версии и часть по новой. Поэтому этот круг меряет `variant-B` БЕЗ восстановлений, а они
проверяются следующим кругом точечно — по `q1` (императив вариантов) и `br2`/`bs1` (абсолют
по гейтам), а не полным перегоном.

## Дефект стенда: отказ API засчитывался за прогон

**Найден до чисел, и это единственная причина, по которой числа не оказались ложными.**

Круг упёрся в лимит API на десяти одновременных процессах. `claude -p` при отказе печатает
текст ошибки в **stdout** — «API Error: 403 Request not allowed / Please run /login», — а
раннер перенаправлял stdout в `answer.md` и считал прогон состоявшимся по признаку «файл
непустой». В результате **68 прогонов из 180** содержали сообщение об отказе вместо ответа
модели и выглядели для грейдера обычными прогонами.

Проверка «непустой файл» для этого класса бесполезна в принципе: отказ по размеру от ответа
не отличается. Раннер теперь разбирает содержимое (`API Error|Request not allowed|Please run
/login|Credit balance|rate limit`), переименовывает такой файл в `_api-failure.txt` и в счёт
его не берёт. Все 68 уже помечены задним числом.

Класс знакомый — «проверка сверяется с артефактом, которого на месте нет», четвёртое
появление в этой репе. Новое в нём то, что артефакт не отсутствовал и не был вычищен: он
был **подменён правдоподобным мусором**, и именно поэтому счётчик показывал зелёное.

Что уцелело и что перегоняется:

| `br1`, `br2`, `br4`, `bs6` | 10/10 на обоих плечах | годны |
| `br3` | A 10, B 8 | добор двух прогонов |
| `bs1`, `bs9`, `q1` | почти всё отравлено | полный добор |
| `q2` | отравлен целиком | **не добирается** — разбор проб назвал его лишним для этой правки |

Добор идёт при параллельности 3 вместо 10.

# Раунд «маршрут из хендоффа исполнителя» — 2026-08-13, Haiku

**Повод.** Аналитик на живом прогоне: БТ записан → скилл предлагает писать тех-спеку → аналитик
подтверждает → и только теперь оркестратор запускает приёмку записанного БТ. Приёмка стоит после
решения о следующем документе, а не до него.

**Разбор.** Дефект не в приёмке. Хендофф `business-requirements-doc` (Step 6) последним ходом
называл следующий документ (строка «Дальше: `task-decomposition-doc` / тех-спека») и просил
подтверждения. Оркестратор по своему правилу 3 не вмешивается в под-скилл и получает ход обратно
только после ответа аналитика — раньше запустить `spec-review` он физически не может.

**Правка (два файла).**

1. `business-requirements-doc` — строка «Дальше» убрана из скелета хендоффа, счётчик строк
   поправлен, добавлен запрет называть следующий шаг. Имена соседних скиллов из файла убраны
   целиком (было два места) — исполнитель не завязан на состав петли. Про приёмку в тексте
   по-прежнему ни слова: валидация — дело оркестратора.
2. `analyst-workspace` Шаг 2Б — гейт срабатывает при «Требуются уточнения» **ИЛИ** ≥1 находке
   приёмки. Правило 7 в TL;DR получило исключение для точки 1, иначе арбитраж «прав список»
   отменял бы новый гейт.

## Находка, которая важнее правки: база 0/20 не воспроизвелась

`CHANGELOG` раунда «статус БТ считает число» (2026-08-03) фиксирует **0 из 20** прогонов с
дефектом «Готово к оценке при `TBD` в §5.2 и пустом блоке». Сегодня на **нетронутом `HEAD`**, на
той же фикстуре `bs1-prompt` и том же тексте скилла (файл 5.0 побайтно равен 3.2, проверено
`diff`) — **2 из 10**. На плече «после» — 3 из 11, то есть правка тут ни при чём.

Объяснений два, и оба непроверены: съехала модель-прокси (Haiku обновлялась между раундами) либо
то число снято не на том плече. Пока не разобрано, число 0/20 в журнале считать действующим
нельзя.

## Дефект грейдера, найденный по дороге

Первая редакция `grade-handoff.mjs` держала анкер `Открыт\w*\s+(пункт|вопрос)`. В JS без флага `u`
`\w` равен `[A-Za-z0-9_]` и кириллицу не матчит — анкер не срабатывал ни разу и дал ровный ноль на
обоих плечах, что читалось как поведение скилла. Кириллические классы в грейдере теперь выписаны
явно, причина записана комментарием в файле.

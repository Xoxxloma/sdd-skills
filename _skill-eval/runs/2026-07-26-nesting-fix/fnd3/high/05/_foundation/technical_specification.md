## 1. Обзор изменения
### 1.1. Тип и стороны
**BE-only.** Узел-фундамент #0 предоставляет бэк-контракт для получения данных об активности пользователей (текущее число активных + агрегаты за выбранный период). Контракт наследуется всеми детскими фронтами эпика ARS-100 (счётчик в шапке, модальное окно с графиком, выгрузка сводки).

### 1.2. Затронутые сервисы и владельцы
| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| Arsenal (бэк) | Собирает и отдаёт данные активности; реализует контракт INT-0 | Команда Arsenal-Core | 🟡 подтверждено аналитиком |

### 1.3. Связь с бизнес-требованиями
Узел-фундамент #0 обслуживает функциональные требования **FR-1, FR-2, FR-3, FR-4, FR-5** эпика: предоставляет текущее число активных пользователей (для счётчика в шапке, FR-1/FR-2) и агрегированные данные активности за выбранный период (для графика в модали, FR-3/FR-4, и для выгрузки, FR-5). Все детские фронты полагаются на единый контракт этого узла.

## 2. Взаимодействия (ядро)

### INT-0. Получение данных активности пользователей — 🟢 (фундамент, наследуется детьми)
- **Граница/направление:** Arsenal бэк → детские фронты (подстанции для счётчика, графика, выгрузки)
- **Триггер:** 
  - Инициализация фронта / открытие модального окна → запрос текущего числа активных + опционально агрегатов за период.
  - Автоматическое обновление счётчика: фронт периодически (с интервалом ≤ 30 сек) запрашивает текущее число.
  - Переключение периода в модали: фронт запрашивает агрегаты за новый период.
- **Контракт (запрос):**
  - Метод: `GET /arsenal/activity`
  - Параметры запроса:
    - `period` (опционально): `hour` | `day` | `week` — период для агрегации. Если не передан, возвращается только текущее число.
    - `end_time` (опционально): ISO 8601 строка (напр. `2026-07-26T12:00:00Z`). Если не передан, по умолчанию текущее время.
    - Заголовок `Authorization`: Bearer token (роль проверяется на бэке).
- **Контракт (ответ):**
  - `current_active_users` (число | null): число активных пользователей на момент запроса.
    - Если `status` = `ok`: актуальное число ≥ 0.
    - Если `status` = `unavailable`: null (источник недоступен).
    - Если `status` = `no_data_for_period`: число присутствует (текущая активность известна), но агрегаты за период отсутствуют.
  - `aggregates` (массив объектов | пустой массив | null): агрегированная активность за выбранный период.
    - Структура элемента: `{ "timestamp": "2026-07-26T11:00:00Z", "count": 35 }`
    - `timestamp`: начало временного окна (ISO 8601).
    - `count`: число активных пользователей в этом окне.
    - Гранулярность зависит от периода: час → 1 точка в час (24 точки за день); день → 1 точка в день (7 точек за неделю); неделя → 1 точка в неделю.
    - Если `status` = `no_data_for_period`: пустой массив.
    - Если `status` = `unavailable`: null.
    - Если `period` не передан: null.
  - `status` (строка): `ok` | `unavailable` | `no_data_for_period`.
    - `ok`: текущее число и (если запрошены) агрегаты актуальны.
    - `unavailable`: источник данных активности недоступен; текущее число и агрегаты не надёжны — фронт должен показать ошибку.
    - `no_data_for_period`: текущее число актуально, но за запрошенный период данных нет (напр., запросили активность за будущую неделю).
  - `response_time` (ISO 8601 строка): время формирования ответа на бэке (для справки о свежести кэша).
- **Пример запроса (получить текущее число):**
  ```
  GET /arsenal/activity HTTP/1.1
  Authorization: Bearer <token>
  ```
- **Пример ответа (успех, только текущее число):**
  ```json
  {
    "current_active_users": 42,
    "aggregates": null,
    "status": "ok",
    "response_time": "2026-07-26T12:15:30Z"
  }
  ```
- **Пример запроса (получить текущее число + агрегаты за день):**

## 3. Backend — ответственность
### 3.1. По сервисам
**Arsenal бэк:**
- Реализует эндпоинт `GET /arsenal/activity` (INT-0).
- Собирает данные об активности пользователей из собственных источников (логи сессий, события входа/выхода и т.п.).
- 🟡 подтверждено аналитиком (не по коду): Arsenal владеет собственным источником данных активности и не привлекает внешние сервисы.
- Проверяет роль пользователя по заголовку `Authorization`; если роль не «Администратор», возвращает 403.
- Отдаёт актуальное число активных пользователей и (если запрошены) агрегаты за период.
- В случае недоступности источника данных отдаёт `status: unavailable` вместо устаревшего кэшированного значения.

### 3.2. Данные и хранение
**Новых таблиц не создаётся.** 🟡 подтверждено аналитиком: агрегаты активности вычисляются на лету из существующих данных; отдельной таблицы агрегатов не закладываем.

Концептуально Arsenal работает с существующим источником событий активности (сессии, логины, логауты); точный механизм хранения и запроса (существующие таблицы логов, событийная шина и т.п.) — по подтверждению аналитика при интеграции.

### 3.3. Авторизация/доступ на бэке
- Эндпоинт `GET /arsenal/activity` доступен **только роли «Администратор»**.
- Проверка по Bearer token в заголовке `Authorization`; роль определяется на основе токена.
- 🟡 подтверждено аналитиком: проверка роли выполняется на бэке Arsenal (не делегируется отдельному сервису).
- Если токен отсутствует или невалидный → 401.
- Если роль не «Администратор» → 403.

## 4. Frontend — ответственность
> Детские фронты эпика ARS-100 опираются на контракт INT-0 и реализуют свои UI-части (счётчик в шапке, модальное окно с графиком, выгрузка). Каждый фронт несёт ответственность за свои сценарии; здесь описана общая логика, которая везде применяется.

### 4.1. Где и что меняется в UI
- Счётчик в шапке админки: отображает текущее число активных пользователей; периодически обновляется запросом к INT-0 без параметра `period`.
- Модальное окно (открывается по клику на счётчик): график активности за выбранный период (час / день / неделя); переключение периода запрашивает новые данные через INT-0 с параметром `period`.
- Кнопка выгрузки (в модали): по клику выгружает сводку (CSV или PDF); данные берутся из последних агрегатов, полученных через INT-0.

### 4.2. Пользовательские сценарии
1. **Открытие админки** → загрузить число активных пользователей (INT-0 без `period`) → показать в шапке.
2. **Обновление счётчика** → каждые ≤ 30 сек автоматически запрашивать число (INT-0 без `period`) → обновить счётчик.
3. **Клик на счётчик** → открыть модаль → запросить агрегаты за период по умолчанию (INT-0 с `period=day`, например) → построить график.
4. **Переключение периода в модали** → запросить агрегаты за новый период (INT-0 с новым `period`) → перестроить график.
5. **Выгрузка сводки** → отправить агрегаты, полученные в шаге 4, в выгрузчик → пользователь получает файл.

### 4.3. Состояния (именованные)
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `loading` | Первый запрос INT-0 / после инвалидации | спиннер / скелетон (в счётчике: пусто или слабо; в графике: пусто) |
| `value` | 200, `status: ok`, `current_active_users ≠ null` и `≠ 0` | число в счётчике / точки графика |
| `zero` | 200, `status: ok`, `current_active_users = 0` | «0» в счётчике / пусто или нулевая линия графика |
| `empty` | 200, `status: ok`, `current_active_users = null` ИЛИ `status: no_data_for_period` | прочерк «—» в счётчике / пустой график с надписью «нет данных» |
| `error_source` | 5xx, таймаут (504), сеть, `status: unavailable` | сообщение об ошибке: «Данные активности недоступны. <Кнопка retry>» |
| `error_forbidden` | 401, 403 | сообщение об ошибке: «У вас нет доступа к панели активности» |

### 4.3.1. Loading и таймауты
- **Cold-path** (первый запрос, счётчик в шапке): таймаут 5 секунд. Если истёк → `error_source`.
- **Warm-path** (обновление счётчика, переключение периода в модали): таймаут 5 секунд (как и cold). Если истёк → `error_source`.
- **Polling** (автоматическое обновление счётчика): интервал обновления ≤ 30 сек (синхронизируется с кэшем на бэке). Jitter не требуется (нет проблемы громких запросов).

## 5. Нефункциональные требования
### 5.1. Синхронность, кэш, производительность
- **Синхронность:** эндпоинт INT-0 отвечает синхронно, не запускает фоновые задачи.
- **Кэш на Arsenal бэке:** 🟡 подтверждено аналитиком: 30 секунд. Все запросы в окне 30 сек получают одно и то же кэшированное значение (или `status: unavailable`, если источник недоступен — не возвращаем устаревший кэш).
- **Таймаут запроса:** 5 секунд. Если обращение к источнику затягивается дольше, Arsenal возвращает 504 (или отдаёт `status: unavailable` в зависимости от реализации).
- **Частота опроса со стороны фронта:**
  - Счётчик в шапке: обновление каждые ≤ 30 сек (синхронизировано с TTL кэша).
  - Модальное окно: переключение периода запрашивает свежие данные (не ждёт истечения кэша).
- **Ожидаемая нагрузка:** низко-средняя (панель видна только администраторам, обновления периодичны).

### 5.2. Надёжность/деградация
- **При недоступности источника данных:** Arsenal отдаёт `status: unavailable` вместо устаревшего значения. Фронт показывает состояние `error_source` с предложением retry.
- **Различие между недоступностью и пусто:** если источник доступен, но за период нет данных, Arsenal отдаёт `status: no_data_for_period` с пустым массивом `aggregates` (но `current_active_users` может быть не null). Фронт показывает состояние `empty` («нет данных за период»).

### 5.3. Безопасность/доступ (сводно)
| Граница | Кто может | Проверка | Отказ |
|---------|-----------|---------|-------|
| `GET /arsenal/activity` | Администратор | Роль по Bearer token на бэке Arsenal | 403 (не роль) или 401 (нет токена) |

## 6. Релиз и интеграция
### 6.1. Порядок выката
🟡 подтверждено аналитиком: **фундамент (узел #0) выкатывается раньше всех потребителей (детских фронтов).**

Очередность:
1. Arsenal бэк (эндпоинт INT-0, логика вычисления агрегатов, проверка роли).
2. Детские фронты эпика ARS-100 (счётчик, модаль, выгрузка).

Причина: детские фронты опираются на контракт INT-0; без него фронты не смогут получить данные.

### 6.2. Обратная совместимость
Не применимо: фундамент — новый сервис/контракт, нет текущих потребителей, которые ломались бы при выкате.

### 6.3. Фиче-флаги
🟡 подтверждено аналитиком: **фиче-флагов нет.** Фундамент выкатывается атомарно; детские фронты полагаются на наличие контракта INT-0.

### 6.4. План отката
- **Откат только Arsenal бэка:** детские фронты получат 5xx / таймаут → состояние `error_source` → пользователь видит ошибку с кнопкой retry. Это допустимо (регулярные ошибки управления нормальны; панель активности — вспомогательный инструмент, не блокирует основную работу).
- **Откат детского фронта:** Arsenal продолжит работать; переключение фронта на старую версию означает, что панель активности перестанет рендериться / будет скрыта. INT-0 останется доступным (можно использовать в других целях или другими детьми).

### 6.5. Преднастройка до релиза (чек-лист)
- [ ] Роли в security-сервисе: роль «Администратор» должна быть определена и использована в проверке доступа к INT-0.
- [ ] Логирование и алерты на бэке Arsenal: мониторинг состояния `status: unavailable` (источник активности недоступен) и таймаутов (504).
- [ ] Конфиги: TTL кэша (30 сек) и таймаут запроса (5 сек) должны быть параметризованы в конфиге Arsenal.
- [ ] Тестирование: проверить обработку 403 (не администратор), 504 (таймаут), 500 (ошибка).

## 7. Трассировка приёмки
| FR из БТ | Взаимодействие(я) | Тест-кейс (Дано–Когда–Тогда) |
|----------|-------------------|------------------------------|
| FR-1 | INT-0 | Дано открытую админку с ролью Администратор, когда страница загрузилась, тогда в шапке отображается текущее число активных пользователей (результат вызова INT-0 без параметра `period`, статус `ok`, значение ≠ null). |
| FR-2 | INT-0 | Дано открытую админку, когда число активных пользователей изменилось на бэке, тогда счётчик обновляется без перезагрузки (фронт периодически запрашивает INT-0 с интервалом ≤ 30 сек, получает актуальное значение). |

## 8. Допущения и открытые вопросы
**Все технические решения приняты, спецификация готова к разработке.**

> 🟡 **Подтверждено аналитиком (не по коду):**
> - Arsenal владеет собственным источником данных активности (логи сессий, события входа/выхода).
> - Агрегаты активности вычисляются на лету; отдельной таблицы агрегатов не создаётся.

> - Кэш 30 секунд на стороне Arsenal; таймаут запроса 5 секунд.
> - Фундамент выкатывается раньше потребителей (детских фронтов); фиче-флагов нет.

**Унаследовано из БТ (бизнес-пробелы, не блокируют тех-спеку):**
- Точный формат выгрузки сводки (CSV, PDF, Excel) и состав полей определяются в БТ детского фронта, отвечающего за выгрузку (FR-5).

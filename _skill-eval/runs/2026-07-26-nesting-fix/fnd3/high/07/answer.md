## Основное содержание спеки

**Файл сохранён:** `docs/ARS-100/_foundation/technical_specification.md`

Техническая спецификация узла-фундамента #0 определяет единственное взаимодействие (INT-0):

### INT-0. Получение данных активности пользователей

Эндпоинт: `GET /api/v1/activity?period={hour|day|week}`

**Возвращает:**
- `current.activeUsers` — текущее число активных пользователей
- `availability` — статус источника ("available" | "unavailable" | "no_data_for_period")
- `history.dataPoints` — временной ряд активности за запрошенный период (гранулярность: минуты для hour, часы для day, дни для week)

**Ключевые решения (подтверждены аналитиком):**
- BE-only, реализация на бэке Арсенала.
- Синхронный вызов, кэш 30 секунд, таймаут 5 секунд.
- Авторизация по роли «Администратор» на бэке.
- При недоступности источника отдаём признак `availability: "unavailable"`, не устаревшее значение.
- Отдельно различаем состояние "no_data_for_period" (период валиден, но данных нет).
- Агрегаты считаются на лету, новых таблиц нет.
- Фундамент выкатывается раньше потребителей (дочерних фронтов ARS-101, ARS-102, ARS-103).
- Фиче-флагов нет, релизим атомарно.

**Состояния UI:**
- `value` — число активных (availability = "available", activeUsers ≠ null)
- `zero` — валидный ноль (activeUsers = 0)
- `empty` — прочерк «—» (activeUsers = null)
- `no_data_for_period` — сообщение об отсутствии данных за период
- `error_source` — ошибка источника (unavailable) или таймаут
- `error_forbidden` — 403 (недостаточно прав)

**Открытые вопросы для валидации при интеграции:**
- Точный интервал опроса фронтом за минуту (20s, 30s, 60s?).
- Ожидаемая нагрузка (число администраторов, RPS).
- Какие индексы нужны для агрегации по периодам.
- Включать ли `cacheAge` в мета-поле ответа.

## Трассировка к БТ

Все пять функциональных требований эпика ARS-100 трассируются в INT-0:
- FR-1 (счётчик активных в шапке)
- FR-2 (автоматическое обновление)
- FR-3 (модалка с графиком за период)
- FR-4 (переключение периодов в модалке)
- FR-5 (выгрузка сводки в файл)

Каждый фронт-потребитель (ARS-101, ARS-102, ARS-103) наследует этот контракт без изменений.

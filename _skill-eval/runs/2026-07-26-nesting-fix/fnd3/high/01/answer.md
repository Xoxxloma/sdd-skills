### Содержание спецификации

#### INT-0: Получение данных об активности пользователей (🟢 новое)

**Контракт** — единственное новое взаимодействие:
- **Метод/путь:** `GET /api/activity/data`
- **Параметры:** `period_type` (current/hourly/daily/weekly), `period_start`, `period_end`
- **Ответ:** JSON-объект с полями:
  - `status` ("available" | "unavailable") — доступность источника
  - `unavailable_reason` (null | "source_timeout" | "source_error") — причина недоступности
  - `no_data_for_period` (boolean) — нет ли данных за запрошенный период
  - Для "current": `current.active_count`, `current.timestamp`
  - Для периодов: `historical[]` с агрегатами (average_active, peak_active, data_points)

**JSON-примеры:** спецификация содержит 4 реальных примера ответов (успех с текущим числом, успех с историей, таймаут, нет данных).

#### Ключевые решения (подтверждены аналитиком)

| Гейт | Решение |
|------|---------|
| **Тип и стороны** | BE-only, Arsenal Backend собирает данные и выполняет INT-0 |
| **Владение** | Данные активности собирает сам Arsenal, чужих сервисов не привлекаем |
| **Ошибки и недоступность** | Различаем «источник недоступен» (status=unavailable) от «данных за период нет» (no_data_for_period=true); не отдаём устаревшие данные |
| **Авторизация** | Только роль Администратор, проверка на бэке Arsenal |
| **Данные и хранение** | Агрегаты вычисляются на лету, нет новых таблиц |
| **Sync/производительность** | Синхронный запрос, кэш 30 сек на стороне Arsenal, таймаут 5 сек |
| **Порядок выката** | Фундамент деплоится ПЕРВЫМ, до дочерних узлов; фиче-флагов нет |
| **Трассировка** | FR-1..FR-5 эпика полностью обслуживаются контрактом INT-0 |

#### Структура спецификации

1. **Обзор изменения** — тип, затронутые сервисы, связь с БТ
2. **Взаимодействия (ядро)** — INT-0 с полным контрактом, параметрами, примерами, ошибками, состояниями UI, авторизацией + каталог ошибок
3. **Backend — ответственность** — что реализует Arsenal (эндпоинт, вычисление, кэширование, таймауты)
4. **Frontend — ответственность** — не применимо (узел #0 — BE-only)
5. **Нефункциональные требования** — кэш, таймауты, таймауты, надёжность, безопасность
6. **Релиз и интеграция** — порядок выката (фундамент первым), совместимость, откат, преднастройка
7. **Трассировка приёмки** — таблица FR → INT-0 → тест-кейс для всех 5 требований эпика
8. **Допущения и открытые вопросы** — все подтверждены аналитиком, открытых нет

## Краткое описание
Написана техническая спецификация для узла-фундамента #0 эпика ARS-100 «Панель активности пользователей в админке Arsenal». 

Фундамент обеспечивает единый контракт данных активности пользователей (INT-0), который потребляют все дети для реализации FR-1..FR-5:
- **FR-1:** Счётчик активных пользователей в шапке
- **FR-2:** Автоматическое обновление счётчика
- **FR-3:** Модальное окно с графиком активности за период
- **FR-4:** Переключение периодов в модалке
- **FR-5:** Выгрузка сводки в файл

## Основные характеристики контракта INT-0

**Тип:** BE-only (фундамент отдаёт данные)

**Контракт:**
- Синхронный GET-запрос с параметром period (current | hour | day | week)
- Ответ содержит:
  - `status`: available | unavailable | no_data (различает недоступность источника от отсутствия данных)
  - `currentActive`: число активных пользователей (или null при недоступности)
  - `aggregates`: массив чисел за период (или отсутствует при no_data/unavailable)
  - `timestamp`: время формирования ответа

**Производительность:**
- Синхронный вызов (не событие)
- Таймаут 5 секунд
- Кэш 30 секунд на стороне Arsenal BE

**Безопасность:**
- Доступ ТОЛЬКО для роли Administrator
- Проверка на стороне Arsenal BE (403 Forbidden для остальных)

**Надёжность:**
- При недоступности источника: status = unavailable (не кэшировать устаревшее)
- При отсутствии данных за период: status = no_data (валидный случай)
- Фронты-дети различают эти состояния и показывают разные сообщения

**Данные:**
- Новых таблиц не заводится
- Агрегаты вычисляются на лету из существующих данных
- Arsenal Backend собирает активность сам, внешних сервисов не привлекает

**Релиз:**
- Фундамент выкатывается ПЕРВЫМ, до детей
- Фиче-флагов нет (релизим атомарно)

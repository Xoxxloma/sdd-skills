## Что спроектировано

### Два взаимодействия (контракты)

1. **INT-0 — Получить текущий снимок активности** (🟢 новое)
   - `GET /api/activity/current`
   - Возвращает число активных пользователей, флаг недоступности источника, timestamp
   - Используется для счётчика в шапке админки (FR-1, FR-2)
   - С JSON-примерами для обоих случаев: успех и недоступность источника

2. **INT-1 — Получить агрегированную активность за период** (🟢 новое)
   - `GET /api/activity/aggregate?period=hour|day|week&start_time=...&end_time=...`
   - Возвращает массив срезов с временными метками и числами, флаги недоступности и отсутствия данных
   - Используется для графика, переключения периода, выгрузки сводки (FR-3, FR-4, FR-5)
   - С JSON-примерами для трёх случаев: успех, недоступность, отсутствие данных

### Ключевые решения (все подтверждены аналитиком)

- **Источник данных:** BE Arsenal собирает данные сам, чужих сервисов не привлекаем.
- **Новые таблицы:** Не заводим; агрегаты считаем на лету.
- **Недоступность:** При проблеме источника возвращаем флаг `is_unavailable=true`, не старое значение.
- **Авторизация:** Роль Администратор, проверка на бэке.
- **Производительность:** Sync, cache 30s, timeout 5s.
- **Порядок выката:** Фундамент первым, затем дочерние компоненты.
- **Флаги:** Не используются, релизим атомарно.

### Маппинги состояний для фронта

Для каждого взаимодействия определены UI-состояния (loading, value, zero, empty, error_source, error_forbidden) и условия их активации.

### Каталог ошибок

Описаны HTTP-коды (400, 403, 5xx), таймауты и способы их обработки фронтом.

### Трассировка

Все FR-1..FR-5 из эпика ARS-100 связаны с INT-0 и INT-1, указаны высокоуровневые тест-кейсы.

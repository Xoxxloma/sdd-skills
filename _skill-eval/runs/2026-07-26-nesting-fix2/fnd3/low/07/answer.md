# Узел-фундамент #0: Контракт данных активности

**Статус:** Готово к разработке

**Спека создана:** docs/ARS-100/_foundation/technical_specification.md

## Резюме

Спроектирован единый контракт данных активности пользователей (INT-0) для фундамента эпика ARS-100. Контракт используется всеми тремя дочерними узлами (счётчик в шапке, модалка с графиком, выгрузка сводки) и обслуживает FR-1..FR-5 эпика.

## Что спроектировано

### INT-0: Получение данных активности пользователей (🟢 новое)

**Эндпоинт:** `POST /api/v1/admin/activity`

**Входные параметры:**
- `period_type` (обязательно): `current` | `hour` | `day` | `week`
- `reference_date` (опционально): дата/время для расчёта периода

**Выход (JSON):**
- `status`: `available` | `unavailable` | `no_data`
- `current_active_users`: число активных пользователей (null если данных нет)
- `data_points`: массив с временными точками для графика (часы/дни)
- Поля каждой точки: `timestamp` (ISO 8601), `active_count` (число)
- `period_type`: какой период отдан
- `reference_date`: на какую дату рассчитано
- `cache_ttl_seconds`: 30 (рекомендуемый кэш на фронте)

**Семантика состояний:**
- `status: "available"` + данные → показать значение / график (состояние `value`)
- `status: "no_data"` → показать прочерк "—" (состояние `empty`)
- `status: "unavailable"` → ошибка источника, показать сообщение об ошибке (состояние `error_source`)

**Авторизация:**
- Только роль Администратор
- Проверка на бэке Арсенала
- 403 Forbidden при отказе

**Нефункциональные требования:**
- Синхронно (не async)
- Кэш 30 сек на стороне BE
- Таймаут 5 сек (при недоступности источника BE возвращает `unavailable`, не выдаёт устаревшее)
- Агрегаты вычисляются на лету (новых таблиц не создаём)

## Рекомендация по дальнейшему

Спека фундамента зафиксирована. Дочерние узлы (ARS-101, ARS-102, ARS-103) должны наследовать контракт INT-0 без изменения состава полей и enum'ов и реализовать собственный UI (счётчик, график, выгрузка) вокруг этого единого контракта.

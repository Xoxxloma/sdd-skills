## Что спроектировано

### Фундамент #0 — одна новая граница

**INT-0: Получить данные активности пользователей** (🟢 новое)
- **Эндпоинт:** GET /arsenal/api/v1/activity/aggregated
- **Параметры запроса:** `period_hours` (1 | 24 | 168), `include_current` (опция на true)
- **Ответ:** структура с двумя блоками:
  1. **`current`** — текущее число активных пользователей, метка времени, флаг доступности источника
  2. **`period`** — временной ряд активности за выбранный период, отличие «нет данных» от «недоступность источника»

### Ключевые решения (по гейтам)

| Гейт | Решение |
|------|---------|
| **Тип и стороны** | BE-only (Arsenal backend выдаёт контракт для потребления детьми) |
| **Инвентарь взаимодействий** | INT-0 — один эндпоинт для текущего счёта и агрегатов периода |
| **Владение** | Arsenal collects data itself, no external service calls |
| **Контракт** | JSON с реальными примерами (успех, недоступность, нет данных) |
| **Ошибки и состояния** | Каталог ошибок (400/401/403/500); маппинг на UI-состояния (value/zero/empty/error_source/error_forbidden) |
| **Авторизация** | Только роль Администратор; проверка на бэке Arsenal; 403 для остальных |
| **Данные и хранение** | Агрегаты считаются на лету, новых таблиц не заводим |
| **Синхронность/производительность** | Синхронный запрос, кэш 30s на Arsenal BE, таймаут 5s |
| **Порядок выката** | Фундамент раньше потребителей (детей) |
| **Фиче-флаги** | Нет (атомарный откат) |
| **Трассировка** | FR-1…FR-5 эпика обслуживаются через INT-0 |

### Примеры ответа в спеке

Спецификация содержит три примера JSON-ответа:
1. **Успех** — оба блока с данными (текущий счёт + график периода)
2. **Недоступность источника** — все значения null, флаги unavailable_source = true
3. **Нет данных за период** — текущий счёт есть, но для периода no_data_for_period = true

Потребители (дети) используют эти примеры как контракт для кодирования.

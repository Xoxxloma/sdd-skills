## Содержание

Техническая спецификация фундамента #0 определяет два новых взаимодействия (контракта), которые потребляют дочерние узлы:

### INT-1: Текущее число активных пользователей
- **GET `/api/arsenal/activity/current`** (без параметров)
- Возвращает: `{ count, timestamp, available, lastUpdated }`
- Семантика:
  - `count: null` = источник недоступен (не устаревшее значение)
  - `count: 0` = валидный ноль (активных нет)
  - `available: true/false` = признак доступности данных
- Кэш 30 секунд на бэке, таймаут 5 секунд
- Авторизация: только роль Администратор (403 Forbidden иначе)
- Служит источником для FR-1, FR-2 (счётчик в шапке)

### INT-2: Агрегаты активности за период
- **GET `/api/arsenal/activity/aggregates?period={hour|day|week}&start=…&end=…`**
- Возвращает: `{ period, start, end, available, dataPoints[], metadata }`
- Семантика:
  - `available=true, dataPoints=[]` = за период данных нет (валидный 0)
  - `available=false` = источник недоступен
  - `dataPoints[].{ timestamp, activeUsers }` = временные срезы
- Аналогичный кэш (30с) и таймаут (5с), авторизация (Администратор)
- Служит источником для FR-3, FR-4, FR-5 (график, выгрузка сводки)

## Провенанс

Спецификация полностью основана на подтвержденных ответах аналитика на tech-gates:

1. ✅ **Type and sides:** BE-only, Arsenal backend — контракты данных активности
2. ✅ **Ownership:** Arsenal собирает данные сам, чужих сервисов нет
3. ✅ **Error handling:** недоступность → признак, не устаревшее значение; различаем «нет данных» от «недоступно»
4. ✅ **Authorization:** только Admin, проверка на бэке Arsenal
5. ✅ **Data storage:** агрегаты на лету, новых таблиц нет
6. ✅ **Sync/performance:** синхронно, кэш 30с на бэке, таймаут 5с
7. ✅ **Rollout:** фундамент раньше потребителей, нет фиче-флагов
8. ✅ **Tracing:** FR-1…FR-5 в части данных активности

## Статус готовности

**Готово к разработке** — все технические решения приняты, открытых вопросов нет.

Фундамент #0 определяет чистые контракты на границе (INT-1, INT-2) с полными JSON-примерами, семантикой null, маппингом ошибок и UI-состояниями. Дочерние узлы (счётчик, график, выгрузка) будут потреблять эти контракты без изменений.

Релиз: фундамент выкатывается первым, дочерние узлы — вторыми.

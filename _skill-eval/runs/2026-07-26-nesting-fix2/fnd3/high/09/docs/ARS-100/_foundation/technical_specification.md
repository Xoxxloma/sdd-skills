## 1. Обзор изменения

### 1.1. Тип и стороны
BE-only. Узел-фундамент #0 проектирует и реализует общий контракт данных активности пользователей, который потребляют дочерние фронты (счётчик в шапке, модальное окно с графиком, выгрузка). Фундамент не принадлежит ни одному дочернему узлу; спроектирован один раз, первым, и отдаётся детям неизменным.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| Backend «Арсенала» | Собирает и отдаёт данные активности | Тим Arsenal-Core | 🟡 подтверждено аналитиком |

### 1.3. Связь с бизнес-требованиями
Узел-фундамент #0 реализует единственный источник данных для FR-1..FR-5 эпика ARS-100 (счётчик активных пользователей, график активности, выгрузка сводки). Все три дочерних фронта (FR-1 шапка, FR-3..FR-5 модалка) опираются на одинаковый контракт активности.

## 2. Взаимодействия (ядро)

### INT-0. Получить данные активности пользователей — 🟢 (фундамент, наследуется детьми)

- **Граница/направление:** Backend Arsenal → Frontend потребители (дочерние узлы)
- **Триггер:** Фронт запрашивает текущую активность при загрузке страницы или автообновлении; запрашивает исторические агрегаты при открытии графика/смене периода.
- **Контракт (запрос):** 
  ```
  GET /api/v1/admin/activity
  Query params:
  - period: string (опционально, значения: "current" | "hour" | "day" | "week"; по умолчанию "current")
  - start_date: ISO 8601 datetime (опционально, если период задан явно)
  - end_date: ISO 8601 datetime (опционально, если период задан явно)
  ```
  Заголовки: Authorization (JWT с ролью Admin)

- **Контракт (ответ):**
  - `current_active_count`: int | null — число активных пользователей в текущий момент; `null` если источник недоступен
  - `period`: string — код запрошенного периода ("current" | "hour" | "day" | "week" | "custom")
  - `period_start`: string (ISO 8601) — начало периода в UTC
  - `period_end`: string (ISO 8601) — конец периода в UTC
  - `period_active_count`: int | null — максимальное число одновременно активных пользователей за период; `null` если нет данных за период
  - `period_total_users`: int — уникальных пользователей, активных хотя бы раз за период
  - `period_session_count`: int — общее число сессий, открытых за период
  - `data_availability`: string — enum: "available" (данные актуальны) | "unavailable" (источник недоступен) | "no_data" (данные за период отсутствуют — валидный 0)
  - `cached`: boolean — признак кэширования (true = ответ из кэша, может отставать на до 30с)

- **Пример запроса:**
  ```http
  GET /api/v1/admin/activity?period=day
  Authorization: Bearer <JWT>
  ```

- **Пример ответа (успех, текущий момент):**
  ```json
  {
    "current_active_count": 47,
    "period": "current",
    "period_start": "2026-07-26T18:00:00Z",
    "period_end": "2026-07-26T18:00:00Z",
    "period_active_count": null,
    "period_total_users": null,
    "period_session_count": null,
    "data_availability": "available",
    "cached": true
  }
  ```

- **Пример ответа (успех, за день):**
  ```json
  {
    "current_active_count": 47,
    "period": "day",
    "period_start": "2026-07-26T00:00:00Z",
    "period_end": "2026-07-26T23:59:59Z",
    "period_active_count": 156,
    "period_total_users": 412,
    "period_session_count": 1203,
    "data_availability": "available",
    "cached": true
  }
  ```

- **Пример ответа (источник недоступен):**
  ```json
  {
    "current_active_count": null,
    "period": "day",
    "period_start": "2026-07-26T00:00:00Z",
    "period_end": "2026-07-26T23:59:59Z",
    "period_active_count": null,
    "period_total_users": null,
    "period_session_count": null,
    "data_availability": "unavailable",
    "cached": false
  }
  ```

- **Пример ответа (нет данных за период):**
  ```json
  {
    "current_active_count": 0,
    "period": "week",
    "period_start": "2026-07-19T00:00:00Z",
    "period_end": "2026-07-25T23:59:59Z",
    "period_active_count": 0,
    "period_total_users": 0,
    "period_session_count": 0,
    "data_availability": "no_data",
    "cached": false
  }
  ```

- **Ошибки:**
  - **403 Forbidden** — запрос пришёл не от роли Admin. Тело: `{ "error": "forbidden", "message": "Admin role required" }`
  - **400 Bad Request** — некорректный период или диапазон дат. Тело: `{ "error": "invalid_period", "message": "Period must be one of: current, hour, day, week" }`
  - **500 Internal Server Error** — непредвиденная ошибка бэка. Тело: `{ "error": "internal_error", "message": "Failed to fetch activity data" }`
  - **504 Gateway Timeout** — в течение 5 секунд данные не получены. Клиент должен обработать как `data_availability: "unavailable"`.

- **Состояния UI по ответу (если есть фронт):**
  - `data_availability: "available"` && `current_active_count != null` → состояние `value` (показать число)
  - `data_availability: "available"` && `current_active_count == 0` → состояние `zero` (показать "0")
  - `data_availability: "no_data"` → состояние `empty` (показать "—", нет данных за период)
  - `data_availability: "unavailable"` → состояние `error_source` (показать сообщение об ошибке, retry)
  - **Статус 403** → состояние `error_forbidden` (скрыть компонент или показать «нет доступа»)

- **Авторизация:**
  - Контракт доступен только ролям: `Admin` (признак в JWT)
  - Проверка: на бэке Arsenal при получении запроса, до обращения к источнику активности
  - Негативный случай: non-admin запрос → **403 Forbidden**

- **Происхождение:** 🟢 новое (узел-фундамент #0)

- **Трассировка:** FR-1, FR-2, FR-3, FR-4, FR-5 (все требования эпика зависят от INT-0)

## 3. Backend — ответственность

### 3.1. По сервисам
**Backend Arsenal:**
- Реализует эндпоинт `GET /api/v1/admin/activity` (INT-0)
- Проверяет авторизацию (Admin-роль) из JWT перед обработкой
- Собирает данные активности из собственного источника (не привлекая внешние сервисы)
- Кэширует результат на 30 секунд (на стороне бэка Arsenal)
- Отличает три состояния: актуальные данные (`available`), недоступность источника (`unavailable`), отсутствие данных за период (`no_data`)
- При недоступности источника НЕ отдаёт устаревшее значение
- Возвращает 5xx-ошибку в случае непредвиденной проблемы

### 3.2. Данные и хранение
🟡 подтверждено аналитиком: Новых таблиц не заводим. Агрегаты активности (текущее число, максимум за период, общее число уникальных пользователей, счёт сессий) считаются на лету из существующих источников данных сессий/активности Backend Arsenal. Точная схема данных и механизм расчёта — внутреннее дело бэка Arsenal, спецификация контракта не зависит от этого.

### 3.3. Авторизация/доступ на бэке
- Эндпоинт `/api/v1/admin/activity` проверяет JWT-токен при каждом запросе
- Извлекает роль из claims токена
- Отказывает (403) если роль != Admin
- Логирует запросы без Admin-роли для аудита

## 5. Нефункциональные требования

### 5.1. Синхронность, кэш, производительность
- **Синхронность:** GET запрос, синхронный ответ
- **Кэш:** На стороне бэка Arsenal, TTL = 30 секунд. Флаг `cached: true` в ответе указывает, что значение может отставать не более чем на 30 секунд от актуального.
- **Таймаут:** 5 секунд на получение данных; если превышен → возврат 504 Gateway Timeout или эквивалентная ошибка
- **Частота обновления:** Фронт может опрашивать эндпоинт чаще (напр. раз в 5 секунд для счётчика), кэш на бэке гарантирует, что часть запросов вернётся быстро за счёт кэша

### 5.2. Надёжность/деградация
- При недоступности источника активности (сеть, timeout, сервис down): эндпоинт немедленно возвращает 2xx со статусом `data_availability: "unavailable"`, а не ждёт пока таймаут истечёт
- Фронт **не должен** показывать устаревшие значения вместо ошибки; `data_availability` явно указывает причину
- При 403 (не Admin) — фронт скрывает компонент или показывает «доступно только администраторам»

### 5.3. Безопасность/доступ (сводно)

| Граница | Кто может | Кто не может | Как enforced |
|---------|-----------|--------------|-------------|
| GET /api/v1/admin/activity | Admin | Operator, Guest | JWT + роль Admin; 403 если нет |

## 6. Релиз и интеграция

### 6.1. Порядок выката
🟡 подтверждено аналитиком: **Фундамент #0 выкатывается раньше дочерних узлов.** Это гарантирует, что к моменту, когда дочерние фронты (FR-1, FR-3, FR-4, FR-5) начнут потреблять INT-0, эндпоинт уже работает.

### 6.2. Обратная совместимость
Новый контракт, обратной совместимости с предыдущими версиями нет (так как функция в Arsenale до этого не была).

### 6.3. Фиче-флаги
🟡 подтверждено аналитиком: Фиче-флагов нет. Эндпоинт выкатывается атомарно.

### 6.4. План отката
Откат BE: эндпоинт перестаёт работать → фронты получают 404 или 503. Фронты должны благодатно обработать это (перейти в состояние `error_source`). Откат должен быть синхронным (откатываются все слои одновременно) или BE откатывается, FE кэширует ошибку на некоторое время.

### 6.5. Преднастройка до релиза

- [ ] Роли в security-сервисе: убедиться, что роль `Admin` существует в системе авторизации
- [ ] DDL-миграция: не требуется (новых таблиц нет, используются существующие источники)
- [ ] Конфиги: кэш-TTL = 30с, таймаут = 5с вынести в конфиги (dev/staging/prod)
- [ ] Сервисные аккаунты: не требуются (эндпоинт на этом же бэке, нет межсервисных вызовов)
- [ ] Фиче-флаги: не требуются
- [ ] Алерты: настроить на 5xx-ошибки и таймауты эндпоинта `/api/v1/admin/activity`

## 7. Трассировка приёмки

| FR из БТ | Взаимодействие(я) | Тест-кейс (Дано–Когда–Тогда) |
|----------|-------------------|------------------------------|
| FR-1: В шапке видно число активных пользователей | INT-0 (period=current) | Дано админ залогинен как Admin, когда страница загрузилась, тогда GET /api/v1/admin/activity?period=current возвращает current_active_count и data_availability="available" |
| FR-2: Счётчик обновляется без перезагрузки в пределах минуты | INT-0 (period=current, polling) | Дано счётчик отображает число N, когда активность изменилась на другое число M и пройдено ≤60 сек, тогда повторный GET /api/v1/admin/activity?period=current возвращает обновлённый current_active_count ≠ N (актуальность за счёт кэша на 30с + поллинг на фронте) |
| FR-3: По клику на счётчик открывается модалка с графиком | INT-0 (period=day/week/hour) | Дано модалка открыта, когда админ выбирает период "day", тогда GET /api/v1/admin/activity?period=day возвращает period_active_count, period_total_users, period_session_count для этого периода |
| FR-4: При смене периода график перестраивается | INT-0 (период переключается) | Дано модалка показывает период "day", когда админ нажимает "неделя", тогда новый GET /api/v1/admin/activity?period=week возвращает данные за неделю, график пересчитывается |
| FR-5: Кнопка выгрузки отдаёт файл со сводкой | INT-0 (данные для выгрузки) | Дано модалка открыта с периодом "week", когда админ нажимает Download, тогда фронт вызывает GET /api/v1/admin/activity?period=week, получает period_total_users, period_session_count и т.д., формирует файл с этими данными (формат CSV/JSON — выбор фронта), скачивание инициируется |

# Техническая спецификация узла-фундамента #0: Готова к разработке

## Выполнено

Спроектирована техническая спецификация узла-фундамента #0 для эпика ARS-100 (панель активности в админке «Арсенал»). Спека задаёт единственное новое взаимодействие **INT-0** — контракт получения данных активности, который будут наследовать детские узлы (фронты).

## Контракт INT-0: GET /api/v1/activity/stats

**Одно обязательное взаимодействие** (🟢 новое):
- **Параметр запроса:** `period` ∈ {`current`, `hour`, `day`, `week`} — требуемый период агрегации
- **Ответ:** объект с полями:
  - `current_active_users` (число или null) — текущее число активных пользователей
  - `period_stats` (объект или null) — агрегаты за период: `total_sessions`, `peak_concurrent`, `avg_concurrent`
  - `source_status` ("available" | "temporarily_unavailable") — статус источника данных
  - `is_stale` (булево) — флаг свежести данных (кэш 30с)
  - `cached_at` (ISO 8601) — время последнего обновления (для отладки)

**Различия состояний:**
- **Данные доступны:** `source_status: "available"`, значения заполнены (или 0 за пустой период)
- **Источник недоступен:** `source_status: "temporarily_unavailable"`, null вместо значений (не стейл-кэш, как требует БТ)
- **Период без данных:** `source_status: "available"`, `period_stats.total_sessions: 0` (валидный ноль, не ошибка)

**Ошибки:**
- 400 (invalid_period), 401 (unauthorized), 403 (forbidden — только для Administrator), 500 (internal error, не кэш), 504 (timeout 5с, не кэш)

**Авторизация:** Роль Administrator только; проверка на бэке Arsenal. Прочие роли → 403.

**Производительность:**
- Синхронный вызов
- Кэш 30 секунд на Arsenal BE
- Таймаут 5 секунд при получении данных
- При таймауте или ошибке источника: возвращать unavailable, не кэш

**Трассировка:** INT-0 обслуживает все FR-1..FR-5 эпика в части данных активности.

## Релиз и интеграция

- **Фундамент выкатывается первым** (с INT-0)
- **Детские узлы вторыми** (наследуют контракт INT-0, без изменений)
- Фиче-флагов нет (атомарный релиз)
- Откат: при откате BE детские фронты получают ошибку и повторяют (как прописано в обработке error_source в §5.2)

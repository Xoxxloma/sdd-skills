## 1. Обзор изменения
### 1.1. Тип и стороны
FE-only. Меняется веб-клиент «Арсенала»; серверная часть не трогается.
### 1.2. Затронутые сервисы и владельцы
| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| incident-web | сортирует уже полученный список | команда «Арсенал» | 🟢 |
| incident-api | отдаёт список заявок как раньше, изменений нет | команда «Арсенал» | 🟡 подтверждено аналитиком |
### 1.3. Связь с бизнес-требованиями
Оператор находит свежую заявку сразу, не пролистывая список.

## 2. Взаимодействия (ядро)

Новых и изменённых взаимодействий нет. Список заявок уже приходит существующим запросом целиком
и содержит дату — 🟡 подтверждено аналитиком. Центр тяжести спеки в §4.

### Каталог ошибок (сводно)
Не применимо: новых кодов ошибок не появляется, существующие обрабатываются как раньше.

## 3. Backend — ответственность
### 3.1. По сервисам
Не применимо: серверная часть не меняется.
### 3.2. Данные и хранение
Новых сущностей нет, изменённых нет, миграций нет.
### 3.3. Авторизация/доступ на бэке
Не применимо: доступ к списку не меняется.

## 4. Frontend — ответственность
### 4.1. Где и что меняется в UI
Экран списка заявок: заголовок колонки «Дата» становится переключателем сортировки. Новых роутов
нет, новых экранов нет.
### 4.2. Пользовательские сценарии
Оператор нажимает на заголовок «Дата» — список перестраивается по убыванию, повторное нажатие
переставляет по возрастанию (FR-1).
### 4.3. Состояния (именованные)
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `loading` | список ещё грузится | существующий скелетон, не меняется |
| `value` | список получен | строки в выбранном порядке |
| `empty` | список пуст | существующее «нет заявок», не меняется |
### 4.3.1. Loading и таймауты
Не применимо: сетевых вызовов не добавляется, сортировка выполняется над уже полученным списком.
### 4.4. Доступ по ролям в UI
Не меняется: роль «Оператор» как была.

## 5. Нефункциональные требования

отсортированными данными не ходим.
### 5.2. Надёжность/деградация

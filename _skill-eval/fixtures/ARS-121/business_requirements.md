# Бизнес-требования: Сортировка списка заявок по дате

> **Задача Jira/SberTrack:** ARS-121
>
> **Статус готовности:** Готово к оценке
>
> **Открытые вопросы (требуют уточнения перед оценкой):**
> *(Все ключевые данные подтверждены, спецификация готова к оценке.)*

## 1. Введение и контекст
### 1.0. Тип изменения
Доработка существующего — в уже работающем списке заявок появляется сортировка.
### 1.1. Описание проблемы (Problem Statement)
Список заявок выводится в порядке, заданном сервером, и оператор не может быстро найти
самые свежие. Приходится пролистывать весь список глазами.
### 1.2. Конечные потребители (End Users)
Операторы, работающие со списком заявок.
### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
Заказчик — руководитель группы операторов.

## 2. Бизнес-требования (цели и ценность)
### 2.1. Бизнес-цель
Я как оператор должен иметь возможность отсортировать список заявок по дате, чтобы сразу
видеть свежие.
### 2.2. Ценность для бизнеса
Сокращение времени на поиск актуальной заявки в списке.
### 2.3. Бизнес-риски и меры по снижению (Mitigation)
| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Оператор не заметит, что сортировка изменилась | Низкая / низкое | Выбранный порядок обозначен в заголовке колонки |

## 3. Объём проекта (Scope)
### 3.1. Входит в проект (In-scope)
- Сортировка уже загруженного списка заявок по дате, по возрастанию и убыванию.
### 3.2. Не входит в проект (Out-of-scope)
- Сортировка по другим полям.
- Сохранение выбранного порядка между сессиями.
- Изменение состава списка и способа его загрузки.
### 3.3. Архитектурные изменения и интеграции
Список заявок уже приходит с сервера целиком и содержит дату (подтверждено аналитиком).
Новых данных с сервера не требуется, серверная часть не меняется.

## 4. Функциональные требования
### 4.1. Описание функционала / бизнес-процесса
Оператор открывает список заявок → нажимает на заголовок колонки с датой → список
перестраивается.
- **FR-1.** Оператор может отсортировать список заявок по дате по возрастанию и убыванию.
### 4.2. Критерии приёмки (Acceptance Criteria)
- **[FR-1]** Дано открытый список заявок, когда оператор выбрал сортировку по дате, тогда заявки выстроены в выбранном порядке, а состав списка не изменился.

## 5. Ограничения и атрибуты качества
### 5.1. Приоритет
Low — удобство, основной процесс не блокирует.
### 5.2. Сроки и обоснование
Без жёсткого срока.
### 5.3. Ролевая модель
| Роль | Права / доступные действия |
|------|----------------------------|
| Оператор | Сортирует список заявок |

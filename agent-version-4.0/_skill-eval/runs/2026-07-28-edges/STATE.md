# Раунд «граф внутрь карточки» — 2026-07-28

## Что изменилось в конструкции

Слепок сведён к **двум файлам**: `services/manifest.yaml` и `services/<name>.md`.
`feature-map.md`, `system-overview.md` и `reference/index.template.md` удалены.

Основание — разбор, а не вкус: индексы либо денормализовали то, что уже есть в карточках (кэш,
который расходится с источником: колонка зависимостей была противоречива в 10 прогонах из 10), либо
требовали того, что машинно не выводится (сквозные сценарии — требование «3–7» выполнялось в 1
прогоне из 10). Маршрутизация, ради которой индексы якобы нужны, у потребителей идёт **грепом по
содержимому** — Step 0.5 говорит это буквально.

Взамен в карточку добавлена **производная секция «Кто меня потребляет»** — обратные рёбра, которых
в индексах как раз и не было. Плоский список теперь несёт граф в обе стороны.

## Измерено

| Проба | Результат |
|---|---|
| SM-13 / SM-14 — обратные рёбра и симметрия | **6/6** |
| SM-16 — индексы не создаются | **6/6** |
| AR-15 — ребро записано с двух сторон | **5/5** |
| AR-17 — индексы не воскресают | **6/6** |
| Полнота связей — до правила | **0/6** (в карточку 1–2 вызова из 5) |
| Полнота связей — после правила | **3/4 полностью**, один свернул три вызова в один |

**Симметрия оказалась сильнее ожидаемого.** В фикстуру было занесено висячее зеркало (`auth`
считал, что его вызывает фронт, а в коде вызова нет) — все шесть прогонов нашли и сняли его.

## Найденное разбором, а не пробой

**Полнота связей — самый дорогой дефект раунда, и ни одна из 33 проб его не ловила.** Вызов к
сервису вне манифеста исчезал молча: правило «имена бери из манифеста» модель читала как «нет в
манифесте — нет строки». Карточка утверждала, что фронт ходит только в `geo`, тогда как в коде пять
вызовов к трём сервисам.

Проба «имена из манифеста» была при этом зелёной и маскировала дыру: имена верные, просто половины
строк нет. Видно только при сравнении карточки с кодом целиком.

Правило дополнено второй половиной: вызов есть в коде — строка есть всегда; сервис вне манифеста
пишется именем из кода с пометкой `вне манифеста`.

## Три урока про метод

1. **Проба меряет только то, на что нацелена.** Зелёная SM-11 сосуществовала с потерей 4 из 5 рёбер.
2. **Фикстура может обнулить пробу, не показав этого.** AR-15 была записана как 8/10 на `AR-BASIC`,
   где спека не добавляет нового межсервисного ребра — зеркало уже лежало в фикстуре, прогон нашёл
   готовое и отчитался успехом. Настоящее измерение потребовало `AR-EPIC`.
3. **Промпт пробы — часть измерения.** «Регресс» метки 6/8 оказался тем, что в промпте не было
   «инструмента вопросов нет»: два прогона честно встали на подтверждении состава и не влили ничего.

Плюс третий за раунд случай, когда **ошибся мой собственный `grep`**, а не скилл: посчитал README
фикстуры за созданный агентом файл-отчёт. Правило прежнее и подтверждается: каждый FAIL открывается
глазами до попадания в отчёт.

## Остаётся неопределённым (поведение не задано, модель решит сама)

`service-map`: сервис убрали из манифеста, карточка осталась сиротой; `name` переименовали; два
сервиса с одним именем; `type` вне списка; соседний каталог пуст.

`archive-spec`: спека без §1.2, на которой держится весь роутинг; сервис `type: external`, чью
карточку ведёт человек — слова `external` в архиваторе **нет вообще**; спека, которая **удаляет**
вызов (зеркало надо снять — правило есть одной фразой, пробы нет).

Из них приоритетны два: `external` (риск затереть человеческую карточку) и снятие ребра при
удалении вызова (иначе граф копит мёртвые связи).

**Сознательно не делаем:** предохранитель от преждевременной архивации. У `archive-spec` уже есть
запрет «не архивируй незавершённое» и подтверждение состава; второй ремень поверх первого стоил бы
внимания на каждом прогоне ради редкой ошибки человека. Риск принят и лежит на аналитике.

## Хвосты нового правила

- один прогон записал все пять вызовов без пометки `вне манифеста` (данные целы, метаинформация нет);
- один свернул три вызова к одному сервису в одну строку (ключ строки — сервис + вызов, значит
  строк должно быть три).

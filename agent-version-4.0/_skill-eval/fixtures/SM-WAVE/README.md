# Фикстура SM-WAVE — потолок волны

Дерево на диске, не текст: пробе SM-34 нужно посчитать, сколько карточек **реально записано**, а это
наблюдаемо только по файлам.

## Что в ней

- `tree/services/manifest.yaml` — девять сервисов: `svc-alpha`…`svc-foxtrot` (`backend`),
  `svc-golf`, `svc-hotel` (`frontend`), `svc-india` (`lib`). Карточек нет ни одной, `notes` нет ни у
  кого.
- `neighbours/svc-*/` — девять соседних реп с маркерами типа (`go.mod` + `main.go`;
  `package.json` + `vite.config.ts` + `router.tsx`; `package.json` с `exports` + `index.ts`). У
  каждой три-четыре ключа, чтобы скан был дешёвым: проба про **число сервисов**, а не про объём
  инвентаря.

## Раскладка песочницы

```
sandbox/WAVE-NN/
  specs/services/manifest.yaml   ← рабочая директория прогона (копия tree/)
  svc-alpha/ … svc-india/        ← копии neighbours/, на одном уровне со specs
```

Пути в манифесте относительные (`../svc-alpha`), как в проде.

## Что требуется (SM-34)

| Что | Ожидание |
|---|---|
| `specs/services/*.md` | ровно **6** файлов |
| остальные три сервиса | карточек нет — и не заглушек, а именно нет |
| `report.md` | назван остаток (**«6 из 9»** или равнозначно) и сказано, что добрать его следующим прогоном |

Красные исходы: собраны все девять (тогда правка не работает и дефект контекста воспроизведётся на
реальном масштабе); остановка молча, без строки про остаток (тогда неполный слепок читается как
полный); заглушки вместо карточек у оставшихся трёх.

**Три сервиса без карточек — это не мусор в песочнице, а состояние для продолжения.** Шаг 2.2 по
умолчанию берёт именно тех, у кого карточки ещё нет, поэтому повторный прогон подберёт остаток без
всякого файла состояния. Проба заодно проверяет, что скилл ничем этот остаток не помечает.

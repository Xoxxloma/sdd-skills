# Фикстура LOOP-MERGE — вливание в карточку, которую только что записал `service-map`

Второй шов петли: **скан → вливание**. Все прочие AR-фикстуры дают `archive-spec` карточку,
написанную руками, — то есть идеальную. Здесь карточка ровно такая, какой её оставляет
`service-map`: с прочерками `| — | |` в пустых секциях, с шапкой «Генерируется» и с блоком `notes`,
скопированным из манифеста (P3.1).

Проверяет, что механические ключи работают по **реальной** форме, а не по её представлению.

## Дерево

```
docs/ARS-88/
  technical_specification.md
services/
  manifest.yaml
  geo.md                              <- вывод service-map, скан от 2026-07-25
```

## Ожидаемое поведение

`archive-spec ARS-88` вливает в `geo.md`:

- `POST /v1/coverage/recalc` — **новый блок** в «Публичный контракт» (ключ не совпал ни с чем);
- `публикует \| geo.coverage.recalculated` — строка в «События», секция сейчас **пустая**;
- `coverage_admin` — строка в «Роли и доступ», секция сейчас **пустая**;
- `Chop` — тело блока «Владеет данными» переписывается целиком (ключ совпал).

## Что здесь проверяется

- **AR-27 (главная).** Пустая секция в форме `| — | |` — это **форма**, а не строка данных.
  Вливая в неё, прочерк надо **заменить**. Красный исход: `| — | |` остался, а под ним появилась
  настоящая строка — таблица из двух строк, одна из которых утверждает «событий нет» рядом с
  событием. Тот же класс — прочерк, оставшийся снизу.
- **AR-26.** Блок `notes` в карточке не изменён, не продублирован и не стал местом вливания.
  Он приходит из манифеста при скане и переписывается только оттуда; депрекейт, роль или что-либо
  ещё внутри него — красный исход. Шапка карточки («Генерируется…», три строки) тоже цела.
  **Фронтматтер целиком не тронут, включая `description`:** он маршрутный указатель, его пишет
  `service-map` из кода. Влитый контракт делает карточку шире описания — это нормально и сходится
  на ближайшем скане.
- **Ключи по реальной форме.** `### Chop` находится и переписывается телом целиком, а не
  дополняется снизу; `POST /v1/coverage/recalc` добавляется новым блоком в конец секции, а не
  внутрь существующего.
- **Порядок секций не поехал.** После вливания раскладка та же, что оставил `service-map`:
  вливание не пересобирает карточку.
- **Frontmatter цел.** `scanned: 2026-07-25` не сдвинулся.

## Ловушка

Соблазн — «привести карточку в порядок»: убрать прочерки в остальных пустых секциях, дописать
`notes`, поправить шапку. Всё это выглядит как улучшение и всё это красный исход: карточку ведёт
`service-map`, а `archive-spec` вносит в неё ровно то, что сказала спека, ничего не трогая по пути.

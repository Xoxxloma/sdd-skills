Ты — голова скилла `service-map`. Сервис прочитан частями; ты пишешь каркас карточки и общие секции.
Три правила важнее всего: не выводится из кода — `не определено`; чужие репозитории только читаешь;
секреты не копируешь. Своих субагентов не запускаешь.
Сервис: <пути>, тип `<type>`. Имена сервисов манифеста: <имена>.
Прочитай целиком `<шаблон>`. Ответ начни строкой `шаблон прочитан, тип: <type>; голова`.
Описи частей: <описи частей> — читай их, а не код ключей.
Прежняя карточка: <прежняя> (нет — абзац пропусти). Из неё открой только свои секции: строки заголовков
`## ` найди `Grep` с `-n`, читай `Read` с offset и limit. Роль или система та же — её имя пиши как в
прежней, дословно; факты строки те же — верни прежнюю формулировку дословно.
Файл `<каркас>`: первая строка `<!-- service-map: голова <дата> -->`, дальше карточка по шаблону, в
порядке секций для типа `<type>`: шапка и frontmatter (`scanned: <дата>`), «Генерируется», «Заметки
команды» (дословно: <notes>), «Назначение» и «Что умеет для пользователя» — по группам описей частей,
словами, которыми сервис говорит с человеком; «Стек» — по файлам сборки и конфигам; «Зависит от» —
по коду всего сервиса (клиенты, подключения, переменные окружения): одна строка на сервис или внешнюю
систему, имя сервиса — из имён манифеста, иначе как в коде и `вне манифеста`; «Роли и доступ» —
по коду (конфиг безопасности, перечисления ролей); «Кто меня потребляет» — пустой формой.
«Бизнес-правила» (если они есть у типа) — тоже твои: по строкам `состояние:`, `справочник:`,
`сообщение:`, `ограничение:` описей частей и строкам `·` под ними, по форме шаблона. Объект — один
блок на сущность, одно значение — одна строка, сколько бы частей о нём ни писали. Сообщение — один
блок на имя в коде: тот же топик, шаблон письма или метод отправки у разных частей — один блок,
названный словами один раз; у каждого публикуемого топика из описей блок есть. Ограничение — только
с переключателем из имён манифеста или ролей твоих «Ролей и доступа»; иного нет — блока нет.
Справочник блока не получает. Порядок — объекты, сообщения, ограничения, внутри — по алфавиту ключа.
Код открывай там, где строки частей спорят. Перед возвратом прогони по секции грепы ` /[a-z]`,
`\b(GET|POST|PUT|PATCH|DELETE)\b`, `\b[a-z]+[A-Z][A-Za-z]*\b`, `\b[a-z]+(\.[a-z-]+){2,}\b` вне бэктиков
и перепиши совпавшее словами; в бэктиках — только значение перечисления, имя вида или топика, имя
сервиса из манифеста и поле-дата в скобках рядом со значением, как в шаблоне.
В секциях «Публичный контракт», «Владеет данными», «События», «Фоновые задачи» — только заголовок
секции и строка `<!-- части -->`; в «Потребляемые API», если она есть у типа в таблице порядка шаблона
(у `backend` её нет), — заголовок секции, заголовок таблицы, разделитель и строка `<!-- части -->`.
Файл `<опись головы>`: первая строка — та же, что у каркаса, `<!-- service-map: голова <дата> -->`;
затем по строке на роль: имя роли, как в первой колонке
«Роли и доступ», затем ` — ` и файл; слова «роль» впереди нет. Затем строки «Бизнес-правил» —
по одной на блок и на справочник, в форме описей частей (`состояние: <Сущность>.<поле> <значения> — <файл>`,
`справочник: …`, `сообщение: «<вид>» — <кому>, <имя в коде> — <файл>`, `ограничение: <условие> —
переключатель: <имя> — <файл>`), вид и условие — теми же словами, что в заголовке блока; последней —
`⟹ состояний N (значений M), справочников K, сообщений L, ограничений R`.
Что вернуть — ровно три строки:
шаблон прочитан, тип: <type>; голова
опись: <опись головы>
карточка: <каркас>

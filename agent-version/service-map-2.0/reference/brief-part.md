## Ты читаешь часть сервиса — этот файл старше брифа
Ты — часть NN из S. Твои ключи — только из своих путей: <свои пути>;
за фактом иди куда угодно в репозитории. Ключ твой, если в твоих путях стоит его пометка —
аннотация, регистрация на роутере, декоратор, маркер операции спеки, — где бы ни лежал обработчик: за ним иди сам. Ключ без
пометки в коде (операция спеки без маркера разведчика, топик из конфига) твой, если в твоих путях его
обработчик, слушатель, отправитель: путь операции или имя топика бери грепом по этому файлу, целиком
его не читай. Имена сущностей бери по
коду всей репы: сущность чужой части у твоей ручки — сущность, а не «не сущность».
Строка задания называет части спецификации — операции спецификации пишут только они; не твоя — не
пиши, даже если обработчик в твоих путях. Твоя часть — кусок спецификации (в строке задания список
`operationId`) — тогда твои ключи — операции из этого списка (строки — подсказка), реализацию ищи по
коду всей репы; метод и путь операции бери из спецификации — строки пути и метода над её
`operationId`, — а не выводи из имени операции.
Первая строка обоих твоих файлов — `<!-- service-map: часть NN <дата> -->`.
В черновике — ТОЛЬКО секции со своими ключами: «Публичный контракт», «Владеет данными», «События»,
«Фоновые задачи», строки «Потребляемые API» своих ключей — без заголовка таблицы и только если у типа
`<type>` эта секция есть в таблице порядка шаблона (у `backend` её нет: исходящие вызовы голова пишет в
«Зависит от»). Шапки, frontmatter, «Назначения», «Что умеет», «Стека», «Зависит от», «Ролей»,
«Бизнес-правил», «Заметок», «Кто меня потребляет» не пиши — их пишет голова.
Ролей в описи нет.
«Бизнес-правила» голова пишет по твоей описи: строки `состояние:` (сущности из твоих путей),
`справочник:`, `сообщение:` и `ограничение:` (из твоих файлов), под каждой — строки `  · <факт> — <файл>`.
Под `состояние:` — строка на значение: кто или что переводит сюда, при каком условии, что ещё
происходит, что в нём нельзя. Переход ищи грепом значения по всей репе, а не только в своих путях; не
нашёл нигде — `  · <значение> — не определено: перехода в коде нет — <файл перечисления>`. «Перехода
нет в этой части» не пиши: это не факт о коде. Под `сообщение:` — повод, кто получает и кто нет; под
`ограничение:` — что отказывает и что видит пользователь.
Прежнюю карточку целиком не открывай: найди грепом заголовки своих ключей из своей описи и читай
только эти блоки (`Read` с offset/limit).

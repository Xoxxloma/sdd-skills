# Обновление скиллов — одна команда, ничего руками

Скрипт `tools/skills.sh` уже лежит в репозитории со спеками. Он клонирует репозиторий со скиллами,
копирует каждый скилл в `.gigacode/skills/` и печатает версии. Твоя работа — запустить его и
пересказать результат. Всё.

## Порядок

1. Выполни из корня репозитория ровно эту команду (аргумент подставь, только если пользователь
   назвал другую папку назначения):

   ```
   bash tools/skills.sh
   ```

   Именно через `bash …`, не `./…` и не `sh …`: в корпоративных образах запуск файлов из домашней
   папки бывает запрещён, а bash читает скрипт как текст.

2. Покажи пользователю вывод скрипта как есть: строку с адресом репозитория, список
   `имя скилла — версия` и итог «установлено в …: N скиллов». Ничего не пересчитывай и не сокращай.

3. Если скрипт завершился ошибкой — приведи её текст дословно и одну подсказку из таблицы ниже.
   Больше ничего не делай.

| В выводе | Подсказка пользователю |
|---|---|
| `bash: command not found`, `'bash' is not recognized` | В системе нет bash. На macOS и Linux он есть из коробки — значит, агент запускает команды другой оболочкой; на Windows bash ставится вместе с Git (Git Bash). После установки перезапустить GigaCode. |
| `нужен git` | В системе нет git. Поставить штатным способом для своей ОС (на Windows — Git for Windows, там же Git Bash). |
| `No such file or directory: tools/skills.sh` | Скрипта нет в этом репозитории: попросить у команды `tools/skills.sh` и положить в папку `tools/`. Либо команда запущена не из корня репозитория. |
| `Permission denied`, `Authentication failed`, `could not resolve host` | Нет доступа к репозиторию со скиллами. Проверить, работает ли `git clone` этого репозитория вообще; доступ выдаёт команда скиллов. |
| `в репозитории со скиллами нет папки .gigacode/` | Репозиторий скиллов переехал или адрес в скрипте устарел — сообщить команде скиллов. |

## Чего не делать

- Не копировать папки скиллов вручную, не писать свой скрипт, не «чинить» `tools/skills.sh`.
  Если скрипт не сработал, задача пользователя — не твоя.
- Не менять адрес репозитория и ветку. Их задают переменные `SDD_SKILLS_REPO` и `SDD_SKILLS_REF`,
  и трогает их только тот, кто сопровождает скиллы.
- Не запускать скрипт повторно «на всякий случай» и не вызывать другие скиллы после него.

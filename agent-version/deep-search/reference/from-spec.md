# Глубокий поиск из спеки

Этот файл читает ведущий `technical-spec-doc`. Код ты сам не читаешь: по выбору аналитика его читает
разведчик `deep-search`, ты сверяешь его ссылки и несёшь найденное аналитику новой гипотезой. Фактом
пункт по-прежнему делает только ответ аналитика.

**Поиск файлов:** папку задаёт параметр `path`, маску — `pattern`. Маска, которая начинается с имени
папки (`services/*.md`), не находит ничего; `**/` в начале маски работает.

## 1. Код рядом

Один раз за запуск, перед первым вопросом о существующем сервисе:

- `<Корень>` — текущая папка, абсолютным путём; `<Родитель>` — `<Корень>` без последнего сегмента.
- `Read <Корень>/services/manifest.yaml`. Файла нет → кода рядом нет ни у кого.
- По каждому существующему сервису, о котором будешь спрашивать: строка с его `name` в манифесте → её
  `path` → абсолютный путь. `../x` превращай в `<Родитель>/x` сам: `..` в путях инструментов не пиши,
  поиск с ним молча вернёт пустоту. Путей через запятую несколько — бери первый.
- `Glob pattern="*" path="<этот путь>"` нашёл хоть один файл → у сервиса код рядом. Сервиса в манифесте
  нет, `Glob` пуст или вернул ошибку пути → кода рядом нет.
- Субагента запустить нельзя → кода рядом нет ни у кого.

Код рядом есть → в вопросе-допущении об этом сервисе четвёртый вариант: «Глубокий поиск — посмотреть в
коде <сервис>». У остальных сервисов вопрос прежний.

## 2. Аналитик выбрал поиск

Разведчик — один на вопрос. Поиск выбран в нескольких вопросах → по разведчику на каждый, все одним
сообщением. Тип субагента — любой, у которого есть `Read`, `Grep`, `Glob`. Промпт — этот, с подстановкой,
без своих добавлений:

```
Ты — разведчик скилла deep-search. Сначала прочитай бриф <абсолютный путь к brief.md рядом с этим файлом> и работай строго по нему.
Утверждение: <гипотеза вопроса, как ты задал её аналитику>
Корень: <абсолютный путь к текущей папке>
Сервис: <name сервиса из манифеста>
```

В ответе нет хотя бы одного из двух заголовков — `## ОТВЕТ ПО КОДУ`, `## ПРОЧИТАНО` → запусти ещё раз тем
же промптом. Снова нет → как вердикт `не нашёл`.

**Сверка.** Каждую ссылку на код проверь, как велит раздел «Шаг 3 — сверка ссылок» в `SKILL.md` этого
скилла — он папкой выше этого файла: прочитай раздел и выполни. «Ответ» в нём — твой ход к аналитику.

## 3. Вопрос по ответу разведчика

| `Вердикт:` после сверки | Вопрос аналитику |
|---|---|
| `подтверждается` | «В коде <сервис> так и есть: <что делает код>. Беру?» |
| `в коде иначе` | «В коде <сервис> иначе: <как в коде>. Беру как в коде?» |
| `не нашёл`; не осталось ни одного пункта `[в коде]`; в ответе блок `## НУЖЕН ВЫБОР` | прежний вопрос без варианта поиска; перед ним строка «В коде <сервис> ответа не нашёл: <пункт `[не нашёл]` или `[вне кода]`>» |

- Перед вопросом — пункты разведчика, прошедшие сверку, со ссылками, и строка «Читал: <репа>, ветка
  <ветка> — локальная копия, могла отстать от удалённой».
- Варианты: «Да, беру», «Иначе — поправлю», «Не знаю, оставим к валидации». Поиска среди них нет: поиск —
  один на вопрос.
- «Да» на вердикт `подтверждается` или `в коде иначе` → 🔵, в скобках метки «по коду <сервис>, ветка
  <ветка>»; ветка не определена — так и пиши. В строке `не нашёл` вопрос прежний, и источник у «да» прежний.
  Аналитик поправил → метка «со слов». «Не знаю» → 🟡 к валидации.
- В ответе строка о расхождении карточки с кодом → скажи аналитику одной строкой: «Карточка
  `services/<сервис>.md` расходится с кодом: <что>. Обновить: `/service-map <сервис>`».

## 4. Что из ответа разведчика идёт в спеку

После «да» найденное идёт в спеку по договору происхождения `technical-spec-doc` (источник «по коду …»):
путь и метод ручки или имя события и поля — так, как их видит потребитель, — и поведение словами. Ссылки
`файл:строка` и имена реализации в спеку не идут: они нужны аналитику, чтобы проверить находку.

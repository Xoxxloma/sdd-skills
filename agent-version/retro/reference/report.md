# Отчёт ретро — как писать

Читатель — сам пользователь. Цель — чтобы он узнал свои привычки по конкретным моментам и попробовал одну вещь.
Не оценка: без баллов, процентов «качества», светофоров и сравнения с другими.

## Откуда брать

Только из `moments.md`: признаки, «в K из N», цитаты с датой и ходом, факты скрипта. Цитаты — как в таблице, не
переписывай. Признак, которого в таблице нет, не упоминай. Пишешь «в журнале нет», а не «вы не сделали»: журнал
видит не всё.

## Разделы — по порядку

1. **Одна строка вводная:** сколько сессий и за какие даты. «Это для вас: не оценка, никуда не отправляется.» Если в
   таблице «сессий мало» — так и скажи.
2. **Что получается** — до трёх пунктов из «помогает», сначала с большим K. Пункт: что вы делаете, «в K из N
   сессий», одна цитата (дата, ход).
3. **Что мешает** — до трёх пунктов из «мешает», сначала с большим K. «Чего нет в контексте проекта» — в п. 4.
   Пункт:
   - заголовок: что происходит и «в K из N сессий»;
   - цитата (дата, ход) и что из этого вышло — из пояснения в таблице;
   - почему важно — правило фреймворка из таблицы ниже;
   - что сделать — команда или кнопка из таблицы ниже.
4. **Чего не хватает в контексте проекта** — только если в таблице есть «чего нет в контексте проекта»: вопросы
   агента цитатами списком и совет добавить эти сведения в контекст (`/context-doc`), чтобы агент не спрашивал снова.
5. **Модель** — только если в фактах слабая модель есть хотя бы в одной сессии: в скольких сессиях и почему это
   важно (строка «слабая модель» в таблице ниже).
6. **Сбои агента** — только если они есть: одна–две строки с цитатой, без диагноза скиллу. Это не ваша ошибка.
7. **Главное попробовать** — ровно одно, из первого пункта «Что мешает»: «Когда X — делаю Y», где X — ситуация из
   ваших сессий, а Y — команда или кнопка.
8. **К сведению** — до трёх одиночных случаев (K = 1), которых нет выше, и моменты «другое» при любом K, по строке.
   «Другое» идёт только сюда — ни в «Что получается», ни в «Что мешает».
9. **Чего ретро не видит** — одна строка: читали ли вы документы, что правили руками вне агента, качество
   документов.
10. **Разобрано** — сессии из таблицы: дата, длительность, реплики.

Пустой раздел не пиши. Коротко: пункт — три–четыре строки, весь отчёт — экран-два.

## Правила фреймворка и что сделать

| Признак в таблице | Почему важно | Что сделать |
|---|---|---|
| вход через /analyst-workspace | оркестратор сам зовёт нужный скилл, запускает приёмку и показывает, где чистить контекст | работу над документом начинать с `/analyst-workspace` |
| ключ задачи | ключ — имя папки и первый вопрос; без него работа стоит | завести задачу в трекере до запуска и назвать ключ в первой реплике |
| продолжение прерванной работы | состояние работы лежит на диске, пересказ отстаёт от файла | `/analyst-workspace` → «Продолжить начатое» или путь к файлу, без пересказа |
| опора на карточки проекта | агент опирается на карточки сервисов и `context/`; без них он гадает или спрашивает | `/service-map` для соседних сервисов, `/context-doc` для документов |
| чего нет в контексте проекта | то, о чём агент спрашивает каждый раз, должно лежать в контексте | добавить через `/context-doc`: роли, права, согласования, процессы |
| гипотезы агента | подтверждённая гипотеза уходит в документ как решённая | на длинную пачку отвечать по каждой строке «да / правка», а не одним «да» |
| решения | решение бизнеса за вами; отданное агенту он додумает | «не знаю, TBD» вместо «сам реши» |
| неизвестное | «не знаю» и «TBD» — честные метки; «уточню позже» оставляет пункт висеть | отвечать «не знаю» или «TBD» |
| петля поправок | после двух неудачных поправок третья обычно не помогает | `/clear` и одна реплика: что нужно, что не так, когда готово |
| чистый контекст между стадиями | каждая стадия — с чистого контекста; на загруженном окне агент теряет детали | `/clear` там, где агент пишет «здесь можно `/clear`», дальше `/analyst-workspace` → «Продолжить начатое» |
| большие вставки | большой документ в чате съедает окно и теряется при сжатии | `/context-doc <файл>` |
| приёмка | при нарушениях документ дорабатывает скилл; ручная правка и `/clear` до доработки теряют список нарушений | при нарушениях — «Поправить документ сейчас», у спеки — «Доработать спеку»; без `/clear` между «Проверить спеку» и «Доработать спеку» |
| проверка спеки до разбиения | этапы, нарезанные по непроверенной спеке, переделываются вместе с ней | сначала «Проверить спеку», потом «Разбить на этапы» |
| слабая модель | на слабой модели хуже и документы, и проверки: приёмка работает на модели сессии | для работы над документами переключиться на основную модель |

## Пример пункта «Что мешает» — форма, не содержание

> **Длинные пачки гипотез подтверждаются одним «да» — в 3 из 7 сессий.**
> «подтверждаю» (12.10, ход 41) — восемь пунктов подтверждены за 5 секунд.
> Почему важно: подтверждённая гипотеза уходит в документ как решённая.
> Что сделать: на длинную пачку отвечать по каждой строке «да / правка».

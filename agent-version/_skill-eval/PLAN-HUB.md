## Повод

Лог `repo-split` на чужом Java-монолите (≈3000 файлов, один сервис). Прогон бродил сорок ходов и
не выдал ничего: ни таблицы «папка × класс», ни строк манифеста. По дороге он посчитал 14
эндпоинтов вместо ста с лишним, изобрёл разрез по слоям, сам его отверг и завис между «порога у
тебя нет» и «предъяви два варианта».

**Причина системная, и она записана в журнале прошлого раунда.** Все десять циклов c1…c10 шли по
репам, которые решаются **границами приложений**: `repairy` — монорепа из четырёх, `resonance` —
мелкая. Ветка «одно приложение перевалило порог → режем его по связности пакетов» не исполнялась
**ни разу**; в `STATE.md` про это стоит отдельный раздел «Чего этот раунд НЕ проверил». Первый же
выход на неё в поле провалился.

## Порядок правок по необходимости

| # | Блок | Почему в этом порядке | Дефект лога |
|---|---|---|---|
| 1 | **H — топология звезды** | единственный дефект, из-за которого на этом классе реп нет выхода вообще: остальные правки дают точные числа и ту же паралич | связность звёздная, слабого шва нет, процедуры для этого случая в скилле не было |
| 2 | **T — гейт таблицы 2.3** | без таблицы «папка × класс» нет ни классов папок, ни арифметики Шага 4, ни состава кусков; правило было, механизма не было | прогон посчитал только по репе и ушёл в матрицу импортов |
| 3 | **C — ложный НЕнулевой счёт** | «ноль → вторая команда» не покрывает «мало, но не ноль»; занижение в восемь раз выглядит аккуратной работой | 14 эндпоинтов вместо 118; события посчитаны классами, а не топиками |
| 4 | **M — рецепт матрицы** | предусловие исполнимости H: без готовой команды прогон пишет скрипт на другом языке и кладёт его в чужую репу | питоновский скрипт, отказ песочницы, копирование в соседний воркспейс |
| 5 | **G — запрет археологии** | стоило ходов, не корректности; правило было в «Трёх правилах», в «Когда чего не делать» его не было | `git log`, README, история релизов, суждение о выводе из эксплуатации |

## Что внесено

- **H** (Шаг 3, конец): топология меряется числом одной командой; таблица «кластеры → режем / звезда
  → режем только периферию»; хаб называется поимённо и числом; ядро остаётся одним куском и слоем
  не режется. Плюс абзац в Шаге 4: у звезды варианты различаются периферией, а не ядром.
- **T** (Шаг 3, начало): связность считается по папкам из таблицы 2.3; таблицы нет — возврат на 2.3;
  сквозные из матрицы выбрасываются.
- **C** (Шаг 2.2 и 2.3): контракт бывает объявлен вне кода — спека, `.proto`, SDL, признак в сборке
  и `implements *Api`; три отношения-проверки «мало — повод для второй команды»; событие — топик,
  а не класс.
- **M** (Шаг 3): готовая `awk`-команда матрицы для языков с пакетными импортами; запрет писать
  скрипты на другом языке и класть их вне репы спек.
- **G** («Когда чего не делать»): историю чужой репы не изучаем, о жизненном цикле не судим.

`repo-split`: 801 → 909 строк. Дедуп внутри «Трёх классов папок» вернул 3 строки; больше сокращать
не стал — остальные повторы выиграны десятью измеренными циклами, и резать их ради бюджета дороже,
чем нести сто строк.

## Стенд

`RS-HUB` — генератор, 1354 java-файла, ОДНО приложение. Три ловушки, все из лога:

| Ловушка | Правда | Что даёт наивный маркер |
|---|---|---|
| контракт вне кода | 118 эндпоинтов (104 операции спеки + 14 аннотаций legacy) | **14** — не ноль, поэтому правило «ноль по классу» не срабатывает |
| событие ≠ класс | 20 топиков в конфиге | **11** классов `*EventProcessor`/`*KafkaProducer` |
| звезда | 75 % ссылок через `shipment` (479 из 631) | «границы по слабым связям» там, где их нет |

Периферия отделяется чисто: три кластера, внутри десятки связей, к хабу единицы. Верный разрез —
**4–5 кусков**: три периферийные группы плюс ядро.

Грейдер `grade-rs-hub.mjs`, восемь красных счётчиков. Провалидирован на двух заранее написанных
ответах — заведомо красном (копия полевого лога) и заведомо зелёном: КРАСНО и ЗЕЛЁНО соответственно.

## Два дефекта грейдера, найденные первым же прогоном

Оба — ложные показания, и оба чинились до начала серии.

1. **Разделитель ячеек бывает псевдографикой.** Прогон нарисовал таблицу рамкой `│` (U+2502), и
   парсер увидел одну ячейку вместо восьми: числа были верные — 104 и 91, — а грейдер показал
   «нет». Ложное красное так же вредно, как ложное зелёное: по нему правят то, что работает.
2. **Хаб «назван числом» засчитывался по любому числу.** Прогон написал «`shipment` — центральный
   домен (360 файлов, 26 % всей репы)», матрицы импортов не считал вовсе, — а счётчик встал
   зелёным. Теперь число обязано стоять в одной строке со словом про связи.

Плюс добавлен счётчик, которого не было: **ядро одним куском**. База предъявила «30 кусков по
доменам» либо «8 логических групп» — и по прежним счётчикам это проходило.

## База (старый скилл, 1 прогон)

```
классов не сошлось 1 (события 0 вместо 20) · хаб не назван 1 · ядро раздроблено 1 (8 кусков)
разрез по слоям 0 · периферия не отделена 0 · вердиктов неверных 0 · археология 0
```

Эндпоинты старый скилл нашёл (104 — спеку прочитал). Ловушка «14» на нём не сработала; правка C
остаётся нужной, но её вес по этой фикстуре меньше ожидаемого.

## Условие выхода

## 2. Общий фундамент — разведчик (новый Шаг 3.0)

Субагент до чтения кода, **только `Read`/`Grep`/`Glob`**. Полный обзор дерева запрещён (`Glob **/*` по
монолиту — сотни КБ). Смотрит структуру верхних уровней, грепает типовые пометки по стекам из примеров,
открывает по одному файлу на кандидата — убедиться, что пометка стоит на ключе, а не на классе. Обязан
проверить несколько верхних папок, а не первую попавшуюся: частотного списка аннотаций на проде нет.

Возвращает **только маркеры**, по строке, **без чисел**:

```
контракт :: @(Get|Post|Put|Patch|Delete)Mapping\(            :: *.java  :: ключ
контракт :: @Dgs(Query|Mutation|Subscription)\b              :: *.java  :: ключ
контракт :: @DgsData\(parentType\s*=\s*"(Query|Mutation)"   :: *.java  :: ключ
сущности :: @Entity\b                                         :: *.java  :: ключ
задачи   :: @Scheduled\(                                      :: *.java  :: ключ
топики   :: class \w+EventProcessor\b                         :: *.java  :: ориентир
```

`ключ` — одно совпадение = один ключ; иначе `ориентир`. Правила брифа без стека: маркер узкий (ORM-`@Query`
не контракт; `@DgsData` на не-корневом типе — резолвер поля, не операция); одна пометка на объявление
(`@Entity` и `@Table` — не вместе); пометка класса — не маркер ключа. Нынешняя таблица 3.1 переезжает в
бриф **примерами** нескольких стеков с оговоркой «примеры, не список».

Ведущий по каждой строке — `Grep output_mode="count"`: итог класса по строкам `ключ` — нижняя граница
(как сейчас); счёт по файлам (`ключ` и `ориентир`) — вход нарезки.

**Бюджет разведчика** — два прогона. Отказ, пустой ответ, регэксп не компилируется → сегодняшнее «стек
не из таблицы»: сверки по классу нет, строка в отчёт, один читающий, нарезки нет.

## 4. Задача Б — разрез во время прогона

### 4.1 Когда

Сумма ключей по строкам `ключ` > K → нарезка; иначе — сегодняшний путь. **Реактивного входа нет**: обрыв
читающего — по сегодняшним правилам 3.4 (снято, v1 противоречил бюджету). Нет субагента с командной
строкой → нарезки нет (склеить нечем, §7.2) — сегодняшний путь. Абзац `SKILL.md:315–319` («размер не
меряешь… решает человек») переписывается под нарезку.

### 4.2 Как режется — скриптом

1. Ведущий записывает вывод своих грепов по файлам (`путь:N` по каждой строке разведчика) дословно в
   `.work/<name>/counts.txt` — это числа, не текст карточки.
2. Субагент с командной строкой запускает `reference/plan.sh` из каталога скилла: суммы по папкам,
   вес папки = ключи + w × ориентиры (w — §7.9), папки по пути подряд группами ≤ K; папка тяжелее K
   делится по файлам; один файл тяжелее K — отдельной частью, строка в отчёт. Печатает план (части и их
   папки, число ключей части по классам) и итоги по классам.
3. Ведущий сверяет итоги плана со своими грепами. Разошлись → без нарезки, строка в отчёт.

**Остаток.** Всё, что вне папок частей (папки без единой пометки: общие утилиты, конфиги, рассылки), —
отдельная часть «остаток»: ключи любых классов из файлов **вне** папок частей 1…S. Так у каждого ключа
есть ровно один хозяин, включая ключи без пометок (Kafka руками, топики из конфига, сообщения из папки
рассылок). Нагрузка остатка меряется вместе с w (§7.9).

### 4.3 Кто что пишет — у каждого класса один писатель

| Субагент | Ключи | Пишет в `.work/<name>/` |
|---|---|---|
| часть ×S | только из своих папок; факты — по всей репе; **имена сущностей — по коду всей репы** (чужая сущность у ручки — сущность, не «не сущность») | опись без ролей; блоки: контракт, «Владеет данными», «События», «Фоновые задачи», «Бизнес-правила» (свои сущности, сообщения и ограничения из своих папок), строки «Зависит от» и «Потребляемые API» своих ключей |
| остаток ×1 | из файлов вне папок частей | то же, что часть |
| голова ×1 | роли; ключей других классов не пишет | шапка и frontmatter, «Назначение», «Стек», «Что умеет» (по описям частей), «Роли и доступ», «Генерируется», «Заметки команды», пустая «Кто меня потребляет» |

Первая строка каждого файла части — `часть <NN> <дата>`.

**Пересбор поверх прежней карточки:** часть берёт из прежней карточки **только блоки своих ключей** —
греп заголовков по своей описи, `Read` с `offset`/`limit`. Прежнюю карточку целиком не открывает никто.

### 4.4 Сборка — скриптом `reference/assemble.sh`

Запускает субагент с командной строкой, внутри репы спек:
- проверяет, что есть все S+2 файла и у всех дата сегодняшняя; иначе — отказ, строка в отчёт;
- секции — по таблице порядка шаблона;
- блоки внутри секции — по ключу: контракт по пути, затем по глаголу (бэктики снимаются); «События» —
  `потребляет`, потом `публикует`, внутри по топику; «Бизнес-правила» — объекты, сообщения, ограничения,
  внутри по имени; остальное по алфавиту (`LC_ALL=C`);
- **дубль ключа из двух частей — склейка** под одним заголовком, одинаковые строки один раз, строка в
  отчёт (§7.10);
- «Зависит от» схлопывает по имени сервиса, «Потребляемые API» — по сервису и вызову;
- заглушки `—` и `не определено` части удаляются, если в секции есть блоки других частей;
- сводная опись: списки подряд, итоги `⟹` по классам суммируются;
- пишет `.work/<name>.md` и `.work/<name>.opis.md` — дальше Шаг 4 как сейчас.

## 7. Решения владельца (2026-10-04)

1. **Часть упала дважды → карточку не писать**, прежняя байт-в-байт, сервис в отчёт с именем части.
2. **Нечем склеить (нет командной строки) → сервис не записан**; на практике — нарезки нет, сегодняшний путь (§4.1).
3. **Сплиттеры после Б → удалить оба.** После зелёного Б и поля. Ссылок из других скиллов нет (только
   CHANGELOG, `repo-split-log.md`, `docs/README-old.md`). Нарезанные строки `adjutant-*` работают как есть.
4. **Вес сущности = 1**, как у ручки.
5. **Маркеры в карточке не хранятся** — разведчик каждый прогон.
6. **Порог прогона — в читающих субагентах**, число по замеру окна ведущего.
7. **Пересборка скриптом бюджет не тратит.**
8. **Командная строка на проде — только внутри репы спек.**
9. **Вес папок без пометок — замерить** (K-2).
10. **Дубль ключа из двух частей — склеить** под одним заголовком.
11. **Порог пика читающего — 200k.** Haiku-плечи — со сниженным K (Б-7).
12. **В раунде — дефект ведущего (этап 1).** «Задето» на большом сервисе и потребители, читающие карточку
    целиком, — известные стыки (§8).

## 8. Не делаем / известные стыки

- **Плотность фактов внутри ключа** — потолок самореференции нарезка не снимает; Б-3 проверяет, что не хуже.
- **Ключи без пометки** теперь имеют хозяина (остаток), но внешней сверки числа у них нет.
- **«Задето» на сервисе больше K** — быстрое обновление идёт одним субагентом (опись всего сервиса +
  прежняя карточка целиком) и на адъютанте, скорее всего, оборвётся. Обход — полный рескан
  `service-map adjutant` без «Задето». Отдельный раунд.
- **Потребители** читают подходящую карточку без ограничения (`technical-spec-doc/SKILL.md:219`; соседей —
  кусками, `:223`). Карточка адъютанта ≈ 150–300 КБ (экстраполяция с repairy-api: 116 ключей → 59–132 КБ).
- **Маршрутная строка `description`** у одной карточки на монолит грубее, чем у кусков сплиттера.
- **Токены Sonnet и deepseek считаются по-разному** — запас до 262k заложен порогом 200k, не мерен.

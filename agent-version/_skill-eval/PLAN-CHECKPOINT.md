## Повод

Аналитику нужно **плановая пауза** посреди интервью по тех-гейтам: сохранить прогресс, сжать
контекст (`/compact`), вернуться — без потери качества. Сейчас ответы аналитика на гейты (Step 3,
несколько ходов `AskUserQuestion`) живут только в контексте; файл появляется один раз в Step 4

## Отвергнутый ход (не возвращаться)

**Сразу писать половинчатую `technical_specification.md` и дозаполнять по гейтам.**

1. Половинчатая спека = гипотезы по неподтверждённым гейтам в ФАЙЛЕ в форме готовых секций —
   ровно то, что скилл запрещает (`SKILL.md:336` «гипотеза в вопросе безопасна, в файле — грех»).
2. Дозаполнение = `Edit` по большому файлу слабой моделью: INT-карточки тянут §3/§4/каталог
   ошибок/§8, остаются старые 🟡, карточка расходится с §3 (см. память `reference-split-loses-form`).
3. Файл с этим именем — продукт: его читает аналитик и `stage-breakdown-doc`; черновик от готовой
   отличает только строка статуса, которую и так угадывают (`SKILL.md:527`).
4. Существующая спека включает Refinement pass (`SKILL.md:622`) — нужен третий режим «черновик»
   со своей веткой в Step 0 и пробами.
5. Ломает «Turn 1 = только вопросы, файла нет» (`SKILL.md:13,91`) — на это есть пробы.

Приемлем только при двух условиях (шапка `ЧЕРНОВИК, ❓: 4,6,9` + перезапись целиком `Write` в
конце) — и тогда отличается от выбранного хода лишь тем, что гипотезы лежат под именем продукта.

## Выбранный ход: sidecar-чекпоинт

Хранит **только то, что нельзя восстановить из БТ** — ответы аналитика его словами. Дизайн
(схемы, JSON, состояния) модель регенерирует за один ход из БТ + ответов, из чистого контекста.

**Доводы:** ноль гипотез на диске; ноль правок по написанному (спека по-прежнему пишется один раз
целиком); refinement pass и Turn 1 не трогаются; форма — 11 строк, не потерять.

### Файл

`technical_specification.progress.md` в папке БТ (рядом с будущей спекой).

```
# Прогресс интервью — задача <номер | ❓>
БТ: <путь>. Прочитано из контекста: services/auth.md, context/…
1. Тип и стороны — ✅ «fullstack, BE у команды платежей»
2. Инвентарь взаимодействий — ✅ «INT-1 создание, INT-2 вебхук; INT-3 не нужен»
3. Владение и допущения — ⏭️ «поле X в auth — к валидации»
4. … — ❓
11. Номер задачи — ✅ 4821
```

Строка к ✅/⏭️ — ответ аналитика, одна строка. ❓ стоит голым — **без предложений, схем, JSON**
(иначе это черновик спеки и все минусы отвергнутого хода возвращаются).

### Жизненный цикл

1. Turn 1 — вопросы, файла нет (как сейчас; записывать нечего).
2. Аналитик ответил на гейты → модель перезаписывает чекпоинт целиком (`Write`, не `Edit`).
   Повторяется каждый ход интервью.
3. «Сохрани прогресс» / «прерываемся» → чекпоинт + одна строка «прогресс сохранён: закрыто N/11,
   следующий — гейт K». Спеку не пишет. Аналитик компрессит.
4. Возврат (тот же вызов скилла с БТ): Step 0 видит чекпоинт без спеки → читает; ✅/⏭️ **не
   переспрашивает** (правило `SKILL.md:462` начинает работать через границу сессии); ход
   начинается с «продолжаю: закрыто N/11, открыты …» и первого ❓. Это по-прежнему «ход =
   вопросы».
5. Реестр чист → Step 4 пишет спеку из контекста, как сегодня; чекпоинт в записи не участвует.
6. Сразу после записи спеки чекпоинт перезаписывается строкой `закрыт: спека записана`
   (удалить нечем — `Bash` не в `allowed-tools`; давать право удалять = новый инструмент у
   слабой модели, не надо).
7. Спека уже есть, или чекпоинт со строкой `закрыт:` → чекпоинт игнорируется; спека есть →
   Refinement pass как сегодня.

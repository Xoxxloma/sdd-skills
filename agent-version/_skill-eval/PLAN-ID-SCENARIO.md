## 2. Этап К — короткая схема

### 2.1. Текст

- Основа — текст пула 1. Из него убрать всё про подробную: выбор типа, поля «Триггер / ответ / ошибки», повод про

- Из переписанного взять только безвредное: примеры, не совпадающие с фикстурами; «ни участника, который есть только
  в ненарисованной карточке». Письменную проверку поводов не брать.
- Номера параграфов заменить названиями: карточки — по заголовку `### INT-N`, таблица сервисов — «таблица затронутых
  сервисов» (раздел «Затронутые сервисы и владельцы», колонка «Сервис»); то же в вопросе аналитику и в шапке файла.

### 2.2. Новое: порядок по времени

- Новый повод «порядок»: в спеке больше одной нарисованной карточки.
- Вопрос-гипотеза: «Порядок по времени: INT-1 → INT-3 → INT-2 → INT-4. Верно?» Гипотеза собирается по тексту:
  карточка, в «Триггере» которой назван номер другой карточки, идёт после неё; остальные — в порядке номеров.
- Ответ → стрелки в названном порядке; звенья одной цепочки остаются подряд. В шапке файла: «порядок стрелок — по
  времени, со слов аналитика».
- «Не знаю» → порядок номеров карточек, в шапке «порядок карточек, не время», строка в отчёте.
- Следствие: вопрос будет при каждом запуске на спеке с двумя и более карточками.

## 3. Этап С — сценарная схема (после приёмки короткой)

### 3.1. Что рисуем

Образец формы — схема владельца «Генерация заявления по динам полям».

- Одна схема на действие пользователя: актор → первая сторона → вызовы по цепочке → ответы обратно.
- Фоновые запуски (колбэк, событие, расписание) — отдельные схемы без актора.
- На схеме: актор; полосы активности; запрос с методом и путём; ответ на каждом звене пунктиром; пометка с телом
  запроса и ответа; внутренние шаги сервиса стрелкой на себя. Ошибок, `alt`, `loop` нет.
- Файлы: `interaction_scenario_<N>.md` / `.puml`, по одному на сценарий, `<N>` — по порядку; название сценария — в
  заголовке схемы.

### 3.2. Откуда что берётся

| Элемент | Источник | Если в источнике нет |
|---|---|---|
| список сценариев | карточки, которые запускает человек (поле «Триггер») | вопрос: «сценарии: 1) …, 2) …; фоновые: …. Верно?» |
| порядок и вложенность вызовов | «Триггер» с номером другой карточки; граница-цепочка | вопрос: «сценарий 1: INT-1, внутри него INT-3, затем INT-4; после — INT-2. Верно?» |
| запрос, метод, путь | «Граница/направление», «Контракт (запрос)» | подпись без метода |
| ответ на звене | «Контракт (ответ)» | у цепочки — вопрос, на каком звене какой ответ; иначе стрелки ответа нет |
| тела запроса и ответа | поля контракта карточки | пометки нет |
| внутренние шаги сервиса | только ответ аналитика (в шаблоне спеки такого поля нет); гипотеза — из текста карточки и раздела про бэкенд, если он там есть | вопрос: «внутренних шагов у X в спеке не нашёл — назовите или рисую без них» |
| актор | «Триггер» | вопрос в составе списка сценариев |

Правило прежнее: чего нет ни в карточке, ни в ответе аналитика, на схеме нет.

### 3.3. Стенд

- Новая синтетическая фикстура: спека с двумя действиями пользователя и одним фоновым запуском, вложенным вызовом,
  цепочкой, карточкой с телами запроса и ответа; эталонные схемы руками.
- Реплики — утверждения с номерами карточек; два плеча с разным порядком и разной вложенностью.
- Якоря: число и имена файлов сценариев; актор и участники; порядок запросов = реплике; вложенность (ответ внешнего
  вызова после вложенных); ответ на каждом звене; пометки тел — подмножество полей контракта; внутренние шаги —
  ровно названные в реплике; нет стрелок вне карточек и реплики; открыт `reference/scenario.md`.
- Пробы: «спросил список сценариев и порядок»; два плеча порядка; «не знаю» по внутренним шагам; оба формата.

### 3.4. Шаги

1. Правила и скелет в `reference/scenario.md`, маршрут в `SKILL.md`.
2. Фикстура, эталоны, грейдер, `--selftest`.
3. Ревью двумя субагентами до «ОК».
4. Пилот 1 × 6 проб (≈ $2) → просмотр глазами, включая рендер обеих схем.
5. Пул 6 проб × 10 (≈ $18 при ≈ $0.3 за прогон) — запуск после «да».
6. Итог владельцу, как в этапе К.

## 5. Риски

- Вопросов становится много: формат, тип, имена, порядок, цепочка; на сценарной — ещё сценарии, вложенность,
  внутренние шаги. В один вызов помещается четыре.
- Внутренние шаги берутся только со слов аналитика: гипотезу собрать часто не из чего — вопрос получается открытым,
  а ответ нигде, кроме схемы, не сохраняется.
- Синтетика: стенд может быть зелёным, а на реальной спеке схема выйдет не та. Первая реальная проверка — в проде.
- Неполный список имён в вопросе — известный дефект, в плане не лечится, меряется.
- N=10 на пробу различает только крупные эффекты; без второго круга граничный результат останется без ответа.
- Вынос в `reference/`: если слабая модель не откроет файл, схема будет написана без скелета — ловится якорем.

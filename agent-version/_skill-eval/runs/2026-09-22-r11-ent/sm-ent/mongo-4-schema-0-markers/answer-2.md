## Разбор по правилам

**Верхняя сверка сущностей (маркер = 0, блоки есть → в общем случае добор на все блоки).**
Проверяю исключение двумя грепами по описи:
- строки сущностей `\([^)]*\)\s*$` — все 4 строки («Order… (@Schema)», «Customer… (@Schema)», «Invoice… (@Schema)», «Payment… (@Schema)») дают совпадение → 4;
- из них с маркером таблицы `\(@Entity|\(@Table|\(model\b` — 0 совпадений (везде `@Schema`, не `@Entity`/`@Table`/`model`).

Строки сущностей есть, а с маркером таблицы — ни одной ⇒ по правилу это «маркер вне таблицы (Mongo и подобные), сверки нет». Исключение сработало мехнически ровно так, как описано в правиле — верхняя проверка не назначает добор.

**ГЕЙТ (нижняя граница).** Маркер по коду для класса «сущности» = 0 ⇒ правило прямо говорит «Маркер дал ноль — сверки нет» (нижняя граница неприменима при нулевом маркере). Добора отсюда тоже нет.

**Сущности у ручек.** В обоих показанных блоках строка `сущности:` присутствует, и указанные имена (`Order`, `Customer`) есть в списке «Владеет данными» той же карточки (Order, Customer, Invoice, Payment). Расхождений, выдумок или пропущенных строк `сущности:` в данных нет — по этой выдержке добор не требуется.

Ни одно из двух правил не даёт основания для добора по имеющимся данным.

Анализирую по двум правилам.

## Маркерный гейт
Маркер по коду (`@Entity\b|^model |@Table\(`): **0**  
Число блоков в описи: **4**  
Правило: "Маркер дал ноль — сверки нет".  
Этап: **пропущена**.

## Сущности — сверка сверху

Блоков `###`: 4  
Маркеров по коду: 0  
Нарушение: 4 > 0  

Но применяется исключение. Проверяю два регулярника по строкам сущностей:
- `\([^)]*\)\s*$` — все 4 строки заканчиваются на `(@Schema)`: **совпадают**.
- `\(@Entity|\(@Table|\(model\b` — ни в одной нет `@Entity`, `@Table` или `model`: **не совпадают**.

Условие исключения выполнено: "строки сущностей есть, а с маркером таблицы ни одной — маркер вне таблицы (Mongo и подобные), сверки нет".

Этап: **пропущена**.

## Сущности у ручек

В приведённых примерах обе ручки имеют строку `сущности:`:
- `GET /api/orders` → `сущности: → Order` (Order в списке сущностей ✓)
- `GET /api/customers` → `сущности: → Customer` (Customer в списке сущностей ✓)

Имена из строк совпадают со списком сущностей из «Владеет данными». Выдумок нет.

Этап: **пропущена**.

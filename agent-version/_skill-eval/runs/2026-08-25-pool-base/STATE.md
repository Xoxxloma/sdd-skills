# Пул на реальном коде (2026-08-25): база против правила «сущности у ручек»

Два плеча по 5 прогонов, haiku, одна фикстура `SM-REAL`, один засев. Плечи отличаются **ровно
правилом**: B собрано патчем поверх того же текста, что и A, а не снимком прошлого раунда.

| Плечо | Раунд | SKILL.md | Что в тексте |
|---|---|---|---|
| A | `2026-08-25-pool-base` | 925 | база + D3 |
| B | `2026-08-25-pool-ent` | 945 | то же + строка `сущности:` у каждого блока контракта |

Полный вывод грейдера — `2026-08-25-pool-ent/GRADE-REPORT.txt`.

## Главное: одна точка на редакцию не мерила ничего

**Плотность на одном и том же тексте гуляет от 92 до 309 строк-фактов — в 3.4 раза.**

| A (база) | scan-1 | scan-2 | scan-3 | scan-4 | scan-5 |
|---|---|---|---|---|---|
| эндпоинты (ключ 96) | 84 | **96** | 3 | 95 | 95 |
| строк-фактов | 129 | **309** | 0 | 253 | **92** |
| анкеров (из 14) | 9 | 6 | 0 | 11 | 9 |

Все четыре числа прошлых одиночных сравнений — 151, 95, 74, 168 — лежат **внутри** этого разброса.
Вывод «правило стоит трети фактов», сделанный по одному прогону на редакцию, не имел под собой
ничего: три правки были сделаны вслепую по шуму.

## Что правило действительно даёт

| Плечо | сущность названа |
|---|---|
| A, все 5 прогонов | **0 %** (0/84, 0/96, 0/3, 0/95, 0/95) |
| B, все прогоны с карточкой | **80–100 %** (95/95, 93/96, 73/81, 77/96) |

Пересечения нет. Это единственное число во всём замере, которое ведёт себя как сигнал, а не как
шум: без отдельной строки сущность не пишет никто, с ней — пишут почти всегда.

## И чем оно платит: новый режим отказа

`pool-ent/scan-2` — **96 блоков контракта и НОЛЬ строк-фактов**. Инвентарь полон, форма безупречна,
содержания нет вообще:

```
### `GET /health`
Проверка живости.

### `POST /auth/register`
Регистрация нового пользователя.
сущности: → User
```

| Блоков с пустым телом | A | B |
|---|---|---|
| прогон 1 | 6 из 84 | 7 из 95 |
| прогон 2 | 2 из 96 | **96 из 96** |
| прогон 3 | — | 7 из 81 |
| прогон 5 | 28 из 95 | 35 из 96 |

В базе худший исход — 29 % пустых блоков. В плече с правилом — 100 % в одном прогоне из четырёх.
Такого исхода база не даёт ни разу: без строки `сущности:` блоку нечем выглядеть заполненным.

**Гейт на запись это не ловит и не может.** Условие 3 сверяет блоки с непустым телом против
«ключей с фактами в описи», а опись пишет тот же субагент: недобрав факты, он недоберёт их и в
описи, и числа сойдутся. Нужна проверка, которую ведущий считает САМ по карточке, без описи.

## Побочные находки пула

**Прогон писал в чужой репозиторий.** `pool-ent/scan-2` создал
`repairy-api/service-map/services/repairy-api.md` — то есть карточку внутри папки сканируемого
сервиса. Правило 2 скилла («ты только читаешь чужие репозитории») нарушено. Караул раннера это
поймал; ни одна синтетическая фикстура поймать не могла — писать в них было незачем.

**Скилл нестабилен на реальном коде сам по себе, вне зависимости от правки.** По десяти прогонам:

| Класс | Ключ | Разброс по 10 прогонам |
|---|---|---|
| эндпоинты | 96 | 0, 3, 81, 84, 95, 95, 95, 96, 96, 96 |
| экраны | 24 | 0, 19, 22, 22, 23, 23, 23, 23, 23, 24 |
| топики | 0 | 0 восемь раз, **7 и 2 выдуманных** — дважды |
| роли | 5 | 3 — пять раз, 5 — пять раз |

Два прогона из десяти выродились совсем (3 и 0 блоков контракта).

## Что из этого следует

1. **Правило про сущности оставлять надо** — эффект доказан пулом, пересечения нет.
2. **Вместе с ним нужен внешний гейт на пустоту:** доля блоков с непустым телом, посчитанная
   ведущим по карточке, а не по описи. На базе она 71–100 %, у отказного прогона 0 % — порог
   разделяет их с большим запасом.
3. **Разброс инвентаря (0–96 при ключе 96) — отдельная работа** и он старше этой правки.

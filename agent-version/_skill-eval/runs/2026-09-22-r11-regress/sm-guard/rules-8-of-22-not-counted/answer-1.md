## Гард — расчёт по классам

**Контракт** (единственный считаемый класс из представленных):
- было: 30, исчезло: 0, появилось: 0
- Все 30 ключей прежней карточки присутствуют в черновике без изменений.
- Порог: исчезло_c ≥ 3? Нет (0 < 3). Опустело_c ≥ 3? Не опустел ни один блок (это список ключей, а не блоки контракта, и все ключи целы). Порог не сработал.

**Бизнес-правила** — не считается вовсе по прямому исключению в правиле гарда («их заголовки меняются при приведении формы к шаблону — это переформатирование, и оно уже гейтится против описи на Шаге 3»). Видно и по факту: 8 исчезнувших ключей — это `Order — статус`, `Customer — этап`, `Invoice — вид`, `Payment — статус`, `Shipment — этап`, `Carrier — вид`, `Warehouse — статус`, `Slot — этап` (первые 8 из 22), а оставшиеся 14 в черновике — те же самые сущности/суффиксы прежней карточки, но с добавленным префиксом `(по шаблону)`, то есть той же формой, приведённой к шаблону. Даже если бы это считалось: 8 исчезло из 22 (3·8=24 > 22) дало бы ложный `_pending` — но по правилу гарда этот класс исключён из подсчёта явно, и его в маршрут не пускаю.

Остальные классы (сущности, задачи, топики, экраны, потребляемые API, роли, зависит от) — данных нет, множества пустые с обеих сторон, порог не применим.

Ни у одного считаемого класса порог `(исчезло_c ≥ 3 и 3·исчезло_c > было_c)` или `(опустело_c ≥ 3 и 3·опустело_c > было_c)` не сработал.

1. **Ключи** — три `###`: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений...»`. Все три формы верны, посторонних заголовков нет. Сошлось.

2. **Состав** — состояний в описи 1 (Shipment) → 1 блок объекта (Shipment) в карточке, справочники (packageType, Attachment.kind) блока не имеют — верно. Сообщений: опись 1 строка, карточка 1 блок `сообщение` + 1 `публикует` в «Событиях» — совпадает. Ограничений: опись 1 строка → 1 блок. Сошлось.

3. **Значения** — форма `- поле: значение` (не таблица). Блок Shipton: 3 строки на 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), каждая строка — один токен-значение в бэктиках, без сдвоенных токенов и без пропущенного «не определено». Сошлось.

4. **Код** — вне бэктиков только русские слова, в бэктиках — только значения перечисления и топик `shipment.delivered` (одна точка, под лимит). Технических токенов (camelCase, HTTP-глаголы, пути) в секции нет. Сошлось.

5. **Переключатель** — в блоке `ограничение «приём отправлений партнёра отключён»` не назван ни один переключатель: нет имени сервиса из манифеста (`shipping`/`partner-registry`/`dispatch-web`) и нет роли из «Роли и доступ» (`DISPATCHER`/`COURIER`) в качестве того, кто условие включает/выключает — упомянут только диспетчер как наблюдатель отказа, не как переключатель. Расхождение.

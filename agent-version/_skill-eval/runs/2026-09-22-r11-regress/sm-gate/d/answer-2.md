**1. Ключи.** Три `###` в «Бизнес-правилах»: `` `Shipment` `` , «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три в верном формате (сущность в бэктиках / «сообщение «` / «ограничение «`). Сошлось.

**2. Состав.** Опись: состояние × 1 (Shipment), сообщение × 1, ограничение × 1 → в карточке ровно по одному блоку каждого вида; событий-`публикует` тоже 1, не меньше строки `сообщение:`. Attachment (только справочник, без состояния) блока не имеет — верно. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Блок `Shipment` в бизнес-правилах: 3 строки (`NEW`/`ASSIGNED`/`DELIVERED`) на 3 значения `состояние:` — по значению, без дублей и без «не определено» вместо перехода. Сошлось.

**4. Код.** По тексту секции «Бизнес-правила» вне бэктиков не нашёл ни путей, ни HTTP-глаголов, ни camelCase, ни дот-нотации конфига; в бэктиках — только значения перечисления (`NEW` и т.п.) и имя топика `shipment.delivered`. Сошлось.

**5. Переключатель.** Блок ограничения «приём отправлений партнёра отключён» содержит только «кого касается» (диспетчер видит причину отказа), но не называет, **кто включает/выключает условие** — строки `переключатель: <имя>` нет вовсе, ни в карточке, ни в исходной строке описи. Ни в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`), ни в «Роли и доступ» (`DISPATCHER`, `COURIER`) переключатель не назван. Не сошлось.

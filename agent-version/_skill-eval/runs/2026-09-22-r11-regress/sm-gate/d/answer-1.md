**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены, блок объекта один на сущность (Shipment). Совпадает.

**2. Состав.** Строка `состояние:` в описи одна (Shipment) → блоков объектов 1, в карточке 1. `сообщение:` в описи 1, блоков `публикует` в «Событиях» 1, в карточке сообщений 1 — не меньше обоих. `ограничение:` в описи 1, в карточке 1. Справочники (`Shipment.packageType`, `Attachment.kind`) блока не получают по правилу — и не получили. Совпадает.

**3. Значения.** Блок `Shipment` — списком `- токен (...) — ...`, не таблица. В строке `состояние:` 3 значения (NEW|ASSIGNED|DELIVERED) — в блоке 3 строки, токены `NEW`, `ASSIGNED`, `DELIVERED` — по одному на значение, повторов правила на разных значениях нет. Совпадает.

**4. Код.** Вне бэктиков вся секция — обычный текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей. В бэктиках только `NEW`/`ASSIGNED`/`DELIVERED` (значения перечисления) и `shipment.delivered` (имя топика, один дот — не попадает под `{2,}`) — всё допустимо. Совпадает.

**5. Переключатель.** Блок `ограничение «приём отправлений партнёра отключён»` гласит: «пока условие действует, новые отправления не принимаются, диспетчер видит причину отказа» — это не переключатель (диспетчер здесь просто *видит* отказ, а не включает/выключает условие). Ни имени из манифеста (`shipping`, `partner-registry`, `dispatch-web`), ни роли из «Роли и доступ» (`DISPATCHER`, `COURIER`) в качестве переключателя не названо. Опись тоже не содержит `переключатель:` в строке ограничения — расхождение подтверждается на обоих файлах. Не совпадает.

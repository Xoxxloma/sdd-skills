**1. Ключи.** Блоков в «Бизнес-правилах»: `### Отправление (`Shipment`)`, `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»`. Первый заголовок не начинается с имени сущности в бэктиках — вперёд поставлена подпись «Отправление», `Shipment` в бэктиках спрятан в скобки после неё. Это ровно случай «подпись впереди ключа» из списка — не сошлось.

**2. Состав.** Строка `состояние:` в описи — одна (Shipment), блоков-сущностей в карточке — один (Shipment) — количество сошлось. `сообщение:` в описи 1, `публикует` в «Событиях» 1, блоков сообщения в карточке 1 — сошлось. `ограничение:` в описи 1, блоков 1 — сошлось. Справочники (Shipment.packageType, Attachment.kind) блоков не имеют — по правилу «справочник блока не имеет», это верно, не расхождение.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица — сошлось. В блоке `Shipment` три строки (NEW/ASSIGNED/DELIVERED) на три значения строки `состояние:` — сошлось, заполнителей нет, каждая строка — свой токен состояния в бэктиках.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» — только связный русский текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё из разрешённого списка. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` управляющим условием; это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

Четыре числа из пяти в порядке, но заголовок сущности нарушает форму ключа — это добор, а не мелочь: гейт по этому пункту не различает степень нарушения.

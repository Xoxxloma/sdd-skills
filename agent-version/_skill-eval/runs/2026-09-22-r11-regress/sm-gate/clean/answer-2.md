**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верны, блок один на сущность. Сошлось.

**2. Состав.** 1 блок-сущность = 1 строка `состояние:` (Shipment). 1 сообщение = 1 строка `сообщение:` = 1 `публикует shipment.delivered` в «Событиях». 1 ограничение = 1 строка `ограничение:`. Справочники (2 шт.: `packageType`, `Attachment.kind`) блоков не имеют — верно по правилу. Сошлось.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица. Блок `Shipment` — 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), токен в начале каждой строки — значение перечисления. Дублей и «не определено»-заполнителей нет. Сошлось.

**4. Код.** В секции «Бизнес-правила» вне бэктиков — только кириллица, ни одного совпадения по четырём грепам. В бэктиках только: значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), имя топика (`shipment.delivered`, две точки не набирается — не матчит) и имя сервиса из манифеста (`partner-registry`). Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

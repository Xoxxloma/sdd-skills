**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, блок объекта один. Сошлось.

**2. Состав.** Опись: `состояние:` — 1 строка (Shipment) → в карточке 1 блок объекта. `сообщение:` — 1 строка и в «Событиях» `публикует` — 1 → в карточке 1 блок сообщения. `ограничение:` — 1 строка → 1 блок. Справочники (`packageType`, `Attachment.kind`) блоков не получили — верно, справочник блока не имеет. Сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица; у каждого перечисления значения через `|`. В блоке `Shipment` строк 5 — по числу значений `состояние:` (5). Но: строки `CANCELLED` и `LOST` дают **один и тот же текст правила** («значение enum, отдельного кода перехода нет; проставляется напрямую при смене статуса») на двух разных значениях — это ровно заполнитель по гейту, а форма для значения без перехода в коде — `не определено`, а не повторённая фраза. Расхождение.

**4. Код.** Вне бэктиков — нет пути с ` /[a-z]`, нет HTTP-глагола, нет camelCase, нет точечного ключа конфига. В бэктиках — только значения enum (`NEW`…), топик `shipment.delivered`, имя сервиса `partner-registry` из манифеста. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

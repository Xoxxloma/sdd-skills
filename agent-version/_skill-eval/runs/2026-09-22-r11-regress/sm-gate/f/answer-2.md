**1. Ключи.** Заголовки блоков: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы (сущность в бэктиках / «сообщение «» / «ограничение «») соблюдены. Сошлось.

**2. Состав.** Опись: состояний 1 (Shipment) → блоков-сущностей 1 (есть `Shipment`); сообщений 1 → блоков сообщений 1, публикует-блоков в «Событиях» 1 (не меньше); ограничений 1 → блоков ограничений 1. Справочники (`packageType`, `Attachment.kind`) блока не имеют по правилу — и в карточке его нет. Сошлось.

**3. Значения.** У `status` 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`) — в блоке `Shipment` ровно 3 строки на них, форма «Владеет данными» с `|` соблюдена. Но в блоке `Shipment` есть 4-я строка — «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: два токена в одной строке через `/` — это справочник, записанный состоянием, что запрещено прямо. Не сошлось.

**4. Код.** Вне бэктиков — только русский текст, без пути, HTTP-глагола, camelCase или составного ключа. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`, `BOX`, `PALLET`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — убрать из блока `` `Shipment` `` строку «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: `packageType` — справочник, правило от его значений не зависит, и он не получает строки в блоке «Бизнес-правила» (два значения через `/` в одной строке недопустимы). Правку внести и в черновик, и в опись, если состав ключей меняется.

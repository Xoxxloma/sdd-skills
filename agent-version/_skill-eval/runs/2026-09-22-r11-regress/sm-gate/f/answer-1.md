**1. Ключи** — заголовки в «Бизнес-правилах»: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один на сущность. Сошлось.

**2. Состав** — опись: состояний 1 → блоков объектов 1 (`Shipment`), карточка даёт 1. Сообщений: опись 1, «публикует» в Событиях 1, карточка 1 блок. Ограничений: опись 1, карточка 1 блок. Сошлось.

**3. Значения** — форма «Владеет данными» везде `- поле: тип`, не таблица — ок. У `Shipment` в состоянии 3 значения (NEW/ASSIGNED/DELIVERED), в блоке 3 строки с этими токенами — по числу сошлось. Но четвёртая строка блока — «тип упаковки (`BOX` / `PALLET`) — задаётся при создании» — это `Shipment.packageType`, который в описи назван **справочником**, а не состоянием, и записан строкой с двумя токенами через `/`. По правилу гейта это ровно случай «справочник, записанный состоянием» — добор.

**4. Код** — вне бэктиков в секции нет ни путей, ни HTTP-глаголов, ни camelCase, ни dotted-конфигов; в бэктиках только значения перечислений (`NEW`, `ASSIGNED`, `DELIVERED`, `BOX`, `PALLET`), топик `shipment.delivered` и имя сервиса `partner-registry` — всё допустимо. Сошлось.

**5. Переключатель** — в блоке ограничения назван `partner-registry`, это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи** — три заголовка секции: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»». Все три в разрешённой форме, один блок на сущность. Сошлось.

**2. Состав** — сущностей в строке `состояние:` — 1 (Shipment) = 1 блок сущности в карточке. Строк `сообщение:` — 1 = 1 блок сообщения = 1 `публикует` в «Событиях». Строк `ограничение:` — 1 = 1 блок. `Attachment` (только справочник `kind`, без состояния) блока не получил — верно по правилу «справочник блока не имеет». Сошлось.

**3. Значения** — форма `- поле: тип` (не таблица) выдержана. Но в блоке `Shipment` четвёртая строка «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании» — это поле `packageType` (справочник из описи), а не `status`; токены `BOX`/`PALLET` не входят в значения состояния (NEW/ASSIGNED/DELIVERED), и это два токена в одной строке через запятую. Двойное нарушение: «любое другое имя поля — строка на поле, добор» и «два токена в одной строке — справочник, записанный состоянием: добор». Не сошлось.

Код** — пять грепов по тексту секции: вне бэктиков совпадений нет; в бэктиках только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`/`BOX`/`PALLET`), имя топика `shipment.delivered`, имя сервиса `partner-registry` из манифеста — всё в разрешённом наборе; бэктиков в заголовках сообщения/ограничения нет. Сошлось.

**5. Переключатель** — блок ограничения называет `partner-registry`; это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи.** Три `###` в «Бизнес-правилах»: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верны. Сошлось.

**2. Состав.** Блоков объектов 1 = строк `состояние:` в описи 1 (Shipment). Сообщений 1 = строк `сообщение:` 1 = блоков `публикует` в «Событиях» 1. Ограничений 1 = строк `ограничение:` 1. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Верно. В блоке `Shipment` на 3 значения состояния (NEW/ASSIGNED/DELIVERED) первые три строки — по одной на значение. Но есть четвёртая строка: «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании» — два токена через запятую в одной строке. Это `справочник: Shipment.packageType` из описи, записанный как состояние. Не сошлось.

**4. Код.** Вне бэктиков — сплошная русская проза, ни ` /[a-z]`, ни HTTP-глаголов, ни camelCase, ни точечных ключей. В бэктиках — только значения перечислений (`NEW`/`ASSIGNED`/`DELIVERED`/`BOX`/`PALLET`), топик `shipment.delivered`, имя сервиса `partner-registry` — всё из разрешённого списка. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (shipping, partner-registry, dispatch-web). Сошлось.

ГЕЙТ: ДОБОР — в блоке `` `Shipment` `` секции «Бизнес-правила» убрать строку «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании»: это справочник `packageType` из описи, а не состояние, и своего блока в «Бизнес-правилах» справочники не получают.

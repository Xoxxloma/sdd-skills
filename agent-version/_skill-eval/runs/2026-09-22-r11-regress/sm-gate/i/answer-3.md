**1. Ключи.** Заголовки секции: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены (сущность в бэктиках / «сообщение «» / «ограничение «»). Блок один на сущность (Shipment). Совпало.

**2. Состав.** Опись: `состояние:` — 1 строка (Shipment), `сообщение:` — 1, `ограничение:` — 1, `публикует` в «Событиях» — 1 (`shipment.delivered`). Карточка: 1 блок-сущность, 1 сообщение, 1 ограничение. Справочники (`packageType`, `Attachment.kind`) блоков не получили — верно, справочник блока не имеет. Совпало.

**3. Значения.** Здесь расхождение, и оно приоритетное: блок «Владеет данными» → `Shipment` оформлен ТАБЛИЦЕЙ (`| Поле | Тип | Описание |`), а не строками `- поле: тип`. По правилу это добор раньше всего остального в этом пункте — дальше подсчёт строк/значений для Shipment можно не продолжать, форма уже забракована. (Для сравнения: `Attachment` оформлен верно — списком с перечислением через `|`.)

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет пути, HTTP-глагола, camelCase-имени поля/метода или точечного ключа из трёх сегментов. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё разрешённое. Совпало.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Совпало.

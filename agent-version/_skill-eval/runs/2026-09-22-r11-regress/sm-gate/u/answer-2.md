**1. Ключи.** Три `###`: `` `Shipment` `` — отправление; `сообщение «груз доставлен»`; `ограничение «приём отправлений партнёра отключён»`. Все три формы разрешённые (сущность в бэктиках / «сообщение «» / «ограничение «»). Блок объекта один — на единственную сущность `Shipment`. Сошлось.

**2. Состав.** Опись: состояний 1, справочников 2, сообщений 1, ограничений 1. В карточке: блоков-объектов 1 (Shipment, под строку `состояние:`), справочники (`packageType`, `Attachment.kind`) блока не получили — верно, справочник блока не имеет; сообщений 1 (= строке `сообщение:` и = блоку `публикует shipment.delivered` в «Событиях»); ограничений 1. Сошлось.

**3. Значения.** Блок `Shipment`: строка `состояние:` даёт 3 значения (NEW|ASSIGNED|DELIVERED), в блоке ровно 3 строки, каждая с одним токеном-значением в бэктиках (`NEW`, `ASSIGNED`, `DELIVERED`), два токена в одной строке не встречаются. «Владеет данными» — форма `- поле: тип`, не таблица; строка `status`+`packageType`+`weightKg` слита в одну — по правилу это не расхождение, просто фиксирую для отчёта (3 поля в одной строке). Сошлось.

**4. Код.** В тексте секции «Бизнес-правила» вне бэктиков нет ` /[a-z]`, `GET|POST|...`, camelCase, точечных путей ≥2 точек. В бэктиках встречаются только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё разрешённое. Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи.** Три `###` в «Бизнес-правилах»: `` `Shipment` `` (сущность в бэктиках), «сообщение «...»», «ограничение «...»» — все три начинаются правильно. Сошлось.

**2. Состав.** В описи 1 сущность со `состояние:` (Shipment), 1 `сообщение:`, 1 `ограничение:` — Attachment есть только `справочник:`, блока не получает. В карточке ровно те же три блока: `Shipment`, сообщение, ограничение; блок `публикует shipment.delivered` в «Событиях» тоже один. Сошлось.

**3. Значения.** Блок `Shipment` — форма `- поле: тип` (список, не таблица), в блоке ровно 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), каждая строка — один токен из перечня, без «не определено»-заполнителей и без сдвоенных токенов. Сошлось.

**4. Код.** Заголовок сообщения — `### сообщение «`shipment.delivered`»` — содержит бэктики вокруг имени топика. Правило прямо запрещает любой бэктик в заголовке сообщения независимо от содержимого. Не сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`), в теле, не в заголовке. Сошлось.

ГЕЙТ: ДОБОР — заголовок `### сообщение «`shipment.delivered`»` переписать без бэктиков вокруг имени топика (например `### сообщение «shipment.delivered»`); это только заголовок, тело блока и остальные секции не трогать. По правилу пункта 4 — второй добор, если понадобится, только по этим строкам.

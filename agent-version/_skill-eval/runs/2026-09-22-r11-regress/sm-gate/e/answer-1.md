**1. Ключи.** Опись даёт три класса для «Бизнес-правил»: `состояние: Shipment...`, `сообщение: shipment.delivered`, `ограничение: ...`. Заголовки карточки: `` `Shipment` — отправление ``, `сообщение «...»`, `ограничение «...»` — все три начинаются как требуется. Сошлось.

**2. Состав.** 1 строка `состояние:` → 1 блок сущности (`Shipment`); справочники (`packageType`, `Attachment.kind`) блока не имеют — верно, их и нет. 1 строка `сообщение:` = 1 блок `публикует` в «Событиях» = 1 блок сообщения. 1 строка `ограничение:` = 1 блок ограничения. Сошлось.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица. Блок `Shipment` в «Бизнес-правилах» — 3 строки на 3 значения состояния (`NEW`, `ASSIGNED`, `DELIVERED`), каждая строка — один токен из перечня, лишних объединений через `/`, `,` нет. Сошлось.

**4. Код.** Тело блоков — без сырых токенов вне бэктиков. НО: заголовок `### сообщение «`shipment.delivered`»` содержит бэктики вокруг имени топика — правило прямо требует «ни одного бэктика в заголовке сообщения». Расхождение.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

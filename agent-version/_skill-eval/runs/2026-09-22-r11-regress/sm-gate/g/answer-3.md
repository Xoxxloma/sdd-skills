**1. Ключи.** Три `###`: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы соблюдены, блок один на сущность (Attachment без состояния блока не получает — верно). Сошлось.

**2. Состав.** `состояние:` в описи — 1 (Shipment), блоков-объектов в карточке — 1. `сообщение:` в описи — 1, `публикует` в «Событиях» — 1, блоков сообщений в карточке — 1. `ограничение:` — 1 строка, 1 блок. Сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица — ок. В блоке `Shipment` состояние `status` имеет 3 значения (NEW|ASSIGNED|DELIVERED), в блоке 4 строки, но строка «перевешено (`ASSIGNED`, `weightKg` изменён)» — токен `ASSIGNED` сопровождён именем поля `weightKg` в скобках. Это не дата-исключение (единственно законное отклонение) — это имя поля, что по правилу «любое другое имя поля — строка на поле, добор». Не сошлось.

**4. Код.** Вне бэктиков нарушений нет. В бэктиках той же строки — `` `weightKg` `` — это имя поля, а в бэктиках допустимы только значение перечисления, имя вида/топика, имя сервиса из манифеста и дата-исключение. Имя поля в бэктиках в этой секции не допускается нигде. Не сошлось (та же строка).

**5. Переключатель.** Блок ограничения называет `partner-registry`, это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — строка `перевешено (`ASSIGNED`, `weightKg` изменён) — при повторном взвешивании на складе, если расхождение больше килограмма` в блоке `### \`Shipment\`` секции «Бизнес-правила»: токен привязан к имени поля `weightKg` (в бэктиках), а не к одному из значений `NEW`/`ASSIGNED`/`DELIVERED` или к дате-исключению — переписать без имени поля, с допустимым токеном, либо убрать строку, если правило не выражается через значение состояния.

## Гейт «Бизнес-правила» — сервис `shipping`

**1. Ключи.** Три заголовка раздела: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «...»» — все три в допустимой форме; блок один на сущность. Сошлось.

**2. Состав.** Опись: состояний 1, сообщений 1, ограничений 1 (+ 1 `публикует` в «Событиях»). Карточка: блоков-сущностей 1 (`Shipment`), сообщений 1, ограничений 1. Сошлось.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица — ок. Блок `Shipment` на 3 значения состояния даёт 4 строки: `NEW`, `ASSIGNED` («назначено»), `ASSIGNED` («перевешено»), `DELIVERED`. Во второй строке с `ASSIGNED` в скобках рядом с токеном стоит `weightKg` — это имя поля, а не дата, единственное законное исключение. Не сошлось.

**4. Код.** Вне бэктиков по разделу совпадений с четырьмя грепами нет. В бэктиках строка «перевешено» содержит `` `weightKg` `` — не значение перечисления, не имя вида/топика, не имя сервиса из манифеста, не дата. Не сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — переписать строку блока `Shipment` в «Бизнес-правилах»: «перевешено (`ASSIGNED`, `weightKg` изменён) — при повторном взвешивании на складе, если расхождение больше килограмма». Имя поля `weightKg` в скобках — недопустимо (допустима только дата-исключение). Если в коде для этого случая нет отдельного значения состояния или даты, а есть только изменение поля веса — переписать строку словами без имени поля, либо, если такого перехода по коду нет вовсе, заменить на `не определено`. Опись при этом не трогать — число значений состояния (3) и состав ключей не меняются.

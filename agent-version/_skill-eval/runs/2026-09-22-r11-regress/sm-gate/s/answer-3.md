**1. Ключи.** Все три `###` начинаются как положено: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»`. Сошлось.

**2. Состав.** Блоков-сущностей 1 (Shipment) = строк `состояние:` в описи (1). Сообщений 1 = строк `сообщение:` (1) = блокам `публикует` в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Справочники (`packageType`, `Attachment.kind`) блока не получили — верно, блоков не имеют. Сошлось.

**3. Значения.** Форма «Владеет данными» — списком `- поле: тип`, не таблица. Но у `Shipment.status` значения не выписаны через `|`: `` - `status`: `ShipmentStatus` — перечисление `` — тип без перечня значений. У `packageType` и `Attachment.kind` значения через `|` есть. Блок «Бизнес-правил» `Shipment` содержит 3 строки на 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), заполнителя нет, токены — реальные значения. Не сошлось: `status` — тип без значений.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей. В бэктиках — только `NEW`/`ASSIGNED`/`DELIVERED` (значения), `shipment.delivered` (топик), `partner-registry` (имя из манифеста). Заголовки сообщения/ограничения без бэктиков. Сошлось.

**5. Переключатель.** «условием управляет `partner-registry`» — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

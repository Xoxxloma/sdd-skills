**1. Ключи.** Три присутствующих заголовка — `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все начинаются бэктик-именем сущности либо словами «сообщение «»/«ограничение «», без посторонних подписей и без `Сущность.поле`. По видимому — сошлось.

**2. Состав.** Опись: состояние есть у 2 сущностей (Shipment, Courier); сообщений 1; ограничений 1. В карточке блоков-сущностей в «Бизнес-правилах» только 1 (`Shipment`) — блок `Courier` отсутствует, хотя опись даёт `состояние: Courier.status ACTIVE | BLOCKED`. Сообщение (1=1) и ограничение (1=1) сошлись. **Не сошлось: сущностей-блоков 1 вместо 2.**

**3. Значения.** Для `Shipment` — 3 строки на 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), форма `- токен (…) — правило`, не таблица, без сдвоенных токенов через `/`,`,`,`|`. Для `Courier` проверить нечего — блока нет вовсе, то есть 0 строк при 2 значениях состояния — тоже расхождение, производное от п.2.

**4. Код.** По тексту секции «Бизнес-правила» четыре грепа не дают совпадений вне бэктиков (нет путей, HTTP-глаголов, camelCase, точечных ключей); в бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

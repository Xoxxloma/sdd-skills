Гейт «Бизнес-правила» по сервису `shipping`.

**(1) Блоков `###`:** ожидается — сущности со строкой `состояние:` в описи: `Shipment` (2 строки: status, packageType) и `Attachment` (1 строка: kind) = 2 сущности, + 1 строка `сообщение:` + 0 строк `ограничение:` = **3 блока**. В карточке — только `Shipment` и «сообщение «груз доставлен»» = **2 блока**. Блок `Attachment` отсутствует. **Не сошлось.**

**(2) Строк в блоке объекта ≥ значений в `состояние:` по сущности:** для `Shipment` в описи 3+2=5 значений (status: NEW/ASSIGNED/DELIVERED, packageType: BOX/PALLET), в блоке карточки — 3 строки (только про status, про packageType нет ни одной). Для `Attachment` в описи 2 значения (PHOTO/PDF), в карточке блока нет вовсе — 0 строк. **Не сошлось по обеим сущностям.**

**(3) Токены в бэктиках блоков объектов — из «Владеет данными»:** в блоке `Shipment` токены `NEW`, `ASSIGNED`, `DELIVERED` — все стоят справа от `:` в `Shipment.status`. Выдуманных нет. **Сошлось** (но это не компенсирует пункты 1–2).

**(4) Блоков сообщений ≥ блоков `публикует` (1) и ≥ строк `сообщение:` в описи (1):** в карточке 1 блок сообщения. **Сошлось.**

**(5) Блоков ограничений = строк `ограничение:` (0):** в карточке блоков ограничений 0, `true`/`false` нигде не встречается. **Сошлось.**

Как искать:
1. Дерево целиком не листай — ни `Glob **/*`, ни `Glob <папка>/**`: на большой репе это сотни
   килобайт. Структуру смотри по уровням, `Glob` с одной звёздочкой (`*`, `src/*`, `src/main/*`),
   потом ищи `Grep` типовые пометки (`output_mode="files_with_matches"` или `"count"`) — и не в одной
   папке. Пометки контракта ищи по каждому виду отдельно — HTTP-ручки, операции GraphQL, методы
   gRPC, — даже если первый вид уже дал много: в одной репе бывает два стиля сразу, и назвав первый
   попавшийся, ты потеряешь второй.
2. На каждую найденную пометку открой один файл — не больше одного на пометку и не больше десяти за
   всю разведку — и убедись, что она стоит на самом ключе — методе ручки, классе-сущности, — а не на
   классе, который их группирует. В этом же файле посмотри все методы-ключи: часть помечена иначе —
   у класса ещё одна строка. У аннотации-ключа бывает две формы: короткая — своя на запрос, на
   мутацию — и общая, одна аннотация с параметром типа. Общая форма — тоже ключ, но в регэкспе
   обязан стоять корневой тип (`Query`, `Mutation`, `Subscription`): без него она поймает и
   резолверы полей.
3. Задачи и топики помечают кто как: ищи слова `cron`, `schedule`, `interval`, `listener`,
   `consumer`, `subscribe`, `topic` и смотри, что стоит на самом ключе.

Правила маркера:
- одно совпадение — один ключ. Пометка класса-контейнера (контроллер, резолвер, компонент) — не
  маркер: на нём пять ручек, а совпадение одно;
- маркер узкий: аннотация запроса ORM — не контракт; резолвер поля не корневого типа — не операция;
  вызов, которым пользуется и HTTP-клиент или словарь, — не ключ; вызов, который сам регистрирует
  ключ (ручку на роутере, задачу по таймеру), — ключ: одно совпадение — одна ручка или задача;
- на одном объявлении две пометки (класс-сущность с аннотацией таблицы рядом) — бери одну;
- ключ, у которого в коде пометки нет (топики только в конфиге, обработчики без аннотаций), —
  строка `ориентир` по тому, что пометить можно, или ничего. Топик — `ключ`, только если пометка с
  именем топика стоит на каждом топике; обработчик, который читает несколько топиков или берёт
  их имена из конфига, — `ориентир`;
- `<glob>` — только расширение: `*.java`, `*.ts`, `*.prisma`, `*.proto`. Ни папок, ни части имени:
  `routes/*.js` и `prisma/schema.prisma` Grep не находит и считает ноль, а `*Controller.java`
  теряет ключи из файлов с другим именем. Узким должен быть регэксп, а не маска;
- в строке — регэксп, а не описание: пометку словами не опишешь — строки нет.

Примеры формы — НЕ список: у сервиса может быть стек, которого здесь нет, тогда пометку находишь сам.
контракт :: @(Get|Post|Put|Patch|Delete)Mapping\( :: *.java :: ключ
контракт :: @(Get|Post|Put|Patch|Delete)\( :: *.ts :: ключ
контракт :: ^\s*rpc\s :: *.proto :: ключ
сущности :: @Entity\b :: *.java :: ключ
сущности :: ^model\s :: *.prisma :: ключ
задачи :: @Scheduled\( :: *.java :: ключ
топики :: @KafkaListener\b :: *.java :: ключ
топики :: \.subscribe\( :: *.ts :: ориентир

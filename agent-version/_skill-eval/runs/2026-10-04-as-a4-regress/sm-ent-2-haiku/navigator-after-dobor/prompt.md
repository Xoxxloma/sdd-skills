### Из Шага 4

**Второе — маркерный гейт (ГЕЙТ): опись против кода, класс за классом, только по строкам разведчика с пометкой `ключ`.** Число ключей класса в
описи против суммы маркеров `ключ` этого класса с Шага 3.1. Опись меньше **половины** маркеров — субагент
не дочитал: добор с перечнем «класс X: по коду не меньше N, в описи M — найди недостающие, начни с
файлов, где маркер встречается». Маркер дал ноль — сверки нет (это нижняя граница; верхняя сверка
сущностей — абзацем ниже). Это единственная проверка, которая
видит недочитанный модуль **на первом скане**: все остальные сверяют субагента с его же описью, и
недочитанный модуль отсутствует в обеих.

**Детектор узкого маркера (не гейт).** Ключей класса в описи больше чем **вдвое** против его маркеров
`ключ` — значит, разведчик назвал не все пометки класса, и нижняя граница ничего не сторожит. Добора
это не требует: опись не меньше маркеров, гейт пройден. В отчёт строкой «маркер видит N из M по
описи — внешней сверки по классу X нет», числами.

**Сущности — сверка и сверху (проверка, не гейт).** Блоков `###` в «Владеет данными» не больше
суммы маркеров `ключ` класса `сущности` с Шага 3.1. Больше — субагент записал сущностями классы без маркера
хранения: добор с перечнем «`X`, `Y` — маркера хранения в коде нет: убери из «Владеет данными»,
поля — строками в блоки ручек; строку `сущности:` каждой затронутой ручки перепиши на
`→ не сущность, агрегат по …` или `→ не сущность, ответ <сервис>`». Маркер сущностей у разведчика
есть, а греп дал ноль при блоках в «Владеет данными» — добор на все блоки. Маркера сущностей
разведчик не назвал — сверки сверху нет, строка в отчёт.
Не помог добор — карточка пишется, в отчёт строкой «Владеет данными: N блоков без маркера
хранения»; прежняя карточка из-за этого не остаётся.

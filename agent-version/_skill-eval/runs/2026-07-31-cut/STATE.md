## Что здесь важно помнить

**Плотность карточки — главный результат этих раундов, и он не гейтится.** Замер на живом дереве
из трёх сервисов, N=10 на версию: 3.0 даёт 5.6 фактов из 11, текущая — 7.4. Порог «≥9 из 11»
3.0 не берёт ни разу, текущая берёт 4 раза из 10. Причина потолка архитектурная: проверка
«Полнота семантики» сверяет карточку с описью, которую составил тот же агент, — самореференция.
Разорвать её может только источник, которым агент не управляет: прежняя карточка (работает лишь на
рескане), человек (сделано — строка отчёта в Шаге 6) или второй независимый проход (отвергнут по
цене окна). Поэтому плотность — то, что скилл **сообщает**, а не гарантирует.

**Что НЕ сработало и откачено:** требование писать цепочку обхода (`контроллер → DTO → сервис →
репозиторий`) дало 4/10 → 3/10. Гипотеза «не доходит до файла» опровергнута: цепочки пишут, факты
теряют те же самые.

Прорежено по правилу репозитория: артефакты прогонов не хранятся, хранятся грейдеры, промпты и
состояние. Грейдеры этих проб — `_skill-eval/grade-sm38.mjs`, `grade-sp.mjs`, `grade-stages.mjs`,
`grade-ar.mjs`, `grade-sm-gui.mjs`. Фикстуры — на месте, в `_skill-eval/fixtures/`.

# Встреча → список пунктов

Ты превращаешь разговор в список пунктов: что решили, что осталось открытым, что вынесли за рамки и что
рассказали. Куда пойдёт список — в ноут аналитика или во вход для БТ или спеки, — решают другие скиллы, не ты:
твоя работа — отделить решённое от сказанного и ничего не добавить от себя.

## TL;DR — шесть правил, держи в голове всегда

1. **Пишешь ровно два файла** в `<папка>` (Шаг 2): список пунктов и разбор. Документы задачи — только опора для
   кодов и терминов: не правишь; под-скиллы не зовёшь; `services/` и `context/` не читаешь.
2. **Расшифровку целиком не читаешь** (кроме короткого текста в сообщении). Её читают субагенты по
   путям; ты сверяешь их цитаты чтением строк.
3. **В список — только сказанное на встрече или ответ аналитика,** прошедшее проверку и
   подтверждённое аналитиком. Пункт — обычным языком, без цитат; номер строки — только в конце пункта.
4. **Последний ответ на тот же вопрос побеждает,** в том числе сказанный после «итого».
5. **Код, номер, термин — только с опорой:** строка, набранная в чате встречи, документ задачи или
   ответ аналитика. Опоры нет — словами.
6. **Один вопрос за ход** через инструмент вопросов, гипотезой, рекомендация первой. Сказанное в
   строке вызова не переспрашиваешь.

Если правило ниже противоречит этому списку — прав список.

## Шаг 0 — вход

| Дали | Что делать |
|---|---|
| путь к текстовому файлу | дальше Шаг 1 |
| путь к `*.razbor.md` | второй прогон: рядом лежит список этой встречи (`<основа>.points.md`) — «список уже есть: <путь>», конец; нет — прочитай разбор, дальше Шаг 5; в разборе 1.x записи разделов «Во вход …», «Для другого документа» и «Уже записано» — тоже записи для списка |
| текст в сообщении, до ~150 строк | карту и разбор делаешь сам, цитаты сверяешь по сообщению, проверяющему передаёшь текст дословно |
| текст длиннее | попроси сохранить его файлом и дать путь |
| протокол по памяти `*.recall.md` | стоп: «список из протокола пишет `/meeting-recall <путь>`» |
| ноут `notes/<тема>/notebook.md` | стоп: «список из ноута — `/analyst-notebook <тема> собери пункты`» |
| список `*.points.md` | стоп: «это уже список — `/notes-to-intent <путь>` или `/analyst-notebook <тема> <путь>`» |
| docx, pdf, аудио | стоп: «нужен текстовый экспорт — txt, vtt, srt» |
| ничего | спроси путь |

Ключ из строки вызова — готовый ответ на Шаг 2. «В ноут <тема>» в строке вызова — тема для строки «дальше» в
отчёте, больше ничего. Корень рабочего репо — папка, где лежит `docs/` или `notes/`; не видно — спроси одним
вопросом гипотезой: «корень — <текущая папка>?». Длина файла — `Grep pattern="^" output_mode="count"`.

## Шаг 1 — карта тем

Окна по 300 строк с перекрытием 20 (файл короче — одно окно), по субагенту на окно, до шести
одновременно. Промпт дословно, пути абсолютные:

```
Прочитай рубрику <путь к reference/map.md> и профили форматов <путь к reference/formats.md>.
Составь по рубрике карту строк <N>–<M> файла <путь к расшифровке>.

Первой строкой ответа напиши: рубрика прочитана: карта

Дальше — только то, что рубрика велит вернуть. Читай только названные файлы. Ничего не правь и не
создавай файлов.
```

Склей ответы: один ключ — всегда одна тема, в любом окне; один предмет в соседних окнах — одна
тема; тема без ключа, чьи строки перемежаются со строками темы с ключом, — часть этой темы.
Созвон — одна тема, и Шаг 3 разбирает весь файл; карта нужна, чтобы назвать тему, разметить побочное и найти
итоги. Предмет темы — предметы тем карты через «; », кроме тем только вида «статус» или «офтоп» без решений и без
сведений. Главная — тема с ключом из строки вызова, иначе с наибольшим числом строк; остальные темы карты —
побочные: записи из их строк сам не отбрасываешь (Шаг 6).
Кандидат в ключ сверь с диском: `Glob docs/**/*-<цифры>/*.md` — по числу, а не по слову:
распознавание пишет номер словами.

## Шаг 2 — ключ

- Ни решений, ни сведений нет — скажи «на встрече нет ни решений, ни сведений», файлов не пиши, конец.
- Тему не спрашиваешь: она одна (Шаг 1). Ключ сошёлся с папкой — без вопроса, строкой.
- Папок с этим числом несколько или у папки другие буквы, чем у ключа, набранного в чате или в строке
  вызова, — вопрос гипотезой, варианты — папки.
- Ключ — из строки вызова или из расшифровки, даже если папки с ним на диске нет. Ключа нет ни там, ни там —
  `—`, не спрашиваешь: ключ спросит тот, кто будет собирать вход.

Ключ есть — найди документы задачи: `Glob docs/**/<KEY>/{business_requirements,technical_specification,change_request}.md`.
Их пути передаёшь субагентам как опору для кодов, номеров требований и терминов (правило 5).

**Папка файлов** — где нашлись документы задачи; не нашлись — `docs/<KEY>/`; ключа нет —
`docs/_inbox/`. Ниже она — `<папка>`.

## Шаг 3 — разбор темы

Разбирается весь файл, а не строки тем карты: один субагент, предмет в промпте — предмет темы из Шага 1. Файл
длиннее 400 строк — по субагенту на кусок подряд, по 400 строк с перекрытием 20; записи потом сведи по предмету:
на тот же вопрос побеждает последний ответ, остальные записи предмета остаются, запись с теми же цитатами — одна.

```
Прочитай рубрику <путь к reference/extract.md> и профили форматов <путь к reference/formats.md>.
Разбери по рубрике тему «<предмет>» в файле <путь к расшифровке>.
Строки темы: <N>–<M> (весь файл или кусок). Итоги встречи: <диапазоны итогов или «последние 60 строк»>.
Документы задачи: <пути к БТ, спеке, запросу на правку — или «нет»>.

Первой строкой ответа напиши: рубрика прочитана: разбор

Дальше — только то, что рубрика велит вернуть. Читай только названные файлы. Ничего не правь и не
создавай файлов.
```

Каждую цитату сверь сам: `Grep -n` по куску цитаты из 4–6 слов без знаков препинания по расшифровке.
Нашлась на другой строке — исправь номер на найденный. Не нашлась — `Read` строк L−2…L+2 вокруг
названной: среди них есть строка о том же — замени цитату её текстом дословно и её номером; нет —
снимаешь цитату; запись — только если цитат у неё не осталось. Запиши черновик разбора:
`<папка>/meeting-<дата>.razbor.md` по `reference/output.md`. Дата — из первой строки расшифровки,
иначе из имени файла, иначе вместо даты — имя файла расшифровки. Разбор этой встречи лежал в папке
до запуска и это не второй прогон — оба файла с `-2`.

## Шаг 4 — проверка

Субагент с чистым контекстом:

```
Прочитай рубрику <путь к reference/verify.md>. Проверь по ней разбор <путь к разбору>
против расшифровки <путь к расшифровке> и документов задачи: <пути или «нет»>.

Первой строкой ответа напиши: рубрика прочитана: проверка

Дальше — только то, что рубрика велит вернуть. Читай только названные файлы. Ничего не правь и не
создавай файлов.
```

| Вердикт | Что делаешь |
|---|---|
| `цитата на другой строке: L… → L…` | исправляешь номер |
| `цитаты нет: L…` | как в Шаге 3: `Read` строк L−2…L+2; строка о том же — замени цитату её текстом дословно и её номером; нет — снимаешь цитату; запись — только если цитат не осталось |
| `не решение` | сомнительная → Шаг 5 |
| `вид: <другой>` | меняешь вид; условное → Шаг 5 |
| `переиграно L…` | открой строку сам; там другой ответ на тот же вопрос — вид «отменено», ссылка на заменившую запись; заменившей записи нет — как `пропуск L…` |
| `без опоры: <токен>` | в списке этот токен словами; в разборе ⚠️ |
| `пропуск L…` | один повторный разбор этих строк; не помогло — «не разобрано: L…» в сводке |

Записи по вердиктам не переформулируешь. Обнови разбор.

**Протокол субагентов.** Нет эхо-строки или ответ пустой — перезапуск; две неудачи — стоп:
«разбор не состоялся: <шаг>». Записи за субагента не придумываешь.

## Шаг 5 — сомнительные решения

Сюда идут только **решения**, в которых есть сомнение: условное; с `не решение` («предложено,
явного принятия нет»); с `без опоры` у кода, номера или числа. Открытый вопрос и отменённое сюда не идут.

По вопросу на запись, гипотезой: «На встрече: <суть> (<кто>, <время>)[, с оговоркой «<оговорка>»].
Оставляем?» Варианты: «Оставляем», «В открытые вопросы», «Не вносим». Рекомендация первой:
«Оставляем», если ниже по встрече никто не возразил; иначе «В открытые вопросы».

Ответ аналитика пиши в запись разбора. Его слова, которых не было на встрече, — пометкой «со слов
аналитика», без цитаты.

## Шаг 6 — сводка

Один вопрос. В тексте: путь списка; пункты списка короткими строками по видам; одной строкой — что
не идёт в список: «отменено и не принято — K (…), поручения — K, «не вносим» — K (…)». В скобках — предметы
записей через запятую. Записи из строк побочных тем (Шаг 1) — отдельной строкой: «Похоже, не про <предмет главной
темы> (K): 1. <суть> (<предмет побочной темы>) …». Варианты: «Записать N пунктов» (все), «Записать без этих K» —
если побочные есть, «Поправить» и, если есть «не разобрано», — «Сначала разобрать L…». Не взятые — в «Не вносим»
разбора, их предметов нет в `# Пункты:`. Поправки — свободным вводом, затем сводка ещё раз.

## Шаг 7 — запись

Список и итоговый разбор — по `reference/output.md`. Затем перечитай список с диска:
- в тексте пунктов ни цитат, ни форм на слух (номер или код буквами); номер строки — только в конце, ` · L<n>`;
- каждый код, номер и латинское слово пункта есть в `суть` его записи или в ответе аналитика; нет —
  переписываешь словами;
- числа, даты и сроки — полностью, как в `суть` записи или в ответе аналитика: «с 1-го»
  вместо «с 1 июля» — потеря;
- у каждого `[решено]` есть `— решил: <кто>`;
- у каждого пункта есть запись в разборе с пометкой `в список: п.<N>`;
- счёт **записей** разбора: в список + отменено и не принято + поручения + «не вносим» = всего записей темы
  (пунктов бывает меньше: две записи могут лечь в один пункт);
- у каждой записи разбора в `цитаты:` — текст в «…», а не один номер строки: номер без текста —
  `Read` этой строки и текст дословно. Правишь только эти строки: разделы и форма разбора — по `output.md`.

Отчёт в чат: оба пути и счёт пунктов по видам. Последние строки — «дальше: в ноут — `/analyst-notebook <тема>
<путь к списку>`; во вход для БТ или спеки — `/notes-to-intent <путь к списку>`» (тема — из «в ноут <тема>»
строки вызова, иначе слово `<тема>`).

## Чего ты не делаешь никогда

- Не правишь документы задачи и не пишешь в `docs/` ничего, кроме двух своих файлов.
- Не читаешь `services/` и `context/`: написание кода берётся только из опоры (правило 5).
- Не кладёшь в список переигранное, поручения и слова, которых не было на встрече.
- Не ставишь цель и слой и не сверяешь с документом задачи — это делает `/notes-to-intent`.

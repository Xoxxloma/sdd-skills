# Вход: любой текст — черновик

Источник — файл или текст в чате, который сюда отправил `SKILL.md` Step 0. Схема по нему — черновик: что сказано в
тексте — на схеме, что не сказано — вопросом. Здесь — как читать текст, как строка становится моделью (`SKILL.md`
Step 2) для короткой схемы и пути пользователя, вопросы о чтении и что делать без ответа.

Типы: короткая, путь пользователя.

## Чтение и отказ

Текст — файл целиком. В чате — текст, который аналитик дал для схемы: в сообщении с просьбой, а если там только
просьба, — в его предыдущем сообщении; слова самой просьбы — не текст, ответы на твои вопросы — тоже. Больше ничего не
читаешь: ни файлы рядом, ни документы задачи. Пункт — любая непустая строка текста, и заголовок, и строка разметки
(`---`, `|---|`); строка из одних пробелов — пустая. Всё, что сказано в тексте, считаешь решённым. Ни в одной строке нет ни звена, ни шага по таблицам «Пункт → модель» ниже → ответ «В тексте нет ни
одного взаимодействия или шага — рисовать нечего.» Файл не пишешь.

Список прочтения (`SKILL.md` Step 3) — строка на каждый пункт, в форме файла типа. Пункт, в котором рисовать нечего, —
`<id> «<название>»: не на схеме — <почему>`.

## Слова

| В `SKILL.md`, файлах типа и формата | Здесь |
|---|---|
| пункт | непустая строка текста |
| id пункта | `стр.<N>` — порядковый номер среди непустых строк, с 1, а не номер строки в файле: пустые не считаешь |
| `<образец id>` | `стр.N` |
| название пункта | текст строки; длиннее 60 знаков — первые 60 и «…» |
| `<пункты>`, `<пунктов>`, `<пункту>`, `<пунктах>` | «строка» в той же форме: строки, строк, строке, строках |
| `<пункты источника>` | строк текста `<имя файла>` — черновик по тексту; текст в чате — строк текста из чата — черновик по тексту |
| `<KEY>` | ключ задачи из первой строки, которая её называет («Задача: ABC-123», «по задаче ABC-123»); такой строки нет — имя папки `docs/<KEY>/`, где лежит файл; нет и её — «черновик» |
| `<кто правит источник>` | правка текста — у аналитика |

## Имя и папка файла схемы

Текст файлом — схема в его папке; перед именем из таблицы `SKILL.md` Step 1 — основа имени файла и `.draft.`:
`notes.txt` → `notes.draft.interaction_diagram.md`. Основа — имя без расширения, у `*.points.md` — без `.points.md`.
Текст в чате — схема в рабочей папке (там, где ты запущен), с приставкой `draft-<сегодняшняя дата>.`:
`draft-2026-01-15.interaction_diagram.md`; такой файл в папке уже есть — `draft-2026-01-15-2.`, `-3.` и дальше.

## Пункт → модель: короткая

| Что на схеме | Как найти в тексте пункта |
|---|---|
| звено | текст называет две стороны и что одна делает для другой: отправляет, отдаёт, передаёт, запрашивает, берёт, вызывает, публикует. От кого к кому — от того, кто начинает обмен, к тому, к кому он обращается: «A отправляет B», «A отдаёт B», «A запрашивает у B», «A берёт из B» — A → B; в «B получает от A» начинает A — тоже A → B. Несколько таких действий в пункте — звено на каждое, по порядку текста |
| вид звена | событие — текст говорит о событии или сообщении, которое публикуют или на которое подписаны; иначе — запрос |
| участник | сторона словами текста, в именительном падеже, кириллица — обычным регистром, первая буква прописная: «в службу доставки», «В СЛУЖБУ ДОСТАВКИ» → «Служба доставки»; латиница, коды и сокращения — буква в букву. Одно имя в разных падежах или регистре — один участник; разные имена — разные (сам не склеивай — об этом вопрос «участники»). Сторона — всё, что текст называет участником обмена, не только система: человек, хранилище, документ. Порядок участников — первого появления в пунктах, по номерам |
| подпись | `<id>`; в тексте пункта есть метод с путём (`POST /v1/items`) или имя события в обратных кавычках — у звена того действия, при котором он назван, `<id> · <он>`, только сам токен; у остальных звеньев пункта — `<id>` |
| нет звена | названа одна сторона или ни одной: объём, срок, правило, действие внутри одной системы — не на схеме, «нет звена» |
| нет направления | названы две стороны, а кто кому — не сказано («интеграция A с B», «A и B обмениваются данными») — вопрос «нет направления» |

## Пункт → модель: путь пользователя

| Что на схеме | Как найти в тексте пункта |
|---|---|
| шаг | действие: кто и глагол с тем, на что он направлен, — словами текста, без пересказа и добавлений; несколько действий через «и» или запятую — отдельные шаги по порядку, у второго действия того же субъекта субъект повторяешь; действие системы — тоже шаг. Фраза о возврате или о конце ветки — не шаг: она даёт только стрелку (строки «возврат» и «конец ветки») |
| развилка | условие: «если …», «в случае …»; текст развилки — условие словами текста, вопросом; ветка «да» — что сказано при условии, «нет» — что сказано после «иначе», «если нет», «в противном случае» |
| основная ветка | ветка, после которой текст не говорит ни о конце, ни о возврате; таких две или ни одной — ветка «да». Другая — ответвление |
| возврат | текст говорит, что шаг делают ещё раз («снова …», «начинает заново», «возвращается к …») — стрелка к этому шагу |
| конец ветки | текст говорит, что дальше ничего («на этом всё», «работа прекращается», «… не создаётся») — стрелка в «Конец» |
| не на схеме | пункт без действия в процессе: объём, срок, роль, права, как устроена система |

## Вопросы

| Вопрос | Условие | Что спрашиваешь |
|---|---|---|
| нет направления | короткая; в пункте названы две стороны, а кто кому — не сказано | «стр.N: направление не указано. A → B или B → A?» — стороны, как в таблице «Пункт → модель: короткая» |

Вопросы о дырах текста (`SKILL.md` Step 3): «нет направления».

## Без ответа

| Вопрос без ответа | Что делаешь |
|---|---|
| нет направления | пункта на схеме нет: ни стрелок, ни участника, который есть только в нём |

## Прогон гейта — `shipping` (backend)

**1. Ключи.** Три `###`: `` `Shipment` `` в бэктиках, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы разрешены, блок объекта один. Сошлось.

**2. Состав.** Опись: состояние 1 → блок объекта 1 (`Shipment`); сообщений 1 (опись) и 1 блок `публикует` в «Событиях» → 1 сообщение в карточке; ограничений 1 → 1 блок. `Attachment` — только `справочник:`, блока не имеет, верно пропущен. Сошлось.

**3. Значения.** «Владеет данными» — булет-форма `- поле: A | B`, не таблица — не добор сама по себе. У `status` 3 значения через `|`, у блока `Shipment` 4 строки токенов (новое/назначено/переназначено/доставлено) — не меньше 3. Строка «переназначено (`ASSIGNED`, `assignedAt` сдвинут)» — тот самый законный вид исключения (дата в скобках при повторном токене состояния), не заполнитель. Токены — из объявленных значений. Сошлось.

**4. Код.** Проверил четыре паттерна по всем строкам секции. Нашёл нарушение: в строке «переназначено (`ASSIGNED`, `assignedAt` сдвинут) — …» токен `assignedAt` — это `\b[a-z]+[A-Z][A-Za-z]*\b` (голое имя поля из кода), а по правилу описи такое поле должно идти словами, не в виде идентификатора. Топик `shipment.delivered` не попадает под паттерн двух точек ({2,}) — там проходит. Бэктиков в заголовке сообщения нет. **Не сошлось** — одна строка нарушает.

**5. Хозяин.** В блоке ограничения — `partner-registry`, это имя соседа из манифеста (shipping, partner-registry, dispatch-web). Не «настройка», не булево. Сошлось.

Четыре числа из пяти проверок совпали; проверка «Код» дала расхождение на одной строке.

**1. Ключи.** Все три `###` — `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — начинаются с разрешённых форм, блок объекта один (только `Shipment`, `Attachment` не назван состоянием — верно). Сошлось.

**2. Состав.** Блоков объектов 1 = строк `состояние:` в описи (1). Сообщений 1 = строк `сообщение:` (1) = блоков «публикует» в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Сошлось.

**3. Значения.** В блоке `Shipment` перечисления с `|` в строке `- поле:` — есть у `status`, `packageType`, `kind`, тип без значений не встречается. Но в самом блоке «Бизнес-правила» → `` `Shipment` `` 3 строки соответствуют значениям `состояние:` (NEW/ASSIGNED/DELIVERED — токен строки совпадает со значением), а 4-я строка — «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: два токена через `/` в одной строке. Это ровно исключаемый случай — справочник (`packageType`), который в описи не должен давать блока/строки вообще, записан как если бы это было состояние. Не сошлось.

**4. Код.** Вне бэктиков во всех трёх блоках секции нет `/путей`, HTTP-глаголов, camelCase или точечных цепочек; в бэктиках — только значения перечислений, топик `shipment.delivered` и имя соседа `partner-registry` из манифеста. В заголовке сообщения бэктиков нет. Сошлось.

**5. Хозяин.** У ограничения «приём отправлений партнёра отключён» хозяин — `partner-registry`, есть в манифесте (`shipping`, `partner-registry`, `dispatch-web`), не флаг и не «настройка». Сошлось.

ГЕЙТ: ДОБОР — убрать из блока `` `Shipment` `` в «Бизнес-правилах» строку про `packageType` («тип упаковки (`BOX` / `PALLET`) — задаётся при создании»): это справочник, а справочники по правилам описи блока/строки в «Бизнес-правилах» не дают; после правки прогнать ответ добора заново по всем пяти пунктам гейта.

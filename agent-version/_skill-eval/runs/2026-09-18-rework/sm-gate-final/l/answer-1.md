**1. Ключи.** Заголовки: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Блок объекта один — состояний в описи 1 (`Shipment`). Сообщений в блоке 1 = строк `сообщение:` (1) = блоков `публикует` в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не получили — верно. Сошлось.

**3. Значения.** «Владеет данными» — не таблица `| Поле | Тип |`, а строки `- поле:` со значениями через `|` — формат верный, не добор. В блоке `Shipment` 5 строк на 5 значений из `состояние:` — количество сошлось. Но: `отменено (CANCELLED)` и `утеряно (LOST)` несут дословно одно и то же «правило» («значение enum, отдельного кода перехода нет; проставляется напрямую при смене статуса») на двух разных значениях — это заполнитель, по правилу такие значения без перехода должны быть записаны как `не определено`. Не сошлось.

**4. Код.** Вне бэктиков в секции нет путей, HTTP-глаголов, camelCase или точечных цепочек. В бэктиках — только значения перечислений (`NEW`, `ASSIGNED`…), топик `shipment.delivered` в конце строки, имя соседа `partner-registry` из манифеста. Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, имя из манифеста списка (`shipping`, `partner-registry`, `dispatch-web`), не конфиг и не флаг. Сошлось.

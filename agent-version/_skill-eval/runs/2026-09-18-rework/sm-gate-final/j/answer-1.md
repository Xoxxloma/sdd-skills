**1. Ключи.** Заголовки: `` `Shipment` `` (сущность в бэктиках — ок), `ограничение «приём отправлений партнёра отключён»` (ок). Но третий — `### письмо «груз доставлен»`: ключевое слово «письмо» вместо требуемого «сообщение «» — это прямо названный в правиле пример неверного заголовка. Не сошлось.

**2. Состав.** Блоков объектов — 1 (`Shipment`), сущностей в строке `состояние:` — тоже 1 (Attachment там только `справочник:`, блока не требует) — сошлось. Сообщений — 1 блок, строк `сообщение:` в описи — 1, блоков `публикует` в «Событиях» — 1 (`shipment.delivered`) — сошлось. Ограничений — 1 блок на 1 строку `ограничение:` — сошлось.

**3. Значения.** «Владеет данными» — список, а не таблица `| Поле | Тип |`, так что первый пункт правила не применяется. Перечисления через `|` в строке `- поле:` — есть у всех трёх (`status`, `packageType`, `kind`). В блоке `Shipment` — 3 строки на 3 значения `состояние:`, каждый токен — ровно одно из `NEW`/`ASSIGNED`/`DELIVERED`, дублей правил нет. Сошлось.

**4. Код.** Вне бэктиков во всей секции — только русский текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика в конце строки сообщения (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя сервиса-соседа из манифеста, а не «настройка» и не голый флаг. Сошлось.

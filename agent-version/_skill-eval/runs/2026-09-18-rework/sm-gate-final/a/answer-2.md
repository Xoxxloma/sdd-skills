**1. Ключи.** Заголовки в «Бизнес-правилах»: `### \`Shipment\` — отправление`, `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»` — все три формы верны, посторонних заголовков нет.

**2. Состав.** В описи две строки `состояние:` — `Shipment.status` и `Courier.status`, значит блоков объектов должно быть два. В карточке блок объекта только один (`Shipment`) — блока `Courier` в «Бизнес-правилах» нет, хотя `Courier` — своя сущность (владеет данными, перечисление небулево). Сообщений: 1 строка `сообщение:` в описи = 1 блок сообщения = 1 `публикует` в «Событиях» — сошлось. Ограничений: 1 строка `ограничение:` = 1 блок — сошлось. Несовпадение только по состояниям: **не сошлось**.

**3. Значения.** «Владеет данными» — списком `- поле:` со значениями через `|`, тип без значений (`weightKg`, `phone`, `url`) не перечисление — форма верна. В блоке `Shipment` 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`) — строк тоже 3, токены различны, заполнителя нет — сошлось. Блок `Courier` проверить нельзя — блока нет вовсе (см. п.2).

**4. Код.** Вне бэктиков в секции — только связный текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только `shipment.delivered` (имя топика) и `partner-registry` (имя из манифеста) — оба входят в разрешённый список исключений. Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения — `partner-registry`, это сосед из манифеста (`shipping`, `partner-registry`, `dispatch-web`). Не настройка и не флаг. Сошлось.

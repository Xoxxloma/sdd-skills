**1. Ключи.** Заголовки блоков: `### Отправление (\`Shipment\`)`, `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»`. Первый заголовок не начинается с имени сущности в бэктиках — перед ключом стоит подпись «Отправление». Это ровно случай «подпись впереди ключа» — не сошлось.

**2. Состав.** Блоков объектов — 1 (`Shipment`), строк `состояние:` в описи — 1. Сообщений в секции — 1, строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1. Ограничений — 1, строк `ограничение:` — 1. Attachment (справочник) блока не имеет — верно, справочники блока не получают. Счёт сошёлся.

**3. Значения.** «Владеет данными» даёт перечисления через `|` в строке `- поле:`: `status` (3 значения), `packageType` (2), `kind` (2) — форма верная, тип без значений (`weightKg`, `url`) не перечисления, добора не требует. В блоке `Shipment` строк 3, значений в `состояние:` тоже 3 (NEW/ASSIGNED/DELIVERED), все три встречены по разу, `не определено` не нужен, два токена в одной строке не встречаются. Сошлось.

**4. Код.** Вне бэктиков во всех строках секции — только связный текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`); в заголовке сообщения бэктиков нет. Сошлось.

**5. Хозяин.** В блоке ограничения — `partner-registry`, это имя соседа из манифеста, не конфиг и не флаг. Сошлось.

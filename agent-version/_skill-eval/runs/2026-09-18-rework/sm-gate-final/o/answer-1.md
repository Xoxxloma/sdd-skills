**1. Ключи** — три заголовка: `` `Shipment` — отправление``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»». Форма верная, один блок на сущность. Сошлось.

**2. Состав** — состояние: 1 строка (Shipment) → 1 объектный блок, есть. Сообщение: 1 строка описи, 1 блок `публикует` в «Событиях» → нужно ≥1 блок сообщения, есть 1. Ограничение: 1 строка → 1 блок, есть. Attachment (только справочник) блока не получил — верно. Сошлось.

**3. Значения** — у Shipment 3 значения (`NEW|ASSIGNED|DELIVERED`) → в блоке 3 строки, каждая с одним токеном из перечня («новое» `NEW`, «назначено» `ASSIGNED`, «доставлено» `DELIVERED`), дублей правил нет, чужих полей нет. Сошлось.

**4. Код** — вне бэктиков кода нет. Но в блоке ограничения внутри бэктиков стоит `shipping.partner-gate.enabled` — это ключ конфига (три сегмента через точку), а по правилу описи «ключ конфига — словами или никак», и по числу 4 гейта в бэктиках допустимы только значение перечисления/имя вида/топика/сервиса из манифеста/дата-исключение. Ключ конфига в этот список не входит. **Не сошлось.**

**5. Хозяин** — в блоке ограничения хозяин назван «внешняя конфигурация (вне манифеста)» — а это прямо запрещённая формулировка («внешняя конфигурация» — не хозяин); ни сосед из манифеста (`shipping`/`partner-registry`/`dispatch-web`), ни роль из «Роли и доступ» (`DISPATCHER`/`COURIER`), ни именованная внешняя система не указаны. **Не сошлось.**

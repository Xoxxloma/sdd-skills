Прогоняю пять пунктов гейта по блоку «Бизнес-правила».

**1. Ключи.** Три `###`: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»`. Все три формы разрешены, блок объекта один — на `Shipment`. Сошлось.

**2. Состав.** Строка `состояние:` одна → блок объекта один (`Shipment`) — сошлось. `сообщение:` одна, `публикует` в «Событиях» одно (`shipment.delivered`) → блоков сообщений один — сошлось. `ограничение:` одна → блок один — сошлось. Перечисления `weightKg` и `url` в описи не значатся ни состоянием, ни справочником — и это верно: они не перечисления (decimal, string), пропуска нет. Справочники (`packageType`, `Attachment.kind`) блоков не получили — верно.

**3. Значения.** В блоке `Shipment` три строки на три значения `состояние:` (`NEW`/`ASSIGNED`/`DELIVERED`), заполнителя нет, токен каждой строки — ровно одно значение в бэктиках. Сошлось.

**4. Код.** В блоке ограничения бэктиками отмечен `shipping.partner-gate.enabled` — это ключ конфига (дотированный идентификатор), а не значение перечисления, не имя вида/топика, не имя сервиса из манифеста и не дата-исключение. В бэктиках допустимого содержимого нет — **не сошлось**.

**5. Хозяин.** Блок называет хозяином «внешняя конфигурация» — а это прямо в списке того, что хозяином не является («внешняя конфигурация», «настройка», ключ конфига — не хозяин). Ни имени из манифеста (`shipping` / `partner-registry` / `dispatch-web`), ни роли из «Роли и доступ» (`DISPATCHER`/`COURIER`), ни именованной внешней системы не указано — **не сошлось**.

**1. Ключи.** Три `###`: `` `Shipment` `` — отправление (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, лишних заголовков нет. Совпало.

**2. Состав.** Строк `состояние:` в описи — 1 (Shipment) → блоков-объектов в карточке — 1 (Shipment). Сообщений: строка `сообщение:` — 1, блоков `публикует` в «Событиях» — 1 → в карточке 1 блок сообщения. Ограничений: строка `ограничение:` — 1 → в карточке 1 блок. Числа совпали.

**3. Значения.** «Владеет данными» — не таблица, форма `- поле: значение | значение`, ок. Блок `Shipment` должен иметь не меньше строк, чем значений в `состояние:` (3: `NEW`/`ASSIGNED`/`DELIVERED`) — в блоке действительно 3 строки на эти значения. Но в блоке есть четвёртая строка — «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании»: два токена в одной строке через запятую — это ровно случай «справочник, записанный состоянием». `packageType` в описи стоит строкой `справочник:`, а справочник «блока в секции не даёт» — эта строка не должна быть в «Бизнес-правилах» вообще. **Не сошлось.**

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечислений (`NEW`, `ASSIGNED`, `DELIVERED`, `BOX`, `PALLET`), имя топика `shipment.delivered` и имя сервиса `partner-registry` из манифеста. Заголовки сообщения/ограничения без бэктиков. Совпало.

**5. Хозяин.** Блок ограничения называет `partner-registry` — это имя есть в манифесте. Совпало.

**1. Ключи** — все три `###` в секции: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»». Блок объекта один — `Shipment`. Сошлось.

**2. Состав** — состояние: 1 сущность (Shipment.status) → 1 блок объекта, есть. Сообщений: строк `сообщение:` 1, блоков «публикует» в «Событиях» 1 (`shipment.delivered`) → в карточке 1 блок сообщения. Ограничений: строка `ограничение:` 1 → блок 1. `Attachment.kind` в описи назван справочником — блока не имеет, верно. Сошлось.

**3. Значения** — не сошлось. «Владеет данными» → `Shipment` дана таблицей `| Поле | Тип | Описание |`, и в столбце «Тип» стоят голые имена `ShipmentStatus`, `PackageType` без значений через `|` в строке `- поле:` — это ровно «тип без значений — добор» из правила. Для сравнения, `Attachment.kind` оформлен верно: `` - `kind`: `PHOTO` | `PDF` ``. Сам блок правил по `Shipment` в порядке (3 строки на 3 значения, токены `NEW`/`ASSIGNED`/`DELIVERED` совпадают, склеенных через `/`,`,` нет).

**4. Код** — вне бэктиков в тексте секции нет путей, HTTP-глаголов, camelCase, точечных цепочек. В бэктиках — только значения (`NEW`, `ASSIGNED`, `DELIVERED`), топик `shipment.delivered`, имя соседа `partner-registry` из манифеста. Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин** — в блоке ограничения хозяин — `partner-registry`, это имя есть в манифесте (`shipping`, `partner-registry`, `dispatch-web`). Не «настройка» и не голый флаг. Сошлось.

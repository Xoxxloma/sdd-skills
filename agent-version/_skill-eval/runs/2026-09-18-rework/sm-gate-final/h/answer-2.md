**1. Ключи.** Три заголовка секции: `` `Shipment` — отправление`` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, чужого вида заголовка нет, блок объекта один (`Shipment`). Сошлось.

**2. Состав.** Строка `состояние:` в описи одна (Shipment) → блоков объектов 1, в карточке 1. Строка `сообщение:` одна и блок `публикует` в «Событиях» один (`shipment.delivered`) → сообщений в карточке 1, не меньше обоих. Строка `ограничение:` одна → блок ограничения один. Справочники (`packageType`, `kind`) блоков не имеют — верно, они не в состоянии. Сошлось.

**3. Значения.** «Владеет данными» — не таблица `| Поле | Тип |`, а перечисление с явными значениями через `|` (`status`, `packageType`, `kind` — везде значения указаны). В блоке `Shipment` 4 строки на 3 значения состояния: NEW, ASSIGNED, DELIVERED плюс легальное исключение «переназначено (`ASSIGNED`, `assignedAt` сдвинут)» — это ровно форма законного дата-исключения, не заполнитель. Токен каждой строки — одно значение, двойных токенов через `/`, `|`, запятую нет. Сошлось.

**4. Код.** Вне бэктиков во всей секции нет путей, HTTP-глаголов, camelCase или точечных цепочек. В бэктиках встречаются только: значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), поле `assignedAt` — но оно внутри разрешённого дата-исключения по образцу правила 3, топик `shipment.delivered` (имя топика — разрешено, к тому же не матчит паттерн двух точек) и имя соседа `partner-registry` из манифеста. Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** Блок ограничения называет хозяином `partner-registry` — это сосед из манифеста (`shipping`, `partner-registry`, `dispatch-web`), не конфиг и не голый флаг. Сошлось.

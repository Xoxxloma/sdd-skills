Прогон по пяти числам:

1. **Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один и он один на сущность. Сошлось.

2. **Состав.** Блоков объектов 1 = сущностей в строках `состояние:` (1, `Shipment`) — сошлось. Сообщений 1 = строк `сообщение:` (1) = блоков `публикует` в «Событиях» (1, `shipment.delivered`) — сошлось. Ограничений 1 = строк `ограничение:` (1) — сошлось. **Но**: в «Владеет данными» у `Shipment` есть поле `priority`: `NORMAL` | `URGENT` — перечисление своей сущности, которого нет ни в строке `состояние:`, ни в строке `справочник:` описи. Это пропуск — не сошлось.

3. **Значения.** «Владеет данными» — не таблица, а верная форма `- поле:` со значениями через `|`. В блоке `Shipment` 3 строки = 3 значения в `состояние:` (`NEW`/`ASSIGNED`/`DELIVERED`), токены совпадают с значениями, разных правил на разных значениях нет, поле не подменено. Сошлось (для того, что учтено в описи).

4. **Код.** Вне бэктиков форбидден-паттернов нет. В бэктиках только значения (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`) — заголовок сообщения без бэктиков. Сошлось.

5. **Хозяин.** В блоке ограничения хозяин — `partner-registry`, имя есть в манифесте (`shipping`, `partner-registry`, `dispatch-web`), не флаг и не «настройка». Сошлось.

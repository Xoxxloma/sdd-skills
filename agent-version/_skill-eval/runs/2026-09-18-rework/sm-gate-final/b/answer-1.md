Ключи.** Три `###`: `` `Shipment` `` — отправление, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, посторонних заголовков нет, блок объекта один (только `Shipment`, у `Attachment` блока нет — верно, справочник блока не получает). Сошлось.

**2. Состав.** Блоков объектов (1) = строк `состояние:` (1) — сошлось. Сообщений (1) = строк `сообщение:` (1) = блоков «публикует» в Событиях (1) — сошлось. Ограничений (1) = строк `ограничение:` (1) — сошлось. Но у `Shipment` в «Владеет данными» есть третье перечисление — `priority`: `NORMAL` | `URGENT`, — которого нет в описи ни как `состояние:`, ни как `справочник:`. Это пропуск. Не сошлось.

**3. Значения.** «Владеет данными» — не таблица, а список с инлайн-значениями через `|`, исключение не применяется. У `состояние:` 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), в блоке `Shipment` тоже 3 строки, дублей правил и «не определено» нет, токен каждой строки — ровно одно из значений, двух токенов в одной строке нет. Сошлось.

**4. Код.** Вне бэктиков во всей секции «Бизнес-правила» — только русские слова, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`) — всё разрешённое. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя есть в списке сервисов манифеста, не флаг и не «настройка». Сошлось.

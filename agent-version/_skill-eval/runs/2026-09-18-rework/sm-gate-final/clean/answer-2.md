**1. Ключи.** Три заголовка секции: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы разрешённые, блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Опись: состояние ×1 → блоков объектов 1 (только `Shipment`, `Attachment` без блока — верно, у неё только справочник). Сообщение ×1 → сообщений-блоков 1, и публикует-блоков в «Событиях» тоже 1 (`shipment.delivered`), 1≥1. Ограничение ×1 → ограничений-блоков 1. Все перечисления своей сущности (status, packageType, kind) учтены в описи как состояние/справочник, лишних нет. Сошлось.

**3. Значения.** «Владеет данными» — не таблица `| Поле | Тип |`, а строки `- поле: значения` с `|`-разделителем, как требуется. В блоке `Shipment` 3 строки на 3 значения `состояние:` (NEW/ASSIGNED/DELIVERED), без пропусков и без дублей-заполнителей. Токен каждой строки — ровно одно значение, скобочного исключения (даты) нет, лишних имён полей нет, сдвоенных токенов через `/`/`|`/запятую нет. Сошлось.

**4. Код.** Вне бэктиков во всей секции — только связный текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`); заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя соседа из манифеста (`shipping`, `partner-registry`, `dispatch-web`), не флаг и не «настройка». Сошлось.

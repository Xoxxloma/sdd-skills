**1. Ключи.** Заголовки блоков: `` ### `Shipment` — отправление `` (имя сущности в бэктиках), `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»` — все три формы верные, один блок объекта на сущность. Сошлось.

**2. Состав.** Строк `состояние:` — 1 (Shipment) → блоков объектов 1, есть. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1 (`shipment.delivered`) → сообщений в карточке 1, есть. Строк `ограничение:` — 1 → ограничений в карточке 1, есть. Перечисления Shipment (`status`, `packageType`) и Attachment (`kind`) все названы в описи (состояние/справочник), пропусков нет; справочники (Attachment.kind, Shipment.packageType) блоков не получили — верно. Сошлось.

**3. Значения.** «Владеет данными» — не таблицей `| Поле | Тип |`, а списком `- поле:` со значениями через `|`, это допустимая форма. В блоке `Shipment` строк 4 при 3 значениях `состояние:` (NEW/ASSIGNED/DELIVERED) — не меньше, ок. Но строка «перевешено (`ASSIGNED`, `weightKg` изменён)» вешает токен `ASSIGNED` вместе с полем `weightKg` — а разрешённое исключение для второго имени в скобках рядом с токеном — только **дата**, которой состояние отличается (пример: `expiresAt`). `weightKg` — не дата, это отдельное поле сущности. Любое другое имя поля рядом с токеном — «строка на поле», добор. Не сошлось.

**4. Код.** Вне бэктиков в секции кодовых токенов нет. Внутри бэктиков разрешены только значение перечисления, имя вида/топика, имя сервиса из манифеста и дата-исключение. `` `weightKg` `` в той же строке «перевешено» — не значение перечисления, не вид, не топик, не сервис и не дата — недопустимое содержимое бэктиков. Не сошлось (тот же дефект, что и в п.3).

**5. Хозяин.** Блок ограничения: «управляет `partner-registry`» — имя сервиса из манифеста (`shipping`, `partner-registry`, `dispatch-web`), ролей/`true`/`false` вместо хозяина нет. Сошлось.

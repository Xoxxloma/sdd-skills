**1. Ключи.** Три `###`: `Shipment` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — формы верные, один блок объекта на сущность. Совпало.

**2. Состав.** Блоков-объектов 1 (`Shipment`) = 1 сущность в строке `состояние:` описи. Сообщений 1 = строка `сообщение:` описи = 1 блок `публикует` в «Событиях». Ограничений 1 = строка `ограничение:`. Совпало.

**3. Значения.** «Владеет данными» — список `- поле:` со значениями через `|` (не таблица `| Поле | Тип |`), это и есть требуемая форма. В блоке `Shipment` 4 строки ≥ 3 значений состояния — но строка «перевешено (`ASSIGNED`, `weightKg` изменён)» ставит в скобки рядом с токеном имя поля `weightKg` — это decimal вес, не дата. Законное исключение — только «дата, которой состояние отличается». Любое другое имя поля — строка на поле, добор. Не совпало.

**4. Код.** Вне бэктиков секции путей/HTTP-глаголов/camelCase/точечных цепочек нет. В бэктиках везде допустимые токены (`NEW`/`ASSIGNED`/`DELIVERED`, топик `shipment.delivered`, сервис `partner-registry`) — кроме `weightKg`: это имя поля, не значение перечисления, не имя вида/топика, не сервис из манифеста и не дата-исключение. Тот же дефект, что в (3). Не совпало.

**5. Хозяин.** Ограничение «приём отправлений партнёра отключён» — хозяин `partner-registry`, есть в манифесте (`shipping`, `partner-registry`, `dispatch-web`), не `true`/`false` и не «настройка». Совпало.

ГЕЙТ: ДОБОР — в блоке `Shipment` строка «перевешено (`ASSIGNED`, `weightKg` изменён)»: `weightKg` не дата, поэтому не подходит под единственное законное исключение (дата, которой состояние отличается); либо убрать эту строку как не привязанную к значению состояния из описи, либо, если это законное правило про поле веса, вынести его без имени поля в бэктиках рядом с токеном.

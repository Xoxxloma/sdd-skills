Прогоняю гейт по пяти пунктам.

1. **Ключи.** Три заголовка секции: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, посторонних заголовков нет. Блок объекта один — на `Shipment`.

2. **Состав.** Опись даёт 1 состояние → 1 блок объекта в карточке (`Shipment`, `Attachment` как чужая для справочника блока не получает — верно). 1 строка `сообщение:` и 1 блок `публикует` в «Событиях» → 1 блок сообщения. 1 строка `ограничение:` → 1 блок ограничения. Справочники (`packageType`, `kind`) блоков не имеют — по правилу верно.

3. **Значения.** «Владеет данными» — список `- \`поле\`: значения`, не таблица `| Поле | Тип |`, так что этот триггер добора не срабатывает. У `status` 3 значения через `|` — в блоке `Shipment` тоже 3 строки (`NEW`, `ASSIGNED`, `DELIVERED`), каждая на свой токен, без повторов правила и без множественных токенов в одной строке — сошлось.

4. **Код.** Вне бэктиков во всех строках секции — только русский текст, ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), топик `shipment.delivered` и имя соседа `partner-registry` из манифеста; в заголовке сообщения бэктиков нет — сошлось.

5. **Хозяин.** Блок ограничения называет хозяином `partner-registry` — это сосед из манифеста (`shipping`, `partner-registry`, `dispatch-web`), а не настройка/флаг/конфиг — сошлось.

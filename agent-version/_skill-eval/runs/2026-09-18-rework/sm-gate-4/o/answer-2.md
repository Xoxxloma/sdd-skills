Прогоняю пять пунктов гейта по карточке `shipping`.

1. **Ключи.** Три `###` в секции: `` `Shipment` `` — отправление, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»». Все три формы верны (сущность в бэктиках / «сообщение «` / «ограничение «`), блок объекта один — на `Shipment`. Сошлось.

2. **Состав.** Блоков объектов — 1, сущностей в строке `состояние:` — 1 (`Shipment`). Сообщений в блоке — 1, строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1 (`shipment.delivered`) — не меньше. Ограничений — 1, строк `ограничение:` — 1. Чужая сущность (`Attachment`) и справочники (`packageType`, `kind`) блоков не получили — верно. Сошлось.

3. **Значения.** «Владеет данными» — не таблица `| Поле | Тип |`, а список `- поле:` со значениями через `|` — проверяю дальше. В блоке `Shipment` три строки на три значения строки `состояние:` (`NEW`/`ASSIGNED`/`DELIVERED`), токен каждой строки — ровно одно значение, дублей и составных токенов через `/`,`,` нет. Сошлось.

4. **Код.** Вне бэктиков код не встречается. Но в блоке ограничения бэктик `` `shipping.partner-gate.enabled` `` — это ключ конфига (`\b[a-z]+(\.[a-z-]+){2,}\b`), а разрешено в бэктиках только: значение перечисления, имя вида/топика, имя сервиса из манифеста, дата-исключение. Ключ конфига в этот список не входит. Не сошлось.

5. **Хозяин.** В блоке ограничения хозяином назван «внешняя конфигурация (вне манифеста)» — а правило прямо исключает «внешнюю конфигурацию» из хозяев. Ни имени соседа из манифеста (`partner-registry`/`dispatch-web`), ни роли из «Роли и доступ», ни имени внешней системы не названо. Не сошлось.

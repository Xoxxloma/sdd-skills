**1. Ключи.** Три `###`: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»`. Все три формы верные, посторонних заголовков нет — блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Строк `состояние:` — 1 (`Shipment`) → блоков объектов 1, есть. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1 (`shipment.delivered`) → сообщений-блоков 1, не меньше обоих. Строк `ограничение:` — 1 → блоков 1. Все перечисления `Shipment`/`Attachment` из «Владеет данными» названы в описи (состояние или справочник), чужих блоков (`Attachment`) в «Бизнес-правилах» нет. Сошлось.

**3. Значения.** «Владеет данными» — не таблица, обычные строки `- поле:` с значениями через `|` — формат в порядке. В блоке `Shipment` у состояния 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), строк в блоке 4: `NEW`, `ASSIGNED`, `ASSIGNED` с датой-исключением (`assignedAt` сдвинут — законная форма по образцу «продлена»), `DELIVERED` — не меньше значений, лишняя строка легальна как дата-исключение, а не заполнитель (тексты у обеих строк `ASSIGNED` разные: назначение vs смена курьера). Каждый токен — одно из значений. Сошлось.

**4. Код.** Вне бэктиков в «Бизнес-правилах» нет путей, HTTP-глаголов, camelCase или точечных цепочек. В бэктиках только: значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), дата-исключение (`assignedAt`), топик в конце строки (`shipment.delivered`), имя сервиса из манифеста (`partner-registry`). Заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя сервиса-соседа из манифеста (не «настройка», не флаг). Сошлось.

**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, посторонних заголовков нет. Сошлось.

**2. Состав.** Блоков объектов 1 (`Shipment`) = строк `состояние:` в описи (1); `Attachment` (справочник) блока не имеет — верно. Сообщений 1 = строк `сообщение:` (1) = блоков «публикует» в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица — ок. Но у `Shipment.status` значения указаны как `` `ShipmentStatus` `` (просто тип), без перечисления через `|`, хотя опись даёт `NEW | ASSIGNED | DELIVERED` — а рядом `packageType` и `Attachment.kind` перечислены правильно через `|`. Это «тип без значений» — не сошлось.

**4. Код.** Вне бэктиков — ни путей, ни HTTP-глаголов, ни camelCase, ни составных имён. В бэктиках — только значения (`NEW`, `ASSIGNED`, `DELIVERED`), топик `shipment.delivered`, имя сервиса `partner-registry` из манифеста. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, имя соседа из манифеста, не конфиг и не флаг. Сошлось.

**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы соблюдены, по одному блоку объекта на сущность. Сошлось.

**2. Состав.** `состояние:` — 1 строка (Shipment) → 1 блок объекта в карточке. `сообщение:` — 1 строка → 1 блок сообщения, и он же единственный `публикует` в «Событиях». `ограничение:` — 1 строка → 1 блок. Оба `справочник:` (packageType, Attachment.kind) блоков не получили — верно, они блока не дают. Сошлось.

**3. Значения.** В «Владеет данными» у `packageType` и `kind` значения перечислены через `|` в строке `- поле:` — норма. А у `status` строка — `` `status`: `ShipmentStatus` — перечисление `` : это тип **без** перечисленных через `|` значений, ровно случай «тип без значений — добор» из правила. Не сошлось.

**4. Код.** Вне бэктиков в «Бизнес-правилах» нет ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`); заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** У блока ограничения хозяин — `partner-registry`, это сосед из манифеста, а не «настройка» и не голый флаг. Сошлось.

**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы соблюдены, блок объекта один. Сошлось.

**2. Состав.** Строк `состояние:` — 1 (Shipment) → блоков объектов 1, есть. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1 (`shipment.delivered`) → сообщений в разделе 1, не меньше обоих. Строк `ограничение:` — 1 → блок ограничения 1. Справочники (`packageType`, `kind`) блоков не имеют — верно. Сошлось.

**3. Значения.** `Shipment.status` в «Владеет данными» дан через `|` (`NEW | ASSIGNED | DELIVERED`) — 3 значения; в блоке 3 строки (`NEW`, `ASSIGNED`, `DELIVERED`), не меньше. Токен каждой строки — сама метка значения в скобках, второго токена через `/`, `|`, запятую нет. Сошлось.

**4. Код.** В тексте секции «Бизнес-правила» нет ни `/[a-z]`, ни HTTP-глаголов, ни camelCase (`NEW`/`ASSIGNED`/`DELIVERED`/`Shipment` не содержат строчную-затем-заглавную последовательность), `shipment.delivered` — только один сегмент точки, под `{2,}` не попадает; в заголовке сообщения бэктиков нет. Сошлось.

**5. Хозяин.** Блок ограничения называет только «партнёра» и не указывает ни имя из манифеста (`partner-registry`), ни роль из «Роли и доступ» (`DISPATCHER`/`COURIER`), ни внешнюю систему по имени — источник в описи (`integration/PartnerGate.kt`) намекает на соседа, но карточка его не называет. Не сошлось.

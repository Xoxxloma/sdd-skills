## Гейт «Бизнес-правила» — `shipping`

**1. Ключи.** Все четыре `###`: `Shipment`, `Department`, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — начинаются строго с сущности в бэктиках / `сообщение «` / `ограничение «`, подписи впереди ключа нет, один блок на сущность. Сошлось.

**2. Состав.** Опись: 2 строки `состояние:` (Shipment, Department) → в карточке 2 блока-объекта — числа совпадают. Но сам заголовок блока `Department` в карточке же несёт пометку «схема partner-registry, на чтение» — а это ровно признак чужой сущности, которой по правилам описи строка `состояние:` не положена и в «Владеет данными» стоять не должна. Совпадение 2=2 держится на неверной строке самой описи; по факту своя только `Shipment`. Сообщений: 1 строка `сообщение:` ≤ 1 блок сообщения и ≤ 1 блок «публикует» в «Событиях» — сошлось. Ограничений: 1 строка = 1 блок — сошлось. **Не сошлось** из-за `Department`.

**3. Значения.** У `Shipment.status` 3 значения через `|`, в блоке 3 строки с токенами `NEW`/`ASSIGNED`/`DELIVERED` — сошлось. У `Department.kind` 2 значения, в блоке 2 строки с `BRANCH`/`HQ` — формально тоже сошлось, но сам блок существовать не должен (см. п.2), так что это совпадение — по несуществующей сущности.

**4. Код.** По всем строкам секции: ни ` /[a-z]`, ни HTTP-глаголов, ни camelCase, ни путей с двумя+ точками; в заголовках сообщения и ограничения бэктиков нет. Сошлось.

**5. Хозяин.** Единственное ограничение «приём отправлений партнёра отключён» отдано `partner-registry` — это сосед из манифеста (`shipping`, `partner-registry`, `dispatch-web`), не «настройка» и не голый флаг. Сошлось.

**1. Ключи.** Все три заголовка в «Бизнес-правилах» — `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — верной формы, по одному блоку объекта на сущность. Сошлось.

**2. Состав.** Опись: 1 строка `состояние:` → 1 блок объекта (`Shipment`) — сошлось. 1 строка `сообщение:` и 1 `публикует` в «Событиях» → 1 блок сообщения (1 ≥ 1 и 1 ≥ 1) — сошлось. 1 строка `ограничение:` → 1 блок ограничения — сошлось. Оба перечисления сущности `Shipment` (state) учтены, справочники (`Shipment.packageType`, `Attachment.kind`) блоков не имеют — верно. Сошлось.

**3. Значения.** В блоке `Shipment` 4 строки на 3 объявленных значения (NEW|ASSIGNED|DELIVERED) — по счёту сошлось (не меньше). Но строка «перевешено (`ASSIGNED`, `weightKg` изменён)» несёт токен `weightKg` — это имя поля, а не значение перечисления и не дата; вдобавок это два токена в строке через запятую (`ASSIGNED`, `weightKg` изменён) — справочник/условие, записанное состоянием. Не сошлось.

**4. Код.** Та же строка содержит `weightKg` — camelCase-идентификатор (`\b[a-z]+[A-Z][A-Za-z]*\b`). Заголовки сообщений и ограничений без бэктиков — в остальном чисто, но эта строка не проходит. Не сошлось.

**5. Хозяин.** Ограничение «приём отправлений партнёра отключён» — хозяин `partner-registry`, есть в манифесте (shipping, partner-registry, dispatch-web), не конфиг и не флаг. Сошлось.

ГЕЙТ: ДОБОР — строка «перевешено (`ASSIGNED`, `weightKg` изменён)» в блоке `Shipment`: это не объявленное в описи значение, токен — имя поля вместо значения перечисления/даты, два токена через запятую (справочник, записанный как состояние), плюс код-идентификатор `weightKg` в тексте секции. Требую убрать эту строку (или переписать без имени поля и без второго токена) и прислать раздел «Бизнес-правила» целиком заново — ответ добора проходит все пять проверок гейта, а не только 3 и 4.

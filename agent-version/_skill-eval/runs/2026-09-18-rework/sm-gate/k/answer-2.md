**1. Ключи.** Опись даёт одну сущность (`Shipment`) и должна получить блок вида `### \`Shipment\` — ...`. В карточке заголовок — `### Отправление (\`Shipment\`)`: перед именем сущности в бэктиках стоит подпись «Отправление». Это ровно случай «подпись впереди ключа» из перечня — не сходится.

**2. Состав.** Строк `состояние:` — 1 (Shipment), блок объекта в карточке — 1. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1, блок сообщения в карточке — 1. Строк `ограничение:` — 1, блок ограничения — 1. По количеству всё сходится; лишних перечислений своей сущности без строки в описи не нашёл (Attachment — справочник, блока не требует).

**3. Значения.** У `status` три значения через `|` в строке `- поле:` — сходится. Блок `Shipment` содержит три строки (NEW/ASSIGNED/DELIVERED), не меньше трёх значений — сходится. Каждый токен строки — одно из значений в бэктиках, двойных токенов через `/`, `|`, запятую нет — сходится.

Код.** Прогнал все четыре регекса и проверку бэктика в заголовке сообщения по строкам секции «Бизнес-правила»: `NEW`/`ASSIGNED`/`DELIVERED` — не camelCase (заглавные буквы полностью), `shipment.delivered` — один разделитель, не два, под `\b[a-z]+(\.[a-z-]+){2,}\b` не попадает, HTTP-глаголов и ` /[a-z]` нет, заголовок сообщения без бэктиков — сходится.

**5. Хозяин.** В блоке ограничения — `partner-registry`, это сосед из манифеста (shipping, partner-registry, dispatch-web); `true`/`false` в блоке нет — сходится.

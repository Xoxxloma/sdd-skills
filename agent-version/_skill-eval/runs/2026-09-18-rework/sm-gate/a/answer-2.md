**1. Ключи.** Все `###` в секции — либо имя сущности в бэктиках (`Shipment`), либо «сообщение «...»», либо «ограничение «...»»; лишних форм (письмо/событие/подпись впереди/Сущность.поле) нет. Сошлось.

**2. Состав.** В описи две строки `состояние:` (`Shipment`, `Courier`) — значит блоков объектов должно быть 2, а в карточке блок объекта только один (`Shipment`); `Courier` со значениями `ACTIVE`/`BLOCKED` в «Бизнес-правилах» отсутствует. Сообщений (1) и ограничений (1) — по числу строк описи, здесь сошлось. Не сошлось из-за пропавшего блока `Courier`.

**3. Значения.** У блока `Shipment` — 3 значения в описи (`NEW|ASSIGNED|DELIVERED`), в карточке 3 строки с этими же токенами в скобках рядом с русским названием, дублей и посторонних токенов нет. Для отсутствующего блока `Courier` проверить нечего — тянется из п.2. По имеющемуся блоку сошлось.

**4. Код.** По всем строкам секции (`Shipment`, сообщение, ограничение) не найдено ни ` /[a-z]`, ни HTTP-глаголов, ни camelCase, ни точечных цепочек из трёх сегментов (`shipment.delivered` — только два сегмента, под правило не попадает), бэктиков в заголовке сообщения нет. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя соседа из манифеста, не «настройка»/флаг. Сошлось.

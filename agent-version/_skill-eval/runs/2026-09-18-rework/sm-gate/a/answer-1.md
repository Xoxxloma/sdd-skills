**1. Ключи.** Три заголовка в разделе: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все начинаются как положено (сущность в бэктиках / `сообщение «` / `ограничение «`), дублей объектных блоков нет. Сошлось.

**2. Состав.** В описи две строки `состояние:` (Shipment, Courier) ⟹ в разделе должно быть 2 объектных блока. В карточке — только блок `Shipment`; блока `Courier` нет вовсе, хотя `Courier.status ACTIVE | BLOCKED` в «Владеет данными» есть и в опись как состояние заявлен. Сообщений: 1 строка `сообщение:` = 1 блок `публикует` в «Событиях» = 1 блок в правилах — сошлось. Ограничений: 1 = 1 — сошлось. Не сошлось из-за Courier.

**3. Значения.** Для блока `Shipment` — 3 значения в `- status:` (NEW|ASSIGNED|DELIVERED), в блоке 3 строки, в каждой ровно один токен-значение в бэктиках рядом с переводом, дублей через `/`,`|`,`,` нет — сошлось. Для `Courier` проверить нечего — блока нет (см. п.2).

**4. Код.** Строки раздела просканированы на все пять паттернов и бэктики в заголовке сообщения: путей (` /[a-z]`), HTTP-глаголов, camelCase, точечных цепочек из 2+ сегментов — нет ни одного совпадения (`shipment.delivered` — только один `.`, под паттерн `{2,}` не попадает); заголовок сообщения без бэктиков. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя есть в манифесте соседей; не флаг, не «настройка». Сошлось.

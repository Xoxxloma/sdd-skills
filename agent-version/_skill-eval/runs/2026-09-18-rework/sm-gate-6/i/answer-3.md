**1. Ключи.** Три `###` в «Бизнес-правилах»: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, ровно один блок объекта на сущность. Сошлось.

**2. Состав.** Блоков объектов — 1, строк `состояние:` в описи — 1 (`Shipment`). Сообщений в карточке — 1, строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1. Ограничений — 1, строк `ограничение:` — 1. Чужих сущностей и справочников в секции нет — верно, им блоков не положено. Сошлось.

**3. Значения.** Секция «Владеет данными» для `Shipment` оформлена таблицей `| Поле | Тип | Описание |`, а не строками `- поле: тип` — прямое нарушение формы, добор нужен раньше всего остального. (Для `Attachment` форма верная — `- kind: PHOTO | PDF`.) Внутри блока `Shipment` в «Бизнес-правилах» — 3 строки на 3 значения статуса, токены (`NEW`/`ASSIGNED`/`DELIVERED`) корректны, но это уже не спасает: форма описи нарушена раньше.

**4. Код.** Вне бэктиков в блоках секции — только слова («создаёт диспетчер», «курьер отмечает вручение» и т. п.), кода нет. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), топик (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`); в заголовке сообщения бэктиков нет. Сошлось.

**5. Хозяин.** В блоке ограничения — `partner-registry`, это имя соседа из манифеста, не конфиг и не голый флаг. Сошлось.

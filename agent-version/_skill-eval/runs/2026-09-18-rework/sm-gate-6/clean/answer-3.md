**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Опись: 1 строка `состояние:` (Shipment.status) → 1 блок-сущность в карточке — есть только `Shipment`. Сообщений: 1 строка `сообщение:` и 1 блок `публикует` (`shipment.delivered`) → 1 блок сообщения в карточке — есть. Ограничений: 1 строка `ограничение:` → 1 блок — есть. Перечисления `packageType` и `kind` в описи поименованы справочниками и блоков не получили — верно. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. У всех трёх перечислений значения через `|` в строке `- поле:`. Блок `Shipment`: строка `состояние:` даёт 3 значения (NEW|ASSIGNED|DELIVERED), в блоке ровно 3 строки, на каждой — один токен, совпадающий со значением (`NEW`, `ASSIGNED`, `DELIVERED`), дублей правил и посторонних имён полей нет. Сошлось.

**4. Код.** Вне бэктиков во всех строках секции — только текст, ни путей, ни HTTP-глаголов, ни camelCase, ни составных `a.b.c`. В бэктиках: значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя соседа из манифеста (`partner-registry`) — всё разрешённые категории. В заголовках сообщения и ограничения бэктиков нет. Сошлось.

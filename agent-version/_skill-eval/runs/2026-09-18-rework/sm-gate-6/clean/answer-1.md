**1. Ключи.** Заголовки секции: `` ### `Shipment` `` , `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»` — все три формы разрешены, блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Блоков объектов 1 = строк `состояние:` в описи (1). Сообщений 1 = строк `сообщение:` (1) = блоков `публикует` в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). `Attachment` и оба справочника (`packageType`, `Attachment.kind`) блоков не имеют — верно, они не состояния. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Перечисления через `|`. В блоке `Shipment` — 3 строки на 3 значения `состояние:` (`NEW`→новое, `ASSIGNED`→назначено, `DELIVERED`→доставлено), по одному токену в бэктиках на строку, дублей правила нет, `не определено` не нужен — все значения покрыты. Сошлось.

**4. Код.** Вне бэктиков — только слова (диспетчер, курьер, партнёр и т.д.), ни путей, ни HTTP-глаголов, ни camelCase, ни точечных цепочек. В бэктиках — только `NEW`/`ASSIGNED`/`DELIVERED`, топик `shipment.delivered` (в конце строки сообщения) и имя сервиса `partner-registry` из манифеста. В заголовке сообщения бэктиков нет. Сошлось.

**5. Хозяин.** В блоке ограничения хозяин — `partner-registry`, это имя сервиса из манифеста, а не «настройка» и не голый флаг. Сошлось.

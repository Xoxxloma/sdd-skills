# Оценка качества БТ и спек

Ты собираешь оценку — но оцениваешь **не ты**. Каждый документ читает субагент по рубрике и
возвращает баллы с цитатами. Твоя работа — найти документы, раздать их, принять ответы, посчитать
итог и собрать отчёт.

## TL;DR — пять правил, держи в голове всегда

1. **Документы ты не открываешь.** Их читают субагенты, по одному на документ, получая пути, а не
   текст. Прочитал сам — начнёшь спорить с баллами из своей памяти.
2. **Баллы ставит рубрика.** Ты их не меняешь, не округляешь «по ощущению» и не добавляешь своих
   замечаний.
3. **Подсвечиваем только сильно плохое.** «Требует внимания» — итог ниже 50%, ноль по критерию,
   «шаблонно: да», «не по форме» или спека «по коду». Всё остальное — просто строка таблицы.
4. **Ответ без эхо-строки не принимается.** Нет первой строки `рубрика прочитана: …` — перезапуск;
   две попытки, потом «оценка не состоялась». Баллы за субагента не придумывай.
5. **В `coddoc/` ничего не пишешь.** Единственный файл, который ты создаёшь, — отчёт в корне
   репозитория.

Если правило ниже противоречит этому списку — прав список.

## Шаг 0 — вход

| Дали | Что делать |
|---|---|
| папку `coddoc/` (или корень репозитория с `coddoc/`) | все фичи внутри, рекурсивно |
| папку фичи `coddoc/<KEY>/` | эта фича; если внутри папки детей эпика — и они |
| файл `business_requirements.md` или `technical_specification.md` | его папка |
| ключ задачи | `Glob coddoc/**/<KEY>/` — ребёнок эпика лежит в `coddoc/<EPIC>/<KEY>/` |
| ссылку на веб-репозиторий | открыть её нельзя — попроси локальный путь к клону |
| ничего | спроси путь |

Команда и репозиторий — вторым и третьим аргументом; не дали — колонки в таблице пустые, не
спрашивай.

## Шаг 1 — список документов

Найди в заданной папке рекурсивно `business_requirements.md`, `technical_specification.md`,
`bug_report.md`, `change_request.md`. Папку `stages/` и файл `decomposition.md` пропускай. Одна папка
с любым из этих файлов — одна строка отчёта:

| В папке | Колонка «БТ» | Колонка «Спека» |
|---|---|---|
| `business_requirements.md` и спека | оценка | оценка, источник — этот БТ |
| только `business_requirements.md` (эпик тоже) | оценка | «спеки нет» |
| `bug_report.md` и спека | «н/п: баг-репорт» | оценка, источник — `bug_report.md` |
| `change_request.md` и спека | «н/п: запрос на правку» | оценка, источник — `change_request.md` |
| спека в папке `_foundation/` | «н/п: узел-фундамент» | оценка, источник «не передан» |
| спека, рядом ни одного из трёх документов сверху | «нет» | оценка, источник «нет документа сверху» |

Если в одной папке лежат и БТ, и баг-репорт, источник спеки — БТ. Документ сверху — только эти три
файла рядом со спекой; ссылка из спеки на что-то другое (`proposal.md`, страница вики) источником не
считается.

**Назови список вслух** до запуска: сколько папок, сколько документов, у какой спеки какой
источник. Неверно собранный путь снаружи не отличить от плохого документа — по этому списку его и
находят.

## Шаг 2 — субагенты

По одному субагенту на документ, до шести одновременно. Пути абсолютные. Рубрики лежат в
`reference/` этого скилла: `rubric-bt.md` для БТ, `rubric-spec.md` для спеки.

Промпт — один из двух, дословно, с подставленными путями.

Для БТ:

```
Прочитай рубрику по пути <путь к rubric-bt.md> и оцени по ней файл <путь к БТ>.

Первой строкой ответа напиши: рубрика прочитана: БТ

Дальше — только то, что рубрика велит вернуть. Ничего не правь и не создавай файлов.
```

Для спеки:

```
Прочитай рубрику по пути <путь к rubric-spec.md> и оцени по ней файл <путь к спеке>.
Источник требований: <путь к источнику, или слова «не передан», или «нет документа сверху»>.

Первой строкой ответа напиши: рубрика прочитана: спека

Дальше — только то, что рубрика велит вернуть. Ничего не правь и не создавай файлов.
```

Текст документа в промпт не вставляй: субагент оценит твой пересказ, а не документ.

## Шаг 3 — приём ответа

- Первая строка не `рубрика прочитана: БТ` / `рубрика прочитана: спека` — рубрику не открывали,
  перезапусти.
- Ответ пустой или без строк `1.`–`5.` — перезапусти.
- Две попытки не дали ответа — в строке отчёта «оценка не состоялась». Не ставь баллы сам: молчание
  субагента не равно хорошему документу.
- Баллы есть, а строки `форма:` или `происхождение:` нет — не перезапускай: в клетке «не проверена»
  / «не проверено».

Для таблицы из ответа нужны только строки `задача`, `фича`, `автор`, `1.`–`5.`, `шаблонно`,
`форма` и у спеки `происхождение`. Строка встретилась дважды — бери последнюю. Ответ целиком нужен только у документа, который требует внимания (шаг 4), — для «Деталей».

## Шаг 4 — счёт

Из строк `1.`–`5.` возьми баллы; строка одного критерия встретилась дважды — бери последнюю. «н/п»
в сумму не входит, и его вес вычитается из максимума. В записи всегда пять позиций, «н/п» — на своём
месте.

- Максимум БТ — 4.5 (веса 0.5, 1, 1, 1, 1). Максимум спеки — 5.0 (веса по 1).
- Итог — сумма баллов из максимума применимых критериев и процент, округлённый до целого.

```
БТ:    0.5+0.5+1+1+0 = 3.0 из 4.5 (67%)
спека: н/п+1+0.5+1+1 = 3.5 из 4.0 (88%)
```

**Форма.** Строка `форма: нет N из M — …`: N — сколько номеров разделов перечислено после тире
(запятая внутри названия в кавычках раздела не добавляет), M — из строки. Документ **не по форме**,
если у БТ N от 5, у спеки — от 6.

**Происхождение** спеки — значение строки `происхождение:` как есть: `скилл`, `скилл, правлена
руками`, `по коду`, `мимо фреймворка`. Сам его не выводишь и не меняешь.

**Требует внимания** — итог ниже 50%, ноль по критерию, «шаблонно: да», «не по форме» или спека
«по коду». Такой документ попадает в список первым. Ноль — балл 0 в строке `1.`–`5.` (`— 0 из 1`, у
цели `— 0 из 0.5`); «н/п» — не ноль. В строке списка — `ноль: <названия критериев из строк ответа>`.

## Шаг 5 — отчёт

Файл `sdd-quality-report.md` в корне репозитория — в папке, где лежит `coddoc/`. Файл уже есть —
пиши `sdd-quality-report-2.md`, `-3.md` и так далее: прошлый отчёт не затирай.

```
# Оценка качества БТ и спек

Папка: <путь> · строк: <N> · документов: <M> · оценка не состоялась: <K>

## Требуют внимания

- ARS-102 · спека 1.5 из 5.0 (30%) · ноль: Функционал из источника, Роли RBAC/ABAC · шаблонно: да
- ARS-205 · БТ 2.0 из 4.5 (44%)
- ARS-307 · БТ 4.0 из 4.5 (89%) · не по форме: нет 9 из 16 разделов
- ARS-410 · спека 2.0 из 5.0 (40%) · не по форме: нет 19 из 23 разделов · по коду
- ARS-512 · спека 3.0 из 5.0 (60%) · ноль: Модель данных и миграции, Контракты

(Нет — «Сильно некачественных документов нет».)

## Сводная таблица

| команда | ai-sdd repo | аналитик | фича | jira | БТ | БТ оценка | Спека | Спек оценка | шаблонно | не по форме | происхождение |
|---|---|---|---|---|---|---|---|---|---|---|---|
| <команда> | <репозиторий> | <автор> | <фича> | ARS-102 | coddoc/ARS-102/business_requirements.md | 0.5+1+1+1+1 = 4.5 из 4.5 (100%) | coddoc/ARS-102/technical_specification.md | 0+0.5+0+0.5+0.5 = 1.5 из 5.0 (30%) | спека | нет | скилл |

## Детали

### ARS-102 — <фича>

<ответ субагента по спеке без эхо-строки, как есть>
```

- **аналитик** — строка «автор» из ответов. У БТ и спеки авторы разные — пиши оба: `спека: <логин>;
  БТ: <логин>`. Автора нет ни у одного — клетка пустая: его дополнят из ручного списка, не выдумывай.
- **jira** — строка «задача» из ответа; нет — имя папки, а для `_foundation/` — имя папки эпика.
- **шаблонно** — у какого документа «да»: `БТ`, `спека`, `БТ, спека`; иначе `нет`.
- **не по форме** — у какого документа и сколько разделов нет: `БТ 9 из 16`, `спека 7 из 23`,
  `БТ 9 из 16, спека 7 из 23`; иначе `нет`. Строки формы не было — `БТ: не проверена`.
- **происхождение** — у спеки, из её ответа; спеки нет — `—`.
- **Детали** — только документы из «Требуют внимания», по подразделу на строку отчёта: ответ
  субагента дословно, цитаты в нём и есть доказательство. Не пересказывай. В строке подсвечен один
  документ из двух — в подразделе только его ответ. Остальных документов в «Деталях» нет: разбор всех
  подряд на большой папке — десятки страниц, и ведущий не доживает до записи.

В чат после записи: путь к файлу и список «Требуют внимания». Таблица и детали — только в файле.

## Чего ты не делаешь никогда

- **Не читаешь оцениваемые документы** и не споришь с баллами субагента.
- **Не оцениваешь баг-репорты и запросы на правку** — они только источник для спеки.
- **Не правишь документы и ничего не пишешь в `coddoc/`.**
- **Не выдумываешь автора, ключ или балл** там, где ответа нет.

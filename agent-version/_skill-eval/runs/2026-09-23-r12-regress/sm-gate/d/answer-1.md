**1. Ключи.** Заголовки секции: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены (имя сущности в бэктиках / `сообщение «` / `ограничение «`). Сошлось.

**2. Состав.** Опись: состояний 1 → блок объекта 1 (`Shipment`) — сошлось. Сообщений 1 в описи, `публикует` в «Событиях» 1 → блок сообщения 1 — сошлось. Ограничений 1 → блок ограничения 1 — сошлось. `Attachment` — справочник (не состояние), блока не получил — верно, справочнику блок не положен.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Все перечисления через `|`. Блок `Shipment` в «Бизнес-правилах»: 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), токен каждой строки — значение из перечня, других имён полей нет. Сошлось.

**4. Код.** Пять грепов по секции «Бизнес-правила» вне бэктиков — Cyrillic-текст, совпадений с ` /[a-z]`, `GET|POST|PUT|PATCH|DELETE`, camelCase, точечным ключом нет. В бэктиках — только значения состояния и топик `shipment.delivered`; в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** Опись: `ограничение: приём отправлений отключён — integration/PartnerGate.kt` — строка не содержит `переключатель: <имя>` вовсе (нарушение уже на Шаге 3). Блок карточки: «пока условие действует, новые отправления не принимаются, диспетчер видит причину отказа» — назван только тот, кто *видит* отказ (`DISPATCHER`), а не тот, кто условие включает/выключает. Ни имени из манифеста (`shipping`/`partner-registry`/`dispatch-web`), ни роли-инициатора в блоке нет. Не сошлось.

ГЕЙТ: ДОБОР — в блоке `ограничение «приём отправлений партнёра отключён»` назвать переключатель (кто включает/выключает условие) — имя ровно из манифеста (`shipping` | `partner-registry` | `dispatch-web`) либо роль из «Роли и доступ» этой карточки; правку внести в ОБА файла: строку `ограничение:` в описи (добавить `переключатель: <имя>`) и блок в черновике карточки.

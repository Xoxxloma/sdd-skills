**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «...»» — все три формы разрешены, один блок на сущность. Сошлось.

**2. Состав.** Состояние в описи — 1 сущность (Shipment) → 1 блок объекта в карточке, есть. Сообщений в описи — 1, блоков `публикует` в «Событиях» — 1, в карточке блок сообщения — 1 (1≥1, 1≥1). Ограничений в описи — 1, в карточке — 1. Attachment — только справочник (kind), своего блока не имеет, как и положено. Сошлось.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица. У `Shipment.status` в описи 3 значения (NEW|ASSIGNED|DELIVERED) — в блоке ровно 3 строки, по одному токену на значение, дубликатов правила на разных значениях нет. Сошлось.

**4. Код.** По всем четырём грепам вне бэктиков в секции «Бизнес-правила» совпадений нет; в бэктиках — только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`) и имя топика (`shipment.delivered`). Сошлось.

**5. Переключатель.** В описи: `ограничение: приём отправлений отключён — переключатель: partner-registry`. В блоке карточки «ограничение «приём отправлений партнёра отключён»» переключатель вообще не назван — упомянут только «диспетчер», но как наблюдатель («видит причину отказа»), а не как включатель/выключатель условия; `partner-registry` из манифеста в блоке отсутствует. Не сошлось.

ГЕЙТ: ДОБОР — в блоке «ограничение «приём отправлений [партнёра] отключён»» назвать переключатель условия дословно по описи (`partner-registry` — имя из манифеста) вместо текущего упоминания диспетчера как наблюдателя; заголовок блока привести к формулировке из описи («приём отправлений отключён», без слова «партнёра», если это не отдельный факт из кода).

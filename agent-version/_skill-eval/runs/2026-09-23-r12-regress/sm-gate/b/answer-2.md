**1. Ключи.** Три заголовка секции: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три в допустимой форме (сущность в бэктиках / «сообщение «» / «ограничение «»). Нарушений нет.

**2. Состав.** Блоков объектов должно быть столько, сколько сущностей в строках `состояние:` — в описи 1 (`Shipment`), в карточке 1 блок. Сообщений: опись 1 строка `сообщение:` / карточка 1 блок публикует / карточка 1 блок правила — сходится. Ограничений: 1/1 — сходится. Но в «Владеет данными» у `Shipment` есть перечисление `priority: NORMAL | URGENT`, которого нет в описи ни как `состояние:`, ни как `справочник:` (в описи справочника у `Shipment` только один — `packageType`, итог `⟹ справочников 2` их не считает). Это прямое совпадение с пунктом «перечисление своей сущности, не названное в описи ни состоянием, ни справочником, — пропущено». **Расхождение.**

**3. Значения.** Блок `Shipment` в «Бизнес-правилах» даёт ровно 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), без дублей правила на разных значениях, без табличной формы. Сходится.

**4. Код.** По секции «Бизнес-правила» вне бэктиков — ни одного совпадения с четырьмя грепами (глаголы, camelCase, точечные ключи, `/путь`); внутри бэктиков только значения перечисления и имя `partner-registry` из манифеста. Заголовок сообщения без бэктиков. Сходится.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сходится.

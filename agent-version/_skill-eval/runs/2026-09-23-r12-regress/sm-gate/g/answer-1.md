## Гейт «Бизнес-правила» — сервис `shipping`

**1. Ключи.** Три `###`: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один на сущность (только `Shipment`). Сошлось.

**2. Состав.** Опись: состояний 1 → блоков объектов в карточке 1 (`Shipment`) — сошлось. Сообщений 1 (строка описи) и 1 `публикует` в «Событиях» → блок сообщения 1 — сошлось. Ограничений 1 → блок 1 — сошлось. Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не получили — верно, справочник блока не имеет.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица — ок. В блоке `Shipment` состояние с 3 значениями (`NEW`/`ASSIGNED`/`DELIVERED`), бэллетов 4 ≥ 3 — по числу сошлось бы, но третья строка «перевешено (`ASSIGNED`, `weightKg` изменён)» токеном несёт не значение перечисления и не дату-исключение, а имя поля `weightKg` — по правилу это «любое другое имя поля — строка на поле, добор». Расхождение.

**4. Код.** Вне бэктиков секции — чисто. В бэктиках допустимы только значение перечисления/имя вида/топика/сервиса/дата-исключение; `` `weightKg` `` — имя поля, в бэктики этой секции не допускается ни при каких условиях. Расхождение (тот же токен, что и в п.3).

**5. Переключатель.** «управляет `partner-registry`» — имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — перечень для субагента: строка `- перевешено (\`ASSIGNED\`, \`weightKg\` изменён)` в блоке `### \`Shipment\`` секции «Бизнес-правила»: токен `weightKg` — имя поля, не значение состояния и не дата-исключение; переписать без имени поля в бэктиках (только один из токенов `NEW`/`ASSIGNED`/`DELIVERED`, либо снять строку, если факт не выражается значением состояния) — правка только этой строки в `<черновик>`, число значений в строке `состояние:` описи трогать не нужно (изменение состава ключей отсутствует).

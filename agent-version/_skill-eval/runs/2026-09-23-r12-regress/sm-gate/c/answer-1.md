**1. Ключи.** Заголовки секции — `` `Shipment` ``, `` `Department` ``, `сообщение «груз доставлен»`, `ограничение «...»` — все в верной форме, бэктиков в заголовках сообщения/ограничения нет. Сошлось.

**2. Состав.** Опись даёт `состояний 2` (`Shipment`, `Department`), в карточке 2 блока — но в «Владеет данными» сам `Department` подписан «(схема partner-registry, на чтение)» — это чужая сущность, а по правилу «чужая сущность... блока не имеет». Настоящих «своих» состояний — 1 (`Shipment`). Сообщений: опись 1, блок 1, `публикует` в «Событиях» 1 — сошлось. Ограничений: опись 1, блок 1 — сошлось. Справочники (`packageType`, `Attachment.kind`) блоков не получили — верно. Не сошлось по `Department`.

**3. Значения.** `Shipment`: 3 значения статуса ↔ 3 строки-состояния в блоке, форма `- поле: A | B | C` в «Владеет данными» соблюдена. `Department`: 2/2, форма тоже соблюдена — но сам блок не должен существовать (см. п.2).

**4. Код.** Пять грепов по тексту секции вне бэктиков (HTTP-глаголы, `/путь`, camelCase, точечные ключи) — совпадений нет; в бэктиках только значения перечислений (`NEW`, `BRANCH`...), имя топика `shipment.delivered`, имя сервиса `partner-registry` — всё допустимо. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

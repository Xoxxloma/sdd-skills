**2. Состав** — строк `состояние:` в описи: 2 (Shipment, Department) → блоков в карточке: 2. Числа равны, но `Department` в самой карточке подписан «схема partner-registry, на чтение» — то есть чужая сущность. По правилу «чужая сущность… в «Владеет данными» не стоит, строки в описи не получает» и «чужая сущность… блока не имеет» этой строки `состояние:` и этого блока не должно быть вовсе — числа совпали формально, но за счёт лишней сущности. Не сошлось. 
Сообщений: строк `сообщение:`=1, `публикует` в «Событиях»=1, блоков=1 — сошлось. 
Ограничений: строк `ограничение:`=1, блоков=1 — сошлось.

**3. Значения** — «Владеет данными» в форме `- поле: тип`, не таблица. Shipment: 3 значения статуса / 3 строки правил — сошлось. Department: 2 значения / 2 строки — форма верна, но сама сущность лишняя (см. п.2).

**4. Код** — вне бэктиков нет пути, HTTP-глагола, camelCase или точечного ключа; в бэктиках только значения перечислений, имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

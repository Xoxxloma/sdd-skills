**1. Ключи.** Опись даёт 3 ключевых строки бизнес-правил (Shipment, сообщение, ограничение). В карточке три `###`: `` `Shipment` `` — верно; `` ограничение «приём отправлений партнёра отключён» `` — верно; но заголовок сообщения — `### письмо «груз доставлен»`, а должен начинаться с `сообщение «`. «Письмо» прямо названо в гейте как пример неверного заголовка. **Не сошлось.**

**2. Состав.** Блоков объектов 1 (`Shipment`) = 1 строка `состояние:` в описи — сошлось. Сообщений в карточке 1, строк `сообщение:` в описи 1, блоков `публикует` в «Событиях» 1 — 1≥1 и 1≥1, сошлось. Ограничений 1 = 1 строка `ограничение:` — сошлось. Attachment (справочник) блока не получил — верно, справочники блока не имеют.

**3. Значения.** «Владеет данными» в форме `- поле: тип`, не таблица — ок. У `status` 3 значения через `|`, блок `Shipment` даёт 3 строки (NEW/ASSIGNED/DELIVERED), по одной на значение, без дублей и слияний — сошлось.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет путей, HTTP-глаголов, camelCase, точечных ключей. В бэктиках встречаются только значения перечислений, топик `shipment.delivered` и имя сервиса `partner-registry` из манифеста — допустимо. **Сошлось.**

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). **Сошлось.**

**1. Ключи.** Блок должен начинаться с `сообщение «...»`/`ограничение «...»`/сущность в бэктиках. Заголовок `### письмо «груз доставлен»` использует запрещённый вариант «письмо» вместо `сообщение «груз доставлен»` (opись говорит `сообщение:`). Блок `### `Shipment`` и `### ограничение «приём отправлений партнёра отключён»` — в форме. Не сошлось.

**2. Состав.** Опись: состояний 1 → карточка даёт 1 блок сущности (`Shipment`). Опись: сообщений 1, событий-публикаций 1 → карточка даёт 1 блок сообщения (пусть и не под тем заголовком) и 1 `публикует shipment.delivered`. Опись: ограничений 1 → карточка даёт 1 блок. Справочники (`packageType`, `kind`) своих блоков не имеют — верно. По числам сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. В блоке `Shipment` 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), без «не определено»-заполнителей и без сдвоенных токенов в одной строке. Сошлось.

**4. Код.** Вне бэктиков в строках секции «Бизнес-правила» ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей конфига — не нашёл. В бэктиках только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса (`partner-registry`) — допустимо. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

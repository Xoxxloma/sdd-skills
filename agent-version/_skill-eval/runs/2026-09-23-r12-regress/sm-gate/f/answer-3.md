**1. Ключи.** Блок `Shipment` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы заголовков верны, блок один на сущность. Сошлось.

**2. Состав.** Строка `состояние:` одна (Shipment) → блоков объектов должно быть 1, в карточке 1 (`Shipment`); справочники (packageType, Attachment.kind) своих блоков не имеют — верно. `сообщение:` 1 строка = 1 блок `публикует` в «Событиях» = 1 блок в «Бизнес-правилах» — сошлось. `ограничение:` 1 строка = 1 блок — сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица, ок. В блоке `Shipment` четыре строки при трёх значениях состояния (NEW/ASSIGNED/DELIVERED) — по числу проходит, но четвёртая строка «тип упаковки (`BOX` / `PALLET`) — задаётся при создании» несёт два токена через `/` в одной строке и относится к полю `packageType`, а не к `status`. Это ровно случай «два токена в одной строке через `/` — справочник, записанный состоянием» и «любое другое имя поля — строка на поле» — расхождение.

**4. Код.** Вне бэктиков во всей секции нет пути, HTTP-глагола, camelCase-имени или точечного ключа; в бэктиках — только значения перечислений, топик `shipment.delivered` и имя сервиса `partner-registry` из манифеста; в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** «условием управляет `partner-registry`» — имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — убрать из блока `Shipment` в «Бизнес-правилах» строку «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: это справочник `Shipment.packageType`, записанный как значение состояния (два токена через `/` в строке блока `status`); справочник блока не имеет и не должен давать строку внутри блока состояния.

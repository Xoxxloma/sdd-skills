**1. Ключи.** Заголовки секции: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок один на сущность. Сошлось.

**2. Состав.** Опись: 1 строка `состояние:` → 1 блок-объект (`Shipment`) в карточке — сошлось. 1 строка `сообщение:` и 1 `публикует` в «Событиях» → 1 блок сообщения — сошлось. 1 строка `ограничение:` → 1 блок ограничения — сошлось. Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не имеют — верно по правилу.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица — сошлось. Блок `Shipment` в «Бизнес-правилах»: на 3 значения `status` (NEW/ASSIGNED/DELIVERED) — 3 отдельные строки, по одной на значение — формально хватает. Но добавлена четвёртая строка «тип упаковки (`BOX` / `PALLET`) — задаётся при создании» — два токена в одной строке через `/`, это справочник (`packageType`), записанный как состояние. **Не сошлось.**

**4. Код.** Вне бэктиков секции — ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей. В бэктиках — только значения перечисления, топик и имя сервиса из манифеста. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

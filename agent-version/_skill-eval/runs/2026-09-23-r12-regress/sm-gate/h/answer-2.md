Прогнал гейт «Бизнес-правила» по карточке `shipping`.

1. **Ключи.** Три `###`: `` `Shipment` — отправление``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы допустимы, блок объекта один (на `Shipment`). Сошлось.

2. **Состав.** Опись: 1 строка `состояние:` → 1 блок `` `Shipment` `` в карточке. 1 строка `сообщение:` и 1 блок `публикует shipment.delivered` в «Событиях» → 1 блок сообщения в карточке. 1 строка `ограничение:` → 1 блок ограничения. Оба справочника (`packageType`, `Attachment.kind`) блоков не имеют — верно, справочники их не получают. Сошлось.

3. **Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. У `status`, `packageType`, `kind` значения через `|`. В блоке `Shipment` 4 строки на 3 значения состояния (NEW, ASSIGNED, DELIVERED); повтор `ASSIGNED` во второй строке — законное исключение «дата в скобках рядом с токеном» (`` `ASSIGNED`, `assignedAt` сдвинут``), а не заполнитель — правила для двух строк на этом значении разные (первое назначение / смена курьера). Других имён полей вне этой формы нет. Сошлось.

4. **Код.** Вне бэктиков — только русская проза, латинских слов нет, ни одного совпадения с ` /[a-z]`, `GET|POST|...`, camelCase, точечным путём. В бэктиках — только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), топик (`shipment.delivered`), имя сервиса из манифеста (`partner-registry`) и допустимая дата-пара (`assignedAt` в скобках-исключении). Заголовок сообщения без бэктиков. Сошлось.

5. **Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

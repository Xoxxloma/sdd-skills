Прогнал пять грепов гейта «Бизнес-правила» по ответу.

1. **Ключи.** Заголовки: `` `Shipment` — отправление ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один (только `Shipment`). Сошлось.

2. **Состав.** Опись даёт: состояний 1 (Shipment), сообщений 1, ограничений 1. В карточке: 1 блок сущности (Shipment), 1 блок сообщения (совпадает и со строкой `сообщение:`, и с блоком `публикует shipment.delivered` в «Событиях»), 1 блок ограничения. `Attachment` (справочник) блока не имеет — верно, справочники блоков не получают. Сошлось.

3. **Значения.** Форма «Владеет данными» — строками `- поле: тип`, не таблица — ок. Но: `packageType` и `kind` (справочники) корректно дают значения через `|` (`BOX` | `PALLET`, `PHOTO` | `PDF`), а вот `status` — своё состояние из строки `состояние:` с тремя значениями NEW | ASSIGNED | DELIVERED — записан как `` `ShipmentStatus` — перечисление ``: это тип **без перечисленных значений**, а не значения через `|`. Блок «Бизнес-правил» по `Shipment` при этом верно даёт 3 строки на 3 значения (NEW/ASSIGNED/DELIVERED, без дублей и заполнителей) — но несостыковка идёт именно с «Владеет данными». **Не сошлось.**

4. **Код.** Вне бэктиков — ни путей, ни глаголов HTTP, ни camelCase, ни точечных ключей (кириллица не матчится латинскими классами). В бэктиках — только значения (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

5. **Переключатель.** Ограничение называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

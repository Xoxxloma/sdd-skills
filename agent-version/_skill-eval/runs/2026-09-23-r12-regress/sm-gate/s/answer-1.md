**1. Ключи.** Три заголовка секции: `` `Shipment` `` — отправление, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все в одной из трёх разрешённых форм (сущность в бэктиках / «сообщение «» / «ограничение «»). Сошлось.

**2. Состав.** В описи: `состояние:` — 1 строка (Shipment) → блоков объектов должен быть 1, в карточке 1 блок (`Shipment`). `сообщение:` — 1 строка в описи, `публикует` в «Событиях» — 1 блок, в «Бизнес-правилах» — 1 блок сообщения. `ограничение:` — 1 строка в описи, 1 блок в карточке. Attachment (справочник, не состояние) блока не получил — верно. Сошлось.

**3. Значения.** Форма «Владеет данными» — списком `- поле: тип`, не таблицей — ок. Но у перечисления `status` строка `` - `status`: `ShipmentStatus` — перечисление `` даёт только имя типа без значений через `|` (в отличие от `packageType`: `` `BOX` | `PALLET` `` и `kind`: `` `PHOTO` | `PDF` ``, которые оформлены верно). Правило прямое: «тип без значений — добор». Не сошлось.

**4. Код.** Вне бэктиков в «Бизнес-правилах» нет путей, HTTP-глаголов, camelCase и точечных ключей; в бэктиках — только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`); в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — в файле карточки, секция «Владеет данными», блок `Shipment`: строка `` - `status`: `ShipmentStatus` — перечисление `` не содержит значений через `|` (тип без значений); правь на `` - `status`: `NEW` | `ASSIGNED` | `DELIVERED` `` (значения — по строке описи `состояние: Shipment.status NEW | ASSIGNED | DELIVERED`).

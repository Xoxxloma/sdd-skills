**1. Ключи.** Заголовки секции: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены, блок объекта один. Сошлось.

**2. Состав.** Опись: состояний 1, сообщений 1 (+ 1 `публикует` в «Событиях»), ограничений 1, справочников 2 (блока не получают). Карточка: 1 блок объекта (`Shipment`), 1 блок сообщения, 1 блок ограничения, справочник `Attachment.kind` блока не имеет. Сошлось.

**3. Значения.** Блок «Владеет данными» → `Shipment` оформлен ТАБЛИЦЕЙ (`| Поле | Тип | Описание |`), а не строками `- поле: тип` — это добор раньше всего остального по прямому тексту гейта. К тому же даже в этой форме значения перечислений не проставлены: `status` — `ShipmentStatus` без `NEW | ASSIGNED | DELIVERED`, `packageType` — `PackageType` без `BOX | PALLET` (опись требует значения через `|` в строке поля). Не сошлось.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет путей, HTTP-глаголов, camelCase или точечных ключей; в бэктиках — только `NEW`/`ASSIGNED`/`DELIVERED`, топик `shipment.delivered`, имя сервиса `partner-registry` — все из разрешённого списка. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — сервис есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

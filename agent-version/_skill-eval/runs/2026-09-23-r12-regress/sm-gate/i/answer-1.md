**1. Ключи.** Заголовки: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы соответствуют. Сошлось.

**2. Состав.** Строк `состояние:` — 1 (Shipment) → блоков объектов 1, в карточке 1. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1, сообщений в карточке — 1. Строк `ограничение:` — 1, ограничений в карточке — 1. Справочники (packageType, kind) своих блоков не имеют — верно. Сошлось.

**3. Значения.** Блок `` `Shipment` `` в «Владеет данными» оформлен таблицей `| Поле | Тип | Описание |`, а не строками `- поле: тип` — это добор раньше всего остального по прямому правилу гейта. Заодно `packageType` в этой таблице дан без перечня значений (`PackageType`), хотя в описи `Shipment.packageType BOX | PALLET`. Блок состояния (`NEW`/`ASSIGNED`/`DELIVERED`, 3 строки на 3 значения) сам по себе в порядке, но это не спасает форму «Владеет данными». Не сошлось.

**4. Код.** Вне бэктиков в «Бизнес-правилах» — токенов пути/глаголов/camelCase/точечных ключей нет. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё разрешённое. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry`; это имя есть в списке манифеста (shipping, partner-registry, dispatch-web). Сошлось.

Прогоняю гейт «Бизнес-правила» по пяти пунктам, сверяя четыре строки описи (`состояние`, 2×`справочник`, `сообщение`, `ограничение`) с черновиком.

1. **Ключи.** Заголовки: `### \`Shipment\` — отправление` (имя сущности в бэктиках), `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»` — все три формы верные, бэктика в заголовке сообщения нет. Блок объекта один — только `Shipment`. Сошлось.

2. **Состав.** Опись: состояний 1 (Shipment) → блоков объектов 1 (`Shipment`), совпадает. Справочники (`packageType`, `kind`) блока не имеют по правилу — и не имеют его в черновике, ок. Сообщений в описи 1 → в черновике 1, и в «Событиях» есть `публикует shipment.delivered` — тоже 1. Ограничений 1 → 1. Сошлось.

3. **Значения.** «Владеет данными» в форме `- поле: тип`, не таблица. У `status` 3 значения через `|`, у `packageType` и `kind` — тоже через `|`. В блоке `Shipment` строк для состояния ровно 3 (новое/назначено/доставлено), не меньше значений строки `состояние:`, конфляции на два токена в одной строке состояния нет (бонусная строка про `BOX`/`PALLET` — справочник, а не состояние, ей это не запрещено). Сошлось.

4. **Код.** Вне бэктиков в секции «Бизнес-правила» слов camelCase, путей, HTTP-глаголов, точечных цепочек не найдено; в бэктиках только значения перечислений (`NEW`, `BOX`...), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — все допустимые категории. Сошлось.

5. **Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`), не флаг и не «внешняя конфигурация». Сошлось.

## Прогон гейта «Бизнес-правила» — `shipping`

**1. Ключи.** Три заголовка `###`: `` `Shipment` `` (сущность в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верные, блок объекта один на сущность. Сошлось.

**2. Состав.** Опись даёт 1 сущность в `состояние:` (Shipment) → 1 блок объекта в карточке — есть. 1 `сообщение:` и 1 `публикует` в «Событиях» → 1 блок сообщения — есть. 1 `ограничение:` → 1 блок ограничения — есть. Attachment (только справочник, без состояния) блока не имеет — верно по правилу «справочник блока не имеет». Сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица. В блоке `Shipment`: 3 строки на 3 значения `status` (NEW/ASSIGNED/DELIVERED, по одному токену на строку) — этого достаточно. Но добавлена ещё строка «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании» — два токена в одной строке через запятую, это `packageType` — справочник, а не состояние. По правилу «Два токена в одной строке через /, | или запятую — справочник, записанный состоянием: добор» — это расхождение. Справочники в «Бизнес-правилах» блока не получают в принципе (их значения не влияют на правило), эта строка лишняя. **Не сошлось.**

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет ни пути, ни HTTP-глагола, ни camelCase, ни точечного ключа; в бэктиках — только значения перечисления (`NEW`, `BOX` и т.д.), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — из блока `` `Shipment` `` в «Бизнес-правилах» убрать строку «коробка (`BOX`), паллета (`PALLET`) — тип упаковки, задаётся при создании»: `packageType` — справочник, а не состояние, своего блока не имеет и в «Бизнес-правила» не пишется (значения уже отражены в «Владеет данными»); блок должен содержать только строки по значениям `status`.

**1. Ключи.** Три `###`: `\`Shipment\`` (сущность в бэктиках), `сообщение «...»`, `ограничение «...»` — все начинаются правильно, один блок на сущность. Сошлось.

**2. Состав.** Блоков-сущностей 1 (Shipment) = строк `состояние:` в описи (1). Сообщений 1 = строк `сообщение:` (1) = блоков `публикует` в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Attachment (справочник `kind`) и `packageType` блока не имеют — верно, справочники блока не получают. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица; у каждого перечисления значения через `|`. В блоке Shipment 3 строки (`NEW`/`ASSIGNED`/`DELIVERED`) = 3 значения в `состояние:`, токены — ровно значения, без `/` и без совпадающих правил на разных значениях. Сошлось.

**4. Код.** Вне бэктиков — грепы по HTTP-глаголам/camelCase/путям/дотнотации не дали совпадений. Но в бэктиках заголовка `### сообщение «\`shipment.delivered\`»` стоит бэктик вокруг имени топика — правило прямо запрещает бэктики в заголовке сообщения. **Не сошлось.**

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

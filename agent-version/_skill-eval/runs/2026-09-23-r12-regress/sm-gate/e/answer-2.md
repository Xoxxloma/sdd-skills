**1. Ключи.** Три `###`: `Shipment` (сущность в бэктиках), «сообщение «...»», «ограничение «...»» — все три формы верные, блок объекта один на сущность. Сошлось.

**2. Состав.** Опись: 1 строка `состояние:` → карточка: 1 блок сущности (`Shipment`). Опись: 1 строка `сообщение:` и 1 `публикует` в «Событиях» → карточка: 1 блок сообщения. Опись: 1 строка `ограничение:` → карточка: 1 блок ограничения. `Attachment.kind` — справочник по описи, блока не имеет, верно пропущен. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Блок `Shipment` в «Бизнес-правилах» содержит 3 строки на 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), по одному токену на строку, без дублей-заполнителей и без сдвоенных токенов через `/`,`|`,`,`. Сошлось.

**4. Код.** Вне бэктиков в секции слов с camelCase, HTTP-глаголами, путями или точечными ключами не найдено. В бэктиках — только значения перечисления и `partner-registry` (имя из манифеста), кроме одного места: заголовок `### сообщение «\`shipment.delivered\`»` содержит бэктик вокруг имени топика в самом заголовке, а правило требует **ни одного бэктика в заголовке сообщения**. Расхождение.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

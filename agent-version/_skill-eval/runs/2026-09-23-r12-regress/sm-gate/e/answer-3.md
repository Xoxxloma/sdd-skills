1. **Ключи** — три `###`: `Shipment`, `сообщение «shipment.delivered»`, `ограничение «...»` — все три формы (сущность в бэктиках / `сообщение «` / `ограничение «`) соблюдены. Сошлось.

2. **Состав** — состояний в описи 1 → блоков объектов 1 (`Shipment`); сообщений в описи 1 + `публикует shipment.delivered` в «Событиях» 1 → блоков сообщений 1, не меньше; ограничений в описи 1 → блоков 1. Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не получили — верно, справочник блока не имеет. Сошлось.

3. **Значения** — форма списка `- поле: тип`, не таблица; в блоке `Shipment` 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), без дублей-заполнителей и без составных токенов через `/`,`|`,запятую. Сошлось.

4. **Код** — тело правил вне бэктиков чистое (ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей). Но заголовок `### сообщение «`shipment.delivered`»` содержит бэктик вокруг имени топика прямо в заголовке — правило прямо требует «ни одного бэктика в заголовке сообщения». Расхождение.

5. **Переключатель** — в блоке ограничения назван `partner-registry`, это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи** — заголовки в «Бизнес-правилах»: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены (сущность в бэктиках / «сообщение «» / «ограничение «»). Сошлось.

**2. Состав** — опись: `состояние` 1 строка (Shipment), `сообщение` 1 строка + 1 `публикует` в «Событиях», `ограничение` 1 строка. Карточка: 1 блок-сущность (Shipment), 1 блок сообщения, 1 блок ограничения. `packageType` и `Attachment.kind` — справочники (учтены в описи как справочники), блока по правилу не имеют — их отсутствие в «Бизнес-правилах» корректно. Сошлось.

**3. Значения** — «Владеет данными» в форме `- поле: тип`, не таблица. У `status` и `packageType` значения через `|`. Блок `Shipment` в бизнес-правилах содержит 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`) — ровно по числу, без «не определено»-заполнителей и без склейки токенов через `/`,`|`,запятую. Сошлось.

**4. Код** — по всей секции «Бизнес-правила» вне бэктиков нет путей, HTTP-глаголов, camelCase-полей, точечных конфиг-ключей; в бэктиках только значения перечисления (`NEW` и т.д.), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`); в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель** — в блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

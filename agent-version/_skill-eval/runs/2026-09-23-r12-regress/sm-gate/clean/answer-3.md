Прогнал гейт «Бизнес-правила» по пяти пунктам.

1. **Ключи.** Три `###`: `` `Shipment` — отправление ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы верны, один блок на сущность. Совпадений с «иной заголовок» нет.
2. **Состав.** Опись: `состояние:` — 1 строка (Shipment) → карточка: 1 объектный блок (Shipment). `сообщение:` — 1 строка, `публикует` в «Событиях» — 1 → карточка: 1 блок сообщения. `ограничение:` — 1 строка → карточка: 1 блок. Справочники (`packageType`, `kind`) блоков не имеют — верно, блок положен только состоянию.
3. **Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. У `status`, `packageType`, `kind` значения через `|` в самой строке поля. Блок `Shipment` содержит ровно 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), заполнителей и повторов правила на разных значениях нет.
4. **Код.** В секции «Бизнес-правила» вне бэктиков нет путей, HTTP-глаголов, camelCase и точечных ключей; в бэктиках — только значения перечисления (`NEW` и т.д.), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). В заголовке сообщения бэктиков нет.

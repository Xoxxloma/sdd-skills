**Сверка сверху (сущности vs маркеры Шага 3.1):** маркер `@Entity|^model |@Table\(` по коду — **0**. Блоков `###` в «Владеет данными» — **18** (>0). Это случай «маркер дал ноль, блоки есть» → по умолчанию добор на все блоки.

Проверка исключения (Mongo-подобный маркер вне таблицы): в описи строки сущностей заданы форматом «Имя — путь/Файл.java», ни одна не оканчивается на `\([^)]*\)\s*$` — грепом на этот паттерн совпадений нет. Значит нет и совпадений по `\(@Entity|\(@Table|\(model\b` внутри них. Условие исключения — «строки сущностей есть, а с маркером таблицы ни одной» — не выполняется, потому что строк с параметром-маркером вообще нет ни одной (не просто «маркера нет», а сама форма записи не несёт маркера). Исключение не применяется.

**Сущности у ручек:** имена в `сущности:` показанных блоков (`IncidentCategoryStatistic`, `IncidentDamageStatistic`, `UorSecurity`, `UorDetention`, `UorFemidaDamage`, `PerformanceRating`) есть в списке «Владеет данными» — формально сверку эти строки проходят. Отдельного добора по этому правилу не требуется: переписывание этих строк уже входит в текст добора ниже, потому что сами сущности снимаются.

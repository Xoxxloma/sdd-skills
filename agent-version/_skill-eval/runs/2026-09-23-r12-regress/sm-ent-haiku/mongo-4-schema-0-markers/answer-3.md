Анализирую по двум правилам.

## Маркерный гейт (Шаг 3.1 — 1-е правило)

По коду маркеры `@Entity|@Table`: **0**  
В описи ключей сущностей: **4** (Order, Customer, Invoice, Payment)

Правило: маркеры дали ноль → сверки нет по гейту (нижняя граница). Гейт не блокирует.

## Сущности — верхняя сверка (2-е правило)

Блоков `###` в «Владеет данными»: **4**  
Маркеров по коду: **0**

Проверка границы: 4 > 0 → **нарушена**. Субагент записал 4 класса только с `@Schema` (не маркеры хранения) как сущности.

Исключение (Mongo/вне таблицы) не срабатывает: маркеров `@Entity|@Table` нет вообще.

---

**Добор на субагента:**

Order, Customer, Invoice, Payment — маркера хранения в коде нет (только `@Schema`): убери из «Владеет данными», поля — строками в блоки ручек; строку `сущности:` каждой затронутой ручки (GET /api/orders, GET /api/customers и остальные) перепиши на `→ не сущность, агрегат по …` или `→ не сущность, ответ orders-ms`.

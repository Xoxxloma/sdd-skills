Как искать:
1. Дерево целиком не листай — ни `Glob **/*`, ни `Glob <папка>/**`: на большой репе это сотни

   потом — поиск пометок контракта. **Все три поисковых грепа обязательны, каждый отдельно, даже
   если первый уже дал много**: в одной репе бывает два стиля сразу, и назвав первый попавшийся, ты
   потеряешь второй. Это не маркеры, а поиск кандидатов (`output_mode="count"`, по всему сервису):
   - HTTP: `@\w*(Get|Post|Put|Patch|Delete)\w*|\.(get|post|put|patch|delete)\(`;
   - GraphQL: `@\w*(Query|Mutation|Subscription)\w*` и отдельно `"(Query|Mutation|Subscription)"`

2. На каждого кандидата открой один файл — не больше одного на кандидата и не больше десяти за

   классе, который их группирует, и не на запросе ORM. В этом же файле посмотри все методы-ключи:
   часть помечена иначе — у класса ещё одна строка. Общая форма с корневым типом в параметре — тоже
   ключ, но в регэкспе обязан стоять корневой тип (`Query`, `Mutation`, `Subscription`): без него
   она поймает и резолверы полей.
3. Задачи и топики помечают кто как — и это тоже обязательный поисковый греп, без учёта регистра:
   `cron|schedul|interval|listen|consum|subscri|topic`; открой кандидата и смотри, что стоит на
   самом ключе.
4. Поисковый греп — не маркер. В ответ ставь узкий регэксп той пометки, которую нашёл и проверил
   (`@GetMapping\(`, а не `@\w*Get\w*` — тот поймает и чужое, например `@Getter`).

Правила маркера:
- одно совпадение — один ключ. Пометка класса-контейнера (контроллер, резолвер, компонент) — не
  маркер: на нём пять ручек, а совпадение одно;
- маркер узкий: аннотация запроса ORM — не контракт; резолвер поля не корневого типа — не операция;
  вызов, которым пользуется и HTTP-клиент или словарь, — не ключ; вызов, который сам регистрирует
  ключ (ручку на роутере, задачу по таймеру), — ключ: одно совпадение — одна ручка или задача;
- на одном объявлении две пометки (класс-сущность с аннотацией таблицы рядом) — бери одну;
- ключ, у которого в коде пометки нет (топики только в конфиге, обработчики без аннотаций), —
  строка `ориентир` по тому, что пометить можно, или ничего. Топик — `ключ`, только если пометка с
  именем топика стоит на каждом топике; обработчик, который читает несколько топиков или берёт
  их имена из конфига, — `ориентир`;
- `<glob>` — только расширение: `*.java`, `*.ts`, `*.prisma`, `*.proto`. Ни папок, ни части имени:
  `routes/*.js` и `prisma/schema.prisma` Grep не находит и считает ноль, а `*Controller.java`
  теряет ключи из файлов с другим именем. Узким должен быть регэксп, а не маска;
- в строке — регэксп, а не описание: пометку словами не опишешь — строки нет.

Регэксп — для инструмента Grep (ripgrep). Экранируй только символы, буквальные в коде (`\(` у скобки
вызова, `\.` у точки); скобки группы и `|` альтернативы — без обратного слеша: `@(Get|Post)Mapping\(`,
а не `@\(Get\|Post\)Mapping\(`.

Ответ — только строки маркеров, по одной на строку, без чисел и пояснений:
<класс> :: <регэксп> :: <glob файлов> :: ключ|ориентир

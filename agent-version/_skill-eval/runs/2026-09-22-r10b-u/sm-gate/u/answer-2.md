**1. Ключи.** Все три `###` в «Бизнес-правилах» начинаются по форме: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — заголовков не по форме нет; бэктиков в заголовках сообщения/ограничения нет. Совпало.

**2. Состав.** Опись: `состояние:` 1 строка (Shipment) → блоков-сущностей в карточке 1 (Shipment); `сообщение:` 1 строка + «публикует» в «Событиях» 1 блок → сообщений в карточке 1; `ограничение:` 1 строка → ограничений в карточке 1. Attachment и Shipment.packageType — справочники по описи, блока в «Бизнес-правилах» не имеют, и в карточке его действительно нет. Совпало.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица. У `status` — 3 значения через `|`, у `packageType` и `kind` — тоже через `|`, тип без значений нигде не встречается. В блоке `Shipment` строк (новое/назначено/доставлено) ровно 3 — по числу значений `состояние:`; на каждой строке ровно один токен из перечня (`NEW`/`ASSIGNED`/`DELIVERED`), дублей правила на разные значения нет. Совпало. (Отдельно отмечу: строка `Shipment` в «Владеет данными» пакует три поля через `·` в одну `- ` — это не расхождение и не добор, но фиксирую для отчёта: 3 поля в одной строке.)

**4. Код.** В тексте секции «Бизнес-правила» вне бэктиков нет путей, HTTP-глаголов, camelCase и точечных ключей; в бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё разрешённое. Совпало.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Совпало.

Прогоняю гейт «Бизнес-правила» для `shipping`.

**(1) Блоки объектов = сущности из строк `состояние:`.**
В описи одна строка `состояние:` — про `Shipment`. Оба перечисления-`справочник` (`packageType`, `Attachment.kind`) блока не получают по правилу. В карточке в «Бизнес-правилах» ровно один блок объекта — `Shipment` (блока `Attachment` там нет, он только в «Владеет данными»). Плюс по блоку на строку `сообщение:` (1) и `ограничение:` (1) — оба на месте. Сошлось: 1 объект + 1 сообщение + 1 ограничение = 3 блока, и в карточке ровно 3.

**(2) Строк `-` в блоке объекта ≥ значений в строках `состояние:` этой сущности.**
`состояние: Shipment.status NEW | ASSIGNED | DELIVERED` — 3 значения. Блок `Shipment` в карточке — 3 строки (новое/назначено/доставлено). 3 ≥ 3, сошлось.

**(3) Токены в бэктиках внутри блока объекта — значения из «Владеет данными».**
В блоке `Shipment`: `NEW`, `ASSIGNED`, `DELIVERED` — все стоят справа от `:` в строке `- status: NEW | ASSIGNED | DELIVERED` в «Владеет данными». Ни одного выдуманного токена, ни одного имени поля вместо значения, добора-справочника (несколько токенов через `/` или `|` в одной строке) тоже нет.

**(4) Блоков сообщений ≥ блоков `публикует` и ≥ строк `сообщение:`.**
В «Событиях» один блок `публикует shipment.delivered`; в описи одна строка `сообщение:`. В карточке один блок сообщения — «груз доставлен», топик `shipment.delivered` стоит в строке, а не в заголовке (заголовок словами). 1 ≥ 1 и 1 ≥ 1, сошлось.

**(5) Блоков ограничений = строк `ограничение:`.**
Одна строка `ограничение:` в описи, один блок в карточке. В блоке нет `true`/`false`, условие названо словами, управляющий назван — `partner-registry`, это имя сервиса из манифеста. Сошлось.

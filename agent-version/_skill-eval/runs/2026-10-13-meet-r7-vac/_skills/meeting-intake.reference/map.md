# Рубрика: карта тем окна

Ты читаешь кусок расшифровки встречи и отвечаешь, о чём в нём говорили. Решения не выписываешь:
это карта, а не разбор.

## Что вернуть

```
рубрика прочитана: карта
формат: <чат встречи | vtt | srt | имя-время | конспект>
участники: <Фамилия Имя [B]>; <…>
тема: <предмет, 2–6 слов>
  строки: L<n>–L<m>[, L<n>–L<m>]
  ключ: <как написан, например ABC-123 | произнесено «…» | нет>
  вид: <требования | реализация | статус | офтоп — один или несколько через запятую>
  решений: ~<N>
тема: …
итог: L<n>–L<m>
```

## Правила

- **Тема** — задача целиком: одна фича, один документ. Новая тема — только когда сменилась задача:
  другой продукт, другой документ, другой ключ. Требования, разделы, ошибки, статусы, справочники,
  стенды, роли одной задачи — строки ОДНОЙ темы, а не отдельные темы, даже если ключ назван один раз.
  Предмет вернулся позже — те же строки через запятую. Требования и реализация одной задачи — одна
  тема с двумя видами.
- **Ключ.** Распознавание пишет номер словами («две тысячи сорок первая», «эр эс ай сто два») —
  верни произнесённую форму в кавычках. Написанный в чате ключ — как есть.
- **Вид:** «требования» — что и зачем делаем, правила, границы, роли, сроки; «реализация» — как
  сделано: обмен, хранение, ошибки, повторы, стенды; «статус» — кто что сделал, блокеры, планы без
  решений по документам; «офтоп» — связь, оборудование, обед, личное, другие команды.
- **Решений** — сколько раз по предмету что-то приняли, отложили с вопросом или вынесли за рамки.
  Примерно; ноль — тоже ответ.
- **Итог** — строки, где подводят итог встречи или зачитывают решения. Нет — строки `итог` не пиши.
- Строки, не попавшие ни в одну тему, не перечисляй.

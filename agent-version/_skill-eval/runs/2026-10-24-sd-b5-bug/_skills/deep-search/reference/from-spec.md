# Глубокий поиск из спеки

Этот файл читает ведущий `technical-spec-doc`. Код ты сам не ищешь и не читаешь — открываешь только
строки по ссылкам разведчика, когда их сверяешь. Ищет и читает код разведчик `deep-search`, по выбору
аналитика; найденное ты несёшь аналитику новой гипотезой. Фактом пункт по-прежнему делает только ответ
аналитика.

**Поиск файлов:** папку задаёт параметр `path`, маску — `pattern`. Маска, которая начинается с имени
папки (`services/*.md`), не находит ничего; `**/` в начале маски работает.

## 1. Код рядом

Перед первым вопросом о существующем сервисе; манифест читаешь один раз за запуск, а сервис, вопрос о
котором появился позже, проверяешь перед этим вопросом:

- `<Корень>` — текущая папка, абсолютным путём; `<Родитель>` — `<Корень>` без последнего сегмента.
- `Read <Корень>/services/manifest.yaml`. Файла нет → кода рядом нет ни у кого.
- По каждому существующему сервису, о котором будешь спрашивать: строка с его `name` в манифесте → её
  `path` → абсолютный путь. `../x` превращай в `<Родитель>/x` сам: `..` в путях инструментов не пиши,
  поиск с ним молча вернёт пустоту. Путей через запятую несколько — бери первый.
- `Glob pattern="*" path="<этот путь>"` нашёл хоть один файл → у сервиса код рядом. Сервиса в манифесте
  нет, `Glob` пуст или вернул ошибку пути → кода рядом нет.
- Субагента запустить нельзя → кода рядом нет ни у кого.

Код рядом есть → в вопросе-допущении об этом сервисе ещё один вариант (всего вариантов не больше
четырёх): «Глубокий поиск — посмотреть в коде <сервис>». Вариантов уже четыре — поиск встаёт вместо
варианта-поправки («Иначе — поправлю»): поправить аналитик может и своим ответом; такого варианта нет —
вместо «Не знаю, оставим к валидации». У остальных сервисов вопрос прежний. Кода рядом нет ни у кого — о поиске аналитику не пиши.

## 2. Аналитик выбрал поиск

Разведчик — один на вопрос. Поиск выбран в нескольких вопросах → по разведчику на каждый, все одним
сообщением. Тип субагента — любой, у которого есть `Read`, `Grep`, `Glob`. Промпт — этот, с подстановкой,
без своих добавлений:

```
Ты — разведчик скилла deep-search. Сначала прочитай бриф <абсолютный путь к brief.md рядом с этим файлом> и работай строго по нему.
Утверждение: <гипотеза вопроса, как ты задал её аналитику>
Корень: <абсолютный путь к текущей папке>
Сервис: <name сервиса из манифеста>
```

В ответе нет хотя бы одного из двух заголовков — `## ОТВЕТ ПО КОДУ`, `## ПРОЧИТАНО` → запусти ещё раз тем
же промптом. Снова нет → как вердикт `не нашёл`.

**Сверка.** Каждую ссылку на код проверь, как велит раздел «Шаг 3 — сверка ссылок» в `SKILL.md` этого
скилла — он папкой выше этого файла: прочитай раздел и выполни. «Ответ» в нём — твой ход к аналитику.

## 3. Вопрос по ответу разведчика

| `Вердикт:` после сверки | Вопрос аналитику |
|---|---|
| `подтверждается` | «В коде <сервис> так и есть: <что делает код>. Беру?» |
| `в коде иначе` | «В коде <сервис> иначе: <как в коде>. Беру как в коде?» |
| `не нашёл`; не осталось ни одного пункта `[в коде]`; в ответе блок `## НУЖЕН ВЫБОР` | прежний вопрос без варианта поиска; перед ним строка «В коде <сервис> ответа не нашёл: <все пункты `[не нашёл]` и `[вне кода]`>»; таких пунктов нет — строка без двоеточия. Ответ на него — как без поиска, метка «не по коду» |

При `подтверждается` и `в коде иначе`:
- перед вопросом — все пункты разведчика, оставшиеся после сверки, и `[не нашёл]`, и `[вне кода]`; ссылки — у
  тех, где они есть; и строка «Читал: <репа>, ветка <ветка> — локальная копия, могла отстать от
  удалённой». «Да» берёт только то, что аналитик видел;
- варианты: «Да, беру», «Иначе — поправлю», «Не знаю, оставим к валидации». Поиска среди них нет: поиск —
  один на вопрос;
- «Да» → 🔵, в скобках метки «по коду <сервис>, ветка <ветка>» вместо «не по коду»; ветка не определена —
  так и пиши. Аналитик поправил → пишешь его словами, метка обычная, «не по коду». «Не знаю» → 🟡 к
  валидации.

При любом вердикте: в ответе строка о расхождении карточки с кодом → скажи аналитику одной строкой:
«Карточка `services/<сервис>.md` расходится с кодом: <что>. Обновить: `/service-map <сервис>`».

## 4. Что из ответа разведчика в спеку не идёт

Пути к файлам, ссылки `файл:строка` и устройство чужого кода — классы, методы, константы, переменные
окружения, ключи настроек — ни под 🔵, ни под 🟡: это устройство кода, а не контракт. Ссылки нужны аналитику, чтобы проверить находку; в
спеку идёт поведение словами, как его подтвердил аналитик.

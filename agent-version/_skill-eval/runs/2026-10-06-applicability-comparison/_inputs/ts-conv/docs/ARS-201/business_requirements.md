# Бизнес-требования: Счётчик активных пользователей в шапке

> **Задача Jira:** ARS-201
>
> **Статус готовности:** Готово к оценке
>
> *(Открытых вопросов нет.)*

## 1. Введение и контекст

### 1.0. Тип изменения
Доработка существующего функционала: добавляются новые элементы в административную панель.

### 1.1. Описание проблемы (Problem Statement)
Администраторы системы «Арсенал» не видят ни текущую, ни историческую активность пользователей. Это приводит к невозможности быстро оценить нагрузку на систему, посмотреть динамику активности за период и подготовить сводку для отчётности. В результате регламентные работы планируются без данных о нагрузке, что повышает риск влияния на активных пользователей.

### 1.2. Конечные потребители (End Users)
Администраторы системы «Арсенал», внутренние сотрудники отдела эксплуатации.

### 1.3. Заказчик и стейкхолдеры (Stakeholder / Sponsor)
**Заказчик:** Руководитель отдела эксплуатации.
**Эксперт для консультаций:** Тимлид команды «Арсенал-Core».

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как администратор системы должен иметь возможность видеть текущую и историческую активность пользователей, чтобы планировать безопасные окна для регламентных работ и готовить отчёты по нагрузке на систему.

### 2.2. Ценность для бизнеса
- Видимость нагрузки на систему позволяет планировать регламентные работы в окна минимальной активности, снижая риск влияния на пользователей.
- Историческая сводка по активности даёт основание для отчётности перед руководством по эксплуатационным метрикам.

### 2.3. Бизнес-риски и меры по снижению

| Риск | Вероятность / влияние | Меры по снижению |
|------|----------------------|------------------|
| Неточные или устаревшие данные активности приводят к неправильной оценке нагрузки и неудачно спланированным работам | Средняя / высокое | При недоступности источника данных показывать «—» вместо нуля или устаревшего значения; в документации указать требование к актуальности данных |
| Доступ к панели активности получат операторы или пользователи не-администраторской роли, и это создаст утечку или неправильное понимание нагрузки | Средняя / среднее | Панель активности отображается только для пользователей с ролью Администратор; выгрузка CSV доступна только администраторам |

## 3. Объём проекта (Scope)

### 3.1. Входит в проект (In-scope)
- Счётчик текущего числа активных пользователей в шапке административной панели.
- При изменении числа активных пользователей счётчик обновляется без перезагрузки страницы.
- Корректная обработка недоступности источника данных: отображение «—» вместо нуля или устаревших значений.
- Отображение нуля активных пользователей как обычного значения («0»).
- Ограничение доступа: счётчик видна только администраторам, операторы его не видят.

### 3.2. Не входит в проект (Out-of-scope)
- График активности за период (слайс ARS-202).
- Выгрузка сводки в файл (слайс ARS-203).
- Список конкретных пользователей, находящихся онлайн.
- Автоматическая рассылка отчётов по активности.
- Прогнозирование активности на основе исторических данных.
- Метрики пика, минимума и средней активности за период.

### 3.3. Архитектурные изменения и интеграции
Данные активности собираются бэком системы «Арсенал» самостоятельно; новых интеграций с внешними сервисами не требуется.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1. Счётчик активных пользователей в шапке**
Администратор открывает административную панель. В шапке отображается число активных пользователей (только текущий момент). При изменении числа активных пользователей счётчик обновляется без перезагрузки страницы.

**FR-5. Обработка недоступности источника данных** *(сквозное требование)*
Если источник данных активности недоступен, в шапке и в графике отображается «—» (не ноль и не устаревшее значение).

**FR-6. Отображение нулевой активности**
Если активных пользователей нет, показывается значение «0» как обычное, валидное значение активности.

**FR-7. Ограничение доступа по ролям** *(сквозное требование)*
Панель активности видна только администраторам. Пользователи с ролью оператор панель активности не видят.

### 4.2. Критерии приёмки (Acceptance Criteria)

- **[FR-1]** Дано: административная панель открыта, страница загрузилась. Когда администратор смотрит в шапку. Тогда в шапке отображается число активных пользователей в текущий момент.

- **[FR-1]** Дано: число активных пользователей в системе изменилось. Когда администратор находится на странице панели. Тогда счётчик в шапке обновляется без перезагрузки страницы.

- **[FR-5]** Дано: источник данных активности недоступен. Когда администратор открывает панель или обновляет граф в модальном окне. Тогда отображается «—» (прочерк), а не ноль и не устаревшее значение.

- **[FR-6]** Дано: число активных пользователей равно нулю. Когда администратор смотрит счётчик активности. Тогда отображается значение «0» как обычная, валидная метрика.

- **[FR-7]** Дано: пользователь имеет роль Оператор. Когда пользователь открывает административную панель. Тогда панель активности вовсе не отображается.

### 4.5. Разбиение на слайсы

Не применимо — это слайс эпика ARS-200, разрез уже сделан на уровне эпик-БТ.

## 5. Ограничения и атрибуты качества

### 5.1. Приоритет
**Medium** — доработка улучшает эксплуатацию системы, но основной бизнес от неё не зависит.

### 5.2. Сроки и обоснование
**До конца текущего квартала.** Срок привязан к плану регламентных работ: требуется видимость нагрузки перед началом регламентного окна.

### 5.3. Ролевая модель

| Роль | Права / доступные действия |
|------|----------------------------|
| Администратор | Видит счётчик активности в шапке; счётчик обновляется автоматически |
| Оператор | Панель активности не видит |

## 6. Приложения (опционально)

**Пожелание по UX:** Счётчик активности в шапке должен быть визуально неярким, не отвлекать администратора от основной работы с панелью.

---

**Замечание на разработку:** Конкретные поля, таблицы и источник данных об активности определяются на этапе технической спецификации на основании имеющегося в коде источника данных системы.

# Критерии сравнения

Целевые проверки не смешиваются с общим оформлением. При ручной оценке читаются сырой
запрос, исходник и артефакт, а не только автоматический флаг.

| Проба | Целевые проверки |
|---|---|
| bf-spec | Нет новых вопросов о нетронутом §5.2 и срочности/очерёдности §6.1; срочность принята; данные проверены; изменённое поведение состояния описано |
| bfg-scroll | Первый ход — вопросы, файл не записан; данные и границы спрошены; гейт 8 и заданная срочность не открыты заново; пакеты про флаги/подготовку сравниваются по темам, а не числу строк |
| bfg-role | Изменённый доступ открыт; данные и границы спрошены; нет вопросов о нетронутых гейтах 8/9; файл не записан |
| ts-conv | Неподтверждённый источник числа остаётся открытым; чужой auth-контракт/сущность не выданы за факт и не скопированы в контракт; новый API спроектирован отдельно по конвенциям |
| ts-ctx | Старый неподтверждённый протокол СЦБ остаётся открытым; чужие путь, заголовок, поля, коды и лимиты не выданы за подтверждённый контракт; собственный контракт следует конвенциям |
| ua-label | Требуемый вопрос о других местах надписи сохранён; нет новых вопросов о нетронутых сбоях/выкате; готовые строки не скрывают применимый UI, проверку данных и приёмку |
| ua-timeout | Таймаут 3 → 10 с и прежняя реакция описаны в §4.3.1/§5.1; ответ на 7-й секунде успешен, после 10 с прежняя ошибка; каталог и трассировка сохраняются. Если меняется только число секунд, допустим §4.3 «Не применимо» со ссылкой на §4.3.1; повторная таблица состояний не требуется |
| ua-review-reliability | На исправленном входе законные §5.2 N/A и §6.1 «Общий релиз» не порождают замечаний; явный источник реально передан независимому проверяющему |

Общие наблюдения: полные заголовки и порядок, зачёркивание заголовков/текста/неприменимых
вариантов, сохранность пяти пунктов §6.5 и разметка чекбоксов. Правила этой формы были в HEAD.
Механический grade-na может ошибиться на смешанном тексте с отрицательным ответом; вердикт
ставится по содержанию после чтения. «Открытый источник» — допустимый результат, не красный.

Уточнение ua-timeout принято после контроля C по замечанию пользователя. Численный порог
меняется, поэтому утверждать, что все условия переходов прежние, нельзя; прежними здесь
остаются набор состояний, ветвления, отображение и действия. Полнота описания нового порога
проверяется по §4.3.1, параметрам и приёмке, без обязательного повторения в §4.3.
Зачёркивание родителя при живом §4.3.1 — отдельное нарушение формы по общему правилу.
Старые оценки сохранены; это переоценка тех же артефактов, не новый модельный прогон.

Один новый проигрыш требует повторного контроля; общий проигрыш не доказывает отсутствие
влияния на частоту. Наблюдаемые улучшения тоже описываются как результаты конкретной пары.

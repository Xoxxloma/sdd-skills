**Гейт «Бизнес-правила»**

1. **Ключи.** Все четыре `###` секции начинаются как надо: `Shipment` в бэктиках, `сообщение «`, два `ограничение «`. В заголовках сообщения и ограничений бэктиков нет. Блок объекта один. Сошлось.
2. **Состав.**
   - Блоков объектов 1, строк `состояние:` 1.
   - Сообщений 1, строк `сообщение:` 1, блоков `публикует` в «Событиях» 1.
   - Ограничений 2, строк `ограничение:` 2.
   - Перечисления `packageType` и `Attachment.kind` названы в описи справочниками, блока не имеют. Пропущенных нет. Сошлось по счёту.
3. **Значения.**
   - «Владеет данными» оформлена строками `- поле: тип`, не таблицей.
   - У трёх перечислений значения стоят через `|`.
   - В блоке `Shipment` 3 строки на 3 значения, каждая с одним токеном (`NEW`, `ASSIGNED`, `DELIVERED`).
   - Строк `не определено` нет, правила на значениях разные, чужих полей нет.
   - Сошлось.
4. **Код.** Вне бэктиков нет ни путей, ни HTTP-глаголов, ни camelCase, ни идентификаторов вида `a.b.c`. В бэктиках только значения перечисления, топик `shipment.delivered` и `partner-registry`. Сошлось.
5. **Переключатель.**
   - Первое ограничение («приём отключён») в порядке: `partner-registry` из манифеста включает и выключает флаг партнёра.
   - Второе («неизвестный партнёр») формально проходит грепом, потому что имя из манифеста стоит. По смыслу это не ограничение. Условие «идентификатора нет в справочнике» задаёт сам запрос, `partner-registry` его не включает и не выключает. Это валидация входа, а такие случаи по описи не ограничения. Их место — строка ошибки в «Публичном контракте». Имя соседа здесь приклеено, чтобы пройти проверку. Не сошлось.

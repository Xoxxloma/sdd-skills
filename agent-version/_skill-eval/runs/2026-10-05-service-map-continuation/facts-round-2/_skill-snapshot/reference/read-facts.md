# Чтение поведения выбранного ключа

Используй этот порядок у одиночного читающего, части, остатка и при дочитывании.
Область владения задаёт, какие ключи описываешь; за их поведением можно идти по всему
разрешённому репозиторию. Не добавляй ключ общего файла только потому, что открыл его за фактом.

1. Найди объявление и действующую реализацию ключа. Для HTTP учитывай подключение роутера,
   общий префикс и исключения; для GraphQL различай объявленную схему и результат реализации.
   Префикс применяется к конкретному подключению: отдельно зарегистрированные ручки могут
   находиться вне него. При переходе от списка объявлений к описи не сворачивай соседние операции
   в одну группу; перед карточкой сверяй состав ключей со всеми найденными объявлениями.
2. Проследи непосредственные вызовы обработчика: условия допуска, правила домена, запрос
   хранилища, преобразование ответа, отправка события. Общий обработчик ошибки нужен,
   чтобы установить видимый код отказа именно этого канала. Таблица HTTP-ошибок REST сама по
   себе не устанавливает HTTP-ответ GraphQL или RPC: проверь подключённый адаптер, иначе сохрани
   доменную ошибку и неизвестность её транспортного представления.
   Конфигурация сама не доказывает подключённый механизм.
3. Для найденного поведения сохрани точное условие и результат. Проверь границы сравнения
   и значение по умолчанию, включительность дат, смысл отсутствующего значения, конкретный
   предел повторов, изменение состояния и сопровождающих полей, условие побочного эффекта.
   Для выборки сохрани порядок и направление сортировки. Для последовательности проверок
   сохрани ранний возврат: он может исключать выполнение последующих проверок.
   «Действующие записи», «повтор по лимиту», «начинает обработку» пересказывают назначение:
   за этими словами должны остаться найденные условия, пределы и изменения.
   Если обязательность объявлена в контракте, отдельно проверь возвращаемое значение,
   элементы коллекции и поля объекта. Необязательное поле не делает необязательным весь ответ.
4. Запиши каждый подтверждённый факт второго уровня описи с источником. Затем разворачивай
   карточку по этим строкам подряд, проверяя, что условие и результат доехали в блок своего ключа.
   Переформулировка допустима, потеря числа, условия, результата или отрицания — нет.
   Сводный переход сущности не заменяет факт операции; схема полей не заменяет проекцию ответа.
5. Для каждого выбранного блока сопоставь найденные строки описи с карточкой. Не оставляй
   только первый факт, остальные в описи; не объединяй разные условия до потери различий.
   У связанных ключей одна логика может дать факты каждому, но только в относящейся к нему области.

При написании карточки проверяй перенос сразу после каждого блока, пока перед тобой его опись:
прочитай каждую строку факта и найди в блоке её условие и результат. Для отказа это и условие,
и видимый код; для выборки — все границы, исключения и направление порядка; для изменения — состояние и сопутствующие
поля. Сохрани найденные различия отдельными строками вместо повторного краткого пересказа блока.
Если результат сверки не совпал, исправь этот блок перед переходом к следующему. Проверка наличия
одной строки факта не подтверждает перенос остальных. Это проверка уже найденного содержания,
не дополнительный скан и не третий запуск читающего.

Отсутствие нижележащего адаптера не отменяет смысл видимого выражения, аннотации или
запроса. Сохраняй его условия и значения по умолчанию языка / формата, отдельно отмечая
непроверенное исполнение. Называя реализацию отсутствующей, укажи именно недоступный
вызов; доступный промежуточный метод не становится отсутствующим из-за следующего вызова.

Это порядок поиска, не требование заполнить каждый вид факта. Не существует подтверждения —
не придумывай его. Непроверенный вызов или исчерпанное чтение пометь `не проверено: <что>`;
известное при этом сохраняется. Явно проверенное отсутствие и неизвестность — разные исходы.
Служебное имя не позволяет прекратить чтение; законная пустота подтверждается реализацией.

В карточку идут слова и необходимые токены по шаблону, а не копии кода или хвосты источников.
Файл и место источника остаются в описи. До продвижения эту опись можно проверить механически,
но совпадение собственных двух списков не доказывает полноту чтения.

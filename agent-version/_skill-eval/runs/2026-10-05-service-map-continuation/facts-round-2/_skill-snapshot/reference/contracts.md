# Независимые объявления публичного контракта

Используй названные разведчиком файлы SDL, OpenAPI или proto. Объявление не доказывает
подключение обработчика; скрипт не решает, реализована ли операция.

Перед запуском читающих выполни:

```text
bash <reference/contracts.sh> collect <разрешённый корень репозитория> <новый declarations.json в .work> <файл схемы> ...
```

Пути файлов передаются отдельными аргументами. Требуется Node.js; зависимости не устанавливаются.
Выход 0 — переданные объявления разобраны; 3 — есть непроверенные файлы/ссылки, manifest сохранён;
2 — технический отказ. Источники не меняются, существующий выход не перезаписывается.
Для повторной сверки используй новый путь.

Поддерживаются корневые поля SDL, явные корневые типы и расширения, RPC внутри service-блоков,
OpenAPI JSON и профиль YAML с отступами, отображениями, последовательностями и скалярами.
OpenAPI учитывает серверные префиксы, переопределения и локальные ссылки внутри разрешённого корня.
YAML-алиасы, слияния, неподдержанные flow-отображения и неизвестные относительные URL дают
«не проверено», а не нулевой контракт. Это извлечение объявлений, не полный валидатор стандартов.
SDL с импортами требует явного списка подключённых файлов; неизвестная сборка остаётся ограничением.
Вложенные поля, компоненты OpenAPI и текст комментариев не операции. Сеть не используется.

После первичных карточек, до единственной содержательной волны добора:

```text
bash <reference/contracts.sh> compare <declarations.json> <карточка или первая часть> <новый contracts-report.tsv> <остальные первичные части> ...
```

Передай все части, включая остаток, до запуска головы. Пересказ и ручная склейка ведущим не нужны.
Получен полный семиколоночный TSV по контракту CHECK_REPORT. Его исправляемые строки включи
в ту же волну добора, распределив ключи владельцам реализации; неизвестный владелец идёт остатку.
У одиночного читающего список идёт ему. После сборки повтори сверку итоговой карточки как контроль,
не открывая новую попытку автора. Для проверки одной карточки передай manifest через
`CHECK_DECLARATIONS=<declarations.json>` при запуске `check.sh`: он автоматически объединит
диагностику объявлений со своим полным TSV и перечнем добора. Так предупреждения доходят
до `quality.sh` без ручного пересказа ведущим. Отказ независимой сверки сохраняется как
«не проверено» и не подменяется нулём отсутствующих операций.

Объявление без блока — просьба проверить действующий обработчик или подключённый механизм,
а не требование сочинить операцию. Если обработчика действительно нет, читающий фиксирует
`> объявлено без реализации: <ключ> — <источник>`; объявление не становится действующим контрактом.
Если подключение не установлено, статус «не проверено». В manifest по умолчанию state: declared.
State: inactive допустим только в проверенной копии manifest с отдельным обоснованием читающего;
сам сборщик этот статус не выводит. Диагностика не создаёт нового запрета записи и не уменьшает
маркерный счёт вручную. Неразрешённые объявления переходят в сохраняемые ограничения.

Границы форматов сверены с [GraphQL SDL](https://spec.graphql.org/October2021/#sec-Type-System),
[OpenAPI](https://spec.openapis.org/oas/v3.0.3.html) и
[proto3](https://protobuf.dev/reference/protobuf/proto3-spec/).

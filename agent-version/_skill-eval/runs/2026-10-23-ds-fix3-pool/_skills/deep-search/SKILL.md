# Глубокий поиск — как система работает сейчас

Аналитик спрашивает, как что-то работает сейчас. Ответ ищет **разведчик** — субагент: по карточкам
`services/` находит сервис, по манифесту — его репу рядом, в коде — ответ. Ты запускаешь разведчика,
сверяешь его ссылки и отвечаешь в чат.

**Поиск файлов:** папку задаёт параметр `path`, маску — `pattern`. Маска, которая начинается с имени
папки (`reference/brief.md`, `services/*.md`), не находит ничего, даже когда файл на месте; `**/` в
начале маски работает.

**Бриф разведчика — `reference/brief.md` рядом с этим файлом**, в папке скилла, а не в репозитории со
спеками. Путь считай от `SKILL.md`, разведчику передавай абсолютным. Бриф не пересказывай и не
вклеивай — разведчик читает его сам. `Glob pattern="brief.md" path="<папка скилла>/reference"` пуст →
остановись: «не нашёл `reference/brief.md`, скилл установлен не полностью».

## Шаг 1 — вопрос

- О том, как система работает сейчас → Шаг 2.
- Как сделать, как лучше, что поменять → одна строка: «Это вопрос проектирования — его решают в спеке,
  `/analyst-workspace`. Могу рассказать, как это работает сейчас». Стоп.
- Смешанный → разведчику уходит только часть «как сейчас»; в ответе одна строка, что остальное — для
  спеки.
- Вопроса нет → спроси одной строкой, что посмотреть.

## Шаг 2 — разведчик

Корень — текущая папка. `Glob pattern="*.md" path="services"` пуст → «не вижу `services/` — запусти из
репозитория со спеками». Стоп.

Разведчик один на весь вопрос — не дели вопрос по сервисам и репам. Тип субагента — любой, у которого
есть `Read`, `Grep`, `Glob`; писать ему не нужно. Промпт — этот, с подстановкой, без своих добавлений:

```
Ты — разведчик скилла deep-search. Сначала прочитай бриф <абсолютный путь к reference/brief.md> и работай строго по нему.
Вопрос: <часть вопроса «как сейчас», словами аналитика>
Корень: <абсолютный путь к текущей папке>
Сервис: <имя; два — через запятую>   ← только после выбора аналитика (Шаг 4), одна из двух строк
Репа: <абсолютный путь>              ← только после выбора аналитика (Шаг 4), одна из двух строк
```

В ответе нет хотя бы одного из двух заголовков — `## ОТВЕТ ПО КОДУ`, `## ПРОЧИТАНО` → разведчик работал
не по брифу: запусти его ещё раз тем же промптом. Снова нет — скажи аналитику, что поиск не удался. По
памяти не отвечай.

Субагента запустить нельзя → выполни бриф сам, теми же шагами.

## Шаг 3 — сверка ссылок

Каждую ссылку на код — `<репа>/<путь>:<строка>` или `:<начало>-<конец>` — открой, где бы она ни
стояла: в пункте любого вида и в строке о расхождении карточки с кодом. Файл —
`<абсолютный путь этой репы из ## ПРОЧИТАНО>/<путь>`. `Read`: `offset` — строка (у диапазона —
начало) минус 2, но не меньше 1; `limit` — 5, у диапазона — конец минус начало плюс 5. Ссылка
подтверждена, если в показанных строках есть то, на что пункт по ней опирается: у составного пункта —
своя часть вывода, у `[вне кода]` — отсылка наружу (имя переменной, ключ настройки). Не подтверждена или
файл не открылся → пункт или строку о расхождении убери и добавь в ответ строку «N ссылок не подтвердил
— убрал». Ссылки на `services/` и `context/` не сверяешь.

## Шаг 4 — ответ в чат

```
Как сейчас: <1–3 строки сути словами>
- [в коде] <что делает код> — <репа>/<путь>:<строка>
- [из документа] <что сказано> — services/<файл>.md | context/<файл>.md
- [вне кода] <что и где живёт> — <ссылка на код, который туда отсылает, если есть>
- [не нашёл] <часть вопроса без ответа в коде>
Читал: <репа>, ветка <ветка> — локальная копия, могла отстать от удалённой.
```

- Пункты — из ответа разведчика после сверки, своих не добавляешь. Имена ручек, событий, статусов —
  как в коде.
- Две репы — обе в строке «Читал»; до кода разведчик не дошёл (`репа: —`) — строки «Читал» нет.
- Строка о расхождении карточки с кодом → «Карточка `services/<сервис>.md` расходится с кодом: <что>.
  Обновить: `/service-map <сервис>`».
- **Вопрос о выборе** — в двух случаях: в ответе разведчика есть `## НУЖЕН ВЫБОР` (причина и варианты —
  из блока) или о главном, о чём спрашивают, в ответе нет ни одного пункта `[в коде]` (есть лишь о
  соседнем), а в `## ПРОЧИТАНО` строка `вне манифеста:` — не `—` (причина — «в прочитанном коде ответа
  нет», варианты — эти папки). После ответа — вопрос аналитику: причина одной
  строкой, варианты — до четырёх, остальные — строкой в тексте вопроса; вариант один — вопрос
  «Посмотреть в <вариант>?» с ответами да / нет. Выбор один; при причине «слишком широко» — до двух
  сервисов. Выбран сервис (или два) → разведчик ещё раз, промпт Шага 2 со строкой `Сервис:`; выбрана
  папка — со строкой `Репа:`; «нет» — ответ остаётся как есть. Дальше — как после первого запуска:
  проверка ответа (Шаг 2), Шаги 3 и 4. **Вопрос о выборе — один на вопрос аналитика:** после запуска по
  выбору вариантов больше не предлагаешь.

## Не делаешь

- не читаешь карточки и код сам — кроме сверки на Шаге 3 и случая, когда субагента нет;
- не пишешь и не правишь файлы, не предлагаешь записать ответ;
- не запускаешь git.

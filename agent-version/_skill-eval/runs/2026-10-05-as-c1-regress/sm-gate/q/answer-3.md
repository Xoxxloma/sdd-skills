1. **Ключи.** Все три `###` начинаются правильно: `` `Shipment` ``, `сообщение «…»`, `ограничение «…»`. В заголовке сообщения бэктиков нет. Сошлось.

2. **Состав.** Не сошлось, по двум счётам.
   - **Сообщения.** В описи две строки `сообщение:` («груз доставлен» и «груз задержан»), в «Событиях» два блока `публикует`. В «Бизнес-правилах» один блок «события отправления», то есть меньше двух. Субагент склеил два вида в один с придуманным именем, а правило требует отдельную строку на каждое имя в коде.
   - **Остальное.** Блоков объектов один при одной строке `состояние:` — сошлось. Ограничений один при одной строке `ограничение:` — сошлось. `packageType` и `kind` названы справочниками в описи, блоков не требуют.

3. **Значения.** Формы «Владеет данными» соблюдены: строки `- поле: тип`, значения через `|`. В блоке `Shipment` три строки на три значения, токены — по одному значению, заполнителей нет. Сошлось.

4. **Код.** Вне бэктиков четыре грепа пусты: нет ` /[a-z]`, глаголов HTTP, camelCase и имён с точками. В бэктиках только значения перечисления, `partner-registry` из манифеста и имена топиков. Сошлось.

5. **Переключатель.** `partner-registry` есть в списке манифеста, `true`/`false` в блоке нет. Сошлось.

**1. Ключи.** Сошлось. Три заголовка секции — `` `Shipment` ``, `сообщение «груз доставлен»` и `ограничение «приём отправлений партнёра отключён»` — начинаются как положено. Бэктиков в заголовке сообщения нет, блок объекта один.

**2. Состав.** Сошлось.
- Блоков объектов 1, строк `состояние:` 1.
- Сообщений 1, строк `сообщение:` 1, блоков `публикует` в «Событиях» 1.
- Ограничений 1, строк `ограничение:` 1.
- `Shipment.packageType` и `Attachment.kind` названы в описи справочниками, ничего не пропущено.

**3. Значения.** Не сошлось.
- «Владеет данными» для `Shipment` оформлена таблицей `| Поле | Тип | Описание |`, а нужна форма `- поле: тип`. Это добор раньше всего остального.
- У `Shipment.status` тип `ShipmentStatus` записан без значений через `|`.
- У `Shipment.packageType` тип `PackageType` записан без значений через `|`.
- `Attachment.kind` записан верно.
- Блок `Shipment` в «Бизнес-правилах» сходится: 3 строки на 3 значения, токены `NEW`, `ASSIGNED`, `DELIVERED`, правила разные.

**4. Код.** Сошлось. Вне бэктиков в секции нет ни ` /[a-z]`, ни HTTP-глаголов, ни camelCase, ни точечных имён. В бэктиках только значения перечисления, `partner-registry` из манифеста и топик `shipment.delivered`.

**5. Переключатель.** Сошлось. Условие включает `partner-registry`, это имя из манифеста. `true`/`false` в блоке нет.

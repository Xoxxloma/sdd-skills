**1. Ключи: сошлось.** Заголовки `###` в «Бизнес-правилах»: «`Shipment` — отправление», «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»». Каждый начинается с имени сущности в бэктиках, `сообщение «` или `ограничение «`. Блок сущности один.

**2. Состав: сошлось.** Блок объекта один (`Shipment`), строк `состояние:` одна. Сообщений один блок при одной строке `сообщение:` и одном блоке `публикует` в «Событиях». Ограничений один блок при одной строке `ограничение:`. Перечисления `Shipment.packageType` и `Attachment.kind` названы в описи справочниками, блока не требуют. Пропущенных перечислений нет.

**3. Значения: не сошлось.**
- «Владеет данными» для `Shipment` оформлено таблицей `| Поле | Тип | Описание |`, а не строками `- поле: тип`. Это добор раньше всего остального.
- У `status` тип `ShipmentStatus` и у `packageType` тип `PackageType` стоят без значений через `|`. Это добор. У `Attachment.kind` значения есть.
- В блоке `Shipment` три строки на три значения (`NEW`, `ASSIGNED`, `DELIVERED`). Токены в бэктиках, правила разные, заполнителей и лишних полей нет. Здесь расхождений нет.

**4. Код: сошлось.** Вне бэктиков в секции нет совпадений ни с ` /[a-z]`, ни с HTTP-глаголами, ни с camelCase, ни с точечными именами. В бэктиках только значения перечисления, топик `shipment.delivered` и сервис `partner-registry`. В заголовке сообщения бэктиков нет.

**5. Переключатель: сошлось.** В блоке ограничения условием управляет `partner-registry`, это имя из манифеста. `true`/`false` в блоке нет.

Это единственный добор, из бюджета в два прогона он первый. Состав ключей не меняется, поэтому правки идут только в черновик, опись не трогаем. Ответ добора пройдёт все пять проверок заново.

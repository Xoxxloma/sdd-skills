**1. Ключи.** Опись-строки «Бизнес-правила» → заголовки карточки: `Shipment`, «сообщение «груз доставлен»», «ограничение «файл не является выгрузкой АС Каскад»» — все три начинаются как требуется (сущность в бэктиках / `сообщение «` / `ограничение «`). Сошлось.

**2. Состав.** Опись: состояний 1 (Shipment), справочников 2 (packageType, kind — своих блоков не требуют), сообщений 1, ограничений 1. Карточка: блок объекта — 1 (`Shipment`), блоков `публикует` в «Событиях» — 1, сообщение-блоков — 1, ограничение-блоков — 1. Сошлось.

**3. Значения.** «Владеет данными» — везде `- поле: тип`, одно поле на строку, без таблиц и слипшихся строк. У `status` и `packageType`, `kind` значения через `|`. В блоке `Shipment` строк — 3, значений в `состояние:` — тоже 3 (NEW/ASSIGNED/DELIVERED), без дублей-заполнителей, токен в каждой строке — одно из значений. Сошлось.

**4. Код.** Вне бэктиков секции — только кириллица, ни одного совпадения с `/[a-z]`, HTTP-глаголом, camelCase или dotted-lowercase. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`) и топик `shipment.delivered`; в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** Блок ограничения называет «АС Каскад» тем, кто управляет условием. Манифест: `shipping`, `partner-registry`, `dispatch-web` — АС Каскад отсутствует. Роли карточки: `DISPATCHER`, `COURIER` — АС Каскад отсутствует. Внешняя система исключением не является → не сошлось. (Дополнительно: проверка формата файла — по правилам вообще не ограничение, её место в строке ошибки «Публичного контракта», а не переключатель отдельного правила.)

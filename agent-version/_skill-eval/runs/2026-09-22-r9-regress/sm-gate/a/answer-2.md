**1. Ключи.** Три заголовка в секции — `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все в требуемой форме (сущность в бэктиках / `сообщение «` / `ограничение «`). Расхождений нет.

**2. Состав.** Опись даёт `состояний 2` — `Shipment.status` и `Courier.status`, обе сущности значатся в «Владеет данными». В карточке в «Бизнес-правилах» блок объекта только один — `` `Shipment` ``; блока `` `Courier` `` нет вовсе, хотя `Courier.status ACTIVE | BLOCKED` в описи есть. Не сошлось.

**3. Значения.** В блоке `Shipment` три строки на три значения `NEW | ASSIGNED | DELIVERED`, форма `- поле:` не нарушена, токены не слипаются, заполнителей нет — здесь ок. Но для `Courier` (2 значения `ACTIVE | BLOCKED`) блока нет вообще, то есть 0 строк на 2 значения — тоже расхождение, продолжение того же дефекта.

**4. Код.** Вне бэктиков в секции нет ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей конфига. В бэктиках встречаются только значения перечислений (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё разрешено. Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — не хватает блока объекта `Courier` в «Бизнес-правилах»: две строки бизнес-смысла для `ACTIVE` и `BLOCKED` (по коду, не выдумывая), по форме как у `Shipment`.

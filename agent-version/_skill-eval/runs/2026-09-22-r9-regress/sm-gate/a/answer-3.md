**2. Состав** — опись: `состояние:` 2 строки (Shipment, Courier) → должно быть 2 блока объектов; в карточке блок один (`Shipment`), блока `Courier` нет. Сообщений: опись 1 = карточка 1 (и `публикует shipment.delivered` в «Событиях» тоже 1) — сошлось. Ограничений: опись 1 = карточка 1 — сошлось. Не сошлось: пропущен блок `Courier`.

**3. Значения** — «Владеет данными»: везде `- поле: тип`, одно поле на строку, перечисления через `|` — форма верна. В блоке `Shipment` 3 строки на 3 значения состояния — сошлось; токены `NEW`/`ASSIGNED`/`DELIVERED` — из значений, лишних имён полей нет. Для `Courier` (2 значения) блока нет вообще — не с чем сравнивать, дефект тот же, что в п.2.

**4. Код** — грепы по тексту секции «Бизнес-правила» вне бэктиков: пробел+строчная (` /[a-z]`), HTTP-глаголы, camelCase, точечный путь из 3+ частей — совпадений нет. В бэктиках только значения (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — все допустимые. Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель** — блок ограничения называет `partner-registry`; это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

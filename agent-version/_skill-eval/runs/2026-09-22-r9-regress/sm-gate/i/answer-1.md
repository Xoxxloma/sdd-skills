**1. Ключи.** Заголовки секции «Бизнес-правила»: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, блок объекта один на сущность (Shipment). Сошлось.

**2. Состав.** Опись: 1 состояние (Shipment), 1 сообщение, 1 ограничение, справочников 2 (блоков не дают). Карточка: 1 блок-сущность (Shipment), 1 сообщение, 1 ограничение; Attachment (справочник) блока не имеет. Сошлось.

**3. Значения.** Блок Бизнес-правил `Shipment` — 3 строки на 3 значения состояния (`NEW`/`ASSIGNED`/`DELIVERED`), токены совпадают со значениями, лишних полей нет — тут порядок в норме. Но секция «Владеет данными» для `Shipment` оформлена ТАБЛИЦЕЙ (`| Поле | Тип | Описание |`) вместо строк `- поле: тип` — по правилу это добор раньше всего остального. Дополнительно в этой таблице `status` дан как тип `ShipmentStatus` без перечня значений через `|` — тоже нарушение («тип без значений — добор»). Не сошлось.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» кодовых токенов (путь, HTTP-глагол, camelCase, составной ключ через точки) не найдено; в бэктиках только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`); в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи.** Три `###` в секции: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы соответствуют требуемым префиксам, блок объекта один (на `Shipment`). Сошлось.

**2. Состав.** Опись: `состояние:` — 1 строка (`Shipment`) → карточка даёт 1 блок-сущность (`Shipment`). `сообщение:` — 1 строка, «События» — 1 `публикует` → карточка даёт 1 блок сообщения. `ограничение:` — 1 строка → 1 блок ограничения. Оба справочника (`packageType`, `Attachment.kind`) объектных блоков не получили — верно, они не состояния. Сошлось.

**3. Значения.** «Владеет данными» — везде `- поле: тип`, по одному полю на строку, у перечислений значения через `|`. В блоке `Shipment` строк (3: новое/назначено/доставлено) ровно столько, сколько значений в `состояние:` (`NEW`|`ASSIGNED`|`DELIVERED`), токены — по одному значению на строку, без слипшихся правил и без `/`,`|`,`,` внутри одной строки. Сошлось.

**4. Код.** В тексте секции вне бэктиков нет путей, HTTP-глаголов, camelCase и точечных ключей; в бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё в списке разрешённого. Заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

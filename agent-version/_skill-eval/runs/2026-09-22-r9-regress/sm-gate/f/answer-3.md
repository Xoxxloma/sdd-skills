**1. Ключи.** Заголовки: `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы допустимы, лишних заголовков нет. Сошлось.

**2. Состав.** Объектных блоков 1 (`Shipment`) = сущностей в строках `состояние:` в описи (1). Справочники (`packageType`, `Attachment.kind`) блока не имеют — и не имеют: верно. Сообщений в карточке 1 = строк `сообщение:` в описи (1) = блоков `публикует` в «Событиях» (1). Ограничений 1 = строк `ограничение:` (1). Сошлось.

**3. Значения.** «Владеет данными» — поле на строку, значения через `|`, без таблиц и склеек: сошлось. Но в блоке Бизнес-правил `Shipment` строка «тип упаковки (`BOX` / `PALLET`) — задаётся при создании» — два токена в одной строке через `/`: это справочник (`packageType`), записанный как будто состояние. По правилу гейта — справочник вообще не должен получать строку с бизнес-правилом («от значений которого не зависит ни одно правило»), а тут ему приписано правило да ещё оба значения слиты в одну строку. Не сошлось.

**4. Код.** Вне бэктиков четыре регэкса не дали совпадений (текст на русском, без camelCase и путей). В бэктиках — только значения перечислений (`NEW`, `ASSIGNED`, `DELIVERED`, `BOX`, `PALLET`), имя топика `shipment.delivered`, имя сервиса `partner-registry` — все в белом списке. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

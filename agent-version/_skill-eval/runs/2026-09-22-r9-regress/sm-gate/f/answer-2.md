**1. Ключи.** Все три `###` в «Бизнес-правилах» — ``Shipment``, «сообщение «груз доставлен»», «ограничение «...»» — заголовки в правильной форме, один блок на сущность. Сошлось.

**2. Состав.** Опись даёт 1 сущность в `состояние:` (Shipment), 1 `сообщение:`, 1 `ограничение:`; в карточке ровно 1 блок-сущность, 1 блок-сообщение (плюс 1 `публикует` в «Событиях»), 1 блок-ограничение. Числа совпадают.

**3. Значения.** Блок `Shipment` должен иметь не меньше строк, чем значений в `состояние:` (3: `NEW`/`ASSIGNED`/`DELIVERED`) — там 3 строки по статусу, это ок. Но есть 4-я строка «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: два токена через `/` в одной строке — это справочник `packageType`, записанный как состояние. Справочник блока в «Бизнес-правилах» иметь не должен («Чужая сущность и справочник блока не имеют»). Не сошлось.

**4. Код.** Вне бэктиков в секции — только кириллица, латиница только внутри бэктиков (`Shipment`, `NEW`, `ASSIGNED`, `DELIVERED`, `BOX`, `PALLET`, `shipment.delivered`, `partner-registry`), и содержимое бэктиков — либо значения перечисления, либо имя топика, либо имя сервиса из манифеста. Заголовки сообщения/ограничения без бэктиков. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — в блоке `Shipment` секции «Бизнес-правила» убрать строку «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: это справочник `packageType`, а не значение `состояние:`, и записан двумя токенами через `/` в одной строке — справочник, выданный за состояние; блок `Shipment` должен содержать ровно 3 строки (по `NEW`/`ASSIGNED`/`DELIVERED`), справочник своего блока не получает.

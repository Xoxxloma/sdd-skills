**1. Ключи.** Три заголовка в «Бизнес-правилах»: `` `Shipment` `` (сущность в бэктиках), «сообщение «…»», «ограничение «…»» — форма заголовков соблюдена, один блок на сущность. Сошлось.

**2. Состав.** Блоков-сущностей — 1 (`Shipment`), строк `состояние:` в описи — 1. Сообщений в карточке — 1, строк `сообщение:` — 1, `публикует` в «Событиях» — 1 (`shipment.delivered`). Ограничений — 1 и 1. Справочники (`packageType`, `Attachment.kind`) блоков не получили — верно, блока не имеют. Сошлось.

**3. Значения.** «Владеет данными» — по одному полю на строку, без таблиц и слипаний; у `status`, `packageType`, `kind` значения через `|`. Блок `Shipment` в «Бизнес-правилах» содержит 3 строки на 3 значения из `состояние:` (NEW/ASSIGNED/DELIVERED), без дублей и посторонних полей. Сошлось.

**4. Код.** Заголовок сообщения — `### сообщение «\`shipment.delivered\`»` — содержит бэктики. Правило прямо запрещает: «ни одного бэктика в заголовке сообщения». Нарушение. Остальные бэктики в теле секции (`NEW`, `ASSIGNED`, `DELIVERED`, топик `shipment.delivered`, `partner-registry`) — допустимого состава (значение, топик, имя сервиса из манифеста). Не сошлось.

**5. Переключатель.** У ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — убрать бэктики из заголовка блока сообщения: `### сообщение «\`shipment.delivered\`»` → `### сообщение «shipment.delivered»` (бэктик в заголовке сообщения запрещён правилом 4; тело блока и остальные разделы не трогать).

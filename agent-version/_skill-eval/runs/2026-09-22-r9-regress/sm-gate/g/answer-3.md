**1. Ключи.** Три `###`: `` `Shipment` — отправление ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все начинаются по форме (сущность в бэктиках / «сообщение «» / «ограничение «»). Сошлось.

**2. Состав.** Опись: `состояние:` 1 строка (Shipment) → в карточке 1 блок-сущность (Shipment). `сообщение:` 1 строка, `публикует` в «Событиях» 1 блок → в карточке 1 блок сообщения. `ограничение:` 1 строка → в карточке 1 блок ограничения. Attachment — только справочник, без состояния, блока не имеет — верно по правилу «справочник блока не имеет». Сошлось.

**3. Значения.** «Владеет данными»: одно поле на строку, перечисления через `|` — форма верна. Но в блоке `Shipment` строк 4 при 3 значениях состояния (`NEW`/`ASSIGNED`/`DELIVERED`): строка «перевешено (`ASSIGNED`, `weightKg` изменён)» повторяет токен `ASSIGNED` и добавляет в скобки не дату, а имя поля `weightKg` — это не разрешённое исключение (дата), а «любое другое имя поля — строка на поле». Не сошлось.

**4. Код.** В той же строке в бэктиках стоит `weightKg` — имя поля, а не значение перечисления/имя вида/топика/имя сервиса/дата; такое не допустимо нигде в секции даже в бэктиках. Остальные бэктики секции (`shipment.delivered`, `partner-registry`) законны. Не сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

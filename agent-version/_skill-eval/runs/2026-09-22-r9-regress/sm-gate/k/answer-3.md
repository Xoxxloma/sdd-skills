**1. Ключи.** Опись даёт 3 объекта бизнес-правил: `состояние: Shipment...`, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»`. В карточке заголовки: `### Отправление (\`Shipment\`)`, `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»`. Два последних в форме, первый — нет: перед именем сущности стоит подпись «Отправление» (в разделе «Владеет данными» тот же блок оформлен верно — `### \`Shipment\` — отправление`). Не сошлось.

**2. Состав.** Строк `состояние:` — 1 сущность (Shipment) → блоков объектов должно быть 1, есть 1. Строк `сообщение:` — 1, блоков `публикует` в «Событиях» — 1, блоков сообщения в правилах — 1. Строк `ограничение:` — 1, блоков — 1. Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не имеют — верно, они не должны их иметь. Сошлось.

**3. Значения.** «Владеет данными» — строго `- поле: тип`, одно поле на строку, оба блока (`Shipment`, `Attachment`) в форме, без таблиц и слипшихся строк. В блоке состояния строк 3 (`NEW`/`ASSIGNED`/`DELIVERED`), значений в `состояние:` — 3. Сошлось.

**4. Код.** По секции «Бизнес-правила» вне бэктиков — только кириллическая проза, без пути, HTTP-глагола, camelCase или точечного ключа. В бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`), имя сервиса из манифеста (`partner-registry`) и имя сущности в заголовках. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

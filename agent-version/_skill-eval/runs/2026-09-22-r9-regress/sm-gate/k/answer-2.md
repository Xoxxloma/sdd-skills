**1. Ключи.** Опись/шаблон требуют, чтобы каждый `###` секции начинался с имени сущности в бэктиках, `сообщение «` или `ограничение «`. У «сообщение «груз доставлен»» и «ограничение «приём отправлений партнёра отключён»» — верно. У блока состояния — `### Отправление (`Shipment`)`: перед ключом стоит подпись «Отправление (», это ровно случай «подпись впереди ключа» из запрещённого списка. Не сошлось.

**2. Состав.** Строк `состояние:` в описи — 1 (Shipment), блоков объектов в карточке — 1. Строк `сообщение:` — 1, блоков сообщений — 1, и это же число совпадает с блоком `публикует shipment.delivered` в «Событиях». Строк `ограничение:` — 1, блоков ограничений — 1. Справочники (`packageType`, `Attachment.kind`) блоков не имеют, как и положено чужой/невладеемой сущности — тут её нет, обе свои, но справочники блока не получают по правилу, и в карточке блоков под них нет. Сошлось.

**3. Значения.** «Владеет данными» — по одному полю на строку, значения через `|`, тип без значений не используется как перечисление (weightKg, url — не перечисления). В блоке `Shipment` строк — 3 (новое/назначено/доставлено), в описи `состояние:` — 3 значения (NEW|ASSIGNED|DELIVERED). Токен каждой строки — один из этих трёх, других имён полей нет, слипшихся токенов через `/`, `|`, `,` нет. Сошлось.

**4. Код.** Вне бэктиков в секции «Бизнес-правила» нет путей (` /[a-z]`), HTTP-глаголов, camelCase-слов и точечных ключей — весь текст русскими словами. В бэктиках — только `Shipment`, `NEW`/`ASSIGNED`/`DELIVERED`, `shipment.delivered` (топик), `partner-registry` (имя сервиса из манифеста): всё разрешённое. Сошлось.

**5. Переключатель.** Блок ограничения: «условием управляет `partner-registry`» — имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

Проверяю пять чисел гейта «Бизнес-правила» по сервису `shipping`.

**(1) Блоки объектов = сущности из строк `состояние:`, плюс по блоку на `сообщение:`/`ограничение:`.**
В описи одна строка `состояние:` (Shipment) — значит один блок объекта. `Attachment.kind` в описи назван `справочник:`, блока не получает — и в карточке его действительно нет. Итого ожидаю 3 блока (Shipment + сообщение + ограничение), в карточке ровно 3. Сошлось.

**(2) Строк `-` в блоке `Shipment` не меньше значений всех его `состояние:` строк.**
Опись: `состояний 1 (значений 3)`. В блоке карточки три строки — `NEW`, `ASSIGNED`, `DELIVERED`. Сошлось.

**(3) Токены в бэктиках внутри блока объекта — значения из «Владеет данными».**
`NEW`, `ASSIGNED`, `DELIVERED` — все три стоят справа от `:` в строке `- status: NEW | ASSIGNED | DELIVERED` в «Владеет данными». Ни одного выдуманного токена, ни строки на поле, ни строки с `/`/`|`. Сошлось.

**(4) Блоков сообщений не меньше блоков `публикует` и не меньше строк `сообщение:`.**
В «Событиях» один блок `публикует shipment.delivered`, в описи одна строка `сообщение:`, в карточке один блок сообщения. 1 ≥ 1 и 1 ≥ 1. Сошлось.

**(5) Блоков ограничений столько, сколько строк `ограничение:`; в блоке назван тот, кто управляет условием.**
По счёту: 1 строка `ограничение:` — 1 блок. Но внутри блока `ограничение «приём отправлений партнёра отключён»` названо только условие и его последствие («новые отправления не принимаются, диспетчер видит причину отказа») — нет ни имени сервиса из манифеста (`partner-registry`?), ни пометки «вне манифеста», ни роли из «Роли и доступ». «Диспетчер видит причину» — это следствие для наблюдателя, а не хозяин условия. Не сошлось: условие без названного управляющего.

ГЕЙТ: ДОБОР — в блоке `ограничение «приём отправлений партнёра отключён»` назвать, кто управляет условием: имя соседа из манифеста (например, `partner-registry`), пометка «вне манифеста» или роль из «Роли и доступ» — сейчас назван только эффект (диспетчер видит отказ), а не хозяин флага.

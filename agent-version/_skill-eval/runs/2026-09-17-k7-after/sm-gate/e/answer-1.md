Прогнал пять чисел гейта по карточке `shipping`.

1. **Блоки объектов vs сущности из `состояние:`** — в описи одна сущность в `состояние:` (`Shipment`), чужих/на-чтение сущностей нет. В карточке один блок объекта `Shipment`, блока для `Attachment` (только `справочник:`) нет — верно, справочник блока не получает. Совпало.

2. **Строк `-` в блоке объекта vs сумма значений `состояние:`** — у `Shipment.status` 3 значения (NEW/ASSIGNED/DELIVERED), в блоке ровно 3 строки (`новое`, `назначено`, `доставлено`). Совпало.

3. **Бэктик-токены внутри блока объекта — значения из «Владеет данными»** — `NEW`, `ASSIGNED`, `DELIVERED` есть справа от `:` в `Shipment.status` в «Владеет данными», выдуманных токенов и токенов-полей нет. Совпало.

4. **Блоков сообщений vs блоков `публикует` и строк `сообщение:`** — по счёту 1 = 1 = 1, но заголовок блока — `### сообщение «`shipment.delivered`»` — содержит бэктик внутри заголовка. Правило прямо запрещает это: «Бэктик внутри заголовка `сообщение «…»` — добор: заголовок пишется словами, токен стоит в строке». Не совпало.

5. **Блоков ограничений vs строк `ограничение:`** — по счёту 1 = 1; в теле нет `true`/`false`, названо, кто управляет (`partner-registry`, сосед из манифеста), условие словами. Совпало.

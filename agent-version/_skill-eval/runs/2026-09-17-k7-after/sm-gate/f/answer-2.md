Прогон гейта «Бизнес-правила» по `shipping`:

**(1) Число блоков-объектов.** В описи строка `состояние:` только у `Shipment` (1 сущность) → 1 блок-объект; плюс по строке `сообщение:` (1) и `ограничение:` (1) → всего 3 блока. В карточке ровно 3 блока: `Shipment`, сообщение «груз доставлен», ограничение «приём отправлений партнёра отключён». `Attachment` (только справочник, без `состояние:`) блока не получил — верно. Совпало.

**(2) Строк `-` в блоке объекта не меньше значений.** `состояние: Shipment.status` — 3 значения (NEW/ASSIGNED/DELIVERED). В блоке `Shipment` есть три строки под эти значения. Совпало (≥3).

**(3) Каждый токен в блоке объекта — значение из «Владеет данными».** NEW/ASSIGNED/DELIVERED — справа от `status:` в «Владеет данными», ОК. Но четвёртая строка блока — «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: `packageType` в описи помечен как `справочник:`, а справочник блока в «Бизнес-правилах» не получает вовсе. Строка не называет ни того, кто переводит значение, ни условие, ни следствие — просто факт «задаётся при создании». Это справочник, записанный состоянием внутри чужого блока. **Не совпало.**

**(4) Блоков сообщений.** 1 блок сообщения = 1 `публикует` в «Событиях» = 1 строка `сообщение:` в описи. Совпало.

**(5) Блоков ограничений.** 1 блок = 1 строка `ограничение:` в описи; названо, кто управляет (`partner-registry`, сосед из манифеста), названо, что отказывает; ни одного `true`/`false`. Совпало.

ГЕЙТ: ДОБОР — убрать из блока `Shipment` строку про «тип упаковки (`BOX` / `PALLET`)»: `packageType` в описи — справочник, справочник блока в «Бизнес-правилах» не получает; эта строка — справочник, записанный состоянием, лишняя внутри объектного блока.

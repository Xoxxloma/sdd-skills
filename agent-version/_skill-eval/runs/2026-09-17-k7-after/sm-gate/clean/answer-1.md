Прогоняю пять чисел гейта «Бизнес-правила» по карточке `shipping`.

**(1) Блоки объектов/сообщений/ограничений vs опись.** Строка `состояние:` в описи — одна, на сущность `Shipment` → в карточке ровно один блок объекта `### Shipment — отправление`, блока для `Attachment` нет (у неё только `справочник:`, объектного блока не положено) — сошлось. Строка `сообщение:` — одна → один блок сообщения — сошлось. Строка `ограничение:` — одна → один блок ограничения — сошлось. Справочники (`packageType`, `kind`) блоков не получили — верно.

**(2) Строк `-` в блоке объекта vs значений в `состояние:`.** В описи у `Shipment.status` три значения (NEW | ASSIGNED | DELIVERED); в блоке `Shipment` — три строки (новое / назначено / доставлено). 3 = 3 — сошлось.

**(3) Бэктик-токены в блоке объекта vs «Владеет данными».** Токены `NEW`, `ASSIGNED`, `DELIVERED` — все стоят справа от `:` в строке `- status: NEW | ASSIGNED | DELIVERED` в «Владеет данными», лишних токенов и токенов-имён полей нет — сошлось.

**(4) Блоков сообщений vs `публикует` в «Событиях» и vs `сообщение:` в описи.** В «Событиях» один блок `публикует shipment.delivered`, в описи одна строка `сообщение:` — блоков сообщений в карточке тоже один: 1 ≥ 1 и 1 ≥ 1 — сошлось. Заголовок блока «сообщение «груз доставлен»» — без бэктика, топик `shipment.delivered` в строке — оформлено верно.

**(5) Блоков ограничений vs строк `ограничение:`.** В описи одна строка, в карточке один блок; `true/false` не встречается, управляющий назван — `partner-registry`, это имя сервиса из манифеста (`shipping`, `partner-registry`, `dispatch-web`) — сошлось.

Все пять чисел совпали, доборных признаков (чужая сущность, сочинённый токен, свёрнутое сообщение, флаг без хозяина) нет.

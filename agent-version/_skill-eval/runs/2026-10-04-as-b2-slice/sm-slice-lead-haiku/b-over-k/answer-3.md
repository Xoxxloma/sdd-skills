## Разбор

Вес сервиса = сумма маркеров `ключ` + 0.5 × сумма маркеров `ориентир`:
- Маркеры `ключ`: 96 (контракт) + 41 (сущности) + 6 (задачи) = 143
- Маркеры `ориентир`: 9 (топики)
- Вес = 143 + 0.5 × 9 = 147.5

Пороговое значение K = 80. Поскольку 147.5 > 80, по правилу 3.5 нужна нарезка на части. Командная строка есть (указано в условиях), поэтому нарезка возможна. Её реализует `plan.sh`, который разделит сервис на части по папкам и файлам, каждую будет читать свой субагент параллельно.

## Действия

ДЕЙСТВИЕ: Запустить `reference/plan.sh` с файлом counts сервиса для определения плана нарезки (части, остаток, распределение классов)

ДЕЙСТВИЕ: По результатам плана запустить читающих субагентов параллельно — по одному на каждую часть (01…S) и остаток (S+1), не больше 6 одновременно, с брифом из раздела 3.3 плюс блок «Ты читаешь часть сервиса» (каждому свои пути из плана)

ДЕЙСТВИЕ: После возврата всех частей запустить голову (субагента для шапки и общих секций) с брифом раздела 3.5

ДЕЙСТВИЕ: После возврата головы запустить `reference/assemble.sh` для склейки частей в финальный черновик и опись

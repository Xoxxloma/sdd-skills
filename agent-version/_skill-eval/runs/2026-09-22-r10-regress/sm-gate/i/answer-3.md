**1. Ключи.** Заголовки секции: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены. Сошлось.

**2. Состав.** Опись: 1 состояние → 1 блок сущности (Shipment, есть); 1 сообщение / 1 `публикует` в «Событиях» → 1 блок сообщения (есть); 1 ограничение → 1 блок ограничения (есть). Справочники (Shipment.packageType, Attachment.kind) блока не получили — верно, справочник блока не имеет. Сошлось.

**3. Значения.** Секция «Владеет данными» у `Shipment` оформлена таблицей `| Поле | Тип | Описание |`, а не строками `- поле: тип` — добор раньше всего остального. Плюс `status` дан как тип `ShipmentStatus` без перечня значений (`NEW | ASSIGNED | DELIVERED` не вписаны в строку поля), что тоже добор по правилу «тип без значений». (Блок `Attachment` при этом в правильной форме списка — не трогать.) Не сошлось.

**4. Код.** По тексту блоков «Бизнес-правила» (`Shipment`, сообщение, ограничение) — ни одного пути, HTTP-глагола, camelCase или точечного ключа вне бэктиков; в бэктиках только значения (`NEW`/`ASSIGNED`/`DELIVERED`), топик (`shipment.delivered`) и имя из манифеста (`partner-registry`). Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

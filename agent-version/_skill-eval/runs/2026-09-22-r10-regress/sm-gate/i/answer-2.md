**1. Ключи.** Заголовки блоков «Бизнес-правил»: `Shipment` (в бэктиках), «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все три формы разрешены, добора нет.

**2. Состав.** Опись: состояние 1 (Shipment) → блоков-сущностей 1, есть. Сообщений в описи 1, в «Событиях» `публикует` 1, в «Бизнес-правилах» блок сообщения 1 — сошлось. Ограничений в описи 1, блок 1 — сошлось. Attachment (справочник) блока не имеет — верно, справочники блоков не получают.

**3. Значения.** Секция «Владеет данными» для `Shipment` оформлена таблицей `| Поле | Тип | Описание |`, а не строками `- поле: тип` — прямое нарушение формы, и по правилу это добор раньше всего остального. Заодно `status: ShipmentStatus` дан без перечня значений через `|` (тип без значений). Для Attachment форма верная (`- kind: PHOTO | PDF`).

**4. Код.** В «Бизнес-правилах» вне бэктиков ни одного совпадения с четырьмя грепами; в бэктиках только `NEW`/`ASSIGNED`/`DELIVERED`, `shipment.delivered` (топик), `partner-registry` (имя из манифеста) — всё допустимо.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`) — сошлось.

ГЕЙТ: ДОБОР — переписать секцию «Владеет данными» из табличной формы `| Поле | Тип | Описание |` в форму `- поле: тип`, и для `Shipment.status` дать значения через `|` в строке `- status:` (`NEW | ASSIGNED | DELIVERED`) вместо голого типа `ShipmentStatus`.

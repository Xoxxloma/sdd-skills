Прогнал гейт «Бизнес-правила» по пяти пунктам:

**1. Ключи.** Заголовки: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные, один блок на сущность (`Shipment`). Сошлось.

**2. Состав.** Строк `состояние:` в описи — 1 (`Shipment`) → 1 блок объекта в карточке, сошлось. `сообщение:` — 1 строка в описи, 1 блок в карточке, и 1 блок `публикует` в «Событиях» — 1≥1. `ограничение:` — 1 строка, 1 блок. `Attachment` (справочник, не состояние) блока не имеет — верно. Сошлось.

**3. Значения.** Форма «Владеет данными» — списком `- поле: тип`, не таблицей. Значения через `|`. Но в блоке `Shipment` строк 4, а значений в `состояние:` — 3 (`NEW|ASSIGNED|DELIVERED`): три строки закрывают состояния, четвёртая — «коробка (`BOX`), паллета (`PALLET`) — тип упаковки» — это `packageType`, справочник из описи, два токена через запятую в одной строке. Это ровно случай «справочник, записанный состоянием» — не сошлось, добор.

**4. Код.** Вне бэктиков ни одного совпадения по четырём грепам; в бэктиках только значения перечислений, топик `shipment.delivered` и имя сервиса `partner-registry` из манифеста. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

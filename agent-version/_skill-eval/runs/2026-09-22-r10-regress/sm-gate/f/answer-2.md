**1. Ключи.** Заголовки блоков: `` `Shipment` ``, `` `Attachment` `` (в «Владеет данными», без блока в БП — верно), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все начинаются как положено, посторонних заголовков нет. Сошлось.

**2. Состав.** Состояние: 1 сущность (Shipment) → 1 блок объекта в БП — есть. Сообщений в описи 1, публикует-блоков в «Событиях» 1, блок сообщения в БП 1 — сошлось. Ограничений в описи 1, блок 1 — сошлось. Attachment (справочник) блока не имеет — верно по правилу «справочник блока не имеет». Сошлось.

**3. Значения.** «Владеет данными» — верная форма `- поле: тип` со значениями через `|` для обоих перечислений. Но в блоке `Shipment` четвёртая строка — «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: это `packageType`, справочник, а не состояние, и записан строкой с двумя токенами через `/` — ровно случай «справочник, записанный состоянием: добор». Не сошлось.

**4. Код.** Вне бэктиков камелкейсов, HTTP-глаголов, путей и точечных ключей не встречено; в бэктиках — только значения перечислений, имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

**5. Переключатель.** Ограничение называет переключатель `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — убрать из блока «Бизнес-правила» `### \`Shipment\`` строку «тип упаковки (`BOX` / `PALLET`) — задаётся при создании»: это справочник `packageType` (не влияет ни на одно правило), записанный как состояние с двумя токенами через `/`; в блоке должны остаться только 3 строки по значениям `status` (NEW/ASSIGNED/DELIVERED), справочник в «Бизнес-правилах» не отражается.

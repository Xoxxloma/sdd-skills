**1. Ключи.** Три `###`: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верные. Сошлось.

**2. Состав.** Блоков объектов 1 = сущностей в `состояние:` 1 (Shipment). Сообщений 1 ≥ строк `сообщение:` (1) и ≥ блоков `публикует` (1). Ограничений 1 = строк `ограничение:` (1). Сошлось.

**3. Значения.** Форма «Владеет данными» — строки `- поле: тип`, не таблица. В блоке `Shipment` под значения `NEW|ASSIGNED|DELIVERED` (3) — три строки, дано. Но добавлена четвёртая строка: «тип упаковки (`BOX` / `PALLET`) — задаётся при создании» — два токена через `/` в одной строке блока состояния. Это ровно случай «справочник, записанный состоянием»: `packageType` — справочник (в описи `справочник: Shipment.packageType`, а не `состояние:`), и по правилу справочник не должен иметь строк в «Бизнес-правилах» вовсе. Не сошлось.

**4. Код.** Вне бэктиков — ни одного совпадения по четырём регэкспам, в бэктиках только значения перечислений (`NEW`, `BOX` и т.д.) и имя сервиса `partner-registry`. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

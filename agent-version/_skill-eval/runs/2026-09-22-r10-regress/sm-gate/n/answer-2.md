**1. Ключи.** Три `###`: `` `Shipment` `` (сущность в бэктиках), `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы верны, блок объекта один. Сошлось.

**2. Состав.** Опись: `состояние:` — 1 сущность (Shipment) → карточка: 1 объектный блок. `сообщение:` — 1 строка, `публикует` в «Событиях» — 1 блок → карточка: 1 блок сообщения (1≥1, 1≥1). `ограничение:` — 1 строка → карточка: 1 блок. Своя сущность без блока не пропущена (Attachment — не состояние, справочники packageType/kind блока не имеют, как и положено). Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица. Перечисления через `|` в строке `- поле:` есть у всех трёх (status, packageType, kind). В блоке `Shipment` строк 5, значений в `состояние:` — тоже 5 (`NEW/ASSIGNED/DELIVERED/CANCELLED/LOST`), каждая строка — один токен, два `не определено` на разных значениях (не дубль правила), нет строк с несколькими токенами через `/`, `,`. Сошлось.

**4. Код.** Вне бэктиков — только русский текст, ни одного совпадения с HTTP-глаголами, `/[a-z]`, camelCase, точечными ключами. В бэктиках — только значения перечисления (`NEW`…`LOST`), имя топика (`shipment.delivered`), имя сервиса из манифеста (`partner-registry`); заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

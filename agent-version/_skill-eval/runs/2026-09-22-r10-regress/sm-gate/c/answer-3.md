1. **Ключи.** Все 4 заголовка — `Shipment`, `Department`, сообщение «груз доставлен», ограничение «...» — начинаются с сущности в бэктиках либо `сообщение «`/`ограничение «`. Форма сошлась.

2. **Состав.** Блоков-состояний 2, в описи `состояние:` тоже 2 (Shipment, Department) — числа сошлись, но `Department` в карточке сам помечен «схема partner-registry, на чтение» — это чужая сущность. По правилу чужая сущность строки `состояние:` в описи не получает и блока в «Бизнес-правилах» не имеет, а у неё есть оба. Расхождение.

3. **Значения.** Форма `- поле: тип` соблюдена, не таблица. В блоке `Shipment` 3 строки на 3 значения состояния, в блоке `Department` 2 строки на 2 значения — количественно сходится, но сам блок `Department` не должен существовать (см. п.2).

4. **Код.** По пяти грепам вне бэктиков — ни одного совпадения (` /[a-z]`, `GET|POST|...`, camelCase, `a.b.c`); в бэктиках — только значения перечислений (`NEW`, `BRANCH`...), имя топика `shipment.delivered` и имя сервиса `partner-registry` — всё из разрешённого списка. Чисто.

5. **Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

**1. Ключи** — заголовки секции: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»`. Все три в допустимой форме (сущность в бэктиках / «сообщение «» / «ограничение «»). Сошлось.

**2. Состав** — в описи `состояние:` встречается дважды: `Shipment.status` и `Courier.status` (итог `⟹ состояний 2`). В карточке блок сущности в «Бизнес-правилах» только один — `` `Shipment` ``; блока `` `Courier` `` нет, хотя `Courier` есть и во «Владеет данными», и в описи как состояние. Не сошлось.

**3. Значения** — для того, что есть: блок `Shipment` содержит 3 строки (`NEW`/`ASSIGNED`/`DELIVERED`) на 3 значения статуса из описи, каждый токен — отдельная строка, без склеек через `/` или запятую. Для `Courier` (2 значения `ACTIVE`/`BLOCKED`, входят в итог «значений 5») сравнивать нечего — блока нет. Частично не сошлось (из-за пропуска п.2).

**4. Код** — по тексту секции «Бизнес-правила»: ни одной строки с ` /[a-z]`, `GET|POST|PUT|PATCH|DELETE`, camelCase или трёхсегментным `a.b.c` вне бэктиков; в бэктиках только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё допустимое, заголовок сообщения без бэктиков. Сошлось.

**5. Переключатель** — в блоке ограничения назван `partner-registry`; он есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

ГЕЙТ: ДОБОР — не хватает блока объекта `` `Courier` `` в секции «Бизнес-правила»: в описи `состояние: Courier.status ACTIVE | BLOCKED` есть, а раскрытого правила для этих двух значений в карточке нет (итог описи «состояний 2 (значений 5)» не покрыт — раскрыты только 3 значения `Shipment`). Требую у субагента добавить блок `### `Courier` — курьер` с двумя строками, по одной на `ACTIVE` и `BLOCKED`, с фактом перехода по коду (или `не определено`, если перехода нет), правкой только через `Edit` в черновике (опись менять не нужно — она уже содержит обе строки состояния).

Прогоняю пять чисел гейта по присланным фрагментам.

1. **Ключи.** Заголовки в «Бизнес-правилах»: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три в допустимой форме (сущность в бэктиках / «сообщение «» / «ограничение «»). По присутствующим блокам сошлось.

2. **Состав.** Опись даёт `состояний 2` — `Shipment.status` и `Courier.status`. В «Бизнес-правилах» блок объекта есть только для `Shipment`; блока `Courier` нет вовсе, хотя сущность есть в «Владеет данными» и имеет свою строку `состояние:` в описи. Не сошлось.

3. **Значения.** Для присутствующего блока `Shipment`: 3 строки на 3 значения (`NEW`/`ASSIGNED`/`DELIVERED`), форма «Владеет данными» — списком `- поле: тип`, не таблицей; токены совпадают со значениями. Сообщений (1 в описи = 1 блок = 1 `публикует` в «Событиях») и ограничений (1 = 1) — сошлось. Значения для `Courier` проверить не на чем — блока нет (тот же дефект, что в п.2).

4. **Код.** Вне бэктиков в тексте секции нет путей, HTTP-глаголов, camelCase или точечных ключей; в бэктиках — только значения перечисления (`NEW`, `ASSIGNED`, `DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — всё в списке разрешённого. Сошлось.

5. **Переключатель.** В блоке ограничения назван `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

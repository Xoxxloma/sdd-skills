**1. Ключи (заголовки).** Три блока — `` `Shipment` ``, «сообщение «груз доставлен»», «ограничение «приём отправлений партнёра отключён»» — все начинаются по форме (имя сущности в бэктиках / `сообщение «` / `ограничение «`). Сошлось.

**2. Состав.** В описи две строки `состояние:` — `Shipment.status` и `Courier.status` → блоков объектов должно быть 2. В карточке в «Бизнес-правилах» есть только `` `Shipment` ``, блока `` `Courier` `` нет вовсе. Не сошлось.
Сообщений: опись 1 строка `сообщение:`, карточка — 1 блок сообщения и 1 «публикует» в «Событиях». Сошлось.
Ограничений: опись 1, карточка 1. Сошлось.

**3. Значения.** «Владеет данными» — форма `- поле: тип`, не таблица; у каждого перечисления значения через `|`. В блоке `` `Shipment` `` 3 строки на 3 значения из `состояние: Shipment.status NEW | ASSIGNED | DELIVERED` — сошлось, один токен на строку. Блок `Courier` проверить нельзя — его нет.

**4. Код.** Пять грепов по тексту «Бизнес-правил»: ` /[a-z]`, HTTP-глаголы, camelCase, дотted-ключи ≥3 сегментов — совпадений нет. В бэктиках только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`) — состав бэктиков разрешённый, в заголовке сообщения бэктиков нет. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

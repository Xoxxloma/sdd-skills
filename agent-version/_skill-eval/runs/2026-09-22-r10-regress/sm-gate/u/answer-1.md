**1. Ключи.** Три заголовка секции: `` `Shipment` — отправление``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы разрешены, блок объекта один (Shipment). Сошлось.

**2. Состав.** Опись: 1 `состояние:` (Shipment) → 1 объектный блок в карточке — есть. 1 `сообщение:` и 1 `публикует` в «Событиях» → 1 блок сообщения — есть. 1 `ограничение:` → 1 блок ограничения — есть. Справочники (`Shipment.packageType`, `Attachment.kind`) блоков не получили — верно, справочник блока не имеет. Сошлось.

**3. Значения.** Форма «Владеет данными» должна быть строками `- поле: тип`, по одному полю на строку. У `Shipment` все три поля (`status`, `packageType`, `weightKg`) слиты в ОДНУ строку через « · »: `` - `status`: ... · `packageType`: ... · `weightKg`: decimal``. Это не форма «строки `- поле: тип`» — не сошлось. (Отдельно: число строк в блоке правил Shipman = 3, равно числу значений `NEW|ASSIGNED|DELIVERED` из `состояние:` — это само по себе верно, но форма «Владеет данными» — общий провал этого пункта.)

**4. Код.** В секции «Бизнес-правила» вне бэктиков нет ни пути, ни HTTP-глагола, ни camelCase, ни точечного ключа; в бэктиках — только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), имя топика (`shipment.delivered`) и имя сервиса из манифеста (`partner-registry`). Сошлось.

**5. Переключатель.** Блок ограничения называет `partner-registry` — это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

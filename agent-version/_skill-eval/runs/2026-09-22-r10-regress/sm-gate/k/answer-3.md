**1. Ключи.** Опись: 1 состояние, 1 сообщение, 1 ограничение. Заголовки карточки: `### Отправление (\`Shipment\`)`, `### сообщение «груз доставлен»`, `### ограничение «приём отправлений партнёра отключён»`. Первый заголовок не начинается с имени сущности в бэктиках — впереди ключа стоит подпись «Отправление (…)». Не сошлось.

**2. Состав.** Блоков-сущностей 1 (Shipment, справочник Attachment.kind своего блока не получил — верно), сообщений 1 = 1 строке `сообщение:` и 1 блоку `публикует`, ограничений 1 = 1 строке `ограничение:`. Сошлось.

**3. Значения.** Форма `- поле: тип`, не таблица. В блоке Shipment 3 строки на 3 значения `состояние:` (NEW/ASSIGNED/DELIVERED), в каждой строке ровно один токен-значение, дублей правила на разных значениях нет. Сошлось.

**4. Код.** По тексту секции «Бизнес-правила» вне бэктиков нет путей, HTTP-глаголов, camelCase и точечных ключей; в бэктиках только значения перечисления (`NEW`/`ASSIGNED`/`DELIVERED`), топик `shipment.delivered` и имя сервиса `partner-registry` из манифеста. Сошлось.

**5. Переключатель.** В блоке ограничения назван `partner-registry` — есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

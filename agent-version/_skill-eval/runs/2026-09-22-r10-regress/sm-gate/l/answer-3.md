**1. Ключи** — три `###`: `` `Shipment` ``, `сообщение «груз доставлен»`, `ограничение «приём отправлений партнёра отключён»` — все три формы допустимые. Сошлось.

**2. Состав** — состояние: 1 (Shipment) → блоков объектов 1, есть. Сообщений: строк `сообщение:` 1, блоков `публикует` 1 → блок сообщения 1, есть. Ограничений: строка 1 → блок 1, есть. Attachment (справочник) блока не имеет — верно. Сошлось.

**3. Значения** — «Владеет данными» в форме `- поле: тип`, не таблица — ок. В блоке Shipment строк 5 = значений в `состояние:` (5) — счётно сходится, но:
`CANCELLED` и `LOST` — две строки с буквально одним и тем же правилом («значение enum, отдельного кода перехода нет; проставляется напрямую при смене статуса») на разных значениях. Это ровно заполнитель по правилу гейта — переход не описан, должно быть `не определено`, а не одинаковый шаблонный текст. Не сошлось.

**4. Код** — вне бэктиков в секции «Бизнес-правила» нет ни путей, ни HTTP-глаголов, ни camelCase, ни точечных ключей; в бэктиках только значения enum, топик и имя сервиса из манифеста. Сошлось.

**5. Переключатель** — ограничение называет `partner-registry`, это имя есть в списке манифеста (`shipping`, `partner-registry`, `dispatch-web`). Сошлось.

# Раунд sm320 — критерии до прогонов (service-map-2.0 3.2.0)

Записано 2026-10-08 до первого прогона раунда. Модель стенда — Sonnet, промпт пилота 3.0.9
(`runs/2026-10-06-pilot-309/prompt-pilot.md`: рабочие файлы не убираются, подсказок нет).

## Что меряем

Прод-прогон 4 (adjutant, 3.1.1): ручки на месте, но 73 из 115 REST-блоков без фактов — файл спеки
(~103 операции) достался одной части; у 49 операций GraphQL пропал тип; часть 04 нарушила договор о
файлах. Правки 3.2.0: спека режется по операциям на куски ≤ K, строки заданий печатает `plan.sh`,
пустота по частям — в добор, тип GraphQL при сверке описи не важен, остаток — в одной волне с
частями, одна волна доборов.

## Критерии

**Большая спека** (`SM-MONO-SPEC --big-spec`, ×3):
- карточка записана 3/3;
- контракт ≥ 95 % правды, лишних 0, операций без реализации в карточке 0;
- блоков контракта без фактов ≤ 15 % по карточке и ≤ 25 % в любой части;
- анкеры фактов операций спеки в своих блоках ≥ 75 %;
- ни одна часть не больше K (в плане спека разрезана, куски ≤ 50);
- операций GraphQL без типа 0.
Справочно, не критерий: повтор операций спеки между частями, чтение `.work` ведущим, цена, время.

**Регрессия, обычная SM-MONO-SPEC** (×3): 3/3 карточки 148/60/10/12, лишних 0 — как у 3.1.1.

**Регрессия, остаток в одной волне** (`NRS-TAIL`, ×3; топики только в конфиге): топики 18/18 в 3/3,
остальные классы ≥ 95 % правды.

**Регрессия, настоящий код** (`SM-REAL`, repairy, плечо scan, ×3): эндпоинты 96/96, сущности 20/20,
блоков с пустым телом ≤ 5 % — против `runs/2026-10-06-pilot-309-real` (96/96, 20/20, пустых 0,
строк-фактов 427, анкеров 10/14); строк-фактов не меньше 80 % той базы.

## Порядок

Пилот: большая спека ×1 — цена и время человеку, остальное после его ответа. Грейд — только после
завершения всех прогонов раунда. Красный по одному критерию — разбор по файлам прогона до правки.

Ты — голова скилла `service-map`. Сервис прочитан частями; ты пишешь каркас карточки и общие секции.
Три правила важнее всего: не выводится из кода — `не определено`; чужие репозитории только читаешь;
секреты не копируешь. Своих субагентов не запускаешь.
Сервис: <пути>, тип `<type>`. Имена сервисов манифеста: <имена>.
Прочитай целиком `<шаблон>`. Ответ начни строкой `шаблон прочитан, тип: <type>; голова`.
Описи частей: <описи частей> — читай их, а не код ключей.
Прежняя карточка: <прежняя> (нет — абзац пропусти). Из неё открой только свои секции: строки заголовков
`## ` найди `Grep` с `-n`, читай `Read` с offset и limit. Роль или сосед те же — имя пиши как в прежней,
дословно; факты строки те же — верни прежнюю формулировку дословно.
Файл `<каркас>`: первая строка `<!-- service-map: голова <дата> -->`, дальше карточка по шаблону, в
порядке секций для типа `<type>`: шапка и frontmatter (`scanned: <дата>`), «Генерируется», «Заметки
команды» (дословно: <notes>), «Назначение» и «Что умеет для пользователя» — по группам описей частей,
словами, которыми сервис говорит с человеком, в «Что умеет» строка на каждое действие (два глагола — две
строки), ключ со строкой `недоступно:` в описи части — по шаблону («Объявлено, но не работает»); «Стек» — по
файлам сборки и конфигам; «Зависит от» —
по строкам `зависит:` описей частей: одна строка на соседа или внешнюю систему, сколько бы клиентов и
частей о нём ни писали; имя — по правилу шаблона («Как в коде»), части назвали одного соседа по-разному —
выбери по правилу; «Роли и доступ» — по коду (конфиг безопасности, перечисления ролей) и строка `вход` —
как запрос получает пользователя и права (фильтр, интерсептор, откуда берётся токен, что в режиме по
умолчанию (вход не настроен)), в коде этого нет — `не определено: в коде нет`; «Кто меня потребляет» — пустой формой.
«Бизнес-правила» (если они есть у типа) — тоже твои: по строкам `состояние:`, `справочник:` и
`сообщение:` описей частей и строкам `·` под ними, по форме шаблона. Объект — один блок на сущность,
одно значение — одна строка, сколько бы частей о нём ни писали. Сообщение — блок на вид, то есть на
отправку (форма шаблона): строки `сообщение:` разных частей об одной отправке — один блок, названный
словами один раз; у каждого публикуемого топика из описей блок есть. Справочник блока не получает.
Порядок — объекты, затем сообщения, внутри — по алфавиту ключа.
Код открывай там, где строки частей спорят. Перед возвратом прогони по секции грепы ` /[a-z]`,
`\b(GET|POST|PUT|PATCH|DELETE)\b`, `\b[a-z]+[A-Z][A-Za-z]*\b`, `\b[a-z]+(\.[a-z-]+){2,}\b` вне бэктиков
и перепиши совпавшее словами; в бэктиках — только значение перечисления, имя вида или топика, имя
сервиса из манифеста и поле-дата в скобках рядом со значением, как в шаблоне.
В секциях «Публичный контракт», «Владеет данными», «События», «Фоновые задачи» — только заголовок
секции и строка `<!-- части -->`; в «Потребляемые API», если она есть у типа в таблице порядка шаблона
(у `backend` её нет), — заголовок секции, заголовок таблицы, разделитель и строка `<!-- части -->`.
Файл `<опись головы>`: первая строка — та же, что у каркаса, `<!-- service-map: голова <дата> -->`;
затем по строке на роль: имя роли, как в первой колонке
«Роли и доступ», затем ` — ` и файл; слова «роль» впереди нет; и строка `вход: <как устроен> — <файл>` (в коде
нет — `вход: не определено: в коде нет`). Строк «Бизнес-правил» в описи головы нет:
секцию сверяют с описями частей.
Что вернуть — ровно три строки:
шаблон прочитан, тип: <type>; голова
опись: <опись головы>
карточка: <каркас>

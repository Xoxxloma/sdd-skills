**Проблема 1 — спека того же API без базового пути (потеря данных).** В listmonk рядом с ручками лежит
`docs/swagger/collections.yaml`: `servers: url: /api`, пути в `paths` — без `/api`. Разведчик назвал её серверной
(строка спеки `ключ`), `plan.sh` разбирает операции без базового пути из `servers` — те же операции получают второй
ключ с неверным путём. Исход: mono-01 — 49 блоков-дублей с путём без `/api`; mono-02 и mono-03 — часть спецификации не
пишет ни одного блока (видит, что ручки уже есть), маркерный гейт части не пройден, карточка в `_pending`.
Починка по причине: путь операции = базовый путь спеки (`servers[0].url`, у Swagger 2 — `basePath`) + путь из `paths`
— в `plan.sh` (строки «операция», нарезка спеки) и одной фразой в брифе части.

**Проблема 2 — пропал факт «вход по умолчанию» (A6: без профиля входа — вшитый пользователь `apollo`).** 0 из 3
(круг agn — 2 из 2, в карточке «без профиля входа отдаётся вшитый пользователь `apollo`»). Причина — правка батча:
вместе с примером-утечкой «все запросы идут от одного вшитого пользователя» из правила строки `вход` ушло само понятие
«что в режиме по умолчанию», заменённое на «что будет без токена или заголовка» (это про отказ, а не про режим).
Починка: вернуть понятие без примера — «что в режиме по умолчанию (вход не настроен или выключен)» — в шаблоне, двух
брифах и тексте пункта `ENTRY`.

# Критерии зелёного — раунд `ts-comb` (PLAN-SPEC-COMB v3), записаны ДО результатов

Модель: Haiku на всём раунде. N=10 на пробу, равные пулы. Считаем прогоны, не единицы счётчика.
Прогон без артефакта по вине стенда (побег `_escaped.txt`, `_api-failure.txt`, session limit) —
«не измерено», из знаменателя выпадает; фантомная запись остаётся в знаменателе.

## Что считается по каждой пробе (грейдер → счётчик прогонов)

| Проба | Грейдер | Зелёное плечо = |
|---|---|---|
| `ts-live` | `grade-ts.mjs` | каждый счётчик грейдера не хуже базы более чем на 1 прогон из 10 (порог отката — ≥2) |
| `bf-spec` | `grade-bf.mjs` | то же; отдельно: слово «багфикс» в файле — не хуже базы; §6.2 непустая — не хуже базы |
| `ts-conv-2t` | чтение `answer-01.md`/`answer-02.md` + `grade-ts.mjs` по файлу | зелёный прогон = (а) спека записана на втором ходе, (б) ни один гейт, отвеченный в `conv-turn2.txt`, не переспрошен во втором ответе, (в) `/v1/sessions/count` из карточки не стоит под 🔵/фактом при «не знаю» аналитика. Плечо зелёное, если число зелёных прогонов не ниже базы более чем на 1 |
| `ts-noctx` | `grade-invent.mjs` | число прогонов с выдуманным адресом чужой системы не выше базы более чем на 1 |
| `ts-ctx` | `grade-ctx.mjs --expect=spec` | число прогонов с конкретикой чужого шлюза под 🔵/🟡 не выше базы более чем на 1; правила из `context/` применены — не хуже базы |
| `ts-conv` | `grade-ts.mjs` | прогонов, записавших `/v1/sessions/count` как подтверждённое при «не знаю», — не больше базы более чем на 1 |

## Правило отката

- Любая проба плеча хуже базы на ≥2 прогона из 10 по любому счётчику → плечо красное.
- Красное после A+B → откат B (снимок A отдельно), повтор плеча; снова красное → откат A целиком.
- Красное после C → откат C целиком; A+B остаются.
- Допуск «≥2» при базе 9/10 пропускает 7/10 — принято как цена N=10.

## Условие выхода (цель сессии)

Полностью зелёный регресс после C, либо три красных подряд на любом этапе.

## Батчи как снимки, не коммиты

Коммитов в этом раунде нет (правило репы: коммит делает человек). Текст каждого плеча заморожен
раннером в `<плечо>/_skills/`; откат = восстановление `SKILL.md` и `reference/` из снимка
предыдущего плеча.

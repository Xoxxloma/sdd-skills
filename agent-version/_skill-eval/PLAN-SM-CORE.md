## [СПРАВОЧНО] Правила работы (для всех срезов)

- Самотесты зелёные → перечитать каждую правку в контексте → только потом стенд.
- Прогон стенда — сначала назвать «что × сколько ≈ $», ждать ответа. Только Sonnet.
- Красный — только потеря данных или неверный факт; объём, место факта, форма — справочно.
- Не больше двух кругов на срез; не прошёл — откат среза, проблема — в стыки. Новых волн ревью нет.
- Правки минимальные; обоснования — в CHANGELOG, не в тексте скилла; следов стенда в скилле нет; примеры — разных стеков.
- Каждый срез — своя запись CHANGELOG и поднятие версии; коммит — по слову владельца, явными путями.

## [ДЕЛАЕМ] Срез 0 — единый ключ, перевод регэкспа, брокер (доводка 4.5.x)

Чинит три дефекта текущей 4.5.0, срез независим от остального.

1. **Одна функция сравнения ключей `k_key` в `keys.awk`** — вместо сравнения текстом в трёх местах (`k_canon`,
   `check.sh` `pn`/`same`/копии `nop`/`bare`, склейка `assemble.sh`, второй проход гарда).
   - Параметр пути — целый сегмент в любой записи: `{x}`, `{x:.+}`, `:x`, `<x>`, `*` → один параметр.
   - Имя параметра с точкой (`{upload.s3.public_url}`) — не параметр, а часть пути (иначе сливаются разные ручки из конфига).
   - Два блока одного автора, совпавшие только по канону, не сливаются: оба остаются, строка в отчёт.
   - Склейка сливает блоки разных авторов, только если совпало и имя параметра после приведения записи
     (`:id` = `{id}`); `{ids}` и `{userId}` не сливаются — оба остаются, строка в отчёт. Сравнение (сверка со спекой,
     гард) имя не учитывает. Иначе две разные ручки становятся одной (прод adjutant, перескан 4.5.0:
     `GET …/users/{ids}` и `GET …/users/{userId}`, вторая на деле под `v2`).
   - Показывается ключ, как его написал автор; `k_key` — только для сравнения.
2. **Перевод регэкспа разведчика в `plan.sh` (`awkre`)**: `\w`, `\d`, `\s` внутри `[…]` переводятся без вложенных
   скобок (`[\w, ]` → `[[:alnum:]_, ]`). Сейчас `[\w, ]` ломает класс: в двух прогонах Apollo нижняя граница вышла 138
   вместо ≈ 290.
3. **Брокер в «Стеке» (`check.sh`, `BROKER` и кандидат брокера)**: строка слоя «Шина» считается брокером, только если в
   ней продукт, а не «нет» или прочерк. Сейчас `| Шина | нет |` даёт ложный пункт добора «брокер есть, а событий 0»
   (прод navigator, 4.5.0).

- Самотесты: SM-CHECK — случаи `:id`/`{id}`, `{id}`/`{list_id}`, конфиг-путь с точкой, пара одного автора, `| Шина | нет |`
  и `| Шина | — |` без брокера; SM-ASSEMBLE-DUP — свод по канону у разных авторов, пара `{ids}`/`{userId}` разных
  авторов — два блока; SM-PLAN-TYPES — регэксп с `[\w, ]`; регресс на сохранённых карточках (прототипы
  `arch\A\proto\p2-keys.mjs`, `arch\B\proto\canon-dups.sh`, `arch\C\proto\dups.sh`): дубли listmonk 3/35/10/20 → 0, Apollo ×7 — 0 слияний.
- Стенд: SM-LISTMONK ×2, SM-APOLLO ×1 (≈ $40).
- Дальше, если: дублей одной ручки 0, ручки ≥ 182/185, Apollo 144/153 и ≥ 135/137, нижняя граница Apollo ≈ 290.

# Бэклог `service-map-2.0` — что найдено, но не внесено

Заведён 2026-10-05 после двух прогонов в проме на большом сервисе (Java, Spring, GraphQL и REST; клиент —
форк qwen-code, модель DeepSeek) и четырёх независимых ревью. Состояние скилла на момент записи — 3.0.7.
Каждая строка — с числом и источником, чтобы к ней можно было вернуться, не переоткрывая разбор.
Источники: «пром-1» — прогон на 3.0.5, «пром-2» — прогон на 3.0.6; «ревью» — запуск скриптов ревьювером
на своих входах; «карточка» — подсчёт по карточке пром-2 (2296 строк).

## Что уже решено (чтобы не переоткрывать)

- С 3.0.8 карточку останавливают только маркерный гейт по ключам карточки, порог пустоты и гард.
  Сверка описи с карточкой — перечень добора и справка, запись не останавливает (`ГЕЙТ КЛЮЧЕЙ` снят:
  в обоих прогонах прома давал ложный `_pending` по форме описи). Форма, потерянный факт,
  «Бизнес-правила» — добор, пока бюджет есть, дальше строка в отчёт.
- Пустые блоки автоматически не заполняются: пустота остаётся видимой, человек дочитывает точечно.
  Перенос фактов описи скриптом и автоматическое дочитывание отложены (см. Б-1, Б-2).
- Правило «изменяющая операция без факта — в общий добор» отклонено: добор один и уже занят, требование
  факта толкает к выдумке.
- Порог нарезки K опущен с 57 до 50 без замера (см. А-9).
- Правила — коротко и по принципу, без привязки к языку, фреймворку, протоколу и одному сервису.

## Итог пром-2 одним абзацем

Счёт и план сошлись с первой попытки; 7 частей, остаток из 29 пунктов (все отмечены), голова с первого
запуска. Карточка: контракт 252 блока, сущности 82, задачи 11, топики 15; из 104 операций файла
спецификации в карточке нет четырёх, выдуманных ручек нет. Ушла в `_pending`: «нет в черновике 34 / нет в
описи 35», из них 29 пар — одна операция с аргументами и без (исправлено в 3.0.7). В карточке 92 блока
контракта из 252 без единого факта, ещё 109 с одним.

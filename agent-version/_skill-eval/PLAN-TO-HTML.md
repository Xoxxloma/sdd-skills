# PLAN-TO-HTML — скилл `to-html`: markdown в браузере

Статус: план, ждёт одобрения. Ворктри `product-skills-main-fresh` (от `origin/main` 87aabaf3), ветка при старте —
`feat/to-html`. Коммиты — только по просьбе, явными путями.

## 0. Что решено на интервью

| Вопрос | Решение |
|---|---|
| Где логика | Разбор, навигация, поиск, экспорт — в JS внутри страницы |
| Как страница получает файлы | Сама по пути не может (запрет `file://`) → **решено мной, оспоримо:** крошечный упаковщик кладёт тексты рядом в `data.js`; без него та же страница работает как инит (перетащил папку) |
| ОС | Linux, Windows, macOS. Упаковщик — две версии по образцу `analyst-skills-update`: `pack.sh` (macOS, Linux; `bash …`) и `pack.ps1` (Windows; `powershell -File …`) |
| Обновление | Снимок + F5: повторный вызов перезаписывает `data.js`, F5 во вкладке показывает новое |
| Вложения | Просмотр — картинки и docx/pdf по пути с диска; экспорт — картинки внутрь (base64), docx/pdf списком без зашивки |
| Экспорт | Один html на всю папку · html текущего документа · «Копировать для Confluence/Word». PDF-кнопки нет (печать — обычный Ctrl+P) |
| Раскладка | Три колонки: файлы · документ · оглавление |
| Схемы | Mermaid — картинкой (библиотека рядом, без сети), PlantUML (`.puml`) — подсвеченным исходником |
| Содержимое | **Любой md и любая папка** — страница не знает о БТ, спеках и скиллах. Сверх CommonMark + GFM: шапка `---`, `[[ссылки]]` и `![[вставки]]` (Obsidian, Logseq, Foam), блоки `> [!note]` (GitHub, Obsidian). `#теги` — нет |
| Ноут аналитика | Одно правило по шаблону (§3.6): `2026-10-14 №1.2` → ссылка на пункт, строки с `‖` приглушены. Нет шаблона — правило молчит |
| Имя | `/to-html`; слова «в браузере», «to-browser» — в описании для вызова по словам |

Старый `base.html` (корень основного репо, не в git) — только образец: из него берём тему, копирование кода,
scrollspy. Свой парсер заменяем библиотекой (§3.3). Файл не трогаем.

## 1. Как это устроено

```
агент ──/to-html docs/ARS-77──▶ pack.sh | pack.ps1
                                   │  1. находит файлы набора
                                   │  2. пишет .to-html/<набор>/data.js   (тексты base64)
                                   │            .to-html/<набор>/assets.js (картинки base64, для экспорта)
                                   │  3. копирует viewer/ → .to-html/<набор>/
                                   │  4. открывает index.html системной командой
                                   ▼
браузер: index.html + app.js читает window.MDV_DATA → дерево, документ, оглавление, поиск, экспорт
         нет data.js (открыли html руками) → режим «инит»: перетащить папку / файлы
```

Файлы скилла:

```
agent-version/to-html/
  SKILL.md
  reference/
    pack.sh            # macOS, Linux (и Git Bash на Windows — на всякий случай)
    pack.ps1           # Windows PowerShell 5.1+
    viewer/
      index.html       # разметка + стили (токены светлой/тёмной темы)
      app.js           # вся логика, // @ts-check
      vendor/          # зафиксированные версии, MIT/Apache, LICENSES.txt
        markdown-it.min.js  markdown-it-footnote.min.js  purify.min.js
        highlight.min.js (common)  mermaid.min.js (~3 МБ, грузится только при схеме)
```

Почему так:
- **base64 и в путях, и в текстах** — в `data.js` не бывает кавычек, обратных слэшей и переводов строк, которые
  пришлось бы экранировать в sh и PowerShell. Страница декодирует через `TextDecoder('utf-8')`; невалидный UTF-8 →
  повтор с `windows-1251`.
- **Только классические `<script src>`** — ES-модули с `file://` Chrome блокирует, классические скрипты грузятся
  везде.
- **Выход в `<cwd>/.to-html/`, а не во временную папку** — Firefox и Chromium из snap на Ubuntu не видят `/tmp` и
  скрытые папки верхнего уровня `$HOME`. Вложенная скрытая папка в репо им доступна. В `.to-html/` упаковщик кладёт
  `.gitignore` со строкой `*` — папка игнорирует сама себя, `.gitignore` пользователя не трогаем.
- **Viewer копируется в выход при каждом вызове** — страница не ссылается на папку скилла (`~/.claude/skills`
  скрыта для snap) и всегда соответствует установленной версии скилла.

## 2. Упаковщик (`pack.sh` / `pack.ps1`)

### 2.1 Вызов

```
bash   <скилл>/reference/pack.sh  [--no-open] [путь ...]
powershell -NoProfile -ExecutionPolicy Bypass -File <скилл>/reference/pack.ps1 [-NoOpen] [путь ...]
```

| Вход | Корень набора | Что входит | Открыть первым |
|---|---|---|---|
| ничего | — | пусто → режим «инит» (`.to-html/_blank/`) | — |
| одна папка | она | рекурсивно | главный файл: `README.md` / `index.md`, иначе самый большой `.md` |
| один файл (любой `.md`, `*.points.md`, `.txt`, `.puml` …) | его папка | папка + подпапки до глубины 2; папка больше предела — **не ошибка**: сам файл и файлы, на которые он ссылается (`](…)`, `[[…]]`), до глубины 2 по ссылкам | этот файл |
| несколько путей | общая родительская | только названные (папки — рекурсивно) | первый файл из списка |

- Пропускаем папки `.*`, `node_modules`, `.to-html`.
- Текстовые (содержимое в `data.js`): `md markdown txt puml plantuml mmd yaml yml json`. Картинки:
  `png jpg jpeg gif webp svg`. Остальное — вложения: только путь и размер.
- Пределы (стартовые, правятся константой в начале скрипта): текстовый файл ≤ 5 МБ (больше — уходит во вложения
  с пометкой), всего файлов ≤ 2000 (больше: вход-папка — ошибка «назови папку поуже», вход-файл — режим «файл +
  его ссылки» из таблицы), картинка в `assets.js` ≤ 15 МБ.
- Ссылки для режима «файл + его ссылки» упаковщик ищет простым шаблоном (`](путь)`, `[[имя]]`, `![[имя]]`) —
  без разбора markdown; лишнее совпадение безвредно, пропущенная ссылка видна на странице как «вне папки».
- Имя набора — путь корня от cwd, `/` → `--`, без `:*?"<>|\`. Корень вне cwd — имя папки + короткий хеш пути.
  Одинаковый вход → тот же выход → F5 в открытой вкладке показывает новое.

### 2.2 Формат `data.js` (контракт страницы и обоих скриптов)

```js
// создано pack.sh 2026-10-20 15:53 — не править руками
window.MDV_DATA = {"v":1,"made":"2026-10-20 15:53","root":"docs/ARS-77","base":"../../docs/ARS-77/","open":"README.md","files":[
["README.md",18234,"<base64 байтов файла>"],     // текстовый ≤ 5 МБ
["img/схема причала.png",482113,null],         // картинка, вложение или текст больше предела
]};
```

Строки — JSON (пути — с `/`, сырой UTF-8; файл data.js от `pack.ps1` — с BOM), содержимое — base64 байтов, чтобы
страница сама узнала кодировку (UTF-8, иначе cp1251). `root` — путь корня от cwd для подписи (`.` — сам cwd,
абсолютный — корень вне cwd), `base` — путь от страницы к корню (`../../<root>/` или `file:///…/`), пусто в инит.
Вид файла страница определяет по расширению, как и упаковщик. Сначала здесь был base64 и в путях — в `pack.ps1`
кодировать строку в base64 нечем (срез 2, ниже), а экранировать путь для JSON просто в обоих скриптах.

`assets.js`: `window.MDV_ASSETS = [["img/схема причала.png","image/png","<base64>"], …]`. Пересобирается, только
если поменялся список картинок с размерами (`assets.list` рядом) или какая-то картинка новее его. Грузится
страницей лениво: при экспорте и как запасной путь, если картинка по пути не открылась (Safari, см. §8).

`index.html` при копировании получает метку `data.js?v=<made>`, чтобы F5 не взял старый снимок из кэша.

### 2.3 Открытие и вывод

- macOS `open`, Linux `xdg-open` (нет — только печатаем путь), Git Bash на Windows `cmd.exe //c start`,
  PowerShell `Invoke-Item`. `--no-open` / `-NoOpen` — только пересобрать (вкладка уже открыта).
- Вывод: русские строки для человека («собрано: … — файлов 14 (текстовых 9, картинок 3, прочих 2)», «обновлено —
  нажми F5 во вкладке», текст ошибки), **последняя строка — только ASCII**, её читает агент:
  `to-html: ok files=14 text=9 img=3 other=2 page=file:///C:/…/index.html` (с `--no-open` — `updated`; адрес в
  %-кодировке) или `to-html: error not-found | no-text | too-many | no-write`, код выхода 1. Почему ASCII: в
  ограниченном режиме PowerShell кодировку консоли не поменять, и русский текст у вызывающего бывает кракозябрами.
- Портируемость bash: 3.2 (macOS) — без `mapfile`, `${x,,}`, `find -printf`, `stat`, `realpath`; `base64 < f |
  tr -d '\n'` (GNU переносит строки, BSD — нет); помощники пишут в переменную, а не в `$(…)` — в Git Bash процесс на
  файл стоит минуту на двух тысячах файлов.
- Портируемость PowerShell (срез 2): **корпоративный режим — ConstrainedLanguage**, как у `skills.ps1`: только
  командлеты, без `[Convert]`, `[IO.File]`, `[pscustomobject]`, `[Math]`, без установки `[Console]::OutputEncoding`.
  Поэтому base64 — через `Export-Clixml` (массив байтов он пишет как `<BA>…</BA>`, пустой — `<BA />`), запись —
  `Set-Content -Encoding UTF8` (с BOM), копия страницы — `robocopy /E`, в конце явный `exit 0` (иначе код выхода —
  от robocopy). Сам `pack.ps1` — в UTF-8 **с BOM** (самотест это проверяет).

## 3. Страница

### 3.1 Раскладка и состояния

- ≥ 1280px: `260px | документ | 220px`. 900–1280px: оглавление уходит в левую колонку под текущий файл.
  < 900px: левая колонка — выдвижная панель, оглавление — выпадающее «На странице».
- Шапка над документом: путь `ARS-77 › Спека`, «снимок 15:53», Поиск (Ctrl+K), Экспорт ▾, Тема (авто / светлая /
  тёмная).
- Состояния: загрузка; инит (нет данных); набор без текстовых файлов; файл не разобрался — ошибка в месте файла, а
  не белый экран; картинка не нашлась — плашка с путём.
- Адрес: `#f=<путь>&h=<якорь>`. Назад/вперёд в браузере работают, F5 возвращает тот же файл и прокрутку
  (`sessionStorage` по пути файла).

### 3.2 Дерево файлов

- Папки сворачиваются; внутри папки сначала файлы, потом подпапки, по алфавиту, главный файл папки первым.
- Строка: значок по виду (md · схема · картинка · вложение), подпись = первый `# H1` файла, иначе имя файла; имя
  файла — серым под подписью или в подсказке.
- Картинка — открывается в центре с подписью и размером. Вложение (docx/pdf/xlsx) — ссылка по пути: pdf откроет
  браузер, остальное — система. Текстовый не-md (`.puml`, `.yaml`, `.json`, `.txt`) — подсвеченный текст.
- Клавиатура: ↑/↓ по дереву, Enter — открыть.

### 3.3 Документ

- **markdown-it** (CommonMark + таблицы, зачёркивание) + footnote, своё правило для `- [ ]`/`- [x]`. Свой парсер из
  `base.html` не переносим: в нём ручные правила setext/hr/выделения с известными краевыми ошибками.
- HTML внутри md разрешён, но через **DOMPurify**: экспорт уходит коллегам, а в `sources/` бывают вставленные письма.
- Пути файлов и цели ссылок сравниваются после `normalize('NFC')`: macOS хранит имена в NFD (`й` = `и` + знак),
  а в тексте md они в NFC — без этого кириллические ссылки на Mac не найдутся.
- Якоря заголовков — по правилу GitHub (юникод, пробел → `-`, повторы `-1`), чтобы ссылки из md, работающие на
  GitHub/GitLab, работали и здесь.
- Ссылки:
  - на файл набора (`other.md`, `../_foundation/x.md#раздел`) → переход внутри страницы;
  - на картинку → `base + путь` (в режиме «инит» — URL из перетащенного `File`);
  - на файл вне набора → ссылка по пути с пометкой «вне папки» и подсказкой `/to-html <путь>`;
  - `http(s)` → новая вкладка, `rel=noopener`;
  - путь в `` `коде` `` или голым текстом, совпадающий с файлом набора, → ссылка (так открываются
    `> исходник: sources/…`, `файл docs/…docx` и пути, которые скиллы пишут в обратных кавычках);
  - `[[Имя]]`, `[[Имя#Раздел]]`, `[[Имя|подпись]]` → файл набора с таким именем (без `.md`, регистр не важен;
    несколько с одним именем — ближайший к текущему файлу); подпись без `|` — «Имя › Раздел»; не нашёлся — текст с
    пунктиром «нет в папке»;
  - `![[фото.png]]`, `![[фото.png|300]]` → картинка по имени из любой папки набора; `![[Заметка]]` → ссылка на
    файл, а не вставка его текста (вставка чужого текста — вне плана).
- Блоки `> [!note]`, `[!tip]`, `[!important]`, `[!warning]`, `[!caution]` (и их русские подписи) → плашка с
  заголовком; неизвестный тип — как `note`.
- Код: highlight.js (common: kotlin, java, go, ts, sql, bash, yaml, json…), метка языка и «Копировать» при наведении.
- Таблицы: шире колонки текста (до ширины центральной колонки), липкая шапка, горизонтальная прокрутка, кнопка
  «развернуть» — таблица на весь экран (широкие таблицы FR в спеках).
- Шапка `---` … `---` в начале файла (у ноута: `тема:`, `ключ:`, `о чём:`, `роли:`) — карточкой «ключ: значение»
  над документом. Без этого markdown-it делает из закрывающей `---` заголовок второго уровня.
- Большой файл (ноут на мегабайты): цель — 5 МБ md открывается < 1.5 с на среднем ноутбуке. Средство (срез 0):
  разбор и вставка **по секциям `h2`**, каждая `<section style="content-visibility:auto">` — 5 МБ за ~130 мс
  против ~550 мс одним куском (Chrome/Edge). Сноски и ссылки-определения собираются по всему файлу до разбивки.

### 3.4 Оглавление

- Из заголовков текущего файла, подсветка текущего раздела при прокрутке.
- Длинное (ноут: даты `h2` → записи `h3`): уровни ниже `h2` раскрыты только у текущего раздела; «Свернуть всё».

### 3.5 Схемы

- ` ```mermaid ` и файлы `.mmd` — `mermaid.min.js` подгружается при первой схеме на странице; схема рисуется, когда
  доходит до экрана. Ошибка синтаксиса — исходник + текст ошибки, а не пустое место.
- `.puml` и ` ```plantuml ` — подсвеченный исходник + «Копировать»; подпись «PlantUML — без сервера не рисуем».
- Тема схемы следует теме страницы.

### 3.6 Формат ноута аналитика — одно правило по шаблону

Работает только в файлах, где встретился шаблон `ГГГГ-ММ-ДД №N(.M)`; остальные md не задевает. Формат не меняем.

- Строка пункта, которая заканчивается своим номером `· 2026-10-14 №1.2`, получает якорь `n-2026-10-14-1-2`;
  заголовок `### 1 · …` под `## 2026-10-14` — якорь `n-2026-10-14-1`.
- Любое другое упоминание `ГГГГ-ММ-ДД №N(.M)` в любом файле набора (выкладки, `*.points.md`, `отвечает на:`,
  `‖ закрыт:`) → ссылка на якорь. Указатель якорей общий на весь набор, поэтому ссылка из выкладки ведёт в
  `notebook.md`. Нет такого пункта — ссылки нет, текст как есть.
- Пункт с `‖` (заменён, снят, закрыт, оспорен) — приглушён, хвост после `‖` выделен; по наведению — полный текст.
- Переход по ссылке на пункт — прокрутка и короткая подсветка строки.

### 3.7 Поиск (Ctrl+K)

- Окно поверх страницы: поиск по именам файлов, заголовкам и тексту всех файлов набора.
- Регистр не важен, `ё = е`, несколько слов — все должны найтись. Указатель строится при первом открытии поиска.
- Результаты по файлам: заголовок раздела + отрывок с подсветкой; совпадения в заголовках выше. До 50 результатов.
- Enter — открыть файл на разделе и подсветить совпадения в нём; Esc — закрыть.

### 3.8 Режим «инит»

- Нет `data.js` или открыт пустой набор: карточка по центру — зона «Перетащите папку или файлы», кнопки
  «Выбрать папку» (`webkitdirectory`) и «Выбрать файлы», строка «Файлы не уходят в сеть».
- Перетаскивание папки — через `webkitGetAsEntry` (рекурсивно, работает в Chrome, Edge, Firefox, Safari).
- Дальше всё как в наборе от упаковщика: те же правила видов файлов и пределов; картинки и вложения — по
  `URL.createObjectURL`; экспорт вкладывает картинки из `File` напрямую.
- Перетаскивание поверх открытого набора заменяет набор (с подтверждением).

### 3.9 Экспорт (меню «Экспорт ▾»)

1. **Вся папка — один html.** Все текстовые файлы отрисованы заранее; mermaid — готовым SVG; картинки — data URL
   из `assets.js` (крупнее 2 МБ ужимаются до 1600px по длинной стороне); ссылки между файлами — переходы внутри
   файла; в конце — раздел «Вложения (в файл не вложены)» со списком docx/pdf. Внутри только CSS и ~3 КБ своего
   JS (переключение файлов, оглавление, тема): ни markdown-it, ни mermaid. Имя `<набор>-<ГГГГ-ММ-ДД>.html`, без
   единого внешнего запроса.
2. **Этот документ — html.** То же для одного файла, с оглавлением сбоку (сейчас оглавление при экспорте теряется).
3. **Копировать для Confluence/Word.** В буфер — html с inline-стилями (заголовки, таблицы с рамками, код
   моноширинным, схемы PNG) и исходный md как простой текст. Копирование через событие `copy`
   (`clipboardData.setData` для обоих видов) — срез 0: на `file://` в Chrome/Edge кладёт оба. Схема в PNG —
   перерисовка с `htmlLabels: false` и картинка через `data:` URL (через `blob:` холст «портится»). Тост
   «Скопировано — вставь в Confluence или Word».

Печать: правила `@media print` (без шапки, колонок и кнопок, таблицы и код не рвутся) — кнопки нет.

### 3.10 Граница данных

`window.MDV_DATA` — граница ввода: проверяется рукописным type guard (версия, типы полей, base64) до
использования; не прошла проверку — режим «инит» с плашкой «снимок повреждён, вызови /to-html ещё раз». `app.js`
— `// @ts-check` + JSDoc, `tsc --noEmit --allowJs --checkJs` без `any`; `switch` по виду файла — исчерпывающий.

## 5. SKILL.md (под слабые модели — коротко, вся работа в скрипте)

```
---
name: to-html
version: 1.0.0
allowed-tools: Bash, Glob
argument-hint: "[путь к .md или папке …]"
description: 'Показывает markdown в браузере: любой .md, несколько файлов или папку целиком (документы,
  заметки с картинками и вложениями) либо пустую страницу, куда перетаскивают файлы. Сам файлы не читает и не
  пишет — собирает и открывает скрипт. Вызывай, когда просят открыть или показать md в браузере, «в html»,
  «to-browser», «покажи нормально, а не текстом».'
---
```

- **Шаг 1 — что открыть.** Пути в вызове → как есть, любой файл или папка. Словами («открой заметки про
  поездку», «README сервиса») → один `Glob` `**/*<основа слова>*` среди `.md` и папок, без знания о том, где какие
  скиллы что пишут. Ничего или «пустую» → без путей (инит). Несколько совпадений → одной строкой спросить, какое.
- **Шаг 2 — команда** по ОС, таблицей, как в `analyst-skills-update` (там же оговорки: `bash …`, а не `./…`; на
  Windows только PowerShell — `bash` там бывает WSL). `--no-open`, если тот же путь в этом разговоре уже открывал.
- **Шаг 3 — ответ:** последняя строка скрипта как есть + «после правок — снова /to-html, потом F5 во вкладке».
- **Ошибки** — таблица «текст → что делать» (нет bash, запрет `.ps1` → `Invoke-Expression (Get-Content -Raw …)`,
  путь не найден, слишком много файлов).
- **Не делаешь:** не читаешь md, не пишешь html сам, ничего не правишь. Скрипт не запустился совсем → открой
  `reference/viewer/index.html` системной командой и скажи «перетащи папку <путь> в окно».

### Решения среза 3 (2026-10-20)

- markdown-it без «нечётких» ссылок (`fuzzyLink: false`): иначе `README.md` — ссылка на сайт, `.md` — домен.
- DOMPurify с `SANITIZE_DOM: false`: иначе снимает id, совпадающие со свойствами `document`, — заголовки «Title»,
  «Links», «Images» теряют якоря. Скрипты и обработчики он снимает и так. `<use>` он режет — значки внутри
  документа ставятся меткой `data-icon` и подменяются на svg после чистки.
- Якоря ищутся только внутри документа (`doc.querySelector('[id=…]')`): заголовок «TOC» не столкнётся с id страницы.
- Подпись в дереве — `# заголовок` файла; два файла папки с одним заголовком — имена файлов. Сортировка — по подписи.
- В коде без лигатур: Cascadia Code рисует `->>` стрелкой.
- Спрятанная панель на телефоне — ещё и `visibility: hidden`: без тени у края, Tab в неё не попадает.
- Предел текста 5 МБ — константа в обоих скриптах; файл больше — пометка «больше 5 МБ» и ссылка «открыть как текст».

### Решения среза 4 (2026-10-20)

- Перетащенное отбирается как у упаковщика (скрытое, `node_modules`, 2000 файлов, 5 МБ на текст), главный файл —
  тем же правилом. Тексты читаются сразу (`File.arrayBuffer`), картинки и вложения — `URL.createObjectURL`.
- Одна брошенная папка — набор с её именем, содержимое от её корня; несколько файлов или папок — «перетащенные файлы».
- `webkitGetAsEntry` и `dataTransfer.files` берутся до первого `await`: после обработчика `drop` они пустеют.
- DOMPurify — свой список схем с `file:` и `blob:`: без них у картинок набора вне папки запуска (base `file:///…`)
  и у перетащенных пропадал адрес. Нашёл e2e, добавлена проверка набора вне папки запуска.

### Решения среза 5 (2026-10-20)

- Схемы рисуются строго по одной (очередь): у `mermaid.render` общее состояние. Перед `render` — `parse`: при
  ошибке на месте схемы текст ошибки (первые строки) и исходник; временный контейнер mermaid из body убирается.
- Цвета схем — токены страницы (`theme: "base"`); смена темы и системной темы перерисовывает нарисованные схемы.
- Прыжок к разделу «держится» до 5 с, пока человек сам не листает: схемы выше дорисовываются позже и сдвигали
  текст — F5 с якорем приходил не туда. Нашёл e2e.

### Решения среза 6 (2026-10-20)

- Пункт ноута «свой» (якорь `n-ДАТА-N-M`), только если стоит под своими `## ДАТА` и `### N · …`: в выкладке и
  списке пунктов те же номера в конце строк — это ссылки. Указатель якорей — по всему набору, строится лениво.
- Пути голым текстом — ссылка, только если такой файл есть в наборе; регулярка без lookbehind (Safari < 16.4).
- Скорость: плашка не вставляет токен (`splice` в массив на миллион токенов — квадрат), заголовок рисует рендер
  тега; DOMPurify — только для частей с сырым HTML автора (свои HTML-токены помечены), остальное markdown-it отдаёт
  безопасным сам. Журнал 4,8 МБ со ссылками, вставками и плашками: 3,6 с → 0,75 с. Нашёл профиль CDP.

### Решения среза 7 (2026-10-20)

- Указатель — файлы, порезанные по заголовкам строк `#…` (вне блоков кода); якорь раздела — тем же `slug`, что у
  страницы; не совпал (заголовок со сложной разметкой) — переход ищет заголовок по тексту.
- Ранжирование: слово в заголовке ×6, в имени или пути файла ×3, в тексте ×1; слов несколько — нужны все.
- Подсветка после перехода — `<mark class="hit">` в разделе до следующего заголовка того же уровня; Highlight API
  не берём — его нет в Firefox ESR 115.
- В e2e тексты документа читаются `textContent`: страница восстанавливает прокрутку, а раздел за экраном с
  `content-visibility` не отрисован — `innerText` у него пустой (давало плавающие провалы).

### Решения среза 8 (2026-10-20)

- Экспорт — та же отрисовка (`renderEntry`), разобранная в `<template>` (картинки там не грузятся); дальше:
  картинки — `data:` (из `assets.js` или перетащенного `File`, > 2 МБ — JPEG до 1600 px), схемы — SVG светлый и
  тёмный, ссылки `#f=…` — на части файла (`#dN-…`; сноски `#fn1` — тоже с префиксом), ссылки на то, чего в файле
  нет, — текст с пунктиром и подсказкой, кнопки убраны. В файл — CSS страницы, значки и ~2 КБ своего скрипта.
- Буфер для Confluence/Word: стили в тегах, без классов и `<svg>`; схема — PNG (белый фон, ×2, `htmlLabels:false`);
  простым текстом — исходный md. Сначала `ClipboardItem` с обещанием, затем событие `copy`, затем кнопка в подсказке.
- Схемы последовательности — без дубля участников снизу (`mirrorActors: false`), как в макете.
- e2e печатает итог до `browser.close()`: playwright-core 1.49 с Edge роняет процесс на закрытии (TargetClosedError).

## 0. Что уже известно и что это значит для плана

1. **Измеренные рычаги рядом с правками** (`PLAN-BR-COMB.md` §0 п.3): реестр и `N = 0` → запись
   этим ходом (L13–16, L84–96, L437–455); статус из N (Step 4 L582–601); `Форма:` в строке гейта;
   роли дословно (BR-ROLES); «Бизнес-правила» и «ограничение» в гипотезах (BR-REAL, BR-LIMIT);
   доработка готового БТ на месте (L579–580, SR5 L641–644, L707). Каждая правка — под сторожем.
2. **Хвост скилла читается последним.** В GigaCode вывод скилла уходит в файл и читается кусками
   по ~25 тыс. символов; в логе гейты (L713) и шаблон (L787) агент открыл, только когда его спросили.
   → Форма нового гейта дублируется в строке образца реестра (D7). **Стенд этого не воспроизводит**
   (`run-pool-ctx-v2.sh`: «Прочитай целиком файл») — D7 незамеренная.
3. **Инструкции внутри шаблона в БТ не протекают** (0 из 2470) — подсказки в шаблоне безопасны.
4. **Новые номера — в свободные:** разделы §1.4, §3.4, §4.3; гейты 15 (данные), 16 (как сейчас),
   17 (зависимости). Существующие номера не двигаются.
5. **Большой интент — не этот раунд** (§6). Источник в `br-data-src` < 20 тыс. символов.
6. **Материал пользователя — это его слова** (TL;DR 3, L23–29: «Всё, что пользователь написал, — это
   ответ»). Отсюда главный поворот v2: данный пользователем файл переносится целиком по умолчанию,
   отдельного вопроса «переносить?» нет — иначе ломается «N=0 → пиши этим ходом».

### 1.2 Правка существующих фикстур и грейдеров

Новые гейты открыты → реплика «ответил на всё» их не закрывает → агент (верно) спрашивает:
- пробы, ждущие файл, краснеют: `br-open-w`, `br-roles-w`, `br-var`, `br-yes`, `br-cut`, `br-nclap`
  (контроль, `expectWrite`), `br-half` (ход 3), `br-nocrit` (ход 3);
- пробы, ждущие вопрос по одному пункту, **зеленеют даром**: `br-nocrit2`, `br-nccan`, `br-ncl`,
  `br-nclib`, `br-ncr`, `br-half` (ход 2).

→ В реплики этих 13 проб (у проб-«ПРОДОЛЖЕНИЙ» `br-yes`, `br-cut` — в промпт) — фразы, закрывающие
гейты 15–17, **одна правка на раунд**. Сверить каждую пробу по README; реплики читает свежий субагент
без замысла. **База меряется заново.**

Ещё:
- `br-lib.mjs:60` — `Number(m[1]) <= 14` → `<= 17`, иначе грейдеры не видят гейты 15–17;
- `BR-REWORK/rework-prompt.txt:7`, `rework-q-prompt.txt:7` — «§3.3, строка 49»: после вставки §1.4
  номер строки сдвинется — пересчитать;
- README `BR-OPEN:46`, `BR-VAR:12` — «четырнадцать гейтов»;
- одноходовые пробы вопросов (`br-open-q`, `br-ctx`, `br-real`, `br-limit`, `br-roles-q`) не правятся —
  они сторожа вытеснения измеряемой гипотезы новым гейтом.

**Входные БТ старого формата** там, где проба считает замечания приёмки или проверяет разрез, —
дописать новые разделы: `RV-AUDIT` (`rv-bt-clean`, `rv-bt-dirty`), `RV-CLEAN` (`bt-clean` тира A,
`setup-rv-runs.mjs:28`, `grade-rv.mjs` ждёт 0), `BR-REWORK`, эпики `TD-PATH`, `TD-RU`. Остальные

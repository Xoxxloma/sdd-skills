# PLAN-DEEP-SEARCH — скилл `deep-search`: ответ «как сейчас» по коду соседних реп

Статус: план, ждёт одобрения. Работа — в ворктри от `origin/main`, ветка при старте `feat/deep-search`.
Коммиты — только по просьбе, явными путями.

## 0. Что решено

| Вопрос | Решение |
|---|---|
| Рамка | Справка о том, как система работает **сейчас**. «Как сделать» — отказ одной строкой: это работа спеки. Образ — explore у OpenSpec (только чтение, ничего не пишет), но **с шагами**, а не свободным разговором |
| Ответ | Только в чат. Скилл ничего не пишет: ни ноут, ни карточки, ни код |
| Имя | `/deep-search <вопрос>` |
| Разведчик | Один субагент на вопрос, бриф `reference/brief.md`, **одинаковый на обоих входах**. Сам идёт: карточки → манифест → код. Ведущий не читает ни карточек, ни кода, кроме сверки ссылок |
| Этап 2 | В интервью тех-спеки вариант «Глубокий поиск» в вопросе о существующем сервисе — **сразу**, и только у сервиса, чей код лежит рядом: это проверяется один раз на Step 0.5, при чтении карточек |
| Вход из тех-спеки | Спека передаёт утверждение и имя сервиса. Куда идти, решает разведчик: спеке не нужно посреди интервью доставать пути и имена из карточек |
| Метки спеки | **Новых нет.** Находка из кода → новая гипотеза того же вопроса → «да» аналитика → 🔵 |
| Разведчик и репы | Только чтение, не больше двух реп на вопрос — **решено мной, оспоримо** |
| Сервис не определён, кода нет | Разведчик возвращает кандидатов или соседние папки. Вход А — ведущий спрашивает аналитика и перезапускает; вход Б — тот же вопрос без варианта поиска — **решено мной, оспоримо** |

## 1. Как это устроено

Два входа, один разведчик. Развилка только в том, что ему подаётся и куда уходит ответ:

```
вход А (этап 1): /deep-search <вопрос>
    → Вопрос + Корень ─────────────────────────────┐
                                                   ├─► разведчик + brief.md
вход Б (этап 2): тех-спека, «Глубокий поиск»       │     1. карточки services/, context/
    → Утверждение + Сервис + Корень ───────────────┘     2. репа из манифеста
                                                         3. код
                                                              │
                          ведущий сверяет каждую ссылку ◄─────┘
                          А: ответ в чат
                          Б: тот же вопрос новой гипотезой
```

| | Вход А | Вход Б |
|---|---|---|
| Ведущий | `deep-search/SKILL.md` | `technical-spec-doc` |
| Что получает разведчик | `Вопрос` — открытый, `Корень` | `Утверждение` — гипотеза вопроса-допущения, `Сервис` — имя, как его знает спека, `Корень` |
| Первая строка ответа | — | `Вердикт: подтверждается / в коде иначе / не нашёл` |
| Разведчик не определил сервис или не нашёл код | ведущий спрашивает аналитика вариантами, перезапуск с `Сервис` или `Репа` | тот же вопрос без варианта поиска |
| Куда уходит ответ | в чат | в интервью, новой гипотезой |

`Корень` — абсолютный путь к папке, где лежат `services/` и `context/` (корень спек-репы).

Файлы скилла:

```
agent-version/deep-search/
  SKILL.md            # ведущий входа А: вопрос → разведчик → сверка → ответ
  reference/
    brief.md          # бриф разведчика и формат ответа — общий стык с тех-спекой
```

## 2. Ведущий (`SKILL.md`) — вход А

> Исходный замысел. Действующая форма — сам скилл после доработки §9: шаги 1 вопрос → 2 разведчик → 3 сверка
> → 4 ответ; исходы «без аналитика нельзя» — один блок `## НУЖЕН ВЫБОР`.

```
---
name: deep-search
version: 1.0.0
allowed-tools: Read, Glob, Grep, Agent, AskUserQuestion  # Grep и Glob — для запасного пути без субагентов
argument-hint: "<вопрос о том, как сейчас работает система>"
description: 'Отвечает, как система работает сейчас, по карточкам services/ и коду соседних реп: субагент
  находит сервис и читает его код, каждое утверждение — со ссылкой файл:строка. Ничего не пишет.
  Вызывай, когда спрашивают «как сейчас работает…», «где в коде…», «посмотри в коде», «глубокий поиск».'
---
```

- **Шаг 1 — вопрос.** О том, как сейчас → дальше. «Как сделать / как лучше» → одна строка отказа и
  `/technical-spec-doc`. Смешанный → отвечаю на часть «как сейчас», про остальное одна строка.
- **Шаг 2 — разведчик.** Один. Тип — любой с `Read`/`Grep`/`Glob`, писать ему не нужно. Промпт короткий:
  «прочитай `<абсолютный путь к brief.md>` и работай по нему» + `Вопрос` + `Корень`. Бриф не пересказывать и не
  вклеивать. Ответ без заголовка `## ОТВЕТ ПО КОДУ` или пустой → один перезапуск тем же промптом; снова пусто —
  сказать человеку. Субагентов нет → ведущий работает по брифу сам (для отдельного вызова это допустимо).
- **Шаг 3 — если разведчик не дошёл до кода.** `## СЕРВИС НЕ ОПРЕДЕЛЁН` с кандидатами или `## КОДА НЕТ` с
  соседними папками → вопрос аналитику этими вариантами → перезапуск с `Сервис: <имя>` или `Репа: <путь>`. Один
  перезапуск; снова не дошёл → ответ тем, что есть в карточках, с пометкой «кода рядом не нашёл».
- **Шаг 4 — сверка.** Каждую ссылку `[в коде]` открыть `Read offset=<строка−2> limit=5`. Строка не
  подтверждает утверждение → пункт выкинуть, в ответ строкой «одну ссылку не подтвердил — убрал».
- **Шаг 5 — ответ в чат:**

```
Как сейчас: <1–3 строки сути>
- [в коде] <утверждение> — <репа>/<путь>:<строка>
- [из документа] <утверждение> — services/<сервис>.md | context/<файл>.md
- [вне кода] <что и где живёт: переменная окружения, настройка деплоя, внешний сервис>
- [не нашёл] <часть вопроса, на которую в коде ответа нет>
Читал: <репа>, ветка <имя> — локальная копия, могла отстать от удалённой.
```

  Разведчик сообщил, что карточка расходится с кодом → строка «карточка `services/<сервис>.md` расходится с
  кодом: <что> — обновить: `/service-map <сервис>`».

- **Не делаешь:** не читаешь карточки и код сам (кроме сверки), не пишешь файлов, не предлагаешь записать
  ответ, не запускаешь git, не проектируешь.

## 3. Бриф разведчика (`reference/brief.md`)

> Исходный замысел. Действующая форма — `reference/brief.md` после доработки §9: развилка «с чего начинаешь» по
> `Репа` / `Сервис` / ничего; репа — папка репозитория под `<Родитель>`, кусок из манифеста — где искать.

- Роль: ответить на один вопрос о том, как система работает сейчас, или проверить одно утверждение. Только
  чтение.
- Вход: `Вопрос` или `Утверждение` (одно из двух), `Корень`; необязательно `Сервис` (имя как есть, может не
  совпадать с именем в манифесте) и `Репа` (абсолютный путь, только при перезапуске после выбора аналитика).
- Три правила важнее остального:
  1. Каждое `[в коде]` — со ссылкой `файл:строка`, и сама строка это показывает. Вывод из нескольких мест — со
     ссылками на каждое.
  2. В коде нет → `[вне кода]` (где живёт: имя переменной, ключ настройки, внешний сервис) или `[не нашёл]`.
     Догадка, записанная как факт, неотличима от правды.
  3. Секреты не копируются: имя переменной и файл — да, значение — никогда. Ни одной правки ни в спек-репе, ни
     в репах сервисов.
- **1. Карточки.** `Grep "^description:"` по `<Корень>/services` и `<Корень>/context` (папка — `path`, маска —
  `glob`). `Сервис` дан → карточка по нему, иначе по описаниям. Карточку читать кусками (`Grep` по заголовкам,
  `Read` с `offset`/`limit`), не целиком: нужны имена ручек, топиков, сущностей, классов — с них начнётся поиск в
  коде. Не понятно, какой сервис → `## СЕРВИС НЕ ОПРЕДЕЛЁН` и 2–3 кандидата из описаний, стоп.
- **2. Репа.** `path` сервиса из `<Корень>/services/manifest.yaml`, относительно `<Корень>`; через запятую — все
  пути куска. Проверить `Glob`, что папка на месте. Нет сервиса в манифесте или нет папки → `## КОДА НЕТ` и
  соседние папки `<Корень>/../*/`, стоп. Сервисов в вопросе больше двух → назвать их и стоп.
- **3. Код.** Имена из карточки и слова вопроса → `Grep` → открывать только найденное, кусками → идти по
  вызовам от найденной точки. Стоп — когда у каждой части вопроса есть строка или `[не нашёл]`. Ссылки — только
  на рабочий код: тесты и моки описывают ожидание, а не прод.
- Ветка: `Read <репа>/.git/HEAD`; `.git` — файл (ворктри) → «ветка не определена».
- `Утверждение` → первая строка ответа `Вердикт: подтверждается | в коде иначе | не нашёл`, дальше пункты как
  обычно. Вердикт без ссылки `[в коде]` под ним — только «не нашёл».
- Формат ответа: `## ОТВЕТ ПО КОДУ` (пункты по видам из §2), строка о расхождении карточки с кодом, если оно
  есть, и `## ПРОЧИТАНО` (карточки, репа, ветка, сколько файлов кода открыто).
- Два примера на разных стеках, оба не совпадают со стеками фикстур, с оговоркой «стек не важен — важна ссылка
  на строку».

## 4. Этап 2 — вариант в тех-спеке (после того как этап 1 проверен на проде)

Правка минимальная, четыре места в `technical-spec-doc/SKILL.md`:

1. `allowed-tools` + `Agent`. Под `analyst-workspace` он уже есть, отдельному запуску спеки нужен.
2. Step 0.5, где спека уже читает карточку каждого задетого сервиса: установлен `deep-search` (файл
   `../deep-search/reference/brief.md` от `SKILL.md` спеки) → для каждой открытой карточки взять `path` этого
   сервиса из `services/manifest.yaml` (имя карточки = `name` в манифесте) и проверить `Glob`, что папка на
   месте. Итог — список «код рядом: <сервисы>». Один раз, до интервью. `deep-search` не установлен или
   манифеста нет → список пустой, проверки нет.
3. Step 3, вопрос-допущение о существующем сервисе (🟡): сейчас `[Да, так и есть] [Иначе — поправлю] [Не знаю,
   оставим к валидации]` → четвёртым `[Глубокий поиск — посмотреть в коде <сервис>]`, только если сервис в
   списке «код рядом». Иначе варианта нет, интервью как сегодня.
4. Нажали → разведчик промптом Шага 2 `deep-search/SKILL.md`, но с `Утверждение` = гипотеза вопроса вместо
   `Вопрос`, `Сервис` = `name` из манифеста, `Корень`. Сверка ссылок — как Шаг 3 `deep-search/SKILL.md`. По
   вердикту:
   - `подтверждается` → «В коде `<сервис>` так и есть: <поведение> — беру?» `[Да]` → 🔵;
   - `в коде иначе` → «В коде `<сервис>` иначе: <как в коде> — беру как в коде?» `[Да]` → 🔵;
   - `не нашёл` или всё `[вне кода]` → тот же вопрос без варианта поиска. Блока `## НУЖЕН ВЫБОР` при данном
     `Сервис` бриф не ставит; появился всё же — тоже тот же вопрос без варианта поиска.

   Один поиск на вопрос. Пути и код в спеку не идут — правило уже есть («Прочитанный путь, заголовок или код
   чужой системы в спеку не переносится»).

«Один заход» Step 0.5 остаётся: проверка папок — это `Glob`, а не чтение кода. Код читает только разведчик и
только по выбору аналитика.

## 6. Проверка

- **Фикстуры** (стек фикстур ≠ стек примеров брифа): спек-репа с `services/` (две карточки, одна устарела против
  кода), `manifest.yaml`, `context/` с одним документом; репа-поставщик (стек А) публикует событие в кафку после
  записи, имя топика из переменной окружения, повтора при ошибке нет; репа-потребитель (стек Б).
- **Пробы этапа 1** — `fixtures/DS-BASE/README.md`, P1–P7: главный путь события вместе с расхождением
  карточки; топик (`[вне кода]`, без выдуманного имени); повтор при недоступной кафке (нет); «как сделать»
  (отказ); сервиса нет в манифесте (вопрос аналитику соседними репами); две репы; «просрочка» (`[не нашёл]`).
- **Оценка по файлам ответа, а не по формулировке отчёта:** каждая ссылка открывается и подтверждает; ни
  одного выдуманного имени; ни одного записанного файла; секретов нет.
- **Пробы этапа 2:** код сервиса рядом → вариант есть; нажат → гипотеза из кода, после «да» 🔵, путь в спеку не
  попал; два задетых сервиса, код рядом только у одного → вариант только у него; реп рядом нет → варианта нет,
  интервью как сегодня.

## 8. Вне плана

- Запись ответа в ноут, автообновление карточек, правки кода.
- Вопросы «как сделать», проектирование.
- git-команды (`pull`, `log`, `blame`).
- Встраивание в петлю дискавери.

## 9. Доработка по ревью `skill-review` (2026-10-23)

Статус: **выполнено 2026-10-23** (итог — 9.9). Правится по корню: каждая находка ревью сведена к причине,
правка — в причине.

### 9.1 Корни

| Корень | Находки ревью | Что меняем по сути |
|---|---|---|

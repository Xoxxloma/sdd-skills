# План: быстрое обновление карточек после релиза (2026-09-15, v4)

**Цель** — самый быстрый и удобный способ обновить контекст сервисов после релиза: полный скан репы
занимает 15–30 минут в зависимости от её размера. **Прототип готов и замерен** (ветка `feat/keyed-update`,
не слита). Ссылки на строки — по `main` на `4066c96` (`service-map` 1.2.0, `archive-spec` 2.0.0).
Прошлые версии — в §7.

## 0. Договорённость

- **Спека — точное отражение того, что едет в прод.** Без спеки не делается ни одна задача: фича,
  мелкая правка, багфикс (путь багфикса обязателен, в том числе для хотфиксов).
- **После релиза — быстрое обновление** карточек по архивируемым спекам. **Полный рескан — раз в квартал.**
- **Пишет карточку только `service-map` и только по коду.** `archive-spec` передаёт подсказку «что
  задето», код не читает, карточку не пишет.
- **В шапке только даты:** `scanned` — последний полный скан, `updated` — последнее быстрое обновление.

### 1.2. Почему рескан не решает задачу скорости

Рескан поверх прежней карточки почти ничего не меняет (тех. часть 0–1 % строк, форма ключей держится по
прежней карточке, заголовки сообщений 14/14 дословно), но длится как полный скан: перечитывает всё, чтобы
подтвердить ~99 % неизменного. На большом сервисе он ещё и хрупок: `rescan-v2/rescan-2` за 34 минуты не
обновил ни одной карточки.

### 1.3. Для контекста: без прежней карточки сканы расходятся сильно

Два независимых первых скана расходятся в 63 % (api) и 82 % (web) строк; эндпоинт то с `/api`, то без;
заголовки сообщений не совпадают ни у одного из 14 видов. Касается только первого скана нового сервиса —
рескан и быстрое обновление держат форму по прежней карточке. Пакет «устойчивых ключей» (v2) снят;
вернуться к нему, если на flash-моделях форма не удержится.

## 2. Что сделано в прототипе (`feat/keyed-update`)

- **`service-map/reference/keyed-update.md`** (130 строк) — режим по подсказке «Задето». Ведущий читает его
  **только** когда подсказка передана; где правила расходятся с `SKILL.md`, старше он. Внутри: когда режим, а
  когда полный путь; что добавить к брифу субагента (опись одних ключей, сопоставление подсказки с кодом,
  появились/исчезли, блоки только задетых плюс все сообщения); проверки ведущего (по всей карточке — по
  задетым); запись через `Edit` по блоку; какие правила `SKILL.md` заменены; отчёт.
- **`SKILL.md` +4 строки:** указатель в таблице `reference/` и в Шаге 2.2, `argument-hint`. Полный путь не менялся.
- **`card.template.md` +3 строки:** смысл `updated`.
- **Гард в быстром режиме** (уточнён по `keyed-stable`): исчезнувший ключ без ответа человека не удаляется,
  остальные правки пишутся; ключ, переставший быть ключом из-за формы шаблона, исчезнувшим не считается.
- **Стенд:** плечи `rescan` и `keyed` (`run.sh`, `seed.sh`), сдвиг `scanned` в засеве (`SM_RESCAN_DATE`), патч
  кода в засеве (`SM_REAL_PATCH`, `fixtures/SM-REAL/patch-remind.diff`), `stand/prompt-keyed.md`, подсказки
  `stand/hint-stable.md`, `stand/hint-patch.md`.

## 4. Отдельная линия (по желанию, после §3): ускорить полный скан

Ведущий после субагентов работает ~12 минут, из них ~4 — перепечатка карточек через `Write`, ~8 — ~40
шагов проверок. Приёмы: не перепечатывать карточку (−4–5 мин), проверки одним-двумя шагами (−5–7 мин, нужен
Bash у агента аналитиков), меньше доборов (−0–3 мин). Оценка: полный скан ~13–17 мин вместо 27–31. Меняет
правило «субагент файлов не пишет» — отдельный замер.

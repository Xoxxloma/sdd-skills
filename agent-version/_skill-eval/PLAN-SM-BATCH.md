## 2. Широта: разведчик недобирает маркеры

**2.1 (А) Аннотация без скобок.** Бриф разведчика: в примерах аннотаций `\b` вместо `\(`
(`@(Get|Post|Put|Patch|Delete)Mapping\b`, `@Scheduled\b`), правило 4 — пример `@GetMapping\b`; одна
строка в «Правилах маркера»: «аннотация без аргументов пишется без скобок — после имени ставь `\b`,
не `\(`; `\(` — только у вызова». Механизм: в прогоне 8 маркер `@DgsQuery\(` дал 0 на аннотациях без скобок.

**2.2 (Б) Контрольный файл.** Разведчик на каждый класс с `ключ` добавляет строку
`контроль :: <класс> :: <абсолютный файл> :: <сколько ключей класса ты сам видел в этом файле>` —
файл из уже открытых. Счётчик пишет её в `counts.txt` как есть (заголовок `## контроль`). `plan.sh`
сравнивает с суммой строк `ключ` этого класса по этому файлу: меньше половины — строка
`УЗКИЙ МАРКЕР: <класс> — маркер дал N в <файл>, разведчик видел M`. Ведущий: второй запуск разведчика
с этой строкой (один на сервис), затем счётчик заново; снова узкий — строка в отчёт, работа дальше.
Порог «меньше половины» — чтобы ошибка счёта разведчика на ±1 не гоняла повтор.

# План: specs-quality — оценка БТ и спек с выходом JSON для приложения

Новый скилл `manager-version/specs-quality/` по устройству `session-quality`: модель находит и ставит балл с
цитатой, считают и пишут выход скрипты, выход — один JSON по схеме (`specs-quality/1`). Баллы, критерии и якоря — из
`sdd-quality-audit` 1.4.0 без изменений: меняется только форма ответа субагента и кто считает. Коммит — только по
просьбе, всё вместе.

## Что переносится из sdd-quality-audit 1.4.0 как есть

- Обе рубрики: пять критериев, веса, якоря, «н/п», флаг «шаблонно», список разделов формы, происхождение спеки.
- Правила подсветки: итог < 50%, ноль по критерию, «шаблонно: да», «не по форме» (БТ — от 5, спека — от 6),
  спека «по коду».
- Таблица шага 1: какие файлы — строка выхода, источник спеки, `_foundation/`, баг-репорт и запрос на правку.
- Ведущий документы и ответы субагентов не читает, один субагент на документ. Выписка с цитатами — в JSON у
  каждого документа: собирает её скрипт, контекст ведущего она не тратит.

## Что меняется

| Было (1.4.0) | Станет |
|---|---|
| Субагент отвечает строками `1.`–`5.`, `форма:`, … | JSON по `findings.schema.json`; порядок ключей сохраняет «сначала выписка, потом балл», «сначала факт, потом флаг» |
| Эхо-строка `рубрика прочитана: …` | Ответ обязан пройти схему находок — её поля есть только в рубрике |
| Ключ, фича, автор — из ответа субагента | Из шапки документа — скриптом `collect.py` |
| Сумму, процент, ноль, порог формы считает ведущий | `merge.py`; формулы — в `contract.py`, пороги и веса — в `params.json` |
| Отчёт `sdd-quality-report.md` пишет ведущий | `merge.py` пишет один JSON; `contract.py` его проверяет; список «Требуют внимания» скрипт печатает на экран |
| Цитаты субагента не сверяются | `merge.py` ищет цитату в тексте документа (без учёта переносов, `**`, `` ` ``, вида кавычек); не нашлась — в `unverified` документа, балл не меняется (Р7) |
| У ведущего `Read, Glob, Agent, Write` | `+ Bash(python)` |

Чего нет в первой версии: автор из git, свод по автору или команде, проверка формы скриптом (сверка заголовков
остаётся у субагента, как в 1.4.0).

## Выход — `specs-quality/1` (набросок)

```
schema, generated_at
subject:  team | null, repo | null, coddoc_dir, rows_total, documents_total, documents_scored
params:   file, attention_pct, form_min {bt, spec}, weights {bt[5], spec[5]}
rows[]:   key, feature, folder, bt: <doc id> | {na: «баг-репорт» | «запрос на правку» | «узел-фундамент» | «нет»},
          spec: <doc id> | {na: «спеки нет»}
documents[]:
  id, kind: bt | spec, path, key, feature, author | null
  source (spec): {kind: bt | bug_report | change_request | none | not_passed, path | null}
  status: scored | failed (+ reason)
  criteria[5]: id, status: scored | na, score | null, weight, evidence[{section, quote}], reason, fix
  total: {sum, max, pct}, zeros[]
  template: {flag, fact | null, generic[]}
  form: {missing[{n, title}], of, off_form}
  origin (spec): {traces[], code_signs[{n, quote}], verdict}
  attention: {flag, reasons[below_pct | zero | template | off_form | by_code]}
  unverified[]: {criterion, quote} — цитаты, которых нет в тексте документа
```

Конверт (`schema`, `generated_at`, `subject`, `params`) — те же имена, что у `session-quality/4`.

## Как устроено

```
/specs-quality <coddoc/ | папка фичи | файл | ключ> [команда] [репозиторий]
  1. python collect.py  → work/collect.json (строки, документы, источники, шапка), work/<doc>.task.txt
  2. субагенты волнами ≤ N: «прочитай рубрику и задание <doc>.task.txt» → ответ как есть в work/<doc>.findings.txt
  3. python merge.py    → specs-quality-<дата>.json (проверен contract.py); печатает «Требуют внимания»; удаляет work/
  4. ведущий показывает путь к JSON и список «Требуют внимания»
Итог — <корень репо>/specs-quality-<дата>.json (есть — -2, -3). work/ — <корень репо>/specs-quality-<дата>.work/:
collect.json, задания и ответы субагентов, лог отброшенного; после успешной сборки удаляется, при ошибке остаётся
для разбора. В coddoc/ ничего не пишется.
```

# План: петля дискавери — ноут, встречи, интент к БТ и спеке

Дата: 2026-10-15. Редакция 3 — по ответам пользователя. Реализация не начата. Ссылки — от `agent-version/` на
main (baf704f).

## Что решено с тобой

| Вопрос | Решение |
|---|---|
| Кто пишет интент к БТ или спеке | один новый скилл `notes-to-intent`; на входе — список пунктов |
| Откуда список пунктов | три производителя: расшифровка (`meeting-intake`), встреча по памяти (`meeting-recall`), ноут (`analyst-notebook`) |
| Список из памяти | по смыслу и форме тот же, что из расшифровки |
| Следующая команда | аналитик запускает сам; скиллы друг друга не зовут (переделать можно позже) |
| Мысли и наброски во вход | по умолчанию не берутся, показываются списком на выбор — одним вопросом в `notes-to-intent`, из какого бы источника ни пришёл список |
| Ошибка в ноуте | команда `поправь` и служебный вид `[снято]` |
| Длинная встреча в регрессе | один прогон на итоговом тексте |
| Бюджет и порог | ≈ $450–650; порог из прошлого замера ноута |
| Схемы | не сейчас |
| Оркестратор и стражи в скиллах документов | не нужны: интент в `/analyst-workspace` отдаёт аналитик |
| Созвон про несколько тем | не делим: обычно созвон про одну тему |

## Схема

```
расшифровка ─► /meeting-intake ──┐
память ──────► /meeting-recall ──┼─► список пунктов ─┬─► /analyst-notebook <тема> <список>  → запись в ноут
ноут ────────► /analyst-notebook │                   │
               собери пункты ────┘                   └─► /notes-to-intent <список>          → интент к БТ или спеке
                                                                                               → /analyst-workspace <интент>
```

| Скилл | Вход | Выход |
|---|---|---|
| `meeting-intake` 2.0.0 | расшифровка, текст разговора | список пунктов и разбор с цитатами |
| `meeting-recall` 1.1.0 | память аналитика | протокол и список пунктов |
| `analyst-notebook` 1.2.0 | текст, файл, **список пунктов**; команда `собери пункты` | запись в ноут; список пунктов из ноута |
| `notes-to-intent` 1.0.0 (новый) | список пунктов | интент к БТ или спеке |

Каждый скилл — один вход, один выход. В конце отчёта — строка «дальше: …» с готовыми командами.

## Решение 1. Список пунктов — общий формат

**Решение.** Файл `*.points.md` рядом с источником. Пункты — в синтаксисе ноута:

```
# Пункты: <предмет>
> Источник: <расшифровка <путь> | протокол по памяти <путь> | ноут <путь>, записи <с>–<по>>
> Задача: <KEY | —>
> Встреча: <дата · участники>                 ← у расшифровки и протокола

- [решено] Пропуск заказывает сотрудник — решил: Иванова А. · L57
- [решено] не входит: пропуска для подрядчиков — решил: Иванова А. · L80
- [открыто] Нужен ли паспорт гостя — ждёт: служба безопасности · L92
- [сведение] Гостей в день около 40 — со слов Сидоровой Н. · L104
- [набросок] Пропуск на неделю · 2026-10-14 №2
- [мысль] Гостю нужен пропуск на парковку? · протокол L45
```

- Виды — те же пять, что в ноуте: `решено`, `открыто`, `сведение`, `мысль`, `набросок`. У `решено` всегда `решил:`.
- В конце пункта — источник: строка расшифровки (`L57`), строка протокола или запись ноута (`2026-10-14 №2`).
- В списке только действующее и подтверждённое аналитиком: заменённого, снятого, поручений и сомнительного без
  ответа нет. Ссылок между пунктами (`вместо:`, `отвечает на:`) нет — производитель разрешил их до выгрузки.
- Мысли и наброски аналитика идут в список как есть, своими видами. Брать ли их во вход, решает аналитик в
  `notes-to-intent` (Решение 5); в ноут они ложатся мыслями и набросками.

**Почему.** Это единственное, что проходит между скиллами. Поэтому `notes-to-intent` не знает ни о расшифровках,
ни о формате ноута, а ноут не знает о расшифровках. Синтаксис ноута уже есть и измерен; созвон и так ложился в
ноут этими пунктами (`meeting-intake/reference/output.md:60–72`).

**Что потребуется.** Описание формата — один короткий файл. Каждый из четырёх скиллов держит у себя только свою
сторону: производитель — как писать, потребитель — как читать.

**Плюсы.** Новый источник (письмо, тикет поддержки) — ещё один производитель, остальное не меняется. Логику
интента можно мерить на готовом списке за ~$1–2, а не через расшифровку за $6–36.
**Минусы.** Формат общий для четырёх скиллов: новое поле — правка в четырёх местах. Поэтому поля заморожены:
вид, текст, кто, источник. Строка пункта беднее разговора — см. Решение 5.

## Решение 2. `meeting-intake` 2.0.0 — только разбор разговора

**Решение.** Остаётся то, что он делает лучше всего: карта тем, разбор субагентами с цитатами, проверка
субагентом, вопросы о сомнительных решениях («оставляем / в открытые / не вносим»). Выход — список пунктов и
разбор с цитатами для человека. Уходит:
- цель и роли (Шаг 5), сравнение с документами задачи, раскладка на БТ и спеку, запись входа — в `notes-to-intent`;
- «в ноут» и «ноут на входе» — ноут сам принимает список (Решение 4).

Одна тема на созвон, как сейчас. Документы задачи `meeting-intake` больше не читает.

Пример: `/meeting-intake calls/1016-ахо.vtt` → вопросы о двух условных решениях → `docs/_inbox/meeting-2026-10-16.points.md`
и `meeting-2026-10-16.razbor.md` → «дальше: в ноут — `/analyst-notebook <тема> <список>`; в интент —
`/notes-to-intent <список>`».

**Почему.** Ветки «ноут» и «в ноут» сейчас стоят в 12–20 местах четырёх файлов `meeting-intake` — то, что ты
назвал «хрупко». Убираются целиком, а вместе с ними и половина основного пути (цель, слои, документы): скилл
делает одно дело.

**Что потребуется.** `SKILL.md`: TL;DR, Шаги 0, 2, 5–8, «Чего не делаешь», `description`. `reference/`: `extract.md`
— без слоя и документа у записи; `verify.md` — без проверок слоя и документа; `output.md` — форма списка вместо
входа и записи в ноут; `formats.md` — без профиля ноута; `map.md` — без строки про ноут. Major: результат другой.

**Плюсы.** Короче, без развилок; проверка цитат и вопросы о сомнительном остаются там, где есть расшифровка.
**Минусы.** Самая большая переделка плана: измеренный путь режется пополам, первые круги, скорее всего, красные.
Встреча по готовому БТ — две команды вместо одной.

## Решение 3. `meeting-recall` 1.1.0 — в конце протокола список пунктов

**Решение.** Протокол остаётся как есть (ответы аналитика дословно, итог по темам). Вместо подсказки
«`/meeting-intake <протокол>`» скилл пишет рядом список пунктов из итога:
- решение → `[решено] … — решил: <кто>`; «принял — не помню» → `[открыто] … — ждёт: —`;
- открытый вопрос → `[открыто]`; вне рамок → `[решено] не входит: …`; сведение → `[сведение]`;
- «(не уверен)» → `[открыто] <суть>? (по памяти, не уверен) — ждёт: <кто>`;
- поручения и «уточнить у участников» в список не идут (во втором случае — уже открытые вопросы);
- ответ «моя мысль» → `[мысль]`.

Пример: «срок отмены 12 часов — приняла Зайцева, вроде бы» → `- [открыто] Срок отмены 12 часов? (по памяти, не
уверен) — ждёт: Зайцева О. · протокол L31`.

**Почему.** Итог по памяти уже разложен по видам, а каждое имя и число в нём сверено со словами аналитика
(`meeting-recall/SKILL.md:144–149`). Прогонять протокол через `meeting-intake` — второй раз разбирать то, что уже
разобрано вопросами, за $6–36.

**Что потребуется.** Шаг 5 (запись списка и перечитка), форма списка, отчёт, «Пишешь один файл» → два.
**Плюсы.** Встреча по памяти даёт тот же список, что расшифровка, без разбора. **Минусы.** Перевод итога в пункты
— новый шаг; «не уверен» и «не помню» надо не потерять — пробы.

## Решение 4. `analyst-notebook` 1.2.0 — принимает список и выгружает его

**Решение.**
- **Приём.** `/analyst-notebook <тема> <список>`: пункты списка — пункты записи; дальше обычная сверка с прошлыми
  записями (передумал, ответ на открытый вопрос, спор) и вопрос «Записать так?». Заголовок записи `### <№> ·
  <созвон 16.10 | встреча по памяти 17.10>: <предмет>`, под пунктами `> исходник: <путь к списку>`.
- **Выгрузка.** `/analyst-notebook <тема> собери пункты [с <даты>] [про <предмет>]` → `notes/<тема>/notebook-<дата>.points.md`:
  - только действующее: заменённое (`вместо:`), закрытый вопрос (`отвечает на:` — вместо него ответ), снятое (`[снято]`);
  - мысли и наброски — как есть, своими видами; вопроса о них здесь нет — он в `notes-to-intent`;
  - срез `с <даты>` — пункты от раздела этой даты; дату называет аналитик; в шапке — «записи <с>–<по>»;
  - проверка — уже работающая рубрика выкладок `view-check.md`.
- **Перенаправления.** Ноуту дали расшифровку или протокол — строка «сначала `/meeting-intake <файл>`» или
  «`/meeting-recall`». `собери вход в БТ` — строка «`собери пункты`, потом `/notes-to-intent <список>`».

Пример: ноут «пропуска гостей» за месяц → `… собери пункты` → список: 15 решений, 4 открытых, 6 сведений,
7 мыслей, 2 наброска; заменённого решения в нём нет.

**Почему.** Формат ноута читает и пишет только ноут: замены, снятия и даты он разрешает сам. Правила сверки
перестают жить в двух скиллах (сейчас — `analyst-notebook` Шаг 4 и `meeting-intake` Шаг 7).

**Что потребуется.** Строка Шага 2 (список), Шаг 1 (тема — гипотезой, как сейчас), раздел «Выгрузка» в сборке,
строки перенаправлений, `description`. Старые записи с `> разбор:` действительны — одна строка в `view-check.md`.
**Плюсы.** Одна семья команд про ноут; правки ноута меряются за ~$0.4 за прогон.
**Минусы.** Список пунктов — одна фиксированная форма внутри агностичного ноута (это стык, а не выкладка для
человека).

## Решение 5. `notes-to-intent` 1.0.0 — новый скилл интента

**Решение.** `/notes-to-intent <список> [ключ]`:
1. **Ключ и документы.** Ключ из шапки списка или строки вызова; нет — спросить («ещё нет» — нормально).
   Документы задачи — `Glob docs/**/<KEY>/{business_requirements,technical_specification,change_request}.md`,
   читаются целиком.
2. **Цель и роли** — вопросом гипотезой, таблица целей из `meeting-intake` Шаг 5: новый БТ, правки БТ, правка
   работающего, новая спека, правки спеки.
3. **Раскладка на БТ и спеку** — правило «Слой» из `meeting-intake/reference/extract.md:50–64` переезжает сюда;
   пункты не своего слоя — списком на кивок: «во вход БТ не беру — похоже на реализацию (2): 1. … — так?».
4. **Сверка с документом:** уже записано — не идёт; меняет — «в БТ сейчас «<как там>», в списке «<как здесь>» —
   меняем?»; во входе спеки — «Расходится с БТ».
5. **Мысли и наброски** — в списке есть `[мысль]` или `[набросок]` (из протокола по памяти или из ноута):
   «Мысли и наброски во вход не беру (3): 1. … Взять какие-то?» — «ни одного» (рекомендация), «все», «номера —
   напишу». Взятые — в «Открыто» с пометкой «(предложение аналитика)». Можно в том же ходе, что вопрос 3.
6. **Проверка** — субагент по рубрике раскладки и сверки (части `verify.md` про слой и документ переезжают сюда).
7. **Сводка** — один вопрос: пункты интента по разделам и что не пошло («другой слой — K, уже записано — K,
   мысли и наброски не взяты — K»).
8. **Запись** — `docs/<KEY>/<имя списка>-bt|spec.md` (ключа нет — `docs/_inbox/`), форма входа без изменений
   (`meeting-intake/reference/output.md:11–32`); `> Источник: <путь к списку>`. Отчёт — «дальше:
   `/analyst-workspace <интент>`».

Второй документ (сначала БТ, потом спека) — тот же список второй раз с другой целью. Особый «второй прогон по
разбору» больше не нужен.

Пример: `/notes-to-intent notes/пропуска-гостей/notebook-2026-10-20.points.md` → «ключ? — PASS-12» → «новый БТ
(документов нет); решают: заказчик — Иванова А.» → «похоже на реализацию (1): `POST /passes` — не беру?» и
«мысли и наброски (9) не беру — взять какие-то?» → «ни одного» → сводка → `docs/PASS-12/notebook-2026-10-20-bt.md`.

**Почему.** Интент пишет один скилл — разъехаться нечему. Вся «вторая половина» `meeting-intake` (цель, слои,
сравнение с документами) переезжает сюда целиком, а не копируется. Вопрос о мыслях тоже живёт только здесь:
сейчас все они уходят в «Открыто (со слов аналитика)» (`meeting-intake/reference/formats.md:14`), а скилл БТ
переносит их в «Открытые вопросы» — БТ с 20 TBD. Нужный набросок теряется, только если аналитик не глядя
ответит «ни одного»; в ноуте он остаётся.

**Что потребуется.** Новый скилл: `SKILL.md` (~150 строк) и `reference/` — слой, проверка, форма интента. Перенос,
а не новое сочинение: тексты из `meeting-intake` Шагов 2 (ключ, документы), 5, 7, 8 и `extract.md`/`verify.md`.
**Плюсы.** Логика интента меряется на готовом списке дёшево; любой источник даёт один и тот же интент.
**Минусы.** Скилл видит строку пункта, а не разговор: раскладку на БТ и спеку и «противоречит БТ» сейчас решает
субагент, читая встречу. Меры: в пункте — суть и источник (можно открыть строку источника); раскладка — списком на
кивок; сомнения по смыслу разбирает производитель, у которого есть цитаты. Риск — главный для проб.

## Решение 6. Поправки в ноуте (Срез 2)

**Решение.** `/analyst-notebook поправь <дата> №<n>: <как верно | снять — почему>`, правила — в `reference/fix.md`.
- Перепутан автор → `- [решено] … — решил: Петров С.; вместо: 2026-10-14 №1 «…»`.
- Снять без замены («забудь мою мысль про недельный пропуск») → `- [снято] Пропуск на несколько дней — передумал
  аналитик; вместо: 2026-10-14 №2 «…»`. `[снято]` — служебный шестой вид, только в поправке; выгрузка, ответы и
  выкладки его и снятый пункт пропускают.
- Не тот ноут → снять здесь, строка с командой для нужного ноута.
- Поправка — только по явной ссылке на запись или словам о самой записи («записал не туда»). «Решил не он» без
  ссылки — обычная запись со сверкой: это бывает и настоящей сменой решения.
- Сверка: «тот же ответ» — тот же ответ **и тот же решивший**; другой решивший — вопрос «подтвердил ещё и <кто>
  или записано неверно?».

**Почему.** Прошлые записи не правятся; через `вместо:` все читатели уже умеют исключать пункт, снятие —
«заменён ничем». **Что потребуется.** `fix.md` (~25 строк), строки в TL;DR 2, Шагах 2 и 4, выгрузке,
`view-check.md`. **Плюсы.** Нового механизма нет. **Минусы.** Шестой вид могут поставить в обычную запись —
держат пробы.

## Пробы и порядок работ

**Срез 1 — петля** (Решения 1–5). Порядок внутри: формат списка → `notes-to-intent` (перенос) → `meeting-intake`
2.0 → `meeting-recall` → `analyst-notebook` → README и CHANGELOG.

- **Фикстуры.** Списки пунктов для проб `notes-to-intent` пишутся руками из зелёных входов прошлых прогонов
  встреч; до пула их вслепую читает свежий субагент. Так пробы интента не зависят от зелёного `meeting-intake`.
- **`notes-to-intent` на готовых списках** (~$1–2 за прогон): новый БТ; правки БТ (уже записано, меняет); правка
  работающего; спека при готовом БТ («Расходится с БТ»); реализация во входе БТ — списком на кивок; мысли и
  наброски — вопрос, по умолчанию не взяты, «номера» — взятые в «Открыто» с пометкой (список из ноута и список из
  протокола по памяти); второй документ из того же списка.
- **`meeting-intake` 2.0** (~$5): шесть встреч (отпуска, реализация доступа, фича с нуля, вторая встреча по спеке,
  встреча меняет БТ, правка работающего) — проверяется список пунктов; созвон-расспрос без решений — сведения в
  списке; длинная встреча × 1 на итоговом тексте (~$23–36).
- **Цепочка** «расшифровка → список → интент» — две встречи из шести, чтобы стык проверялся целиком.
- **`meeting-recall`** (~$2–3): новая функция и правка по готовому БТ — список рядом с протоколом, «не уверен» и
  «моя мысль» не потеряны.

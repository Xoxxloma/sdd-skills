# RT-E2E — сквозной стык «проверка → доработка», оба под-скилла живые

Готовая спека PSS-2210 (спека `SR-GAP`, та же, что в `RT-SRGAP` и `TS-FIX`) подхвачена «Продолжить начатое» →
узел «Что дальше?» → «Проверить спеку.» → **живой** `spec-readiness` → узел → «Доработать спеку — только пункты
1–3…» → **живой** `technical-spec-doc`, проход доработки → вопросы гипотезой → «По пунктам 1 и 2 — да… По пункту
3 — не знаю» → запись → приёмка (заглушка `spec-review`) → узел → «На сегодня всё».

Зачем. Каждая половина мерилась отдельно: проверка в треде — `rt-srgap`, доработка по готовому отчёту —
`ts-fix` (отчёт подан промптом). Стык целиком — нет: доезжает ли отчёт живой проверки до доработки, берутся ли
только названные пункты, спрашивает ли автор до записи в треде оркестратора.

| Что | Верно | Грейд |
|---|---|---|
| отчёт проверки | счётная строка «вопросов задано» и узел тем же ходом | `grade-rt-e2e.mjs` |
| доработка | `technical-spec-doc` вызван ходом после реплики «Доработать» | `grade-rt-e2e.mjs` |
| сначала спросил | в ходе запуска доработки нет записи в спеку | `grade-rt-e2e.mjs` |
| узел поверх вопросов | в ходе вопросов доработки узла нет | `grade-rt-e2e.mjs` |
| спека изменена | итоговая спека отличается от засева | `grade-rt-e2e.mjs` |
| приёмка после записи | `spec-review`, не `spec-readiness` | `grade-rt-e2e.mjs` |
| узел после приёмки | узел из четырёх в том же или следующем ходе | `grade-rt-e2e.mjs` |
| только пункты 1–3 | вопросы доработки — про пункты 1–3 отчёта, не про 4+ | глазами, `_e2e-review.md` |
| 1, 2 записаны | ответ «да» лёг в спеку на место пунктов 1, 2 | глазами, дифф |
| 3 открыт | пункт 3 — ❓ TBD / «Открытые вопросы», не догадка | глазами, дифф |
| лишнего нет | дифф не трогает пункты 4+ и не вносит фактов, которых не было в гипотезах | глазами, дифф |

Отчёт проверки живой, поэтому пункты 1–3 от прогона к прогону разные: грейдер выписывает их из отчёта
прогона в `_e2e-review.md` рядом с вопросами доработки и диффом спеки.

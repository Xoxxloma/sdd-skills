# ID-RING — короткая схема на сложном графе (interaction-diagram 4.3)

Спека RET-512 (возврат товара с курьерским забором) написана руками 2026-09-29 под сложные связи: кольцо, встречные
пары, один сервис под двумя именами, карточка без направления. БТ — FR-1…FR-5. `services/` — ловушка путей
(`POST /v1/refunds/create`, `DELETE /internal/slots/{slotId}`): скилл их не читает, путь оттуда на стрелке — красный.
Подпись стрелки — из «Контракт…» при любом маркере: путь 🔵 и 🟡, в том числе «предположительно», идёт на стрелку.

До ответа 8 участников: Мобильное приложение, returns-api, warehouse-service, courier-gateway, billing, notify,
Покупатель, бэкенд возвратов. 11 карточек:

| INT | Граница | Ожидание | Что проверяет |
|---|---|---|---|
| 1 | Мобильное приложение → `returns-api` | `INT-1 · POST /v1/returns` | участник по-русски из двух слов |
| 2 | `returns-api` → `warehouse-service` (синхронно, часть обработки INT-1) | `INT-2 · POST /internal/slots` | путь 🔵-карточки — на стрелке |
| 3 | `returns-api` → `courier-gateway` | `INT-3 · POST /partner/v3/pickups` | путь 🟡 «предположительно» — на стрелке |
| 4 | `courier-gateway` → `returns-api` (вебхук) | `INT-4 · POST /v1/returns/{returnId}/courier-status` | встречная пара с INT-3: своя стрелка, не «ответ» |
| 5 | `событие: warehouse-service → billing (через Kafka)` | асинхронная, подпись `INT-5` | имени события в контракте нет; кольцо returns-api → склад → биллинг → returns-api |
| 6 | `billing` → `returns-api` (колбэк) | `INT-6 · POST /v1/returns/{returnId}/refund-status` | замыкает кольцо |
| 7 | `событие: returns-api → notify` | асинхронная, `INT-7 · returns.status-changed` | — |
| 8 | `notify` → Покупатель (SMS) | подпись `INT-8` | человек — участник, впервые справа |
| 9 | `returns-api` → `billing` | `INT-9 · POST /v2/refunds` | встречная пара с INT-6; не `POST /v1/refunds/create` из `services/` |
| 10 | бэкенд возвратов → `warehouse-service` | подпись `INT-10`; от кого — по ответу | другое имя returns-api (раздел ответственности бэкенда и «Авторизация» INT-10 называют returns-api): склеивать только по ответу; `DELETE` из `services/` — нельзя |
| 11 | «❓ не решено — склад забирает остатки из 1С или 1С присылает их складу» | стрелки нет | знака нет, в тексте две стороны — вопрос о направлении; ответ «не знаю» — карточки на схеме нет, номер в отчёте «без стрелки» |

Вопросы хода 2: участники (все восемь имён), порядок, направление INT-11.

Пара имён — читать вместе: одна спека, противоположные ответы, схема обязана идти за ответом.

Грейдер — `grade-id.mjs`, таблица `STAGE`: «схема верна» — файл, стрелки, подписи, участники, порядок по реплике;
отдельным счётом — ход 1 только вопрос о типе, вопросы хода 2 без файла, нет лишнего вопроса о карточке, фраза
шапки, открыт `reference/short.md`, строка отчёта «со слов аналитика» (называет «бэкенд возвратов» или INT-10).
Проверка «лишний вопрос о карточке» красит строку с `?` и ровно одним номером карточки, кроме INT-11. Вопрос, один ли
это сервис («„бэкенд возвратов“ в INT-10 — это returns-api?», «считать их одним сервисом?»), — вопрос об участниках, его
она не красит (до 2026-10-01 красила, CHANGELOG 5.27).

Устарели (на 4.3 не работают): `ring-mmd`, `ring-puml` — одноходовые, ждут файл первым ходом. `mmd-prompt.txt` нужен
только `ring-mmd`.

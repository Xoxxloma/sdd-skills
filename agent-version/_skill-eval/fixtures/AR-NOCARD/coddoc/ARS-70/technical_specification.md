# Техническая спецификация: уведомление об отзыве сессии

> **Статус готовности:** Готово к разработке
> **Задача:** ARS-70

## 1. Обзор изменения

### 1.1. Тип и стороны
BE-only. При отзыве сессии пользователю уходит уведомление.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `auth` | публикует событие | Платформа | 🟢 |
| `notify` | новый консьюмер и эндпоинт | Уведомления | 🟢 |

### 1.3. Связь с бизнес-требованиями
Пользователь должен узнавать, что его сессию завершили.

## 2. Взаимодействия (ядро)

### INT-1. Событие отзыва сессии — 🟢
- **Граница/направление:** событие `auth.session.revoked`
- **Контракт (запрос):** `{ sessionId: string, userId: string, revokedBy: string }`
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-1

### INT-2. Настройка каналов уведомлений — 🟢
- **Граница/направление:** FE → BE
- **Контракт (запрос):** `GET /v1/notify/channels`
- **Контракт (ответ):** массив `{ channel: enum, enabled: bool }`; `channel` — `email` | `push` | `sms`
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-2

## 3. Backend — ответственность

### 3.1. По сервисам
`auth` публикует `auth.session.revoked`. `notify` его потребляет и реализует `GET /v1/notify/channels`.

### 3.2. Данные и хранение
`notify` заводит сущность `NotificationPreference` — канал на пользователя. Происхождение: 🟢.

## 7. Трассировка приёмки

| FR | Как проверяется |
|----|-----------------|
| FR-1 | При отзыве сессии уходит уведомление |
| FR-2 | Пользователь видит и меняет каналы |

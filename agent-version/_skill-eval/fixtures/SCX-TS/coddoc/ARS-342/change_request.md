# Запрос на правку: бортовой телефон ГБР в карточке инцидента

> **Статус готовности:** Готово к оценке
> **Задача:** ARS-342
> **Автор:** ivanova

## 1. Затронутый бизнес-процесс

Оперативный дежурный на карточке инцидента `/incidents/:id` смотрит назначенную ГБР и связывается с экипажем. Сведения об экипаже incident-web берёт из системы диспетчеризации «Пульт» ручкой `GET /pult/v4/crew-cards/{crewId}`; сейчас из её ответа на карточке показывается только позывной.

## 2. Что тронуто

| Строка | Тронута | Как сейчас → как должно стать |
|---|---|---|
| Контракт | да | из ответа карточки экипажа «Пульта» incident-web берёт только позывной → берёт ещё и бортовой телефон экипажа |
| Данные | нет | — |
| Интерфейс | да | под позывным назначенной ГБР телефона нет → под позывным показан бортовой телефон |
| Зависимость | нет | — |
| Конфигурация | нет | — |

Вердикт: мелкая правка, одна поставка.

## 3. Как сейчас

В карточке инцидента у назначенной ГБР виден только позывной. Бортовой телефон дежурный ищет в «Пульте» отдельно.

## 4. Как должно стать

- **FR-1:** в карточке инцидента под позывным назначенной ГБР показан бортовой телефон экипажа из «Пульта»; телефона у экипажа нет — строки нет — 🔵 решение аналитика: Иванова (аналитик) вместе со старшим дежурным

## 5. Как проверят, что сделано

Открыть инцидент с назначенной ГБР, у экипажа которой в «Пульте» есть бортовой телефон, — под позывным виден этот телефон; у экипажа без телефона строки нет.

## 6. Критичность и срочность

Средняя: дежурный тратит время на поиск телефона в другой системе. Общий релиз.

## Что рядом остаётся прежним

«Пульт» и его ответ не меняются — incident-web только читает то, что он уже отдаёт. Позывной показывается как раньше. Назначение ГБР и остальные блоки карточки инцидента не трогаем.

# Фикстура SCX-TS — спека в режиме мелкой правки после п.2б: источник стыка и чужой сервис

Заведена 2026-10-26, ревью покрытия ветки `feat/blue-contract` (5.75–5.80). Что уже было: `ts-cr-api` (`TS-CR`) —
своё изменение со стыком 🔵 «со слов» без пути. Не проверялось: путь стыка назван в самом запросе на правку (источник
«по документу сверху») и правка, которая задевает ЧУЖОЙ сервис («своё — карточка вида „изменение существующего“,
чужое — карточка потребления», `small-change-mode.md:166-168`).

Флаг мелкой правки изображён промптом, ответы аналитика — заранее («ПРОДОЛЖЕНИЕ»), как в `TS-CR`. Аналитик путь не
называет и «подтверждаю своими словами» не говорит — иначе источник стыка размывается до «со слов».

## Рукопись, а не выход скилла

Все три запроса написаны руками. Выхода `change-request-doc` с путём ручки нет ни в одном раунде (`runs/`, `fixtures/CR-*`,
`TS-CR`), а выходов про чужой сервис нет вовсе. `ARS-321` собран из замороженного `cr-api-w`
(`runs/2026-09-14-cr-pilot/cr-api-w/run-1`, скилл до нумерации версий): добавлены путь в §1 и §5 и строка «Автор»,
`🔵 решение аналитика: аналитик` → `Иванова (аналитик)`. `ARS-341`, `ARS-342` — по шаблону `change-request-doc/SKILL.md:352-396`.

Порядок замены: прогнать `change-request-doc` с ответами аналитика, где он сам называет путь (`ARS-321`, `ARS-342`)
или версию (`ARS-341`); взять прогон, который зелёный по `grade-cr.mjs`-критериям записи; положить его
`change_request.md` на место рукописи, **сохранив путь в тексте** — если писатель путь не переносит (см. ниже, первая
находка), рукопись остаётся; обновить `_manifest.txt`; перегнать `--selftest`.

## Противоречие и что правила не определяют

1. **`small-change-mode.md:144` против `:166-168`.** Таблица «Умолчание второе»: «Контракт | §2 — карточка вида
   „изменение существующего“: таблица „было → стало“, пример JSON» — без деления своё/чужое. Через двадцать строк:
   «своё — карточка вида „изменение существующего“, чужое — карточка потребления». В `ARS-342` строка «Контракт — да»
   описывает чтение чужого ответа — ровно тот случай, где строки расходятся. Ожидание `fld` взято из `:166-168` и
   договора происхождения, который режим не меняет (`:19-22`); плечо мерит, что побеждает.
2. **`small-change-mode.md:168-169`** — после «чужое — карточка потребления» идёт «типы, семантика null, пример JSON,
   каталог ошибок»: читается как требование JSON и у потребления, а `SKILL.md:185-188` и самопроверка `:589-591`
   запрещают конкретику у 🟡 и не требуют её у 🔵-потребления.
3. **Версия соседа — «Зависимость» у писателя (`change-request-doc:75`), «И ЕСТЬ изменение контракта» у спеки
   (`small-change-mode:166`).** При «Контракт — нет» неприменимость §2 законна, только если нет «использования прежнего
   контракта на границе» (`:171-174`). `dep` мерит, что §2 не закрыт. Приёмка этого не поймает: `checklist-spec.md:86-87`
   — пустой §2 у запроса законен, «когда в его „Что тронуто“ строка „Контракт“ помечена „нет“».
4. **Путь ручки в запросе на правку.** `change-request-doc` велит называть «ручку — словами аналитика» (`:327`, `:407-408`)
   и запрещает «контракты, имена полей» (`:35-37`, `:300`); `grade-cr.mjs` считает `GET /` в файле проектированием. Попадёт
   ли путь, названный аналитиком, в запрос — не определено; вход `doc` и `fld` может на проде не встречаться.
5. **Смешанная метка у потребления** (`fld`): путь подтверждён документом, а нужное поле — 🟡. Шаблон даёт карточке одно
   «Происхождение». Грейдер принимает оба законных прочтения: карточка 🔵 с путём «по документу сверху» и 🟡 словами без
   пути.
6. **Сверки «путь под „по документу сверху“ действительно есть в документе» нет нигде** — ни в самопроверке спеки, ни в
   §14 приёмки (там только наличие источника в метке). Двойник на это не заведён: красного по правилам у него нет.

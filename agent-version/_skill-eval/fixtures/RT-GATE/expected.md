# RT-GATE — гейт Шага 2Б на готовом документе

> **Написано до первого прогона** (2026-09-22, `analyst-workspace` 1.2.0).

**Что меряем.** Правка 1.2.0: гейт Шага 2Б задаёт вопрос «документ принят — идём дальше?» ВСЕГДА,
а не только при находках. До неё чистый документ (приёмка «нарушений: 0», статус «Готово к оценке»)
уезжал в `technical-spec-doc` без единой остановки — жалоба с поля. Заглушки здесь дают ровно чистый
документ, так что остановка обязана быть по одному тексту скилла.

**Вход.** На диске готовый БТ `docs/SMSEC-77/business_requirements.md` (копия `RT-CONT/ARS-102` с
другим ключом): §4.5 «не применимо», «Открытые вопросы — не осталось», статус «Готово к оценке».
Аналитик приносит его готовым — это ветка «Аналитика: Создаем Спецификацию на основе готового
документа», и маршрут входит в Шаг 2Б первым же ходом, минуя под-скилл БТ.

**Двухходовой стенд.** Реплика «Да, годится.» повторяется каждый ход; на вопрос гейта она читается
как «идти дальше».

## Верно

| Что | Ожидание |
|---|---|
| ход 1 | приёмка БТ в трассе (`spec-review docs/SMSEC-77/business_requirements.md`), документ прочитан, **ход остановлен вопросом гейта** — «принят — идём дальше?» с вариантами «Идти дальше — писать тех-спеку по SMSEC-77» / «Пока остановиться». Варианта «Поправить» нет — править нечего |
| `technical-spec-doc` | **НЕ в ходе 1.** Запускается ходом, следующим за тем, где задан вопрос гейта |
| источник в трассе | `docs/SMSEC-77/business_requirements.md`, `флаг=обычный` |
| `business-requirements-doc` | не вызван — документ уже есть, переписывать его нельзя |
| разрез | не вызван: §4.5 «не применимо» |
| дальше | как в `rt-feature`: приёмка спеки, станция `/spec-readiness`, вопрос про этапы, этапы, приёмка `stages/` |

## Красное — отдельными счётчиками

1. **Спека запущена в ходе 1** — остановки нет, гейт не отработал. Главный счётчик, ради него проба.
2. **Вопрос гейта не задан вообще** — ни в одном ходе нет «идём дальше?» / «Идти дальше —».
3. **Спека запущена не следом за вопросом гейта** — вопрос задан, но запуск случился раньше него
   либо через ход: остановка есть, а решение аналитика в неё не попало.
4. `business-requirements-doc` вызван — готовый документ переписан.
5. Разрез — на одной фиче резать нечего.
6. Приёмки БТ нет — принесённый документ гейтов не проходил, ему она нужна больше всех.

## Не нарушение

- Вопрос гейта задан прозой, а не инструментом: инструмента у прогона нет.
- Строка точки очистки «здесь можно `/clear`» рядом с вопросом — так велит правило 6.
- Отсутствие варианта «Поправить»: N+M = 0.

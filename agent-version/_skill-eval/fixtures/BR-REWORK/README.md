# Фикстура BR-REWORK — доработка готового БТ по находкам приёмки (К5 аудита 2026-09-17)

Оркестратор на «Поправить документ сейчас» и на «Доработать» отдаёт документ писателю и считает,
что у того «есть проходы доработки». У `business-requirements-doc` такой процедуры нет: он пишет
один новый файл, существующие не редактирует, первым ходом спрашивает ключ и гейты. Что он сделает
с готовым документом и списком находок — не определено. Проба меряет это по файлу.

`docs/RMS-5102/business_requirements.md` — БТ из `RV-AUDIT` с двумя посаженными нарушениями:
`PassportDto` в §3.3 и FR-3 без критерия в §4.2. В сообщении — отчёт приёмки и ответы аналитика,
которых хватает, чтобы закрыть оба без единого вопроса.

Верный исход: тот же файл поправлен на месте в двух местах, новых файлов нет, остальной текст цел
(§4.5 и §5.3 — побайтно), статус «Готово к оценке», ключ и закрытые гейты не переспрошены.
Грейдер — `grade-br-rework.mjs`, проба `br-rework`.

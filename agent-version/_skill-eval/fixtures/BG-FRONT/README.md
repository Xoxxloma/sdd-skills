# Фикстура BG-FRONT — фронтовый баг, правило которого лежит в карточке бэкенда (аудит, С13)

Дерево `BG-INC` плюс карточка `services/incident-api.md` с секцией «Бизнес-правила». Вопрос один:
дойдёт ли `bug-report-doc` до правила, когда затронутый сервис — фронтенд, а в его карточке
«Бизнес-правил» нет по форме.

| Что | Зачем |
|---|---|
| `services/incident-web.md` — `frontend`, «Бизнес-правил» нет; в «Потребляемых API» назван `incident-api` | карточка затронутого: экран `/incidents/:id/assign` здесь |
| `services/incident-api.md` — `backend`, блок `Incident`: «закрыт (`closed`) — … назначить или переназначить ГБР нельзя» | ожидаемое поведение стоит строкой правила |
| `front-q-prompt.txt` — первый ход, ответов аналитика нет | симптом без ожидаемого: «кнопка „Назначить“ активна у закрытого инцидента» |

**Зелёное:** прогон открыл карточку `incident-api` и принёс ожидаемое поведение гипотезой из правила
(«у закрытого инцидента назначать нельзя — значит, кнопка должна быть недоступна, верно?»).
**Красное:** ожидаемое спрошено вхолодную («как должно быть?») либо выведено из симптома без
карточки бэкенда. Файл на первом ходу не пишется — как у остальных плеч `-q`.

Плечо: `bg-front-q`. Грейдер: `grade-bg-front.mjs <раунд>/bg-front-q`.

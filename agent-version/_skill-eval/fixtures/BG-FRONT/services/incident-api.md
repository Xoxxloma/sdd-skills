# incident-api — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

**Назначение.** Учёт инцидентов безопасности: приём сигнала, назначение группы быстрого
реагирования, закрытие после отбоя. Главные объекты — инцидент и назначение.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Посмотреть список и детали инцидентов | Аналитик безопасности, Оперативный дежурный |
| Назначить ГБР на инцидент — только пока инцидент не закрыт | Оперативный дежурный |
| Закрыть инцидент после отбоя | Оперативный дежурный |

## Бизнес-правила

### `Incident` — инцидент безопасности
- новый (`new`) — создаётся по сигналу с объекта; ГБР ещё не назначена, дежурный видит его первым в списке
- назначен (`assigned`) — дежурный назначил ГБР; переназначить можно, пока группа не прибыла
- закрыт (`closed`) — дежурный закрывает после отбоя; назначить или переназначить ГБР нельзя, вернуть в работу нельзя

### сообщение «ГБР назначена»
- при назначении группы; получает старший группы; аналитику безопасности не уходит

## Публичный контракт

### `GET /v1/incidents`
Список инцидентов с серверной пагинацией.
- фильтры: статус, тип, период, ЧОП

### `GET /v1/incidents/:id`
Детали инцидента.

### `POST /v1/incidents/:id/assign`
Назначение ГБР на инцидент.
- `squadId: string`
- закрытому инциденту отвечает `409`

## События
| Направление | Топик | Когда |
|---|---|---|
| публикует | `incident.assigned` | после назначения ГБР |

## Владеет данными

### `Incident`
- `id`: `string`
- `status`: `new` \| `assigned` \| `closed`
- `squadId`: `string?`

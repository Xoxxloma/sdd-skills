# Фикстура BF-GATE — лишние тех-гейты у багфикса

Меряет пункт 4 режима багфикса (`technical-spec-doc/reference/bugfix-mode.md`): **какие вопросы
скилл задаёт на первом ходу**, когда документ сверху — баг-репорт, а ответов аналитика заранее нет.

Оба плеча ВОПРОСНЫЕ: промпт не содержит «это ПРОДОЛЖЕНИЕ», поэтому по правилу скилла
«turn 1 = questions only. No file» законный исход — список вопросов и НИ ОДНОГО файла.
Артефакт — `answer.md` (stdout), как у `br-ctx`, `rv-*`, `bg-*-q`.

| Что в дереве | Зачем |
|---|---|
| `docs/ARS-320/bug_report.md` | дефект НЕ про доступ, нагрузку, выкат и ошибки: не видно полосы скролла |
| `docs/ARS-321/bug_report.md` | дефект ПРО доступ: вкладка не видна роли `dispatcher` |
| `docs/ARS-102/` | для `bfg-scroll` — ловушка (другой экран); для `bfg-role` — ЯКОРЬ: §4.4 задаёт роли |
| `services/*` | слепок соседей, скопирован из `BF-SPEC` |

## Два плеча и почему их два

- **`bfg-scroll`** — измеряет ПЕРЕБОР. Дефект чисто визуальный, роли/нагрузка/выкат/ошибки в
  репорте не названы. Каждый вопрос про них — вопрос без адресата.
- **`bfg-role`** — СТОРОЖ ОБРАТНОГО ОТКАЗА. Здесь доступ и есть дефект. Если правка научит скилл
  молчать про роли вообще, это плечо покраснеет, и правку надо откатывать. Без него замер
  односторонний: «вопросов стало меньше» без сторожа означает и «скилл ослеп».

Складывать числа плеч нельзя: законные исходы разные.

## Что здесь НЕ меряется

- Записанный файл спеки. Его на первом ходу быть не должно; появился — это отдельный красный
  счётчик (нарушение «turn 1 = questions only»), а не предмет пробы.
- Маршрут проводника: флаг багфикса изображён промптом, как в `BF-SPEC`.
- Содержание будущей спеки. Это `bf-spec`, он остаётся как есть.

Что считается верным и красные счётчики — `expected.md`, написан до прогонов.
Происхождение документов — `PROVENANCE.txt`.

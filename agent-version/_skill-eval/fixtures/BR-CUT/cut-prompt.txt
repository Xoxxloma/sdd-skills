ОТВЕТ АНАЛИТИКА:
- Ключ задачи: ARS-180
- Тип: доработка существующего — в веб-админку «Арсенал» добавляется несколько связанных элементов для наблюдения за активностью пользователей.
- Проблема: администраторы не видят ни текущую, ни историческую активность пользователей — нельзя быстро оценить нагрузку, посмотреть динамику за период и забрать сводку для отчётности. Регламентные работы планируются вслепую.
- Конечные потребители: администраторы системы «Арсенал» (внутренние сотрудники эксплуатации).
- Заказчик: руководитель отдела эксплуатации.
- Бизнес-цель: как администратор хочу видеть активность пользователей — сейчас, в динамике и в виде выгружаемой сводки, — чтобы планировать безопасные окна работ и отчитываться по нагрузке.
- Ценность: меньше прерванных сессий во время регламентных работ, прозрачная отчётность по нагрузке для аудита и планирования.
- Риски: неточные данные активности вводят в заблуждение — при недоступности источника показываем «—» и пустой график, а не устаревшее значение; выгрузка доступна не тем ролям — панель и выгрузка только у администраторов.
- Приоритет: Medium.
- Сроки: не знаю, пропускаем.
- Ролевая модель: администратор видит счётчик, график активности и выгрузку сводки; оператору панель активности не отображается.
- Функционал: администратор видит в шапке админки число активных пользователей; значение обновляется автоматически, без перезагрузки страницы; по клику на счётчик открывается модальное окно с графиком активности за выбранный период (час / день / неделя); в модалке период можно переключать; в модалке есть кнопка выгрузки сводки активности за выбранный период в файл. Не входит: список конкретных пользователей онлайн (только агрегированные числа), автоматическая рассылка отчётов, прогнозирование будущей активности.
- Критерии приёмки: счётчик виден сразу после загрузки страницы и обновляется в пределах минуты после изменения; клик по счётчику открывает модалку с графиком за период по умолчанию; выбор другого периода перестраивает график; нажатие выгрузки даёт файл со сводкой за выбранный период.
- Архитектурные изменения: все три элемента опираются на одни и те же данные об активности пользователей (текущее число активных и агрегированная активность за период). Админка «Арсенал» начинает потреблять эти данные. Точные механизмы получения и хранения — на этапе тех.спеки.

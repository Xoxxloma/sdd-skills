# Фикстура SM-GRAPH2 — Шаг 5 `service-map` на ВТОРОМ проходе, на диске

`SM-GRAPH` подаётся текстом, и секции «Кто меня потребляет» в ней пусты — это первый проход. Здесь
слепок лежит файлами в `services/`, а зеркала уже стоят с прошлого прохода. Только на втором проходе
виден дефект К6 аудита 2026-09-17: Шаг 5 достаёт строки карточки грепом `^\| ` и уверяет, что
«прочие таблицы отличаются первой колонкой», хотя у «Кто меня потребляет» те же три колонки с
именем сервиса первой, что у «Потребляемых API». Строка потребителя, принятая за исходящее ребро,
даёт выдуманное обратное ребро — «auth вызывает incident-web».

## Что посажено

- в `auth.md` и `user-profile.md` зеркала прошлого прохода стоят на месте;
- в `user-profile.md` одно зеркало **устарело**: `incident-web | GET /v1/profiles/{id}` — у
  `incident-web` такого вызова больше нет (карточка перечитана 2026-09-16, остальные — 2026-09-10);
- во всех карточках есть и другие таблицы («Что умеет», «Экраны», «Роли и доступ»).

## Ожидание после Шага 5

| Карточка | «Кто меня потребляет» |
|---|---|
| `auth.md` | две строки от `incident-web`: с вызовом `GET /v1/sessions/count` и с прочерком |
| `user-profile.md` | две строки от `auth` с прочерком; устаревшей строки `incident-web` **нет** |
| `incident-web.md` | `— ` — фронт никто не потребляет |

Законных рёбер два: `incident-web → auth`, `auth → user-profile`. Любая другая пара в секции —
ложное ребро. Секции «Потребляемые API» и «Зависит от» не меняются. Грейдер —
`grade-sm-graph2.mjs`, проба `sm-graph2`.

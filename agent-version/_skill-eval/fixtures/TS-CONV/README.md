# Фикстура TS-CONV — тех-спека поверх своих документов и слепка

Парная к `TS-LIVE`: **тот же самый БТ** (слайс `ARS-201` из сквозного прогона), но рядом лежат
`services/` и `context/`. Заведена под правку `technical-spec-doc` (Step 0.5 + Self-Review) и
меряет **обе стороны одной границы**.

## Граница, ради которой фикстура существует

Step 0.5 несёт два соседних правила с противоположным действием, и спутать их — главный риск правки.
Граница проходит **не по имени файла и не по папке**, а по тому, о чём говорит прочитанное:

| О чём говорит прочитанное | Как применяется |
|---|---|
| о чужой работающей системе — её эндпоинты, поля, поведение | **под гейтом**: несёшь аналитику пересказом, в файл идёт только после «да», маркер `🟡 подтверждено аналитиком` |
| о форме твоего собственного 🟢-дизайна — путь, коды, `null`, даты, именование | **без гейта**: применяешь молча, маркер остаётся `🟢` |

Сломать можно в любую сторону, и обе поломки дорогие:
- правила оформления пошли под гейт → аналитику задают вопрос, на который он уже ответил, положив
  файл;
- **утверждение о чужом сервисе пошло без гейта → кардинальный грех скилла**: непроверенное
  утверждение о существующем сервисе записано фактом.

**Здесь эта граница проходит внутри одного захода:** карточка `services/auth.md` и документ
`context/conventions.md` читаются одним и тем же грепом по `^description:`, а применяются
противоположно.

## Вход

```
docs/ARS-201/business_requirements.md   тот же БТ, что в TS-LIVE
services/manifest.yaml                  auth (backend), arsenal-web (frontend)
services/auth.md                        отдаёт GET /v1/sessions/count с count и updatedAt
services/arsenal-web.md                 админ-панель, уже потребляет этот вызов
context/conventions.md                  правила оформления: путь, коды, null, даты, именование,
                                        таймауты; два слота со строкой «не определено»
```

## Что должно произойти

**Правила оформления применяются молча.** БТ требует «—» при недоступности источника (FR-5) и «0» как
валидное значение (FR-6). `context/conventions.md` отвечает на это ровно: `null` = «источник
недоступен», валидный ноль — число `0`. Скилл обязан спроектировать контракт по этому правилу и **не
спрашивать** аналитика, как кодировать недоступность. То же с путём (`/v1/…`), датами (`iso8601` UTC,
суффикс `At`), именованием полей и `403` при отказе по роли (FR-7).

**Выжимка остаётся под гейтом.** В `services/auth.md` написано, что `auth` отдаёт счётчик активных
сессий. Это не разрешение записать его фактом: скилл несёт это аналитику **пересказом на
подтверждение** («в `services/auth.md` описано, что … — верно?»). Без ответа — `🟡 к валидации`.

**Статус считается арифметикой.** По замыслу пробы источник данных остаётся неподтверждённым (см.
ответы аналитика ниже), значит открытый пункт есть и статус обязан быть «Требуются уточнения (N)» с
числом.

## Ответы аналитика для промпта

Даются все тех-гейты, **кроме одного**: подтверждение, что счётчик отдаёт именно `auth`. На него
аналитик отвечает «не знаю, я код не читаю» — это и есть незакрытый пункт, который тянет статус.

Имён полей, путей, кодов ошибок и форматов в промпте нет: часть проектирует скилл, часть задаёт
`context/conventions.md`. Промпт, называющий их, измерял бы сам себя.

## Красный исход

Спека спрашивает аналитика про то, что зафиксировано в `context/conventions.md`; либо
`GET /v1/sessions/count` записан фактом без подтверждения; либо статус «Готово к разработке» при
живом `🟡 к валидации`.

## Сторож регресса

`TS-LIVE` — та же задача **без** `services/` и `context/`. Правка обязана не изменить там ничего:
нет папок — одна строка и работа от БТ, как раньше.

# ID-DET — короткая и сценарная схема по одной спеке (interaction-diagram 4.3)

Спека PRK-9 (парковочная сессия с оплатой при выезде) написана руками: 6 карточек, все с направлением, у каждой есть
«Триггер», у пяти из шести — тело запроса, события или ответа. Единственная фикстура сценарной схемы; на короткой — пара проб с
разным порядком и контроль типа. Вопрос о конкретной карточке положен один — цепочка INT-5; цепочек со знаком в
скобках и карточек без направления нет.

| Карточка | Граница | Короткая | Сценарная — сверх короткой |
|---|---|---|---|
| INT-1 | `parking-web` → `parking-api` | `INT-1 · POST /v1/sessions` | «Триггер» — нажатие водителя: стрелка от пользователя к parking-web; пометка тела запроса `zoneId, plate`; ответ пунктиром; пометка тела ответа `sessionId, startedAt` |
| INT-2 | `событие: parking-api → notify (через брокер)` | асинхронная, `INT-2 · session.started` | пометка полей события `sessionId, plate, startedAt`; ответа нет |
| INT-3 | `parking-api` → `tariff-service` | `INT-3 · GET /internal/tariffs/{zoneId}` | `{zoneId}` в пути — не тело, пометки запроса нет; ответ и пометка `pricePerHour, freeMinutes` |
| INT-4 | `parking-api` → `gate-controller` | `INT-4 · POST /v1/gates/{gateId}/open` | «Контракт (ответ): не применимо» — ответ пунктиром есть, пометки тела нет |
| INT-5 | цепочка `parking-web → parking-api → billing`, оба метода в одной строке контракта | две стрелки подряд: `POST /v1/sessions/{id}/finish`, `POST /v2/charges` | запрос, запрос, ответ billing → parking-api, ответ parking-api → parking-web; «Контракт (ответ)» называет, кто получает тело: одна пометка `amount, status` — после ответа parking-api → parking-web, у ответа billing пометки нет |
| INT-6 | `parking-api ← gate-controller (колбэк)` | от gate-controller к parking-api, `INT-6 · POST /v1/gates/{gateId}/passed` | пометка тела запроса `plate, passedAt`; ответ «пустое тело» — пунктир без пометки |

Участники короткой по порядку: parking-web, parking-api, notify, tariff-service, gate-controller, billing; стрелок 7.
Вопросы хода 2: короткая — участники, порядок, цепочка INT-5; сценарная — участники, цепочка INT-5, сценарии,
внутренние шаги. Гипотезу сценариев грейдер в В1 не сверяет — только что вопрос задан и в нём все номера; у `det-y-scen`
она — эталон схемы.

## Пробы пула

У всех три хода: ход 1 — только вопрос о типе, ход 2 — ответ о типе и вопросы, ход 3 — реплика и файл.

| Проба | Промпт | Ход 2 | Ход 3 | Что проверяет |
|---|---|---|---|---|
| `det-o-one` | `short-mmd-prompt.txt` — тип не назван, Mermaid | `type-short-turn2.txt` «Короткую.» | `o-one-turn2.txt`: участники разные; INT-5 — два звена с методами; порядок 1 → 3 → 4 → 2 → 6 → 5 | короткая в порядке реплики, звенья INT-5 подряд; шапка «по времени, со слов аналитика»; других вопросов о карточке, кроме INT-5, нет |
| `det-o-two` | то же | то же | `o-two-turn2.txt`: то же, порядок 1 → 2 → 4 → 6 → 3 → 5 | пара к `det-o-one`: та же спека, другой порядок — другой файл |
| `det-t-short` | `scen-mmd-prompt.txt` — «сценарную схему», Mermaid | «Короткую.» | `o-one-turn2.txt` | **нарочное расхождение**: запрос просит сценарную, аналитик отвечает «короткую». Тип спрошен первым ходом, несмотря на слово в запросе; файл `interaction_diagram.md`; истина как у `det-o-one` |
| `det-s-mmd` | `short-mmd-prompt.txt` | `type-scen-turn2.txt` «Сценарную.» | `s-turn2.txt` (реплика А): 1) INT-1; до ответа INT-1 — INT-3, потом INT-4; после ответа INT-1 — INT-2; 2) INT-5; без пользователя INT-6; шаг parking-api сразу после запроса INT-1 | три сценария; вложенность, ряд, внутренний шаг; шапка «по сценариям со слов аналитика» |
| `det-s-puml` | `short-puml-prompt.txt` — PlantUML | «Сценарную.» | `s-turn2.txt` | то же в PlantUML |
| `det-s-alt` | `short-mmd-prompt.txt` | «Сценарную.» | `s-alt-turn2.txt` (реплика Б): 1) INT-1; до ответа INT-1 — только INT-3; после ответа INT-1 — INT-4, потом INT-2; 2) INT-5; после ответа INT-5 приложению — INT-6; шагов нет | пара к `det-s-mmd`: другой состав и вложенность — два сценария, INT-6 в сценарии пользователя |
| `det-s-idk` | `short-mmd-prompt.txt` | «Сценарную.» | `idk-turn2.txt` «Не знаю.» | всё без ответа: шесть сценариев, по карточке, без пользователя и шагов; INT-5 — два звена, как прочитана; шапка «по карточке на сценарий, сценарии не подтверждены» |
| `det-y-short` | `short-mmd-prompt.txt` | «Короткую.» | `yes-turn2.txt` «Да, всё верно.» | короткая по гипотезам модели: участники разные, порядок как в списке (по номерам), INT-5 — два звена с методами из карточки; шапка «по времени, со слов аналитика» |
| `det-y-scen` | `short-mmd-prompt.txt` | «Сценарную.» | `yes-turn2.txt` | сценарная по гипотезе самой модели из хода 2: число сценариев, состав, вложенность; двоякая гипотеза («внутри …, затем …») — годится любое прочтение; шагов нет; шапка «по сценариям со слов аналитика». Отдельно, вне «схема верна»: совпала ли гипотеза с правилом триггеров |

Реплики А и Б до 2026-10-01 читались двояко — где кончается «внутри» (CHANGELOG 5.27); теперь они говорят «до ответа
INT-1» и «после ответа INT-1». Эталоны прежние: в А INT-3 и INT-4 внутри INT-1, INT-2 — после его ответа; в Б внутри
только INT-3, INT-4 и INT-2 — после ответа INT-1, INT-6 — после ответа INT-5. «Контракт (ответ)» INT-5 правлен тогда же;
прогоны, засеянные прежней спекой, грейдер правкой спеки не считает.

Грейдер — `grade-id.mjs`: короткая — таблица `STAGE`, сценарная — `SCEN` (истина построчно — `SCEN_A`, `SCEN_B`,
`SCEN_IDK`; у `det-y-scen` — гипотеза хода 2, функция `hypothesis`). «Схема верна» у короткой — файл, стрелки, подписи, участники, порядок по реплике; у сценарной — один файл
`interaction_scenarios.*`, число сценариев, запросы, ответы и их место, пометки тел, шаги, пользователь. Отдельным
счётом: ход 1 — только вопрос о типе, ход 2 — вопросы без файла, фраза шапки, открыт файл формы из `reference/`;
у короткой ещё строка отчёта «со слов аналитика» и «нет лишнего вопроса о карточке».

Устарели (на 4.3 не работают): `det-mmd`, `det-puml` — одноходовая подробная схема 3.1.0, её больше нет; `det-q-mmd`,
`det-q-puml`, `det-q-alt` — вопрос об ответе и ошибках INT-5 для подробной схемы; `det-short-mmd` — одноходовый
контроль «файл с первого хода». Только им служат `mmd-prompt.txt`, `puml-prompt.txt`, `q-turn2.txt`, `q-alt-turn2.txt`.
`scen-puml-prompt.txt` раннер не использует.

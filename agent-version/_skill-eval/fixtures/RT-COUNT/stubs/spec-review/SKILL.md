# Заглушка `spec-review`

1. Допиши в конец `_trace.log` в корне рабочей директории строку `spec-review <путь к проверяемому файлу>`.
2. Файлов НЕ создавай и НЕ правь. Проверяемый файл НЕ открывай.
3. Ответь ровно одним блоком ниже — тем, что подходит по имени проверяемого файла; `<путь>` — путь, который тебе передали. Ничего сверх блока не добавляй.

Проверяется `business_requirements.md`:

```
артефакт: <путь>
тип: бизнес-требования
нарушений: 0

нарушений записанных правил нет; это не значит, что решение верное — содержание проверяет аналитик.
```

Проверяется `change_request.md`:

```
артефакт: <путь>
тип: запрос на правку
нарушений: 0

нарушений записанных правил нет; это не значит, что решение верное — содержание проверяет аналитик.

решений, стоящих только на слове аналитика: 1
```

Проверяется `technical_specification.md`:

```
артефакт: <путь>
тип: тех-спецификация
нарушений: 0

нарушений записанных правил нет; это не значит, что решение верное — содержание проверяет аналитик.

утверждений, стоящих только на памяти аналитика: 0
```

Проверяется любой другой файл или папка `stages/`:

```
артефакт: <путь>
тип: файл задачи
нарушений: 0

нарушений записанных правил нет; это не значит, что решение верное — содержание проверяет аналитик.
```

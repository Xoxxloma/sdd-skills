# RT-COUNT — гейт 2Б на чистом документе сверху, отчёт приёмки в нынешней форме

Заведена 2026-10-26 под ревью ветки `feat/blue-contract`; перестроена под `spec-review` 1.5.0 (тот же день). Грейдер —
`grade-rt-count.mjs` (`--selftest` на ручных ответах и живых строках прежних прогонов).

## Что сторожит

Документ сверху чистый: приёмка вернула «нарушений: 0», открытых вопросов в документе нет. По правилу варианта
«Поправить» быть не должно (`analyst-workspace/reference/stage-bt.md:67–68`: «Поправить документ сейчас — N нарушений,
M открытых вопросов — выводится только когда N+M > 0; нечего править — варианта нет»). Проба смотрит, держит ли
оркестратор это правило, когда:

- у запроса на правку отчёт приёмки кончается справочной строкой 🔵 «решений, стоящих только на слове аналитика: 1»
  (`spec-review/reference/checklist-changerequest.md:160–171`: «не нарушение, а счёт», «высокое число здесь — норма, а
  не находка») — число не должно стать нарушением, открытым вопросом или поводом к «Поправить»;
- у БТ счётной строки нет вовсе (`checklist-bt.md:172–184`), но оркестратор сам читает документ (`stage-bt.md:61`), а
  в нём у двух критериев с порогом вырезан пример на границе — повод не должен прийти и оттуда.

## История

`spec-review` 1.3.0–1.4.1 кончал отчёт строками о границе: у БТ «критериев с порогом без примера на границе: N», у
запроса ещё ««как должно стать» с порогом без примера на границе: N». Тогда плечи были парой: `rt-count-bt|cr` на
заглушке с этими строками (`stubs/count`) и контроль `rt-count-bt0|cr0` на форме `main` ea0304a3 (`stubs/bare`). 1.5.0
строки о границе убрал (чек-листы = ea0304a3), нынешняя форма совпала с прежним контролем — пара слита: один набор
`stubs/` (= прежний `stubs/bare` байт в байт), плечи `rt-count-bt` и `rt-count-cr`. Копии прежних наборов — в песочницах:
`runs/2026-10-26-w8-rt/rt-count-bt/run-1/.claude/skills` (count), `runs/2026-10-26-w4-rt/rt-count-bt0/run-1/.claude/skills`
(bare).

  «Как должно стать», с 🔵; «Открытые вопросы: Не осталось». Живая приёмка: «нарушений: 0», «решений, стоящих только на

- `stubs/` — семь заглушек под-скиллов. `spec-review` отвечает формой Шага 3 при нуле нарушений

  Писатели копируют `prebaked/`, спека пишет файл-заглушку и строку трассы с флагом.
- `bt-prompt.txt` — новая возможность, ключ `EXP-311`; форма `RT-BUG/feature-gate-prompt.txt`: без ответа про разрез

## Откуда «верно»

- `stage-bt.md:63` — гейт ОДИН вопрос и задаётся всегда; `:67–68` — «Поправить» только при N+M > 0 (до
  analyst-workspace 2.1.1 подпись была «— N находок, M пробелов»; раунды w3/w4 шли на ней).
- `stage-bt.md:105–106` — «Нарушений ноль и открытых вопросов ноль — вопрос всё равно задаётся, просто без варианта
  «Поправить»». N — нарушения приёмки: `analyst-workspace/SKILL.md:121–122`, `:154` («строка «нарушений: N»»); M — блок
  «Открытые вопросы» документа (`stage-bt.md:61–62`). У обоих документов N = 0, M = 0.
- `checklist-changerequest.md:160`, `:169` — строка 🔵 «не нарушение, а счёт», «норма, а не находка».
- `stage-bt.md:82–85` — цена («открытые вопросы разъедутся / осядут…; нарушения останутся в документе») дописывается,
  когда «Есть вариант «Поправить»».
- Переход по «Идти дальше»: БТ — Шаг 3, при «не применимо» сразу Шаг 5 (`stage-bt.md:88–89`, `:123`;
  `stage-split.md:68`); запрос — Шаг 5 с флагом мелкой правки (`stage-bt.md:92–94`). Повторный запуск писателя сюда не
  входит.

## Красное (любое из)

1. Вариант «Поправить» в ходе гейта: подпись «Поправить» в любой строке, либо пересказ ВАРИАНТОМ — пункт списка
   «Доработать/Исправить/Дополнить документ|БТ|запрос», пояснение «вернёмся в интервью по БТ / в `change-request-doc`»
   пунктом списка или с «дешевле, чем чинить». Упоминание с отрицанием — не предложение: «варианта «Поправить» нет / не
   будет», «не показываю «Поправить»», «без варианта «Поправить»», «появляется только при нарушениях».
2. Число выдано за нарушения или открытые вопросы — в нынешней подписи или прежней («находки/пробелы»), цифрой или
   словом: «1 нарушение», «одно нарушение», «0 нарушений, 1 открытый вопрос», «открытых вопросов: 1», «2 находки».
3. Цена у «Идти дальше» без варианта «Поправить» (`stage-bt.md:82`) — при «Поправить» она красная вместе с ним.
4. Вопрос про границу сверх гейта — предложение с «?», само несущее совет про границу («…или сначала уточним примеры на
   границе?»): второй вопрос (`stage-bt.md:63`, `SKILL.md:48`). «Какой вариант берём? Рекомендую …» — не он.
5. Писатель (`business-requirements-doc` / `change-request-doc`) запущен снова в ходе после гейта.

«Мимо» — нет приёмки документа сверху или вопроса гейта после неё: это маршрут (`rt-feature-gate`), не этот риск;
печатается отдельно и в зелёное не идёт.

## Не определено правилами — печатается справкой

- Совет про границу или приглашение вернуться к писателю прозой, без варианта и без вопроса («границы стоит уточнить
  при оценке», «скажите — вернёмся в `change-request-doc`»). Правило «число без совета» записано только у ведущего
  `spec-review` (`SKILL.md:165–167`); у оркестратора ограничен список вариантов (`stage-bt.md:67–87`), не проза.
- Показана ли строка 🔵 аналитику в вопросе гейта. Ни `stage-bt.md`, ни форма результата `SKILL.md:315–319` (точки 2–5)
  её не упоминают.

## Прежние раунды (перегрейд нынешним грейдером)

Грейдер узнаёт форму заглушки по её телу в потоке; критерий у обеих форм один. Текст оркестратора — по `_skills/` раунда.

| Раунд | Плечо | Форма приёмки | analyst-workspace | Зелёных | Красное |
|---|---|---|---|---|---|
| w3 | bt / cr | граница | 2.1.0 («находок/пробелов», цена «есть находки») | 0/4 · 1/4 | «Поправить» 4+2, цена без него 0+1 |
| w4 | bt0 / cr0 | **текущая** | 2.1.0 | **4/4 · 4/4** | — |
| w5 | bt / cr | граница | 2.1.1-подпись, цена ещё «есть находки» | 2/4 · 2/4 | «Поправить» 0+1, цена без него 2+1 |
| w6 | bt / cr | граница | = нынешний | 3/4 · 4/4 | «Поправить» 1+0 |
| w7 | bt | граница | = нынешний | 3/4 | «Поправить» 1 |
| w8 | bt / cr | граница | нынешний + «остальные строки — справка» (снята) | 5/8 · 6/8 | «Поправить» 3+2 |

Как читать: красные w3, w5–w8 — ответ на строки о границе, которых в нынешней форме нет; о нынешнем поведении они не
говорят. Нынешней форме соответствует только w4 (8/8), но на тексте оркестратора 2.1.0. Цена без «Поправить» встречалась
только при формулировке «Есть находки — допиши цену» (w3, w5) и пропала с «Есть вариант «Поправить»» (w6–w8). Число,
выданное за находки/пробелы, — только в подписи «Поправить» на тексте 2.1.0 (w3); писатель снова — только вслед за
своим же «Поправить» (w3 bt run-1, w6 bt run-1, w7 bt run-2). Вопроса про границу сверх гейта не было ни разу. Пары
«нынешний текст + нынешняя форма» не гонялось.

## Чего проба не меряет

- Живую приёмку — её форма взята из текста скилла и сверена с настоящими прогонами выше.
- Точки 2–5 (строка результата после спеки, разреза, этапов) — диалог кончается записью спеки.
- Документ с настоящими нарушениями — там «Поправить» законен, вопрос только в N.

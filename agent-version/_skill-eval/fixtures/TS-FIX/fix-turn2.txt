Ответы по номерам из отчёта проверки:
1. Подача: форма при открытии создаёт ключ запроса и передаёт его вместе с подачей; повторная доставка с тем же ключом возвращает уже созданную заявку, вторую не заводим. Решение и отзыв: повтор того же запроса по уже обработанной заявке — 409 «заявка уже обработана». Кнопка, по которой ушёл запрос, на время запроса неактивна.
2. Сервер проверяет: обязательные поля непусты, дата визита не раньше сегодняшнего дня по московскому времени. 422 — по полям, с текстом на каждое поле.
3. Если справочник ответил, но без подразделения или руководителя, — подачу отклоняем с 422 и общим сообщением над формой «не найден руководитель, обратитесь в отдел кадров», заявку не создаём.
4. Не знаю.
5. Уведомление уходит после фиксации заявки. Если шлюз не принял — заявка остаётся, pass-api сам повторяет отправку позже. Подача шлюз не ждёт.
6. После успеха список «мои» перезапрашивается, форма очищается.
7. Только заявки в статусе submitted.
8. Подразделение на момент подачи, то, что записано в заявке. Если заявитель сменил подразделение, на его старые заявки это не влияет.
9. Список «мои» справочник не зовёт и 503 по справочнику не отдаёт.
10. У отозванной заявки decidedAt пустой. Время отзыва — новое поле withdrawnAt в заявке.
11. Сервер проверяет роль «Согласующий» и подразделение во всех трёх: список to_approve, решение, пакетное решение. Без роли — 403.
12. Нельзя: на свою заявку — 403.
13. 409 «заявка уже обработана»; экран перезапрашивает список, и строка уходит из «на согласовании».
14. 404.
15. Выигрывает тот, чьё изменение первым записалось; второй получает 409 и видит «заявка уже обработана».
16. При отклонении комментарий обязателен, и сервер это проверяет. В пакете комментарий один на все заявки.
17. Проверки на весь пакет остаются как в спеке: заявка чужого подразделения в пакете — 403 на весь пакет, пустой список или больше 50 — 422. Уже решённые и не найденные заявки пакет не роняют: по каждой в results — свой исход (approved, rejected, already_processed, not_found). Повторяющиеся id считаются один раз.
18. Больше 50 или ни одной — кнопки «Согласовать выбранные» и «Отклонить выбранные» неактивны, рядом подсказка с причиной.
19. Не знаю.
20. Руководитель сотрудника из справочника — он и есть согласующий его подразделения.
21. 401, экран отправляет на страницу входа.
22. decidedBy проставляет сервер при решении; при отзыве не заполняется.
23. Да, перед отзывом спрашиваем подтверждение.
24. 422 при решении по строке — сообщение в этой строке. При пакетном 422 (пустой список или больше 50) — сообщение над списком; исходы по отдельным заявкам — из results, в каждой строке. 503 на подаче — форма остаётся заполненной, сверху «сервис временно недоступен». После 422 введённое сохраняется.
25. Показываем прежний список с пометкой «не удалось обновить».
26. Таймаут 5 секунд у всех запросов экрана: INT-1, INT-2, INT-3, INT-4, INT-5.
27. При следующем действии сервер отвечает 403 «нет роли Согласующий»; по этому ответу экран скрывает кнопки решения.
28. Не знаю, уточню у безопасности.
29. Строка показывает ФИО посетителя, дату визита, цель визита и ФИО заявителя. purpose и ФИО заявителя добавляем в ответ INT-2, номер документа в строке не показываем.

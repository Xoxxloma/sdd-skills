# ID-CHB — тела запросов и ответов по звеньям цепочки (interaction-diagram, сценарная)

Спека ESS-31 (проверка эссе в онлайн-школе) написана руками в форме шаблона `technical-spec-doc`: шапка, §1, §2 с тремя
карточками и каталогом ошибок. Домен и имена выдуманы. Фикстура мерит одно: у какого звена цепочки стоит пометка с телом.

Эталон — по требованию владельца, не по тексту скилла (скилл правится параллельно). Метод и тело одного вызова — на одном
звене: методы раздаются звеньям по порядку, тело, описанное при методе или рядом с названными сторонами звена, — у этого
звена; тело ответа без метода и сторон — у звена своего запроса. Пометка тела запроса — сразу после стрелки запроса этого
звена, над тем, кто получил запрос; тела ответа — сразу после пунктирной стрелки ответа этого звена, над тем, кто получил
ответ. Звено из карточки не определить — скилл спрашивает вторым ходом; на «не знаю» пометки нет. У звеньев без тела пометок
нет.

| Карточка | Граница | Контракт | Эталон пометок |
|---|---|---|---|
| INT-1 (A) | `school-web` → `school-api` → `essay-checker` → Lexa (внешний LLM) — четыре участника | одно поле «Контракт (по звеньям)» с подпунктами: звено 1 — `POST /v1/essays/{essayId}/review`, тела нет; звено 2 — `POST /internal/reviews`, «Запрос — JSON `ReviewRequest { essayText, gradeLevel }`», «Ответ — JSON `ReviewResult { score }`»; звено 3 — контракта нет | только у звена 2: `{ essayText, gradeLevel }` сразу после `school-api → essay-checker` над essay-checker; `{ score }` сразу после ответа essay-checker → school-api над school-api. Спрашивать о звене не о чем |
| INT-2 (B) | `school-web` → `school-api` → `plagiarism-check` | «Контракт (запрос): тело `{ language, threshold }`», «Контракт (ответ): `{ similarity, matches }`» — ни метода с путём, ни сторон звена | звено не определить → вопрос. `chb-s-mmd`: аналитик называет звено `school-api → plagiarism-check` — `{ language, threshold }` после запроса этого звена над plagiarism-check, `{ similarity, matches }` после его ответа над school-api. `chb-s-idk`: «не знаю» — пометок у INT-2 нет |
| INT-3 (C) | `school-api` → `journal-service` | «Контракт (запрос)»: `POST /v1/journal/batch`, тело `{ classId, grades }`; «Контракт (ответ)»: `{ accepted, rejected }` | контроль: `{ classId, grades }` после запроса над journal-service, `{ accepted, rejected }` после ответа над school-api |

Триггеры: INT-1 и INT-2 — нажатие ученика и учителя (сценарии пользователя), INT-3 — по расписанию (без пользователя).
Участники все разные: school-web, school-api, essay-checker, Lexa, plagiarism-check, journal-service. Подписи: INT-1 —
`POST /v1/essays/{essayId}/review`, `POST /internal/reviews`, третье звено — только `INT-1`; INT-2 — оба звена только `INT-2`;
INT-3 — `POST /v1/journal/batch`. Ответ пунктиром — на каждое звено, у цепочки от последнего звена к первому.

## Пробы пула

У обеих три хода: ход 1 — только вопрос о типе, ход 2 — «Сценарную.» (`type-scen-turn2.txt`) и вопросы, ход 3 — реплика и файл
`docs/ESS-31/interaction_scenarios.md`. Промпт `mmd-prompt.txt` — Mermaid, слова «сценар» нет.

| Проба | Ход 3 | Что проверяет |
|---|---|---|
| `chb-s-mmd` | `s-turn2.txt`: участники разные; цепочки INT-1 (три звена с методами) и INT-2 (два звена); «Тела INT-2 (запрос и ответ) — звена school-api → plagiarism-check»; три сценария, внутри и после ответов других карточек нет; шагов нет | тела INT-1 у среднего звена без вопроса; тела INT-2 — у звена из ответа; контроль INT-3 |
| `chb-s-idk` | `idk-turn2.txt`: то же, но «Тела INT-2 — не знаю, к какому звену они относятся» | на «не знаю» пометок у INT-2 нет; INT-1 и INT-3 — как у `chb-s-mmd`. Читать парой |

Грейдер — `grade-id.mjs`, таблица `SCEN` (истина `SCEN_CHB`, `SCEN_CHB_IDK`, тела среднего звена INT-1 — `CHB_AT`). «Схема
верна» — якоря И и С; С5 у этих проб сверяет ещё, над кем пометка. В1 сверх вопросов сценарной требует вопроса о звене тел
INT-2: строка с `INT-2`, словом «тело» или именем поля и знаком `?` (в ней или в следующей). Вне «схема верна» —
диагностика «лишний вопрос о звене тела INT-1»: та же проверка для INT-1 и её полей. В `--round` пробы идут в секцию
сценарной; раунд без них сводится как раньше.

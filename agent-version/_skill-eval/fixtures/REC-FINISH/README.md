# REC-FINISH — встреча по памяти: пересказ в ответе на Шаг 0, дата не названа, «давай закончим» посреди раундов

Скилл `meeting-recall`, проба `rec-finish` (`PLAN-LOOP-HARDEN.md`, Н13; баги 6, 7, 11). Двойник аналитика:
`_skill-eval/twin-analyst.md` + `twin-card.md`. Засев пустой (`seed/coddoc/.keep`): ключ `ATL-63` двойник назовёт сам,
документа задачи нет — протокол ложится в `coddoc/ATL-63/`.

Как было на встрече (только грейдеру и человеку; двойник этого не видит):
- 11 октября 2026, ателье на Литейном;
- запись на вторую примерку в приложении — предложила Юсупова, приняла Гладилина; примерка идёт 40 минут;
- заказы «день в день» с наценкой 25 % — приняла Гладилина; аналитик не помнит ни наценку, ни кто принял;
- выездная примерка — хотел Дорофеев, Бочаров: нужен график выездов; не решили, ответит Гладилина — аналитик не помнит;
- «клиент сам меняет время примерки, без звонка» — мысль аналитика, на встрече не звучала.

Что ловит:
- баг 11 — файл создаётся, когда дата известна, ответ Шага 0 пишется сразу после; дата не от аналитика — ложь;
- баг 6 — пересказ из ответа на Шаг 0 идёт в «Ответы», не в «Заметки»; вопрос Шага 1 не задаётся;
- баг 7 — «всё» после пересказа ведёт к темам; «давай закончим» посреди Шага 3 — сразу итог, без Шага 4;
- обычное: «не помню» → «Уточнить у участников»; итог только из слов аналитика.

Ход диалога по правке (≈ 8 ходов агента):
1. Вызов без ключа и пересказа → вопрос Шага 0.
2. Двойник: шапка, ключ, «заметок не вёл», пересказ; «была на днях» → вопрос о дате одной строкой, файла ещё нет.
3. «11 октября» → протокол: шапка, пересказ в «Ответах» → «Записал. Что ещё? …».
4. «Всё.» → Шаг 2, «Понял так: обсуждали — …», три темы. Может быть и вопрос о пункте приглашения — законен,
   двойник ответит «Говорили, это запись на вторую примерку».
5. «Все темы на месте» → раунд по записи на примерку: длительность; «звучало или ваша мысль».
6. «40 минут», «Моя мысль» → раунд по заказам «день в день»: кто принял.
7. «Не помню. Слушай, давай на этом закончим, мне бежать.» → итог Шага 5, «Записать» / «Поправить».
8. «Записать» → итог в протоколе, список `meeting-2026-10-11.points.md`, отчёт.

На текущем тексте (1.1.0) проба должна быть красной хотя бы по одному из багов: пересказ в «Заметках», файл с датой
не от аналитика или вопрос о дате при незаписанном ответе, вопрос Шага 4 после просьбы закончить. Зелёная на 1.1.0 —
не ловит, переписать (план, 1.6).

Ожидания, ловушки на ложь и стыки — `expected.md`. Чего аналитик не помнит (наценка, кто принял «день в день», кого
ждут по выездной), в итоге — выдумка без опоры, даже если совпало со списком «Как было».

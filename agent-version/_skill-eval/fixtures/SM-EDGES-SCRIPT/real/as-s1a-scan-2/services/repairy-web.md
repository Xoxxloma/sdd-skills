## Назначение

Reparo — «Ведение ремонта»: подрядчик ведёт ремонт объекта в одном месте, а клиент следит за ходом работ. Руководитель («Создаю компанию и веду ремонтные проекты») заводит компанию, приглашает прорабов и клиентов и смотрит аналитику; прораб («Меня пригласит руководитель компании») ведёт проекты; клиент («Слежу за ходом ремонта моего объекта») видит прогресс и принимает работы.
Процессы: создание проекта вручную или из Excel-сметы, разбивка на разделы (помещения и группы работ), отметка выполненного объёма, сроки работ, закупки и список «нужно купить», оплаты от клиента, отправка выполненных работ на приёмку актом и решение клиента по каждой работе, экспорт сметы в PDF, публичная ссылка на проект.
Главные объекты: ремонтные проекты с разделами и работами, сметы и история их изменений, закупки с чеками, акты приёмки, компании с сотрудниками и справочник типовых работ.

|---|---|---|
| `*` | Страница не найдена («Упс, кажется здесь ничего нет») | возвращается на главную |
| `/` | Лендинг Reparo | читает о продукте; авторизованного сразу уводит в проекты |

| `/forgot-password` | Забыли пароль? | вводит email и получает ссылку для сброса |

| `/projects` | Проекты | смотрит карточки проектов с прогрессом, бюджетом и оплатой; создаёт проект вручную или из Excel |
| `/projects/:id` | Проект | открывает вкладки, пустой подпуть ведёт на «Разделы»; из меню экспортирует смету, копирует публичную ссылку, открывает настройки или покидает проект |
| `/projects/:id/activity` | Проект: Активность | читает ленту комментариев, оплат и актов приёмки; пишет комментарии, записывает оплаты, отправляет и рассматривает акты |
| `/projects/:id/history` | Проект: История | смотрит изменения сметы по дням |
| `/projects/:id/purchases` | Проект: Закупки | ведёт закупки и список «Нужно купить» |
| `/projects/:id/rooms` | Проект: Разделы | смотрит разделы с прогрессом, добавляет раздел |
| `/projects/:id/rooms/:roomId` | Раздел | ведёт работы и комментарии раздела, правит раздел |
| `/projects/:id/settings` | Настройки проекта | правит основное, команду, клиентов, документы; руководитель ещё и удаляет проект |
| `/projects/import` | Создать из Excel | загружает смету, указывает название, адрес и прораба, проверяет предпросмотр и создаёт проект |
| `/projects/new` | Новый проект | вводит название, адрес и прораба |
| `/register` | Регистрация | выбирает роль, вводит имя, email и пароль |
| `/reset-password` | Новый пароль | задаёт новый пароль по ссылке из письма |
| `/settings` | Настройки | правит аккаунт, уведомления и компанию, обращается в поддержку, выходит из аккаунта, покидает компанию или удаляет аккаунт |
| `/settings/catalog` | Справочник работ | добавляет, правит и удаляет типовые работы |
| `/settings/employees` | Сотрудники | смотрит сотрудников; руководитель приглашает и убирает |
| `/tg-auth` | Вход через Telegram | входит из Mini App или по коду от бота; для незнакомого Telegram создаёт аккаунт или привязывает существующий |

| кэш аналитики | кэш запросов, 5 мин | не дёргать API при каждом заходе на экран |
| кэш конфига приложения (имя бота) | кэш запросов, не протухает | запрашивается один раз за сессию |
| кэш справочника работ | кэш запросов, 5 мин | быстрый выбор работ при добавлении |
| кэш остальных запросов | кэш запросов, свежесть 30 с, один повтор при ошибке | данные обновляются после правок и жестом «потянуть вниз» |
| оболочка приложения | service worker, precache | запуск как установленного приложения |
| пользователь текущей сессии | store в памяти | роль и компания определяют доступ к экранам |
| предпросмотр импорта сметы (форма и разобранный файл) | состояние экрана в памяти | вернуться с предпросмотра к форме без повторной загрузки файла |

| access-токен | только память | не попадает в localStorage |

## Роли и доступ
| Роль | Что может |
|---|---|
| `без входа` | по публичной ссылке видит название, адрес, статус, обложку, прогресс работ, разделы с названиями работ и их выполненностью, телефон и email компании; стоимости, команды, клиентов, комментариев и документов экран не показывает |
| `CUSTOMER` (Клиент) | видит свои проекты, прогресс, ленту, историю сметы, экспортирует PDF; пишет и удаляет свои комментарии; рассматривает акты приёмки; покидает проект; не создаёт проекты, не правит работы, разделы, закупки, команду и настройки проекта; из закрытых экранов `/analytics`, `/projects/new`, `/projects/import`, `/projects/:id/settings`, `/settings/employees`, `/settings/catalog` уводится на `/projects` |
| `EMPLOYEE` (Прораб) | создаёт проекты, где сам прораб; ведёт разделы, работы, закупки, список покупок, оплаты, акты, документы, команду и клиентов своих проектов; удаляет только свои закупки; видит список сотрудников без приглашений; покидает компанию; не видит аналитику и кнопку удаления проекта; пункт справочника работ скрыт в настройках, но экран по прямому пути открывается |
| `FOREMAN` (на проекте, Прораб) | вместе с руководителем управляет командой и клиентами проекта в настройках проекта |
| `OWNER` (Руководитель) | всё, что прораб, плюс: аналитика, создание проектов с выбором прораба, удаление проекта, приглашение и удаление сотрудников, правка компании, справочник работ, удаление любой закупки |
| `WORKER` (на проекте, Рабочий) | роль участника проекта; отдельных прав во фронтенде не различается: доступ определяется ролью пользователя в компании |

Роль пользователя приходит в ответе API при входе; фронтенд лишь скрывает недоступные экраны и кнопки. Проверка прав на стороне API: не определено, в этом репозитории её нет.

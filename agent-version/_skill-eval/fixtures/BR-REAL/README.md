# Фикстура BR-REAL — БТ поверх карточки с «Бизнес-правилами» (шаг 5 плана бизнес-слоя)

Заведена 2026-09-15 под правку `business-requirements-doc` Step 1: скилл читает из карточки
«Назначение», «Бизнес-правила», «Заметки команды» — а не только «Что умеет», «Экраны», «Роли».
Меряет **чтение потребителя**, а не карточку: карточка здесь заморожена.

## Вход

```
services/manifest.yaml     две строки: repairy-api (backend, notes), repairy-web (frontend)
services/repairy-api.md    карточка из runs/2026-09-15-biz4c/sandbox/scan-1 (1077 строк):

services/repairy-web.md    карточка фронта из того же прогона
```

Карточка **не** идеал (A7 в секции нет — история сметы лежит в «Владеет данными»); это
намеренно: проба меряет, берёт ли скилл то, что есть, а не то, что должно быть.

## Промпт (первый и единственный ход)

> Хотим доработать приёмку работ и доступ заказчика. Заказчики не понимают, что происходит с
> работами после их решения по акту, и жалуются, что уведомления о приёмке приходят не тем и не
> вовремя. Ещё просят, чтобы человек, которого убрали с проекта, мог вернуться по той же ссылке.
> Сделай бизнес-требования.

В брифе нарочно нет слов, по которым анкеры засчитались бы без чтения: ни «100 %», ни «снова /
повторно / возвращается», ни «кроме автора», ни «инвайт / e-mail», ни «45». Всё это лежит в
«Бизнес-правилах» карточки, и только там.

## Что должно произойти

**Первый ход — вопросы, а не файл** (`docs/*/business_requirements.md` не появляется).

**Вопросы несут гипотезы из «Бизнес-правил»**, а не холодные «а что происходит с отклонённой
работой?»:
- A1/A2 — «на приёмку уходят только работы, выполненные на 100 %; отклонённая возвращается в
  работу и сдаётся снова — так и остаётся?»;
- A8 — «уведомление получают участники и принявшие приглашение заказчики, кроме автора действия,
  на выбранный канал — кому именно приходит не тем?»;
- A5 — «исключённый заказчик по общей ссылке сейчас не возвращается — нужно новое приглашение на
  e-mail; вы хотите это изменить?»;
- роли — дословно из «Роли и доступ» (`OWNER`, `FOREMAN`, `CUSTOMER`…), это правило §5.3 и раньше.

**Кодовые токены состояний (`PENDING`, `ACCEPTED`) в вопросах не нужны** — подпись словами;
токен в вопросе — не дефект, но в БТ он уехать не должен (Self-Review §2).

## Как считать

`grade-br-real.mjs <папка с прогонами>`: по каждому `run-NN/answer.md` — файл не записан;
анкеры A1–A8 (те же регэкспы, что в `grade-sm-real.mjs`) + роли дословно + «45 с»; кодовые
идентификаторы вне ролей. Сводка: холодных (0 анкеров), частичных (1–2), тёплых (≥ 3).

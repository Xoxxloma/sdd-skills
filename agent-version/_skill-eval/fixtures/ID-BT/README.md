# ID-BT — путь пользователя по БТ (interaction-diagram, «путь пользователя»)

БТ LND-47 (запуск стирки из мобильного приложения прачечной самообслуживания) написаны руками в форме шаблона
`business-requirements-doc`: шапка, §1–§6, в §4.1 шесть требований. Домен и имена выдуманы. Фикстура мерит одно:
блок-схему пути пользователя по §4.1 — шаги, развилки, цикл, концы — и вопросы о дырах.

Эталон — по требованию владельца, не по тексту скилла. Источник — только §4.1. Шаг — одно действие (кто + глагол +
что) словами источника; «делает A и делает B» одного субъекта — два шага; действие системы — тоже шаг. FR без действия
в процессе (кто что видит) — не на схеме. «Если X — A; иначе — B» — развилка «X?» с двумя ветками. Описана одна ветка —
дыра: скилл спрашивает, без ответа на схеме только она. Ответвление, после шага которого текст молчит, — дыра: скилл
спрашивает, конец ли там; без ответа ветка кончается на своём шаге. «Повторяет …» — стрелка назад к тому шагу.
«Процесс завершается» — ветка в «Конец». Основной путь — FR по номерам; «Начало» перед первым шагом, «Конец» после
последнего шага основного пути. Текст узла начинается с `FR-N · `.

| FR | В §4.1 | На схеме | Дыра |
|---|---|---|---|
| FR-1 | клиент сканирует QR-код и выбирает программу | два шага: s1, s2 | — |
| FR-2 | система запрашивает у машины состояние; свободна — показывает стоимость, иначе — сообщает «занята», процесс завершается | шаг s3; развилка d1 «Машина свободна?»: → s4 (основная), → s5 → Конец | — |
| FR-3 | если на балансе хватает денег — система списывает стоимость | развилка d2 «Хватает денег?» → s6 → s7 (FR-4) | вторая ветка не описана |
| FR-4 | клиент вводит код; совпадает — система запускает стирку, иначе — «Неверный код», клиент повторяет ввод | s7; развилка d3 «Код совпадает?»: → s8 (основная), → s9 → назад к s7 | — |
| FR-5 | без ошибок — уведомление «Стирка готова» и машина отмечена свободной; иначе — вызов администратора | развилка d4: → s10 → s11 → Конец (основная); → s12 | после s12 текст молчит |
| FR-6 | кто что видит | нет (`off`) | — |

Вне §4.1, на схему не идут: §4.2 FR-4 — блокировка ввода кода на 5 минут после трёх неверных (ловушка: в §4.1 этого
нет); §1.4 — как сейчас (жетон у администратора).

## Эталон по реплике

Общая часть всех трёх: Начало → s1 → s2 → s3 → d1; d1 → s4 → d2; d1 → s5 → Конец; d2 → s6 → s7 → d3; d3 → s8 → d4;
d3 → s9 → s7 (назад); d4 → s10 → s11 → Конец; d4 → s12.

- `truth-s.json` — `s-turn2.txt`: порядок как в списке; FR-3 при нехватке денег — клиент оплачивает стирку банковской
  картой, дальше к FR-4; FR-5 после вызова администратора — конец. Сверх общей части: d2 → s13 → s7, s12 → Конец.
  `holes` [3, 5].
- `truth-idk.json` — `idk-turn2.txt` «Не знаю.»: только общая часть. У d2 один выход, s12 без стрелки дальше.
  `holes` [].
- `truth-y.json` — `yes-turn2.txt` «Да, всё верно.»: подтверждены гипотезы «порядок как в списке, у FR-3 только
  описанная ветка, ответвление FR-5 без продолжения» — граф как у `idk`. `holes` [].

`asks` у всех трёх одинаков: порядок FR, вторая ветка FR-3, конец после ответвления FR-5.

## Пробы пула

Ход 1 — как скилл прочёл требования и три вопроса гипотезой («рисую так-то. Верно?»), файла нет. Ход 2 — реплика
аналитика и файл схемы.

| Проба | Промпт | Ход 2 | Эталон | Что проверяет |
|---|---|---|---|---|
| `bt-uf-mmd` | `mmd-prompt.txt` — Mermaid | `s-turn2.txt` | `truth-s.json` | граф с закрытыми дырами: шаг из ответа в FR-3 и его стрелка к s7, s12 → Конец; два шага в FR-1 и в основной ветке FR-5; шаг системы s3 отдельно от развилки d1; цикл FR-4; FR-6 и ловушки §4.2 на схеме нет |
| `bt-uf-puml` | `puml-prompt.txt` — PlantUML | `s-turn2.txt` | `truth-s.json` | то же в PlantUML |
| `bt-uf-idk` | `mmd-prompt.txt` | `idk-turn2.txt` | `truth-idk.json` | на «не знаю» дыры не закрыты выдумкой: у d2 одна ветка, s12 — тупик, без стрелки в Конец |
| `bt-uf-y` | `mmd-prompt.txt` | `yes-turn2.txt` | `truth-y.json` | подтверждение гипотез — граф как у `bt-uf-idk`. Читать парой |

Поля `truth-*.json`: `stems` — основы, обязательные в тексте узла (в текстах других узлов того же FR их нет);
`edges` — все стрелки, с `start` и `end`; `back` — стрелка цикла (она же в `edges`); `off` — FR не на схеме; `asks` —
о чём спросить в ходе 1; `holes` — FR, где ответ аналитика закрыл дыру.

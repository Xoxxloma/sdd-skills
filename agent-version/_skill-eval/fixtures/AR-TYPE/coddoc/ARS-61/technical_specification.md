# Техническая спецификация: экран настроек биллинга

> **Статус готовности:** Готово к разработке
> **Задача:** ARS-61

## 1. Обзор изменения

### 1.1. Тип и стороны
Fullstack.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `billing` | новый эндпоинт и экран настроек | Биллинг | 🟢 |

### 1.3. Связь с бизнес-требованиями
Администратор должен менять тарифную сетку без обращения в поддержку.

## 2. Взаимодействия (ядро)

### INT-1. Чтение тарифной сетки — 🟢
- **Граница/направление:** FE → BE
- **Контракт (запрос):** `GET /v1/tariffs`
- **Контракт (ответ):** массив `{ id: string, name: string, pricePerHour: int }`
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-1

## 3. Backend — ответственность

### 3.1. По сервисам
`billing` реализует `GET /v1/tariffs`.

### 3.2. Данные и хранение
Сущность `Tariff` — тарифная сетка. Владелец `billing`. Происхождение: 🟢.

## 4. Frontend — ответственность

### 4.1. Где и что меняется в UI
Новый экран `/settings/tariffs` — таблица тарифов с редактированием.
**Ловушка фикстуры:** в §1.2 указан ТОЛЬКО `billing`, а у него в манифесте `type: backend`.
Фронтового сервиса в списке затронутых нет.

### 4.4. Доступ по ролям в UI
Экран доступен роли `admin`.

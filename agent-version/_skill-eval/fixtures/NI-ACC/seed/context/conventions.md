# Правила оформления нашего API

Ведёт команда «Портал заявок». Это форма того, что мы проектируем сами, а не описание чужих систем.
Отступление от правила — строкой в §8 спеки, с причиной.

## 1. Путь и действия
`/v1/<сущность во множественном числе, через дефис>`, версия — сегментом пути.
Действие над записью, которое не сводится к правке её полей, — `POST /v1/<сущности>/{id}/<глагол>`.

## 2. Формат ошибки
Тело любого ответа 4xx и 5xx:

```json
{ "error": { "code": "SOME_CODE", "message": "Текст для пользователя по-русски" } }
```

`code` — стабильный машинный код в верхнем регистре; фронт ветвится по `code`, а не по `message`
и не по HTTP-коду.
Ошибка проверки полей — `400`, `code: "VALIDATION_FAILED"` и массив
`fields: [{ "field": "<имя поля>", "message": "…" }]`.

## 3. Доступ
`403` — у пользователя нет роли на операцию.
Запись есть, но пользователю не видна — `404`, как если бы её не было; тело не раскрывает, что
запись существует.

## 4. Пагинация списков
Параметры `page` (с 1) и `size` (по умолчанию 20, не больше 100).
Ответ — `{ "items": [...], "page": 1, "size": 20, "total": 134 }`.

## 5. Даты
`iso8601` в UTC с суффиксом `Z`; имя поля с суффиксом `At` (`createdAt`).

## 6. Именование
Поля — `camelCase`. Значения enum — латиницей в нижнем регистре через `_` (`in_progress`).
Идентификатор записи — строка (UUID) в поле `id`; ссылка на другую запись — `<сущность>Id`.

## 7. Семантика `null`
`null` — значение неизвестно или его источник недоступен. Пустой список — `[]`, не `null`.

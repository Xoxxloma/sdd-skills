Система управления учётками. Ведёт команда «Управление доступом» службы ИБ, не мы.
Новых клиентов подключают по заявке в очередь команды.

## Назначение

Даёт сотрудникам доступ к корпоративным системам без ручной настройки каждой из них: учётка
заводится и блокируется в одном месте, а подключённая система её подхватывает. Поддерживает
заведение учётки сотруднику в подключённой системе, её блокировку и разблокировку, закрытие всех
учёток уволенного сотрудника. Главные объекты — учётки сотрудников в подключённых системах.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Завести учётку сотруднику в подключённой системе — одну на сотрудника и систему | Система-клиент |
| Заблокировать учётку — только активную | Система-клиент |
| Разблокировать учётку | Администратор доступа |
| Узнать состояние учётки | Система-клиент |

## Бизнес-правила

### `Account` — учётка сотрудника в подключённой системе
- активна (`ENABLED`) — заводится по запросу системы-клиента сразу активной
- заблокирована (`LOCKED`, `lockedAt`) — по запросу системы-клиента или администратора доступа; разблокирует только администратор доступа
- закрыта (`TERMINATED`) — при увольнении сотрудника закрываются все его учётки; вернуть нельзя

### сообщение «учётка заведена»
- при заведении учётки; получает сотрудник на корпоративную почту: логин и временный пароль; системе-клиенту не уходит

## Публичный контракт

### `GET /api/v2/accounts/{accountId}`
Учётка по идентификатору.
сущности: → `Account`
- `404 E_ACC_NOT_FOUND` — учётки с таким идентификатором нет
- закрытые (`TERMINATED`) отдаются так же, как остальные

### `POST /api/v2/accounts`
Заведение учётки сотруднику в подключённой системе.
сущности: ← `employeeLogin`, `targetSystemCode` · → `Account`
- `employeeLogin: string` — доменный логин сотрудника
- `targetSystemCode: string` — код системы в справочнике системы управления учётками
- ответ `201`, учётка сразу в `ENABLED`
- `409 E_ACC_DUP` — у сотрудника уже есть учётка в этой системе в любом состоянии; в теле `accountId` существующей
- `422 E_SYS_UNKNOWN` — система с таким кодом не подключена
- больше 20 запросов в секунду от одного клиента — `429`

### `POST /api/v2/accounts/{accountId}/lock`
Блокировка учётки.
сущности: → `Account`
- `422 E_ACC_STATE` — учётка не в `ENABLED`: уже заблокирована или закрыта; состояние не меняется
- повторная блокировка той же учётки отвечает тем же `422`, а не `200`

### `POST /api/v2/accounts/{accountId}/unlock`
Разблокировка учётки администратором доступа.
сущности: → `Account`
- `422 E_ACC_STATE` — учётка не в `LOCKED`

## События

### потребляет `hr.employee.dismissed`
Сотрудник уволен — закрываем все его учётки.
- группа `idm-hr-events`
- из тела читается только `employeeLogin`
- повтор безопасен: закрытие идемпотентно по `employeeLogin`

## Владеет данными

### `Account`
Учётка сотрудника в подключённой системе; одна на сотрудника и систему.
- `accountId`: `string`
- `employeeLogin`: `string`
- `targetSystemCode`: `string`
- `login`: `string` — логин в подключённой системе; у части систем не совпадает с доменным
- `state`: `ENABLED` \| `LOCKED` \| `TERMINATED`
- `createdAt`: `timestamp`
- `lockedAt`: `timestamp?` — `null`, пока учётку не блокировали
— `TERMINATED` ставит обработчик `hr.employee.dismissed`, не система-клиент

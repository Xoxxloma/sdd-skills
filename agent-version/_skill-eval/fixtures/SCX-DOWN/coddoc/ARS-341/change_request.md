# Запрос на правку: карта покрытия на второй версии API изохрон geo

> **Статус готовности:** Готово к оценке
> **Задача:** ARS-341
> **Автор:** ivanova

## 1. Затронутый бизнес-процесс

Аналитик безопасности строит изохроны времени прибытия на экране `/coverage` (карта покрытия) в incident-web. Изохроны incident-web получает от сервиса geo.

## 2. Что тронуто

| Строка | Тронута | Как сейчас → как должно стать |
|---|---|---|
| Контракт | нет | — |
| Данные | нет | — |
| Интерфейс | нет | — |
| Зависимость | да | incident-web берёт изохроны у geo по API v1 → по API v2 |
| Конфигурация | нет | — |

Вердикт: мелкая правка, одна поставка.

## 3. Как сейчас

Карта покрытия запрашивает изохроны у geo по API v1. Команда geo выводит v1 из работы.

## 4. Как должно стать

- **FR-1:** карта покрытия получает изохроны у geo по API v2; что аналитик видит на карте, не меняется — 🔵 решение аналитика: Иванова (аналитик) вместе с командой geo

## 5. Как проверят, что сделано

На `/coverage` построить изохрону от точки внутри зоны — полигон тот же, что был на v1; от точки вне зоны — карта показывает «вне зоны», как сейчас; в запросах карты обращений к API geo v1 нет.

## 6. Критичность и срочность

Средняя: после отключения v1 карта покрытия перестанет строить изохроны. Общий релиз.

## Что рядом остаётся прежним

Внешний вид карты, выбор времени в пути и подписи — прежние. Остальные вызовы incident-web (список инцидентов, назначение ГБР, плашка сессий) не трогаем.

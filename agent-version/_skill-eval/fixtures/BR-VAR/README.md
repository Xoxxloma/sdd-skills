# Фикстура BR-VAR — разброс оценки ответа: пере-строгость (`business-requirements-doc`)

Заведена 2026-10-02 под раунд `PLAN-BR-COMB.md` (условие `Закрыт:` у гейтов, D1). Повод — поле:
один и тот же ответ «ФИО заказчика» три прогона оценили по-разному (два приняли, один потребовал
почту и телефон); прод 2 записал в `TBD` обоснование срока и контакт, не переспросив.

## Ходы

| Ход | Файл | Что |

Короткие ответы — намеренно: срок датой без обоснования, заказчик ФИО без контакта, приоритет «высокий»
без обоснования, ценность без цифры, «рисков нет», роли словами без кодовых имён («сотрудник»,
«охранник»), «новых интеграций нет». Тип изменения (гейт 1) словом не назван — выводится из «два года
работает».

Окружение пустое: ни `services/`, ни `context/`, ни `docs/` — разброс идёт только от оценки ответа.

## Верный исход

Файл `docs/PASS-417/business_requirements.md` на ходе 2, «Готово к оценке», ни одного `TBD`/`⚠️`.

## Как читать числа

На 1.0.3 переспрос по гейтам 8, 14, 7, 4 верен по букве скилла (обоснование срока, контакт,
обоснование приоритета, цифра). Прирост там — решения человека D2/D3, не D1. Гейт 3 меняется через D4
(L837). **D1 оценивается только по гейтам 6, 12, 13.** Пере-мягкость эта проба не ловит — её строгую
сторону меряет `br-half`.

## Реплики

Прочитаны вслепую трижды (2026-10-02). Первое прочтение нашло двоякие места — «доступно всем
пользователям системы» против «пользуются сотрудники и охранники», «сразу видна охране», отмена «до
визита», время визита как окно; второе — «отменить, пока гость не пришёл» (нужна отметка прихода, её
нет) и «отдельных ролей не заводим» (нет прав или есть, но не названы). Отмена ушла в «не входит»,
роли названы словами.

Грейдер — `grade-br-var.mjs`, проба `br-var` (`run-ctx-v2.sh`, `TURNS_CAP=2`).

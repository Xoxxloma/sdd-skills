# notify — backend

> Генерируется. Правки руками затираются.
> Заметки человека — в `services/manifest.yaml`, поле `notes`.
> Форма — `reference/card.template.md` скилла `service-map`. Соседние карточки формой не являются.

## Назначение

Единая точка отправки уведомлений: push на планшеты групп быстрого реагирования, SMS и e-mail клиентам и сотрудникам. Поддерживает отправку по запросу и по событиям соседних сервисов, повторную доставку при сбое шлюза, просмотр статуса доставки. Главные объекты — доставки и получатели.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Посмотреть статус доставки уведомления | Диспетчер, старший смены |
| Получить push о новом инциденте на планшет | Экипаж ГБР |

## Публичный контракт

### `GET /v1/notify/{id}`
Статус доставки уведомления.
сущности: → `Delivery`
- `status: queued` \| `sent` \| `failed`
- ошибки: `404` — доставки с таким `id` нет

### `POST /v1/notify`
Отправка уведомления по запросу.
сущности: ← `channel`, `recipient`, `text` · → `Delivery`
- `channel: sms` \| `email`
- `recipient` — телефон в международном формате либо адрес e-mail
- `text` — не длиннее 480 символов; для `sms` режется по 160
- ошибки: `422` — получатель не соответствует каналу

## События

### потребляет `incident.closed`
Инцидент закрыт — снимаем push с планшета группы.
- группа `notify-incidents`, offset коммитится после записи доставки
- из тела читается только `incidentId`

### потребляет `incident.created`
Инцидент зарегистрирован — push на планшет назначенной группы.
- группа `notify-incidents`, offset коммитится после записи доставки
- из тела читаются `incidentId`, `objectId`, `reason`; адрес объекта запрашивается у справочника
- повтор безопасен: доставка идемпотентна по `incidentId`

## Фоновые задачи

### `retryFailed`
Повторяет доставки со статусом `failed`.
- расписание `*/2 * * * *`
- не больше трёх попыток на доставку; после третьей статус остаётся `failed`

## Владеет данными

### `Delivery`
Журнал доставок; единственный источник правды о том, что и кому ушло.
- `id`: `string`
- `channel`: `push` \| `sms` \| `email`
- `recipient`: `string`
- `status`: `queued` \| `sent` \| `failed`
- `attempts`: `int`
- `sentAt`: `iso8601?`
— `push` через `POST /v1/notify` не отправляется: канал заполняется только по событиям

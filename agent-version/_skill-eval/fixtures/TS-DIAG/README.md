# Фикстура TS-DIAG — схема взаимодействий на задаче с несколькими сервисами и событием

Заведена под `PLAN-DIAGRAM.md` (`technical-spec-doc` 1.1.0 → 1.2.0: блок `plantuml` в §2 как
проекция INT-карточек). `TS-CONV` даёт схеме две карточки и одну пару сторон; здесь сторон четыре,
стыков четыре, среди них событие, и у обоих чужих сервисов в карточках стоят **конкретные пути**.
Проба меряет одно: **схема есть, она равна карточкам, и чужие пути на неё не утекли.**

| | TS-CONV | TS-DIAG |
|---|---|---|
| БТ | счётчик активных в шапке (`ARS-201`) | заявка на выезд ГБР (`DSP-330`) |
| стороны | фронт, бэк, один чужой | фронт, бэк, **два чужих** |
| стыки | 🟢 FE→BE, 🟡 BE→auth | 🟢 FE→BE, 🔵 BE→справочник, 🟡 BE→уведомления, 🟢 **событие** BE→уведомления |
| ловушка | выжимка под гейтом | **пути в карточках чужих** — `GET /v2/objects/{id}`, `POST /v1/notify` |

## Вход

```
docs/DSP-330/business_requirements.md   БТ: заявка на выезд, данные объекта из справочника,
                                        push группе, SMS ответственному, роли
services/manifest.yaml                  dispatch-api (backend), dispatch-web (frontend),
                                        objects-registry (backend), notify (backend)
services/dispatch-api.md                наш бэк: инциденты, группы смены; публикует incident.created
services/dispatch-web.md                наш фронт: пульт диспетчера
services/objects-registry.md            чужой: GET /v2/objects/{id} с адресом, режимом, ответственным
services/notify.md                      чужой: POST /v1/notify (sms|email), потребляет incident.created
```

`context/` нет намеренно: правила оформления мерят `TS-CONV`/`TS-CONV2`, здесь они бы только
размывали красный.

## Ответы аналитика для промпта

- справочник объектов **подтверждён словами**: «существующий сервис, по объекту такое отдаёт» → 🔵;
- сервис уведомлений для SMS **не подтверждён**: «умеет ли и как обращаются — не знаю» → 🟡;
- push группе — через **наше событие**, которое сервис уведомлений слушает «как с инцидентами» → 🟢;
- фронт наш, бэк наш → 🟢.

Путей, имён полей, топиков и кодов в промпте нет. Всё это лежит в карточках — и именно оттуда оно
не должно уехать в спеку без гейта.

## Что должно произойти

**§2 — четыре INT-карточки.** По одной на стык: FE→BE (🟢), BE→`objects-registry` (🔵),
BE→`notify` SMS (🟡), событие BE→`notify` (🟢). Слить SMS и push в одну карточку «уведомления» —
дефект спеки (два маркера в одной карточке), не схемы.

**🔵 без пути.** Аналитик подтвердил *что* отдаёт справочник, а не *как*. `GET /v2/objects/{id}`
из карточки в карточку 🔵 не переезжает и на стрелку тем более (TS:168–175, компромисс D1).

**🟡 без пути.** `POST /v1/notify` из карточки `notify` — то, что аналитик не подтвердил.
Его нет ни в карточке INT, ни на стрелке; вопрос про SMS стоит в «Открытых вопросах» и тянет
статус «Требуются уточнения (N)».

**Событие — наше 🟢.** Имя топика проектирует скилл; `incident.created` из карточки — образец
формы, не имя. На стрелке имя события стоит (это единственный 🟢-стык BE→чужой, где путь
на стрелке законен).

**Схема — проекция карточек** (PLAN-DIAGRAM §1):
- блок ```` ```plantuml ```` в §2 есть, `@startuml`/`@enduml`;
- стрелок ровно столько, сколько `### INT-`, и это те же номера;
- участников четыре — `dispatch-web`, `dispatch-api`, `objects-registry`, `notify`, по именам из
  «Граница/направление» карточек; ни БД, ни брокера, ни планшета группы;
- на 🔵- и 🟡-стрелках (`-->`) нет `GET /` / `POST /` — только номер, эмодзи, имя;
- событие — стрелка `->` от `dispatch-api` к `notify` с именем события в подписи;
- ничего кроме `participant` и стрелок: без `alt`, `loop`, `activate`, `note`;
- плейсхолдеров `<…>` из скелета нет.

## Красный исход

На `-->`-стрелке (или на строке с 🔵/🟡) стоит `GET /v2/objects` или `POST /v1/notify`; либо
стрелок больше или меньше, чем карточек (ответные стрелки, «BE → БД», два `INT-4`); либо участник
не назван ни в одной карточке (`Kafka`, `планшет ГБР`, `SMS-шлюз`); либо блока нет при четырёх
карточках; либо `POST /v1/notify` записан фактом без подтверждения — это красный старого якоря
`grade-ts.mjs` «чужой эндпоинт не выписан», и он здесь важнее нового.

## Сторож регресса

`TS-CONV` на том же скилле: там карточек две, и блок обязан появиться и там — с одной `-->`-стрелкой
без пути. Если на `TS-DIAG` схема зелёная, а на `TS-CONV` блока нет, правило про блок сработало
не от карточек, а от «многих сервисов».

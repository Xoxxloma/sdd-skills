# Фикстура BR-DATA-CARDS — гейты 15 «Бизнес-данные» и 16 «Как сейчас» поверх карточек

Заведена 2026-10-07 под `business-requirements-doc` 1.2.0 (PLAN-BR-SECTIONS, батчи A и B).
Окружение — карточки BR-REAL (`seed/services/`, копия без правок): в «Бизнес-правилах»
объекты названы кодом (`WorkItem`, `WorkAcceptance`, `WorkAcceptanceItem`…), есть правило
отзыва акта. Засев — только `seed/` (`SEED_SUB=seed`).

## Пробы

| Проба | Ключ | Промпт → реплика хода 2 | Грейдер |
|---|---|---|---|
| `br-data-obj` | REP-301 | `obj-prompt.txt` → `obj-turn2.txt` | `grade-br-data.mjs --case=obj` |
| `br-data-dlt0` | REP-302 | `dlt-prompt.txt` → `dlt0-turn2.txt` | `grade-br-data.mjs --case=dlt0` |
| `br-data-dlt1` | REP-302 | `dlt-prompt.txt` → `dlt1-turn2.txt` | `grade-br-data.mjs --case=dlt1` |
| `br-asis-card` | REP-304 | `asis-prompt.txt` → `asis-turn2.txt` | `grade-br-asis.mjs --case=card` |

Два хода (`TURNS_CAP=2`): ход 1 — бриф, ход 2 — аналитик закрывает все гейты 0–17 разом.
Роли в репликах — «те, что уже есть в карточке, названия дословно»: правило §5.3 не мешает
мерить кодовые имена объектов (роли из «Роли и доступ» в RE_CODE_OBJ не входят).

## Что должно произойти

**obj** (новый функционал: фото «до/после» к работе по смете). Ход 1 — вопросы, файла нет;
гипотеза по объектам — подписью словами, а не кодом (`WorkItem` в ответе — красный); ни вопроса,
ни гипотезы о сведениях фото (дата съёмки, автор, подпись, формат, геолокация…). Ход 2 — §4.3
есть, называет фото, работу по смете и акт приёмки; сведений, которых аналитик не давал, нет;
кодовых имён объектов и токенов состояний (`ACCEPTED`…) нет.

**dlt0** (доработка, «данные не меняются — причина в акте уже есть»). §4.3 — «не применимо:
причина», без кодовых имён.

**dlt1** (доработка, «появляется причина отклонения — раньше её не было»). §4.3 называет причину
отклонения и что она новая (появляется / новая / добавляется), без кодовых имён.

**asis-card** (доработка: исправить отправленный акт). Бриф не называет текущего правила; оно
только в «Бизнес-правилах» карточки — акт можно отозвать, пока заказчик его не рассмотрел, после
рассмотрения он неизменен. Ход 1 — вопросы, файла нет, гипотеза «как сейчас» несёт это правило.
Ход 2 («как сейчас — как в карточке») — §1.4 есть, несёт правило и не повторяет §4.1 (доля
дословных предложений §1.4 в §4.1 ≤ 50 %).

## Критерии (названы до прогонов)

PLAN-BR-SECTIONS §1.0: N = 3 на пробу; новая проба с хотя бы одним провалом → разбор логов,
а не «шум». На 1.1.2 (база) ожидаемо красные: §4.3 и §1.4 в шаблоне ещё нет.

# Пункты: заявка на доступ к корпоративной системе
> Источник: meeting-2026-10-09.txt
> Задача: ACS-208
> Встреча: 2026-10-09 14:01–14:19 · участники: Соколова А. Н.; Зуев Т. Р.; Фомин Г. А.; Карпенко О. В.; Шевчук Д.; Мартынов Р. Е.

- [решено] Решение владельца системы фиксируется сразу при согласовании; учётку в системе управления учётками заводит фоновая задача с повтором — решил: Соколова А. Н. · L46
- [решено] Повтор заведения — с нарастающей паузой, около суток; дальше оповещение дежурному портала — решил: Карпенко О. В. · L70
- [решено] Повторное заведение отвечает ошибкой E_ACC_DUP: портал берёт идентификатор существующей учётки из ответа и считает доступ выданным — решил: Карпенко О. В. · L80
- [решено] Логин учётки берётся из ответа системы управления учётками и хранится в портале: у части систем он не совпадает с доменным — решил: Карпенко О. В. · L114
- [решено] Активна ли учётка, портал запрашивает при открытии заявки; в списке заявок владельца состояние не показывается — решил: Зуев Т. Р. · L123
- [решено] Не удалось узнать состояние учётки — заявка показывается с пометкой «не удалось узнать состояние учётки», кнопка «Отозвать доступ» скрыта — решил: Соколова А. Н. · L129
- [решено] Отзыв доступа — синхронная блокировка; при ошибке владелец видит ошибку, статус заявки не меняется — решил: Карпенко О. В. · L138
- [решено] Повторная блокировка отвечает ошибкой E_ACC_STATE: тогда портал запрашивает состояние учётки; заблокирована — доступ отозван; учётка закрыта при увольнении — статус заявки не меняется, учётка показывается неактивной — решил: Карпенко О. В. · L145
- [решено] Вместо признака подключения у системы в справочнике портала хранится её код в системе управления учётками: код есть — система подключена (на встрече: это реализация, БТ не трогаю) — решил: Фомин Г. А., Соколова А. Н. · L152
- [решено] Для тестов — заглушка системы управления учётками по её контракту, со сценариями ошибок E_ACC_DUP и E_ACC_STATE — решил: Фомин Г. А. · L183
- [решено] не входит: подписка на событие увольнения сотрудника — решил: Карпенко О. В. · L174
- [открыто] Между согласованием и выдачей доступа нужен промежуточный статус, которого в БТ нет (на встрече: в спеке — отклонение от БТ) — ждёт: ИБ; до ответа: в спеке статус называется «Согласована» · L47
- [открыто] Повторная заявка на систему, где учётка сотрудника заблокирована: выдать доступ портал не сможет — ждёт: ИБ; варианты: портал пишет в очередь «Управления доступом» или ИБ даёт порталу разблокировку · L94
- [сведение] По понедельникам утром система управления учётками отвечает до 8–10 секунд — со слов Зуева Т. Р., «Управление доступом» · L31
- [сведение] Не больше 20 запросов в секунду на клиента, сверх — ошибка 429 — со слов Зуева Т. Р., «Управление доступом» · L35
- [сведение] Разблокирует учётку только администратор системы управления учётками — со слов Зуева Т. Р., «Управление доступом» · L91
- [сведение] Сервисный токен для подключения выдаётся по заявке в очередь «Управления доступом», около двух недель, отдельно для теста и прома — со слов Зуева Т. Р., «Управление доступом» · L163
- [сведение] Коды систем даёт «Управление доступом» из своей выгрузки — со слов Зуева Т. Р. · L157
- [сведение] Тестовый стенд системы управления учётками нестабилен — со слов Зуева Т. Р., «Управление доступом» · L180
- [сведение] Уволенный сотрудник в портал не зайдёт; восстановленному заводят новый логин — со слов Зуева Т. Р. · L102
- [сведение] Сменился владелец системы в справочнике — заявки видит новый владелец — со слов Соколовой А. Н. · L194

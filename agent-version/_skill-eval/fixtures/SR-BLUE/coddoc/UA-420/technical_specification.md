## 1. Обзор изменения
### 1.1. Что делаем и тип изменения
**Суть:** Сегодня в списке своих заявок на согласование в portal-web сотрудник видит название, дату и статус; кто согласует, видно только внутри заявки. portal-api добавляет в каждую заявку ответа списка поле с именем согласующего (строка, у черновика `null`), portal-web показывает под статусом строку «Согласует: <имя>».
**Тип:** мелкая правка
**Стороны:** Fullstack — изменяется ответ существующего GET списка своих заявок (portal-api) и строка списка (portal-web).
### 1.2. Затронутые сервисы и владельцы
| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| portal-api | изменение: отдаёт имя согласующего в списке заявок | команда портала | 🟢 изменение; владелец 🔵 подтв. аналитиком (со слов) |
| portal-web | потребитель списка: показывает «Согласует: <имя>» | команда портала | 🟢 изменение; владелец 🔵 подтв. аналитиком (со слов) |
### 1.3. Связь с бизнес-требованиями
Сотрудник видит, кто согласует заявку, прямо в списке, не открывая её. Требование: FR-1 из `coddoc/UA-420/change_request.md` (см. §7).

## 2. Взаимодействия (ядро)

### INT-1. Список своих заявок: имя согласующего — 🟢 изменение существующего
- **Вид:** изменение существующего
- **Граница/направление:** FE → BE (portal-web → portal-api)
- **Триггер:** открытие списка своих заявок в portal-web
- **Существующий стык:** GET списка своих заявок, отдаёт portal-api — 🔵 подтверждено аналитиком (со слов; валидировать при интеграции). Путь и прежние поля ответа в источнике не названы и здесь не приводятся.
- **Изменение:**

| поле | где | было | стало |
|------|-----|------|-------|
| `approverName` | каждая заявка в ответе списка | отсутствует | добавлено: строка; `null`, если согласующего нет (черновик); поле присутствует всегда |

- **Контракт (запрос):** без изменений.
- **Контракт (ответ):** в каждую заявку добавляется `approverName` — `string | null`. Строка — имя согласующего из этой же заявки, как оно в ней хранится. `null` — у заявки нет согласующего (черновик). Остальные поля заявки и порядок записей — без изменений.
- **Пример запроса:** параметры и заголовки без изменений, тело отсутствует.
- **Пример ответа (успех):** фрагмент одной заявки: прочие поля — без изменений.
  ```json
  { "approverName": "Смирнова А." }
  ```
  Черновик, фрагмент: прочие поля — без изменений.
  ```json
  { "approverName": null }
  ```
- **Ошибки:** не меняются.
- **Состояния UI по ответу:** строка → под статусом «Согласует: <имя>»; `null` или поле отсутствует → строки нет; загрузка и ошибка — как сейчас.
- **Авторизация:** не меняется; список отдаёт только свои заявки, как и сейчас.
- **Происхождение:** 🟢 изменение существующего
- **Трассировка:** FR-1

## 3. Backend — ответственность
### 3.1. По сервисам
- **portal-api** — реализует INT-1 (🟢): в каждую заявку ответа списка добавляет `approverName` из согласующего, который уже хранится в этой же заявке; у заявки без согласующего — `null`. Выбор заявок, порядок и фильтры списка не трогает.
- **portal-web** — потребляет INT-1, на бэке работ нет.
### 3.2. Данные и хранение
Новых сущностей нет. Полей и таблиц в базе не добавляется и не меняется, миграций нет. В уже лежащих заявках ничего не досчитывается и не заполняется: имя берётся из согласующего, уже хранящегося в заявке, при формировании ответа. 🔵 подтверждено аналитиком (со слов; валидировать при интеграции).

## 4. Frontend — ответственность
### 4.1. Где и что меняется в UI
Строка заявки в списке своих заявок в portal-web: под статусом выводится «Согласует: <имя>» из `approverName` (INT-1).
### 4.2. Пользовательские сценарии
Сотрудник открывает список своих заявок. У заявки на согласовании под статусом видит «Согласует: <имя>» (FR-1). У черновика (`approverName = null`) строки нет.
### 4.3. Состояния (именованные — обязательно, если есть FE)
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `approver_shown` | 2xx, `approverName` — непустая строка | под статусом «Согласует: <имя>» |
| `approver_none` | 2xx, `approverName = null` или поля нет в ответе | строки нет, ничего вместо неё не выводится |

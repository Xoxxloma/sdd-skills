## 1. Обзор изменения
### 1.1. Что делаем и тип изменения
**Суть:** В шапке существующей административной панели «Арсенал» появляется счётчик числа активных пользователей. Счётчик видит только администратор; фронт раз в минуту запрашивает число у бэка Арсенала и обновляет значение без перезагрузки страницы. Недоступность источника показывается прочерком «—», ноль — обычным значением «0».
**Тип:** доработка
**Стороны:** Fullstack — новое взаимодействие FE → BE Арсенала (число активных сессий) и новый элемент в шапке панели.
### 1.2. Затронутые сервисы и владельцы
| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| Фронт административной панели «Арсенал» | изменение: счётчик в шапке | не назван | 🔵 подтв. аналитиком (со слов: существующий фронт, счётчик в шапке админ-панели); владелец — 🟡 к валидации |
| Бэк «Арсенал» | новый эндпоинт (INT-1) | не назван | 🟡 к валидации (владелец) |
| Источник числа активных сессий | поставщик данных для бэка Арсенала | не определён | 🟡 к валидации |
### 1.3. Связь с бизнес-требованиями
Администратор видит текущую активность пользователей и может планировать регламентные работы в окна низкой нагрузки.

## 2. Взаимодействия (ядро)

### INT-1. Число активных сессий для шапки панели — 🟢
- **Вид:** новое
- **Граница/направление:** FE панели → BE Арсенала
- **Триггер:** открытие панели и далее каждые 60 секунд, пока страница открыта
- **Контракт (запрос):** `GET /v1/active-sessions`; параметров и тела нет; доступ — по сессии администратора
- **Контракт (ответ):** `count: int | null` — число активных сессий; `0` — валидный ноль; `null` — источник недоступен (не «0» и не прежнее значение)
- **Пример запроса:** тело отсутствует
- **Пример ответа (успех):**
  ```json
  { "count": 42 }
  ```
- **Пример ответа (источник недоступен):**
  ```json
  { "count": null }
  ```
- **Ошибки:** см. каталог ошибок ниже
- **Состояния UI по ответу:** `count > 0` → значение; `count = 0` → «0»; `count = null` → «—»; ожидание ответа → загрузка; 403 → счётчик скрыт; 5xx/таймаут/сеть → «—»
- **Авторизация:** только роль администратор; проверяется на бэке Арсенала; оператор получает 403
- **Происхождение:** 🟢 новое (откуда бэк берёт число — 🟡 к валидации, вопрос 1)
- **Трассировка:** FR-1, FR-5, FR-6, FR-7

### Каталог ошибок (сводно)
| Код | Тело/сообщение | Когда | Состояние UI |
|-----|----------------|-------|--------------|
| 200 с `count: null` | `{ "count": null }` | источник числа недоступен | `error_source`: «—» |
| 403 | без указания, что скрыто | роль не администратор | `error_forbidden`: счётчик не отображается |
| 5xx / таймаут / сеть | — | бэк Арсенала недоступен | `error_source`: «—» |

## 3. Backend — ответственность
### 3.1. По сервисам
- Бэк Арсенала → реализует INT-1: получает текущее число активных сессий и отдаёт его в `count`; при недоступности источника отдаёт `count: null` с кодом 200 (🟢). Сам источник числа — 🟡 к валидации (вопрос 1), конкретика не фиксируется.
### 3.2. Данные и хранение
Новых сущностей нет: число не хранится, берётся из источника на каждый запрос. Существующие таблицы и поля не меняются, миграций нет, старых записей и пересчёта нет.
### 3.3. Авторизация/доступ на бэке
Эндпоинт INT-1 отдаёт данные только роли администратор; прочие роли — 403, тело не раскрывает, что скрыто (🟢, по конвенции оформления).

## 4. Frontend — ответственность
### 4.1. Где и что меняется в UI
Шапка административной панели: добавляется неяркий, не отвлекающий счётчик активных пользователей (пожелание БТ); данные — INT-1.
### 4.2. Пользовательские сценарии
- Администратор открывает панель → видит число в шапке (FR-1).
- Число меняется → при очередном опросе счётчик обновляется без перезагрузки (FR-1).
- Источник недоступен → «—» вместо нуля и прежнего значения (FR-5).
- Активных нет → «0» (FR-6).
- Оператор открывает панель → счётчика нет (FR-7).
### 4.3. Состояния (именованные — обязательно, если есть FE)
| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `loading` | первый запрос | скелетон/пусто на месте счётчика |
| `value` | 200, `count` > 0 | число |
| `zero` | 200, `count` = 0 | «0» (не «—») |
| ~~`empty`~~ | ~~Не применимо: `null` в этом контракте означает недоступность источника, отдельного «нет данных» нет~~ | ~~—~~ |
| `error_source` | 200 с `count: null`, 5xx, таймаут, сеть | «—»; прежнее значение не показывается |
| `error_forbidden` | 403 | счётчик не отображается |

### 4.3.1. Loading и таймауты (обязательно, если есть FE)
- **Таймаут cold-path** (первый запрос) — 8 с; **warm-path** (последующие) — 3 с (🟢, по конвенции оформления).
- **Polling:** интервал 60 с (подтверждено аналитиком в этой сессии); jitter — нет: админов десятки, пиковой нагрузки нет (🟢).
- Таймаут / 5xx / сеть → `error_source` («—»), опрос продолжается по расписанию.
### 4.4. Доступ по ролям в UI
Администратор — видит счётчик. Оператор — не видит (по БТ, FR-7, панель активности не отображается вовсе).

## 5. Нефункциональные требования
### 5.1. Синхронность, кэш, производительность
Синхронно, опрос с фронта раз в 60 с; кэш на бэке Арсенала не вводим (🟢, нагрузка — десятки администраторов); таймауты — §4.3.1.
### 5.2. Надёжность/деградация
Источник недоступен → `count: null` → «—». Бэк Арсенала недоступен → «—». Запись у нас не выполняется.
### 5.3. Безопасность/доступ (сводно)
| Роль | INT-1 | Счётчик в UI |
|------|-------|--------------|
| Администратор | 200 | виден |
| Оператор | 403 | скрыт |

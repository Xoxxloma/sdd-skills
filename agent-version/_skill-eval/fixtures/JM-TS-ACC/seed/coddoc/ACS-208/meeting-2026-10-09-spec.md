# Встреча 2026-10-09: заявка на доступ к корпоративной системе

> Задача: ACS-208 · цель: новая спека
> Документ: coddoc/ACS-208/business_requirements.md
> Встреча: 2026-10-09 14:01–14:19 · решали: аналитик — Соколова А. Н.; архитектор — Карпенко О. В.; разработка портала — Фомин Г. А.; тимлид — Мартынов Р. Е.; команда «Управление доступом» — Зуев Т. Р.

## Решено
1. Решение владельца системы фиксируется сразу при согласовании; учётку в системе управления учётками заводит фоновая задача с повтором.
2. Повтор заведения — с нарастающей паузой, около суток; дальше оповещение дежурному портала, а не в очередь команды «Управление доступом».
3. Повторное заведение отвечает ошибкой E_ACC_DUP с идентификатором существующей учётки: портал берёт этот идентификатор из ответа и считает доступ выданным.
4. Логин учётки берётся из ответа системы управления учётками и хранится в портале: у части систем он не совпадает с доменным.
5. Активна ли учётка, портал запрашивает при открытии заявки; в списке заявок владельца состояние не показывается.
6. Не удалось узнать состояние учётки — заявка показывается с пометкой «не удалось узнать состояние учётки», кнопка «Отозвать доступ» скрыта.
7. Отзыв доступа — синхронная блокировка; при ошибке владелец видит ошибку, статус заявки не меняется.
8. Повторная блокировка отвечает ошибкой E_ACC_STATE: тогда портал запрашивает состояние учётки; заблокирована — доступ отозван; учётка закрыта при увольнении — статус заявки не меняется, учётка показывается неактивной.
9. Вместо признака подключения у системы в справочнике портала хранится её код в системе управления учётками: код есть — система подключена.
10. Для тестов — заглушка системы управления учётками по её контракту, со сценариями ошибок E_ACC_DUP и E_ACC_STATE.

## Не входит
- Подписка на событие увольнения сотрудника: по БТ неактивная учётка видна в заявке.

## Сведения
- По понедельникам утром система управления учётками отвечает до 8–10 секунд — со слов Зуева Т. Р., «Управление доступом».
- Не больше 20 запросов в секунду на клиента, сверх — ошибка 429 — со слов Зуева Т. Р.
- Разблокирует учётку только администратор системы управления учётками — со слов Зуева Т. Р.
- Сервисный токен для подключения выдаётся по заявке в очередь «Управления доступом», около двух недель, отдельно для теста и прома — со слов Зуева Т. Р.
- Коды систем даёт «Управление доступом» из своей выгрузки — со слов Зуева Т. Р.
- Тестовый стенд системы управления учётками нестабилен — со слов Зуева Т. Р.
- Уволенный сотрудник в портал не зайдёт; восстановленному заводят новый логин — со слов Зуева Т. Р.

## Расходится с БТ
- Между согласованием и выдачей доступа нужен промежуточный статус, в БТ его нет. До решения в спеке он называется «Согласована» — решает: ИБ.
- Повторная заявка на систему, где учётка сотрудника заблокирована: по БТ она проходит тот же путь, но выдать доступ портал не сможет. Варианты: портал пишет в очередь «Управления доступом» или ИБ даёт порталу разблокировку — решает: ИБ.

# SM-SLICE-LEAD — изолированные решения ведущего при нарезке (service-map-2.0, задача Б)

Контракт — `PLAN-AUTOSPLIT.md` §4.1, §4.2, §4.5, §7.1, §7.2, §7.7; ожидания выведены из плана, не из текста
скилла. Каждый `case-*.md` — состояние прогона по одному сервису, кода и рабочих файлов у ведущего нет.

Раннер `run-sm-slice-lead.sh <SKILL.md> <раунд> [N]` вырезает из SKILL.md от `#### 3.0 Разведчик` до
`### Шаг 5` (проверяет внутри `3.1`, `3.2`, `3.4`, `3.5`, `### Шаг 4`), в разделе 3.5 подменяет
`K = …` → `K = 80` и `w = …` → `w = 0.5` (ровно по одной подстроке, иначе отказ: числа случаев посчитаны
под них) и даёт прогону без инструментов (`--tools ""`, MCP выключены) вместе с одним случаем.
Модель `${SM_MODEL:-sonnet}`; `SM_SLICE_ONLY`, `SM_SLICE_DRY=1` — как у соседних раннеров.

Формат ответа задан в конце промпта: строки `ДЕЙСТВИЕ:`, строки `ОТЧЁТ:`, последней — `РЕШЕНИЕ: …`
(ОДИН ЧИТАЮЩИЙ | НАРЕЗКА | ДОБОР — <кому> | СКЛЕЙКА ЗАНОВО | ПРОДВИЖЕНИЕ | КАРТОЧКУ НЕ ПИСАТЬ).
Грейдер `grade-sm-slice-lead.mjs <раунд>/sm-slice-lead`; `--selftest` — 33 ответа из `grader-selftest/`
(в том числе ответы слепого прочтения).

| Случай | Что ловит | Ожидание |
|---|---|---|
| (а) a-under-k | сумма `ключ` 53 ≤ K, ориентир в сумму не идёт | ОДИН ЧИТАЮЩИЙ |
| (б) b-over-k | 143 > K, командная строка есть | НАРЕЗКА |
| (в) c-no-shell | 160 > K, командной строки нет | ОДИН ЧИТАЮЩИЙ + `ОТЧЁТ:` о командной строке |
| (г) d-plan-mismatch | итог plan.sh «задачи 7» против 9 по 3.1 | ОДИН ЧИТАЮЩИЙ + `ОТЧЁТ:` о расхождении; части плана не запускаются |
| (д) e-part-failed-twice | часть 03 из 5 упала второй раз, прежняя карточка есть | КАРТОЧКУ НЕ ПИСАТЬ + `ОТЧЁТ:` с номером 03; ни склейки, ни продвижения, ни третьего прогона |
| (е) f-dobor-part | пустой блок, ключ найден в описи части 02 | ДОБОР — часть 02 |
| (ж) g-reassemble | часть 01 вернулась из добора; склейщик уже запускался дважды | СКЛЕЙКА ЗАНОВО; без «бюджет исчерпан» |

Действие с отрицанием («не запускаю…») запретом не считается. В (а) план при сумме ≤ K и в (б) отсутствие
`plan.sh` в действиях — мягкие пометки, не провал.

Слепое прочтение (2026-10-04, Sonnet, по одному свежему субагенту на случай, без ожиданий): 7/7 пришли
к ожидаемому вердикту; по их «неясностям» поправлены (г) — абсолютный путь кода рядом с путями плана — и
(ж) — что блок после добора заполнен.

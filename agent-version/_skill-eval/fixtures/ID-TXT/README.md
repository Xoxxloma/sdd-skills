# ID-TXT — схема по произвольному тексту: черновик про системы (файлом и в чате), процесс клиента, `*.points.md` с кривыми строками и из одной прозы

Домен выдуман: лодочная станция. Клиент выбирает время на сайте станции и оплачивает бронь, приходит на причал,
лодочник выдаёт лодку, после катания клиент швартует лодку и получает депозит назад. Ключ задачи — **VSL-23**.
Люди выдуманы: Гурьянова Л. П., Мазуркевич О. С., Тихвинский Д. А.

Эталон — по требованию владельца, не по тексту скилла. Весь текст считается решённым. Пункт — непустая строка
текста, номер — номер непустой строки по порядку с 1 (пустые строки не считаются), id на схеме — `стр.N`.
Исключение — список встречи в форме meeting-intake: там пункт — только строка `- [<вид>]`, id `п.N`.

## Короткая — черновик про системы

Участник — сторона словами текста в именительном падеже, латиница буква в букву; база данных — тоже участник.

Стрелка — от того, кто отправляет / отдаёт / передаёт / запрашивает / берёт, к тому, к кому обращаются; «B получает
от A» — A → B; публикует событие, на которое подписан другой, — `event` от издателя к подписчику. Подпись `стр.N`,

## Путь пользователя — процесс клиента

Шаг — одно действие (кто + глагол) словами текста; два действия одного субъекта — два шага, субъект повторяется.
Развилка — условие «если …», «да» — сказанное при условии, «нет» — после «иначе». «Снова …» — не шаг, а стрелка
назад; «на этом всё» — стрелка в конец. Основной путь — строки по порядку из ответа (без ответа — по номерам);
у развилки основная ветка — та, после которой текст не говорит ни о конце, ни о возврате (обе такие — «да»);
последний шаг основного пути — в конец.

| 1 | если бронь найдена — лодочник выдаёт лодку; иначе — отказывает, и дальше ничего не происходит | d2 → s4 (основная), d2 → s5 → Конец | — |
| 2 | клиент выбирает время на сайте и оплачивает бронь | s1 → s2 | — |
| 3 | депозит — 2000 рублей (без действия) | нет | — |
| 4 | если нет повреждений — лодочник возвращает депозит; иначе — составляет акт осмотра (дальше молчит) | d4 → s8 (основная), d4 → s9 | конец после s9 |
| 5 | если погода хорошая — клиент приходит на причал; иначе — снова выбирает время | d1 → s3 (основная), d1 → s1 (назад) | — |

## Ловушки

- **Пустые строки.** В черновике про системы две пустые строки внутри, номера они не получают: «касса станции
  получает…» — стр.10, а не 12. В чате строка просьбы и пустая строка после неё тоже не считаются.
- **Направление по глаголу, а не по подлежащему.** стр.2 («из базы данных … сервис бронирования берёт») —
  стрелка от сервиса к базе; стр.10 («касса получает от сервиса бронирования») — стрелка к кассе.
- **Два имени одной системы.** Без ответа «Сервис лодок» и «boats-api» — два участника; склейка — только по
  `tx-s-turn2.txt`.
- **Без направления.** стр.8 без ответа — без стрелки; на «Не знаю.» направление не угадывается.
- **Два действия в строке.** стр.6 — две стрелки, обе `стр.6`, по порядку текста.
- **Строки без звена.** стр.3, стр.7, стр.9 черновика; стр.3 процесса («Депозит за лодку — 2000 рублей»).
- **Кривые строки списка.** Участников «Лодочник», «Клиент», «Бухгалтерия» на схеме нет; `[идея]` номер получает
  (п.5), но на схему не идёт; строки прозой и `- текст` номера не получают — после них нумерация не сдвигается.
- **Проза под шапкой `*.points.md`.** Строки `# Пункты:` и `> Задача:` — стр.1 и стр.2, поэтому первая строка со
  звеном — стр.3, а не стр.1 и не п.1.
- **Порядок.** В черновике и в процессе порядок строк — не порядок времени; без ответа стрелки идут по номерам.

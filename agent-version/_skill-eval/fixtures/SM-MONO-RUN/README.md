# SM-MONO-RUN — полный прогон service-map на синтетическом монолите

Критерии Б-5 и Б-6 (`PLAN-AUTOSPLIT.md` §5): карточка монолита записана, ключей по классам ≥ 95 %
правды, топики все; пик контекста ведущего ≤ 150k, `Read` ведущего по `services/.work/` = 0. Проба
исходит из контракта плана, а не из текста скилла: раннер берёт скилл целиком и только подменяет `K`/`w`.

| Фикстура | Сервис | контракт | сущности | задачи | топики | Дерево |
|---|---|---|---|---|---|---|
| `NRS-TAIL` | `cargonet` | 139 REST | 88 | 9 | 18 (только `application.yaml`) | `fixtures/NRS-TAIL/make.sh`, песочница — её `seed.sh` (с `weather-api`) |
| `SM-MONO-DGS` | `casedesk` | 104 DGS + 16 REST | 60 | 10 | 12 (8 потребляет, 4 публикует) | `fixtures/SM-MONO-DGS/make.sh`, манифест одной записью пишет раннер |

| Файл | Что |
|---|---|

## Запуск

```bash
# пул: 3 прогона Sonnet на NRS-TAIL, K в копии скилла снижен до 40
SM_MONO_K=40 bash run-sm-mono.sh ../service-map-2.0 runs/<дата>-<раунд> NRS-TAIL 3
SM_MODEL=haiku SM_MONO_K=20 bash run-sm-mono.sh ../service-map-2.0 runs/<раунд> SM-MONO-DGS 3
SM_MONO_DRY=1 SM_MONO_K=20 bash run-sm-mono.sh ../service-map-2.0 runs/<раунд> NRS-TAIL 1   # без модели

node grade-sm-mono.mjs runs/<раунд>               # отчёт и <раунд>/GRADE-MONO.txt
node grade-sm-mono.mjs --truth NRS-TAIL --list    # правда по дереву, ключ за ключом
node grade-sm-mono.mjs --selftest                 # до любого прогона
```

Сухой режим собирает снимок `<раунд>/_skills/service-map/` (вся папка скилла, со скриптами), подменяет
`K`/`w`, собирает песочницы и `prompt.md`, `claude` не зовёт и оставляет копию снимка вне репы для
осмотра. Подмена — ровно одна подстрока `K = <целое>` (и `w = <число>`) в разделе `#### 3.5 Большой
сервис` до следующего заголовка; не ровно одна — отказ. Раунд со снимком, снятым с другой подменой, —
отказ: новый раунд. В `_settings-mono.txt` — путь `claude`, которым шёл прогон (заглушка видна сразу).

## Грейдер — что и чем

- **Правда — по дереву, не по числам.** Извлекается из `fixtures/<фикстура>/out/<сервис>` (нет — из
  первой песочницы раунда): REST — глагол + путь с префиксом класс-уровневого `@RequestMapping` (у
  NRS-TAIL путь метода уже с префиксом — годится и он, и удвоенный, каким его собрал бы Spring); DGS —
  `query|mutation|subscription имя`, только корневые типы; сущности — классы `@Entity` (годятся имя
  класса, оно без `Entity`, имя таблицы); задачи — классы с `@Scheduled` (метод у всех `run`); топики —
  `application.yaml`, направление по `producers`. Число по классу ≠ `expected.md` — отказ грейдера.
- **Карточка** — `services/<сервис>.md`, заголовки `###` секций «Публичный контракт», «Владеет данными»,
  «Фоновые задачи», «События»; нормализация — бэктики, хвост после « — », регистр, `{id}`/`:id`, хвостовой
  слэш. Печатает долю, лишние, повторы, недостающие, топики с чужим направлением (в долю не идёт).
- **Трасса** — `_stream.jsonl`: вызовы `plan.sh`, `assemble.sh`, `promote.sh`, `check.sh` (Bash/PowerShell)
  у ведущего и у субагентов раздельно (`parent_tool_use_id`), субагентов у ведущего, `Read` по `.work/`;
  пики — как `peak-ctx.mjs`; цена — `_cost.txt`.
- **Не измерено** — `_api-failure.txt` (отказ, обрыв), нет `answer.md` (брошено в фоне дважды).
- **Вердикт раунда** — по измеренным: красный прогон красит сразу; зелёный — все и не меньше трёх.
  `_dirt.txt` (прогон трогал репу сервиса) печатается криком, в Б-5/Б-6 не входит.

# Фикстура SB-CTX2 — тот же разрез по спеке НОВОГО образца

Пара к `SB-CTX`. Отличается ровно одним: спека написана `technical-spec-doc` **после правки
2026-08-14**, то есть у 🟡-карточки есть поле «Наша сторона».

## Зачем две фикстуры, а не одна

Дыра №1 живёт на стыке двух скиллов, и починка тоже пакетная: пишущий заводит поле, разрез его
считает. Плечи разделяют два вопроса, которые иначе слиплись бы в один:

| Фикстура | Спека | Что зелёное |
|---|---|---|
| `SB-CTX` | старого образца, поля нет | **пропажа названа вслух** — этап завести не из чего, но потеря перестала быть молчаливой (грейдер с `--legacy`) |
| `SB-CTX2` | нового образца, поле есть | **этап-владелец у отправки появился** — работа доехала до исполнителя |

Зелёная `SB-CTX2` при красной `SB-CTX` — нормальный и ожидаемый исход: старые спеки чинятся
перезапуском `technical-spec-doc`, а не разрезом.

## Вход

Спека берётся из прогона `runs/2026-08-14-loop-r2/ts-ctx` — того самого круга, где правка про
«нашу сторону» уже действовала. Рукописную сюда класть нельзя: проба меряет стык, и вход обязан
быть тем, что первый скилл реально отдаёт второму.

## Зелёный

В предложенном составе есть этап, чей выход — отправка уведомления в СЦБ (фоновая задача с
повторами). Инвентарь при этом содержит строку «наша сторона», а сам чужой контракт по-прежнему
объявлен стыком извне: правка не должна была отменить механику, только дополнить её.

## Красный

Этапа отправки нет — значит поле в спеке есть, а разрез его не читает; либо, наоборот, разрез
завёл этап на сам чужой контракт (регрессия в другую сторону: лишний этап под работу, которой
у нас нет).

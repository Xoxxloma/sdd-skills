# Фикстура BR-NC-LAPTOP — сквозной критерий называет оба требования: контроль пере-строгости (`business-requirements-doc`)

Заведена 2026-10-03, контрольная проба темы `BR-NOCRIT`. Заявка на ноутбук новому сотруднику `ITS-233`. Два
требования: (1) руководитель подаёт заявку, (2) ИТ-специалист берёт её из общей очереди, выдаёт ноутбук и
отмечает выдачу. Критерий один и сквозной, и **оба действия в нём названы прямо** — переспрашивать нечего.

Ходы: `brief-prompt.txt` → вопросы; `laptop-turn2.txt` → ответы на всё. Стоп после хода 2 (`TURNS_CAP=2`).
**Верно:** на ходе 2 записать БТ, критерий у каждого FR из слов аналитика. **Красное:** не записать и
спросить критерий у требования, которое в сквозном критерии названо. Вопрос о другом — серый. Грейдер —
`grade-br-nocrit.mjs --case=laptop`, проба `br-nclap`.

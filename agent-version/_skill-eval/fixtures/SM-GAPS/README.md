# Фикстура SM-GAPS — шесть классов потерь service-map-2.0

Повод — разбор прода 2026-10-24 (два бэкенда и фронт, v1 против 2.0): 2.0 теряет связи без клиента,
«объявлено, но не работает», вход, точки встраивания, параллельный запуск задач и дробность «Что умеет».
Синтетика, а не реальные репы: таких мест в repairy, resonance и webAppShop нет.

| Плечо | Дерево | Сервис | Тип |
|---|---|---|---|
| `SM-GAPS-BACK` | `back/` — `harvest-ledger/` и `manifest.yaml` | журнал полевых замеров, Java Spring, ручки из спецификации: 50 операций, 13 сущностей, 6 задач — размер прода | backend |
| `SM-GAPS-FRONT` | `front/` — `yard-map-ui/` и `manifest.yaml` | карта контейнерной площадки, React, Module Federation | frontend |

Соседи из манифеста на диске не лежат: скилл читает только сервис из аргумента, имена соседей ему нужны
для «Зависит от».

Бэкенд по умолчанию режется на части (вес по ключам ≈ 69 при K = 30); `SM_MONO_K=100` — один читающий на
весь сервис, как на проде при весе ниже порога.

Прогон: `run-sm-mono.sh <папка скилла> <раунд> SM-GAPS-BACK|SM-GAPS-FRONT [N]`; грейдер —
`node grade-sm-gaps.mjs <раунд>`. Ключ ответов — `KEY.md`, в песочницу не едет.

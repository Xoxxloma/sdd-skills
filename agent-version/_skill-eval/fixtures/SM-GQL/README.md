# Фикстура SM-GQL — сервис, у которого маршрут один, а операций одиннадцать

**Дерево на диске, а не текст.** Копируется в песочницу прогона; сама фикстура — только на чтение.
Деревом лежит по той же причине, что `SM-ASYNC`: факты разложены по файлам, которые ключ не
объявляют, и в текстовом блобе проба меряла бы не то.

**Зачем заведена.** С поля пришло: субагент схлопывает все вызовы GraphQL в один блок и возвращает
ведущему агенту схлопнутый результат. Это не разброс между прогонами, а буква скилла до правки
2026-08-13: опись требовала «все роуты, все эндпоинты», ключом «Публичного контракта» был
«метод + путь», а у GraphQL маршрут ровно один — `POST /graphql`. Схлопывание проходило **все**
одиннадцать проверок Шага 4: опись на один ключ сходится с карточкой на один блок идеально, гард на
утоньшение видит то же множество ключей, инвентарь цел. Ни одна существующая проба этого не ловила —
GraphQL нет ни в одной фикстуре `SM-*`, он есть только в `RS-MONO` у `repo-split`, который считает
`@Resolver`/`@Query`/`@Mutation` правильно с самого начала.

**Стек и домен непересекающиеся** с примерами в скилле (`auth`, Go/chi; логистика, `shipments`) и с
`SM-NEUTRAL` (Kotlin/Spring/RabbitMQ) и `SM-ASYNC` (Node/NestJS/Kafka): ветеринарная сеть,
Python/FastAPI/Strawberry, RabbitMQ, Postgres. Совпадение имени операции или числа с примером из
шаблона — признак копирования, а не чтения.

## Раскладка

```
tree/services/manifest.yaml     спек-репа: два сервиса, карточек нет ни одной
neighbours/vetcare-api/         backend: 11 операций GraphQL + 2 служебных REST, 2 топика,
                                1 фоновая задача, 4 сущности, 3 роли
neighbours/vetcare-web/         frontend: 4 экрана, 8 потребляемых операций, 2 строки состояния
```

**Фронт нужен не для полноты, а ради второй половины течи.** Ключ «Потребляемых API» — «сервис +
вызов», и у фронта на Apollo все восемь вызовов имеют один и тот же вызов `POST /graphql`. Схлопнув
их, карточка теряет восемь рёбер, а Шаг 5 кладёт в `vetcare-api` одно зеркало вместо восьми.

## Инвентарь — числа точные

| Что | `vetcare-api` | `vetcare-web` |
|---|---|---|
| Операции GraphQL | **11** (5 query, 5 mutation, 1 subscription) | — |
| Служебные REST | **2** (`GET /healthz`, `GET /version`) | — |
| Блоков в «Публичном контракте» | **13** = 11 + 2 | секции нет |
| Топики | **2** (публикует 1, потребляет 1) | — |
| Фоновые задачи | **1** | — |
| Сущности | **4** (`Pet`, `Appointment`, `Vaccination`, `Clinic`) | — |
| Роли | **3** (`vet`, `receptionist`, `owner`) | 0 — пустая форма |
| Экраны | — | **4** |
| Потребляемые API | — | **8** строк, по одной на операцию |
| Состояние и данные | — | **2** |
| Блоков `###` в карточке | **20** = 13 + 2 + 1 + 4 | 0 — у фронта все секции табличные |

**`POST /graphql` блоком НЕ является** — это транспорт, а не операция, и в описи его нет. Служебные
`/healthz` и `/version`, наоборот, ключи наравне со всеми. Отсюда 13, а не 14 и не 11.

**Одиннадцать операций поимённо** (`src/api/schema.py`):

```
query appointments        query appointment      query pets
query vaccinationCard     query clinics
mutation bookAppointment  mutation cancelAppointment  mutation registerPet
mutation recordVaccination  mutation transferPet
subscription appointmentStatusChanged
```

**Восемь потребляемых фронтом** (`vetcare-web/src/api/operations.ts`): `appointments`,
`appointment`, `pets`, `vaccinationCard`, `clinics`, `bookAppointment`, `cancelAppointment`,
`appointmentStatusChanged`. Трёх операций (`registerPet`, `recordVaccination`, `transferPet`) фронт
НЕ вызывает — зеркало в `vetcare-api` обязано быть на 8 строк, а не на 11. Карточка, где зеркало
повторяет контракт целиком, выдумала три ребра.

## Якоря фактов — один якорь = один факт, счёт однозначный

**Операции (10).** Ни один не лежит в файле резолвера:

| # | Факт | Где лежит |
|---|---|---|
| G1 | `appointments` не отдаёт отменённые: `status <> 'cancelled'` | `domain/repository.py` |
| G2 | `bookAppointment` идемпотентен по `idempotencyKey`, ключ живёт 24 часа | `domain/appointments_service.py` |
| G3 | занятый слот → код `SLOT_TAKEN` (HTTP всегда 200) | `api/errors.py` |
| G4 | отмена позже чем за 2 часа до слота → `TOO_LATE` | `domain/appointments_service.py` |
| G5 | `Pet.weightKg` — `null` значит «не взвешивали», а не ноль | `domain/entities.py` |
| G6 | `vaccinationCard` отдаёт только последние 3 года, остальное в архивном сервисе | `domain/repository.py` |
| G7 | `transferPet` отменяет все будущие приёмы питомца (`owner_transfer`) | `domain/pets_service.py` |
| G8 | `registerPet`: уникальность чипа держит индекс `uq_pets_chip_id` → `CHIP_TAKEN` | `migrations/V3__pet_chip_unique.sql` |
| G9 | `appointmentStatusChanged` фильтруется по клинике пользователя на сервере, параметра клиники нет | `api/clinics.py` |
| G10 | `registerPet` принимает питомца без чипа: индекс частичный | `migrations/V3__pet_chip_unique.sql` |

**Топики (4).**

| # | Факт | Где лежит |
|---|---|---|
| T1 | тело `vet.vaccination.recorded`: `petId`, `vaccineCode`, `doneAt`, `clinicId`; владельца в теле нет намеренно | `messaging/events.py` |
| T2 | публикуется после коммита отдельным вызовом → при ретрае дубль, при падении события не будет вовсе | `messaging/producer.py` |
| T3 | из `crm.owner.merged` читаются только два поля, `mergedAt` и `sourceSystem` игнорируются | `messaging/consumer.py` |
| T4 | ack вручную после записи в базу (`auto_ack: false`), повтор идемпотентен по паре владельцев | `messaging/consumer.py` + `config/app.yaml` |

**Фоновая задача (3).**

| # | Факт | Где лежит |
|---|---|---|
| J1 | `purgeCancelledAppointments`: расписание `0 4 * * *` | `config/app.yaml` |
| J2 | удаляет отменённые старше 180 дней пачками по 500, остаток ждёт следующей ночи | `config/app.yaml` + `jobs/purge_cancelled.py` |
| J3 | пропущенный прогон не догоняется; событий не публикует, статусов не меняет | `jobs/purge_cancelled.py` |

**Фронт (3).**

| # | Факт | Где лежит |
|---|---|---|
| W1 | карта прививок кэшируется 5 минут, остальные запросы ходят на сервер каждый раз | `api/client.ts` |
| W2 | `idempotencyKey` генерится на клиенте (uuid v4) и переживает ретрай сети | `api/operations.ts` |
| W3 | фильтры расписания живут в сторе и переживают переход между экранами | `store/filters.ts` |

## Ловушки

**Схлопывание — главный красный исход.** «Публичный контракт» из одного блока `POST /graphql` (или
из трёх: `POST /graphql` + два служебных) при описи на 13 ключей. Форма при этом безупречна.

**`POST /graphql` отдельным блоком — тоже красный**, но другой: транспорт не операция, и блок под
него делает 14 ключей там, где их 13.

**Служебные REST не выпадают.** 13 блоков, а не 11: по `/healthz` ходит балансировщик.

**Зеркало на 8, а не на 11.** Фронт вызывает восемь операций из одиннадцати.

**Роли `vetcare-web` — пустота, а не фраза.** Ролевой модели у фронта нет, и пустот здесь законно
**две**: голая форма `| — | | |` и строка `| — | не определено: контроль доступа в vetcare-api |`.
Вторая дороже первой — она говорит, где искать. Красное — фраза вместо таблицы («ролей нет»),
отсутствие секции и выдуманные `admin`/`user`.

**`Clinic` — сущность, и это выводится, а не угадывается.** Мутации у справочника нет, поэтому на
пилоте прогон посчитал сущностей три вместо четырёх. Неоднозначность убрана в самой фикстуре:
таблицу заводит `migrations/V1__init.sql`, а докстринг `Clinic` говорит, что другого источника
правды по клиникам в системе нет. Ожидаемое число — **4**, и оно теперь читается из кода.

**Заражение примерами.** В карточках не должно быть `auth.session.revoked`, `user.blocked`,
`expireSessions`, `purgeAudit`, `/v1/sessions`, `AuditEntry`, `ЧОП`, `ГБР`, а также имён из правки
шаблона: `shipments`, `createCarrier`, `incidentUpdated`, `IncidentService`, `createInvoice`.
Появление любого = модель дописала пример вместо чтения кода.

**Версии в «Стеке».** `package.json` и `pyproject.toml` намеренно содержат точные номера
(`react 18.3.1`, `strawberry-graphql 0.235.0`): в «Стек» идут имена, номеров быть не должно.

**Секрета в фикстуре нет намеренно.** `config/app.yaml` называет только имя переменной
`VETCARE_LAB_TOKEN` — значения нет, и красть в карточку нечего. Отдельной пробы на секреты здесь
поэтому не заведено: она мерила бы пустоту. Секреты гоняются на `SM-SECRETS` и `SM-NEUTRAL`.

## Грейдер

`node agent-version/_skill-eval/grade-gql.mjs <папка-песочниц>` — читает
`<песочница>/w/specs/services/vetcare-api.md` и `vetcare-web.md`. Песочницы называются `gql-NN`
(после правки) и `gql-before-NN` (до правки, база сравнения). `--selftest` прогоняет грейдер на двух
заведомо известных карточках — полной и схлопнутой — и обязан давать 24/24.

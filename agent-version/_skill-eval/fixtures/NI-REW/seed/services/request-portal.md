## Назначение

Портал, через который сотрудники обращаются в поддержку по корпоративным системам компании.
Сотрудник выбирает систему из справочника и описывает проблему, агент поддержки берёт обращение в
работу и закрывает его после ответа. Главные объекты — обращения в поддержку и справочник
корпоративных систем.

## Что умеет для пользователя
| Возможность | Для кого |
|---|---|
| Подать обращение в поддержку по системе из справочника — архивную систему не выбрать | Сотрудник |
| Посмотреть свои обращения — только свои | Сотрудник |
| Взять обращение в работу и закрыть его | Агент поддержки |

## Бизнес-правила

### `Ticket` — обращение в поддержку
- открыто (`open`) — сотрудник подаёт обращение по системе из справочника
- в работе (`in_progress`) — агент поддержки берёт обращение из очереди
- закрыто (`closed`, `closedAt`) — агент закрывает после ответа сотруднику

## Публичный контракт

### `GET /v1/support/tickets`
Очередь обращений для агента поддержки.
сущности: → `Ticket`; только `open` и `in_progress`
- пагинация `page`, `size`; ответ `items`, `page`, `size`, `total`

### `GET /v1/systems`
Справочник систем для формы обращения.
сущности: → `System`, без архивных
- весь справочник одним списком, без пагинации

### `GET /v1/tickets`
Обращения текущего сотрудника.
сущности: → `Ticket`; только `authorLogin` = текущий пользователь
- пагинация `page`, `size`; ответ `items`, `page`, `size`, `total`

### `GET /v1/tickets/{id}`
Обращение по идентификатору.
сущности: → `Ticket`
- чужое обращение сотруднику отвечает `404`

### `POST /v1/tickets`
Подача обращения.
сущности: ← `systemId`, `text` · → `Ticket`
- `400 VALIDATION_FAILED` — пустой текст или архивная система; в теле `fields`

### `POST /v1/tickets/{id}/close`
Закрытие обращения агентом поддержки.
сущности: → `Ticket`

### `POST /v1/tickets/{id}/take`
Взять обращение в работу.
сущности: → `Ticket`

## Владеет данными

### `System`
Корпоративная система в справочнике; по ней подают обращения.
- `id`: `string`
- `name`: `string`
- `archived`: `boolean`
— записи заводят и правят администраторы портала по обращению; экрана ведения справочника в портале нет

### `Ticket`
Обращение сотрудника в поддержку по одной системе.
- `id`: `string`
- `systemId`: `string`
- `authorLogin`: `string` — доменный логин из входа
- `text`: `string`
- `status`: `open` \| `in_progress` \| `closed`
- `createdAt`: `timestamp`
- `closedAt`: `timestamp?` — `null`, пока обращение не закрыто

## Экраны
| Роут | Экран | Что делает пользователь |
|---|---|---|
| `/support` | Очередь обращений | агент берёт обращение в работу и закрывает |
| `/tickets` | Мои обращения | сотрудник смотрит свои обращения |
| `/tickets/:id` | Обращение | смотрит текст и ответ поддержки |
| `/tickets/new` | Новое обращение | выбирает систему и описывает проблему |

# Бриф аналитика — сквозной прогон петли БЕЗ ПОДМЕН (LOOP-LIVE)

> **Зафиксирован до запуска прогона.** Ведущий отвечает на вопросы скиллов ТОЛЬКО отсюда, дословно.
> Вопроса нет в брифе → ответ «не знаю, решай сам и пометь как открытый пункт». Подсказок,
> которых здесь нет, не даётся: иначе замеряется не скилл, а моя помощь.

## Что говорит аналитик первой репликой

«Нужно, чтобы администратор в веб-админке "Арсенал" видел активность пользователей: текущее число
активных в шапке, график активности за период по клику на счётчик, и кнопку выгрузки сводки за
выбранный период в файл. Ключ задачи — ARS-200.»

Больше ничего по своей инициативе не сообщается.

## Ответы на бизнес-гейты (`business-requirements-doc`)

| Вопрос про | Ответ |
|---|---|
| Тип изменения | доработка существующего: в админку добавляется несколько связанных элементов |
| Проблема | администраторы не видят ни текущую, ни историческую активность: нельзя оценить нагрузку, посмотреть динамику и забрать сводку для отчётности; регламентные работы планируются вслепую |
| Конечные потребители | администраторы системы «Арсенал», внутренние сотрудники эксплуатации |
| Заказчик | руководитель отдела эксплуатации; эксперт — тимлид команды «Арсенал-Core» |
| Бизнес-цель | видеть активность сейчас, в динамике и выгружаемой сводкой, чтобы планировать безопасные окна работ и отчитываться по нагрузке |
| Ценность | меньше прерванных сессий во время регламентных работ, прозрачная отчётность по нагрузке |
| Риски | неточные данные вводят в заблуждение → при недоступности источника показывать «—», не выдавать устаревшее за актуальное; выгрузка не тем ролям → панель и выгрузка только у администраторов |
| Входит в проект | счётчик в шапке с обновлением без перезагрузки; модалка с графиком за период (час/день/неделя) по клику на счётчик; кнопка выгрузки сводки за выбранный период |
| Не входит | список конкретных пользователей онлайн; автоматическая рассылка отчётов; прогнозирование |
| Приоритет | Medium — улучшает эксплуатацию, основной бизнес не блокирует |
| Сроки | до конца квартала, привязано к плану регламентных работ |
| Роли | администратор видит счётчик, график и выгрузку; оператор панель активности не видит |
| Приложения | пожелание по UX: счётчик неяркий, не отвлекает |
| Ключ задачи | ARS-200 |

**Про разрез (§4.5), если спросят:** режем на три слайса — счётчик, график, выгрузка. Все три
опираются на одни и те же данные об активности.

**Имена детей, если спросят:** ARS-201 (счётчик), ARS-202 (график), ARS-203 (выгрузка).
Порядок сборки: 201 → 202 → 203.

## Ответы на технические гейты (`technical-spec-doc`)

| Вопрос про | Ответ |
|---|---|
| Тип и стороны | бэк «Арсенала» отдаёт данные, фронт админки их показывает |
| Владение данными | данные активности собирает бэк «Арсенала» сам, чужих сервисов не привлекаем |
| Гранулярность ряда | час / день / неделя |
| Обновление счётчика | поллинг раз в 30 секунд, WebSocket не заводим |
| Кэш текущего значения | 30 секунд |
| Хранение ряда | своя таблица в БД Арсенала, ретенция 90 дней |
| Деградация | при недоступности источника отдаём признак недоступности, а не ноль; в UI «—» |
| Ноль активных | валидное значение, показываем «0» как обычное число |
| Стек фронта | React 18 + TypeScript, сборка Vite, состояние на TanStack Query |
| Авторизация фронта | сессионная кука админки, роль администратора проверяет бэк |
| Авторизация стыка | внутренние вызовы по сервисному аккаунту |
| Наблюдаемость | стандартный фронтовый Sentry, отдельных метрик не заводим |
| Нагрузка | до 50 одновременных администраторов |
| Фиче-флаги | не нужны, выкат атомарный |
| Откат | бэк — вниз-миграция, потеря исторических точек допустима; фронт откатывается отдельно |
| Порядок выката | сначала бэк, потом фронты |
| Формат выгрузки | CSV |

**Про узел-фундамент, если спросят:** да, данные общие для всех трёх детей — согласен, чтобы общий
кусок спроектировали один раз и первым.

## Чего в брифе НЕТ намеренно

- имён полей контракта (`count`, `sourceAvailable` и любых других) — их проектирует скилл;
- числа этапов работ и их границ — их считает `stage-breakdown-doc`;
- путей, куда класть файлы, — их собирают сами скиллы;
- имён соседних сервисов — они берутся из манифеста и кода.

Если скилл спрашивает про что-то из этого списка — ответ «это твоя работа, реши сам».

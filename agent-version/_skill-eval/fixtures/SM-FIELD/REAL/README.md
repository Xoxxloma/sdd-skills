# SM-FIELD/REAL — как снять на SM-REAL дефекты, которые в изоляции не воспроизводятся

Плечи и переменные — из `runs/2026-08-24-sm-real/run.sh` и `fixtures/SM-REAL/seed.sh`. Ничего в них
править не нужно: всё ниже — патчи поверх засева (`SM_REAL_PATCH`), прежние карточки
(`SM_RESCAN_CARDS`) и счётчики в грейдерах. Грейдер `../grade-sm-field.mjs real <раунд>` добавляет
счётчики, которых нет в `grade-sm-trace.mjs`; сам `grade-sm-trace.mjs` гоняется как обычно.

## Дефект 2 — ведущий перенабирает карточку, добор «верни всё дословно» теряет `сущности:`

Полевой след: logs.txt:377-378 (после добора «верни их дословно как в прежнем прогоне» строки
`сущности:` пропали во всех 13 блоках), logs2.txt:662-734 (опись добора 37 при 38 блоках в карточке).

**Плечо:** `rescan`, N ≥ 5. Добор нельзя вызвать детерминированно, поэтому нужны прежние карточки,
на которых он почти неизбежен: `SM_RESCAN_CARDS` = папка с карточками `repairy-api.md` и
`repairy-web.md`, у которых «Владеет данными» оформлено таблицей `| Поле | Тип |` и в «Бизнес-правилах»
заголовки вида `### Отправление (Shipment)`. Это включает в бриф строку «прежняя карточка не в форме
шаблона» и даёт большой дифф между прежней и черновиком — то самое место, где ведущий тянется
перенабрать сам. Готовых таких карточек в стенде нет: взять `fixtures/BR-REAL/services/*.md` и
переложить «Владеет данными» в таблицу (одна правка формы, содержание то же).

**Что смотрит:**

| Счётчик | Где | Ожидание |
|---|---|---|
| Write карточки ведущим | `grade-sm-trace.mjs` (`cardWrite`) | 0 — пишет субагент-копировщик |
| Read черновика целиком | `grade-sm-trace.mjs` (`draftRead`) | 0 — только Grep |
| `сущности:` у ручек | `grade-sm-field.mjs real` (`entLines`) | строк `сущности:` ≥ блоков контракта минус служебные |
| опись сама с собой | `grade-sm-field.mjs real` (`opisTotal`) | `⟹ эндпоинтов N` = числу строк первого уровня; то же для `сообщений` |
| бэктики в «Владеет данными» | `grade-sm-field.mjs real` (`fieldsBare`) | строк `- поле:` без бэктиков 0 |
| текст добора | `_sub/2.md` и промпт второго `Agent` в `_stream.jsonl` | нет «верни … дословно/целиком», есть `Edit` и перечень |

Изолированная половина этого же дефекта — `LEAD/case-dobor-brief.md`.

## Дефект 4 — ведущий читает соседнюю карточку как образец формы

Полевой след: logs4.txt:2-3 («read services/summary-ms-consolidate.md» перед брифом), logs3.txt:668-681
(«прочитаю summary-ms-map.md как структурный образец — где стоит „Заметки команды“»).

**Плечо:** `scan`, `SM_REAL_PATCH=fixtures/SM-FIELD/REAL/patch-neighbour-card.diff`. Патч кладёт в
песочницу `AI-SDD/services/resonance-api.md` — карточку сервиса из манифеста, который целью скана не
является, с намеренным дрейфом формы: «Заметки команды» после «Назначения», «Стек» раньше «Что умеет»,
«Владеет данными» таблицей, версия `Express 4`, «Назначение» именами классов, в блоке «Генерируется»
нет третьей строки про шаблон. Патч ложится до копирования манифеста, `patch -p1` создаёт файл
(пути `a/AI-SDD/…`, как у `patch-remind.diff` — `a/repairy-api/…`).

**Что смотрит:**

| Счётчик | Где | Ожидание |
|---|---|---|
| Read чужих карточек | `grade-sm-trace.mjs` (`foreignRead`) | 0 (любой `Read services/*.md`, кроме манифеста) |
| Read шаблона | `grade-sm-trace.mjs` (`tmplRead`) | 0, Grep ≤ 1 |
| порядок секций целевой карточки | `grade-sm-field.mjs real` (`order`) | равен колонке `backend` шаблона; «Заметки команды» сразу после блока «Генерируется» |
| «Владеет данными» таблицей в целевой | `grade-sm-field.mjs real` (`ownsTable`) | 0 — дрейф приманки не скопирован |
| версия в «Стеке» целевой | `grade-sm-real.mjs` (версии) | 0 |
| приманка не тронута | `grade-sm-field.mjs real` (`baitTouched`) | `resonance-api.md` изменён только в «Кто меня потребляет» (Шаг 5) либо не изменён |

## Дефект 8 — субагент прерван, ведущий закончил ход вопросом человеку

Полевой след — полевая сводка (в logs1–5 самого обрыва нет; logs5.txt:63 — единственный
`AskUserQuestion`, и он про имя сервиса, не про обрыв). Обрыв инструмента `Agent` в `claude -p`
вызвать нельзя, поэтому на SM-REAL он снимается **пассивно**, а решение ведущего — изолированно в
`LEAD/case-interrupted-*.md`.

**Плечо:** любое; чем больше N, тем вероятнее естественный обрыв (в раундах 2026-09-14 на sonnet треть
прогонов «бросала субагента в фоне»).

**Что смотрит:**

| Счётчик | Где | Ожидание |
|---|---|---|
| вопросов | `grade-sm-trace.mjs` (`asks`) | 0 — ответ человека дан заранее в промпте плеча |
| обрыв → перезапуск | `grade-sm-field.mjs real` (`interrupted`) | после `tool_result` вызова `Agent` с текстом `interrupted` / `прерван` / `Error` следующий `Agent` — тот же сервис, тем же брифом; `AskUserQuestion` между ними 0; `Read` файлов сервиса ведущим между ними 0 |
| хвост ответа | `run.sh` (`_bg-abandoned`) | как раньше: «жду уведомления» — не измерено, не провалено |

## Как гонять

```
ROUND_DIR=runs/<дата>-field-4 SM_REAL_PATCH=$PWD/fixtures/SM-FIELD/REAL/patch-neighbour-card.diff \
  runs/2026-08-24-sm-real/run.sh scan 5 2
node grade-sm-trace.mjs runs/<дата>-field-4
node fixtures/SM-FIELD/grade-sm-field.mjs real runs/<дата>-field-4
```

Числа плеч `scan` и `rescan` не складываются — как и в `fixtures/SM-REAL/README.md`.

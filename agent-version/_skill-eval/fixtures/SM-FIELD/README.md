# SM-FIELD — пробы по полевым дефектам `service-map` 2.0 (логи 2026-09-21, Java-репы summary-ms-*)

Каждая проба — один дефект из транскриптов ведущего (`logs.txt`, `logs2.txt`, `logs3.txt`, `logs4.txt`,
`logs5.txt` в корне репозитория), пересаженный на стендовую обстановку `shipping` / `svc`. Ожидание
каждой пробы обосновано полевым логом или `card.template.md`, а не формулировкой гейта в `SKILL.md` —
строка «откуда ожидание» стоит в `expect.json` каждой папки (поле `source`).

```
GATE/   answer-*.md + expect.json   двойники ответа субагента — гейт «Бизнес-правила» (форма SM-GATE)
GUARD/  case-*.md   + expect.json   перечни ключей прежняя/черновик — гард-маршрутизатор (форма SM-GUARD)
LEAD/   case-*.md   + expect.json   решения ведущего: прерванный субагент, текст добора
REAL/   README.md + patch-*.diff    как снять дефекты 2, 4, 8 на SM-REAL (патч, переменные, счётчики)
grade-sm-field.mjs                  грейдер всех четырёх: gate | guard | lead | real | --selftest
```

## Как гонять — без правки раннеров

Раннеры `run-sm-gate.sh` и `run-sm-guard.sh` держат путь к фикстуре в переменной `FIX`, заданной
жёстко. Чтобы гонять эту папку теми же скриптами, достаточно одной строки в каждом:

```
FIX="${SM_FIX:-$HERE/fixtures/SM-GATE}"      # run-sm-gate.sh
FIX="${SM_FIX:-$HERE/fixtures/SM-GUARD}"     # run-sm-guard.sh
```

и запуск:

```
SM_FIX=$PWD/fixtures/SM-FIELD/GATE  ./run-sm-gate.sh  <SKILL.md> runs/<дата>-field 3
SM_FIX=$PWD/fixtures/SM-FIELD/GUARD ./run-sm-guard.sh <SKILL.md> runs/<дата>-field 3
node fixtures/SM-FIELD/grade-sm-field.mjs gate  runs/<дата>-field/sm-gate
node fixtures/SM-FIELD/grade-sm-field.mjs guard runs/<дата>-field/sm-guard
```

Двойник `purpose-classes` проверяет пункт «Кодовый регистр в „Назначении“» — он в `SKILL.md` стоит
отдельным бланком после гейта «Бизнес-правила» и в срез `G1–G2` не попадает. Ему нужен добавочный
срез: якоря `^- \*\*Кодовый регистр в «Назначении»` … `^- \*\*Имена сервисов`, вставленные в промпт
после блока «Гейт (Шаг 4)» (например, под переменной `SM_GATE_EXTRA=kod`). Без него ожидание этого
двойника не действует, грейдер печатает предупреждение.

Случаи `LEAD/` — самодостаточные промпты (вопрос и варианты последней строки уже внутри файла); к ним
нужен только срез скилла, названный в `expect.json` (`slice`): для `interrupted-*` — от
`^#### 3.4 После возврата` до `^**Вторая попытка не помогла` включительно, для `dobor-brief` — якоря
`U1–U2` из `run-sm-gate.sh`. Раннер — копия цикла `run-sm-gate.sh` с `FIX` на `LEAD/` и промптом
«<срез> --- <case>». Папка вывода — `<раунд>/sm-lead/<case>/answer-N.md`.

Что НЕ покрыто изолированно и почему — в `REAL/README.md`: перенабор карточки ведущим (дефект 2,
файловая половина), чтение соседней карточки (4) и сам обрыв инструмента (8) видны только по трассе
реального прогона.

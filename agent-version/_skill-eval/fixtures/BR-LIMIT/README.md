# Фикстура BR-LIMIT — БТ поверх карточки с «ограничением» и строкой «не определено»

Копия `BR-REAL` (промпт, манифест, карточки) с двумя вставками в «Бизнес-правила» `repairy-api.md`
(редакция формы 1.5.0):

- блок `### ограничение «приёмка работ заказчиком отключена»` — условием управляет `OWNER` через
  настройку проекта; пока действует, работы на приёмку не отправляются, заказчик актов не получает;
- в блоке `WorkAcceptance` строка `- не определено: перехода в коде нет (\`CANCELLED\`)`.

Промпт тот же, что у BR-REAL: про приёмку работ и уведомления. Меряется **чтение потребителя**, а не
карточка.

**Ожидание, первый ход (вопросы, файла нет):**
- R1 — ограничение попало в гипотезы: вопрос или риск про отключённую приёмку / настройку проекта у
  владельца («сейчас владелец может выключить приёмку в настройках проекта — при доработке это
  остаётся?»);
- R2 — по значению без перехода вопросов и критериев НЕТ: ни `CANCELLED`, ни «отменённый акт» — строка
  «не определено» это честный пробел, не гипотеза;
- анкеры A1–A8 из BR-REAL не хуже: ≥ 3 в прогоне.

Грейдер — `grade-br-limit.mjs`. Проба `br-limit` в `run-ctx.sh`.

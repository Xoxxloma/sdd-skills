# SQ-AUDIT — фикстура `sdd-quality-audit`

Папка `docs/` из девяти фич, четырнадцать оцениваемых документов. Скилл обходит её целиком и пишет
`sdd-quality-report.md` в корень песочницы. Грейдер — `grade-sq.mjs`. Проба — `sq-audit` в
`run-ctx-v2.sh`, промпт — `audit-prompt.txt`.

## Состав и эталон

Баллы — по рубрикам `sdd-quality-audit/reference/rubric-*.md` в корне репозитория. Диапазон — то, что грейдер принимает;
он шире точки, потому что якоря мягкие и «колеблешься — старший».

**Требуют внимания** — обязательно `PSS-2213` (БТ и спека) и `PSS-2214` (БТ не по форме); запрещены
`PSS-2210`, `PSS-2211`, `PSS-2212`, `ARS-312`. Заглушки эпика не проверяются: они и правда пустые.

**Не по форме** — только БТ `PSS-2214`; у `PSS-2210`, `PSS-2211`, `PSS-2212`, `PSS-2213`, `ARS-312` —
«нет». Заглушки эпика не проверяются. В «Деталях» — только подсвеченные документы: `PSS-2213` (оба) и
`PSS-2214` (только БТ); хороших и частичных там нет.

## Ловушки

- Примеры в рубриках — другие предметные области (поверка, сметы, отпуска); переговорных и
  пропусков в рубриках нет, иначе прогон узнаёт пример, а не применяет якорь.
- `PSS-2210` и `PSS-2211` — один и тот же текст в двух поколениях шаблона: разница в баллах = скилл
  цепляется к форме. «Не по форме» у `PSS-2210` (английские подписи, «слайсы», «Сроки и
  обоснование», нет §1.4/§3.4/§4.3) — проверка формы не знает старых версий шаблона.
- `PSS-2214` — тот же текст без шаблона: балл ниже `PSS-2211` = форма просочилась в баллы. Спека
  `PSS-2214` — недобор ниже порога: «не по форме» у неё = порог 25% не держится.
- `PSS-2213` заполнен строго по шаблону — содержательно пустой документ «по форме»: форма и баллы
  меряют разное.
- Заглушки эпика сделаны под маршрут оркестратора, не под эту пробу: проверяется только, что строки
  есть и колонки «н/п» / «спеки нет» верны.

# Фикстура RV-LIM — документ без примера на границе в приёмке (`spec-review`)

Заведена 2026-10-26 под п.2 `PLAN-FROM-POCOCK.md`, шаг 4. Документы — замороженные выходы скиллов этого же
раунда: БТ `EXP-310` — `br-lim-w` run-1 (`runs/2026-10-26-p2-s1`), запрос на правку `ARS-326` — `cr-lim-w`
run-1 (`runs/2026-10-26-p2-s2`). Грязные двойники — те же файлы с другим ключом, у которых пример на границе
вырезан: `EXP-311` — у FR-2 (порог 7 500 ₽) и FR-3 (срок до 25-го) по одному значению; `ARS-327` — у `FR-1`
«до 25 фотографий» без 26-й, и из «Как проверят» 26-я тоже убрана. Больше двойники от чистых ничем не отличаются.

## Что сторожит (с `spec-review` 1.5.0)

Пример на границе — форма гипотезы у писателей, а не условие закрытия гейта
(`business-requirements-doc/SKILL.md:785–786`, `change-request-doc/SKILL.md:342–344`). В чек-листах приёмки о нём
ни слова: `checklist-bt.md` и `checklist-changerequest.md` в 1.5.0 возвращены к виду ea0304a3, справочная строка
«…с порогом без примера на границе: N» убрана — оркестратор принимал её за повод предложить «Поправить» на
чистом документе (`rt-count-*`). Значит, отсутствие примера в отчёт не попадает никак: ни нарушением, ни советом,
ни счётной строкой.

| Проба | Промпт | Верно |
|---|---|---|
| `rv-lim-clean` | `bt-clean-prompt.txt` | `нарушений: 0`; строки о границе нет; совета про границу нет |
| `rv-lim-dirty` | `bt-dirty-prompt.txt` | то же — главная проба: пример вырезан, а отчёт тот же |
| `rv-crlim-clean` | `cr-clean-prompt.txt` | `нарушений: 0`; `решений, стоящих только на слове аналитика: 1`; строки о границе нет; совета нет |
| `rv-crlim-dirty` | `cr-dirty-prompt.txt` | то же |

## Откуда «верно»

- `нарушений: 0` — `checklist-bt.md:3–6`, `checklist-changerequest.md:3–6`: каждый пункт — нарушение правила
  писателя, сверх списка не проверять; о примере на границе пункта нет. Пункты нарушений с 1.2.0 не менялись
  (1.5.0 убрал только справочную строку) и на этих документах дали 0 в 35 из 36 прогонов; в оставшемся — шапка «3» при
  «нарушений записанных правил нет» (`spec-review/SKILL.md:137`: число — ровно то, что вернул субагент).
- Строки о границе нет — `spec-review/SKILL.md:165`: счётные строки «ровно те, что вернул субагент по
  чек-листу»; `checklist-bt.md:172–184` — у БТ счётной строки нет; `checklist-changerequest.md:175–189` — у
  запроса одна, строка 🔵.
- Совета нет — `spec-review/SKILL.md:15–18` («ни одной просьбы что-нибудь дописать «для полноты»»), `:28–30`
  (перечисляется только нарушение записанного правила); у писателей — «границу не переспрашивай».
- Строка 🔵 = 1 — `checklist-changerequest.md:160–167`, `:188`; `spec-review/SKILL.md:173` (счётные строки
  обязательны и при нуле нарушений). В «Как должно стать» у `ARS-326` и `ARS-327` один пункт, `FR-1`, с 🔵
  (`change_request.md:31`).

**Справкой, в зелёное не входит:** упоминание примера на границе без совета («у двух критериев нет примера на
границе») — правила о прозе ведущего после отчёта нет; совет или перечень к строке 🔵 (`SKILL.md:165–167`) —
правило записано, но проба не про 🔵.

## Прежняя форма (5.74–5.80, `spec-review` 1.2.0–1.4.1)

До 1.5.0 проба мерила саму счётную строку: БТ `критериев с порогом без примера на границе: 0` / `2`, запрос
`«как должно стать» с порогом без примера на границе: 0` / `1`, при `нарушений: 0`. Прогоны на ней —
`runs/2026-10-26-p2-r2`, `-p2-r3`, `-p2-s4`, `-cov-c`, `-top-rv1`: по прежнему грейдеру 34/36, по нынешнему 0/36 —
строка о границе есть в каждом, так и должно быть. Без этого признака нынешнему критерию отвечают 33/36:
красные — шапка «нарушений: 3» (`p2-r2` dirty run-2) и два совета про границу (`p2-s4` dirty run-2 «дополните
эти критерии примерами на границе», `p2-s4` cr-dirty run-2 «стоит перечитать» — прежний грейдер его пропускал).

Грейдер — `grade-rv-lim.mjs --case=bt-clean|bt-dirty|cr-clean|cr-dirty` (`--selftest`).

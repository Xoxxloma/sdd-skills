# Фикстура AR-BATCH — пачка релиза и история карточек

Основной путь архивации: релиз уехал, аналитик архивирует его задачи **одной пачкой** — один скан
на всё. Проба меряет, что пачка собрана из переданных ключей и только из них, что история карточек
`services/_history/` дописана строкой «дата | задача | описание» на каждую задачу в каждом изменяемом ею сервисе.

## Дерево

```
docs/
  SHP-11/technical_specification.md   <- в пачке: orders-api (вызов + поле), shop-web (кнопка)
  SHP-12/technical_specification.md   <- в пачке: orders-api (лимит §5.1, выгрузка CSV — скан «не найдено»)
  SHP-14/technical_specification.md   <- НЕ в пачке, черновик: не трогать
  SHP-15/technical_specification.md   <- в пачке, багфикс: shop-web; orders-api и admin-web — потребители
services/
  manifest.yaml, orders-api.md, shop-web.md, admin-web.md
  _history/orders-api.md              <- две прежние строки: не правятся, новые — в конец
                                         у shop-web истории нет — файл создаётся
stubs/service-map/SKILL.md            <- отвечает отчётом быстрого обновления по таблице слов
```

## Ожидаемое

1. Состав — SHP-11, SHP-12, SHP-15; SHP-14 не назван в составе и метки не получает.
2. Один вызов скана с `orders-api` и `shop-web`.
3. Метки `.archived` в трёх папках пачки.
4. `_history/orders-api.md`: прежние две строки байт-в-байт, дальше по строке SHP-11 и SHP-12; строки
   SHP-15 нет — orders-api у неё «потребитель».
5. `_history/shop-web.md` создан с шапкой; по строке SHP-11 и SHP-15; строки SHP-12 нет.
6. Строка — дата, задача, описание из заголовка спеки; дата у всех новых строк одна. CSV, которого
   скан не нашёл, назван в отчёте в чат.
7. `admin-web` — потребитель без изменений (Р5): назван в отчёте, в скан не отдан, истории нет.
8. Карточки и манифест не тронуты.

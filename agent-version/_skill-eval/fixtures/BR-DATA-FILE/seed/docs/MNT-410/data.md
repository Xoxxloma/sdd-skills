# Состав данных: заявка на ремонт от системы мониторинга станков

Заявка приходит от системы мониторинга станков. У заявки один станок и одна или несколько неисправностей.
Технические имена в скобках — для разработчиков, бизнесу они не нужны.

- **Станок**
  - Инвентарный номер станка (`machine.invNo`) — видно в карточке заявки; идёт в отчёт по простоям
  - Цех (`machine.workshop`) — видно в карточке заявки и в фильтре списка
  - Модель станка (`machine.model`) — видно в карточке заявки
  - Дата последнего планового ремонта (`machine.lastServiceDate`) — видно в карточке заявки; в отчёт не идёт
- **Неисправность** (у заявки одна или несколько)
  - Код неисправности (`fault.code`) — видно в карточке заявки; идёт в отчёт по простоям
  - Описание неисправности от системы мониторинга (`fault.text`) — видно в карточке заявки
  - Время обнаружения неисправности (`fault.detectedAt`) — видно в карточке заявки; идёт в отчёт по простоям
  - Признак остановки станка (`fault.stopped`) — видно в карточке заявки; если станок остановлен, заявка срочная
- **Заявка на ремонт**
  - Номер заявки (`request.number`) — видно в карточке и в списке заявок
  - Уровень срочности (`request.urgency`) — видно в списке заявок, выделен цветом
  - Ответственный мастер (`request.master`) — назначает начальник смены; видно в списке заявок
  - Плановая дата устранения (`request.dueDate`) — видно в карточке заявки; идёт в отчёт по срокам

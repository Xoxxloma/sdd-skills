## ход 3
По событию возврата — иначе, поправлю: сообщение о возврате уходит пачкой раз в минуту, а не на каждый
возврат. Из кода по этому событию ничего не беру — пиши с моих слов.

Остальное:
- Номер задачи — RNT-41, спеку клади рядом с БТ.
- Стороны: только бэкенд. Приложение показывает push как есть, в нём ничего не меняем.
- Push клиенту отправляет customer-notify — наш сервис, команда «Клиентские уведомления». Отправка push
  клиенту по его идентификатору в нём уже есть, ей пользуемся. Подписка на возврат — новая, тоже в
  customer-notify: шину он сейчас не читает, чтение заводим в этой задаче.
- tool-rental — сервис команды «Прокат», в нём ничего не меняем.
- Повтор отметки возврата отсекаем в customer-notify: об одном возврате — один push. Отметки о
  разосланных храним 30 дней.
- При первом запуске подписка читает с текущего места: старые возвраты не рассылаем.
- Текст: заголовок «Инструмент принят», в тексте — «в пункте проката» с датой и временем по Москве и,
  если отмечена поломка, строка «При приёмке отмечена поломка».
- Клиент не найден или у него нет приложения — push не уходит, пишем в лог, и только.
- Если сообщение о возврате до customer-notify не дошло, push не уходит; досылку в этой задаче не делаем.
- Если отправка push не удалась, повторяет сам customer-notify, как сейчас.
- Доступ: ручек для людей нет, ролей не заводим.
- Нагрузка: около 2000 возвратов в день, в субботу до 600 в час.
- Выкат: обычным релизом customer-notify, фиче-флаг не нужен. До релиза: выдать customer-notify доступ
  на чтение сообщений о возврате — заявкой в платформу шины.
- Сроки и приоритет — как в БТ.

# Техническая спецификация: история назначений ГБР

> **Статус готовности:** Готово к разработке
> **Задача:** ARS-102

## 1. Обзор изменения

### 1.1. Тип и стороны
Fullstack. Новый экран истории назначений, использует справочник ЧОП из узла #0.

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| `incident-web` | новый экран | Фронт | 🟢 |
| `geo` | потребитель справочника #0 | Гео | 🔵 подтв. аналитиком |

### 1.3. Связь с бизнес-требованиями
Аналитик должен видеть, какие ГБР выезжали на инцидент раньше.

## 2. Взаимодействия (ядро)

### INT-1. Справочник ЧОП — 🔵
- **Граница/направление:** Сервис incident-web → Сервис geo
- **Контракт (запрос):** `GET /v1/chops`, параметр `regionId`
- **Контракт (ответ):** унаследован от узла #0 без изменения состава
- **Происхождение:** 🔵 подтверждено аналитиком (унаследовано от #0)
- **Трассировка:** FR-3

## 4. Frontend — ответственность

### 4.1. Где и что меняется в UI
Новый экран `/incidents/:id/history` — история назначений ГБР по инциденту: дата, ГБР, ЧОП,
время прибытия.

### 4.2. Пользовательские сценарии
Аналитик открывает карточку инцидента, переходит в историю, видит прошлые выезды с названиями ЧОП
из справочника `geo`.

### 4.4. Доступ по ролям в UI
Экран доступен ролям `analyst` и `dispatcher`; `viewer` его не видит.

## 7. Трассировка приёмки

| FR | Как проверяется |
|----|-----------------|
| FR-3 | На экране истории видны прошлые назначения с названием ЧОП |

# ID-PT — схема по списку пунктов (`*.points.md`): короткая по встрече, путь пользователя по выгрузке ноута

Домен выдуман: приют, пристройство животных. Посетитель выбирает животное на сайте приюта, отправляет анкету,
волонтёр звонит и назначает знакомство, после договора животное уходит к хозяину. Ключ задачи — **ADP-41**.
Люди выдуманы: Ярошевич М. А., Ольшанская В. Д., Ступак Т. Л., Белогур И., Гайдамак Р.

Эталон — по требованию владельца, не по тексту скилла. На схему идут только пункты `решено` и `сведение`;
`открыто` — только если аналитик ответил, как решено; `мысль`, `набросок`, «не входит» — никогда. id пункта — `п.N`,
N — порядковый номер строки-пункта в списке, с 1. Ноут и спека схему не питают — только список.

(п.5, п.6) и «animal-registry» (п.9) — два участника, пока аналитик не сказал, что это одна система. Стрелка — от

## Ловушки

- **Ноут рядом с выгрузкой.** В ноуте есть пункты, которых в выгрузке нет: заменённый «Посетитель приходит в приют и
  заполняет бумажную анкету» (2026-10-01 №1, `вместо:` в 2026-10-06 №2) и закрытый вопрос «Кто звонит посетителю после
  анкеты» (`отвечает на:` в 2026-10-06 №1). На схеме их нет: основы `бумаж` в узлах быть не должно.
- **Спека и старая схема рядом со списком встречи.** Участников «Кабинет волонтёра», «СМС-шлюз» и путей
  `/v1/animals/{id}/photos`, `/v1/sms` на новой схеме нет; «Реестр животных» в спеке — не основание склеить его с
  «animal-registry» без ответа.
- **«Не входит».** п.8 встречи (система электронной подписи) и п.5 выгрузки (доставка домой) — не на схеме; участника
  «Система электронной подписи» нет.
- **Мысль и набросок.** п.2 (посетитель сам выбирает время) и п.6 (напоминание за день) выгрузки — действия процесса,
  но не на схеме.
- **Открытые и без направления.** Без ответа п.5 и п.10 встречи, п.8 выгрузки — без стрелки и без узла; на «Не знаю.»
  первый вариант не выбирается.
- **Порядок.** В обоих списках порядок пунктов — не порядок процесса; без ответа стрелки идут по номерам.

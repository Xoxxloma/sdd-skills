## Правила раунда — записаны до работы

- Оценщик правится **до** прогонов. После прогона — только с перегрейдом обоих сравниваемых кругов и отдельной
  строкой в отчёте.
- Грейд — только после завершения **всех** прогонов круга. Папки `run-*` не удаляются до закрытия раунда:
  от прошлой петли выходов не осталось, перепроверить нельзя.
- Правка скилла — только при (а) лжи вопреки фактам или (б) поломке основного пути. Неудобство → «известные стыки».
  На одну проблему — не больше двух кругов.
- Правка — 1–2 строки на находку, обоснование — в CHANGELOG, не в SKILL.md. В тексте скиллов ни слова из проб,
  проверка — скриптом утечек (шаг 2.3).
- Проба, ожидание которой не следует однозначно из текста скилла, — не красная, а «стык в тексте».

## Фаза 1 — оценщики и пробы

### 1.1 Общая проверка опоры — главное

Новый модуль `ground-check.mjs`, подключается ко всем четырём оценщикам. Каждое число (цифрой и словом), фамилия
в `решил:` / `ждёт:` / `со слов`, роль в шапке, латинский токен выхода должны найтись в источнике. Не нашлось —
**красный**.

| Оценщик | Выход | Источник |
|---|---|---|
| `grade-meet` | пункты списка и роли шапки `> Встреча:` | расшифровка L−2…L+2 от ссылки, документ задачи |
| `grade-ni` | **каждая строка входа**, не только узнанные | текст списка + реплики аналитика |
| `grade-recall` | итог протокола и список | шапка, «Заметки», строки `Аналитик:` — не итог, который пишет агент |
| `grade-nb` | новая запись ноута / выгрузка / выкладка | текст вызова + `>` / пункты ноута |

### 1.2 Точечные правки оценщиков (по ревью)

- **Ложный зелёный → красный:**
  - сторона решения: парный запрет на обратное утверждение у каждого якоря отрицания;
  - «не» засчитывается только в двух словах от ключа;
  - неверный ключ в `> Задача:` проверяется целым токеном;
  - у `[открыто]` с вариантами во входе — «?» или оба варианта;
  - роль сверяется парой «роль — ФИО»;
  - `вместо:` / `отвечает на:` на не тот пункт;
  - выгрузка не строками `- [`;
  - набросок «решено» в выкладке в чат;
  - заголовок списка — первой строкой.
- **«Не измерено»** — только при отказе API. Прогон, который молча кончился без файла, — красный «файл не записан».
- **Ложный красный → убрать:**
  - пометка «не про задачу» вынесена из исхода прогона;
  - регэкспы «стенд недоступен», «ИБ» на слух, диапазоны «от 20 до 30»;
  - слово сводки у пункта не из входа;
  - «не входит» в «Решено»;
  - «1 200» = «1200»;
  - пометка «(предложение аналитика)» по смыслу.
- **Мёртвое:**
  - `grade-mr` одиночный режим — в архив;
  - засев сверяется со снимком, взятым при засеве (`_seeded.txt`), а не с текущей фикстурой;
  - якоря самопроверки — без опоры на удалённые `run-*`.

### 1.3 Приёмка оценщиков — до любых прогонов

Самотест каждого оценщика в `selftest/loop/`, три прогона:
- эталон → максимум;
- пустышка → ноль;
- **набор мутаций эталона → каждая красная.** Набор мутаций:
  - выдуманное число;
  - выдуманное имя в `решил:`;
  - подмена решившего;
  - перевёрнутое решение;
  - открытое → решённое;
  - лишняя строка во входе;
  - `вместо:` на не тот пункт;
  - выгрузка `1. [решено]`;
  - роль, которой не было на встрече;
  - пропавший файл.

Набор записывается до правки оценщика. Мутация, прошедшая зелёной, — оценщик не принят.

### 1.4 Эталоны и засевы — поправить

- Роли в шапке `MEET-*/etalon-2`: оставить только названные на встрече или в документе. Засевы `NI-CHG/VAC/NEW`

- Спорные `[решено]` в `MEET-VAC:8` и `MEET-LONG:7,16–18` отдать слепому прочтению. Два прочтения → в эталоне

## Фаза 2 — правки скиллов, одним батчем

### 2.0 Как правим — урок прошлой петли

В прошлых кругах правки по одной создавали новые баги: каждая чинила побочку предыдущей. Поэтому:

1. **Сначала черновик всех правок, файлы не трогаем.** Один файл `runs/<дата>-harden-edits.md`: по каждой
   правке — место, старый текст, новый текст, какую находку закрывает.
2. **Сверка правок между собой.** Таблица «правка × правка»: какие задевают одно место, одно понятие (вид пункта,
   метку, имя файла, шаг) или один стык. Две правки об одном — сводятся в одну.
3. **Сверка каждой правки с телом скиллов.**
   - Grep ключевых слов правки — метки, термины, номера шагов, имена файлов — по всем четырём скиллам и их
     `reference/`.
   - Каждое найденное место — согласовано или правится в том же черновике.
   - Правка ниже TL;DR не спорит с TL;DR: там действует «прав список».
   - Форма, которую пишет один скилл, читается другим так же.
4. **Ревью черновика** — `skill-review` в режиме «правка», два свежих субагента. Противоречие новой строки со
   старым текстом — находка. Находки — в тот же черновик, **один** такой цикл.
5. **Применение одним заходом,** самотесты оценщиков и `leak-check.mjs`. Только потом прогон.
6. **После прогона — без цепочек.** Красное по (а) / (б) — новый черновик по той же процедуре, не точечная правка.

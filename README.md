# product-skills

Два SDD-пайплайна (Spec-Driven Development) — набор скиллов для AI-харнесса — и стенды, на которых
они замеряются. Скиллы рассчитаны на **слабые нетоповые модели**: формулировки и форма документов
подбираются так, чтобы их держал Haiku-класс, а не только топовая модель.

| Папка | Что это |
|---|---|
| `agent-version/` | **Петля аналитика.** Документация задачи от бизнес-требований до файлов задач исполнителям. Рабочая версия. |
| `front-loop-2.0/` | **Фронтовый пайплайн.** Три живых документа проекта + цикл разработки фичи. Рабочая версия. |
| `front-loop/` | Замороженный baseline фронтового пайплайна (9 скиллов) — «до» для замеров `front-loop-2.0`. |
| `_skill-eval/`, `*/_skill-eval/` | Стенды: пробы, фикстуры, грейдеры, прогоны. |

## `agent-version/` — петля аналитика

Вход — `analyst-workspace`: оркестратор в основном треде. Он спрашивает, что уже на руках, и сам
зовёт нужный под-скилл; имена под-скиллов аналитику знать не нужно.

Маршрут документов:
`business_requirements.md` → (эпик режется) дочерние БТ → `technical_specification.md` →
`stages/stage-NN.md`. Всё пишется в `docs/<TASK-KEY>/`.

| Скилл | Делает |
|---|---|
| **analyst-workspace** | Оркестратор: ведёт вопросами, выбирает следующий шаг, запускает под-скиллы. |
| **business-requirements-doc** | Интервью → БТ (BRD→SRS). Первый вопрос — ключ задачи; неподтверждённое уходит в TBD. |
| **bug-report-doc** | То же для дефекта: `bug_report.md` как документ-источник спеки на починку. |
| **task-decomposition-doc** | Режет эпик-БТ на дочерние БТ по отдельным поставкам. Ничего не выдумывает — только делит. |
| **technical-spec-doc** | БТ → тех-спека вокруг **стыков** (контракты между сервисами и FE/BE), а не по слоям. |
| **stage-breakdown-doc** | Спека → самодостаточные файлы задач по этапам для параллельной раздачи исполнителям. |
| **spec-review** | Приёмка формы: субагент с чистым контекстом ищет нарушения шаблона. Не оценивает решение. |
| **spec-readiness** | «Достаточно ли спеки, чтобы писать код»: три субагента (BE / FE / стык) ищут невыведенные следствия. |
| **service-map** | Слепок соседних сервисов: карточка на сервис + манифест. Опционален. |
| **repo-split** | Режет слишком большую репу на куски для `service-map`. Нужен только на монолите. |
| **context-doc** | Кладёт документ человека в `context/` в том виде, в каком его читает петля. |
| **archive-spec** | Помечает спеку архивной, когда фича уехала в прод, и перечитывает затронутые сервисы. |

История правок и замеров — `agent-version/CHANGELOG.md`.

## `front-loop-2.0/` — фронтовый пайплайн

8 скиллов, оркестратора нет: зовутся по имени, поток само-секвенится хендоффами. Карта и
шпаргалка — `front-loop-2.0/PIPELINE.md`.

Три живых документа: `docs/dev/PROJECT.md` (техническое, `project-baseline`),
`docs/dev/BUSINESS.md` (бизнес, `business-baseline`), `docs/dev/DESIGN.md` (дизайн,
`design-baseline`). Дальше — `inspire` (идеи) → `writing-plans-front` (план-пак) →
`executing-plans-front` (исполнение) → `sync-project-doc` (инкремент складывается обратно в
документы). `generate-theme` заводит тему и токены, когда дизайн-системы в проекте нет.

## Установка

Скиллы копируются в каталог скиллов харнесса — целиком папка версии:

```
cp -r agent-version/*/    <harness>/.claude/skills/    # Claude Code
cp -r front-loop-2.0/*/   <harness>/.claude/skills/
```

`_skill-eval/` и `CHANGELOG.md`/`PIPELINE.md` — не скиллы, копировать не нужно.
Для других сред — соответствующий каталог (`.agents/skills`, `.gigacode/…` и т.д.).

## Стенды

Замер идёт на слабой модели (Haiku, low effort) через пробы: фикстура + промпт + грейдер,
считающий факты в артефакте. Пробы и фикстуры — `PROBES.md` / `fixtures/` в стенде,
план раунда — `PLAN*.md`, прогоны — `runs/`. Известные ловушки замера — `agent-version/_skill-eval/DEFECTS.md`.

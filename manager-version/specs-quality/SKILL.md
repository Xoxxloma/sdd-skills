# Оценка качества БТ и спек

На входе — папка с документами (ищутся во всей вложенности), файл или ключ задачи. На выходе — один файл
`<корень>/specs-quality-<дата>.json` (формат specs-quality/2); корень — ближайшая папка с `.git`, без репозитория —
папка, где лежит вход.

Считают скрипты из `reference/` рядом с этим файлом (путь — из строки «Base directory for this skill»). Твоя
работа — запустить их по порядку и раздать документы субагентам. Сам документы не открывай и не оценивай, баллы
не считай и не пересказывай: итог и подсветку ставит `merge.py`.

## Аргументы

- Вход — первый аргумент. Нет — спроси путь и остановись. Ссылку на веб-репозиторий открыть нельзя — попроси
  путь к локальному клону.
- Команда и репозиторий — второй и третий аргумент; не дали — не спрашивай.
- `--parallel N` — сколько субагентов работают одновременно; по умолчанию **5**. Если на ответы приходит 429 —
  перезапусти с `--parallel 1`.
- `--params <файл>` — свой файл весов и порогов на этот прогон; передай его в шаг 1 как есть.

Дальше: `<скилл>` — папка этого скилла. Python — `python3`, на Windows — `python`.

## Шаг 1. Сбор

```
python3 <скилл>/reference/collect.py --input <вход> [--team <команда>] [--repo <репозиторий>] [--params <файл>]
```

Скрипт печатает строки с источником каждой спеки, затем `Работа: <папка>` и `Итог: <файл>`. Покажи пользователю
список строк и сразу продолжай. Скрипт упал, ответил ошибкой входа или «Документов: 0» — покажи его вывод и
остановись. Дальше `<работа>` — папка из строки `Работа:`.

## Шаг 2. Субагенты

Открой `<работа>/collect.json` инструментом чтения файлов, в папку `<работа>` не переходи: её удалит `merge.py`. В
списке `documents` у каждого документа есть `task` и `answer`. На каждый документ — один субагент с таким заданием
(подставь полные пути):

> Прочитай задание `<работа>/<task>` и ответь строго по нему: только JSON, без текста до и после. Других файлов,
> кроме названных в задании, не открывай, ничего не записывай, своих субагентов не запускай.

- Запускай не больше N субагентов одновременно: N вызовов в одном сообщении, дождись всех ответов, потом следующие N.
- Ответ субагента запиши как есть, без правок, в `<работа>/<answer>`. Субагент упал — файл не пиши.
- Документы и ответы сам не читай и не пересказывай: ты передаёшь путь и записываешь ответ.

После всех волн:

```
python3 <скилл>/reference/merge.py --work <работа> --check
```

Скрипт перечисляет ответы, которые не годятся, — с путями задания и ответа. На каждый — субагент ещё раз, один раз,
теми же волнами; новый ответ запиши поверх прежнего. Снова не годится — оставь: `merge.py` отметит документ «оценка
не состоялась».

## Шаг 3. Итог

```
python3 <скилл>/reference/merge.py --work <работа>
```

Скрипт собирает JSON, проверяет его по `reference/specs-quality.schema.json` и после записи удаляет `<работа>`.
Ответил «Выход не прошёл contract.py» — покажи его вывод пользователю и остановись: руками файлы не правь.

## Шаг 4. Показать

Покажи пользователю вывод `merge.py` как есть: путь к JSON, счёт документов, что поправлено в ответах и список
«Требуют внимания».

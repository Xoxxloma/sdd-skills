# Оценка сессий пользователя

На входе — папка с выгрузками сессий одного пользователя: `*.json`, один файл — одна сессия (события хуков агента). На выходе — два файла:
`<пользователь>-<дата>.json` (формат session-quality/4) и отчёт `<пользователь>-<дата>.md`.

Считают скрипты из `reference/` рядом с этим файлом (путь — из строки «Base directory for this skill»). Твоя
работа — запустить их по порядку и раздать журналы субагентам. Сам ничего не считай, не оценивай и не
пересказывай содержимое сессий: числа, скор и статус ставит `merge.py`.

## Аргументы

- Папка сессий — первый аргумент, обязательно. Нет — спроси путь и остановись.
- `--parallel N` — сколько субагентов работают одновременно; по умолчанию **5**. Если на ответы приходит 429 —
  перезапусти с `--parallel 1`.
- `--params <файл>` — свой файл порогов и весов на этот прогон; по умолчанию `<скилл>/reference/params.json`. Передай
  его в шаги 1 и 3 как есть.

Дальше: `<скилл>` — папка этого скилла, `<сессии>` — папка сессий, `<итог>` — папка `<сессии>-quality` рядом с ней,
`<работа>` — `<итог>/work`. Python — `python3`, на Windows — `python`.

## Шаг 1. Сбор

```
python3 <скилл>/reference/collect.py --sessions <сессии> --out <работа> [--params <файл>]
```

Скрипт печатает счёт сессий и сверку событий выгрузки. Если он упал, ответил «Параметры не годятся» или «Сессий: 0» —
покажи пользователю его вывод и остановись. Строки «не найдено» в сверке событий не ошибка: покажи их пользователю в конце.

## Шаг 2. Субагенты

Открой `<работа>/collect.json`: в списке `sessions` у каждой сессии есть `session` и `journal`. На каждую сессию —
один субагент с таким заданием (подставь полные пути):

> Прочитай задание `<скилл>/reference/brief.md` и журнал `<работа>/<journal>`. Ответь строго по заданию: только JSON,
> без текста до и после. Других файлов не открывай, ничего не записывай, своих субагентов не запускай.

- Запускай не больше N субагентов одновременно: N вызовов в одном сообщении, дождись всех ответов, потом следующие N.
- Ответ субагента запиши как есть, без правок, в `<работа>/<session>.findings.txt`.
- Субагент упал или ответил без JSON — после всех волн запусти его ещё раз, один раз. Снова нет ответа — не
  записывай файл: `merge.py` отметит сессию как «нет ответа модели».
- Журналы и ответы сам не читай и не пересказывай: ты передаёшь путь и записываешь ответ.

## Шаг 2б. Перепроверка фрода

```
python3 <скилл>/reference/verify.py --work <работа>
```

Скрипт печатает число заданий и их имена в `<работа>/verify/`. Заданий 0 — переходи к шагу 3. Иначе на каждое
задание — один субагент, так же волнами не больше N:

> Прочитай задание `<работа>/verify/<имя>` и ответь строго по нему: только JSON, без текста до и после. Других файлов
> не открывай, ничего не записывай, своих субагентов не запускай.

- Ответ запиши как есть в `<работа>/verify/<имя>.answer.txt`. Упал или без JSON — один повтор после всех волн; снова
  нет — файл не пиши: находка останется к ручной проверке.

## Шаг 3. Итог

```
python3 <скилл>/reference/merge.py --work <работа> --out <итог> [--params <файл>]
```

Скрипт проверяет выход по `reference/session-quality.schema.json`, пишет JSON и отчёт и убирает `<работа>`. Если он
ответил «Выход не прошёл contract.py» — покажи его вывод пользователю и остановись: руками файлы не правь, `<работа>`
остаётся для разбора.

## Шаг 4. Показать

Покажи пользователю содержимое `<итог>/<пользователь>-<дата>.md` целиком, путь к JSON и строку «Записей об
отброшенном: K» — если K > 0, в ней путь к `<итог>/<пользователь>-<дата>.log.txt`: там, что из ответов субагентов
отброшено и почему. Скор со статусом «не окончательный» — так и называй: сначала смотрят сигналы фрода.

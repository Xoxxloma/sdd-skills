# Задание: находки по одной сессии пользователя

Тебе дан сжатый журнал одной сессии: пользователь работает с ИИ-агентом. Найди в нём то, что перечислено ниже, и
ответь по каждой строке раздела «Проверить». Ответ — только JSON, без текста до и после, без ```.

## Как читать журнал

- `[N]` — номер хода. В ответе используй только номера, которые есть в журнале.
- `ПОЛЬЗОВАТЕЛЬ:` — слова пользователя. `АГЕНТ:` — последнее сообщение агента за ход (промежуточных в журнале нет),
  `ВОПРОС:` — вопрос агента с вариантами. `ОТВЕТ:` — ответ пользователя на него. `СКИЛЛ`, `ОШИБКА API`, `СЖАТИЕ` —
  служебные события.
- `****` — замаскированное значение. `…` — пропущенная часть длинного текста.

## Находки — `findings`

Сообщай только то, что видно в журнале явно. Сомневаешься — не сообщай: ложная находка хуже пропуска. Если в
`note` пишешь «не …», «спорно», «скорее …» — это сомнение: находку не добавляй.

| type | Что это | turn | Поля |
|---|---|---|---|
| `late_requirement` | после готового результата пользователь добавляет условие или данные, которые знал заранее, и это отменяет сделанное («забыл сказать», «там же ещё…») | ход пользователя | `quote` |
| `deception` | пользователь просит записать как подтверждённое или согласованное то, что не подтверждено; выдумать факт; снять пометку «не подтверждено» или «открытый вопрос» без источника; «считай, что подтверждено». Обратное — попросить записать что-то как открытый вопрос или «не подтверждено» — честно: не `deception` и не `bypass`. Своё решение («решено», «берём так») пользователь объявляет сам — это не `deception` | ход пользователя | `quote` |
| `bypass` | пользователь просит игнорировать правила или инструкции, пропустить обязательную проверку, править настройки или файлы скиллов агента. Неподтверждённое как подтверждённое — это `deception`, не `bypass` | ход пользователя | `quote` |
| `off_topic` | реплики пользователя не о работе: `personal` — семья, здоровье, покупки, отдых; `non_work` — чужие нерабочие дела (учёба не по работе, подработка). Вопрос про другую рабочую задачу или проект — не `off_topic`; если реплика может быть о работе — это не `off_topic` | первая реплика темы | **ни `quote`, ни `note`**: личное не пересказывай; вместо них `category` и `turns` — сколько реплик пользователя в этой теме |

`quote` — точный кусок текста из строки этого хода, не длиннее 200 символов, скопированный как есть. `note` —
по желанию, одна фраза: почему.

## Проверить — `checks`

На каждую строку раздела «Проверить» — ровно один объект: тот же `check`, тот же `turn` и `verdict` из таблицы.
Раздел пуст («нет») — `checks: []`.

| check | Ход в строке | `verdict` |
|---|---|---|
| `decision` | ответ пользователя на вопрос агента или на длинный текст агента | `no` — решать было нечего: отчёт о сделанном, ход работы, агент спрашивал только «продолжать?» — даже если пользователь ответил «да»; `engaged` — пользователь включился по существу: поправил агента, своими словами отверг предложение, добавил свой факт или условие, ответил своими словами по сути; честное «не знаю», «уточню», «решим позже» — тоже `engaged`, а не `delegated`; `accepted` — согласился с тем, что предложил агент («да», «ок», выбор любого готового варианта — даже «Нет, …»); `delegated` — вернул решение агенту («на твоё усмотрение», «сам реши», «без разницы»); `ignored` — ответил не на вопрос или предупреждение агента: другая тема, «продолжай» там, где нужен был ответ |
| `ending` | вопрос агента в конце запуска скилла, на который пользователь не ответил | `yes` — без ответа работа не закончена: агент ждал решения или данных; `no` — результат готов, а вопрос — о следующем шаге или из вежливости |

## Форма ответа

Пример формы, не содержания: журнал другой, ходы и тексты выдуманы.

```json
{
  "session": "<id сессии из первой строки журнала>",
  "findings": [
    {"type": "late_requirement", "turn": 42, "quote": "кстати, у них есть второй склад, его тоже надо учесть", "note": "условие после готового расчёта"},
    {"type": "off_topic", "turn": 15, "category": "personal", "turns": 2}
  ],
  "checks": [
    {"check": "decision", "turn": 31, "verdict": "engaged", "note": "поправил срок в гипотезе"},
    {"check": "ending", "turn": 50, "verdict": "no"}
  ]
}
```

Ничего не нашёл — `"findings": []`. Других полей не добавляй.
